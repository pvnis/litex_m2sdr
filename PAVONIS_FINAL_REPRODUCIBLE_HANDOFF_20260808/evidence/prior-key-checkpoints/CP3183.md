# Checkpoint 3183: 15 MHz ZMQ acquisition root cause

## Verdict

PASS. The 15 MHz cell-acquisition failure reproduced without radio and was
fixed without source, RF, kernel, FPGA, or gateware changes.

The defect was a paired-config mismatch. At 10 MHz, OCUDU advertises SSB ARFCN
`367930`; at 15 MHz, with the same carrier ARFCN, OCUDU advertises SSB ARFCN
`367450`. The CP3179/CP3180 UE shape retained `367930`, so srsUE searched the
wrong SSB location.

## Controlled sequence

The isolated Band 3 ZMQ harness used the current OCUDU and srsUE binaries and
the established private-lab subscriber role. Subscriber values were neither
printed nor copied; the generated UE configs remained mode `0600`.

1. The 10 MHz control (`52 PRB`, `11.52 Msps`, SSB ARFCN `367930`) passed
   random access, RRC, PDU-session setup, address assignment, and private-core
   gateway ping.
2. The original 15 MHz shape (`79 PRB`, `15.36 Msps`) reproduced the failure:
   the gNB/core and UE RF device started, but no random access occurred.
3. Runtime gNB geometry showed SSB ARFCN `367450`, while the UE still searched
   `367930`.
4. Changing only the UE SSB ARFCN to `367450` made the 15 MHz run pass every
   milestone through gateway ping.

An earlier 10 MHz setup attempt was void because the ZMQ runner omitted the
baseline's licensed-band extended RAR-window authorization. A second 10 MHz
run reached RRC but used a stale, nonmatching subscriber-database role; it was
correctly rejected and is not an acquisition datapoint.

## Decision

The structural-incompatibility stop condition is rejected. The next rung is a
new isolated CP3184 OTA shape derived from CP3179 with only the UE SSB ARFCN
corrected to `367450`, followed by one bounded 15 MHz sustained benchmark if
the no-RF isolation and immutable-baseline gates pass.
