# Checkpoint 3210: SR-period 5 ms no-RF gate

## Verdict

PASS. Five milliseconds is valid for the active 15 kHz numerology, the
isolated launcher adds only that configuration value, and the established
10 MHz ZMQ chain completes attach, private PDU session, private gateway ping,
and clean teardown.

No RF was opened.

## Source and config gate

OCUDU's validator allows 5 slots at numerology zero, and its UCI scheduler
supports SR periods down to one slot. The translator writes the configured
period into the UE-dedicated SchedulingRequest resource.

The CP3210 launcher pins the same proven gNB binary as CP3206 and adds exactly:

```yaml
pucch:
  sr_period_ms: 5
```

Normalized comparison finds no removed or otherwise changed line. Baseline
`min_k2=4`, the 512-byte SR bootstrap, native SR/BSR, and every radio control
remain unchanged.

## Setup voids

Two attempts are excluded before the valid run:

1. The first direct ZMQ invocation omitted the already-required private-lab
   extended-RAR-window validation fixture. The gNB rejected the unchanged
   40-slot RAR window before NG setup, so 5 ms was never evaluated.
2. The corrected invocation reused the source filename. The launcher correctly
   refused to overwrite the target YAML generated by the first void and exited
   before its activation marker.

A fresh byte-identical source copy removed the artifact-name collision. These
are setup voids, not policy failures.
