# CHECKPOINT 21 - Live raw PRACH window OCUDU sweep

Date: [date-redacted]

Scope: Stage 6 offline replay of CP17 gNB raw PRACH windows. No RF hardware was used in this checkpoint.

## Purpose

Checkpoint 20 proved that OCUDU detects the srsRAN-generated CP17-equivalent synthetic waveform at gNB-side `rb_offset=8`. This checkpoint reuses the same OCUDU demodulator/detector path on the live gNB pre-demod raw windows captured around the seven CP17 UE Msg1 transmissions.

The goal is to test whether the saved live gNB windows contain a detectable PRACH if:

- the expected `rb_offset=8` is used,
- the PRACH is at another nearby or plausible RB offset, or
- the PRACH starts later inside the saved 1 ms raw window.

## Artifacts

- Source: `cp21_ocudu_live_window_sweep_probe.cpp`
- Binary: `cp21_ocudu_live_window_sweep_probe`
- Output: `cp21_live_window_sweep.tsv`

## Method

The probe runs the OCUDU software demodulator and detector against:

- synthetic control: `cp19_srsran_prach_offset7_cpseq.cf32`
- live CP17 windows aligned to UE Msg1 TTIs 5774, 5934, 6094, 6254, 6414, 6574, 6734

For each file it records:

- nominal `sample_offset=0, rb_offset=8`
- broad nominal-window RB sweep: `rb_offset=0..20`
- late-start scan at `rb_offset=8` in 8-sample steps
- late-start scan over `rb_offset=6..10` in 8-sample steps

The live files are 11520 samples each, so the late-start scan covers offsets from 0 through 1116 samples while still leaving enough data for the long PRACH CP+sequence demodulation.

## Interpretation

PASS as a diagnostic: the synthetic control still detects strongly at the expected `rb_offset=8` with preamble index 0 and metric 610.25.

FAIL for live Msg1 evidence: none of the seven live gNB windows produced an accepted PRACH under:

- nominal `rb_offset=8`,
- `rb_offset=0..20` at the nominal window start,
- late-start scan at `rb_offset=8`, or
- combined late-start scan over `rb_offset=6..10`.

The synthetic control also produced a weaker broad-sweep cross-hit at `rb_offset=12` with metric 3.12, but the live windows produced no accepted hit even under the same broad sweep.

The live raw RMS values are about `1.53e-4` to `1.59e-4`, while the synthetic control RMS is about `3.02e-1`. This is not a calibrated RF power comparison, but it is consistent with the captured live windows containing only a very small signal/noise floor relative to a clean generated preamble.

## Stage 6 conclusion after CP21

The CP17 failure is unlikely to be caused by:

- srsRAN PRACH generation at UE-side `freq_offset=7`,
- OCUDU PRACH demod/detect compatibility at gNB-side `rb_offset=8`,
- a one-RB neighborhood mapping error,
- a broad nominal-window RB placement within `0..20`, or
- a simple late start of the PRACH inside the saved 1 ms raw window.

The remaining likely failures are now live RF/RX path or UE transmit timing relative to what the gNB is actually receiving, not static PRACH configuration compatibility.
