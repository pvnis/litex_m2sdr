## Interpretation

PASS as a diagnostic.

CP36 proves the exact CP33 live `srsUE` PRACH buffer can radiate over the [host-redacted] bladeRF and can be received/detected by [host-redacted]/M2SDR when replayed through the controlled sparse/timed plugin harness. This eliminates the CP33 waveform itself as the reason the live run was invisible in the mapped gNB windows.

The remaining live failure is therefore not explained by:

- generic bladeRF RF path,
- generic srsRAN bladeRF plugin send path,
- sparse/timed continuous-stream behavior,
- live `srsUE` TX buffer contents,
- nominal PRACH config (`rb8`, preamble `0`),
- or the CP33 frequency condition (`1747505998`).

The next highest-value branch is timing: CP33 may have emitted at a time not covered by the mapped raw windows, or the current raw-window mapping may be wrong. If the CP33 dump is present elsewhere in the CP33 [host-redacted] raw-window corpus, the failure is a gNB/UE timing-alignment problem. If it is absent everywhere, the remaining fault is a live `srsUE` runtime RF-state interaction not reproduced by the controlled plugin harness.
