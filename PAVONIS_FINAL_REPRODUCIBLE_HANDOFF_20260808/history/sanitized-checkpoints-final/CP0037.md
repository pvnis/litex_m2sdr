## Interpretation

PASS as a diagnostic, negative for live waveform presence.

The CP33 waveform is not present anywhere in the 512 saved gNB-side PRACH raw windows at a detectable level. This means the CP33 failure is not just a bad mapping from UE TTI to raw-window index within the saved PRACH-window corpus. If the live `srsUE` PRACH emitted over RF at comparable power to CP36 during any saved PRACH window, this search should have found a high-correlation match.

Combined with CP36, the boundary is now:

- the live CP33 `srsUE` PRACH buffer is valid and can radiate when replayed;
- the controlled plugin sparse/timed path can radiate with the same metadata shape;
- the CP33 gNB-side PRACH raw-window corpus contains only noise-floor-scale windows.

The remaining likely causes are live `srsUE` runtime RF state/configuration or an emission time that is outside the gNB's saved PRACH-window capture opportunities. A live TX-gain/config audit is the next low-cost check, because the controlled replays used TX gain `35`, while CP33's plugin debug proved sample amplitude and `bladerf_sync_tx()` status but did not by itself prove the live device gain.
