## Interpretation

PASS.

The exact CP33 live `srsUE` TX dump radiates and is detected over the [host-redacted] bladeRF TX1 to [host-redacted]/M2SDR RX path at TX gain `60`. This removes gain mismatch as the explanation for the CP33 live failure. It also confirms that gain 60 itself does not suppress or break the bladeRF plugin transmit path in the controlled harness.

The current boundary is now sharper:

- CP33 live `srsUE` produced valid full-scale PRACH worker buffers.
- CP33 live `srsUE` reached `rf_blade_send_timed()` with valid nonzero samples, `has_time=1`, and `bladerf_sync_tx()` returning OK.
- CP37 found no CP33/CP19-like waveform anywhere in the 512 saved CP33 [host-redacted] PRACH raw windows.
- CP38 proves the same waveform, same nominal TX frequency, same sparse/timed metadata shape, and same TX gain are RF-visible and OCUDU-detectable under the controlled plugin harness.

The remaining likely causes are therefore live `srsUE` runtime RF state or scheduling interaction not reproduced by the controlled harness, or live emission timing outside the saved gNB PRACH capture opportunities. The next checkpoint should compare controlled plugin behavior against live srsUE under more similar full-duplex load/state, or add narrowly scoped live RF-state instrumentation around gain/frequency/channel setup and timed TX metadata.
