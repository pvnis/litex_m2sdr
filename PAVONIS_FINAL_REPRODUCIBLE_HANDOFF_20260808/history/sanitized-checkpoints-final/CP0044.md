## Interpretation

The CP43 PBCH/SFN and out-of-sync errors are not sufficient to explain the invalid result, because CP31 and CP33 had the same class of errors and still reached Msg1. The more precise CP43 failure is that the UE never progressed from the initial placeholder PRACH config to the later usable PRACH config:

- missing `config_idx=1`
- missing `freq_offset=7`
- missing `num_ra_preambles=64`

The CP40 RF-state debug also introduced a new behavior inside `rf_blade_send_timed()`:

- when `PAVONIS_RF_BLADE_TX_DBG` or `PAVONIS_RF_BLADE_STATE_DBG` is enabled, it calls `bladerf_get_timestamp(..., BLADERF_RX, ...)` before every TX write;
- live srsUE sends frequent zero TX chunks, so this adds a per-write RX timestamp query to the hot path;
- CP43's first timed TX line showed `tx_delta_samples=-9503`, meaning the first scheduled TX timestamp was already behind the observed RX timestamp by about `0.825 ms` at 11.52 Msps.

This may be perturbing live UE timing enough to prevent the run from reaching the later PRACH config, and it is not needed on every zero TX chunk. The high-value measurement only needs pre-RX timestamp evidence for the first stream-start writes and any high-peak PRACH writes.

## Next step

Patch `rf_blade_imp.c` so the pre-RX timestamp query is gated to selected TX-debug lines:

- first `PAVONIS_RF_BLADE_TX_DBG_FIRST` calls,
- high-peak calls above `PAVONIS_RF_BLADE_TX_DBG_MIN_PEAK`,
- optionally all calls only if a new explicit env flag is set.

Then redeploy the RF plugin to [host-redacted] and rerun the strict-gated live sequence.
