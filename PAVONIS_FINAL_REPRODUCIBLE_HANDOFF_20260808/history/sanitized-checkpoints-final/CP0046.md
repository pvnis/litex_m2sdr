## Interpretation

Late first SOB alone is not sufficient to reproduce the live failure. CP46 started the timed stream later than the live UE did and still radiated a known-good PRACH waveform strongly enough for template recovery and OCUDU detection.

The important remaining caveat is queue lead. CP46's high-peak bursts were about `48 ms` ahead of the sampled RX timestamp because the controlled plugin writes chunks in a tight loop. The live UE high-peak writes were only about `1.5 ms` to `2.2 ms` ahead. The next rung should therefore test a paced controlled replay that keeps each high-peak write close to the live UE's small TX lead.

## Next Step

Create and run a paced sparse replay variant:

- first SOB still near/behind the current device timestamp;
- transmit zero and PRACH chunks at real-time pace;
- target high-peak write lead around `2 ms`;
- keep gain `60`, RX load enabled, and the same CP33 waveform.

If the paced replay fails while CP46 passes, the likely issue is bladeRF/srsRAN behavior under small TX scheduling margin. If it still passes, the remaining difference is live srsUE's ongoing synchronization/absolute-timing state rather than basic timed TX lead.
