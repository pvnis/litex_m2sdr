## Interpretation

The CP45 live Msg1 buffer itself is not the problem. The exact buffer that failed to appear at the gNB during CP45 radiates and is detected when replayed through the same srsRAN bladeRF plugin path with:

- the same TX gain;
- RX load enabled;
- first SOB later than live;
- high-peak writes at live-like TX lead;
- the same RF frequency and sample rate.

This narrows the live failure to live srsUE runtime/stream state or live absolute alignment against gNB PRACH windows, not to:

- PRACH waveform content;
- baseband amplitude;
- SC16 scaling;
- bladeRF TX gain;
- simple timed TX lead;
- first-SOB lateness by itself;
- libbladeRF return status.

## Next Step

The next live-only test should be guarded and reversible in the RF plugin. A useful candidate is a high-peak PRACH re-arm experiment: when a live high-peak PRACH write is detected, force that write to start a fresh timed burst under an explicit environment flag. If that makes the gNB see Msg1, the live continuous TX stream state is bad before PRACH. If it still does not, the remaining suspect is live absolute timing/window alignment or a lower-level live-only TX state not reproduced by standalone replay.
