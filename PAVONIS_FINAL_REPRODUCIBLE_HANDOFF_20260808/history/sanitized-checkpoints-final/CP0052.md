# Checkpoint 52 - PRACH-burst-only live run did not reach Msg1

## Summary

CP52 deployed and ran the env-gated `PAVONIS_RF_BLADE_PRACH_BURST_ONLY=1` experiment. The strict gNB timeout gate passed and the UE was launched, but this variant did not reach a usable PRACH/Msg1 attempt. The RF layer skipped the early low-peak writes as intended, then only saw zero-sample EOB calls returning `-3 Invalid operation or parameter`; no high-peak PRACH buffers were generated.

This means CP52 does not answer whether a standalone timed `SOB|EOB` high-peak PRACH buffer radiates. It does show that suppressing the low-peak/zero TX stream from process start is too disruptive for the live srsUE path.

## Interpretation

CP52 was intentionally aggressive: it withheld all sub-threshold TX buffers from bladeRF and planned to send only high-peak PRACH as a standalone timed burst. In practice, the UE never reached the high-peak PRACH write. The first low-peak skips were acknowledged at the srsUE RF boundary, but the later zero-sample EOB calls produced bladeRF invalid-parameter errors and the UE remained in a bad sync path.

Therefore, the next ladder step should avoid suppressing the normal zero/low-peak stream. A narrower experiment should keep CP45's normal continuous TX behavior, but modify only the high-peak PRACH buffer metadata.
