# Checkpoint 53 - High-peak EOB-only live run did not reach Msg1

## Summary

CP53 deployed an env-gated `PAVONIS_RF_BLADE_FORCE_HIGH_PEAK_EOB=1` experiment. The mode keeps the normal low-peak/zero TX stream intact and only adds `TX_BURST_END` when a high-peak PRACH buffer is seen. The strict gNB timeout gate passed and the UE launched with the intended environment, but this run did not reach a usable PRACH/Msg1 attempt.

Because no high-peak PRACH buffer was generated, CP53 did not exercise the new EOB-only metadata path. It is therefore inconclusive for the main question of whether ending the existing TX burst flushes/radiates the live PRACH buffer.

## Interpretation

CP53 is safer than CP52 because it does not suppress the normal low-peak stream. However, this particular run never reached the high-peak PRACH path, so the new `PAVONIS_RF_BLADE_FORCE_HIGH_PEAK_EOB` behavior was not tested. The observed failure is a UE sync-loss/RX-overflow run, not an EOB metadata failure.

The next step should rerun the same CP53 variant once under a fresh strict gate. If that rerun reaches the same high-peak Msg1 point seen in CP51, it will directly test whether `EOB` on the live high-peak buffer is accepted by bladeRF and visible at the gNB.
