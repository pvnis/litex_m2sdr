# Checkpoint 54 - CP53 high-peak EOB rerun reached Msg1

## Summary

This was a fresh strict-gated rerun of the CP53 `PAVONIS_RF_BLADE_FORCE_HIGH_PEAK_EOB=1` variant. Unlike the first CP53 sample, this run reached usable PRACH and generated high-peak Msg1 buffers.

The result is informative:

- the first high-peak PRACH buffer with `flags=0x2` / `force_eob=1` returned `status=0`
- the next six high-peak PRACH buffers with the same EOB-only metadata returned `status=-3 Invalid operation or parameter`
- the gNB still saw no accepted PRACH detections

Interpretation: adding EOB to a live high-peak buffer is accepted once and likely closes the current TX burst. Repeating EOB-only on later high-peak buffers is invalid without a new SOB/reopened burst. The one accepted EOB-only PRACH did not produce a gNB detection.

## Interpretation

CP51 proved that adding a mid-stream SOB to the live high-peak PRACH is invalid. CP54 now shows that adding only EOB is accepted for the first high-peak PRACH but makes later EOB-only PRACH writes invalid. This is consistent with the first EOB closing the current continuous TX burst.

The next useful ladder step is a stateful variant: let the first high-peak PRACH close the existing burst with EOB, then send later high-peak PRACH buffers as new timed `SOB|EOB` bursts. That should test whether SOB becomes valid after the prior EOB has closed the live stream.
