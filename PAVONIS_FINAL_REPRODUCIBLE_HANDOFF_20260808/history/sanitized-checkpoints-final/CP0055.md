# Checkpoint 55 - EOB then timed SOB|EOB reached Msg1

## Summary

CP55 deployed and ran `PAVONIS_RF_BLADE_HIGH_PEAK_EOB_THEN_SOB=1`. This stateful variant sends the first high-peak PRACH buffer with EOB only, closing the existing live burst, then sends later high-peak PRACH buffers as new timed `SOB|EOB` bursts.

This run reached usable PRACH and exercised the intended state machine. The result:

- first high-peak EOB-only PRACH returned `status=0`
- later high-peak `SOB|EOB` PRACH writes no longer failed with `-3 Invalid operation or parameter`
- later high-peak `SOB|EOB` writes alternated between `status=0` and `status=-14 Requested timestamp is in the past`
- the gNB still saw no accepted PRACH detections

Interpretation: CP55 fixes the burst-state invalid-operation failure seen in CP54, but exposes a scheduling-margin problem for timed `SOB|EOB` reopens.

## Interpretation

CP55 shows that SOB becomes valid again after the live burst is closed by an earlier EOB. This removes the repeated `-3 Invalid operation or parameter` failure from CP54.

The remaining RF-side issue is timing: some `SOB|EOB` PRACH writes are rejected as `Requested timestamp is in the past` despite positive RX-side delta samples. That suggests the TX timestamp domain or queued TX pipeline is ahead of the RX timestamp used for current diagnostics. The next useful step is to instrument the TX timestamp before scheduled SOB writes and then choose a controlled scheduling guard or replay-style TX timing based on the TX clock rather than the RX clock.
