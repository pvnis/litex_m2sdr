## Interpretation

CP57 and CP58 together show two consecutive no-PRACH runs with the 30000-sample guard enabled. Because neither run reached high-peak PRACH, the guard's intended write-acceptance effect is still unmeasured.

The immediate control is to run the same deployed CP57 binary with the guard disabled, using the CP56 TX timestamp sequence environment. If that returns to usable PRACH, the guard setting or wrapper is implicated. If guard-disabled also fails to reach PRACH, the current issue is acquisition/runtime variability or a broader CP57 source-side regression unrelated to the guard application path.

## Next Experiment
