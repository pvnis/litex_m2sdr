## Interpretation

CP65 shows the lead guard ladder is approaching diminishing returns:

1. Increasing guard from 30000 to 40000 reduced `-14` from two to one.
2. It also introduced repeated `-3` invalid-operation failures on later timed bursts.
3. The sampled TX timestamp plus fixed lead model remains incomplete, because even 40000 samples ahead can still be rejected as time-past once.
4. The unchanged gNB non-detection confirms local TX API acceptance is not the only blocker.

This suggests that the next useful ladder step should change strategy instead of simply increasing guard again. The evidence points at burst/stream state or queued TX boundary behavior, not just insufficient timestamp lead.

## Next Experiment

CP66 should test a burst-state strategy rather than a larger guard:

- Keep CP57 source/plugin.
- Add a mode that forces the first high-peak PRACH attempt to be EOB-only, then for subsequent high-peak PRACH attempts use timed SOB|EOB with a 30000 or 40000 guard only if the previous TX status was clean.
- If a timed burst returns `-14` or `-3`, stop forcing SOB on later retries for that run, so the bladeRF stream state is not hammered by invalid timed bursts.

The purpose is to separate "timestamp too close" from "stream/burst state becomes invalid after a failed timed SOB|EOB".
