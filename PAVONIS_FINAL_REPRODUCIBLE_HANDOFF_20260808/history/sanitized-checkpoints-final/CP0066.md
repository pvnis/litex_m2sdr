# Checkpoint 66 - Patched fallback binary ran, but fallback env was not propagated

## Summary

CP66 deployed a patched `rf_blade_imp.c` that adds `PAVONIS_RF_BLADE_TX_DBG_DISABLE_SOB_AFTER_ERROR`, then ran the Stage 6 RF sequence with guard=40000.

The run reached usable PRACH and produced complete UE/gNB artifacts. However, the new fallback mode was not actually active at runtime. The generated CP66 sequence included `PAVONIS_RF_BLADE_TX_DBG_DISABLE_SOB_AFTER_ERROR=1`, but the remote `cp57_sens_start_stage6_tx_guard_ue_remote.sh` helper whitelisted RF debug variables and did not pass the new variable into `sudo env`, `nohup env`, `launch.env`, or `result.env`.

Therefore CP66 is a valid checkpoint for "patched binary with fallback disabled", not for the intended burst-state fallback experiment. It still provides useful evidence: with fallback disabled, the first timed SOB|EOB PRACH burst succeeded, then the zero-sample EOB returned `-3`, and all later timed SOB|EOB PRACH bursts returned `-3`. The gNB still detected no PRACH.

## Interpretation

CP66 did not test the intended stateful SOB fallback because the UE launch helper filtered out the new env variable. The resulting RF behavior is still informative:

1. The CP66 patched plugin itself loaded and logged the new fields.
2. With fallback disabled, repeated timed SOB|EOB retrying again drove the stream into repeated `-3` failures.
3. The `-3` sequence can begin even without a preceding `-14`; the zero-sample EOB error after the first successful timed PRACH appears to be enough to put later forced SOB|EOB sends into an invalid state.
4. The gNB remained at no PRACH detection, so Stage 6 Msg1 is still the first failed stage.
