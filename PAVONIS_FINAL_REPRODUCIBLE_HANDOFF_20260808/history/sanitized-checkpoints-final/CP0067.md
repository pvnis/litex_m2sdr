## Interpretation

CP67 confirms that the repeated `-3` failures after a timed burst error are at least partly self-inflicted by continuing to force timed SOB|EOB retries after the stream reports an error. The fallback makes the bladeRF TX API path healthier after the first failure.

However, "API status healthy" is not enough. Once fallback disables forced SOB/EOB, later PRACH retries are sent with flags `0x0` and no timestamp. Those writes return `0`, but the gNB still sees no valid Msg1. This means the next useful step is not simply "avoid `-3`"; it must preserve a valid on-air burst/timing model while avoiding the invalid stream state.

## Next Experiment

CP68 should test a more conservative recovery model:

- Keep guard=40000 and the CP67 env propagation.
- After a timed SOB|EOB error, stop sending later high-peak PRACH retries for that UE run instead of sending them as untimed flags `0x0`.
- This separates "bladeRF accepts untimed writes" from "valid PRACH reaches the gNB".

If CP68 still shows no gNB detector response, the remaining likely blocker is PRACH placement/timing/power on air rather than local bladeRF TX API acceptance.
