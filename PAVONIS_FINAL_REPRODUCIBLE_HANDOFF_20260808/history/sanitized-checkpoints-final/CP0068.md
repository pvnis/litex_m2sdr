# Checkpoint 68 - Skip later high-peak PRACH after timed TX error

## Summary

CP68 deployed a CP68 RF patch that adds:

```text
PAVONIS_RF_BLADE_TX_DBG_SKIP_AFTER_ERROR=1
```

with the CP67 fallback still active:

```text
PAVONIS_RF_BLADE_TX_DBG_DISABLE_SOB_AFTER_ERROR=1
```

The run reached usable PRACH. Three timed SOB|EOB high-peak PRACH writes succeeded, the fourth timed SOB|EOB returned `-14`, and the next three high-peak PRACH retries were deliberately not sent. They logged `tx_skipped_after_error=1` and `status_str=SKIPPED_AFTER_ERROR`.

This confirms that CP67's post-error `status=0` entries were just accepted untimed writes, not proof of valid PRACH transmission. CP68 cleanly separates the stream recovery behavior from actual on-air PRACH evidence.

The gNB still detected no PRACH. Stage classification remains first failed stage: Stage 6 Msg1 is generated by the UE path, but is not accepted/detected by the gNB.

## Interpretation

CP68 validates the burst-state ladder:

1. Continuing timed SOB|EOB after a timed error can create repeated invalid-operation failures.
2. Blocking forced SOB after the error avoids those repeated invalid PRACH-send errors.
3. Skipping later high-peak PRACH after the error proves the post-error `status=0` entries in CP67 were not evidence of useful on-air PRACH.
4. The gNB still never accepted Msg1, even during the pre-error timed SOB|EOB PRACH writes.

The next useful ladder step should leave TX API recovery aside and focus on why the pre-error valid timed writes are not detected by the gNB. The evidence now points more strongly at PRACH on-air placement/timing/power/config alignment than at post-error bladeRF API recovery.

## Next Experiment

CP69 should analyze and then test PRACH placement/timing rather than adding more TX API recovery:

- Compare UE PRACH `tti_tx`/`tx_time` against gNB PRACH detector windows in the same run.
- Use the predemod manifest around the expected PRACH windows to see whether the UE energy bump aligns with detector occasions.
- If alignment is off, run a small timing-offset sweep around the existing CP68 timed SOB|EOB model, keeping post-error skip mode only as a guardrail.
