# Checkpoint 69 - CP68 PRACH timing correlation points at UE sync/SFN instability

## Summary

CP69 is an analysis checkpoint on CP68 artifacts. No RF behavior was changed and no new RF run was performed.

The CP68 UE PRACH attempts line up with gNB PRACH detector windows by SFN/slot and wall-clock time, but the gNB predemod raw energy at the transmitted subset stays near baseline and the detector still accepts nothing. At the same wall-clock window, the UE detail log reports heavy `SYNC: detected out-of-sync` and `PBCH-MIB: NR SFN ... does not match current SFN` errors.

This shifts the next ladder step away from bladeRF post-error recovery. The stronger evidence now points at the UE scheduling PRACH while its downlink sync/SFN estimate is unstable.

## Interpretation

CP69 narrows the fault:

1. gNB PRACH windows are present at the same SFN/slot sequence where the UE schedules PRACH.
2. The transmitted pre-error PRACH rows do not produce a detector-level energy/signature increase at the gNB.
3. The UE is visibly losing or mis-tracking downlink SFN around the same moments it schedules PRACH.
4. Post-error bladeRF TX recovery is no longer the leading blocker; it was a secondary failure mode that CP67/CP68 characterized.

The leading hypothesis is now: the UE's PRACH scheduler is using an unstable or wrong SFN/timing reference, so the Msg1 waveform is not reaching the expected gNB PRACH receive window as a valid preamble.

## Next Experiment

CP70 should gate PRACH transmission on UE sync stability before touching timing offsets:

- Keep CP68 source/plugin and skip-after-error guardrail.
- Add or find an existing UE-side condition/log point to suppress PRACH when the PHY has recently reported out-of-sync or PBCH SFN mismatch.
- If suppression confirms PRACH is currently launched during unstable sync, then run a follow-up where PRACH is delayed until after a stable sync interval.

If the code path for gating is too invasive, the fallback CP70 experiment should be an analysis-only source audit of UE sync state variables used by PRACH scheduling.
