# Checkpoint 70 - UE sync/PRACH source audit supports an env-gated PRACH delay experiment

## Summary

CP70 is an analysis-only source checkpoint following CP69. No binary was built, no remote host was changed, and no RF run was performed.

The audited NR standalone UE path confirms that PRACH generation is not guarded by recent downlink sync health. `sync_sa::run_state_cell_camping()` skips worker dispatch on an out-of-sync subframe, but it does not clear or delay a pending PRACH request and does not communicate recent instability to `worker_pool::wait_worker()`. When `worker_pool::wait_worker()` later finds a PRACH opportunity, it generates Msg1 and notifies MAC immediately.

This makes a narrow CP71 experiment feasible: add an environment-disabled-by-default sync-health guard in `worker_pool`, updated by `sync_sa`, that withholds PRACH generation until a configurable number of successful camping subframes have elapsed after a sync loss.

## Audited Flow

The active NR standalone init path is:

```text
phy_nr_sa::init()
  sync.init(...)
  workers.init(args, sync, stack)
```

`sync_sa` owns a `worker_pool&`, and `workers.init()` receives `sync_sa` as the `srsran::phy_common_interface` used by NR workers. The common interface only exposes `worker_end()`, so widening that interface is not the preferred next step.

The camping loop in `srsue/src/phy/sync_sa.cc` does this:

```text
workers.wait_worker(tti)
slot_synchronizer.run_camping(...)
if camping fails:
  log "SYNC: detected out-of-sync... skipping slot ..."
  set is_pending_tx_end
  release worker
  return
if camping succeeds:
  dispatch one worker per slot
  set context.sf_idx = tti
  set context.tx_time
  workers.start_worker(...)
  tti++
```

The PRACH path in `srsue/src/phy/nr/worker_pool.cc` does this inside `wait_worker(tti)`:

```text
if prach_buffer->is_ready_to_send(tti, pci):
  prach_buffer->generate(...)
  scale waveform
  phy_state.stack->prach_sent(TTI_TX(tti), ...)

if prach_nof_sf > 0:
  worker->set_prach(...)
```

`srsue/src/phy/nr/sf_worker.cc` then sends any pending PRACH buffer via `common.worker_end(context, true, tx_buffer)`.

## Findings

1. `sync_sa` prevents worker dispatch for the exact out-of-sync subframe, but it does not record recent instability for later PRACH opportunities.
2. `worker_pool::wait_worker()` has no visibility into recent camping failures and no sync-health predicate before `prach_buffer->generate()`.
3. MAC is notified through `prach_sent()` immediately after PRACH generation, before any RF TX result is known.
4. `prach::is_ready_to_send()` marks the current opportunity, but the pending preamble is consumed only by `prach::generate()`. Therefore, skipping generation can preserve the pending preamble for a later opportunity.
5. PBCH SFN mismatch handling in `cc_worker.cc` corrects the local downlink slot config used by that worker, but the audited path does not show a direct feedback mechanism into `sync_sa::tti` or PRACH scheduling.

## Interpretation

CP69 showed PRACH attempts overlapping severe UE sync/SFN instability. CP70 shows that the code can make exactly that mistake: a PRACH request can remain pending across an out-of-sync subframe and fire at the next PRACH opportunity after camping resumes, even if the UE has not demonstrated a stable downlink timing window.

The next rung should test whether suppressing PRACH during recent sync instability changes behavior. This does not yet prove whether the root cause is wrong absolute SFN, wrong sample-time alignment, PBCH/SFN correction not feeding back, or RF-level invisibility. It does isolate the scheduler from the unstable-sync condition found in CP69.

## CP71 Recommendation

Implement a disabled-by-default experiment with environment controls:

```text
PAVONIS_SRSUE_PRACH_SYNC_GUARD_SLOTS=<N>
```

Suggested initial value: `200`.

Implementation outline:

- Add `worker_pool::note_sync_camping_result(uint32_t tti, bool ok)`.
- Track `prach_sync_guard_slots`, consecutive successful camping subframes/slots, and last failed camping TTI in `worker_pool`.
- In `sync_sa::run_state_cell_camping()`:
  - call the note function with `ok=false` when `run_camping()` fails.
  - call it with `ok=true` after a successful `run_camping()` before dispatching slots.
- In `worker_pool::wait_worker()`:
  - if PRACH is ready but the guard is enabled and the stable count is below the threshold, log a clear `PAVONIS_PRACH_SYNC_GUARD` line and skip `generate()`/`prach_sent()`.
  - leave the pending PRACH preamble intact so a later PRACH opportunity can be used.

This keeps the experiment out of RF code, avoids widening shared interfaces, and gives a direct answer to whether Msg1 is currently being launched too close to sync loss.
