# Checkpoint 73: PBCH-MIB SFN Mismatch Feedback Into PRACH Guard

## Scope

CP72 proved the run-camping PRACH sync guard was active, but it still allowed PRACH during heavy PBCH SFN mismatch churn. CP73 added PBCH-MIB SFN mismatch feedback from `cc_worker` into `worker_pool` so the same 200-slot PRACH guard resets on either run-camping failure or PBCH SFN mismatch.

This checkpoint intentionally stayed inside Stage 6 / Msg1 only.

## Code Change

Added a narrow callback path:

- `worker_pool` creates a PBCH mismatch notifier and passes it into each NR `sf_worker`.
- `sf_worker` passes the notifier into each NR `cc_worker`.
- `cc_worker::measure_csi()` calls the notifier before its existing local `dl_slot_cfg.idx` correction when MIB SFN differs from current SFN.
- `worker_pool` records `last_bad_reason`, emits guard telemetry with the reason, and protects PRACH guard state with a dedicated mutex because CP73 updates it from worker-thread DL processing.

## Interpretation

CP73 confirms the CP72 hole: the UE was satisfying the run-camping-only PRACH guard often enough to transmit, while PBCH SFN mismatch churn was still active. Feeding PBCH mismatch into the same guard suppresses all Msg1 attempts in this run.

This is useful, but not sufficient as a fix. It prevents bad PRACH transmissions; it does not create a stable Msg1 opportunity. The UE never obtains 200 stable slots under combined run-camping and PBCH-MIB health, so no PRACH leaves the UE and the gNB correctly sees no preamble.

## Next Rung

CP74 should stop treating PRACH suppression as the primary fix and move one level upstream: root-cause why PBCH-MIB SFN mismatch churn is continuous after cell camping. The most likely area is the worker-local PBCH SFN correction path in `cc_worker::measure_csi()`, which changes a local DL slot index but does not align the shared sync/worker scheduling state.
