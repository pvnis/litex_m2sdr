## Interpretation

CP81 did not restore the CP48-style replay behavior. Removing CP79's burst-only, TX guard, PRACH timestamp offset, and after-error flags still left the exact CP79 dump only intermittently visible at the receiver:

- CP48 known-good replay: `7/7` selected windows above `0.50`, minimum about `0.924`.
- CP80 CP79 dump with CP79 RF env: `3/7` selected windows above `0.50`.
- CP81 CP79 dump baseline env: `2/7` selected windows above `0.50`.

This means CP80's poor replay cannot be attributed only to the CP79 RF env hook. The CP79 dump itself, the current RF path health, or both are now suspect.

The next checkpoint should be a current known-good replay control using a previously passing waveform, preferably the exact CP45 dump used in CP48 or the CP33 dump used in CP39/CP47. If that known-good replay is clean now, CP81 points to CP79 dump content or generation context. If the known-good replay is also intermittent now, the current RF/capture setup has regressed and the CP79 comparison is not reliable until that path is restored.
