## Interpretation

CP95 is not a PRACH detection result. It did not reach the live UE transmit step.

What CP95 proves:

- The generated gNB config was correctly changed to `rx_gain: 30`.
- The gNB could start and report readiness with that config.
- The strict pre-UE health gate then saw a large number of M2SDR TX writeStream timeouts in `/tmp/gnb_m2sdr_band3_ota.log`.
- The ladder correctly stopped before introducing UE-side variables.
- The stop helper did not fully reap the outer OTA wrapper in this failure mode, so post-run hygiene needs manual verification or a stronger wrapper-kill step.

What CP95 does not prove:

- It does not prove that `rx_gain: 30` is unusable for PRACH, because no PRACH was transmitted.
- It does not prove an antenna/cable/RF-path thermal issue, because the observed failure was a gNB/M2SDR TX timeout gate, not a received-signal degradation measurement.
- It does not distinguish a real `rx_gain: 30` side effect from a transient gNB/M2SDR start problem.
