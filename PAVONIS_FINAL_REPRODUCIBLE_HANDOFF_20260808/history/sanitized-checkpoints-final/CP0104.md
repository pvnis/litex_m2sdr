# Checkpoint 104: gNB PRACH timing instrumentation audit

Date: [date-redacted]

## Scope

This checkpoint audited the current OCUDU gNB receive-side PRACH instrumentation after CP101-CP103 showed:

- CP99 live UE PRACH TX dumps were valid.
- CP99 live gNB PRACH raw windows did not contain a recognizable copy of those dumps.
- The same CP99 dump was strongly visible through controlled replay in CP102 and CP103.

The audit target was therefore not waveform validity, but whether the current live gNB artifacts can prove the exact adjusted baseband sample interval represented by each dumped PRACH raw window.

## Source Evidence

Relevant source files:

- `ocudu/lib/phy/lower/lower_phy_baseband_processor.cpp`
- `ocudu/lib/phy/lower/processors/uplink/uplink_processor_impl.cpp`
- `ocudu/include/ocudu/phy/lower/processors/uplink/prach/prach_processor_baseband.h`
- `ocudu/lib/phy/lower/processors/uplink/prach/prach_processor_worker.cpp`
- `ocudu/include/ocudu/phy/upper/channel_processors/prach/prach_detector.h`
- `ocudu/lib/phy/upper/channel_processors/prach/prach_detector_generic_impl.cpp`

Key findings:

1. `lower_phy_baseband_processor::ul_process()` receives radio baseband buffers with `rx_metadata.ts`, then calls:

   `uplink_processor.process(ul_buffer->get_reader(), apply_timestamp_sfn0_ref(rx_metadata.ts));`

   This means the uplink processor has the adjusted timestamp needed to map samples to SFN/slot time.

2. `lower_phy_uplink_processor_impl::process_symbol_boundary()` derives:

   - subframe index from timestamp
   - sample index within subframe
   - slot index
   - OFDM symbol index
   - `current_symbol_timestamp`

3. `lower_phy_uplink_processor_impl::process_collecting()` currently calls PRACH with only:

   `prach_processor_baseband::symbol_context{.slot = current_slot, .symbol = current_symbol_index, .sector = sector_id}`

   The absolute adjusted baseband timestamp is discarded before entering the PRACH worker.

4. `prach_processor_baseband::symbol_context` only contains:

   - `slot`
   - `symbol`
   - `sector`

   It has no timestamp field.

5. The current `PAVONIS_PRACH_PREDEMOD_DUMP` manifest records:

   - wall-clock nanoseconds
   - SFN/slot
   - PRACH format/config
   - raw RMS/peak
   - optional raw file path

   It does not record the adjusted baseband sample timestamp at which the PRACH collection started or ended.

6. `prach_detector::configuration` already has `slot` for logging, but the current `PAVONIS_PRACHDET_TRACE` line does not include that slot or any timestamp. It records detector metrics only.

## Interpretation

The current artifacts prove that OCUDU processed PRACH requests for particular SFN/slot labels, but they do not prove the absolute adjusted baseband sample interval captured in each raw PRACH window.

That is the missing evidence needed after CP101-CP103:

- If the live UE burst is outside the gNB PRACH collection interval, the detector will correctly see no preamble even when RF is healthy.
- If the burst overlaps the interval but is still not visible, the issue shifts back toward live RF coupling, live RX chain state, or unexpected frequency/port behavior.

The controlled replay successes in CP102 and CP103 make a pure waveform or detector-threshold explanation unlikely. The next best rung is therefore timing instrumentation that ties each PRACH raw window to adjusted sample timestamps.

## Recommended CP105

Add bounded debug-only instrumentation with environment gates:

1. Extend `prach_processor_baseband::symbol_context` with `baseband_gateway_timestamp timestamp`.
2. Populate it from `lower_phy_uplink_processor_impl::current_symbol_timestamp`.
3. In the PRACH worker, record the timestamp of the first collected symbol and the final collected sample interval in the predemod manifest.
4. Add slot/config identifiers to `PAVONIS_PRACHDET_TRACE` so detector rows can be joined to PRACH raw manifest rows.
5. Rebuild/deploy OCUDU and run one live CP99-style diagnostic at the recovered `rx_gain: 30` path.

Expected CP105 success condition:

- A live run produces PRACH raw windows with adjusted timestamp ranges, detector trace rows with slot labels, and UE TX dump timing/status.
- The report can then decide whether the UE burst is outside, partially overlaps, or falls inside the gNB PRACH collection interval.
