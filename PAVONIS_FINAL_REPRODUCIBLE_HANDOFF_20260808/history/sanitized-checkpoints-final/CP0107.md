## Interpretation

CP107 is not a valid live PRACH timing-instrumentation result. It failed at the
pre-UE strict gate with 7436 Soapy TX timeout lines in the temporary gNB log, so
no UE PRACH was transmitted and no CP105 PRACH timing artifacts were generated.

This result is most consistent with a stale-wrapper or transient gNB/M2SDR TX
health failure, similar to earlier gate failures, not with the CP105 timing
instrumentation proving or disproving the live PRACH hypothesis.

## Next Action

Run force cleanup and verify no `run_ota_stage_template`, gNB, or qcore process
remains. After cleanup, run a no-UE strict-gate retry at `rx_gain: 30`. Only if
that passes should the timing-instrumented live PRACH retry be repeated.
