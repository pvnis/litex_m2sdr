## Interpretation

CP113 confirms the CP111 live gNB raw PRACH windows do not contain a recognizable
copy of the UE PRACH waveform:

- Direct same-window score max: about `0.044`.
- Global sliding score max: about `0.066`.
- No score reached the weak `0.10` threshold.
- The approximate wall-time join lands near ordinary low-RMS gNB windows.
- This is consistent with the CP111 detector trace, where `accepted=0` and the
  best detector ratio was only `0.220` against threshold `0.610`.

Together with CP102 and CP103, this is an important split:

- The CP99/CP111 UE PRACH waveform is valid and can traverse the controlled
  [host-redacted]-to-[host-redacted] RF path when replayed.
- The live gNB PRACH receive windows during an actual srsUE run do not contain
  that waveform strongly enough to correlate.

The next suspect is a live-only bladeRF/srsUE RF stream-state condition, not the
dump content, not the CP99 hook set in controlled replay, and not a generic
M2SDR/gNB detector failure.

## Next Action

Audit the live srsUE bladeRF transmit log around the zero-sample EOB invalid
operations that precede the high-peak PRACH dumps. CP111 shows repeated
`nsamples=0`, `eob=1`, `status=-3` events before the high-peak PRACH writes,
while the high-peak writes themselves return `status=0`. The next checkpoint
should determine whether those live-only invalid EOB events can leave the
bladeRF stream in a state where subsequent apparently successful PRACH writes do
not actually radiate.
