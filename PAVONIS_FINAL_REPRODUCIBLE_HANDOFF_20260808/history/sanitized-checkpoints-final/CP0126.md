## Interpretation

CP126 is a partial/reduced controlled replay pass.

It proves the current patched controlled path is still capable of radiating and receiving the CP123 PRACH waveform:

- the replay had clean libbladeRF/plugin status,
- [host-redacted] captured non-noise RF energy,
- sparse correlation reached `0.9208`,
- OCUDU found a nominal RB8/preamble-0 hit on the strong selected window.

However, this was not a clean repeat of the earlier CP102/CP103 controlled replay behavior. Only `1/7` selected windows crossed `0.50`, and only one selected window produced a nominal OCUDU RB8 hit. That points to an intermittent or timing-sensitive controlled replay result under this CP123 hook environment, rather than a fully stable path.

Thermal/antenna note: a passive antenna overheating explanation is not the best fit for this evidence. The path was not dead after the live CP123 failure; it produced one strong controlled replay detection shortly afterward. Active RF-chain thermal behavior, connector/contact intermittency, gain/stream-state drift, or timed-TX sensitivity remain plausible classes, but CP126 does not by itself prove a temperature cause.

## Next step

Run the same CP123 dump controlled replay with the CP123 hook environment removed. If the baseline environment returns to the earlier strong multi-window replay behavior, the CP123 hook/patch environment is affecting controlled replay. If it remains degraded, the issue is more likely current RF/replay variability, timing/capture alignment, or CP123 waveform/path conditions.
