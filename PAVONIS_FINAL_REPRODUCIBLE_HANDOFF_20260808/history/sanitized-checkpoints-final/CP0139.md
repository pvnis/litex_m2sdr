## Interpretation

CP139 is a valid live negative result:

- The gNB started cleanly and passed strict gate.
- srsUE produced four high-peak PRACH buffers.
- bladeRF reported `status=0` / OK for the four high-peak writes.
- The gNB detected no preamble.
- The saved receiver raw levels stayed low.

This is no longer the CP135 failure mode. CP135 stopped before UE launch because the gNB startup stream was unhealthy. CP139 reached the live PRACH test and failed at RF visibility/detection.

The strongest immediate hypotheses are:

- live srsUE/bladeRF timed TX is not emitting where/when the gNB raw capture expects despite `status=OK`,
- live RF path state differs from controlled replay state,
- active RF-chain/path intermittency persists,
- or the waveform is being emitted but outside the saved gNB windows/timing/frequency assumptions.

This checkpoint does not specifically support passive antenna overheating. It remains more consistent with active SDR/RF path state, driver stream state, contact/interconnect variability, or live timestamping/emission behavior.
