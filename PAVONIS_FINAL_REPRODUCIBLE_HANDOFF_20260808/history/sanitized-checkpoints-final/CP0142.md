## Interpretation

CP142 proves the exact CP139 live waveform is not intrinsically invalid. The waveform can be transmitted by the controlled bladeRF plugin and recovered at the M2SDR RX path in five of seven expected windows.

This sharply separates CP139 from a pure detector problem:

- In CP139 live mode, the same waveform was absent from all 512 saved gNB raw windows.
- In CP142 controlled replay mode, the waveform is visible in the capture and produces nominal OCUDU hits.

However, CP142 is only a partial pass. Compared with CP134's clean `7/7`, the current controlled path still shows active RF/path variability or timing/capture intermittency: two expected windows were weak dropouts.

The strongest current interpretation is:

- live srsUE/bladeRF emission/timestamp behavior remains suspect because controlled replay can move the same waveform through the RF path,
- active RF-chain/path state remains variable because CP142 did not recover to `7/7`,
- passive antenna overheating alone remains unlikely; a broader active RF path, interconnect, or SDR state issue is still plausible.

## Next step

Repeat the same controlled replay immediately or after a short idle interval. A stable repeat at `5/7` or better keeps live srsUE timestamp/emission semantics as the main fork; degradation toward `0/7` would support an active RF path decay/thermal/intermittency problem after recent RF activity.
