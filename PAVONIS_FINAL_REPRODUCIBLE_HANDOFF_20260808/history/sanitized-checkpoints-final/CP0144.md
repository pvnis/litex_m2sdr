## Interpretation

CP144 did not test live Msg1. It stopped one rung earlier because the gNB/M2SDR stream was not strict-gate clean.

This recreates the CP135 class of failure:

- the controlled replay path can be clean,
- but a subsequent full live gNB startup can enter a Soapy TX timeout flood before UE launch.

That reinforces two separate issues:

- live Msg1 visibility failure when strict gate passes, as in CP139,
- gNB/M2SDR stream readiness instability before live UE launch, as in CP135 and CP144.

This is not evidence for passive antenna overheating. It points more strongly at active SDR/driver/stream state or full live harness startup state. A physical/interconnect issue could still contribute, but CP143's clean controlled replay immediately before CP144 argues against a simple antenna/path inability to carry PRACH energy.
