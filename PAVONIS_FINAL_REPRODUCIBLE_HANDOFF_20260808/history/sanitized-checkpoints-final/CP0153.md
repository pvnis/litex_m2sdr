## Interpretation

CP153 does not support a straightforward overheating explanation for the SDR RFICs or hosts:

- bladeRF RFIC was only `34.2 C`.
- [host-redacted] AD9361 was `34 C`.
- M2SDR FPGA was about `64 C`, similar to earlier snapshots and not an obvious fault reading.
- Both hosts were lightly loaded and below CPU thermal limits.
- Both RF devices enumerated cleanly.
- No stale radio process was visible.
- The filtered recent kernel logs did not show fresh USB, PCIe, DMA, timeout, reset, thermal, or voltage faults.

This weakens the theory that a simple passive antenna overheating is the cause. It does not eliminate active RF-path intermittency:

- CP151 and CP152 still show controlled RF hits varying from `5/7` to `3/7` with the same waveform and clean TX return codes.
- CP153 cannot measure cable/connector contact, external attenuator/amp/LNA state, antenna feedpoint temperature, shielding/contact changes, or analog front-end drift under load.
- A stateful or thermal effect in the active SDR path can still be present even when the after-the-fact idle RFIC readings look normal.

## Next step

Do a short idle cooldown, then repeat the same CP148 dump `000005` controlled replay. If the hit count recovers after idle, thermal/state recovery becomes more plausible. If it stays degraded, inspect or reset the physical/active RF path before using more live srsUE runs as evidence.
