## Interpretation

CP165 shows the exact CP161 dump `000005` can traverse the controlled bladeRF-to-M2SDR path cleanly at RX gain `40`. This rules out CP161 waveform invalidity as the explanation for the live failure.

The CP164-to-CP165 swing points to controlled-path variability rather than deterministic waveform failure:

- CP164 had clean TX but only `4/7` selected strong receive windows.
- CP165 immediately recovered to `7/7` with the same waveform and settings.
- CP163 still showed the live CP161 TX waveform absent from the gNB raw corpus at the expected times.

The live-vs-controlled split therefore remains the main result: live srsUE/bladeRF reports OK high-peak timed writes, but gNB raw IQ does not contain those writes; controlled replay of the same dump can be received cleanly.

## Next step

Continue with a stricter live-emission/timestamp probe rather than changing the waveform. A useful next rung is a gNB/live retry that logs a shared timing reference more tightly around the UE TX events, or a live-side bladeRF state probe immediately around each OK PRACH write.
