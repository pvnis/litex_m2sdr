## Interpretation

CP184 is the strongest live-versus-controlled split so far. The exact waveform captured during the failed CP182 live run, with the CP182 TX-hook environment active, crosses the RF path cleanly when replayed by the controlled paced plugin minutes later.

This result argues against the CP182 waveform content and against a static receive-path/antenna failure. It also makes passive antenna overheating unlikely as a standalone explanation: if the antenna or passive RF path were simply overheated or dead during this period, the same CP182 dump should not have replayed as `7/7` clean immediately afterward through the same lab RF path.

The remaining suspect area is narrower:

- live srsUE/rf_blade stream state during the actual UE session
- stream transition, timestamp, SOB/EOB, or metadata behavior that differs inside the long-running srsUE path
- an intermittent live-only RF path condition that is cleared or bypassed by the controlled replay sequence

Controlled replay bypasses srsUE's live scheduling and long-running stream context while still using the same bladeRF hardware and RF path.

## Next

Run another strict-gated live reprobe from this clean CP184 state. If live still fails immediately after CP184 controlled replay passes, the evidence points more strongly to a live srsUE stream/RF-state issue than to antenna heating, waveform validity, detector logic, or static RF path loss.
