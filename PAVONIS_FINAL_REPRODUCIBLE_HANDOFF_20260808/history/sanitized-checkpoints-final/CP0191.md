## Interpretation

CP191 reproduces the CP184 conclusion with a fresh live-failure waveform. CP189 dump `000004`, captured from a live run where the gNB saw no PRACH detection and only noise-scale raw power, is received cleanly as `7/7` when replayed through the controlled bladeRF path with the same live hook environment.

This rules out the CP189 waveform content and the CP189 live hook settings in isolation. It also further weakens passive antenna/path overheating as a standalone theory: the same lab RF path cleanly receives the live-captured waveform when the controlled plugin transmits it, while the live srsUE stream path fails.

The remaining suspect is live-only behavior in the srsUE/rf_blade transmit path: stream state, timestamp/SOB/EOB transitions, scheduling context, or another difference between the long-running UE stream and the controlled paced plugin.

## Next

Move up one layer from waveform validity to live stream-state isolation. The most useful next probe is a live run that deliberately resets or reinitializes the bladeRF TX stream immediately before the first PRACH opportunity, or an equivalent cabled/direct-path live test if the lab wiring is available.
