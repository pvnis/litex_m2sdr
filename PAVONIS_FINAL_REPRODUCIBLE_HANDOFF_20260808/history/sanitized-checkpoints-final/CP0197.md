passed the gNB strict gate and launched srsUE, but srsUE never reached a real
high-peak PRACH Msg1 TX path:

- no high-peak RF writes

- no guard release

`SYNC_LOSS_NO_HIGH_PEAK_PRACH`

The next step is to clean [host-redacted] userland state, then run a smaller sync/SSB
health checkpoint before retrying TX_NOW again. Repeating TX_NOW immediately
would likely only retest the same UE sync-loss state rather than the intended
bladeRF TX metadata change.
