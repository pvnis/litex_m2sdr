actually fired on real PRACH writes. It did not move the system past Msg1:

- UE made 5 high-peak PRACH writes with `TX_NOW` applied and write status OK.
- gNB saw 0 non-empty PRACH detections across 1714 PRACH checks.
- detector accepted sum remained 0, with max peak only `0.146` against the

  levels seen in prior failed live runs.

The checkpoint classification is:

`TX_NOW_APPLIED_NO_GNB_MSG1_DETECTION`

This makes pure bladeRF timestamp scheduling less likely as the only live
failure mode. The remaining live-only gap is more consistent with TX energy not
leaving the UE RF path as intended, TX path state not matching the replay/static
path, live sync/frequency/timing instability, or a physical/RF path issue. The
first-failed-stage rule still keeps the work at Stage 6 PRACH Msg1.
