# CHECKPOINT 204 - rf_blade first-high-peak TX stream restart deploy/build

## Purpose

Deploy the local `rf_blade_imp.c` probe that can restart the bladeRF TX stream exactly once, immediately before the first high-peak live PRACH write, then rebuild only the `srsran_rf_blade` plugin on `[host-redacted]`.

This is a narrow live-only probe after CP203 showed that the CP201 PRACH dump and RF path still replay cleanly. The hypothesis being tested next is that the live srsUE/bladeRF TX stream state or boundary context is suppressing the actual over-the-air PRACH, even though the same samples replay cleanly in controlled mode.

## New runtime gate

The new behavior is disabled by default and only activates when all of these are true:

- `PAVONIS_RF_BLADE_TX_DBG=1`
- `PAVONIS_RF_BLADE_TX_DBG_RESTART_TX_STREAM_ON_FIRST_HIGH_PEAK=1`
- `nsamples > 0`
- `cf32_peak >= PAVONIS_RF_BLADE_TX_DBG_MIN_PEAK`
- the first eligible high-peak write has not already used the restart path

The existing CP201 TX_NOW probe remains separately gated by:

- `PAVONIS_RF_BLADE_TX_DBG_HIGH_PEAK_TX_NOW=1`
