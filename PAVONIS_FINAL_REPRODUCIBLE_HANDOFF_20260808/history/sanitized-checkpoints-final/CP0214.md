## Interpretation

CP214 is a strong negative result for the saved gNB detector windows from CP211:

- best same-window score: about `0.0391`
- best global saved-window score: about `0.0563`
- hits >= `0.10`: `0`
- hits >= `0.25`: `0`
- hits >= `0.50`: `0`

Taken with CP213, the picture is now sharper:

- CP211 live: timed metadata PRACH writes reported OK, but gNB detected 0 Msg1
  and the saved PRACH predemod windows are floor-level.
- CP213 controlled replay: the exact CP211 dump `000001` crosses the RF path
  cleanly with `7/7` sparse hits and `7/7` nominal OCUDU hits.
- CP214 offline raw search: the CP211 waveform is not present in the saved gNB
  PRACH windows, and the nearest saved windows are about `33.5 ms` before the
  estimated UE TX times.

This does not support a dead RF path or simple antenna-overheating theory. It
supports a live scheduling/window-alignment problem: the live UE reports valid
timed writes, but the gNB detector windows do not contain that waveform. The
`33.5 ms` phase offset is now the most actionable clue to investigate before
more RF-path changes.

## Next step

Audit the CP211 timing basis end to end: UE `START_UTC`/TX metadata times,
gNB predemod `wall_ns`, PRACH TTI/slot mapping, and the gNB PRACH occasion
schedule. The next experiment should test a controlled live offset adjustment
derived from the observed `~33.5 ms` phase error, or first validate that the
wall-clock join formula is using the correct UE run start reference.
