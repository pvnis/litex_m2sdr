## Interpretation

CP219 passed the infrastructure gate and successfully captured the missing
timing evidence.

Main conclusions:

- CP216 wall-clock instrumentation works.
- The old `START_UTC + secs + frac` join is not reliable in this restart-path
  run; it is about `3.99 s` early relative to the RF-hook wall clock.
- The actual RF hook occurs shortly after a gNB PRACH detector window, not
  inside it.
- The gNB detector windows nearest the RF-hook time are floor-level and no
  preambles are accepted.
- This still does not support antenna overheating or a dead static RF path,
  especially given the clean CP213 controlled replay. It supports a live
  scheduling/window-alignment problem.

The next technical experiment should use the new RF-hook timing basis. A large
negative timestamp offset remains unsafe because the current live TX timestamp
is only `24000` samples in the future. If testing an offset, the feasible
direction is a controlled positive delay toward the next PRACH window, or a
scheduler-level fix that causes the callback to occur before the intended
window with enough lead time.
