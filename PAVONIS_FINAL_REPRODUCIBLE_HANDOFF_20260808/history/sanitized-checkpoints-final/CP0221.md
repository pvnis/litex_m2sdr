## Interpretation

CP221 passed infrastructure setup but is inconclusive for the +143 ms timing
hypothesis. The configured positive offset was present, but it was never
applied because the UE never generated a high-peak PRACH write in this run.

This does not supersede CP219's timing conclusion. CP219 remains the last live
run with usable RF-hook timing evidence:

- high-peak PRACH writes happened
- RF hook wall clock showed they were after the previous gNB detector window
- the next detector window was the feasible positive-delay target

The next step should avoid treating CP221 as a timing miss. Either retry the
same +143 ms condition until a high-peak PRACH write occurs, or adjust the UE
start/sync conditions first so the high-peak Msg1 path is reliably reached.
