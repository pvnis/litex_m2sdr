## Interpretation

CP223 is a second inconclusive positive-delay run. It confirms the setup can
pass the strict gate and launch the UE, but it does not test whether +143 ms
aligns Msg1 with the next gNB detector window because no high-peak Msg1 TX was
generated.

Two consecutive positive-delay attempts, CP221 and CP223, did not reach the
high-peak PRACH path. The next useful step is a known-good control using the
last condition that did produce high-peak PRACH metadata, to separate a general
UE/RF-path regression from a positive-delay-specific problem.
