# Checkpoint 245 - Backoff10 live run recovered real RACH, but cell-select trace env was not propagated

## Summary

CP245 repeated the CP242-style Stage 6 live control:

- gNB tx backoff10 path
- gNB `rx_gain=40`
- UE config `rx_gain=40`
- PRACH time offset `-16000`
- TX guard `40000`
- CP244 rebuilt UE binary present on [host-redacted]

The intended new env, `PAVONIS_SRSUE_CELL_SELECT_TRACE=1`, was added to the outer SSH command, but the remote UE launcher `cp193_sens_start_stage6_high_peak_tx_now_ue_remote.sh` writes a bounded `sudo -n env` wrapper with an explicit env whitelist. That whitelist does not include `PAVONIS_SRSUE_CELL_SELECT_TRACE`, so CP245 has zero `PAVONIS_CELL_SELECT_TRACE` rows.

Even without that trace, CP245 is useful: unlike CP242, the UE reached real SIB1/RACH config and emitted five high-peak PRACH TX attempts. The current first-failed stage moved back from DL cell selection to gNB Msg1 detection.

## Interpretation

CP245 restores the earlier CP219-style first-failed stage: UE can reach real RACH config and transmit high-peak PRACH, while the gNB still sees only detector background.

The DL-acquisition/SFN-sync failure seen in CP242 is therefore intermittent or margin-sensitive, not a permanent failure. The overheating/RF-margin theory remains plausible, but CP245 shows the path can recover without hardware intervention.
