- CP269 offset: `1843200` samples = `160.000000 ms` at `11.52 Msps`

The older CP271 metadata-to-manifest join used `UE START_UTC + secs/frac`. That
is weaker for this purpose because the UE start time and device RF time were
offset by several seconds. For this checkpoint the estimate uses the clock
sample taken immediately around each `bladerf_sync_tx` call:

```text
estimate_ns = sync_realtime_after_ns + tx_domain_delta_samples / 11520000 * 1e9
```

## Caveat

This is a live timing probe, not a proof that wall time is the root cause. CP271
already showed the CP269 waveform was not found anywhere in the first 512 saved
gNB PRACH windows. CP273 then cleared the controlled RF path with the same
waveform and live burst metadata. The remaining plausible fork is live
UE/gNB timing alignment versus a live-only emission/state issue. CP275 directly
tests the timing branch with the smallest controlled change.
