## Interpretation

CP283 is not a PRACH-offset result. It failed before Msg1, and no UE-side PRACH
write occurred. The failed stage is downlink cell acquisition.

The key new finding is that changing the UE config from `rx_gain = 40` to
`rx_gain = 30` did not change the bladeRF-reported actual RX gain; the backend
still reported `actual=60.000`. That weakens any conclusion based on "lower UE
gain" live tests using this config path.

Thermal/antenna note: CP281, run shortly before CP283, still recovered expected
PCI 1 in an independent SSB capture under backoff20/gain30. That argues against
a completely dead or passively overheated downlink antenna path at that moment.
It does not rule out active RF-chain thermal drift, intermittent contacts, or
live srsUE acquisition sensitivity.

## Next Rung

Further PRACH timing changes are not meaningful until the UE again reaches
Random Access and emits high-peak PRACH writes.

The next diagnostic should isolate live UE downlink acquisition/gain behavior:
either return to the CP247-style backoff10 condition that reached real RACH and
then continue Msg1 timing analysis, or add a focused UE-side acquisition/gain
readback test to determine why requested `rx_gain=30` and `rx_gain=40` both
report actual `60.000`.
