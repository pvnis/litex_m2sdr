## Interpretation

CP292 is a clean controlled-path pass for the exact CP289 dump and CP289's
live-style metadata settings:

- the CP289 waveform is valid
- the current bladeRF-to-M2SDR RF path is not dead or grossly degraded
- burst-only `flags=0x3`, guard `40000`, offset `-16000`, and first-high-peak
  restart do not prevent RF emission or OCUDU nominal detection in controlled
  mode

This sharply localizes the CP289 failure. CP289 live srsUE reported five OK
PRACH writes, and CP291 showed the aligned gNB raw windows were floor-level and
waveform-negative. CP292 proves the same waveform and metadata family can
radiate cleanly immediately afterward. The remaining fault is live-only:
srsUE/bladeRF stream state, the live timed-TX scheduling path, or a live
RX-to-TX/device-time semantic mismatch.

This does not support antenna overheating as the primary explanation for the
current failure: a hot/dead passive path should not produce a clean `7/7`
controlled replay minutes later under the same RF endpoints.

## Next Rung

Target live-only TX semantics. The next useful live probe should change one
thing in the srsUE PRACH TX path, such as forcing high-peak PRACH writes to
TX-now or instrumenting post-write bladeRF/device time and stream state, then
compare gNB raw windows again.
