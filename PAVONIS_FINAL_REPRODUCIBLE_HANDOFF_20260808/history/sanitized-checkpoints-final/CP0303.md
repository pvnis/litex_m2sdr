# Checkpoint 303: CP300 mocked failure-flow tests

## Purpose

Validate the CP300 watchdog launcher locally, without touching the RF hosts, before using it during unstable SSH/SCP conditions.

## New artifact

- `cp303_test_cp300_watchdog_launcher_mocked_flows.sh`

The harness overrides `ART` to a temporary directory and supplies fake `ssh_pexpect_run.py`, `scp_pexpect_put.py`, and `scp_pexpect_get.py` helpers. It therefore runs the real CP300 launcher control flow without contacting `[host-redacted]` or `[host-redacted]`.

## Bug found

The first mocked run exposed a shell control-flow bug in:

- `cp300_run_stage6_native_timed_no_guard_no_offset_repeat_after_cp299_invalid_watchdog_sequence.sh`

Problem:

- `run_cmd` unconditionally re-enabled `set -e` before returning the command status.
- When `capture_cmd` called `run_cmd` for an expected nonzero branch, the nonzero return still caused the launcher to abort before executing the intended skip/cleanup logic.
- This meant a local `start_gnb` timeout/failure would hit the EXIT trap, but would not log `SKIP_GATE_AND_UE` or proceed through the explicit stop/package/final-check path as designed.

Fix:

- `run_cmd` now records whether `errexit` was enabled on entry.
- It restores the caller's prior `errexit` state before returning.
- Under `capture_cmd`, nonzero statuses are captured instead of aborting the script.

Additional hardening:

- `ART` is now environment-overridable so local mock tests can run without mutating the real artifact helper paths.
- Explicit `stop_nuc4` and `disarm_nuc4_watchdog` now use captured statuses.
- If explicit stop fails, the launcher keeps `GNB_STARTED=1` and logs `STOP_NUC4_UNCERTAIN`, allowing EXIT cleanup to retry.
- If watchdog disarm fails, it keeps `WATCHDOG_ARMED=1` for EXIT cleanup retry.

## Mocked scenarios

### Scenario 1: `start_gnb_fail`

Injected behavior:

- `start_gnb` returns `51`.

Expected behavior:

- skip strict gate
- skip UE launch
- run explicit `stop_nuc4`
- disarm watchdog
- package/retrieve [host-redacted] path
- final checks
- exit `51`

Observed:

- `SCENARIO_PASS scenario=start_gnb_fail rc=51`
- Call log included `nuc4_stop.log`.
- Call log did not include strict gate or UE launch.

### Scenario 2: `gate_fail_stop_fail`

Injected behavior:

- strict gate returns `42`
- explicit `stop_nuc4` returns `77`

Expected behavior:

- skip UE launch
- preserve first failure as final rc `42`
- log `STOP_NUC4_UNCERTAIN`
- run EXIT `cleanup_stop_nuc4`

Observed:

- `SCENARIO_PASS scenario=gate_fail_stop_fail rc=42`
- Call log included `nuc4_cleanup_stop.log`.
- Call log did not include UE launch.
