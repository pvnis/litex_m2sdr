## Bugs found and fixed

### Mandatory-step failures did not abort

The new `preflight_fail` mock returned rc `31` from [host-redacted] preflight. The launcher logged the failed preflight but continued through upload, watchdog arm, gNB start, UE start, stop, package, retrieve, and final checks.

Root cause:

- `must` used a local variable named `rc`.
- `capture_cmd` also used a local variable named `rc`.
- Bash dynamic scoping caused `printf -v rc ...` inside `capture_cmd` to update its own local `rc`, not the caller's `rc`.
- Result: `must` always saw `rc=0` even when the command failed.

Fix:

- Renamed the `must` status variable to `must_rc`.
- Added `must_or_exit` and used it for mandatory pre-RF steps:
  - [host-redacted]/sens preflight
  - helper uploads
  - helper chmod
  - [host-redacted] watchdog arm

This keeps the intended boundary:

- before RF starts: fail closed and exit
- after gNB may have started: continue through stop/disarm/package/retrieve/final checks

## Expanded mocked scenarios

The harness now covers four local scenarios:

- `preflight_fail`: [host-redacted] preflight returns `31`; observed only one SSH preflight call, no upload, no watchdog, no gNB, no UE.
- `start_gnb_fail`: gNB start returns `51`; observed skip gate/UE, stop/disarm/package/retrieve/final checks, exit `51`.
- `gate_fail_stop_fail`: strict gate returns `42`, explicit stop returns `77`; observed skip UE, preserve final rc `42`, retry stop in EXIT cleanup.
- `happy_path`: all mocked calls succeed; observed strict gate, prearm, UE start/wait, stop, disarm, package, retrieve, and final checks, exit `0`.
