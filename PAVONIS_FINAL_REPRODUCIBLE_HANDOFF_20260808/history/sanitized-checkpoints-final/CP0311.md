## Interpretation

CP309's waveform-negative result still stands, but CP311 refines the timing
diagnosis:

- The earlier wrapper-based UTC join was off by about `3.991 s` for CP300.
- The RF-hook wall clock is the better timing basis for this branch.
- On that basis, the native timed CP300 PRACH writes appear consistently late
  relative to the saved gNB PRACH receive windows, not randomly absent.
- The miss is large enough that applying a negative RF-driver offset is unsafe:
  the callback only had about `0.740-1.466 ms` of post-sync TX lead, while the
  observed phase error is about `18 ms`.

The next useful live rung should reuse the CP300 condition that actually reached
valid PRACH, then apply only a positive PRACH timestamp offset to target the
next gNB PRACH window. The CP300 scheduled-TX-to-next-window offsets cluster
around `141.6 ms`, which is about `1.632M` samples at `11.52 MS/s`.

Under the current unstable control link, that live run should remain gated by
the watchdog launcher and must only start UE TX after both hosts pass no-RF
preflight and the gNB strict gate passes.
