# Checkpoint 314: self-contained native no-offset control

## Purpose

Run a CP300-style control using the CP312 self-contained two-NUC
gate/orchestrator pattern, but with native timing and no PRACH offset. This
checks whether CP312's no-PRACH result was caused by the self-contained
orchestration pattern or by UE acquisition/SFN-sync instability in that specific
run.

## Interpretation

CP314 proves the self-contained NUC-owned pattern can still reproduce CP300's
valid UE PRACH TX condition. CP312's no-PRACH result was therefore an
acquisition/SFN-sync miss in that run, not a fundamental failure of the
self-contained gate/orchestrator design.

CP314 also independently repeats the CP311 timing finding: native PRACH writes
are consistently late relative to the saved gNB PRACH receive windows. The next
useful live rung is a self-contained positive-offset retry using the fresher
CP314-derived target:

- `PAVONIS_RF_BLADE_TX_DBG_PRACH_TIME_OFFSET_SAMPLES=1637172`
