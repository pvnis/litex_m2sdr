# Checkpoint 316: self-contained positive offset from CP314 control

## Purpose

Retry the positive-offset PRACH timing hypothesis using the self-contained
two-NUC gate/orchestrator pattern and the fresher CP314-derived offset. CP314
proved the self-contained pattern can still reach real UE PRACH TX, and its
timing audit measured the native scheduled TX writes about one PRACH-period late
relative to the saved gNB PRACH receive windows.

CP316 therefore used:

- `PAVONIS_RF_BLADE_TX_DBG_PRACH_TIME_OFFSET_SAMPLES=1637172`
- no TX guard
- no restart-on-first-high-peak
- PRACH burst-only TX

## Interpretation

CP316 directly tested the positive-offset timing hypothesis. The offset was
applied, UE produced five valid PRACH TX dumps, and the RF-hook timing audit says
the scheduled TX estimate was close to the target PRACH receive rows.

The gNB still saw only receiver-floor PRACH windows and accepted no preambles.
This makes another blind timing offset retry low value. The next rung should
inspect or augment the gNB RX capture path and RF-path visibility around the
target PRACH windows, rather than continuing to [interface-redacted] only the UE TX timestamp.

The known `freq_offset=7` UE value is not being treated as a new mismatch here:
earlier CP18/CP19/CP20/CP256 work already established that this is the expected
UE-side translation for the gNB-side `rb_offset=8` configuration in this setup.
