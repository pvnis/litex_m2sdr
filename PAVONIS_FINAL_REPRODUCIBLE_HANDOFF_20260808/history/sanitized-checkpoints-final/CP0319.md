# Checkpoint 319: OCUDU targeted UL-symbol raw-save instrumentation

## Purpose

Add receive-side observability for the next PRACH live rung. CP316 applied the
positive PRACH TX offset and moved the scheduled TX estimate close to the
intended gNB PRACH rows, but CP318 found no convincing UE waveform in the saved
gNB PRACH raw corpus. CP318 also showed that the auxiliary UL-symbol raw files
did not cover the target PRACH SFN/slot rows.

CP319 therefore adds a deterministic raw-save trigger to the existing OCUDU
`PAVONIS_UL_SYMBOL_DUMP` debug block.

## Source change

Changed file:

- `/home/[host-redacted]/CLionProjects/ocudu/lib/phy/lower/processors/uplink/uplink_processor_impl.cpp`

New optional environment variables:

- `PAVONIS_UL_SYMBOL_RAW_TARGET_SFN_MOD`
- `PAVONIS_UL_SYMBOL_RAW_TARGET_SFN_REM`
- `PAVONIS_UL_SYMBOL_RAW_TARGET_SLOT`

Behavior:

- The existing `PAVONIS_UL_SYMBOL_DUMP` block still only runs when that debug
  env var is set.
- Existing raw-save behavior based on `PAVONIS_UL_SYMBOL_RAW_MAX`,
  `PAVONIS_UL_SYMBOL_RAW_PEAK_MIN`, and `PAVONIS_UL_SYMBOL_RAW_RMS_MIN` is
  preserved.
- The new target filter can also save raw symbols when the current slot matches
  the configured SFN modulo/remainder and/or slot filter.
- Targeted saves still honor `PAVONIS_UL_SYMBOL_RAW_MAX`.
- The manifest format is unchanged; targeted raw files appear as normal
  non-empty `raw_path` rows.

For the CP316/CP320-style PRACH pattern, the intended live-run settings are:

```bash
PAVONIS_UL_SYMBOL_RAW_TARGET_SFN_MOD=16
PAVONIS_UL_SYMBOL_RAW_TARGET_SFN_REM=1
PAVONIS_UL_SYMBOL_RAW_TARGET_SLOT=4
```

This should save all UL symbols for PRACH slots matching `sfn % 16 == 1` and
`slot == 4`, without depending on the receive amplitude crossing a peak/RMS
threshold.
