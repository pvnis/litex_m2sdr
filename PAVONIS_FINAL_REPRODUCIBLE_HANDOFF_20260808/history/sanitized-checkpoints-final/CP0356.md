was to identify whether the partial replay cases can be explained by static
waveform content, amplitude, phase, or the CP341 nearest-gNB timing metadata

## Interpretation

CP356 found no static CP339 dump-content explanation for the mixed controlled
replay results. The templates are near-identical, have similar amplitude, and
the live-gNB offline timing/search metrics are uniformly weak. The clean passes
on dump000003 and dump000005, plus all-visible dump000002, confirm CP339
waveforms can traverse the controlled RF path. The partial dump000001 and
dump000004 results are more consistent with replay/capture intermittency,
window alignment, or transient device/RF state than with a bad UE dump format.

For the next live UE attempt, the useful hypothesis is not a new blind PRACH
timestamp offset. It is that the UE is transmitting CP339-like PRACH, but the
live gNB capture/detector path still is not seeing a sufficiently aligned or
strong copy in the expected raw windows. Before spending another live UE TX
attempt, a fresh gNB strict-gate/no-UE readiness checkpoint is still prudent;
then the next live run should preserve the current all-or-nothing collection
pattern and focus on gNB raw saves around the expected CP339 cadence.
