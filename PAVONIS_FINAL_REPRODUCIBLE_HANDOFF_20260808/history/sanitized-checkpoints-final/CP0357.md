## Interpretation

CP357 failed before any live UE work. This is the same class of strict-gate
regression seen in CP335: gNB reached ready markers, but M2SDR TX writeStream
timeouts accumulated in the strict-gate window. The live UE PRACH run should
not proceed while this gate is failing.

The immediate fix is to clean the stale [host-redacted] wrapper and retry the strict gate
from a clean process state, matching the CP336 -> CP337 recovery pattern.
