## Interpretation

CP366 did not test the controlled replay into the active gNB. The safety gate
worked: it prevented the CP361 waveform replay from transmitting into a gNB run
that had already entered the M2SDR TX-timeout failure mode.

This reproduces the same intermittent strict-gate failure class seen in CP357
and CP294: gNB reaches ready markers, then the strict gate sees thousands of
M2SDR TX writeStream timeouts. The immediate next checkpoint must be a [host-redacted]
force cleanup before retrying CP366's controlled-injection idea.
