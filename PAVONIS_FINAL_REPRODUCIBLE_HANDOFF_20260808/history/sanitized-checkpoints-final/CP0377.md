## Finding

The main concrete mismatch is center frequency:

```text
active gNB nominal UL center: 1747500000 Hz
CP374 replay TX actual:       1747505998 Hz
CP364 controlled RX center:   1747505998 Hz
delta vs active UL center:    +5998 Hz
```

This does not invalidate CP364: CP364 proves the CP361 waveform is strongly
visible when the controlled receiver is [interface-redacted] to the replay's actual frequency.
But it also means CP364 did not test the exact active-gNB UL-center condition.

The PRACH/RB mapping itself does not look like the next mismatch:

- active gNB advertises `msg1-FrequencyStart=8`
- prior CP18/CP19/CP20/CP256 work established this is the correct gNB-side
  coordinate for the UE-side `freq_offset=7` waveform family
- CP374/CP376 show the waveform is absent in active-gNB saved PRACH rows even
  when phase is swept through those rows

## Interpretation

CP377 identifies a concrete, low-risk next RF hypothesis: repeat the CP374
period-drift active-gNB sweep, but transmit at the active gNB nominal UL center
`1747500000 Hz` rather than `1747505998 Hz`. Keep the same self-contained
strict-gate pattern and the same `PERIOD_MS=159` phase sweep.

If that still produces no active-gNB raw copy, the remaining work should move
below replay phase/frequency and instrument or capture closer to the active gNB
RF input/detector input.
