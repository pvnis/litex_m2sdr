## Interpretation

CP400 confirms that the [host-redacted] receive floor is currently degraded without our TX
running. That means the CP396 controlled baseline degradation cannot be treated
as only a waveform, replay timing, or active-gNB problem.

The lack of kernel faults and the normal CP399 health snapshot point away from
a simple software crash or SDR overtemperature. The current evidence fits:

- external/passband RF content or local interference,
- physical RF path state,
- receiver/device state that varies over time,
- or an active RF-chain/path effect that can relax after idle.

This still does not prove passive antenna overheating, but it makes the
user-suggested "path changes after activity" theory worth testing as an
idle/cooldown behavior rather than as a measured RFIC overtemperature.

## Next Action

Run a no-TX idle/cooldown repeat before more TX. The most useful next checkpoint
is a [host-redacted]-owned script that idles for several minutes, then repeats a small
3 MHz no-TX floor set. If the floor collapses toward CP155 levels, that supports
time/idle-sensitive RF-chain/path state. If it remains high, external
interference or physical path state becomes more likely.
