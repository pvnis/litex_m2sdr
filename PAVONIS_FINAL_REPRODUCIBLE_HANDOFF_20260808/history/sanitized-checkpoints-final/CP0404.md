## Purpose

Rerun the CP394-style active-gNB CP361 replay with the Soapy low-threshold tap
immediately after CP402 restored the CP45 controlled baseline. The goal was to
test the active-gNB boundary only while the controlled RF path was known to be
freshly recovered.

The strict gate was preserved so [host-redacted] would not transmit if the active gNB
started in the M2SDR timeout failure state.

## Interpretation

CP404 is not an active-gNB replay result. It is a strict-gate block: the
controlled CP45 baseline had just recovered in CP402, but the active gNB startup
again entered the M2SDR TX writeStream-timeout failure state. The safety gate
worked correctly and prevented replay TX.

This keeps two branches distinct:

- CP402 proves the controlled RF replay path can recover and pass cleanly.
- CP404 shows the active gNB/M2SDR startup path can still fail independently
  with TX writeStream timeouts.

Before spending another active-gNB replay attempt, recover the gNB strict gate
again or inspect/reset the active gNB/M2SDR state.
