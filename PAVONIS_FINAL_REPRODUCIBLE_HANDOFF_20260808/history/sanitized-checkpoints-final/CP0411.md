## Interpretation

CP411 is not an active-gNB replay result. It is a strict-gate safety block, and
the safety gate worked correctly.

The important result is that the active gNB/M2SDR startup path re-entered the
same Soapy TX writeStream-timeout state as CP404 even after a clean no-TX floor
and clean controlled CP45 replay. This separates the active-gNB startup/TX path
from the gross RF path: the controlled RF path is healthy, but active gNB can
still begin with M2SDR TX timeouts.

The next useful rung should focus on active-gNB/M2SDR startup state, stop/reset
behavior, or strict-gate timing before spending another replay attempt.
