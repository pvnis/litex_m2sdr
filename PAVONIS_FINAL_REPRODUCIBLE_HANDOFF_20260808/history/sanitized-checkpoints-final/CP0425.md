## Patch Behavior

`radio_soapy_device.h` now wraps:

- `setBandwidth()`
- `getSampleRate()`
- `getFrequency()`
- `getGain()`
- `getBandwidth()`

`radio_soapy_impl.cpp` now parses optional environment variables:

- `OCUDU_SOAPY_RF_BW_HZ`
- `OCUDU_SOAPY_TX_BW_HZ`
- `OCUDU_SOAPY_RX_BW_HZ`

Direction-specific values override the common value. Invalid, empty, non-finite,
or non-positive values are ignored.

For each configured TX/RX channel, the constructor still configures sample rate,
center frequency, and gain first. If a requested bandwidth is present, it then
sets Soapy bandwidth for that channel.

It always logs per-channel readback:

```text
Soapy TX ch0 readback: sample_rate_Hz=... frequency_Hz=... gain_dB=... bandwidth_Hz=...
Soapy RX ch0 readback: sample_rate_Hz=... frequency_Hz=... gain_dB=... bandwidth_Hz=...
```

## Compatibility

The bandwidth set is opt-in. With no new environment variables set, behavior is
unchanged except for info-level readback logging.

This preserves the existing active-gNB harness until a checkpoint explicitly
sets `OCUDU_SOAPY_RF_BW_HZ=10000000` or a direction-specific override.
