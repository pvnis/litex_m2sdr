## Interpretation

The CP425/CP426 patch is runtime-active on [host-redacted]: both Soapy bandwidth set calls
and readback logs appeared with `10000000 Hz`.

The strict gate failed because the M2SDR TX writeStream-timeout startup state
reappeared. This is a gNB/M2SDR startup/device-state failure, not a missing
bandwidth-readback failure. No sens TX was spent.

Because CP427 used the common bandwidth env, it set both TX and RX bandwidth.
The next no-replay isolate should set RX bandwidth only with
`OCUDU_SOAPY_RX_BW_HZ=10000000` and leave TX bandwidth untouched. That tests the
active-gNB receive hypothesis without also perturbing the downlink TX bandwidth
path.
