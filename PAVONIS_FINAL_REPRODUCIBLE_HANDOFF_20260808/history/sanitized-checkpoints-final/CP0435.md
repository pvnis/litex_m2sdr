# Checkpoint 435 - gNB Strict Gate with Soapy RX Tap Always-On Pass

Date: [date-redacted]
Stamp: [date-redacted]

## Purpose

Verify the Soapy RX tap runtime path before spending another sens replay.

CP431 requested the Soapy tap, but used the default CP366 package helper, which
does not package `/tmp/pavonis_soapy_rx_manifest.tsv`. CP435 reruns a no-sens
gNB strict gate with:

- RX-only Soapy BW10
- Soapy RX tap always-on, with no arm file
- CP383 Soapy-aware package helper

No sens TX was staged.

## Interpretation

CP435 proves the deployed [host-redacted] gNB can execute the Soapy RX tap and produce a
manifest under the RX-only BW10 startup condition. The CP431 missing Soapy
manifest should not be interpreted as proof that the binary tap was inactive.
It was at least partly a harness/package issue: CP431 used the default CP366
package helper, while Soapy-tap checkpoints need the CP383 package helper.

For the next active replay that needs Soapy RX evidence:

- keep RX-only `OCUDU_SOAPY_RX_BW_HZ=10000000`
- leave TX bandwidth unset
- use `cp383_nuc4_package_stage6_soapy_rx_remote.sh`
- either keep the Soapy tap always-on, or explicitly prove arm-gated tap rows
  before relying on them
