## Interpretation

CP442 closes the Soapy instrumentation gap from CP438. The active Soapy RX tap
now captures the replay interval and overlaps PRACH windows, but no selected
Soapy fragment reaches even the loose `0.25` screen. The controlled reference
remains about `0.94`.

CP440's PRACH phase was not close: the nearest TX-to-PRACH wall-clock distance
was `18.474418 ms`, so CP440 is not a useful PRACH-acceptance timing attempt.
However, the Soapy near-TX correlation is independent of PRACH window alignment.
The `+/-10 ms` near-TX Soapy subset still tops out at only `0.1888`, and the
top-amplitude selected Soapy chunk tops out at `0.2245`.

Current working conclusion: with active gNB running, RX-only BW10, and
arm-gated Soapy capture at GO, the gNB-side Soapy stream still does not show a
strong CP361 replay copy near the sens TX events. This pushes the next question
below PRACH processing and toward active gNB/M2SDR runtime RX behavior, duplex
state, self-desense/interference, or physical-path health under active gNB
conditions.

The next RF checkpoint should bracket this with a controlled passive BW10 replay
again. If controlled BW10 is still strong, the active runtime path is the focus.
If controlled BW10 has degraded, stop active-gNB work and debug the physical RF
path/device state first.
