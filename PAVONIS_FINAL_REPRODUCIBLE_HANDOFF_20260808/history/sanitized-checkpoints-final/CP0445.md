## Key Difference

The RX-facing target settings match where they matter:

- same RX center: `1747500000 Hz`
- same sample rate: `11520000`
- same RX bandwidth: `10000000 Hz`
- same RX gain: `50`
- same M2SDR channel 0

The important difference is runtime state:

- CP443 is a passive RX-only `test_record.py` capture.
- CP440 is an active full gNB runtime using Soapy TX and RX together on the
  same M2SDR/AD9361 path.
- CP440 also has DL TX active at `1842500000 Hz`; TX bandwidth readback stayed
  at the default `30720000 Hz` while only RX bandwidth was forced to BW10.

This audit therefore supports the CP443 interpretation: the gross physical path
and passive BW10 receive path were still healthy immediately after CP440, but
the active gNB runtime receive path did not see the replay waveform strongly.

## Source Check

The local Soapy validator does not expose an obvious RX-only gNB mode. It
requires exactly one TX stream and one RX stream for M2SDR, and rejects
`continuous` TX mode for M2SDR. The supported config surface includes
`discontinuous` and `same-port`, but not a simple "disable TX while keeping gNB
RX" switch.

That means the next low-risk RF rung should not be a blind phase retry. It
should change one active-runtime variable tied to self-desense/interference and
keep RX/capture settings identical.

## Interpretation

The antenna-overheating/gross-path-collapse theory is now unlikely as the
primary cause of CP440. CP443 proved a strong passive CP361 copy at the same
UL center, BW10, RX gain 50, shortly after the active failure.

The strongest current hypothesis is active-runtime receive degradation: full
duplex M2SDR/AD9361 state, DL TX leakage/self-desense, or another gNB Soapy
runtime effect.

## Next Rung

Run one self-contained active replay with the CP440 RX/Soapy settings unchanged
but with more DL amplitude backoff, for example `tx_gain_backoff: 20` instead
of `10`.

Keep:

- strict GO/CANCEL gate before sens TX
- RX center `1747500000 Hz`
- RX BW `10000000 Hz`
- RX gain `50`
- sens replay waveform CP361 dump000001
- arm-gated periodic Soapy capture

Compare against CP440/CP442:

- If active Soapy near-TX correlation rises materially, especially above
  `0.25` or toward the controlled `0.94`, the DL self-desense/interference
  hypothesis gains weight.
- If it remains weak, focus below "DL power too high": M2SDR active channel
  mode, timed full-duplex startup, RX alignment state, Soapy stream handling, or
  a runtime-only analog state difference.
