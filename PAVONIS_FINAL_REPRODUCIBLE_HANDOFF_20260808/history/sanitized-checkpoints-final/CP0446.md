## Purpose

Test the CP445 hypothesis that active gNB DL energy might contribute to the
weak active-RX copy. CP446 kept the CP440 RX/Soapy settings but changed the gNB
DL amplitude control from `tx_gain_backoff: 10` to `tx_gain_backoff: 20`.

The strict GO/CANCEL gate remained in force, so [host-redacted] would transmit only if
the gNB started without M2SDR TX timeout failure.

## Interpretation

CP446 did not test active-RX correlation because the safety gate correctly
blocked sens TX. The result is still useful: the `tx_gain_backoff: 20` variant
hit the known M2SDR TX writeStream-timeout startup failure state even though RX
BW10 readback succeeded.

This does not prove that backoff 20 is intrinsically invalid, because earlier
work showed the timeout state can recur nondeterministically. It does mean the
next rung should be a no-replay gNB strict-gate recovery/retry for the same
TX-backoff-20 start condition before spending another replay attempt.
