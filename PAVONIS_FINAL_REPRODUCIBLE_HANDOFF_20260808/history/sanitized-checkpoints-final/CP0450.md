## Interpretation

CP450 answered the TX-backoff-20 active-replay question: the reduced-DL-energy
variant can pass strict startup health and can run a clean [host-redacted] replay, but
it still does not produce a strong active gNB RX copy or any accepted PRACH.

Because CP450 timing was not close (`14.6 ms` nearest TX-to-PRACH distance), it
is not a useful PRACH-accept timing attempt. The important result is active
Soapy visibility: overlap and near-TX subsets stayed below `0.25`, while the
CP422 passive BW10 reference remains near `0.94`. Reducing `tx_gain_backoff`
from the CP440 value did not close the active/passive gap.

The next useful rung is another controlled passive BW10 bracket after CP450, or
source-level active-runtime instrumentation, not another blind active replay.
