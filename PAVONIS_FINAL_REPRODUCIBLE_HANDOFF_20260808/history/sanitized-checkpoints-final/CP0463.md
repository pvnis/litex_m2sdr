## Interpretation

CP463 is not a valid active replay attempt because the strict gate correctly
cancelled before GO. It is a valid instrumentation result: enabling this much
runtime tracing perturbs the active gNB enough to reproduce the TX writeStream
timeout failure state.

The high-volume trace sources are especially suspect:

- `OCUDU_SOAPY_TRACE=1` logs `readStreamStatus ret=-1` roughly every 1 ms.
- `OCUDU_SOAPY_RX_TRACE=1` logs very frequent RX receive/acquire events.
- Combined with TX/RX/M2SDR traces, the log path produced over `100000` trace
  lines during startup.

Next trace rung should be lower-impact and [host-redacted]-only first: keep strict gate,
disable OCUDU wrapper/RX/TX trace spam, and retain only bounded M2SDR TX
slip/RMS/DMA probes. If that passes, then use the same lower-impact trace set
for an active replay.
