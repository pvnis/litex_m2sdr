## Interpretation

Increasing `tx_gain_backoff` from `20` to `40` did not improve active-gNB PRACH
visibility. The detector maximum was lower than CP472 (`0.189` vs `0.215`), no
row passed threshold, and the relevant active correlation subsets stayed below
`0.25`.

This weakens the simple "gNB downlink amplitude self-desenses RX" branch for the
current setup. It does not rule out active full-duplex/runtime RX state as the
remaining problem, but a static downlink baseband backoff alone is not enough.

The run also landed late in timing (`+43.94 ms` nearest), which reinforces that
wall-clock-derived replay phase is not stable run to run. However CP472 already
landed close (`-3.75 ms`) without improving detector or correlation, so the next
rung should not be another blind timing tweak. Prefer a NUC-owned active-runtime
instrumentation checkpoint that can directly compare replay-time M2SDR TX/RX
state, or a controlled gNB-RX-only substitute if one can be made without breaking
the strict gate.
