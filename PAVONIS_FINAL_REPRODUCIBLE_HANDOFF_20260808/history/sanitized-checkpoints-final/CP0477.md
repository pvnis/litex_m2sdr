# Checkpoint 477 - LiteXM2SDR TX Probe Arm Source Patch

Date: [date-redacted] UTC

## Purpose

Add a bounded way to make the existing M2SDR TX probes observe the replay
window instead of only gNB startup.

CP467/CP470/CP472/CP474 showed that the current TX probes are low-impact, but
CP469 showed they are exhausted roughly 30 seconds before the [host-redacted] replay.
The next active checkpoint needs replay-time M2SDR TX evidence without
reintroducing CP463's high-volume trace timeout failure.

## File Changed

- `/home/[host-redacted]/CLionProjects/litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp`

## Change

Added environment-gated arm-file support around the existing TX probe paths:

- `M2SDR_SOAPY_TX_PROBE_ARM_FILE`
- `M2SDR_SOAPY_TX_PROBE_ARM_POLL_PERIOD`

The helper returns armed immediately when `M2SDR_SOAPY_TX_PROBE_ARM_FILE` is not
set, so default behavior remains unchanged.

When an arm file is set, the following existing probes do not count, log, or
dump until the file exists:

- `M2SDR_SOAPY_TX_RMS_LOG`
- `M2SDR_SOAPY_TX_DUMP_PATH`
- `M2SDR_SOAPY_TX_DMA_DUMP_PATH`

## Interpretation

This patch creates the missing primitive for the next active checkpoint: keep the
same bounded TX RMS/input/DMA probes, but delay them until the strict gNB gate
arms the PRACH/Soapy dump file. That should capture M2SDR TX evidence near the
sens replay window while preserving the strict GO/CANCEL safety path.
