# Checkpoint 482 - Active RX Timestamp Source Audit

Date: [date-redacted] UTC
Mode: local source audit only; no RF, no SSH

## Purpose

Audit the active RX instrumentation and timestamp path after CP479/CP481 showed
that replay-time gNB TX exists and can align to a PRACH window within
`+0.107558 ms`, while the best-aligned RX window remains at noise-floor
amplitude. The goal was to identify the next useful rung without spending RF on
blind replay timing or gain changes.

## Findings

1. Soapy RX `ret.ts` is captured before lower-PHY processing.

   In `radio_soapy_rx_stream.cpp`, `receiver.receive()` obtains the Soapy RX
   hardware time and converts it to samples as `ret.ts` when
   `SOAPY_SDR_HAS_TIME` is present. If time metadata is absent, it reconstructs
   from `last_sample_ts`/`last_time_ns`.

   Relevant lines: `157..173`, with `last_sample_ts` advanced at `205..209`.

2. The Soapy RX dump is pre-lower-PHY.

   `PAVONIS_SOAPY_RX_DUMP` writes `/tmp/pavonis_soapy_rx_manifest.tsv` after
   Soapy samples are copied into the receive buffer and before lower-PHY
   timestamp normalization. It logs `ret_ts`, `nsamples`, `loops`,
   `overflows`, wall time, RMS/peak, arm file, and optional raw path.

   Relevant lines: `250..379`.

3. Lower PHY changes the timestamp domain before UL/PRACH processing.

   In `lower_phy_baseband_processor.cpp`, `ul_process()` receives
   `rx_metadata.ts`, updates `last_rx_timestamp` using the raw receive
   timestamp, then queues UL processing with
   `apply_timestamp_sfn0_ref(rx_metadata.ts)`.

   Relevant lines: `149..163`.

4. `apply_timestamp_sfn0_ref()` subtracts `start_time_sfn0`.

   In `lower_phy_baseband_processor.h`, the helper adds hyper-frame span only
   if needed for wrap protection, then returns `timestamp - start_time_sfn0`.
   `start_time_sfn0` is set in `lower_phy_baseband_processor::start()` from
   `sfn0_ref_time`.

   Relevant lines: header `173..182`, member at `199`; `.cpp` `48..53`.

5. Downstream UL-symbol and PRACH manifests are in the adjusted timestamp
   domain.

   `uplink_processor_impl.cpp` writes symbol summaries after CFO correction and
   before PRACH/PUxCH processing. Its manifest fields are
   `symbol_start_ts`/`symbol_end_ts`, which come after the lower-PHY timestamp
   normalization.

   Relevant lines: `223..380`.

   `prach_processor_worker.cpp` starts collecting when the current context slot
   equals the PRACH request slot, captures `collection_start_timestamp`, and
   writes `window_start_ts`/`window_end_ts` immediately before PRACH OFDM
   demodulation.

   Relevant lines: `20..59`, `109..115`, `147..265`.

6. Detector trace is post-demod/result-level only.

   `prach_detector_generic_impl.cpp` traces detector config, RSSI, threshold,
   best candidate, preamble-0 candidate, delay checks, and accepted count. It
   does not prove whether the upstream RX timestamp domain was shifted before
   the PRACH worker saw the window.

   Relevant lines: `175..260`.

7. Existing Soapy RX trace can expose cadence/lag but was disabled in CP479.

   `OCUDU_SOAPY_RX_TRACE` logs receive latency, `ret.ts`, delta timestamp, and
   hardware-time lag when enabled. CP479 relied on the Soapy RX dump manifest
   and did not enable this trace.

   Relevant lines: `213..243`.

## Gap

The current artifacts show both sides of the lower-PHY boundary, but not the
boundary itself:

- Soapy RX manifest: raw `ret_ts` before lower-PHY normalization.
- UL-symbol / PRACH manifests: adjusted timestamps after
  `apply_timestamp_sfn0_ref()`.

There is no bounded manifest that logs raw `rx_metadata.ts`, adjusted timestamp,
`start_time_sfn0`, receive buffer length, and wall time in the same row. CP479
appeared numerically consistent, but that is an inference from separate layers,
not direct evidence.

## Interpretation

CP482 keeps the ladder pointed at active RX timestamp/window mapping or active
RX/runtime coexistence, not at detector threshold, gross gNB TX absence, or
blind replay phase [interface-redacted].

The next useful rung is local instrumentation in
`lower_phy_baseband_processor::ul_process()`:

- env-gated, default-off
- optional arm file, matching the existing Stage 6 instrumentation style
- bounded row count
- TSV fields: `idx`, `wall_ns`, raw `rx_metadata.ts`, adjusted timestamp,
  `start_time_sfn0`, `rx_buffer_samples`, `last_rx_timestamp_after`, and arm
  file

checkpoint that collects Soapy RX, lower-PHY timestamp bridge, UL-symbol,
