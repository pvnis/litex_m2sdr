## Findings

`same-port` is parsed as a distinct config value, and the Soapy validator allows
it. However, the Soapy runtime reduces all non-continuous modes to the same
boolean:

- `continuous` is rejected for M2SDR by the Soapy validator;
- both `discontinuous` and `same-port` pass validation;
- `radio_soapy_impl.cpp` computes `discontinuous_tx` as
  `tx_mode != continuous`;
- no Soapy/M2SDR branch distinguishes `same-port` from `discontinuous` after
  that point.

Therefore a `same-port` active replay would exercise the same Soapy TX stream
behavior as the CP487 `discontinuous` run. It is not a high-value RF branch.

The M2SDR channel-topology code also does not expose a clear active/passive
split for the tested one-channel path:

- default AD9361 init data starts in `2T2R`;
- `setupStream()` defaults RX and TX to channel `0` when no explicit channel
  list is supplied;
- a one-channel stream writes the PHY control into `1T1R` mode and sets
  `rx2tx2 = false`;
- if RX and TX streams are both opened, the driver enforces matching channel
  counts;
- after `ad9361_set_no_ch_mode()`, the driver reapplies cached RF settings
  including sample rate, bandwidth, RX frequency, TX frequency, and TX
  attenuation.

The active gNB one-channel TX+RX path and the passive RX-only channel-0 path
therefore both appear to use a one-channel `1T1R` AD9361 datapath. CP487's
strict gate also confirmed the intended RF readbacks: RX/TX bandwidth `10 MHz`,
RX frequency `1747500000`, TX frequency `1842500000`, and no startup TX
timeouts.

## Decision

Do not spend the next RF checkpoint on `tx_mode: same-port` or a blind
1T1R/2T2R topology change.

The next useful rung should directly test active-runtime receive visibility:

- either a bounded contiguous active RX dump around the replay window, so the
  known CP361 waveform can be searched across a broad sample interval outside
  sparse PRACH windows; or
- a standalone full-duplex Soapy/M2SDR recorder that mimics active TX+RX
  runtime without the gNB PHY, if existing tooling can do this in a single
  NUC-owned script.

Given the unstable laptop/SSH link, any RF attempt must remain all-or-nothing
and NUC-owned after launch, with the existing [host-redacted] strict GO/CANCEL gate
preserved before [host-redacted] transmits.
