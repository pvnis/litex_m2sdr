# Checkpoint 497 - Standalone Soapy Full-Duplex Design Audit

Date: [date-redacted] UTC

## Purpose

Define the next safe rung after CP495 moved the failure below gNB PHY/detector:
test the [host-redacted] M2SDR active full-duplex Soapy runtime without the gNB stack, while
preserving the same [host-redacted] gated CP361 replay path.

## Audit Findings

- OCUDU active gNB opens LiteXM2SDR Soapy streams as `SOAPY_SDR_CS16`, not
  `SOAPY_SDR_CF32`.
- LiteXM2SDR `test_record.py` is RX-only and uses `CF32`, so it is not a close
  enough active-path isolate by itself.
- LiteXM2SDR `m2sdr_loopback_latency.py` proves Python Soapy can open TX and RX
  streams concurrently on one device, activate both, and coordinate a TX worker
  with RX reads.
- The CP492/CP495 analyzer can be reused if the standalone recorder writes
  `/tmp/pavonis_soapy_rx_manifest.tsv` plus analyzer-compatible CF32 raw files.

## CP498 Design

- [host-redacted] owns the run after launch:
  - serve HTTP gate as `PENDING`;
  - open/configure M2SDR RX and TX streams at the active gNB RF settings;
  - activate RX/TX, start a bounded zero-CS16 TX worker, and begin RX capture;
  - publish `GO` only after timestamped RX is live and capture is armed;
  - publish `CANCEL` on any pre-GO failure.
- [host-redacted] reuses the existing CP325 prebuild/wait/replay/package script.
- Sens gate polling will be fast so the first replay burst lands in the bounded
  CP495-sized capture window.
- Recorder stream format should be `CS16` to match OCUDU. Captured int16 I/Q is
  scaled to CF32 with the same full-scale convention as the active gNB dump tap
  for template-search comparability.
