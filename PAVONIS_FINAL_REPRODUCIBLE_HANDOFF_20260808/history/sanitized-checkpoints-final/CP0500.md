## Interpretation

CP500 rules out a modest continuous downlink-frequency TX tone, at gNB-like RMS
scale, as the cause of the CP495 active-gNB raw-RX disappearance. Together,
CP499 and CP500 show that standalone LiteXM2SDR `CS16` full-duplex reception is
healthy with both zero TX and low-amplitude nonzero TX.

The remaining gap is more specific to the active gNB condition: actual gNB TX
sample shape/PAPR/duty cycle, gNB runtime scheduling or timestamp behavior, or a
state reached by the gNB radio stack rather than by generic full-duplex stream
activation.

## Next Step

Run the same standalone delayed full-duplex isolate, but use an actual CP495
gNB TX input capture as the [host-redacted] TX waveform. If CP361 stays strong, actual gNB
TX sample content is not sufficient by itself and the problem moves further
toward gNB runtime behavior. If CP361 disappears, the branch becomes actual gNB
downlink waveform/self-interference.
