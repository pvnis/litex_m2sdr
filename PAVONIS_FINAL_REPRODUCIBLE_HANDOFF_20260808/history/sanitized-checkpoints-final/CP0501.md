## Interpretation

CP501 rules out actual CP495 gNB TX sample content, by itself, as the cause of
the CP495 active-gNB raw-RX disappearance. The standalone M2SDR can receive
CP361 strongly with:

- TX stream active and writing zeros (CP499)
- TX stream active with a continuous downlink-frequency tone (CP500)
- TX stream active while looping the actual CP495 gNB TX input `CS16` samples
  (CP501)

The remaining gap is now specific to the full active gNB runtime path: radio
stack scheduling/timestamp behavior, RX/TX stream interaction as driven by gNB,
runtime state, or another gNB-only side effect. It is not explained by gross RF
path loss, generic M2SDR full-duplex activation, modest downlink tone
self-interference, or the isolated gNB TX waveform.

## Next Step

Return to the active-gNB ladder with a narrow runtime-focused split. The next RF
attempt should preserve strict GO/CANCEL gating and delayed raw capture, then
change one gNB-runtime variable rather than replay timing or standalone RF: for
example disable or bound gNB downlink writes during the replay window, or add a
runtime marker/tap proving whether the active gNB's Soapy RX stream is being
drained and timestamped like the standalone recorder.
