## Purpose

Deploy the default-off LiteXM2SDR split prepared in CP506:

`M2SDR_SOAPY_RX_IGNORE_TIMED_ACTIVATION=1`

When enabled, an RX `activateStream(...SOAPY_SDR_HAS_TIME...)` request logs the
requested time and starts RX immediately instead of entering the timed-start
drop/alignment path. This sets up the next active-gNB RF checkpoint to test
whether CP361 disappears because the active gNB uses timed RX activation while
the standalone full-duplex positive controls use immediate activation.

## Interpretation

The active-gNB RX timed-activation split is ready for a live RF checkpoint.
The next run should use the CP495 delayed contiguous Soapy RX/raw capture shape
with the strict [host-redacted] GO/CANCEL gate and set only:

`M2SDR_SOAPY_RX_IGNORE_TIMED_ACTIVATION=1`

Leave `M2SDR_SOAPY_TX_ZERO_AFTER_ARM=0` for a pure split from CP495. CP504
already showed that zeroing active-gNB TX payloads after arm does not recover
CP361.

Expected branch:

- If CP361 becomes strongly visible, the active disappearance is tied to the
  timed RX activation/drop/alignment path.
- If CP361 remains absent, the problem is deeper active-gNB RX/runtime state
  rather than obvious RF config, TX payload content, or timed-start alignment.
