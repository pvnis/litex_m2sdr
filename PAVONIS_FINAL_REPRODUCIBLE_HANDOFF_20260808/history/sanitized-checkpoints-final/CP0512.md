## Purpose

Run a pure CP495-shape active RF split after CP511 deployed the ocudu
readStream fallback:

- `OCUDU_SOAPY_RX_USE_READSTREAM=1`
- `M2SDR_SOAPY_RX_IGNORE_TIMED_ACTIVATION=0`
- `M2SDR_SOAPY_TX_ZERO_AFTER_ARM=0`
- CP495 delayed contiguous Soapy RX/raw capture settings
- strict [host-redacted] GO/CANCEL gate before [host-redacted] TX

This tests whether the active gNB disappearance of CP361 is caused by the
ocudu zero-copy `acquireReadBuffer()` RX consumption path rather than the
LiteXM2SDR timed-RX activation path or active gNB TX payload content.

## Interpretation

CP512 is a valid active-gNB raw-RX recovery. Switching only the active ocudu RX
consumer from the zero-copy `acquireReadBuffer()` loop to `readStream()` is
sufficient to recover strong CP361 copies in active gNB Soapy raw capture.

This implicates the ocudu zero-copy active RX path, its remainder/timestamp
handling, or its interaction with LiteXM2SDR zero-copy buffers as the cause of
the CP495/CP504/CP508 active raw-RX disappearance. It also rules out timed RX
activation as the blocker for raw visibility, because CP512 kept timed
activation enabled and still recovered CP361.

The recovery is not yet a PRACH-detector recovery. PRACH predemod direct
correlation remained below `0.022`, and the detector accepted `0` rows. The next
branch should compare the readStream-recovered Soapy raw timestamps against
lower-PHY/PRACH window scheduling and audit what the zero-copy path was doing
to buffer continuity/timestamps before the PRACH extractor.
