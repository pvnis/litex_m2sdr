## Timing Observation

The CP518 TX-to-PRACH wall-time table no longer brackets a TX call within
sub-ms of a PRACH row:

- `TIMING_NEAREST_MIN_MS=21.754313`
- nearest row: call `1222`, PRACH idx `35`
- `TIMING_NEAREST_SIGNED_DELTA_MS=-21.754313`

For comparison, CP515 had calls near the target PRACH rows at `+0.193563 ms`
and `-0.938545 ms`.

Wall-time alignment between the two hosts should not be treated as a perfect
absolute truth, but the captured signal evidence agrees with it: CP518 raw
remained strong, while PRACH predemod returned to noise-level correlation.

## Interpretation

CP518 falsifies the simple `TIMED_LEAD_MS=0.701` fix. Delaying the scheduled
stream start by that amount did not move the CP515 partial copy into PRACH
predemod; instead the PRACH windows saw no meaningful CP361 copy.

The next timing rung should not keep using `TIMED_LEAD_MS` as the main control.
The remaining lower-risk timing test is a whole-burst placement rung:

- reset `TIMED_LEAD_MS=0`
- try `FIRST_BURST_MS=586`
- keep the CP515 readStream/strict-gate setup

That isolates a one-chunk burst placement change without shifting the entire
scheduled zero/preamble stream start.
