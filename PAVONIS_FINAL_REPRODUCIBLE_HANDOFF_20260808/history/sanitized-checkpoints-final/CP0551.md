## Interpretation

CP551 is the first run in this branch to produce a non-empty gNB PRACH
detection and prove that the downstream RA scheduler/RAR path is alive after a
PRACH accept.

Do not treat the Msg3 CRC failures as a closed-loop UE failure yet. This
checkpoint replays a fixed CP361 UE transmit dump; it is not a live UE that can
decode this run's RAR and adaptively transmit the matching Msg3 at the assigned
timing, RNTI, and resources. The repeated PUSCH `crc=KO` lines mostly show that
the gNB proceeded past PRACH into Msg3 scheduling and then saw no decodable
valid response.

The accepted detector peak was `1.269201636`, which is also above the stock
`0.610` threshold for this PRACH format. Because this run used the override, it
must still be classified as diagnostic rather than a natural stock-threshold
success, but the row itself was a strong event.

Next debugging should stop lowering the detector threshold blindly. The useful
next rung is either:

- a stock-threshold repeat to see whether the strong accepted PRACH event
  reproduces without the override, or
- a transition back toward a real live UE attach path after preserving the
  current PRACH visibility improvements, because fixed replay cannot validate
  Msg3.
