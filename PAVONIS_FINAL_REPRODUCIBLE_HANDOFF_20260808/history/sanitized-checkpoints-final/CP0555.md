## Interpretation

CP555 is a valid orchestration and capture checkpoint, but it is not a valid
live PRACH detector-threshold test. The UE never transmitted Msg1, so the gNB
had no live UE PRACH to detect.

The first failed stage is pre-Msg1 on the UE side. The `0.24` detector threshold
was active on [host-redacted], but the zero accepted rows are non-decisive because the UE
did not reach a Random Access / PRACH-TX attempt.

The next useful live-UE step should focus on getting the UE to an actual Msg1
attempt again, not on further detector threshold changes. Candidate branches
are to relax or shorten the PRACH sync guard for a bounded diagnostic run,
increase the bounded UE runtime, or repeat the last live path that reached
PRACH transmission before changing detector logic again.
