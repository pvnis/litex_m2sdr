# Checkpoint 575 - CP570 TX Realtime Timing Audit

Date: [date-redacted] UTC
Source stamp: [date-redacted]

## Purpose

Refine CP572's timing interpretation. CP572 used the existing CP113
`START_UTC + secs + frac` join, but CP570's UE metadata shows that
`secs/frac` corresponds to `prach_time_offset_old_timestamp`, before the
positive PRACH offset is applied. CP575 checks whether the waveform appears if
we instead align by the offset-applied TX timestamp or by the plugin write-call
realtime plus remaining device timestamp delta.

## Timing Bases Tested

against the matching UE template under four timing bases:

- `old_stream`: `START_UTC + prach_time_offset_old_timestamp / tx_rate`

- `realtime_post_delta`: `sync_realtime_after_ns + post_tx_delta_samples / tx_rate`

## Interpretation

CP575 removes a timing-basis ambiguity from CP572. The earlier CP113 join used
the pre-offset stream timestamp, but even when the positive PRACH offset and the
plugin write-call realtime are considered, the corresponding saved gNB PRACH
raw rows are still low-energy and have no convincing template match.

That means the CP570 no-detect is not explained by choosing the wrong metadata
timestamp for offline scoring. CP570's plugin reports successful timed writes,
but no tested gNB PRACH raw window contains the live waveform with anything
close to CP573's controlled replay strength.

Next debugging should focus on the live UE runtime TX path between accepted
timed writes and actual over-air emission, or on active-gNB receive/runtime
conditions that differ from the controlled capture path.
