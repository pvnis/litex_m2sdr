## Purpose

Replay CP570 UE TX dump `000001` through the controlled replay path while
forcing the live-style PRACH burst-only RF plugin behavior identified in CP576:
low-peak chunks skipped, high-peak PRACH chunks sent as stand-alone timed

burst-only timed SOB/EOB semantics rather than deeper srsUE live runtime state

## Interpretation

CP577 is a clean controlled replay pass while exercising the live-style
burst-only timed SOB/EOB PRACH write path. This rules out a simple failure of
the bladeRF plugin's stand-alone timed SOB/EOB burst semantics under controlled
conditions.

Together with CP572, CP573, CP575, and CP576, the remaining failure boundary is
now beyond:

- malformed CP570 UE waveform
- raw512 missing the relevant CP570 gNB windows
- gross current RF path failure
- CP570 metadata timestamp-basis ambiguity
- controlled bladeRF replay of the CP570 waveform
- controlled live-style `PAVONIS_RF_BLADE_PRACH_BURST_ONLY=1` timed SOB/EOB
  replay of the CP570 waveform

The remaining candidates are deeper srsUE live scheduling/state, live UE
runtime interaction with the RF plugin that the controlled runner still does
not reproduce, or active-gNB/runtime receive state not exercised by the passive
[host-redacted] capture gate.

This also weakens the antenna-overheating theory for the current state: CP577
shows the CP570 waveform is still strongly visible over RF immediately after
the prior runs, including through the live-style burst-only path. Thermal or
state effects are still worth watching if future controlled checks weaken, but
CP577 does not support a currently degraded gross RF path.
