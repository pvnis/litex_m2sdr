## Interpretation

CP591 is a valid no-accept and a useful boundary point. It proves that the
CP587 offset can produce a stock-threshold detector pass on preamble `0`, but
the pass is still rejected because the delay estimate is just beyond the limit.
The direct PRACH-window correlation is weak, so this is not the same clean
active predemod alignment seen in CP587.

The most useful next RF rung is a tiny earlier offset bracket at stock
threshold, after cleanup. A `-2` sample move from CP591/CP587 offset
(`1773655 -> 1773653`) is the most surgical test because CP591 missed the
delay limit by only about `1.2` samples. If that preserves the threshold peak
while pulling delay under `104.8`, it should test the actual accept path.
