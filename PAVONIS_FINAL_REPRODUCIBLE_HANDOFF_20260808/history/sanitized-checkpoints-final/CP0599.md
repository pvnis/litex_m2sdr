## Interpretation

CP599 is a valid negative repeatability checkpoint, not a control-plane or
missing-TX failure. The strict gate passed, both NUC-side scripts completed, the
tarballs are valid, the TX-side run emitted the expected burst count, and the
focused lower-RX analysis found a strong CP570-shaped copy near the detector
maximum.

The failure mode is that the gNB PRACH windows did not receive a strong enough
same-window CP570 copy to cross threshold. This differs from CP597, where the
same offset produced two accepted rows with peaks `0.9638404250` and
`0.8374090195`. CP599's detector maximum is legal delay but only `0.1925374568`,
below the `0.24` threshold.

The current conclusion is that offset `1773655` remains the only proven active
accept point, but acceptance is not deterministic run-to-run. The next useful
step is to preserve the CP597 recipe and run one more controlled repeat or move
to an acceptance-package/reporting step that explicitly records the observed
stochasticity.
