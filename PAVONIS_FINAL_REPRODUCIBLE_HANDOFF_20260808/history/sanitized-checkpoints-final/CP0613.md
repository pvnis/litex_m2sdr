## Findings

CP611 active replay used two timing controls:

- `RF_ENV_TX_DBG_PRACH_TIME_OFFSET_SAMPLES=1773633`
- `TIMED_LEAD_MS=-0.67`

The active replay wrapper passes those through CP579/CP487 into the standalone
paced transmitter. In `cp47_srsran_blade_plugin_paced_sparse_timed_tx.c`,
`TIMED_LEAD_MS` is applied to the replay sequence start:

- the helper samples device time with `srsran_rf_get_time`
- then runs `add_seconds(... cfg.timed_lead_ms / 1000.0)`
- every later chunk timestamp is relative to that shifted start

The live UE path has the PRACH offset knob but no live `TIMED_LEAD_MS` knob:

- `cp557_sens_selfcontained_wait_gate_run_ue_remote.sh` exports
  `PAVONIS_RF_BLADE_TX_DBG_PRACH_TIME_OFFSET_SAMPLES="$PRACH_OFFSET_SAMPLES"`
- the same waiter exports `PAVONIS_SRSUE_PRACH_SYNC_GUARD_SLOTS`
- local searches in `srsRAN_4G` found no `TIMED_LEAD_MS` or `timed_lead`
  handling in the live UE path

The live bladeRF plugin applies the offset exactly where needed for the live
PRACH chunks:

- it reads `PAVONIS_RF_BLADE_TX_DBG_PRACH_TIME_OFFSET_SAMPLES`
- for high-peak chunks with a nonzero timed metadata timestamp, it adds a
  positive offset directly to `meta.timestamp`
- CP570 metadata confirmed the live offset was actually applied:
  `prach_time_offset_samples=1637172`, `prach_time_offset_applied=1`,
  `force_sob=1`, `force_eob=1`, `flags=0x3`, `status_str=OK`

CP611 metadata confirmed the replay offset was also applied:

- `prach_time_offset_samples=1773633`
- `prach_time_offset_applied=1`
- high-peak replay chunks had `status_str=OK`

## Translation

At `11.52 MHz`, `0.67 ms` is about `7718` samples:

- `0.00067 * 11520000 = 7718.4`

Because live UE has no `TIMED_LEAD_MS`, the closest one-knob translation of the
CP611 final PRACH timestamp is:

- CP611 replay offset: `1773633`
- minus replay timed lead: `7718`
- live-equivalent offset: `1765915`

Relative to CP570's live offset:

- CP570 live offset: `1637172`
- CP614 candidate offset: `1765915`
- delta: `128743` samples
- delta: `11.175573 ms`

This is not a proof that live UE and replay have identical base timing. It is
the closest conservative mapping available without adding a new live scheduler
knob or changing the live TX semantics.

## Decision

The next ladder rung should be one live UE Stage 6 run using the CP570/CP557
raw512 live harness and changing only:

- `PRACH_OFFSET_SAMPLES=1765915`

Keep the rest of the live baseline unchanged:

- `GNB_RX_GAIN=50`
- `PAVONIS_PRACHDET_THRESHOLD_OVERRIDE=0.24`
- `PRACH_SYNC_GUARD_SLOTS=80`
- `GUARD_SAMPLES=0`
- default PRACH predemod raw cap `512`
- targeted UL-symbol capture enabled
- strict GO/CANCEL gate

Do not set `TIMED_LEAD_MS` for this live run; it is not a live UE control.
