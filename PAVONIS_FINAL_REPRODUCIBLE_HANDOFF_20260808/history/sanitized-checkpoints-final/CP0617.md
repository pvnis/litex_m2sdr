## Interpretation

CP617 cleanly eliminates the simple live-gNB-bandwidth hypothesis for this
branch. The run is valid, the UE transmitted six healthy live PRACH bursts with
the CP611-derived net offset, and BW10 was proven before GO. The gNB still had
no threshold pass and no accepted preamble.

The result is slightly stronger than CP614 by detector peak (`0.1444` versus
`0.1371`) but weaker by same-window template score (`0.0412` versus `0.0459`).
That is not a meaningful recovery.

Do not spend another RF run only on gNB BW. The next checkpoint should be a
no-RF timing audit focused on why CP611's active-replay `TIMED_LEAD_MS=-0.67`
accept does not translate to the live UE path with only
`PAVONIS_RF_BLADE_TX_DBG_PRACH_TIME_OFFSET_SAMPLES=1765915`. The likely next
one-variable experiment should come from that audit: either add a live
`TIMED_LEAD`-equivalent knob or choose a justified live timestamp bracket from
metadata, not another blind live offset retry.
