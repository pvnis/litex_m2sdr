## Interpretation

The same live replay setup can produce:

- a strong no-accept when the 16-sample comb lands at `76/92/108`, with one
  lobe outside the `104.8` sample delay gate
- a strong accept when the comb lands at `1/17/33`, with all lobes inside the
  delay gate and the selected bin above threshold

The leading hypothesis is no longer RF amplitude loss. The useful target is the
detector/windowing/timing path that controls where this 16-sample-spaced comb
lands and why the detector accepts only the selected bin instead of accounting
for split energy.

Next useful checkpoint: no-RF source audit around PRACH detector delay-grid
generation, windowing/CP alignment, and any place where a 16-sample spacing can
enter the active metric. If more trace is needed, add a bounded trace-only
patch for top-k or full delay-vector logging on high-RSSI p0/global-best rows,
then run a separate RF checkpoint.
