## Active detector constants

From CP638/CP641 traces and detector source:

- format `0`, long preamble
- `root_sequence_index=1`
- `zero_correlation_zone=0`
- `start_preamble_index=0`
- `nof_preamble_indices=64`
- `ra_scs=0`
- `nof_rx_ports=1`
- `N_cs=0`
- `cp_prach=108`
- `L_ra=839`
- detector IDFT size `1024`
- `combine_symbols=1`
- `nof_sequences=64`
- `nof_shifts=1`
- `win_width=131`
- `win_margin=12`
- `max_delay_samples=131`
- delay gate `max_delay_samples * 0.8 = 104.8`

The detector flow is:

1. Convert the extracted PRACH frequency-domain symbol to `cf_t`.
2. Multiply by the conjugate generated root.
3. Place the `839` bins into a `1024`-point IDFT input.
4. Run the IDFT.
5. Take modulus squared.
6. Use `window_start = 0` for `N_cs=0`.
7. Search `win_width=131` delay bins.
8. Accept only if `peak > threshold` and `delay < 104.8`.

The detector does not combine neighboring delay bins. It chooses the single
maximum bin per preamble.

## Upstream PRACH demodulation constants

The worker collects the active PRACH window into `temp_baseband`, converts it
to float, dumps pre-demod raw if armed, and then calls:

```text
demodulator->demodulate(*buffer, cf_buf, config)
```

The CP638/CP641 manifest confirms the active window:

- `window_length=11520`
- `start_symbol=0`
- `rb_offset=8`
- `nof_prb_ul_grid=52`
- `nof_td_occasions=1`
- `nof_fd_occasions=1`
- one receive port

For format 0, `get_prach_preamble_long_info()` returns:

- sequence length `839`
- RA SCS `1.25 kHz`
- number of PRACH symbols `1`
- CP length `3168 kappa`

At `11.52 Msps`, the PRACH demodulator DFT for RA SCS `1.25 kHz` is expected
to be:

```text
11520000 / 1250 = 9216
```

For PUSCH SCS `15 kHz` and PRACH SCS `1.25 kHz`:

```text
K = 15000 / 1250 = 12
prach_grid_size = 52 * 12 * 12 = 7488
k_bar = 7
k_start = 12 * 12 * rb_offset + k_bar = 12 * 12 * 8 + 7 = 1159
```

The OFDM PRACH demodulator copies a `9216`-sample DFT window after the PRACH CP,
extracts `839` contiguous PRACH bins starting at `k_start=1159` inside the
`7488`-subcarrier PRACH grid, and scales those bins into the `prach_buffer` seen
by the detector.

## What does not explain the 16-bin comb

`N_cs` does not explain it:

- `N_cs=0`
- `nof_shifts=1`
- `window_start=0`
- no cyclic-shift window stepping is active

The short-preamble sixteen-kappa correction does not explain it:

- the active format is long format 0
- `start_symbol=0`
- short-preamble CP-extension logic is not active
- sixteen kappa is not the same as 16 detector delay bins

The detector delay gate explains why CP638 missed, but not why the comb exists:

- CP638 selected delay `92` was inside the gate
- CP638 lobe at delay `108` was outside the gate
- CP638 valid top-2 ratio would pass if combined
- the implementation only tests the selected single bin

## Working interpretation

The 16-bin structure is most likely introduced by upstream time/frequency
placement or by the detector's 839-to-1024 correlation response to the extracted
PRACH bins, not by gross RF loss.

The comparison now needs more shape information than top-3 provides. CP641's
positive accept and CP638's no-accept both show a 16-bin-spaced comb, but top-3
cannot distinguish a narrow three-lobe structure from a broader periodic
response.
