# Checkpoint 649 - No-RF local OCUDU PRACH DFT-start sweep

Date: [date-redacted]

## Verdict

Classification:
`CP649_NO_RF_DFT_START_OFFSET_CAN_FLIP_PRACH_ACCEPTANCE`

CP649 did not run RF. It built and ran a local OCUDU replay probe against the
saved pre-demod PRACH windows from CP638, CP641, and CP646. The sweep changes
only the sample offset passed to the OCUDU PRACH demodulator before detection.

The important result is that the CP638 decisive no-accept window becomes a
valid preamble-0 accept when replayed with a small positive DFT-start shift:

```text
CP638 offset 0:  p0_delay=92  p0_peak=1.812831163e-01 accepted=0
CP638 offset 32: p0_delay=104 p0_peak=2.439611554e-01 accepted=1
CP638 offset 40: p0_delay=103 p0_peak=2.461878210e-01 accepted=1
```

This supports the CP648 hypothesis: the failure mode is consistent with PRACH
window/DFT-start alignment moving energy across the detector delay bins, not a
gross RF amplitude or overheating failure.

## Caveat

The local static OCUDU detector library is not bit-identical to the current
[host-redacted] instrumented detector. The local trace reports `win_margin=5`, while the
recent [host-redacted] TOP8/SPLIT detector trace reports `win_margin=12`.

Despite that, nominal offset 0 reproduces the decisive delay/acceptance shape:

```text
run    live delay/peak/accepted        local offset0 delay/peak/accepted
CP638  92 / 1.686228067e-01 / 0        92 / 1.812831163e-01 / 0
CP641   1 / 3.817281127e-01 / 1         1 / 3.942269385e-01 / 1
CP646  39 / 2.417728901e+00 / 1        39 / 2.495318651e+00 / 1
```

So CP649 is a valid offset-sensitivity probe, not a bit-exact replacement for a
current [host-redacted] detector replay.

gate.

## Interpretation

CP649 shows that small changes to the DFT-start cut inside the same 11520-sample
PRACH window can move a marginal CP638 no-accept into an accept. It also shows
that the very strong CP646 row remains robust across many offsets and can become
much stronger without changing RF amplitude.

That makes the next rung no-RF again: run the equivalent replay against the
current [host-redacted] patched detector/build, or add current-detector demod-start tracing,
so the result uses `win_margin=12` and the TOP8/SPLIT instrumentation before any
new RF run.
