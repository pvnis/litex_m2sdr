## Source Findings

The live upper PRACH path builds an invalid detector config for long format0:

```text
lib/phy/upper/uplink_processor_impl.cpp:27
config.ra_scs = to_ra_subcarrier_spacing(context.pusch_scs);
```

The FAPI fast-path translator has the missing long-preamble correction:

```text
lib/fapi_adaptor/phy/p7/fapi_to_phy_fastpath_translator.cpp:377-380
if (config.format < prach_format_type::three) config.ra_scs = kHz1_25;
else if (config.format == prach_format_type::three) config.ra_scs = kHz5;
```

The standalone validator rejects the live config:

```text
The PRACH detector does not support the configuration {Format 0, ZCZ 0, SCS 15kHz, Rx ports 1}.
```

The live `uplink_processor_impl` path calls `prach->detect()` without applying
that correction. The detector then runs anyway.

There is a second bug in the threshold/margin lookup:

```text
lib/phy/upper/channel_processors/prach/prach_detector_generic_thresholds.cpp:102-111
```

`get()` uses `lower_bound()` and returns `it->threshold_and_margin` without
checking `it->configuration == params`. For missing configurations, this can
silently inherit the next table row instead of falling back or rejecting. That
is how the invalid live `format0 + kHz15` config reaches `win_margin=12`.
