## Interpretation

CP665 rules out a purely live-scheduling explanation for the CP663 failure. If
the CP663 live PRACH bytes were detector-equivalent to the accepted CP570
template, the controlled replay path should have reproduced the CP661/CP662
accept. It did not.

The next checkpoint should be no-RF: compare the CP663 live template directly
against the accepted CP570 template for frequency placement, cyclic shift,
phase, conjugation/IQ swap, time alignment, scaling, and preamble/root
properties. Only after that comparison should we spend another RF run on a
transformed live template.
