## Source finding

The threshold override only changes the numeric threshold:

- lines `143-151`: `PAVONIS_PRACHDET_THRESHOLD_OVERRIDE` parses a positive
  float and assigns it to `threshold`.

The detector computes the delay limit from `max_delay_samples`:

- lines `160-162`: `max_delay_samples` is derived from `N_cs`, `cp_prach`,
  `dft_size`, and `L_ra`.
- lines `183-184`: `time_advance_max` uses `max_delay_samples * 0.8`.
- line `199`: trace-side `pavonis_delay_limit` is also
  `max_delay_samples * 0.8`.

The actual accept gate is at lines `449-450`:

```cpp
if ((delay < metric_global.size()) && (peak > threshold) &&
    (delay < static_cast<float>(max_delay_samples) * 0.8)) {
```

So acceptance requires all of:

1. delay inside metric vector,
2. peak above threshold,
3. delay below `0.8 * max_delay_samples`.

The trace instrumentation records the same two booleans:

- `p*_pass_thr`
- `p*_pass_delay`
