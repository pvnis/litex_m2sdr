# CHECKPOINT 681 - Live vs controlled TX semantics audit

## Scope

CP681 is a no-RF audit after CP680.

CP680 replayed the exact CP678 live PRACH dump through the controlled sparse
replay path and the gNB accepted it. That rejected "the CP678 PRACH buffer is
invalid" as the main theory. CP681 therefore compares the live srsUE/bladeRF TX
path against the controlled replay path, focusing on stream activation, timed
metadata, SOB/EOB behavior, RX-load behavior, repetition count, and detector
outcome.

No remote commands were run and no tars were extracted.

## Source audit

Live srsUE bladeRF path:

- starts TX stream on demand when `handler->tx_stream_enabled` is false;
- parses `PAVONIS_RF_BLADE_TX_DBG_PRACH_TIME_OFFSET_SAMPLES`;
- parses `PAVONIS_RF_BLADE_TX_DBG_PRACH_FREQ_ROT_HZ`;
- has PRACH burst-only logic;
- can force `BLADERF_META_FLAG_TX_BURST_START`;
- can force `BLADERF_META_FLAG_TX_BURST_END`;
- sends through `bladerf_sync_tx`.

Controlled sparse replay path:

- starts RX stream before TX;
- runs `rx_load_thread_main`;
- sends through `srsran_rf_send_timed`;
- emits `BURST idx=...` paced replay rows;
- uses `FIRST_BURST_CHUNK` and `PERIOD_CHUNKS`.

This confirms the two paths are not semantically identical even when the PRACH
sample buffer is the same.

## Interpretation

CP681 strengthens the live-vs-controlled semantics theory.

The important new point is that CP680 did not merely send the CP678 live buffer
once. It sent a paced sparse sequence of `198` bursts across about `32 s`,
with RX load active, and one of those bursts landed strongly enough for the gNB
to accept Msg1. CP678 live gave only five PRACH opportunities and remained weak
or off-window at the receiver.

This explains why CP680 can accept the exact CP678 sample buffer while CP678
live does not:

1. controlled replay has much greater frame/window/phase coverage;
2. controlled replay uses a different stream activation/RX-load path;
3. controlled replay shows stable forced SOB/EOB timed bursts in the logged
   high-peak rows;
4. live CP678 had valid TX-side samples but only five attempts and no accepted
   receiver-side coherent peak.

This does not prove the live path is wrong in one specific metadata bit yet. It
does make "send many more live PRACH opportunities or deliberately sweep live
start/frame phase" a stronger next branch than another waveform or threshold
tweak.
