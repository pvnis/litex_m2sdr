shape for making the gNB RACH retry limit explicit.

## Interpretation

This checkpoint does not prove that [host-redacted] will run the edited config, and it does
not advance the RF ladder. It proves the next gNB-side knob can be expressed
cleanly and audited before RF.

Why `20`:

- it is an OCUDU-supported value;
- it is enough to give `4x` CP678's live attempt count if srsUE follows the SIB
  value;
- it is a conservative first step compared with `50`, `100`, or `200`;
- it keeps the live waveform settings unchanged.

The CP678 vs CP680 gap remains large:

- CP678 live opportunities: `5`
- CP680 controlled opportunities: `198`

So `20` does not fully match CP680's phase coverage, but it is a low-risk first
live attempt-count increase.
