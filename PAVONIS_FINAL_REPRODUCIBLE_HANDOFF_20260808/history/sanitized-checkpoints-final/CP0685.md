## What did not work

- No live UE run has yet produced a gNB accepted Msg1 in the recent branch.
- Many timing offsets, TX guards, SOB/EOB variants, and stream restart variants
  changed symptoms but did not recover live Stage 6.
- Blind threshold lowering is not enough. CP551 was useful diagnostically, but
  fixed replay threshold success does not prove live Msg1 or Stage 7.
- Same-offset active replay repeats are not deterministic.
- Live `+500 Hz` and the refined `1773617` offset did not transfer directly
  from controlled replay to live UE.
- Fixed replay RAR/Msg3 scheduling does not prove a real UE decoded RAR or sent
  a valid Msg3.

## Theory status

### Passive antenna overheating

Unlikely as the primary explanation.

Evidence:

- CP86 showed bladeRF RFIC `36 C`, M2SDR AD9361 `39 C`, normal host CPU temps,
  and no [host-redacted] kernel DMA/oops/panic evidence.
- CP257 reviewed the thermal theory and rejected a simple passive-antenna
  overheat model.
- CP658 again found no current ordinary host/CPU overheating.

There is no direct antenna temperature sensor in the collected data. If there
is a powered RF component, cable/contact issue, attenuator/adaptor issue, SDR
state issue, or USB instability, that remains plausible.

### Active RF path variability

Plausible and repeatedly observed.

Evidence:

- Known-good replay sometimes degraded and later recovered.
- No-TX floor and gain/bandwidth settings affected controlled replay quality.
- CP658 found bladeRF USB resets aligned with failing runs.
- CP603 showed strong lower-RX copies even in no-accept repeats, which argues
  against a total RF fade but supports timing/state variability.

### Live PRACH waveform malformed

Currently weakened as the leading theory.

Evidence:

- CP667 accepted a `+500 Hz` corrected live dump under controlled replay.
- CP680 accepted the exact CP678 live dump under controlled replay.

The waveform can be good while live stream timing/RF semantics are still wrong.

### OCUDU detector/config bug

Partly confirmed and acted on.

Evidence:

- CP651 found the invalid live upper PRACH `ra_scs` path.
- CP652 patched it.
- Later controlled accepts improved, but live UE still did not accept.

### Zero-copy RX path bug

Confirmed for active raw visibility.

Evidence:

- CP512 recovered strong active raw copies by switching to `readStream()`.
- CP514 identified the direct-buffer interleaving mismatch.

This solved a lower-rung visibility problem, not the final live Stage 6 issue.

### Phase/window stochasticity

Strongly supported for active replay.

Evidence:

- CP597 accepted twice at the chosen offset.
- CP599/CP601 repeated the same recipe and did not accept.
- CP603 showed the separator was lower-RX template timing relative to PRACH
  windows, not absence of RF energy.

### Live-vs-controlled TX semantics and opportunity count

This is the strongest current branch.

Evidence:

- CP678 live produced only 5 valid PRACH attempts in a full 240 s bounded run.
- CP680 controlled replay sent 198 bursts and accepted one using the exact
  CP678 live sample buffer.
- CP681 showed the live and controlled TX paths differ in stream activation,
  RX-load behavior, repetition count, and burst semantics.
- CP682 found the safe supported gNB knob to force more live attempts:
  `preamble_trans_max`.
