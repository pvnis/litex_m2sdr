## Interpretation

CP689 strengthens the live-vs-controlled RF/stream semantics branch.

The CP684 knob worked at the UE/MAC level:

- CP678 had `5` live attempts.
- CP684 had `15` live attempts.

But the receiver did not move toward the controlled positive:

- CP684 had no accepted rows.
- CP684 had no threshold-pass rows.
- CP684 had no gNB non-empty PRACH lines.
- CP684 wall-nearest raw rows stayed noise-level.

Therefore the next RF run should not simply raise `preamble_trans_max` again.
The attempt-count branch produced useful evidence and is now mostly exhausted
unless a source audit shows the UE still stopped earlier than intended.

The next useful rung is one of:

1. No-RF prepare a controlled replay of CP684 dump `000001`, matching CP680,
   to test whether the slightly lower CP684 live waveform still accepts under
   controlled replay.
2. No-RF inspect CP684 raw windows around all fifteen attempts more directly,
   using saved predemod/Soapy raw files if needed, to see whether any attempt is
   a shifted copy or all are simply weak.
3. Audit live-vs-controlled bladeRF stream/RX-load/start semantics again, now
   with CP684 proving that more live attempts alone was not enough.
