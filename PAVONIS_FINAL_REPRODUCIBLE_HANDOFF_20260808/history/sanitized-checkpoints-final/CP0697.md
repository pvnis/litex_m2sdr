## Collection Window

The live PRACH worker computes the collection window in
`prach_processor_worker::handle_request()`:

```text
window_length =
    get_prach_window_duration(context.format, context.pusch_scs,
                              context.start_symbol, context.nof_td_occasions)
        .to_samples(sampling_rate_Hz);
```

For long preambles, `get_prach_window_duration()` computes the actual PRACH
duration and then rounds the end to the next subframe:

```text
t_end = t_start + preamble_info.cp_length + preamble_info.symbol_length();
t_end = phy_time_unit::from_seconds(1e-3 * ceil(t_end.to_seconds() * 1e3));
```

For the current format-0 case at `11.52 Msps`:

| Quantity | Samples |
| --- | ---: |
| rounded collection window | `11520` |
| actual format-0 demod occasion | `10404` |
| rounded tail not needed by nominal demod | `1116` |

This exactly matches CP694/CP696's maximum useful left-shift sweep range:

```text
11520 - 10404 = 1116
```

## Demodulator Consumption

The worker passes the full collected CF32 window to the PRACH OFDM demodulator:

```text
demodulator->demodulate(*buffer, cf_buf, config);
```

Inside `ofdm_prach_demodulator_impl::demodulate()`:

- format 0 uses `get_prach_preamble_long_info(format)`;
- that long format-0 info is sequence length `839`, RA SCS `1.25 kHz`,
  `nof_symbols=1`, and CP length `3168 kappa`;
- `sample_offset = t_occasion_start.to_samples(srate)` is `0` for
  `start_symbol=0`;
- `nof_samples = occasion_duration.to_samples(srate)` is `10404`;
- the demodulator selects:

```text
input_occasion = input.subspan(sample_offset, nof_samples)
```

So nominal live demodulation consumes only:

```text
cf_buf[0:10404]
```

from the collected:

```text
cf_buf[0:11520]
```

The final `1116` collected samples are normally present in dumps but ignored by
the demodulator for this format.

## CP696 Explained

CP696's result follows directly from the source:

- `crop_short`, `crop_zeropad_tail`, and `circular_left` all move original
  sample `offset` to transformed index `0`;
- the demodulator then consumes transformed samples `[0:10404]`;
- therefore the tail after transformed sample `10404` is irrelevant.

For CP691 idx147 at offset `847`, the demodulator consumes original samples:

```text
847 .. 11250
```

That uses `847` samples from the rounded tail that nominal demodulation ignores
and still leaves:

```text
11520 - 11251 = 269
```

unused original samples at the end.

This explains why full-length zero-padded and circular-left transforms matched
the shorter CP694 crop exactly.

## Patch Point

The most surgical diagnostic patch point is the worker call site immediately
before:

```text
demodulator->demodulate(*buffer, cf_buf, config);
```

A guarded experiment can pass a shifted view only for PRACH demodulation:

```cpp
span<cf_t> demod_cf_buf = cf_buf;
if (pavonis_offset > 0 && pavonis_offset <= 1116 && pavonis_offset < demod_cf_buf.size()) {
  demod_cf_buf = demod_cf_buf.subspan(pavonis_offset);
}
demodulator->demodulate(*buffer, demod_cf_buf, config);
```

This would leave:

- the baseband collection FSM unchanged;
- Soapy RX and UL symbol processing unchanged;
- the saved predemod window unchanged;
- the PRACH detector and threshold unchanged.

It would only alter the input origin seen by the PRACH OFDM demodulator.

The cleaner production fix may belong elsewhere after root cause is understood,
but this is the right minimal diagnostic patch.

## Interpretation

CP697 ties the CP696 local result to the live source path:

- the live worker captures a rounded 1 ms PRACH window;
- the demodulator consumes the actual format-0 occasion from the front of that
  window;
- CP691 becomes detectable when the demodulator's front-of-window origin moves
  later into the rounded tail;
- this is a plausible live test knob because the data already exists in the
  collected PRACH buffer.

This does not prove that `847` is the correct general fix. It proves that a
guarded demod-input-origin experiment is technically well-defined and can be
tested without changing RF scheduling or capture length.
