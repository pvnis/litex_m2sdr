What we tried:

  zero-copy versus `readStream()` comparisons.

What worked:

- `OCUDU_SOAPY_RX_USE_READSTREAM=1` recovered strong active raw copies.

What did not work:

- Fixing raw visibility did not by itself recover live Msg1.

## Most recent state

The broad question is no longer:

```text
Can this waveform family ever be accepted?
```

The answer is yes, under controlled replay.

The current narrow question is:

```text
Why do live UE PRACH transmissions that look waveform-valid on the TX side
arrive at the gNB receiver windows too weakly, off-window, or otherwise
unrecoverably for the detector to accept?
```

CP709 says the CP705 saved live receiver windows do not hide a strong PRACH
copy that can be rescued by moving detector origin. CP710 therefore prepared a
safe next rung that changes receiver visibility first, but only behind a
gNB-only strict gate.

## Next recommended rung

Do not jump directly to another live UE transmission.

Run the prepared CP710 gNB-only strict gate at:

```text
GNB_RX_GAIN=55
RX_BW_HZ=10000000
TX_BW_HZ=10000000
tx_gain_backoff=20
```

The gate must prove:

- gNB starts;
- strict gate returns `PASS`;
- total Soapy TX timeouts remain `0`;
- RX/TX bandwidth readbacks are still `10 MHz`;
- RX gain readback reports the requested gain or a clearly understood
  device-limited value.

Only if that passes should the next live-UE launcher preserve CP705 and change
only:

```text
GNB_RX_GAIN: 50 -> 55
```

with all other live settings held:

```text
+500 Hz
PRACH offset 1773617
UE TX gain 59
preamble_trans_max 20
PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES=847
PAVONIS_PRACHDET_THRESHOLD_OVERRIDE=0.24
```

If the RX-gain 55 gate fails, do not transmit live UE at that setting. Treat it
as gNB/RF runtime-state or gain-limit evidence, clean up, and either retry once
under a controlled gate or choose a smaller visibility change.

## Bottom line

The project has narrowed substantially. Controlled PRACH and the post-Msg1 gNB
RA path work. Live UE PRACH transmission happens and the UE-side saved waveform
family looks valid. The present blocker is that live PRACH energy is not
showing up in the gNB receiver windows in a strong/recoverable way. The next
safe step is the CP710-prepared gNB-only RX-gain 55 strict gate, followed by a
single-variable live run only if that gate passes.
