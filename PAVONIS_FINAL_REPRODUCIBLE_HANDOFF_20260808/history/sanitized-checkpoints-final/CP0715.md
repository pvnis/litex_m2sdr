## Interpretation

CP715 is a valid negative live result.

It proves:

- the live run used the intended RX gain `55`;
- RX readback reported `55.00 dB`;
- strict gate passed with zero Soapy TX timeouts;
- UE cell selection succeeded and the UE transmitted live PRACH;
- gNB detector still accepted zero Msg1 rows;
- gNB reported no non-empty `detected_preambles`;
- no live Stage 7 evidence appeared.

This weakens "gNB RX gain 50 was simply too low" as the primary explanation.
The live problem remains a receiver-window/RF-path visibility or timing-state
problem rather than a pure gain-headroom problem.

## Next rung

Do not continue increasing gain blindly.

The next useful no-RF checkpoint should compare CP715 against CP706/CP707/CP709
at the receiver-window level:

- saved live UE TX dumps versus accepted waveform references;
- nearest gNB predemod windows around saved TX events;
- raw RMS/peak and detector tails;
- whether RX gain `55` moved any receiver window closer to CP704/CP680 accepted
  families.

If CP715 receiver windows are still weak like CP705, move away from gain and
back toward live timing/visibility semantics, cabling/path placement, or
stream-state hypotheses. If CP715 reveals a stronger hidden window, use the
CP709-style local sweep to see whether it is recoverable.

## Bottom line

RX gain `55` was safe at the gNB gate and was applied in a real live UE run, but
it did not recover live Msg1. The current first failed stage remains live Stage
6 PRACH Msg1 detection.
