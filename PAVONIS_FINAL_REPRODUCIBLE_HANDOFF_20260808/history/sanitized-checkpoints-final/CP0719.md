## Interpretation

CP717 showed that the CP714 saved TX dumps had a mostly correctable residual
frequency rotation. CP719 shows that applying the inferred live correction
alone does not fix the live PRACH receive problem.

This weakens the idea that the CP714/CP715 failure was only a UE-side TX
frequency-rotation setting. The leading branch remains upstream of detector
origin: live RF/receiver-window visibility, timing, or active RF-chain state.

## Recommended next rung

Do not launch another RF run immediately. First run a no-extract CP718 audit
matching the CP716 pattern:

- compare CP718 saved UE TX dumps against CP667, CP680, and CP704 accepted
  waveform families;
- measure CP718 saved TX residual frequency/CFO against those templates;
- inspect the nearest gNB receiver windows around CP718 live TX events;
- compare CP718 window strength against CP705 and CP714.

If CP718 TX now matches accepted references but receiver windows remain weak,
the next RF rung should focus on receiver visibility/timing/active RF state,
not another UE waveform-only tweak.
