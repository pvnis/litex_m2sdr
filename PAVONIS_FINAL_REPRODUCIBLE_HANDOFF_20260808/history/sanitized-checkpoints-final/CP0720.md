## What has worked overall

- Controlled replay can accept Msg1.
- Fixed/control replay can exercise enough of the gNB RA path to produce
  RAR/Msg3 scheduling evidence after an accepted Msg1.
- Live UE can cell-select and transmit PRACH.
- Strict gate patterns can verify gNB startup health, bandwidth readback, RX
  gain readback, and TX-timeout absence before live RF.
- The Soapy direct-buffer visibility bug was found and worked around with
  `readStream()`.
- The live `ra_scs` source bug was found and patched.
- The CP698 demod input offset knob was built, deployed, and proven in
  controlled replay.
- Saved live UE TX waveforms can match accepted waveform families.
- The self-contained remote launch/collect/report flow is now robust enough to
  survive intermittent laptop connectivity.

## What has not worked

- No live UE Msg1 accept has been achieved in the current branch.
- More attempts did not solve it.
- Threshold lowering did not become a valid fix.
- `+500 Hz`, offset `1773617`, TX gain `59`, and demod offset `847` did not
  transfer to live accept.

- PRACH freqrot `275 Hz` did not recover live Msg1.
- CP705 saved live receiver windows were not locally recoverable by detector
  origin/RB sweeping.
- Fixed replay RAR/Msg3 scheduling does not prove live UE Stage 7.

## Current state

The broad question is no longer:

```text
Can this waveform family ever be accepted?
```

The answer is yes, under controlled replay.

The current narrow question is:

```text
Why do live UE PRACH transmissions that look waveform-valid on the TX side
arrive at the gNB receiver windows too weakly, off-window, or otherwise
unrecoverably for the detector to accept?
```

CP715 says RX gain `55` alone does not solve it. CP719 says the CP717-derived
freqrot `275 Hz` live candidate does not solve it either. Therefore the next
useful step should be no-RF analysis of the CP718 saved data before spending
more live TX.

## Recommended next rung

Run a no-extract CP718 dump/window audit matching the CP716 pattern:

- compare CP718 saved UE TX dumps against CP667, CP680, and CP704 accepted
  references;
- measure CP718 residual frequency/CFO against those references;
- inspect nearest gNB receiver windows around CP718 live TX events;
- compare CP718 receiver-window strength against CP705 and CP714.

Only after that audit should the next RF experiment be chosen. If CP718 TX now
matches accepted references and receiver windows remain weak, the next RF rung
should target receiver visibility/timing/active RF state rather than another
UE waveform-only tweak.
