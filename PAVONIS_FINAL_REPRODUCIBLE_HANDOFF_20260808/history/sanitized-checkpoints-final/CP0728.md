# CHECKPOINT 728 - Controlled replay regression no-RF audit

Date: [date-redacted] Europe/Zurich

Scope: no-RF, no-SSH controlled-regression audit comparing the CP704 accepting
CP684 controlled replay against the current CP724, CP725, and CP726 controlled
failures. The audit reads existing JSON files and selected tar members through
Python `tarfile`, without extracting tarballs to disk.

No RF command, gNB process, UE process, SSH, SCP, or tarball extraction was run
for this checkpoint.

## Question

CP726 showed that restoring gNB RX gain `50` did not restore the CP704
controlled accept. CP728 asks:

```text
Did the controlled replay waveform or launch mechanics change, or did the same
waveform land in a different receiver-window/metric state?
```

The focus predemod CF32 windows were compared against the CP704 accepted window:

| Checkpoint | Zero-lag corr to CP704 | Max circular corr to CP704 | Signed shift | Signed shift |
| --- | ---: | ---: | ---: | ---: |
| CP704 | `1.000000` | `1.000000` | `0 samples` | `0.0 us` |
| CP724 | `0.017432` | `0.752332` | `-1123 samples` | `-97.48 us` |
| CP725 | `0.001639` | `0.363802` | `-5074 samples` | `-440.45 us` |
| CP726 | `0.003823` | `0.472144` | `+5622 samples` | `+488.02 us` |

Interpretation:

- CP724 contains a receive window fairly similar to CP704 after a large
  circular shift, matching its near-threshold behavior.
- CP725 and CP726 are much less CP704-like even after circular shift.
- CP726 is especially important because it used RX gain `50`, yet the receive
  window is still not aligned/metric-equivalent to CP704.

This reinforces that the current lower-rung failure is not a simple raw-power
failure. It is a receiver-window phase/state/geometry problem.

## Caveats

large nearest-debug deltas and this field is not decisive. The decisive CP728
evidence is the byte-identical source CF32, the detector trace fields, and the
predemod window comparison.

## Interpretation

CP728 narrows the current branch:

```text
The CP684 controlled replay source waveform is unchanged, and launch mechanics
are clean. The same waveform now lands in different gNB receive-window
phase/metric states, so the controlled baseline regression is receiver-side or
stream/window-state related.
```

This also explains why another live UE attempt is not the right next move.
The known-good controlled lower rung is not currently healthy.

Run a no-RF local recoverability audit before any RF:

```text
CP729: CP724/CP725/CP726 shifted-window detector-origin sweep
```

```text
If the failed predemod windows are shifted/cropped in software, can any of them
```

If yes, the next RF rung should target the receiver-window/input-origin timing

or cooldown rather than another demod-origin tweak.
