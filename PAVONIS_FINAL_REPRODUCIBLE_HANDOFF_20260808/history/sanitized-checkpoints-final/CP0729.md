# CHECKPOINT 729 - Controlled replay selected-window transform sweep

Date: [date-redacted] Europe/Zurich

Scope: no-RF, no-SSH local detector recoverability audit. CP729 uses selected
predemod CF32 windows from CP704, CP724, CP725, and CP726 and runs the local
PRACH detector against shifted/cropped/zero-padded views of each window.

No RF command, gNB process, UE process, SSH, SCP, or new tarball extraction was
run for this checkpoint.

## Question

CP728 showed that the controlled replay source waveform is byte-identical
across the accepted CP704 baseline and the current CP724/CP725/CP726 controlled
failures, while the receiver windows landed in different metric states.

CP729 asks:

```text
Do the failed controlled replay windows still contain a recoverable PRACH
signature if the detector is given a different software view of the same local
samples?
```

## Interpretation

CP729 answers the no-RF recoverability question:

```text
Yes. All three current controlled failures, CP724, CP725, and CP726, contain
recoverable PRACH detector signatures offline when the detector is given a
different software view of the same selected predemod samples.
```

This matters because CP728 already ruled out a changed controlled source
waveform and obvious launch-control breakage. CP729 now also rules out the
strong form of "the failed samples are intrinsically undetectable."

The current failure is therefore best described as:

```text
The gNB nominal PRACH receive-window/input-origin/RB/delay view is wrong or
unstable for the current controlled replay state, even though recoverable
signature energy is present in the captured samples.
```

CP724 is the least displaced current miss: RB8 accepts at offset `2` under
crop/circular views. CP725 and CP726 require much larger software transforms,
which is consistent with CP728's large receive-window shifts versus CP704.

CP726 remains the most important regression datapoint because it used RX gain
`50`, matching CP704, and still failed in the nominal path. That weakens any
simple RX-gain-only explanation.

## Caveats

The CP729 transforms are offline detector views over selected windows. They can
show that a signature is present, but they can also overstate what a fixed live
gNB receive path can do. Large offsets such as `4949`, `5498`, `5592`, `5746`,
and `6571` should not be copied into a live RF command as a blind knob.

The next rung should map these offsets back to the real demodulator call site,
window origin, metadata timestamp, and RB-offset handling before another live UE
attempt.
