The large circular/zero-prefix recoveries are useful diagnostics, but they are
not directly deployable with the current positive-crop knob:

- `zero_prefix_delay` means the samples must be delayed relative to the demod

- `circular_left` is an offline circular transform and should not be treated as
  a live RF setting;
- `rb_offset` is frequency extraction, not a time-origin correction.

## Interpretation

CP731 narrows the branch:

```text
The CP729 local detector probe is faithful to the actual gNB demod path when
the existing offset-847 crop is applied. The controlled regression is therefore
real, not a CP729 replay/config artifact.
```

The source and manifest audit also show:

- all four focus windows use `start_symbol=0`, `rb_offset=8`, `window_length=11520`,
  `nof_prb_ul_grid=52`, and one TD/FD occasion;
- `rb_offset=8` is frequency-domain selection, not the timing-origin knob;
- the current offset knob is only a positive crop, so it cannot express the
  strongest zero-prefix recoveries;
- CP724, CP725, and CP726 each have direct-crop recoveries, but they require
  different offsets;
- a blind global change from `847` to one new static value is not justified.

The most likely current explanation is run-to-run receive-window/stream-state
phase variability around a valid but unstable timing origin. A fixed software
offset may repair one current state while breaking another.
