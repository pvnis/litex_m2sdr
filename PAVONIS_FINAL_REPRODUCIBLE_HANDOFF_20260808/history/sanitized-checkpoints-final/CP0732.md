# CHECKPOINT 732 - CP684 controlled RX50 demod-offset sweep no-RF prep

Date: [date-redacted] Europe/Zurich

Scope: no-RF preparation checkpoint for the next controlled replay rung. CP732
prepares a bounded controlled-only RF sweep over the demod input offsets
identified by CP731.

No SSH, SCP, remote command, gNB process, UE process, or RF command was run.
The sweep launcher was executed only in dry-run mode.

## Purpose

CP731 proved two important things:

- replaying saved predemod windows locally with crop offset `847` reproduces
  CP704 accept and CP724/CP725/CP726 failures;
- there is no single RB8 `crop_short` offset that accepts all four controlled
  states offline.

The next RF step should therefore be controlled-only, not live UE, and should
answer:

```text
Can the current hardware/stream state reproduce the CP731 offline direct-crop
recoveries under RF, and does the accepted offset move between controlled runs?
```

## Cleanup controls

The CP732 launcher now supports:

```text
RUN_CLEANUP_BEFORE_EACH=1
RUN_CLEANUP_AFTER_EACH=1
```

When enabled, these call the existing CP98 targeted [host-redacted] cleanup helper before
and/or after each offset. Dry-run mode forces both cleanup flags off.

This is included because CP724-CP726 repeatedly found stale
`run_ota_stage_template.sh` wrappers after controlled runs.

## Intended CP733 RF run

Run CP732 for real as CP733, still controlled-only:

```text
STAMP_BASE=$(date -u +%Y%m%dT%H%M%SZ) \
RUN_CLEANUP_BEFORE_EACH=1 \
RUN_CLEANUP_AFTER_EACH=1 \
./cp732_launch_cp684_controlled_replay_rx50_offset_sweep.sh
```

Pass criteria for each offset:

- both hosts complete and package artifacts;
- fetched tarballs are gzip-valid;
- strict gate passes;
- Soapy TX timeouts remain zero;
- RX/TX bandwidth readbacks remain `10 MHz`;
- RX gain readback is `50.00 dB`;
- detector trace and gNB PRACH log are analyzable.

Interpretation:

- If one or more offsets accept, the controlled baseline is recoverable under
  RF and the accepted offset/state should drive the next lower-rung test.
- If different offsets accept across repeated controlled runs, this confirms
  stateful receive-window/stream-origin variability and weakens a permanent
  static-offset fix.
- If none accept, then the issue has moved below software crop selection and
  the next branch should be RF-chain/stream-state reset or hardware state.

Live UE should still wait until the controlled CP684 baseline is healthy again.
