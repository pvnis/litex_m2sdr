## Interpretation

The main blocker has moved past SFN sync and past "UE did not transmit." In CP745 the live UE selected the cell, used the real PRACH config, issued 18 PRACH transmissions, and produced timed TX debug dumps with the requested 1773617 sample offset and 725 Hz rotation applied.

The controlled replay result is also important. The same paired run accepted controlled Msg1 immediately before the live attempt and again immediately after it. Post-controlled was stronger than pre-controlled. That argues against a simple receiver-path collapse during the run and makes a broad gNB-side antenna overheating explanation less likely for CP745.

This does not rule out all thermal or physical RF theories. There is no temperature telemetry here, and CP745 does not prove the live UE antenna/PA path is healthy over long time. But the evidence we have points more strongly to live over-the-air PRACH being too weak, mistimed, misrotated, or otherwise mismatched at the gNB receiver, while the controlled replay path remains visible.

The most recent live failure is therefore not a wrapper failure and not a UE sync failure. It is a live PRACH visibility/acceptance failure at the gNB.

## Recommended next checkpoint

CP746 should avoid another blind full RF run until we mine the CP745 live artifacts a little more. The next no-RF step should align the 18 UE `tti_tx` attempts with the gNB detector timeline and saved predemod windows, then report whether the weak peaks cluster near the expected P0 windows or are displaced in SFN/slot/delay/preamble. That will tell us whether the next RF run should sweep time offset, frequency rotation, threshold/link budget, or physical UE TX path.

If we do run RF next without additional analysis, the most direct experiments are:

- Lower-threshold live visibility probe to quantify whether live P0 ever becomes a runtime nonempty detection below 0.24.
