## Method

For each CP745 live TX debug dump:

1. Parse the matching `.meta.txt`.
2. Reconstruct `.sc16` to cf32 with `scale = sc16_peak / cf32_peak`.
3. Compare against each accepted reference.
4. Measure direct zero-lag correlation.
5. Sweep frequency from -1500 Hz to +1500 Hz in 25 Hz steps.
6. Allow circular lag and IQ/conjugate transforms.

Transforms checked:

- identity
- conjugate
- IQ swap
- IQ swap conjugate

## Interpretation

CP747 rules out a bad PRACH sample buffer as the primary CP745 failure. The live UE generated a waveform that is essentially the same family as accepted CP684/CP678/CP663 reference waveforms. The best corrected correlations are all near 1.0, with zero circular lag and identity transform.

Combined with CP746:

- UE attempts line up with expected gNB SFN/slot windows.
- Those exact windows have very weak received P0 energy.
- The saved live TX waveform is good.

That points away from waveform generation and toward runtime RF delivery or live timed-transmit behavior. The TX dump proves the buffer and metadata path; it does not prove that the RF energy arrived at [host-redacted] in the expected PRACH window.

The most likely remaining buckets are:

- Actual live RF emission/coupling/path is weak or intermittent despite valid TX buffers.
- Timed transmit lands somewhere other than the gNB window implied by UE `tti_tx`.
- The live srsUE transmit path differs materially from the controlled replay path in stream state, SOB/EOB handling, or hardware timestamp relation.

This is not strong evidence for gNB antenna overheating. CP745 controlled pre and post both accepted, and CP747 shows the UE buffer itself is fine. A physical live UE TX path problem remains plausible because the saved buffer does not prove radiated power at the receiver.

## Recommended next checkpoint

CP748 should isolate live runtime TX delivery:

- Best RF isolation: controlled replay of the CP745 live dump itself through the same controlled replay machinery that accepted CP684. If accepted, the waveform is confirmed good over the controlled path and the live failure is runtime TX timing/RF delivery. If not accepted, there is a replay/input preparation mismatch to fix.

Avoid spending the next RF run on a simple threshold reduction. CP746 showed actual UE attempt P0 windows never reached 0.10, and CP747 shows the waveform is already good.
