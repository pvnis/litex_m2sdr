## Scope

CP750 is a no-RF fix checkpoint after CP749 found that controlled replay runs
labeled `demodoffset562` were actually starting [host-redacted] with demod input offset
`847`.

No SSH, SCP, remote command, gNB process, UE process, or RF command was run for
this checkpoint. Validation was local syntax checking and dry-run only.

## Problem fixed

The controlled replay wrapper chain is:

```text
cp748/cp742 wrapper -> cp723 -> cp579 -> cp487 -> cp366_launch_selfcontained...
```

The outer wrappers exported:

```text
PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES=562
```

but `cp366_launch_selfcontained_cp361dump000001_replay_into_live_gnb_rxgain50.sh`
did not include that variable in the remote environment prefix. The remote
[host-redacted] start helper therefore fell back to:

```text
PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES=847
```

This affected CP733, CP745 controlled pre/post, and CP749/CP748 controlled
replay interpretation.

## Change

Updated:

```text
cp366_launch_selfcontained_cp361dump000001_replay_into_live_gnb_rxgain50.sh
```

Behavior added:

- Capture `PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES` from the local
  environment.
- Log the requested value when present.
- Build the remote environment prefix before dry-run/real branching.
- Append `export PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES=<value>` to the
  remote environment prefix when present.
- In dry-run mode, print:

```text
DRY_RUN remote_env_prach_demod_input_offset_samples=562
```

This makes future controlled replay runs with `demodoffset562` actually pass
that value to [host-redacted].
