## Scope

CP759 is a no-RF orchestration fix after CP758 showed the CP757 live run can
fail before PRACH and therefore lacks TX debug dump files. The previous strict
analyzer treated that as a hard `FileNotFoundError`, even though collection and
cleanup succeeded and a tolerant no-PRACH summary was possible.

No SSH, SCP, remote command, gNB process, UE process, or RF command was run for
this checkpoint. Validation used existing CP758 local tarballs and dry-run
launch only.

## Problem fixed

CP758 collected valid artifacts but the CP757 sequence returned `rc=1` at the
strict analyzer step:

```text
FileNotFoundError: /pavonis_rf_blade_tx_dbg_000001.meta.txt
```

That is expected when the UE fails before PRACH, because no PRACH TX debug
dumps are created. The run should still produce a checkpoint-grade tolerant
summary and exit successfully if collection was valid.

## Interpretation

CP759 fixes the reporting/orchestration issue from CP758. A future CP757-style
live run can now produce:

| Case | Output |
| --- | --- |
| UE reaches PRACH and TX debug dump exists | strict analyzer JSON |
| UE fails before PRACH | tolerant no-PRACH summary JSON |

This does not change the RF hypothesis. It only prevents a no-PRACH live run
from being misclassified as a local analyzer failure.

The next RF checkpoint should rerun the same `PRACH_FREQ_ROT_HZ=350` candidate
unchanged. If it again fails before PRACH, compare against the last known
cell-select-success path or add an explicit DL/SFN-sync gate before more
PRACH-specific trials.
