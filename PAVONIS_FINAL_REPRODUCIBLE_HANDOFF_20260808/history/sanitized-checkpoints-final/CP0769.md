| SFN/cell-select failure | CP758, CP768 | trials `49`, `51` |

This points toward DL/SSB/MIB visibility or timing/margin instability rather
than a wrong static configuration.

## Interpretation

CP769 narrows the active problem to a lower-rung DL/SFN visibility issue:

```text
The UE can sometimes detect PCI, but current detection is late and too marginal
to complete SFN sync. When conditions are worse, it fails cell search entirely.
```

This is consistent with CP767:

- No ordinary host overheating or throttle delta was observed.
- No missing SDR enumeration was observed.
- `[host-redacted]` bladeRF reset-on-open behavior persists but does not itself
  explain the specific SFN failure shape.

The current failure is still below PRACH:

```text
cell search / SFN sync / cell select -> blocked
PRACH / Msg1 -> not reached
RAR / Msg3 / NAS / IP -> out of scope
```

## Recommended next checkpoint

The next useful checkpoint should directly probe DL/SSB/SFN visibility, not
PRACH. Two practical options:

1. A short repeated DL/cell-select baseline after a physical or power-cycle
   intervention, if the user can reset the relevant RF path.
2. A focused DL/SSB visibility probe or UE-side receive snapshot, kept small,
   to compare SSB/MIB quality against the CP740/CP745 successful runs.

Do not spend the next RF run on `350 Hz` Msg1 yet; the UE is still not reaching
PRACH.
