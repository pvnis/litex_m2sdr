# Checkpoint 771 - [host-redacted] bladeRF access audit after CP770

## Scope

Diagnose the CP770 [host-redacted] precheck anomaly without RF transmit. CP770's bare
`bladeRF-cli -p; bladeRF-cli -e info` precheck reported an inaccessible bladeRF,
but the actual CP770 capture succeeded. This checkpoint checks whether that is
a real device-owner issue, USB instability, or a privilege/environment mismatch.

## Bare bladeRF-cli Result

The audit reproduced the bare-command behavior five times:

- `bladeRF-cli -p`: rc `0`, but only reports `inaccessible device (already in use?)`
- `bladeRF-cli -e info`: rc `1`, `No bladeRF device(s) available.`

This is not evidence of an actual process holding the device. `fuser` showed no
owner before, between, and after the attempts.

## Privilege Check

A follow-up no-TX privilege check under the CP771 evidence set showed the real
cause:

- `id`: `uid=1003([host-redacted]) gid=1003([host-redacted]) groups=1003([host-redacted]),4(adm),27(sudo),100(users)`
- `getent group plugdev`: `plugdev:x:46:sens`
- USB node: `crw-rw---- 1 root plugdev ... /dev/bus/usb/004/002`
- bare `bladeRF-cli -e info`: rc `1`
- `sudo -n bladeRF-cli -e info`: rc `0`, shows `USB speed: SuperSpeed`

So the "already in use" string is libbladeRF's ambiguous wording for this
session's missing direct USB permission. The user `[host-redacted]` is not in `plugdev`;
the device node grants access to `root` and `plugdev`.

This also explains why CP770 capture succeeded: the real capture script
`capture_bladerf_sc16.sh` uses `sudo bladeRF-cli`, including for its probe and
capture command file. Live UE runs also use `sudo -n`.

## Result

`CP771_SENS_BLADERF_BARE_CLI_PERMISSION_MISMATCH_NOT_RF_OWNER`

The CP770 precheck anomaly is explained and is not a blocker for the established
capture or UE paths, because those use `sudo`. It should be fixed in future
prechecks by using `sudo -n bladeRF-cli` or by testing the actual helper path.

This does not explain the CP770 weak/ambiguous SSB result. The current first
failed rung remains DL/SSB/SFN visibility, not bladeRF device ownership.
