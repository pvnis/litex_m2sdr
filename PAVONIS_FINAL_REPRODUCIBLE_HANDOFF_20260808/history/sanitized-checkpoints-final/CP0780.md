# Checkpoint 780 - Local time-slice detector sweep without TX

## Scope

Run offline 0.50 s detector windows across the existing 2 s raw captures. CP199
proved PCI1 at 0.50 s but not in the shorter trims, so this checkpoint asks
whether the current CP772/CP776 failures are just capture-start or time-slice
dependent.

This checkpoint uses no RF:

- no gNB TX
- no UE PRACH TX
- local analysis only on already-pulled raw files

Given the current hardware constraint, there is still no separate known-good
installed physical path to compare against. This checkpoint therefore only
tests whether the existing raw files contain any later good PCI1 interval.

## Interpretation

`CP780_CURRENT_DL_AMBIGUITY_IS_STABLE_ACROSS_CAPTURE_TIME`

CP199 remains a strong reference:

- four of seven 0.50 s slices fully prove expected PCI1
- six of seven slices rank PCI1 first
- PSS scores remain high except the 1.00 s slice

The current captures do not contain a hidden later good interval:

- CP772 has zero PCI1-dominant slices
- CP776 RX1 has zero PCI1-dominant slices
- CP772's best rank is `34` at `0.75 s`, still not proof
- CP776 RX1's best rank is `86` at `0.00 s`, still not proof
- current PSS scores remain near `0.17..0.19`, far below CP199

This rules out a simple capture-start/timing-slice explanation on the existing
raw files. The degradation is persistent across the 2 s captures. Combined with
CP779, the failure is not fixed by naive low-pass filtering and is not hidden in
a later portion of the file.

The first failed rung remains independent DL SSB/cell visibility below PRACH.
The next useful remote checkpoints should focus on bounded TX/RX state
comparisons, gain/readback behavior, clock/[interface-redacted] assumptions, or detector-
independent waveform/PSD features. A live UE PRACH retry is still not justified.
