## Interpretation

`CP781_BACKOFF0_DID_NOT_RECOVER_EXPECTED_PCI_OR_RX_LEVEL`

CP781 weakens a simple "current SSB failure is just insufficient configured gNB
DL power" explanation:

- `tx_gain_backoff: 0` was applied in the generated gNB config.
- The gNB advertised the same PCI1 Band 3 cell and had zero Soapy TX timeouts.
- The independent receiver still saw only ambiguous PSS/PCI.
- The received raw level did not increase over the CP772 backoff10 run.

This does not prove the physical path is good or bad; there is no known-good
installed RF path control. It does show that pushing the existing gNB backoff
knob to `0` is not a recovery path for independent DL/SSB/cell visibility.

The first failed rung remains below PRACH. A live UE retry is still not
justified. Next useful remote work should focus on why the requested/current
downlink power changes are not reflected in the independent RX capture, and on
detector-independent comparisons of the emitted/captured waveform state.
