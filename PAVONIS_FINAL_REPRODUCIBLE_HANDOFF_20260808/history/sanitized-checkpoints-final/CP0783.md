## Interpretation

`CP783_TX_BACKOFF_PARSE_PATH_NOT_PROVEN_IN_VISIBLE_GNB_SOURCE`

CP781 proved the generated config contained `tx_gain_backoff: 0`, but CP783 did
not prove that the running gNB binary consumes that field for SSB amplitude.
This makes the CP781 result more subtle: it weakens the existing wrapper knob as
a recovery path, but it does not prove hardware TX power was changed.

The next user-requested step is a simpler LiteX-path baseline: transmit a test
tone and measure repeatability on [host-redacted] before returning to the gNB SSB path.
