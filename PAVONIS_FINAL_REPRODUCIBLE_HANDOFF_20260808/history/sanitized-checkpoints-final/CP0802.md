# Checkpoint 802 - Live 725 Hz After CP801 gNB Recovery, SFN Fail No PRACH

Date: [date-redacted]

## Purpose

CP800 attempted the live `725 Hz` baseline after RF path checks, but failed before UE start because the gNB strict gate saw TX writeStream timeouts and cancelled the gate. CP801 then proved the independent downlink/gNB SSB path had recovered with zero TX timeouts and expected PCI 1 proven.

CP802 repeated the short live `725 Hz` baseline after that recovery, to determine whether the UE could again reach real PRACH.

## Interpretation

CP802 puts us back on the original live blocker:

- Gross RF directions are proven by CP791 and CP799.
- Independent gNB downlink SSB/PCI is proven by CP801.
- CP802's gNB strict gate is clean.
- The UE still finds PCI late and then fails SFN/cell-select 100/100, before PRACH.

This is not a PRACH frequency-rotation result. The `725 Hz` PRACH path was not exercised because no PRACH was emitted.

CP802 closely resembles CP796:

- CP796: PCI found at trial 34, SFN failed 100/100, no PRACH.
- CP802: PCI found at trial 61, SFN failed 100/100, no PRACH.

The difference from CP794 remains the key instability:

- CP794: `725 Hz` reached cell select and emitted 19 PRACH transmissions.
- CP802: `725 Hz` did not complete SFN/cell-select.

## Next Step

Stop [interface-redacted] PRACH until the UE DL/SFN rung is made reproducible. The next useful lower-rung check is a downlink capture that matches the UE receive geometry more closely:

- center near `1842506000 Hz`
- sample rate `11520000`
- bandwidth matching the UE/bladeRF RX setup
- SSB absolute frequency `1839650000 Hz`
- bladeRF RX gain `40 dB`

That would test whether expected PCI and SSB timing are still clean when viewed with the same center/rate geometry the UE uses, rather than with the SSB-centered CP801 capture.
