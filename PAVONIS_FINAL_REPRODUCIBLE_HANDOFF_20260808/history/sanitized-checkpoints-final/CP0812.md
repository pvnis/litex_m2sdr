## Interpretation

CP812 did not recover PBCH. It also did not improve the PSS/SSS detector result.
The gNB configuration did apply `tx_gain_backoff: 15`, and the gNB had zero TX
timeouts, so this is not a gNB startup failure.

The received raw level stayed near the CP792/CP808 range instead of moving
clearly upward. That suggests the next rung should change the receive-side
capture level directly rather than continuing to lower TX backoff blindly.

## Next step

Run an SSB-centered PBCH probe with gNB backoff restored to `20` and bladeRF
capture gain raised from `40` to `45`. Expected level is still near the
non-clipping boundary, and it directly tests whether the current PBCH failure is
partly an ADC/quantization or bladeRF RX-level problem.
