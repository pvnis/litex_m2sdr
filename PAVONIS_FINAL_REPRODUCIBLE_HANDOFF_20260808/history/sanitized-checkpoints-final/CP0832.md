## Interpretation

CP832 confirms that the current zero-copy post-DMA diagnostic failure is not a
bladeRF artifact:

```text
Pre-DMA waveform PBCH: PASS
Zero-copy post-DMA diagnostic slice: KO
bladeRF: not involved
```

This shifts the immediate debugging branch back to the LiteX zero-copy transmit
path or the diagnostic extraction around it. Because copy-mode previously
decoded post-DMA PBCH at CP821 and CP827, the next checkpoint should rerun
copy-mode now. If copy-mode passes again, the split is zero-copy-specific; if
copy-mode also fails, the issue is broader than the zero-copy branch.
