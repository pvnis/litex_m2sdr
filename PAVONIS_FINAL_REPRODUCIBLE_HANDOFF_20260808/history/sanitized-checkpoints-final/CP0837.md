# Checkpoint 837 - Offline SSB offset sweep: no PBCH recovery

## Purpose

Several RF detector runs reported strongest expected-PCI hits with apparent CFO
near `-12.5 kHz`. CP837 tests whether the local PBCH failure is simply an SSB
frequency metadata issue by reanalyzing existing clean RF captures with
different `ssb_file_test -F` values. This spends no new RF transmit time.

## Method

Added helper:

```text
cp837_ssb_offset_sweep.py
```

The helper:

- Reads a fetched `SC16` capture once.
- Writes one `CF32` vector.
- Runs `ssb_file_test` repeatedly with `SSB = center + offset`.
- Sweeps offsets from `-30000` to `+30000` Hz, including `-12500`, `0`, and `+12500`.
- Records CSI/PBCH parse results per offset.

Captures swept:

| Source | Capture | Why |
| --- | --- | --- |
| CP835 | gain `41`, BW `5.6 MHz` | clean TX, expected cell proven at 0.25 s |
| CP830 | gain `42`, BW `5.6 MHz` | clean TX, best receive-gain run by CSI-window count |

## Interpretation

The PBCH failure is not fixed by telling the local decoder that the SSB is
slightly off center:

```text
CP835 offset sweep: 0/21 PBCH CRC OK
CP830 offset sweep: 0/21 PBCH CRC OK
```

This does not prove the RF carrier has no frequency error, but it rules out the
simple metadata-offset explanation for the current `ssb_file_test` PBCH KO.
The RF path still carries expected PCI, but the PBCH payload remains corrupt or
undecodable after RF capture.
