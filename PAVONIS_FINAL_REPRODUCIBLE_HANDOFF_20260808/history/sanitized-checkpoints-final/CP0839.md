# Checkpoint 839 - Offline I/Q transform sweep: no PBCH recovery

## Purpose

CP837 and CP838 ruled out simple SSB metadata offset and simple CFO correction.
CP839 tests whether the bladeRF raw interpretation is wrong by trying I/Q
polarity, conjugation, 90-degree rotations, and DC removal on existing clean
captures.

## Method

Added helper:

```text
cp839_iq_transform_sweep.py
```

For each capture, the helper tests 16 one-second cases:

- `identity`, `neg`, `conj`, `neg_conj`
- `rot_p90`, `rot_m90`, `conj_rot_p90`, `conj_rot_m90`
- each with raw samples and DC-removed samples

Captures swept:

| Source | Capture | Why |
| --- | --- | --- |
| CP835 | gain `41`, BW `5.6 MHz` | clean TX, expected cell proven at 0.25 s |
| CP830 | gain `42`, BW `5.6 MHz` | clean TX, best receive-gain run by CSI-window count |

## Interpretation

No I/Q transform or DC-removal case recovers PBCH:

```text
CP835 I/Q sweep: 0/16 PBCH CRC OK
CP830 I/Q sweep: 0/16 PBCH CRC OK
```

The bladeRF raw interpretation is therefore not wrong in a simple polarity,
swap, conjugation, or DC-offset way. The RF capture still preserves enough
structure for expected PCI under the normal interpretation, but PBCH remains
undecodable.
