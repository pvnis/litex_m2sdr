# Checkpoint 851 - Reference Correlation Against CP850 RF Capture

## Purpose

Check whether the CP850 bladeRF capture contains a recognizable copy of the exact PBCH CF32 vector transmitted by `test_play.py`. This is stricter than PBCH decoding: if the RF capture contains the replayed waveform but PBCH fails, reference correlation should still show a clear peak.

## Inputs

- Reference vector: `cp823_zero_copy_tx_dump_analysis_[date-redacted]/vectors/pre_dma_full_scale32768.cf32`
- Reference sha256: `2b74912866636bf1add15f371d92f80ab3028040be0b05ba3fcb8e6a1b2ad1e5`
- Capture: `cp848_cf32_pbch_replay_bladerf_[date-redacted]/cp848_cf32_pbch_replay_bladerf_capture_[date-redacted].sc16`
- Capture sha256: `8401d682e4f365111bb01cb0c77f2937d2822f95396b706f5267490a828e67fd`

## Command

```sh
python3 cp851_reference_correlation_scan.py \
  --reference cp823_zero_copy_tx_dump_analysis_[date-redacted]/vectors/pre_dma_full_scale32768.cf32 \
  --capture cp848_cf32_pbch_replay_bladerf_[date-redacted]/cp848_cf32_pbch_replay_bladerf_capture_[date-redacted].sc16 \
  --out-dir cp851_reference_correlation_cp850_dlcenter_[date-redacted] \
  --fs 11520000 \
  --max-capture-samples 2200000 \
  --template-len 65536 \
  --template-block 4096
```

## Method

- Select the highest-energy `65536`-sample template from the known-good reference vector.
- Scan `2200000` capture samples, enough to cover one full `2000000`-sample replay period plus margin.
- Search CFO from `-10000` to `+10000` Hz in coarse steps, then refine around the best coarse result.
- Repeat the scan on both normal and conjugated capture samples to test for IQ/spectrum inversion.
- Run a clean positive control by repeating the reference vector in memory and scanning that with the same template.

## Interpretation

The RF capture does not contain an obvious copy of the transmitted PBCH vector. The best normal score is only `0.0184`, the conjugated-IQ score is lower, and the same scanner scores essentially `1.0` on its clean positive control.

This moves the working theory beyond "the decoder cannot decode the RF capture." The more precise statement is: under CP850 settings, the bladeRF RF capture does not look like the known-good PBCH vector replayed by `test_play.py`, even though `test_play.py` can transmit a CF32 tone successfully in CP849.

The next useful isolation point is inside the LiteX/AD9361 TX chain: prove what samples are actually presented/transmitted for a non-tone CF32 file replay, or use a wider-band deterministic waveform with known correlation properties to determine whether wideband file replay is being filtered, clipped, reordered, or otherwise transformed before RF.
