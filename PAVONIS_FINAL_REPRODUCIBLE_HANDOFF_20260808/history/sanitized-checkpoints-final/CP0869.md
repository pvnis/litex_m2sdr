## RF Routing

Before `rx start`, idle routing was open:

```text
RX1: RFIC 0x0 (A_BAL  ) <= SW 0x0 (OPEN   )
RX2: RFIC 0x0 (A_BAL  ) <= SW 0x0 (OPEN   )
TX1: RFIC 0x0 (TXA    ) => SW 0x0 (OPEN   )
TX2: RFIC 0x0 (TXA    ) => SW 0x0 (OPEN   )
```

During active RX:

```text
RX1: RFIC 0x1 (B_BAL  ) <= SW 0x2 (RF3(B) )
RX2: RFIC 0x1 (B_BAL  ) <= SW 0x0 (OPEN   )
TX1: RFIC 0x0 (TXA    ) => SW 0x0 (OPEN   )
TX2: RFIC 0x0 (TXA    ) => SW 0x0 (OPEN   )
```

After `rx wait`, routing returned to idle/open.

During and after RX, RSSI was around:

- preamble: `-97 dB`
- symbol: `-101` to `-100 dB`

## Interpretation

The idle `OPEN` state is normal channel-disabled behavior. During RX1 capture the bladeRF does enable a physical RF route:

```text
RX1 <= RF3(B)
```

This does not explain the weak modulated-waveform result. It does, however, record the exact active route used by the current generic/explicit RX1 capture path. CP775 already showed generic `rx` behaves like explicit RX1 and RX2 is much quieter with no TX, so the current software path is still RX1-equivalent.

The remaining issue is not an obviously disabled RF switch.
