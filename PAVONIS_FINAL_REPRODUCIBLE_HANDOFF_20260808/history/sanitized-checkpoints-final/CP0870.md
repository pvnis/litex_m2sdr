# Checkpoint 870 - 1SC Symbol Projection Analysis

## Purpose

Analyze the CP866 `+60 kHz` one-subcarrier captures without spending more RF.

CP866 showed all bladeRF receive modes stuck near `0.30` whole-waveform correlation. CP870 asks a narrower question:

Does the bladeRF capture contain the expected single subcarrier energy, and if so, does that subcarrier carry the transmitted QPSK symbol sequence?

## Analyzer

New local analyzer:

- `cp870_analyze_1sc_symbol_projection.py`
- sha256: `e3a3f87009f8a5086399a8774b680970b32d9b8672b7b86ea8c79a5c8b66ecae`

The script:

1. Loads the known one-subcarrier CF32 reference.
2. Loads a bladeRF SC16 or LiteX CF32 capture.
3. Uses the existing CP851 best transform/start/CFO.
4. Projects each `384`-sample OFDM symbol onto the intended bin.
5. Compares the resulting per-symbol phasors against the transmitted reference symbols.

## Interpretation

CP870 is an important split:

- The bladeRF captures have substantial energy in the expected `+60 kHz` bin.
- That bin does not carry the transmitted QPSK symbol sequence.
- The phase is effectively random relative to the reference: about `103 deg` standard deviation and only about `25-27%` of symbols within `45 deg`.
- The LiteX-only control passes the same analysis with symbol correlation `0.9696`, phase std `8.3 deg`, and `99.89%` of symbols within `45 deg`.

This says the weak CP866 correlation is not just "too little energy." The capture is energetic in the target bin, but the desired symbol sequence is absent or buried under an unrelated coherent component/spur near the same bin.

The next high-value RF test is to move the same one-subcarrier modulated probe farther from LO/DC, for example to `+500 kHz`, and use a bladeRF RX bandwidth wide enough to include it. If `+500 kHz` recovers symbol correlation while `+60 kHz` fails, the failure is near-LO/DC/spur/filter behavior. If `+500 kHz` also fails while a pure tone passes there, the remaining issue is specific to phase-modulated waveforms through the bladeRF/physical path.
