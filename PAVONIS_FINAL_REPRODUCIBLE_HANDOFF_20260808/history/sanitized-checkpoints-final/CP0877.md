## Interpretation

This isolates the current failure boundary to the part of the path that is present in CP876 but absent in CP877:

- bladeRF receive frontend/settings/calibration
- physical coupling/cable/antenna path into bladeRF
- level/frequency/filter behavior specific to bladeRF RX

It also rules out the main "nothing changed and now the waveform is bad" software-path concern for this probe: immediately after CP876, the same file and matched transmit scale were recovered by LiteX-only RX/TX with full-template scores around `0.97` and dwell scores above `0.996` at `1 ms`.

Next useful rung remains narrowing the bladeRF threshold between `5 ms` and `2 ms`, while keeping CP877 as the current known-good LiteX-only baseline.
