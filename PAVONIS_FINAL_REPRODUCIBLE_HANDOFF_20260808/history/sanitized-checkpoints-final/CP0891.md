## Interpretation

This repeat did not simply reproduce CP887/CP890 with a shifted origin. The mechanics are clean, LiteX TX reports a complete error-free transmission, bladeRF captured the expected byte count without clipping, but the correlation/coherence structure changed materially.

The current evidence still isolates away from the LiteX-only software path because CP888 passed immediately before this repeat. CP891 instead strengthens the bladeRF/physical-path repeatability concern: even with the same CP881 waveform and same nominal RF settings, the bladeRF capture can change from "locally excellent but phase-discontinuous" to "not locally strong under the first plausible fixed-grid checks."

The next step should be either a quick repeated short-tone/phase pilot on the bladeRF path to measure whether the channel is drifting between captures, or a more exhaustive alignment search on CP891 before spending more RF time.
