the CP894 deterministic loop-continuous `500 kHz` CF32 tone file through LiteX SDR

## Interpretation

The LiteX-only deterministic tone baseline is healthy. It detects and coherently
tracks the CP894 file at the expected `500 kHz` with no window-FFT bin drift,
near-zero residual CFO, no stream errors, and high autocorrelation coherence.

This rules out the deterministic tone file, local file replay mechanics, [host-redacted]
LiteX Soapy TX, [host-redacted] LiteX Soapy RX, and the local CP892 analysis as the cause of
the bladeRF-side continuous-phase failures seen in CP892, CP894, and CP895.

The current working model remains: bladeRF receive settings and/or the physical
LiteX-to-bladeRF RF path are the unstable variables. The next ladder step should
continue isolating bladeRF RX behavior, starting with requested RX gain at `2 MHz`
bandwidth using the same deterministic file tone.
