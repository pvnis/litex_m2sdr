# Checkpoint 901 - bladeRF Internal RX Mux Counter Stream Pass

## Purpose

Separate the bladeRF USB/FPGA RX streaming and SC16 file path from the analog RF
receive path.

CP900 showed no obvious clock, mux, loopback, filter, bitmode, or bias-tee
misconfiguration. CP901 therefore temporarily switches the bladeRF RX FIFO input
mux to internal counter sources, captures bounded SC16 files, restores
`BASEBAND`, and verifies that the pulled samples contain monotonic counter
streams.

This does not use the LiteX TX and does not exercise the bladeRF RF input.

## Interpretation

CP901 proves that the bladeRF can stream full-length SC16 captures through the
same CLI/file/SCP/local-analysis class of path and preserve deterministic
internal counter sequences.

This strongly reduces the probability that the current deterministic-tone
failure is caused by generic USB streaming, sample packing, file pull, local
SC16 parsing, or analysis infrastructure. It also proves that the helper can
mutate and restore bladeRF `rx_mux` state cleanly.

Combined with CP896 through CP900:

- LiteX deterministic RX/TX is healthy.
- bladeRF manual-gain RF capture is repeatable in broad spectral terms but not
  phase coherent.
- bladeRF clock/mux/filter/loopback/bitmode/bias-tee state is not obviously
  wrong.
- bladeRF internal digital RX streaming is healthy.

The unresolved boundary is now the bladeRF analog RF receive path and its
retune/correction behavior, or the physical RF path into the bladeRF. The next
non-blind step should keep the CP894 deterministic LiteX tone and manual gain
`42`, then test whether an explicit bladeRF RF receive reset/retune sequence
changes the CP898/CP899 tone coherence class.
