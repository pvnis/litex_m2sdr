# Checkpoint 904 - Tone Window Phase Jumps Localize bladeRF Coherence Failure

## Purpose

Quantify the window-to-window phase offsets hinted by CP890 using the fresh
deterministic tone captures.

CP890 showed that the bladeRF phase-flip waveform can be recovered if each
window gets its own CFO and phase alignment. CP904 applies the same diagnostic
idea to the simpler CP894 continuous tone: use CP892's `10 ms` FFT-peak phase
windows, remove one global linear phase slope, then measure residual phase
jumps between windows.

This checkpoint is analysis-only. It does not touch the radios.

## Method

For each CP892 JSON:

1. Use the `rows_peak_tone` `10 ms` phase windows.
2. Unwrap phase at the CP892 global FFT-peak tone.
3. Fit one global linear phase slope.
4. Wrap the residual phase around that fit.
5. Measure adjacent-window residual phase steps.

This intentionally asks whether one smooth CFO term explains the receive phase.
Large residual steps mean the tone is present but not globally coherent.

## Interpretation

CP904 gives a clean localization:

- LiteX-only tone captures have small residual phase error after one global
  slope: about `0.5-1.7 deg` residual RMS, no adjacent `10 ms` steps above
  `60 deg`, and autocorr coherence around `0.90-0.97`.
- bladeRF RX1 captures have the tone at healthy amplitude and SNR, but one
  global slope leaves about `100 deg` residual RMS and many adjacent `10 ms`
  jumps above `60 deg`.
- CP902's [interface-redacted]/[interface-redacted] reduced the number of large steps but did not
  move the path into the LiteX-only class.
- RX2 is weaker and lower coherence; it does not provide a cleaner path.

This supports CP890's conclusion with the simpler tone: the RF energy is present,
but the bladeRF/physical receive path is introducing window-scale phase offsets
that a single CFO correction cannot model.

The remaining useful branch is not more gain, RX channel selection, or simple
retune reset. The next non-destructive hardware-facing tests should target
bladeRF analog/RF state that can cause phase discontinuity: filter mode,
loopback/BIST behavior, or carefully documented transient DC/IQ correction
experiments. Permanent calibration-table writes are still not justified without
explicit approval.
