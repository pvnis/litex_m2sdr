# Checkpoint 905 - bladeRF RX Filter Bypass Does Not Recover Tone Coherence

## Purpose

Test a reversible bladeRF RX FIR mode change before considering any calibration
or correction mutation.

CP900 showed the bladeRF RX FIR was `normal (default)` and that `bypass` is an
available mode. CP905 captures the same deterministic CP894 LiteX tone with:

- `set filter rx normal`
- `set filter rx bypass`

Both captures use the same LiteX TX session, manual bladeRF gain `42`, `2 MHz`
bladeRF bandwidth, and `2 s` capture length. The helper restores `filter rx
normal` after each capture.

## Interpretation

RX FIR `bypass` is not a recovery path.

It increases amplitude and median tone SNR, but it substantially worsens the
window-frequency estimate, FFT-peak coherence, autocorrelation coherence, and
window-to-window phase jumps. The default `normal` RX FIR remains the least-bad
setting for this deterministic tone.

This closes the simple RX filter-mode branch. The remaining bladeRF-side
software knobs with plausible relevance are calibration/correction operations,
but those mutate state and the current CLI cannot print existing correction
values. They should only be tried as explicitly documented transient
experiments, not as permanent calibration-table writes.
