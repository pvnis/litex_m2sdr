## Relevant Help Surface

`help tx` confirms the same TX mechanism used by the earlier successful
bladeRF TX checkpoints:

- `tx config file=<path> format=bin repeat=<count> samples=<n> buffers=<n> xfers=<n> timeout=<duration> channel=<channel>`
- `tx start`
- `tx wait <timeout>`
- `tx stop`

`help rx` confirms the same RX mechanism used by the bladeRF capture helpers:

- `rx config file=<path> format=bin n=<samples> samples=<n> buffers=<n> xfers=<n> timeout=<duration> channel=<channel>`
- `rx start`
- `rx wait <timeout>`
- `rx stop`

The parameter-specific `help set loopback` and `help set rx_mux` forms are not
accepted by this CLI build, but CP900 already captured the relevant `set` help:

- `set loopback <rfic_bist|firmware|none>`
- `set rx_mux <BASEBAND|12BIT_COUNTER|32BIT_COUNTER|DIGITAL_LOOPBACK>`

## Interpretation

CP906 confirms a bladeRF-internal loopback tone checkpoint is feasible using
only already-tested CLI primitives:

1. Generate a small SC16 tone on `[host-redacted]`.
2. Configure TX1 and RX1 in one `bladeRF-cli` script.
3. Set loopback mode to `firmware` or `rfic_bist`.
4. Start RX first, then TX, wait for both, copy the captured SC16 file locally.
5. Restore `loopback none`, `rx_mux BASEBAND`, and `filter rx normal`.

This is the next non-calibration branch. It should separate bladeRF-internal
TX/RX/loopback behavior from the installed external RF path into RX1/RF3(B).
Calibration/correction writes are still not justified.
