# Checkpoint 907 - bladeRF Firmware Loopback Tone Pass

## Purpose

Test a bladeRF-internal sample loopback before touching calibration/correction
state.

CP901 proved the RX USB/FPGA stream using counter muxes. CP907 adds the TX side:
it generates a small SC16 tone on `[host-redacted]`, configures `set loopback
firmware`, starts RX, starts TX, captures the looped samples, pulls the raw file
locally, and runs the same CP892/CP904 tone-stability analysis used on the
degraded RF captures.

The CLI describes `firmware` loopback as `Firmware-based sample loopback`, so
this checkpoint isolates bladeRF host TX streaming, firmware sample loopback,
host RX streaming, raw-file transfer, and local analysis from the external RF
path into RX1/RF3(B).

## Interpretation

CP907 passes cleanly.

The bladeRF can transmit host-provided SC16 samples, loop them back in firmware,
receive them back over the RX streaming path, and preserve a coherent tone over
the same CP892/CP904 analysis windows that show large phase discontinuities on
the external LiteX-TX to bladeRF-RX RF captures.

This closes another software-only branch:

- not local SC16 analysis
- not SCP/raw-file handling
- not bladeRF RX USB streaming
- not bladeRF host TX streaming
- not bladeRF firmware sample loopback

The remaining unresolved boundary is now below firmware loopback and above the
known-good LiteX deterministic TX baseline: bladeRF RFIC/analog receive path,
RFIC BIST behavior, correction/calibration behavior, or the installed physical
path into RX1/RF3(B).

The next non-calibration checkpoint is an `rfic_bist` loopback tone test. It is
more RFIC-adjacent than `firmware` loopback and still avoids the external RF
cable/antenna path.
