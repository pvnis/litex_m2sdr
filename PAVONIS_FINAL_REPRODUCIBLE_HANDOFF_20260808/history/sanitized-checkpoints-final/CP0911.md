## Purpose

Test whether the normal bladeRF external RX bandwidth setting is responsible for
the degraded LiteX-to-bladeRF tone coherence.

CP910 used `2 MHz` bladeRF RX bandwidth. CP911 repeats the same deterministic
LiteX TX tone and bladeRF RX1/RF3(B) capture with bladeRF RX bandwidth widened
to `5.6 MHz`.

## Interpretation

Widening bladeRF RX bandwidth to `5.6 MHz` is not a recovery path.

It increases received amplitude, but it reduces tone SNR, worsens FFT-peak
coherence, worsens autocorrelation coherence, and increases phase-jump counts.
The best normal external-RX setting tested so far remains the earlier `2 MHz`
bandwidth with RX FIR `normal`, but even that remains much worse than CP907
firmware loopback and CP909 RFIC BIST loopback.

This closes the simple normal-RX bandwidth branch for the current deterministic
tone setup.
