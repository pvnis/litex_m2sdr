## What Is Now Ruled Out

The current evidence argues against:

- broken local tone analysis,
- SCP/raw-file corruption,
- generic bladeRF RX USB streaming failure,
- generic bladeRF host TX streaming failure,
- bladeRF firmware sample-loopback failure,
- RFIC BIST loopback failure,
- simple RX FIR bypass as a recovery path,
- simple wider RX bandwidth as a recovery path,
- tone-offset-specific failure between `100 kHz` and `500 kHz`,
- stale loopback/rx_mux/filter state after restoration.

## What Remains Plausible

The unresolved boundary is the normal external RX path:

- bladeRF normal RF receive front-end/switch path into RX1/RF3(B),
- physical path from LiteX TX to bladeRF RX1/RF3(B),
- correction/calibration state that affects normal RF receive but not firmware
  loopback or RFIC BIST loopback,
- an external-path propagation/fixture issue that preserves gross tone energy
  but breaks phase coherence over 10 ms windows.

## Calibration/Correction Status

No permanent calibration or correction writes were performed.

The CLI can mutate DC/IQ calibration state, but CP900 showed this build cannot
print current correction values with `print correction`, and `calibrate lms
show` is not valid on this bladeRF2. A calibration/correction experiment should
therefore be treated as state-mutating and should only be run with explicit
approval and a clearly logged before/after/restore plan.

## Practical Next Branches

1. Physical-path intervention if available:
   - known-good cable/attenuator path into bladeRF RX1/RF3(B),
   - reseat/check installed path,
   - external spectrum/receiver confirmation at the bladeRF RX input.

2. Explicitly approved transient correction/calibration experiment:
   - avoid table writes first,
   - use only reversible/current-session correction commands if possible,
   - capture before/after deterministic tone metrics,
   - restore normal state and record all CLI output.

3. Return to the live stack while treating bladeRF normal external RX as
   suspect:
   - useful only if the live ladder does not depend on coherent bladeRF
     external RX measurements for the next decision.

## Current Recommendation

Do not spend more time on bladeRF host streaming, firmware loopback, RFIC BIST,
RX FIR bypass, RX bandwidth, or tone offset. Those branches are now closed for
the observed failure.

The next high-value step is either a known-good physical path into bladeRF
RX1/RF3(B), or explicit approval to run a tightly scoped, logged,
non-persistent calibration/correction experiment.
