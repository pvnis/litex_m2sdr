# Checkpoint 916 - LiteX-only Exact PBCH Vector RX/TX Baseline Pass

## Purpose

Create a fresh RX/TX baseline using only the LiteX/M2SDR path, with the same
known PBCH-positive CF32 vector that fails after RF capture through the bladeRF
path in CP915.

This isolates the bladeRF and external receive path from the source waveform:

- if LiteX TX/RX cannot recover the exact vector, the source/replay path is
  suspect;
- if LiteX TX/RX can recover the exact vector but bladeRF still cannot decode
  PBCH, the first failed stage remains on the external bladeRF RF receive side

## Interpretation

The current "we did not change anything and now receive no decodable PBCH"
condition is not explained by loss of the known source vector or by a generic
LiteX file replay failure.

The Stage 5 boundary remains:

```text
Known PBCH-positive CF32 vector
  -> LiteX TX/replay path: current PASS by LiteX-only exact-vector correlation
  -> external LiteX-to-bladeRF RF capture path: current FAIL for PBCH decode
```

This strengthens the CP910-CP915 interpretation: the failure is associated
with the external bladeRF normal RF receive path, the physical path into it, or
bladeRF normal RF calibration/correction state, not with the PBCH source vector
or LiteX TX/RX baseline.

Do not move to PRACH yet. The first failed ladder rung remains Stage 5 RF PBCH
decode.
