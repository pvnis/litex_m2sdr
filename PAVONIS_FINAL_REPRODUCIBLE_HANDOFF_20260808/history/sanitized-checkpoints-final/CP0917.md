# Checkpoint 917 - LiteX-only Full-capture PBCH Decode Pass

## Purpose

Extend CP916 from an exact-vector correlation baseline to a decoder-level
baseline.

correlation through LiteX/M2SDR RX/TX in the current state. CP917 asks the next
question: can `ssb_file_test` decode PBCH/MIB from those LiteX-only captures?

This is still a non-bladeRF baseline. No new RF transmit or capture was run in
this checkpoint; it analyzes the CP916 captures already pulled from [host-redacted].

## Interpretation

This is the strongest current isolation result:

```text
Known PBCH-positive CP823 vector
  -> LiteX TX/RX full-capture decode: PASS
  -> LiteX TX -> bladeRF RX full RF decode: FAIL
```

The source waveform, LiteX replay, and LiteX receive side are not the reason
the system "suddenly cannot receive anything." In the current state, the same
PBCH vector is decodable through the LiteX-only path.

The first failed ladder rung remains Stage 5 after the bladeRF/external RF
receive boundary. Continue isolating:

- bladeRF normal external RF receive chain,
- physical RF/cable/attenuator path into bladeRF,
- bladeRF normal RF correction/calibration state.

Do not move to PRACH yet.
