## Interpretation

CP920 tightens the Stage 5 boundary again.

The failure is reproduced while the bladeRF is actively routed through:

```text
RX1 / RF3(B), baseband mux, loopback none, RX FIR normal, AGC off, gain 42
```

The capture level is healthy and unclipped, but the content is still not a
coherent match to the known-good SSB-centered PBCH reference and does not
decode PBCH.

This makes the remaining non-hardware/software explanation space very small:

- not LiteX source vector,
- not LiteX TX/RX baseline,
- not local PBCH decoder alone,
- not bladeRF USB/sample counter path,
- not bladeRF firmware/RFIC internal loopbacks,
- not obvious idle or active mux/loopback/filter/AGC/channel route state.

The remaining realistic branches are:

- physical RF path into bladeRF RF3(B),
- bladeRF normal external RF receive behavior not exercised by internal
  loopback,
- bladeRF DC/IQ correction/calibration state.

The DC/IQ correction branch mutates device state and the current CLI cannot
print existing correction values, so it should be treated as an explicit
transient experiment only after approval. Do not move to PRACH yet.
