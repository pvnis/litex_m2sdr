## None-loopback Caveat

The fresh `none_file` result is not a stream or correlation failure:

- Soapy counters were clean: `0` RX overflows, `0` RX errors, `0` RX timeouts,
  `0` TX errors, and `0` TX timeouts.
- Exact-vector correlation passed strongly: score `0.8788544265`, normal
  transform, `0.0 Hz` refined CFO.
- Rerunning `ssb_file_test` on the same `none_file` produced the identical log
  hash `d64e0c6f8b9452d4c56f500c0bddecfd752b9107056c6b3514e9493e8b01efbd`.
- Pattern `C` produced the same result and same hash.
- A reframed local slice from the inferred waveform boundary also stayed PBCH
  CRC `KO`: `none_file_skip2022_count2000000.cf32` hash
  `08a4a5308dca2ced3f244322dfb3a9b3f0e2c92122e50089b509f565cf681daf`,
  decode log hash
  `480240c534fda549ef33ce2837a117fbafdbba82dba1555bf90f2c25392497ff`.

This is a regression relative to CP917, where `none_file` decoded PBCH with
CSI SNR `+0.8 dB`. In CP921, `ssb_file_test` measures the same `none` capture at
CSI SNR `-25.2 dB` on the full buffer even though correlation is strong.

The practical interpretation is that the no-loopback LiteX PBCH decoder result
is marginal in this configuration. It should not be used as the sole health
indicator. The stronger, bladeRF-independent controls are:

1. exact-vector correlation through all LiteX loopbacks, including `none`;
2. full PBCH decode through `phy`;
3. full PBCH decode through `ad9361`;
4. the local CP823 source-vector PBCH decode.

## Interpretation

CP921 keeps the bladeRF isolated from the source/LiteX side:

```text
Known PBCH-positive CP823 vector
  -> local source decode: PASS
  -> LiteX TX/RX exact-vector correlation: PASS in none, phy, ad9361
  -> LiteX TX/RX PBCH decode: PASS in phy and ad9361
  -> LiteX TX -> bladeRF RX: still fails PBCH and reference correlation
```

This rules out a broad "LiteX cannot transmit or receive the test waveform
anymore" explanation. It also records a real caveat: the no-loopback LiteX PBCH
decode is currently not reliable enough to be treated as a standalone baseline,
despite coherent vector recovery.

The first failed ladder rung remains Stage 5 RF PBCH decode after the
bladeRF/external receive boundary. Do not move to PRACH/Stage 6.
