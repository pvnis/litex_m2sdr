# Checkpoint 922 - bladeRF Calibration CLI Read-only Audit

## Purpose

Continue the bladeRF-side branch without mutating device state.

CP920 left the likely remaining suspects as:

- physical RF path into bladeRF;
- bladeRF normal external RF receive behavior;
- bladeRF DC/IQ correction or calibration state.

Before running any calibration/correction experiment, this checkpoint audits the
installed `bladeRF-cli` surface to see what can be read, backed up, or restored.
No calibration operation was executed, no `set` command was executed, and no TX
or RX capture was run.

## Calibration Surface

`help` exposes a `calibrate` command. `help cal` lists these operations:

| Operation | CLI form | Effect |
| --- | --- | --- |
| LMS internal DC auto-calibration | `calibrate lms [show]`, `[interface-redacted]`, `txlpf`, `rxlpf`, `rxvga2` | bladeRF1/LMS-oriented calibration surface |
| DC correction calibration | `calibrate dc <rx|tx> [<I> <Q>]`, `calibrate dc <rxtx>` | calibrates or directly applies I/Q DC correction for current frequency/gain |
| IQ balance correction | `calibrate iq <rx|tx> <gain|phase> <value>` | directly applies gain or phase balance correction |
| DC correction table generation | `calibrate table dc <rx|tx> [<f_min> <f_max> [f_inc]]` | generates a local table file |
| AGC table generation | `calibrate table agc <rx|tx> [<f_min> <f_max> [f_inc]]` | generates a table after setting AGC base gain |

Important limitation: the available commands are mostly write/apply operations.
They do not provide a current bladeRF2 DC/IQ correction readback in this CLI
build.

## Readback Surface

`help print` still has no correction parameter. CP919 already verified:

```text
print: Invalid parameter (correction)
```

This audit also checked `help set correction`. The CLI did not expose a
`set correction` parameter; it returned generic `help` command text instead.

`calibrate lms show` returned `rc=0` but printed no calibration values for this
bladeRF2 device. The log also emitted the CLI warning:

```text
calibrate: Only use this calibration on bladeRF x40 and x115 devices.
```

So `calibrate lms show` is not a useful readback path for the current bladeRF2
stack.

## Flash Backup Surface

`help flash_backup` is available and can back up the flash calibration region:

```text
flash_backup <file> cal
```

`help flash_restore` is also available. This is useful for protecting flash
calibration data before any experiment that might touch flash.

However, the suspected CP920/CP915 failure is in active normal RX behavior and
likely volatile DC/IQ correction state. A flash backup does not provide a
readback or restore point for transient runtime DC/IQ correction values applied
by `calibrate dc` or `calibrate iq`.

## Interpretation

This audit closes one important safety question:

```text
The installed bladeRF CLI can apply calibration/correction changes, but it
cannot read back the current bladeRF2 DC/IQ correction state through `print`,
`set correction`, or `calibrate lms show`.
```

Therefore, a calibration/correction branch is not fully reversible from current
CLI readbacks. It remains an explicit-approval branch.

The safest possible future experiment would be transient and bounded:

1. take a flash calibration backup first if flash writes are even a remote risk;
2. record a before capture with the deterministic tone or CP823 PBCH replay;
3. apply only one narrowly scoped runtime correction operation;
4. record an after capture immediately;
5. power-cycle/reopen/reinitialize the bladeRF and re-record state;
6. compare before/after by the same correlation and PBCH/tone metrics.

No such mutation was performed in CP922.

The current first failed rung remains Stage 5 RF PBCH decode after the
bladeRF/external receive boundary. Do not move to PRACH/Stage 6.
