# Checkpoint 923 - bladeRF Calibration Flash Backup

## Purpose

Create a non-mutating restore artifact before any future explicit-approval
calibration/correction branch.

CP922 showed that the installed `bladeRF-cli` can apply calibration/correction
operations but cannot read back the current bladeRF2 DC/IQ correction state.
This checkpoint backs up the bladeRF flash calibration region only. It does not
run RX/TX, does not run `calibrate`, does not run `set`, and does not restore or
write flash.

## Command

Remote backup:

```sh
python3 ssh_pexpect_run.py \
  --host [host-redacted] \
  --out cp923_[date-redacted]TCALBACKUP1_sens_bladerf_flash_backup_cal.log \
  --timeout 180 \
  -- bash -lc 'bladeRF-cli -e "flash_backup /tmp/cp923_bladerf2_5c750e8ef0e44a068c7c99fedb9b35fd_cal_[date-redacted]TCALBACKUP1.img cal"; sha256sum ...; process check'
```

Local pull:

```sh
python3 scp_pexpect_get.py \
  --host [host-redacted] \
  --remote /tmp/cp923_bladerf2_5c750e8ef0e44a068c7c99fedb9b35fd_cal_[date-redacted]TCALBACKUP1.img \
  --local cp923_bladerf2_5c750e8ef0e44a068c7c99fedb9b35fd_cal_[date-redacted]TCALBACKUP1.img \
  --out cp923_[date-redacted]TCALBACKUP1_scp_get_cal_backup.log \
  --timeout 120
```

## Interpretation

This gives us a flash calibration restore artifact, but it does not solve the
main CP920 safety issue by itself:

- it protects the flash calibration region;
- it does not read or preserve volatile runtime DC/IQ correction values;
- it does not make `calibrate dc` or `calibrate iq` fully reversible through
  CLI readback.

So CP923 improves safety for a future approved experiment, but calibration and
correction writes remain explicit-approval-only.

The first failed ladder rung remains Stage 5 RF PBCH decode after the
bladeRF/external receive boundary. Do not move to PRACH/Stage 6.
