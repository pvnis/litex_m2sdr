# Checkpoint 925 - Fresh LiteX-only RX/TX baseline isolates bladeRF

## Purpose

Create a current bladeRF-independent RX/TX baseline using only the LiteX/M2SDR
path. This directly tests the concern that "we did not change anything and now
we cannot receive anything anymore" before continuing on the bladeRF receive
branch.

The test replays the known PBCH-positive CP823 CF32 vector through the existing
CP853 LiteX Soapy file RX/TX harness, captures `none`, `phy`, and `ad9361`
loopbacks, then checks both exact-vector correlation and PBCH decode.

## Interpretation

CP925 gives a clean current source-side baseline:

```text
Known PBCH-positive CP823 vector
  -> local source decode: PASS
  -> LiteX TX/RX exact-vector correlation: PASS in none, phy, ad9361
  -> LiteX TX/RX PBCH decode: PASS in none, phy, ad9361
  -> LiteX TX -> bladeRF RX: still failed in CP924
```

This rules out a broad current "LiteX cannot transmit/receive the test waveform"
explanation. The CP921 no-loopback PBCH caveat did not reproduce here; the
current no-loopback LiteX capture decodes PBCH CRC OK despite one RX overflow.

The first failed ladder rung remains Stage 5 RF PBCH decode at or after the
bladeRF/external receive boundary. Do not move to PRACH/Stage 6.
