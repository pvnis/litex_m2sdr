## Method

For each CP892 JSON:

1. use the `rows_peak_tone` `10 ms` phase-window rows;
2. unwrap phase at the CP892 global FFT-peak tone;
3. fit one global linear phase slope;
4. wrap residual phase around that fit;
5. measure adjacent-window residual phase steps;
6. mark events where absolute adjacent step is at least `60 deg`.

This is the same conceptual metric used in CP904, extended with event timing and
inter-arrival summaries.

## Control Behavior

The LiteX-only `phy` control has no `>=60 deg` events. Its largest adjacent
step is only `2.364 deg`.

The CP928 RFIC BIST control has no `>=60 deg` events. Its largest adjacent step
is effectively numerical zero.

This means CP929's event clustering is specific to the CP927 normal external
bladeRF receive path.

## Interpretation

CP929 refines the CP927 failure:

```text
The external-path phase failure is not just random sparse glitches.
It can enter a sustained late-window burst where nearly every 10 ms window has
a large residual phase step after one global phase slope is removed.
```

That pattern is consistent with a normal external RX path entering an unstable
state during the capture. It is not reproduced by the LiteX-only path or by
bladeRF RFIC BIST.

Current boundary:

```text
LiteX-only RX/TX: PASS
bladeRF RFIC BIST internal path: PASS
LiteX TX -> bladeRF normal external RX: FAIL, with clustered late phase jumps
```

remains Stage 5 RF receive coherence/PBCH at the bladeRF/external path. Do not
