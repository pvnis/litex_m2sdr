# Checkpoint 932 - CP930 segment phase-burst timing

## Purpose

CP930 showed that the four-second external LiteX TX to bladeRF RX tone capture
has a severe sustained late phase-jump burst. CP932 is local analysis only. It
segments the existing phase-window rows into `0.5 s` bins to quantify exactly
when the path changes state.

No radio command was run and no device state was changed.

## Interpretation

CP932 makes the CP930 failure shape more precise:

```text
The external bladeRF receive path is not uniformly bad throughout the capture.
It can be relatively quiet around 1.0-2.0 s, then transitions after 2.0 s into
a sustained high-event state, reaching 100% >=60 deg event fraction after 3.0 s.
```

That matters for future RF tests. A short external capture can miss or
understate the worst mode depending on when it starts and stops. For repeatable
external-path testing, keep the capture long enough to observe whether the late
burst state appears, or deliberately run multiple short captures with a
controlled delay/stagger and compare segment timing.

The source-side controls remain clean:

```text
LiteX-only tone: PASS
LiteX-only PBCH/vector CP931: PASS
bladeRF RFIC BIST: PASS
LiteX TX -> bladeRF normal external RX: FAIL, time-dependent phase-burst mode
```

The first failed ladder rung remains Stage 5 RF receive coherence/PBCH at the
bladeRF/external path. Do not move to PRACH/Stage 6.
