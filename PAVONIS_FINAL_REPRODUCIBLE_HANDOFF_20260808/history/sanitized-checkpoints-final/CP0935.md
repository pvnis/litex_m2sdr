# Checkpoint 935 - RX filter bypass sweep does not recover external path

## Purpose

CP930/CP933/CP934 show the external LiteX TX to bladeRF RX tone path has a
repeatable phase-burst failure. CP935 isolates the bladeRF RX FIR/filter mode by
running a same-replay sweep:

```text
LiteX/M2SDR TX deterministic 500 kHz tone -> installed RF path -> bladeRF RX1/RF3(B)
bladeRF RX filter modes: normal, bypass
RX gain: 42 dB
```

No bladeRF calibration or correction mutation was performed. The helper
restored the RX filter to `normal` at the end of each capture.

## Interpretation

CP935 does not identify the normal RX FIR as the sole cause of the external
path failure:

```text
normal: failed in the familiar sustained phase-burst pattern
bypass: did not recover; analyzer verdict worsened to WARN with unstable tone estimates
```

The bypass result should not be treated as a clean apples-to-apples phase
improvement because its tone SNR and frequency stability collapsed. It is still
useful as a negative result: simply bypassing the RX FIR did not produce a
coherent external receive path.

Current boundary:

```text
LiteX-only PBCH/vector CP931: PASS
LiteX-only tone control: PASS
bladeRF RFIC BIST: PASS
LiteX TX -> bladeRF normal external RX: FAIL
LiteX TX -> bladeRF bypass external RX: not recovered, CP892 WARN
```

The first failed ladder rung remains Stage 5 RF receive coherence/PBCH at the
bladeRF/external path. Do not move to PRACH/Stage 6.
