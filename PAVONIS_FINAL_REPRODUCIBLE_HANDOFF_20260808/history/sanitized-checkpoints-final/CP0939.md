## Interpretation

CP939 is a cleanly executed negative result, but it should not be treated as a
final verdict on `dec2` PBCH reception. The reason is bandwidth: a 15 kHz SSB
occupies about `240 * 15 kHz = 3.6 MHz` before practical filter margins, while
CP939 used a `2 MHz` bladeRF receive bandwidth to mirror the CP937 tone test.
That is a plausible self-inflicted PBCH truncation.

What CP939 does establish:

```text
LiteX source health immediately before run: PASS in CP938
bladeRF capture execution: PASS
bladeRF filter mode: dec2 applied and read back
bladeRF temperature: normal, 32.5 C to 33.3 C
2 MHz PBCH decode/correlation: FAIL
```

The next checkpoint should repeat the same `dec2` PBCH replay/capture with a
PBCH-appropriate receive bandwidth, starting with the previous CP920 default
`CAP_BW_HZ=5600000`.
