# Checkpoint 947 - Near-adjacent tone control on the same centered bladeRF route

## Purpose

CP942-CP944 showed that the centered 5.76 Msps PBCH-positive source does not
recover through the external bladeRF receive path. CP946 then showed that the
same bladeRF receive settings with no transmitter are effectively identical to
those PBCH captures.

CP947 tests whether the same external RF route is completely dead, or whether a
simple tone still couples through:

```text
LiteX/M2SDR replay of 500 kHz tone
  -> external RF path
  -> bladeRF receive, same centered RF settings
filters: normal, dec2
```

No bladeRF calibration or correction state was changed.

## Comparison To The PBCH Failures

| Checkpoint | Route | Result |
| --- | --- | --- |
| CP942 | centered PBCH source -> bladeRF `dec2` | PBCH fail, correlation floor |
| CP943 | centered PBCH source -> bladeRF `normal` | PBCH fail, correlation floor |
| CP944 | centered PBCH source -> bladeRF `normal`, TX_ATT 15 | PBCH fail, unchanged RMS/correlation |
| CP946 | no TX -> bladeRF centered `normal` | no-TX floor matches CP943/CP944 |
| CP947 | 500 kHz tone -> bladeRF centered `normal` and `dec2` | strong tone in both filters |

CP947 rules out a fully dead centered external RF route. The bladeRF receive
path can see a simple near-adjacent tone at the same RF center, sample rate,
bandwidth, and gain where the structured PBCH waveform looked like no-TX
receive floor.

## Interpretation

The current failure boundary is narrower than "nothing reaches bladeRF." A
single-tone source reaches bladeRF cleanly, but the centered PBCH-positive
source does not recover as PBCH and does not correlate above no-TX floor in the
external bladeRF captures.

That points to a waveform/path interaction rather than a completely broken
receiver route. The next control is a fresh LiteX-only RX/TX baseline at the
same centered settings, so any later external bladeRF result can be compared
against a known-good LiteX source/receiver state from the same debugging window.
