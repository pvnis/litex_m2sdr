# Checkpoint 950 - x2 centered PBCH validation is a partial pass for margin testing

## Purpose

CP949 found that x4 boosting was too aggressive for a clean all-loopback PBCH
baseline. CP950 stepped down to x2 to create a lower-risk boosted PBCH source
for a possible external bladeRF link-margin test.

This checkpoint used no bladeRF commands:

```text
CP918 centered PBCH-positive CF32
  -> x2 linear scale, no clipping
  -> local PBCH decode
  -> LiteX-only RX/TX loopbacks: none, phy, ad9361
```

## Interpretation

The x2 source is locally valid, unclipped, and strongly correlated through all
LiteX-only loopbacks. The `phy` and `ad9361` loopbacks also decode PBCH CRC OK.
The `none` loopback is the only caveat: it reports CSI PCI 1 with positive SNR
but full-capture PBCH `crc=KO` at `t_offset=0`.

This means x2 is not a perfect all-loopback PBCH baseline. It is still suitable
for a narrower external test whose primary question is correlation/link margin:

```text
Does a +6 dB centered PBCH source rise above the external bladeRF no-TX floor?
```

If external x2 correlation remains at the CP943/CP944/CP946 floor, then the
failure is not fixed by a modest source-level boost. If correlation rises but
PBCH remains KO, then the next focus should be decoder windowing/CFO/phase
rather than raw RF visibility.
