# Checkpoint 984 - Centered 2SC x8 BW2M Narrower bladeRF Bandwidth Modest Margin, Not Long Coherence

Date: [date-redacted]

## Purpose

CP984 changes one external receive variable after CP983 showed that bladeRF RX
FIR bypass improves level but does not recover long coherence. It keeps the
CP981 external setup, normal bladeRF FIR, and G42 receive gain, but narrows the
bladeRF RX bandwidth from `5600000 Hz` to `2000000 Hz`.

This tests whether the external path failure is mainly broadband receive noise
or out-of-band energy folding into the bladeRF capture.

## Interpretation

CP984 separates receive bandwidth from full long-coherence recovery:

- Narrowing bladeRF RX bandwidth from 5.6 MHz to 2 MHz gives a modest margin
  improvement.
- The improvement is comparable to CP983 FIR bypass, but neither change clears
  the failure.
- The failure mode is still not basic signal absence, clipping, excessive G42
  gain, normal FIR alone, or broad 5.6 MHz bandwidth alone.

The current boundary remains the installed external LiteX TX -> bladeRF RX path.
The bladeRF receive settings affect margin, but the long-window external
coherence problem remains.

## Verdict

CP984 narrower bladeRF RX bandwidth execution: PASS.

Signal presence and short-window recovery: PASS.

Long-window coherence recovery: FAIL.

Current first-failed boundary remains outside the basic LiteX file replay and
inside the external path as observed by bladeRF RX.

## Next Step

Before combining receive-side improvements, run a fresh LiteX-only RX/TX control
baseline with the same CP973 centered 2SC x8 waveform. That brackets the
bladeRF/external experiments and protects against the "nothing changed, now the
source path is broken" ambiguity.

After that control, the next reversible bladeRF rung is either a narrower
`200000 Hz` RX bandwidth with normal FIR at G42, or a combined-margin test using
`CAP_FILTER=bypass` with `CAP_BW_HZ=2000000`. The cleaner ladder is to test the
single remaining bandwidth rung first, then combine variables only if needed.
