# Checkpoint 993 - LiteX TX ATT Register Probe Confirms Soapy ATT Reaches AD9361

Date: [date-redacted]

## Purpose

CP993 follows CP992's readback-only Soapy gain/ATT check with a register probe.
The goal is to determine whether Soapy TX `ATT` changes real AD9361 TX
attenuation registers, still without activating a TX stream.

## Local Source Evidence

Local source inspection showed:

- `LiteXM2SDRDevice.cpp` TX `setGain()` rejects negative values, stores the
  value, logs it as TX attenuation, and calls `m2sdr_set_tx_att(_dev, value)`.
- `m2sdr_rf.c` validates TX values in range `0..89` and calls
  `ad9361_set_tx_atten(phy, gain * 1000, 1, 1, 1)`.
- `ad9361.c` scales attenuation mdB by `250` for quarter-dB units, writes TX1
  and TX2 attenuation registers, then requests immediate update.
- `ad9361.h` defines:
  - `REG_TX1_ATTEN_0 = 0x073`
  - `REG_TX1_ATTEN_1 = 0x074`
  - `REG_TX2_ATTEN_0 = 0x075`
  - `REG_TX2_ATTEN_1 = 0x076`
  - `REG_TX1_DIG_ATTEN = 0x079`
  - `REG_TX2_DIG_ATTEN = 0x07C`

## Probe Method

The probe ran on `[host-redacted]`:

- opened `SoapySDR.Device({"driver": "LiteXM2SDR"})`,
- set TX sample rate `5760000`,
- set TX frequency `1839650000`,
- set TX bandwidth `5600000`,
- did not create or activate a TX stream,
- for ATT values `20`, `26`, `40`, and back to `20`:
  - called Soapy TX `setGain`,
  - read Soapy `getGain()` and `getGain("ATT")`,
  - used `m2sdr_util ad9361-read` for registers `0x073`, `0x074`, `0x075`,
    `0x076`, `0x079`, and `0x07c`.

## Results

Soapy metadata:

- TX gain names: `['ATT']`
- TX range: `0, 89`

Register results:

| Requested ATT | `getGain()` | `0x073` | `0x074` | `0x075` | `0x076` | `0x079` | `0x07c` |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| initial | n/a | `0x0050` | `0x0000` | `0x0050` | `0x0000` | `0x0003` | `0x0003` |
| `20` | `20.0` | `0x0050` | `0x0000` | `0x0050` | `0x0000` | `0x0003` | `0x0003` |
| `26` | `26.0` | `0x0068` | `0x0000` | `0x0068` | `0x0000` | `0x0008` | `0x0008` |
| `40` | `40.0` | `0x00a0` | `0x0000` | `0x00a0` | `0x0000` | `0x0010` | `0x0010` |
| `20` restore | `20.0` | `0x0050` | `0x0000` | `0x0050` | `0x0000` | `0x0003` | `0x0003` |

The values match quarter-dB scaling:

- `20 dB / 0.25 dB = 80 = 0x50`
- `26 dB / 0.25 dB = 104 = 0x68`
- `40 dB / 0.25 dB = 160 = 0xa0`

## Interpretation

CP993 shows that the Soapy `ATT` control is real at the AD9361 register level
in a no-stream context. CP991's unchanged RF level is therefore not explained by
the control being absent, a pure software cache, or a sign misunderstanding.

Remaining possibilities include:

- streaming setup rewrites or bypasses the attenuation after the no-stream
  configuration path,
- the RF path observed by bladeRF is not behaving monotonically for a 6 dB ATT
  change,
- the CP991 level comparison was masked by run-to-run timing or capture-window
  effects,
- another stage after the AD9361 attenuation is dominating the measured level.

## Verdict

Readback/register probe execution: PASS.

Soapy `ATT` reaches AD9361 TX attenuation registers: PASS.

CP991 RF non-response explanation: unresolved.
