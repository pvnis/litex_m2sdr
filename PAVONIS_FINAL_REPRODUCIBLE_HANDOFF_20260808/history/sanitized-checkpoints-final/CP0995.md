| after launch t2 | `[date-redacted]` | `0x0000` | `0x0000` | `0x0000` | `0x0000` | `0x0000` | `0x0000` |

`0x00a0` is the expected quarter-dB code for `40 dB` attenuation. The bladeRF
capture began at `[date-redacted]`, immediately after the `t2` all-zero register
snapshot.

Important caveat: the register probe uses `m2sdr_util` while the Soapy process
is alive. `m2sdr_util` can open/initialize the device, so the probe may perturb
the state it is trying to observe. CP995 is therefore strong evidence that ATT
state is not stable at capture time, but not a clean proof of the root cause.

## Interpretation

CP995 narrows the ATT issue:

- no-stream CP993: Soapy `ATT40` reaches AD9361 registers correctly,
- streaming CP995: `ATT40` appears at `t1`, then registers read zero at `t2`,
  immediately before/at bladeRF capture start,
- bladeRF RF level remains high, consistent with attenuation not being active
  during the capture,
- the register probe itself may perturb the AD9361 because it uses
  `m2sdr_util` while Soapy is active.

For the original RF/coherence problem, CP995 is not a recovery. The external
path still shows short-window visibility but long-window collapse, and CP985
LiteX-only remains the clean control.

## Verdict

CP995 instrumented execution: PASS.

Live ATT register instrumentation: PASS, with perturbation caveat.

ATT active at bladeRF capture time: FAIL/NOT PROVEN. Registers were zero at the
last pre-capture probe and RF level stayed high.

Long-window coherence recovery: FAIL.

## Next Step

Avoid `m2sdr_util` concurrent probing for the next diagnostic. Build a
non-perturbing CP996 `test_play.py` variant or wrapper that logs Soapy
`getGain()`/`getGain("ATT")` from inside the same Soapy process:

- after `setGain`,
- immediately before stream activation,
- during the write loop,
- after deactivation.

If Soapy still reports `ATT40` while RF level remains high, the problem is below
the driver's get/read path or in the RF path after the AD9361 attenuation. If
Soapy reports zero during the write loop, the streaming code path is resetting
ATT.
