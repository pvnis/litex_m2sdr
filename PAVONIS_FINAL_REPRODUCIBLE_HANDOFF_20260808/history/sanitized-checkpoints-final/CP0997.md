## Interpretation

CP997 resolves the `TX_ATT_DB` contradiction from CP991-CP995:

- CP992/CP993 proved the Soapy `ATT` control exists and reaches AD9361
  attenuation registers in a no-stream context.
- CP991/CP994 showed requested higher attenuation did not reduce the external
  RF capture level.
- CP995 showed `ATT40` briefly present during a streaming run but not reliably
  active when the bladeRF capture happened; the concurrent register probe could
  perturb state.
- CP997 shows the same-process Soapy readback changes from `40` back to `20` at
  `setupStream`, then remains `20` throughout active writes.

So the simplest current model is:

1. `setGain(..., ATT)` works before stream setup.
2. LiteX Soapy stream setup or the underlying stream initialization path resets
   TX attenuation to the default `20`.
3. CP920/CP848-style replays therefore transmit at active `ATT=20` unless the
   attenuation is set again after stream setup/activation.
4. The external long-coherence failure remains, but the recent ATT40 tests were
   not true low-power ATT40 tests.

## Verdict

CP997 external TX gaintrace: PASS as a diagnostic.

Requested `TX_ATT_DB=40` is not preserved into active streaming in the current
wrapper order. Active streaming readback is `ATT=20`.

Current first-failed boundary remains the installed LiteX TX -> bladeRF RX path
for long-window coherence, but the transmit attenuation variable must be retested
with the gain set after stream setup or activation.

Run a same-path `ATT40` replay where the instrumented player applies
