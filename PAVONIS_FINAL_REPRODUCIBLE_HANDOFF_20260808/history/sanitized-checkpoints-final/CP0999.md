# Checkpoint 999 - Active ATT26 Returns Intermediate Level but No Long Coherence Recovery

Date: [date-redacted]

## Purpose

CP999 directly retests the earlier CP991 `ATT26` idea after CP997/CP998 proved
the original wrapper order was wrong. In CP999 the player reapplies
`setGain(..., 26)` after `setupStream`, so active writes actually run at
`ATT=26`.

The goal is to determine whether a moderate real attenuation improves the
external LiteX TX -> bladeRF RX long-coherence failure without underdriving the
path as much as CP998 active `ATT40`.

## Verdict

CP999 active `ATT26`: control path PASS, receive recovery FAIL.

The corrected attenuation order works and produces the expected intermediate RF
level. However, active `ATT26` does not improve long-window external coherence
or PBCH decode.

## Next Step

The level knob is now validated. Since `ATT20`, active `ATT26`, and active
`ATT40` do not recover long coherence, the next useful rung is either a tighter
level sweep around `ATT22..26` to find the best SNR/coherence point, or move back
to non-level variables: bladeRF capture phase behavior, LO/CFO stability, or
external-path image/sideband asymmetry.
