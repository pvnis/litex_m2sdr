## Purpose

Test whether the repeatable CP1023/CP1024 external-path coherence failure improves when only the bladeRF receive bandwidth is narrowed.

This keeps the known-good CP1022 LiteX source vector and TX settings fixed, while changing:

- CP1023/CP1024 RX bandwidth: `5600000 Hz`
- CP1025 RX bandwidth: `2000000 Hz`

The signal of interest is still only at `-15 kHz` and `+15 kHz`, so a 2 MHz RX bandwidth should comfortably pass the tones if the issue were wideband receiver/filter behavior.

## Verdict

FAIL, no improvement from narrower RX bandwidth.

This argues against a simple "wide RX bandwidth is the whole problem" theory. The failure remains in the external receive path/bladeRF capture chain after the source-side LiteX baseline passes.

## Next rung

Run a bladeRF RX gain split at the original `5.6 MHz` RX bandwidth. Keep the source vector and TX side fixed, and reduce RX gain from `42 dB` to a lower value such as `30 dB`. If coherence improves, suspect gain/compression/AGC-like behavior or analog front-end level. If it does not, proceed to RX channel/path split.
