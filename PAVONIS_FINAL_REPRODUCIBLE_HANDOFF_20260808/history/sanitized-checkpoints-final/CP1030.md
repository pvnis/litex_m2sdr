## bladeRF Hardware-State Note

The active capture log contains a suspicious hardware-state print while `rx start` is active:

- Active-capture log SHA256: `56e601c7667a046cfa386548e7ef777d7f3bbe87fe5072e4082196fb80836378`
- During active capture:
  - `Temperature: 200.0 degrees C`
  - `RX1: RFIC 0x1 (B_BAL) <= SW 0x2 (RF3(B))`
  - `Gain RX1 overall: 60 dB`
- After `rx wait` in the same log:
  - `Temperature: 34.2 degrees C`
  - `RX1: RFIC 0x0 (A_BAL) <= SW 0x0 (OPEN)`
  - `Gain RX1 overall: 42 dB`

Prior comparable runs CP1023-CP1026 showed active-capture temperatures in the `33.3-35.1 degrees C` range, not `200.0 degrees C`. A post-capture recheck at `[date-redacted]`, `[date-redacted]`, and `[date-redacted]` showed `33.3`, `33.3`, and `34.2 degrees C`; post-capture recheck log SHA256: `69fd3f8552a0696b01f465fbb78d4b63129c25e0dc02641555fd49936eaece4a`.

This does not prove physical overheating. Because the value returned to normal immediately and the same CLI print also shows routing/gain state changes around streaming, the `200.0 degrees C` line may be a transient or invalid hardware-status read during capture. It is still worth tracking on the next repeat because it is new and only appeared in the clean non-symmetric external run.

## Interpretation

CP1030 is a clean external-path failure:

- The exact vector passes the LiteX-only path in CP1028.
- The CP1030 wrapper, TX replay, capture, artifact transfer, and cleanup all returned rc `0`.
- The bladeRF received a strong, unclipped signal.
- Short windows can partially correlate, but coherence collapses as the window grows.
- Non-symmetric mirror analysis does not point to simple image/conjugate confusion.
- A suspicious one-time `200.0 degrees C` active-capture hardware print appeared, but immediate post-capture reads were normal.

## Verdict

The failure is reproducible on the external bladeRF/generic path with a LiteX-proven vector. Current evidence isolates the issue away from the LiteX-only TX/baseband/software path and toward the external receive path, its physical interconnect/routing, or bladeRF/AD9361 state during capture. Next best rung: repeat the clean CP1030 setup once to check reproducibility and whether the `200.0 degrees C` active-capture read repeats.
