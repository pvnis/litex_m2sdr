# CHECKPOINT 1034 - Partial-Write Fix External Capture

Date: [date-redacted]

## Purpose

Test the CP1033 chunk/discontinuity hypothesis by replacing the CP998 replay helper with a new helper that handles partial `writeStream` returns correctly. The prior helper passed buffers to `writeStream`, but when `writeStream` returned a short count such as `1022`, it dropped the unwritten remainder of that buffer.

## Helper Change

- New helper: `cp1034_remote_nuc4_start_cf32_replay_tx_gaintrace_partialwritefix.sh`

- Main change: loop on each CF32 buffer until all samples are accepted by `writeStream`.
- Chunk length used: `1536` samples, matching `4 * 384`-sample waveform periods.

## Interpretation

CP1034 proves the old replay helper had a serious partial-write bug and that it materially damaged the external capture. Fixing dropped partial writes:

- restores full TX sample count,
- improves first-pass reference correlation,
- improves focused long-window correlation,
- dramatically improves occupied-bin phase residual,
- and increases medium-window coherent runs.

The path is not fully recovered to the CP1028 LiteX-only baseline. A slower residual coherence issue remains after roughly `256-512` symbols, and the focused score still tops out below the known-good `~0.97-0.98`.

## Verdict

One major software-path bug is confirmed and fixed: dropped partial TX writes in the CP998-style helper. The external path is now partially recovered, but still not fully coherent. The next rung should keep the partial-write fix and test whether the remaining long-window collapse is caused by the TX buffer cadence or by RF/clock drift. A useful immediate split is to rerun CP1034 with a larger period-aligned chunk such as `3072` or `6144` samples and compare 512/1024-symbol stability.
