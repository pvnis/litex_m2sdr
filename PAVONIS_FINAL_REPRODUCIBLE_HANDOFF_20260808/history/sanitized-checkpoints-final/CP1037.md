## Interpretation

The true `3072` split is useful but not decisive. It confirms chunk cadence matters: some short/medium-window metrics improve materially over CP1034. It also confirms the remaining failure is not just dropped TX samples, since full sample count is correct and long coherence still collapses.

The remote writer still experienced many partial writes (`42180`), so `3072` did not remove the driver fragmentation mechanism. A cleaner next split is a period-aligned chunk below the observed `1022` write acceptance, such as `768` samples. That should preserve waveform-period alignment while eliminating partial writes.

## Verdict

Keep the partial-write fix. Do not treat `3072` as recovered. Next checkpoint should run `CHUNK_LEN_SAMPLES=768` to test whether partial-write retry cadence itself is part of the remaining long-coherence collapse.
