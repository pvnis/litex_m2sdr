## Interpretation

CP1039 is the strongest evidence so far that the current failure is not explained by the chunk setting alone. The explicit `1536` run used the same partial-write-fixed writer behavior as CP1034, wrote the full sample count, kept the requested TX gain, and produced a strong unclipped bladeRF capture. Yet the long-window correlation and tone stability are now much worse than CP1034 and CP1036.

This points to residual state/path/run-to-run degradation in the external setup: bladeRF capture behavior, RF/cable/attenuation path, clock/timing interaction, or some stateful device condition. It does not look like thermal runaway from the observed bladeRF temperatures.

The contemporaneous CP1035 LiteX-only baseline passed earlier, so the next diagnostic should repeat that LiteX-only baseline after the CP1039 degradation. If LiteX-only still passes, the regression remains isolated to the external bladeRF/path side. If LiteX-only now fails, the current source-side LiteX state must be revisited before further external tests.

## Verdict

Do not continue chunk-size [interface-redacted] until the source-side baseline is rechecked. Run a fresh LiteX-only RX/TX repeat next.
