## Interpretation

CP1041 shows the external path is not permanently degraded. With the same external `1536` settings as CP1039, the long-window two-tone metrics recovered strongly after the CP1040 LiteX-only baseline and cleanup sequence.

The important facts are:

- CP1040 proved the LiteX-only path was still good.
- CP1041 used the same TX writer behavior and same full sample count as CP1039.
- CP1041 recovered long-window correlation and image/mirror metrics while PBCH still failed.

That means the variable is not the source vector, not the LiteX-only software path, and not the TX sample-count fix. The remaining issue looks stateful in the external bladeRF/RF/capture path or in timing/phase behavior that appears only over longer windows.

This also keeps the overheating theory unlikely: the bladeRF was in the low/mid 30s C across CP1039 and CP1041. A small cool-down/time/reset effect cannot be fully excluded, but the observed temperatures are not high enough to make thermal shutdown or gross thermal drift the leading explanation.

## Verdict

Use CP1041 as the current best external two-tone baseline. The next rung should move upward from this recovered `1536` setting while keeping the same cleanup discipline, rather than changing chunk size again immediately.
