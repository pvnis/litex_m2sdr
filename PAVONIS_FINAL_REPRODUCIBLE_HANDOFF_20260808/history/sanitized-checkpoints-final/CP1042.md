## Interpretation

CP1042 proves that the CP1041 recovered two-tone condition does not automatically recover PBCH/SSB decode. The TX writer is correct, the capture is present and unclipped, and there is a weak SSB-reference island in the first 6M scan, but the PBCH decoder still sees no CRC-OK windows.

This points to a waveform-complexity or synchronization sensitivity issue above the two-tone rung. The external path can now preserve simple two-tone coherence for medium/long windows, but it still does not preserve the PBCH/SSB waveform well enough for SSB correlation and decode.

The current best next step is to re-establish a PBCH/SSB source-side baseline with the current scripts/settings, then compare that against CP1042. If the source-side PBCH baseline still passes, the next external branch should focus on PBCH-specific timing/CFO/phase handling rather than two-tone chunk-size [interface-redacted].
