# Checkpoint 1059 - Fresh Centered LiteX-Only RX/TX Baseline Isolates bladeRF

Date: [date-redacted]

## Purpose

Run a fresh RX/TX baseline entirely inside the LiteX/M2SDR path, with no
bladeRF commands and no external bladeRF receiver in the path. This is the
control requested after CP1058 so that a later external failure cannot be
explained by "we did not change anything and now LiteX cannot receive anything
anymore."

The source is the same centered CP918 SSB/PBCH-positive 5.76 Msps reference
used by the current external LiteX-to-bladeRF tests.

## Interpretation

CP1059 isolates the current external failure away from:

- the CP918 centered source/reference vector,
- the LiteX Soapy file RX/TX harness,
- [host-redacted]'s ability to run the LiteX transmit/receive loopbacks,
- current sample-rate, bandwidth, and RF-frequency programming,
- a broad "LiteX cannot receive anything anymore" regression.

It does not prove the external bladeRF/RF path is healthy. In fact, because no
bladeRF commands were used here, CP1059 strengthens the boundary: the failing
domain remains the external LiteX TX -> bladeRF RX observation path or an
interaction that only appears when that path is inserted.

The only local wrinkle is the `ad9361` full-buffer decoder candidate-selection
anomaly. Since targeted windows recover PBCH CRC OK, this should be treated as
an analyzer/windowing caveat rather than evidence that LiteX RX/TX is dead.

## Verdict

Fresh centered LiteX-only RX/TX baseline: PASS for isolating bladeRF from the
current failure. Continue the ladder against the external path, using CP1059 as
the current source-side control.
