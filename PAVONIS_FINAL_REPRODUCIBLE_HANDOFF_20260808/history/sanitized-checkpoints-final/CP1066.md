## Purpose

one-second buffer. CP1066 varies the input-buffer start and length around a
known CP1063 PBCH-positive event near `0.150064 s`, using only the existing raw
capture.

No RF hardware was used in this checkpoint.

## Interpretation

CP1066 makes the failure more specific than a simple pre-roll problem:

- A buffer beginning exactly at sample zero can decode PBCH if its length is
  `500 ms`.
- The same sample-zero start fails when the buffer length is `1000 ms`, exactly
  reproducing the CP1063 full-buffer failure log.
- Very small start changes are significant: start `0.000064 s` fails at
  `500 ms` and `1000 ms`, while start `0.000000 s` succeeds at `500 ms`.
- Some late starts decode even at `1000 ms`, for example start `0.130064 s`.

This points to `ssb_file_test` candidate selection depending on the global
buffer contents and length, not just on whether the target PBCH event is
present. Later samples can change which CSI/PBCH candidate the decoder reports.

## Verdict

CP1066: PASS for isolating the full-buffer failure to decoder
candidate-selection/window-content sensitivity. The next local test should be a
prefix-length sweep from sample zero to find exactly where CP1063 changes from
PBCH OK to PBCH KO.
