# Checkpoint 1069 - Sliding-Window Acquisition Policy

Date: [date-redacted]

## Purpose

Define a deterministic local acquisition policy that works on both corrected
ATT10/G42 CP1034 captures. CP1067 showed a sample-zero shorter-prefix success
band for CP1063, but CP1068 showed that fixed sample-zero shortening fails on
CP1062. CP1069 therefore uses the existing aligned-window sweeps to validate a
multi-scale sliding-window rule.

No RF hardware was used in this checkpoint.

## Policy

Given a raw external LiteX-to-bladeRF capture:

1. Decode at nominal center/SSB frequency, `1839650000 Hz`.
2. Scan the first `250 ms` with the existing aligned-window plan:
   - `1 ms` windows every `0.5 ms`
   - `2 ms` windows every `1.0 ms`
   - `5 ms` windows every `2.5 ms`
3. Accept the capture if any window reports:
   - `pbch_crc_ok == True`
   - `search_pci == 1`
4. Record both:
   - first success in scan order, for cheap early exit,
   - earliest chronological success, for timing interpretation.

This policy is deliberately not a fixed start or fixed length. CP1068 showed
that fixed sample-zero prefixes are not robust across repeat captures.

## Interpretation

The sliding-window policy passes on both corrected external captures where
full-buffer acquisition fails. This makes it the current best acquisition
criterion for the external path:

- CP1059 proves the LiteX-only source/RX/TX side is healthy.
- CP1062 and CP1063 prove the external LiteX-to-bladeRF path carries
  PBCH-decodable content.
- CP1064 and CP1065 prove trimmed windows recover PBCH in both captures.
- CP1067 shows sample-zero shorter prefixes can work in CP1063.
- CP1068 shows fixed sample-zero prefixes do not generalize to CP1062.
- CP1069 defines the general rule that does work: scan starts/windows.

## Verdict

CP1069: PASS. Use bounded sliding-window PBCH acquisition as the primary decoder
criterion for the next external RF checkpoint. Keep full one-second decode as a
secondary diagnostic only, because it is now known to be candidate-selection
sensitive.
