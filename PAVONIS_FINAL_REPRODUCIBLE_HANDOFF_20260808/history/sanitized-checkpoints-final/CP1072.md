## Interpretation

CP1072 confirms fixed sample-zero prefixing is not a stable acquisition
strategy. CP1070 has a sample-zero PBCH-positive prefix, but only at `25 ms`;
adding more samples quickly causes the candidate selector to report PBCH PCI 0
CRC KO again.

This matches the broader pattern from CP1067 and CP1068: the external captures
contain PBCH-decodable content, but the reported full-buffer candidate depends
strongly on buffer contents. The reliable health gate is still sliding over
starts/windows, not picking a single global prefix length.

## Verdict

CP1072: PASS as a guardrail against replacing sliding-window acquisition with a
fixed prefix. Continue using the CP1071 evaluator as the standard smoke test.
The next decoder investigation should compare successful sliding windows
against failing longer buffers to identify why PCI 0 candidates dominate the
full-buffer result.
