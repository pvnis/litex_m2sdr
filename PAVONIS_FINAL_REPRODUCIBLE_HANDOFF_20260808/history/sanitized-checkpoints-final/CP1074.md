## Purpose

Audit the local `ssb_file_test` and SSB decoder source after CP1073. CP1073
found a repeatable full-buffer fingerprint (`PBCH PCI 0`, `t_offset=0`,
`payload=00 00 00`, `crc=KO`) while short sliding windows decode PCI 1 PBCH

selected PBCH candidate or a not-found/default result.

No RF hardware was used in this checkpoint.

## Source Findings

`ssb_file_test` performs two separate operations:

- `ssb_file_test.c:199-210` runs `srsran_ssb_csi_search()` and prints the
  `measure - search pci=...` line.
- `ssb_file_test.c:220-233` then runs `srsran_ssb_search()` once and prints
  `search - t_offset=... pci=... ... crc=...` regardless of whether PBCH CRC
  passed.
- `ssb_file_test.c:235-244` unpacks and prints `PBCH-MIB` from the same result
  even when `search_res.pbch_msg.crc` is false.

The public result contract is explicit:

- `ssb.h:123-126` says that if `pbch.crc` is true, SSB was found and decoded;
  otherwise no SSB transmission has been decoded.

The implementation leaves the result zeroed unless PBCH CRC passes:

- `ssb.c:1279-1280` zeroes `res` before searching and documents that the
  default means PBCH CRC unmatched/no cell found.
- `ssb.c:1282-1289` asks `ssb_pss_search()` for one time-domain PSS result for
  that input and CFO hypothesis.
- `ssb.c:1342-1344` returns success without saving anything if PBCH CRC fails.
- `ssb.c:1354-1359` only writes `N_id`, `t_offset`, `pbch_msg`, and
  measurements after CRC is true.
- `ssb.c:1378-1385` zeroes the top-level result before the wide-CFO loop.
- `ssb.c:1391-1414` tries CFO hypotheses and returns as soon as any hypothesis
  decodes PBCH CRC OK.

The binary usage output exposes no option to continue searching alternate PSS
peaks after a PBCH CRC failure. It supports input, rate, sample count, SCS,
duplex mode, pattern, center/SSB frequencies, assert, and verbosity.

## Corrected Interpretation

CP1073's raw fingerprint remains valid, but the interpretation should be
tightened:

- The full-buffer rows with `PBCH PCI 0`, `t_offset=0`, `payload=00 00 00`,
  `crc=KO`, `MIB sfn=0`, and `barred=y` are best interpreted as the
  zero-initialized not-found result printed by `ssb_file_test`.
- They should not be treated as proof that the decoder selected a real bad PBCH
  candidate at sample zero.
- The full-buffer `measure - search` line comes from the separate CSI search,
  so a plausible-looking CSI PCI/delay does not mean the subsequent PBCH search
  decoded the same region.

The likely failure mode is now narrower: for each full-buffer CFO hypothesis,
the SSB PBCH path appears to test one PSS time candidate. If that candidate does
not pass PBCH CRC, the result remains the default not-found value and the code
moves to the next CFO hypothesis. It does not scan alternate time peaks inside
the long one-second input. The sliding-window evaluator succeeds because it
constrains the input to local regions, forcing the one-candidate search onto
different PSS peaks until a PBCH-CRC-valid region is presented.

## Relationship To The LiteX Baseline

CP1059 already isolated the source side with LiteX-only RX/TX loopbacks:

- `none`, `phy`, and `ad9361` loopbacks all completed without RX/TX
  errors/timeouts.
- Correlation was strong at 0 Hz for all three loopbacks.
- Full-buffer PBCH passed on `none` and `phy`; the `ad9361` full-buffer case
  showed a candidate anomaly, but targeted windows recovered PBCH success.

That keeps the current external-path diagnosis from being blamed on an unknown
LiteX TX/RX software failure. The newer CP1070 external RF capture also passed
the reusable CP1071 sliding-window smoke rule, so the remaining issue is the
long-buffer acquisition policy rather than "cannot receive anything."

## Verdict

CP1074: PASS. The decoder source audit explains the CP1073 full-buffer
fingerprint as a not-found/default printout. The robust acquisition policy
should remain the CP1071-style sliding-window scan unless we deliberately patch
srsRAN to evaluate multiple PSS time candidates per CFO hypothesis inside a
single long buffer.

## Next Step

Use the sliding-window evaluator as the standard smoke gate for fresh RF
captures. If an integrated full-buffer decoder is needed, implement it first as
a wrapper-level window scan over `ssb_file_test`; a deeper srsRAN change should
only be attempted after preserving the current passing external RF baseline.
