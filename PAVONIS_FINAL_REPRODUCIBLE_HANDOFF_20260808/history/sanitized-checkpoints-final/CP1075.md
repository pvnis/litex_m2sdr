# Checkpoint 1075 - RF Sliding-Window Smoke Gate

Date: [date-redacted]

## Purpose

Turn the CP1069/CP1071 sliding-window acquisition rule into a reusable
pass/fail gate for external RF captures. This follows:

- CP1059: fresh centered LiteX-only RX/TX baseline passed and isolated bladeRF
  from the source-side path.
- CP1070: a fresh external LiteX-to-bladeRF RF capture passed sliding-window
  PBCH recovery but failed the known-fragile one-second full-buffer decode.
- CP1074: source audit showed the full-buffer `PBCH PCI 0`, `t_offset=0`,
  `payload=00 00 00`, `crc=KO` fingerprint is a zero-initialized not-found
  printout, not proof of a real bad PBCH at sample zero.

No RF hardware was used in this checkpoint. CP1075 only evaluates existing
CP1062, CP1063, and CP1070 artifacts.

## Gate Tool

New helper:

```sh
cp1075_rf_sliding_smoke_gate.py
```

The helper accepts either a CP920 `--stamp` or explicit `--aligned-csv` and
`--full-json` paths. It exits `0` on pass and `2` on fail.

Default pass criteria:

- expected PCI is `1`,
- at least one primary window: PBCH CRC OK and PBCH PCI `1`,
- at least one strict window: primary window where CSI PCI is also `1`.

Example command:

```sh
python3 cp1075_rf_sliding_smoke_gate.py \
  --artifact-root /home/[host-redacted]/CLionProjects/pavonis_stage6_agent_artifacts_[date-redacted]T0918Z/prearmed_raw512_fast_[date-redacted]T0045Z \
  --stamp [date-redacted]TCP1070CENTEREDSSBATT10BYPASSPW1536G42SLIDEPOLICY \
  --out-dir cp1075_rf_sliding_gate_cp1070
```

Known local warning: the sandbox sometimes prints
`Failed to create stream fd: Operation not permitted` during these artifact
evaluations. This was already documented in earlier checkpoints; here it was
nonfatal and all gate runs returned `0`.

## Interpretation

CP1075 makes the current external-path baseline operational:

- CP1059 proves the source-side LiteX RX/TX path is healthy without bladeRF.
- CP1070 proves fresh external LiteX-to-bladeRF RF can still carry
  PBCH-decodable content.
- CP1074 explains why the full-buffer decoder can report a deterministic
  not-found/default result even when nearby short windows decode PBCH.
- CP1075 provides the repeatable smoke gate that future fresh captures should
  pass before deeper debugging continues.

This removes the remaining ambiguity behind "we did not change anything and now
cannot receive anything": if a future external capture fails CP1075 while CP1059
or an equivalent LiteX-only baseline still passes, the problem is in the
external RF/bladeRF observation path or capture conditions. If CP1075 passes,
the path is carrying decodable PBCH and the next issue is higher-level
integration.

## Verdict

CP1075: PASS. The new sliding-window smoke gate passes on CP1062, CP1063, and
CP1070 and should be used as the standard acceptance test for fresh external RF
captures.
