## Notable Failure Signal

The `nr_sa_cell_search_test` log contains repeated RF `Overflow` lines,
including during and after the target SSB candidate. This is different from the
CP1081 scanner path and may point to UE receive-loop timing, buffering, logging
overhead, or stricter PBCH/MIB processing rather than an RF-path outage.

The zero-valued rejected candidates are also suspicious. The current
`cell_search::run_slot()` code logs rejected candidates whenever the reported
SNR is greater than -12 dB. A zero-initialized `srsran_ssb_search_res_t` has
SNR 0.0 dB, so these warning lines may be no-find artifacts rather than real
decoded SSB candidates.

## Conclusion

CP1082 is a useful failure:

- LiteX TX replay remained healthy.
- bladeRF RX state matched the passing CP1081 baseline.
- `nr_sa_cell_search_test` reached the target 1839.65 MHz SSB candidate.
- It still did not detect a cell or PBCH/MIB.
- The failure included zero-valued reject logs and RF overflows.

This does not invalidate the CP1081 live RF baseline. It narrows the next work
to the UE-like cell-search path: receive-loop timing, buffering, overflow
behavior, and the PBCH/MIB acceptance gate. Do not move to PRACH until this
UE-side cell-search divergence is understood.
