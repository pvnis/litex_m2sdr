## Timing Inference

The replay source is:

- size: 8000000 bytes
- format: CF32, 8 bytes/sample
- samples: 1000000
- sample rate: 5760000 samples/s
- loop period: about 173.61 ms

CP1083 target-only found PCI 1 on trial 50. CP1084 first spent a complete
100-trial search window on the off-target 1838.45 MHz candidate, then started
the target 1839.65 MHz candidate.

Because each UE cell-search candidate is capped at 100 one-ms trials, the target
candidate only inspects a 100 ms sample window. With a 173.61 ms replay loop
period, that 100 ms target window can land between repeated decodable PBCH
opportunities after the first off-target window consumed the earlier opportunity.

This explains why:

- CP1083 target-only passed.
- CP1084 full-raster failed even after removing the zero-result warning flood.
- CP1082 also failed when it scanned off-target candidates around the real one.

## Conclusion

CP1084 does not contradict CP1083. It shows that full-raster
`nr_sa_cell_search_test` can miss the known target because the test gives each
candidate only 100 ms, while the finite replay vector repeats every about
173.61 ms.

The next checkpoint should lengthen the UE cell-search trial budget for this
replay-driven test. If the full-raster run then finds PCI 1 at the target, the
CP1082/CP1084 failure is explained as a replay-period/search-window mismatch,
not a bladeRF or LiteX RF-path failure.
