## Purpose

Separate the known-good LiteX TX to bladeRF RX acquisition path from the noisy
post-camping portion of `nr_sa_cell_search_test`.

CP1086 proved that target-only search can find PCI 1, decode MIB, synchronize
SFN, and reach camping, but the built-in 1000-TTI post-select and post-stop loops
produced many overflows and out-of-sync logs. CP1087 added harness/source
controls so those loops can be set independently.

- `--post_stop_ttis`, default `1000`

## Conclusion

CP1087 confirms that the target-only LiteX TX to bladeRF RX path still supports
PBCH/MIB acquisition when the post-select soak is removed. It does not prove SFN
sync/camping because `post_select_ttis=0` starves cell selection of the TTIs it
needs to complete.

Next checkpoint should use a small nonzero `post_select_ttis` and keep
`post_stop_ttis=0`. The goal is to find the minimum bounded window that reaches
SFN sync/camping while avoiding the large post-camping overflow/out-of-sync tail
seen in CP1086.
