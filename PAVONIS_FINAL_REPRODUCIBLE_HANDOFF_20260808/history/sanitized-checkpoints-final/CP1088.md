`post_select_ttis=0` proves PBCH/MIB acquisition but starves SFN cell selection.

## Conclusion

CP1088 did not test the intended bounded post-select behavior because cell search
missed before cell selection could start. The failure is not explained by
`post_select_ttis`; that option is only used after a cell has already been found.

Compared with CP1083, CP1086, and CP1087, this is a live-path repeatability
regression on the same target-only LiteX TX to bladeRF RX setup. The candidate
was visible but too weak or corrupted for PBCH CRC in this run. Replay and device
state looked healthy, and temperatures remained in the same normal range.

Next action: rerun a known-good target-only/default-soak profile with the same
binary. If it passes, CP1088 is an intermittent RF/PBCH-decode miss. If it also
fails, the target path has regressed and needs lower-level RF re-baselining.
