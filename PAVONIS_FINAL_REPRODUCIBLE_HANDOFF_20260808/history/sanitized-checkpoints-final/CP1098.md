## Interpretation

CP1098 does recover evidence of PCI 1 from the CP1097 raw, but only weakly:

- Simple off-center detection failed.
- Simple frequency mix to SSB center without decimation also failed.
- Mix + low-pass + decimate by 2 recovered expected PCI 1 only on the 0.50 s window, and only as `EXPECTED_CELL_SEEN_LOW_MARGIN`.
- The winning ratio was `1.018`, far below the normal dominance threshold of `1.200`.

This is weaker than CP809, where the same transform style recovered PCI 1 cleanly from the earlier CP807 raw. The difference suggests that the live carrier-centered capture quality is variable even though SSB-centered capture is currently clean.

## Current Theory

The live downlink is present, but the carrier-centered/off-center path has poor SSS separation. That can explain a UE seeing PSS/PCI-like events but failing stable NR SA SFN acquisition.

This does not yet implicate PRACH, the Android phone, or a total bladeRF/LiteX RF outage. The useful next rung is to inspect or alter the UE/cell-search receive path so that the SSB is explicitly isolated like the successful offline transform, or to run an additional off-center repeat only if we need to quantify variability.
