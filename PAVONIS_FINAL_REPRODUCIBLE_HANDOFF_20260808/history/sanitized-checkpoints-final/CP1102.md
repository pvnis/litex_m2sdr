# Checkpoint 1102: Live SSB-centered detector at gNB backoff 10 did not prove PCI 1

Date: [date-redacted]

## Purpose

CP1101 tested `nr_sa_cell_search_test` with SSB-centered [interface-redacted] and
`tx_gain_backoff: 10`, but still found no cell. CP1102 checked whether the raw
LiteX TX to bladeRF RX path was actually healthy under that same gNB backoff.

- RF center: `1839650000 Hz`

- gNB config line: `tx_gain_backoff: 10`

- gNB TX timeouts: `SOAPY_TX_TIMEOUT_COUNT=0`

## Result

Diagnostic failure. The capture overlapped TX and saw PSS-like energy, but the
expected PCI did not rank first and did not dominate wrong-PCIs.

## Interpretation

This is not an ADC clipping failure: `RAW_CLIP2040_COUNT=0` on all trims. It is
also not an obvious gNB timeout failure. However, it is not a usable "more power"
condition either: PSS scores collapsed relative to CP1096/CP1103, and PCI 1 was
not proven.

The most likely reading is that `tx_gain_backoff: 10` pushes some part of the
RF/gNB/LiteX path into a worse condition for SSB detection, or exposes another
stateful/timing sensitivity. It should not be used as the main acquisition
baseline.
