Date: [date-redacted]

## Purpose

CP1103 proved the raw SSB-centered LiteX TX to bladeRF RX path at
`tx_gain_backoff: 20`. CP1104 then repeated the live
`nr_sa_cell_search_test` SSB-centered run with NR-SA RX gain changed from 42 to
40, matching the raw detector capture gain.

## Result

Failure. The wrapper completed, but the NR-SA cell-search trace showed no cell.

- NR-SA SSB configuration: `srate=5.76 MHz; c-freq=1839.650 MHz; ss-freq=1839.650 MHz`
- Trials: `100`
- Result: `cell_search_done result=0 trials=100 pci=0`
- Test process RC: `NR_SA_CELL_SEARCH_TEST_RC=0`
- gNB TX timeouts: `SOAPY_TX_TIMEOUT_COUNT=0`
- gNB cell line: `Cell pci=1, bw=10 MHz, 1T1R, dl_arfcn=368500 (n3), dl_freq=1842.5 MHz, dl_ssb_arfcn=367930, ul_freq=1747.5 MHz`

## Interpretation

Changing NR-SA RX gain from 42 to 40 did not make the srsUE acquisition path see
the cell. Since CP1103 passed the raw detector baseline at the same gNB backoff,
the remaining mismatch is likely inside the NR-SA/srsUE RF/acquisition
configuration rather than gross downlink outage.

The next most plausible missing parameter is `rf.freq_offset`: the known full
srsUE config uses `freq_offset=6000`, while CP1099-CP1104 all used `0`.
