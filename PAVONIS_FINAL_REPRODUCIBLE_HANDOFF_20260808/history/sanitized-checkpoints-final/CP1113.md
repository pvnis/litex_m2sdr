# Checkpoint 1113: +6000 Hz scanner attempt did not run because gNB startup failed

Date: [date-redacted]

## Purpose

After the live power bracket showed that backoff 20 is the only currently clean
raw-detector operating point, CP1113 attempted to rerun the lower-level
`nr_cell_search_rf` scanner at backoff 20, RX gain 50, and `rf.freq_offset=+6000`
Hz. This offset matches the direction used by the full UE config and was meant
to test whether the lower-level scanner improves before trying NR-SA again.

## Wrapper Change Before Run

`cp1106_run_live_gnb_nr_cell_search_rf.sh` was updated to expose the already
supported `nr_cell_search_rf` argument:

- New environment variable: `SCAN_RF_FREQ_OFFSET_HZ`
- Passed argument: `--rf.freq_offset='$SCAN_RF_FREQ_OFFSET_HZ'`
- Syntax check: pass
- Wrapper SHA256 after patch: `10ce44ae8b1072fe2d99f8812518a70021589e64211ec5d3affc538c582d69cf`

## Setup

- Harness: `cp1106_run_live_gnb_nr_cell_search_rf.sh`
- Stamp: `[date-redacted]TCP1113LIVE_NRCELLSEARCHRF_SSBCENTER_RXG50_FOFFP6000`
- Tag: `cp1113_live_nrcellsearchrf_ssbcenter_rxg50_foffp6000_after_cp1112`
- gNB backoff: `20`
- Scanner: `nr_cell_search_rf`
- Scanner target SSB: `1839650000 Hz`
- Scanner sample rate: `5760000 sps`
- Scanner RX gain: `50`
- Scanner RF frequency offset: `+6000 Hz`
- Scanner threshold: `-30 dB`

## Result

The scanner did not run. The gNB start window returned `rc=1`, so the wrapper
skipped `nr_cell_search_rf` and performed cleanup.

Start-wrapper summary:

- `READY_SEEN=0`
- `MARKED_TX_DETACHED_RC=1`
- Error: `harness exited before a fresh gNB started marker`
- Scanner: skipped with `reason=start_gnb_window_failed`
- Cleanup after failure: `rc=0`

Remote OTA-stage diagnosis:

- gNB log existed, but gNB exited early.
- `qcore.log` showed a panic:
  - `index out of bounds: the len is 255 but the index is 255`
  - location: `qcore/src/userplane/downlink_buffer.rs:145:32`
- gNB then failed AMF connection:
  - `N2: Failed to connect to AMF on [[ip-redacted]]:38412`
  - `OCUDU ERROR: CU-CP failed to connect to AMF`

## Interpretation

CP1113 is not a frequency-offset RF result. It is a gNB/qcore startup failure
that occurred before the scanner could run. The most likely immediate cause is
the qcore panic, followed by gNB CU-CP failing to connect to AMF.

Because CP98 cleanup completed afterward and earlier/live checkpoints started
gNB successfully, the next action is a single clean retry of the same scanner
checkpoint under a new checkpoint number. If the same qcore panic repeats, the
issue should be split out as a qcore startup regression before continuing RF
tests.
