# Checkpoints 1125-1127 - RF PBCH offset branch closed

## Purpose

CP1123-1124 bracketed bladeRF RX gain and showed a clean gain-41 RF capture
with expected PCI 1, no clipping, and persistent PBCH failure. CP835 was the
strong paired control: same-window zero-copy TX dump decoded PBCH/MIB, while
the same-window bladeRF RF capture still had PBCH KO. CP1125-1127 test whether
the RF failure can be recovered by explicit SSB frequency offsets, whole-second
CFO correction, or short-window focused CFO/pattern selection.

## Interpretation

The frequency/offset branch did not recover PBCH. It improved or preserved
PSS/SSS/CSI visibility in many cases, including high-quality short windows, but
PBCH never moved to PCI 1 and never produced a valid CRC.

That narrows the problem further:

- Not a simple bladeRF RX gain/saturation issue: CP1124 gain 41 had no clipping,
  and CP1127 used CP835 windows with CSI SNR up to `+2.2 dB`.
- Not a simple whole-capture CFO or explicit SSB frequency offset issue: CP1125
  and CP1126 swept both `-F` and sample rotation over `+-40 kHz`.
- Not a short-window pattern/CFO issue for the strongest paired RF capture:
  CP1127 tested 1296 focused cases with zero PBCH PCI 1.
- Still consistent with a live gNB stream/RF-delivery problem after the digital
  TX dump point: CP835 proved pre-DMA and post-DMA digital TX PBCH/MIB OK in
  the same window where RF PBCH failed.

The next isolation step should use the user-suggested LiteX-only OTA baseline,
if feasible, to remove the bladeRF receiver from the path and determine whether
LiteX TX to LiteX RX can recover the same live-style SSB/PBCH OTA signal.
