# Checkpoint 1128 - Fresh LiteX-only PBCH baseline after RF offset branch

## Purpose

CP1125-1127 closed the RF PBCH frequency/offset branch: bladeRF captures could
show PCI 1 and strong CSI windows, but no explicit SSB offset, CFO correction,
or focused short-window search recovered PBCH. CP1128 reruns a fresh LiteX-only
source-side PBCH baseline so the next external failure cannot be explained by a
current LiteX TX/RX or PBCH reference regression.

## Interpretation

CP1128 is a fresh PASS for the LiteX-only centered PBCH source path:

- The reference vector is unchanged and was replayed successfully.
- LiteX TX/RX streams are healthy in `none`, `phy`, and `ad9361`.
- Correlation is strong, normal, non-conjugated, and centered at `0 Hz`.
- `phy` decodes PBCH CRC OK directly.
- `none` and `ad9361` decode PBCH CRC OK with bounded windows despite the known
  full-buffer bad-candidate behavior.

This isolates the current PBCH failure away from a broad LiteX source-side
outage. The remaining failed boundary is still the external/live path involving
LiteX/gNB TX observed by bladeRF RX, or an interaction that appears only when
the bladeRF/external RF path is inserted.
