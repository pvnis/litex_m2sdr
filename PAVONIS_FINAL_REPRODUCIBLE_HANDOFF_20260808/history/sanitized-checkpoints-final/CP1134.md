# Checkpoint 1134-1135 - Full-vector bladeRF vs LiteX-only isolation

## Purpose

CP1130-1133 showed that the full `11.52 Msps` carrier-centered geometry
(`1842500000 Hz` carrier, `1839650000 Hz` SSB) fails through bladeRF, while the
centered `5.76 Msps` known-vector replay still passes. CP1134 captures the full
vector through bladeRF at the carrier center and full bandwidth. CP1135 then
uses only LiteX TX/RX on the same full vector and carrier geometry to isolate
whether the full vector/source path is valid before bladeRF is inserted.

## Interpretation

CP1135 proves the full `11.52 Msps` off-center vector and LiteX source path are
healthy:

- LiteX-only `none`, `phy`, and `ad9361` captures all correlate strongly at
  `0 Hz`.
- The same full vector decodes PBCH through LiteX-only `phy`.
- CP1134, using the same full vector and carrier-centered capture geometry
  through bladeRF, has no meaningful full-vector correlation and no PBCH.

This isolates the current failed boundary to the bladeRF/external receive
interaction for the full carrier-centered/off-center geometry. It is not a
generic full-vector generation failure, not a generic LiteX TX failure, and not
an analysis-only PBCH issue.

The next diagnostic should test bladeRF's `11.52 Msps / 10 MHz` receive mode
independently from off-center SSB content. If bladeRF can receive a centered
known signal at `1842.5 MHz` with full-band capture, then the remaining fault is
specific to the full-vector/off-center content or how bladeRF observes it. If
that fails too, the problem is bladeRF receive configuration/rate/bandwidth or
the RF path at that center.
