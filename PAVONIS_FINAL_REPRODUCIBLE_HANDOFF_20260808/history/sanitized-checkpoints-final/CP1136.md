# Checkpoint 1136-1142 - Replay helper correction and full-vector NRSA pass

## Purpose

CP1134-1135 isolated an apparent full-vector bladeRF failure, but CP1135 also
proved the full vector was healthy inside LiteX-only TX/RX. CP1136-1139 tried to
split frequency, bandwidth, and off-center variables, then CP1140 identified a
more basic problem: the raw capture harness was using the older `test_play.py`
helper, while the known-good NRSA path uses the partial-write-aware helper
`cp1034_remote_nuc4_start_cf32_replay_tx_gaintrace_partialwritefix.sh`.

This report supersedes the CP1136-1139 raw conclusions and establishes the
corrected baseline:

- CP1140: centered `5.76 Msps` raw control passes with the partial-write helper.
- CP1141: full `11.52 Msps` off-center raw capture passes PBCH with the same
  helper.
- CP1142: full `11.52 Msps` off-center NRSA acquisition passes and camps.

## Invalidated Branch: CP1136-1139

CP1136 created a shifted full-vector diagnostic:

- Source: `cp823_zero_copy_tx_dump_analysis_[date-redacted]/vectors/pre_dma_full_scale32768.cf32`
- Shift: `+2850000 Hz`
- Output: `cp1136_shift_fullvector_ssb_to_center_[date-redacted]/cp1136_fullvector_shift_plus2850000_ssb_center_fs11520.cf32`
- Output sha256:
  `d07c5be3eeacdf1c8137786a5ba9001f4d924a017fbe9d7126d15c7bd78fa861`
- Offline `ssb_file_test` validation: CSI PCI 1, PBCH PCI 1, CRC OK, MIB
  decoded.

The CP1136/1138/1139 raw RF runs then failed to correlate or decode. CP1137 was
not a valid RF search because NRSA rejected `1842.5 MHz` as absent from its
requested sync raster/baseband window:

```text
Target SSB center frequency 1842.50 MHz was not present in the requested sync raster/baseband window.
```

The important later finding is that CP1136/1138/1139 used the `cp848` raw
capture harness, whose remote TX helper launches `test_play.py`. That helper is
not equivalent to the partial-write-aware replay helper used by CP1082/NRSA.
Therefore the CP1136/1138/1139 raw failures are harness artifacts, not valid
RF-path conclusions.

## Interpretation

The CP1130/CP1134 no-cell/no-correlation branch is corrected:

- The full vector was always valid; CP1135 proved that inside LiteX-only TX/RX.
- The failed CP848 raw captures were produced with the older `test_play.py`
  helper and are not comparable to the partial-write-aware NRSA path.
- CP1140 confirms the corrected CP920 raw harness reproduces the known centered
  bladeRF control.
- CP1141 confirms full-vector off-center raw RF PBCH works.
- CP1142 confirms full-vector off-center NRSA works and camps.

The ladder is now back above known-vector full-geometry NRSA. The next step is
live gNB full-geometry NRSA using the CP1142 settings as the baseline. If live
gNB still fails, the failure is live-gNB-specific rather than a generic
full-vector/LiteX/bladeRF/off-center geometry problem.
