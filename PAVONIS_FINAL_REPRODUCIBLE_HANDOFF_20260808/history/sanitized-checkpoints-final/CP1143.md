## Purpose

After CP1142 proved that the full/off-center known-vector replay can camp NRSA
through LiteX TX to bladeRF RX, retest the live gNB at the same full geometry
and isolate whether the remaining failure is NRSA-specific, raw RF/PBCH-level,
or already present in the live gNB digital TX path.

Geometry used for the full-geometry ladder:

- DL/carrier center: `1842500000 Hz`
- SSB center: `1839650000 Hz`
- Sample rate: `11520000`
- RF bandwidth: `10000000`

## Interpretation

The current boundary is now:

```text
Known-vector full-geometry replay through LiteX TX -> bladeRF RX NRSA: PASS (CP1142)
Live gNB full-geometry NRSA: FAIL/no-cell (CP1143)
Live gNB full-geometry raw RF PBCH: FAIL/PBCH KO (CP1144)
Live gNB same-window pre-DMA/post-DMA TX dump: PASS with targeted windows (CP1145)
Live gNB same-window bladeRF RF PBCH: FAIL/PBCH KO (CP1145)
```

This is no longer explained by missing PBCH in OCUDU's generated waveform or by
the normal zero-copy DMA ring lacking PBCH. It is also not a generic
LiteX-to-bladeRF full-geometry impossibility, because the known-vector replay
passes through the same nominal carrier/SSB geometry.

Most likely remaining boundary: live gNB real-time TX consumption/RF egress
behavior, the physical RF path under live streaming, bladeRF receive tolerance
to that live stream, or a subtle difference between replayed file TX and live
gNB Soapy TX timing/cadence. The Android phone on [host-redacted] remains irrelevant until
the RF/PBCH/NRSA layer is stable again.
