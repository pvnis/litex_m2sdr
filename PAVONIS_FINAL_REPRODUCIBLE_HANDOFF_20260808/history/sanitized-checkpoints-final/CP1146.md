## Interpretation

CP1146 shows NRSA does not reliably acquire this current pre-DMA vector replay,
but CP1147 shows the same vector is still RF-decodable at PBCH level when sent
through the corrected file replay path.

The important A/B remains:

```text
CP1145 live same-window RF capture: 0/167 PBCH CRC OK windows
CP1147 same-vector file replay RF capture: 3/167 PBCH CRC OK windows
```

So the CP1145 live failure is not explained by the pre-DMA vector lacking PBCH.
The same vector can produce decodable RF PBCH when replayed. The remaining
boundary is live gNB streaming/cadence/RF egress versus the file replay path,
plus any receive-path tolerance differences.

Because the replay pass is weak, NRSA is not a reliable gate for this specific
current vector; raw PBCH windows are the better comparator at this rung.

## Next Step

Remove bladeRF from the next comparison if an existing harness supports it:
capture the live gNB downlink with LiteX/M2SDR RX while the same LiteX/M2SDR is
transmitting, or run an equivalent LiteX-only live TX/RX baseline. If LiteX-only
live RX decodes PBCH while bladeRF does not, the issue is external bladeRF/RF
receive interaction. If LiteX-only live RX also fails, the issue is live gNB
TX/RF egress before bladeRF.
