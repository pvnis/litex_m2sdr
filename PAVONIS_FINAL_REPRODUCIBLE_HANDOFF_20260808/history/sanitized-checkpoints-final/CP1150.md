## Interpretation

CP1150 validates CP1149 as a meaningful live-vs-file split at the same bladeRF
receive gain:

```text
Live gNB, gain36, full geometry:        0 / 170 PBCH OK in 50 ms subset (CP1149)
File replay, gain36, full geometry:    10 / 167 PBCH OK in 50 ms sweep (CP1150)
File replay, gain42, full geometry:     3 / 167 PBCH OK in 50 ms sweep (CP1147)
LiteX-only current vector:             92 PBCH OK cases on phy capture (CP1148)
```

This rules out two simple explanations for the live failure:

- The CP1144/CP1145 live PBCH KO was not solely caused by bladeRF gain42
  clipping, because live gain36 is clean but still KO.
- BladeRF gain36 is not too low to ever decode this RF setup, because the exact
  current vector file replay decodes PBCH at gain36.

The remaining boundary is therefore more specifically the live gNB streaming /
timing / cadence / RF egress behavior, or its interaction with the external
receive path, rather than the vector content, LiteX-only source path, or a simple
bladeRF receive gain setting.
