# Checkpoint 1151 - Timed DMA Reconstruction Decode Still Passes

## Purpose

Test a concrete explanation for the CP1145 live split:

```text
Maybe the post-DMA parser concatenates timed payload buffers, while RF hardware
actually sees timestamped gaps. If so, digital post-DMA PBCH could pass while
OTA PBCH fails.
```

CP1151 reconstructs the CP1145 live TX DMA capture using the nonzero
`timestamp_samples` entries in `tx_dma_buffers.bin.meta.jsonl`, inserts the
corresponding zero gaps, then decodes the timestamp-expanded waveform locally.

Source TX dump:

```text
cp823_zero_copy_tx_dump_[date-redacted]TCP1145_PAIRED_TXDUMP_FULLGEOM_AFTER_CP1144/cp823_paired_zero_copy_tx_dump_bladerf_capture_[date-redacted]TCP1145_PAIRED_TXDUMP_FULLGEOM_AFTER_CP1144/txdump
```

Helper:

```text
python3 cp1151_reconstruct_timed_dma_waveform.py \
  --txdump-dir <CP1145 txdump> \
  --out-dir cp1151_cp1145_timed_dma_reconstruction_[date-redacted] \
  --fs 11520000
```

## Interpretation

The simple gap-concatenation theory is not sufficient:

```text
Concatenated post-DMA ch0:       PBCH PASS
Timestamp-expanded post-DMA ch0: PBCH PASS
Live same-window RF:             PBCH FAIL (CP1145)
Live gain36 RF:                  PBCH FAIL (CP1149)
File replay gain36 RF:           PBCH PASS (CP1150)
```

Local decode still passes after honoring the DMA timestamp gaps. Therefore the
failure is not merely that the analysis removed zero gaps between timed payloads.

The next split should exercise LiteX timed TX over RF using known-good file
content. If a timed-burst file replay fails while continuous file replay passes,
the fault localizes to timed TX mode or hardware behavior during timed bursts. If
timed-burst file replay passes, then the remaining difference is live gNB runtime
behavior beyond the timestamp/gap pattern.
