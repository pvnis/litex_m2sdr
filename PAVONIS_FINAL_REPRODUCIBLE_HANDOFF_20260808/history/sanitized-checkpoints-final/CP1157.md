Date: [date-redacted]

## Purpose

After CP1150 and CP1152 showed that the current pre-DMA PBCH vector can pass over the LiteX to bladeRF RF path when replayed through the CF32 Soapy path, CP1157 tried to replay the CP1145 live TX dump more exactly:

- same `pre_dma_tx.cs16` payload,
- same metadata row sizes,
- same duplicate/split write boundaries,
- same `HAS_TIME` flags and timestamp spacing.

Because the first exact replay was clipped, CP1158 lowered TX power. Because CP1158 still failed, CP1159 and CP1160 tested whether the raw CS16 file itself is a valid Soapy CS16 replay source by replaying it continuously without metadata timing.

## Interpretation

CP1157 by itself was not decisive because the bladeRF capture clipped badly.

CP1158 removed clipping and still failed PBCH, but CP1159 and CP1160 show a more important control failure: even a continuous, no-metadata replay of the same raw CS16 dump fails at clean receive levels, including a level close to the CP1150 passing CF32 replay.

Therefore the current CS16 replay path is not a known-good representation of the CP1145 pre-DMA vector. The raw `pre_dma_tx.cs16` file should not yet be treated as directly replayable through the Soapy CS16 API. Possibilities include format/packing/scaling differences between the dumped pre-DMA representation and Soapy CS16 API input, or another CS16 TX-path difference. This means CP1157/CP1158 do not yet isolate the live metadata/write pattern.

The stronger conclusion is:

- The bladeRF/LiteX RF path can still pass PBCH with CF32 replay controls.
- Raw CS16 Soapy replay of the CP1145 pre-DMA dump fails even without metadata timing.
- The next valid metadata isolation should preserve the CP1145 metadata timing while using the already-passing CF32 sample representation.

## Next step

Run a CF32 exact-metadata replay:

- Convert each `pre_dma_tx.cs16` row to CF32 as `I/Q / 32768.0`.
- Use Soapy `SOAPY_SDR_CF32`, not `SOAPY_SDR_CS16`.
- Preserve row boundaries, `numElems`, duplicate split rows, original `flags`, and shifted `timeNs`.
- Keep bladeRF full geometry: center `1842500000`, SSB `1839650000`, fs `11520000`, RX gain36.

If exact CF32 metadata replay passes, the current CS16 replay path was the invalid branch. If it fails while continuous CF32 still passes, then the metadata/timestamp pattern becomes the active suspect.
