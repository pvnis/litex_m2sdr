# Checkpoint 1165 - Patched Soapy module plugin-path audit

## Purpose

After CP1164 showed that the installed LiteX Soapy modules do not contain the
`M2SDR_SOAPY_TX_CS16_TO_SC12` env hook, find a reversible way to load a patched
module without overwriting root-owned installed modules.

No RF transmission was performed.

## Loader Dry Runs

Plain `SOAPY_SDR_PLUGIN_PATH` is insufficient. With only:

```text
SOAPY_SDR_PLUGIN_PATH=/home/[host-redacted]/CLionProjects/m2sdr/litex_m2sdr/software/soapysdr/build
```

Soapy still registered the installed `/usr/lib/...` module first and treated
the patched build module as a duplicate.

The reversible working load pattern is:

```text
SOAPY_SDR_ROOT=/tmp/empty-soapy-root-cp1165
SOAPY_SDR_PLUGIN_PATH=/home/[host-redacted]/CLionProjects/m2sdr/litex_m2sdr/software/soapysdr/build
```

With those variables, `SoapySDR.listModules()` returned only:

```text
('/home/[host-redacted]/CLionProjects/m2sdr/litex_m2sdr/software/soapysdr/build/libSoapyLiteXM2SDR.so',)
```

`SoapySDR.Device.enumerate({"driver":"LiteXM2SDR"})` still found the device.

## Interpretation

We do not need to overwrite installed modules before the next test. CP1166 can
repeat the CP1164 CS16 replay with:

```text
SOAPY_SDR_ROOT=/tmp/empty-soapy-root-cp1166
SOAPY_SDR_PLUGIN_PATH=/home/[host-redacted]/CLionProjects/m2sdr/litex_m2sdr/software/soapysdr/build
M2SDR_SOAPY_TX_CS16_TO_SC12=1
```

The next RF test must log `SoapySDR.listModules()` from inside the TX process
before opening the device, to prove the patched module is the only loaded LiteX
Soapy module.
