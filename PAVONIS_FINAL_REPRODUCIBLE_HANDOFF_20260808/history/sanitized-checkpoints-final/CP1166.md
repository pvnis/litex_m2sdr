## Interpretation

CP1166 proves the source-tree CS16-to-SC12 conversion path works when the
patched build module is actually loaded. It also explains CP1164:

- CP1164 forced the env, but the installed active modules did not contain the
  env hook, so the capture remained clipped.
- CP1166 loaded the patched module, used the same env and RF geometry, removed
  clipping, and recovered off-center PBCH CRC OK.

The raw CS16 replay-format branch is therefore recovered. The next ladder step
is live gNB with the same reversible module-load environment and
`M2SDR_SOAPY_TX_CS16_TO_SC12=1`, not another CS16 replay.

The 20 ms sweep did not show PBCH OK windows even though the full one-shot did,
so acquisition remains timing/window-sensitive. Use the correct off-center
analysis and do not rely on the centered CP920 built-in PBCH result for this
full-geometry case.
