# Checkpoint 1169 - No-RF live Soapy TX egress source audit

## Purpose

Audit the live OCUDU Soapy TX path after CP1168 showed CP1167 live raw has
clean RF level but weak correlation against the known-good CP1145 pre-DMA
reference.

This checkpoint uses source inspection only. It spends no RF time.

## Result

The live gNB Band 3 template uses Soapy discontinuous TX:

```text
ru_sdr:
  device_driver: soapy
  device_args: "driver=LiteXM2SDR"
  expert_cfg:
    tx_mode: discontinuous
  srate: 11.52
  otw_format: sc16
```

Source: `/home/[host-redacted]/CLionProjects/litex_m2sdr/litex_m2sdr/software/validation/ocudu/configs/gnb_m2sdr_band3_ota.template.yml`

The Soapy device wrapper hardcodes stream setup to `SOAPY_SDR_CS16`:

```text
/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_device.h:141-148
```

That is already accounted for by CP1166/CP1167's patched-module
CS16-to-SC12 work, but it remains relevant because live gNB is still using the
CS16 Soapy stream mode.

Main source finding:

```text
/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp:197-216
```

When the FSM flags end-of-burst for an empty discontinuous gap, the Soapy path
notifies OCUDU's radio event notifier, computes the sample range, then returns
early:

```text
if (tx_md.is_empty && discontinuous_tx) {
  // Nothing to write; burst was already closed via flag.
  return;
}
```

That means no zero-length `writeStream(..., SOAPY_SDR_END_BURST, ...)` is sent
to SoapySDR for the normal live empty-gap EOB case.

The UHD path handles the analogous empty discontinuous buffer differently:

```text
/home/[host-redacted]/CLionProjects/ocudu/lib/radio/uhd/radio_uhd_tx_stream.cpp:279-305
```

It maps empty discontinuous data to a zero-length transmit view, then enters a
`do { transmit_block(...) } while (...)` loop. That sends one zero-length UHD
packet carrying the EOB metadata. So the Soapy path is not a semantic mirror of
the UHD path for empty-gap EOB propagation.

Secondary source finding:

```text
/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp:221-235
```

The live Soapy path asks Soapy to write the entire remaining baseband block and
relies on partial `writeStream` returns for chunking. The known-pass replay
helpers instead write explicit small chunks:

- CP1166 CS16 patched replay uses `--chunk-len 1022` and writes flags/time `0`.
- CP1152 timed nonzero CF32 replay uses `--chunk-len 1022`, `SOAPY_SDR_HAS_TIME`
  only on the first chunk of each nonzero segment, and no EOB flag.

Those replay helpers prove the vector and LiteX RF path can work, but they do
not exercise the live discontinuous empty-gap EOB behavior.

## Interpretation

CP1169 identifies a concrete live-only software-presentation candidate:

- Live gNB uses discontinuous TX.
- The Soapy FSM can generate `SOAPY_SDR_END_BURST` when the next buffer is
  empty.
- The current Soapy transmit code returns before sending that EOB marker to the
  Soapy device.
- UHD's implementation does send an empty EOB packet in the equivalent case.
- Known-pass replays avoid this live discontinuous EOB path, so their success
  does not close this branch.

This fits the CP1168 evidence better than a level or static-vector theory:
CP1167 has TX energy and clean level, but does not correlate like replayed
current vectors.

The next useful checkpoint is a minimal, reversible Soapy TX patch/test:

1. When `tx_md.is_empty && discontinuous_tx && is_eob`, send a zero-length
   `writeStream` with `SOAPY_SDR_END_BURST` before returning.
2. Keep logging of zero-length EOB send count and return code.
3. Run a live full-geometry raw capture with the same patched-module
   `M2SDR_SOAPY_TX_CS16_TO_SC12=1` environment used in CP1167.
4. If PBCH/correlation improves, the live blocker is EOB propagation. If not,
   move to explicit live chunk-size/cadence control.
