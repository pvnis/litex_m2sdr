## Evidence

### OCUDU Soapy TX Loop

`radio_soapy_tx_stream.cpp` currently loops while `sent_total <
data_nof_samples`, passes the entire `remaining` sample count to Soapy, and
copies `SOAPY_SDR_END_BURST` into `chunk_flags` on every loop iteration when
the logical OCUDU buffer is end-marked.

Important local lines:

```text
241-257: sent_total loop, remaining = data_nof_samples - sent_total
250-254: HAS_TIME only on first chunk, END_BURST copied unconditionally
257: write_stream(..., remaining, chunk_flags, ...)
267-268: sent_total advances by ret; chunks increments
```

This means a logical buffer with `END_BURST` can produce multiple Soapy writes
that all carry `END_BURST` if the driver returns a partial count.

### LiteX Soapy Driver

`LiteXM2SDRStreaming.cpp` makes those partial counts expected behavior:

```text
[date-redacted]-[date-redacted]: returnedElems = min(numElems, getStreamMTU(stream))
2173-2177: first writeStream into a fresh DMA buffer becomes that buffer metadata
2130-2139: late END_BURST may be ORed into an in-progress remainder buffer
2750-2785: releaseWrite writes HAS_TIME/END_BURST into each DMA header
```

So if OCUDU asks for a large end-marked logical write, the LiteX Soapy API
will only accept up to MTU samples and return. OCUDU then retries with the same
logical EOB bit. The resulting hardware-visible DMA headers can show
END_BURST on more than the final frame of a multi-frame logical burst.

### Timed-TX Convention

The LiteX timed-TX arbiter documents the host-side burst convention in
`timed_tx.py`:

```text
Single-frame timed:   HAS_TIME=1, END_BURST=1
Multi-frame timed:    first HAS_TIME=1, last END_BURST=1
Multi-frame untimed:  HAS_TIME=0, ..., END_BURST=1
```

That convention is incompatible with repeated END_BURST on every short write
of a split multi-frame timed burst.

### Known-Pass Replay Helpers

Known-pass CF32 replay helpers CP1161 and CP1162 explicitly avoid repeated
metadata on short writes:

```text
cp1161 write_row:
  writeStream(..., flags if first else 0, time_ns if first else 0)
  first = False after a successful write

cp1162 write_row:
  same first-write-only flags/time pattern
```

This does not prove repeated live EOB is the only blocker, but it is a concrete
live-vs-known-pass presentation mismatch at the hardware metadata boundary.

## Verdict

CP1174 finds a stronger candidate than the previous empty-gap EOB issue:

```text
Live OCUDU Soapy TX can propagate END_BURST on every short write of an
end-marked logical buffer, while LiteX timed-TX expects END_BURST only on the
last DMA frame of a multi-frame burst.
```

The current aggregate `OCUDU_SOAPY_TX_TRACE` is also insufficient. It logs only
one summary after a complete `transmit()` call when the total call exceeds the
threshold. It does not record the per-write requested sample count, returned
count, flags, time, or whether a write is the final logical chunk.

## Next Checkpoint

Implement a scoped local OCUDU Soapy TX patch:

1. Add a per-write trace knob, e.g. `OCUDU_SOAPY_TX_TRACE_WRITES`.
2. Add an optional write-size limiter, e.g.
   `OCUDU_SOAPY_TX_FORCE_CHUNK_SAMPLES`, so live gNB cadence can be aligned to
   known-pass replay-style chunks.
3. Stop applying `SOAPY_SDR_END_BURST` to non-final split writes. Preserve
   `SOAPY_SDR_HAS_TIME` only on the first write as today.
