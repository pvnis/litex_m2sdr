# Checkpoint 1190 - Live gNB Stderr TX Summary Period 100 Produces Lines

Date: [date-redacted] Europe/Zurich

Scope: [host-redacted]-only live gNB process environment and stderr-summary diagnostic.
No bladeRF capture, no UE, no Android, no PBCH/NRSA analysis.

## Result

PASS for the intended summary output.

After CP1188/CP1189 changed the opt-in summary path to print directly to
stderr, the short live gNB probe with `OCUDU_SOAPY_TX_SUMMARY_PERIOD=100`
produced the startup summary line and periodic TX summary lines in the gNB log.

This proves the live gNB path does construct and use
`radio_soapy_tx_stream`. It also proves the summary environment reaches that
path. The earlier no-line results were therefore due to logger/log-capture
behavior, not because the live path skipped the OCUDU Soapy TX stream.

## Interpretation

CP1190 closes the "live gNB may not construct/use `radio_soapy_tx_stream`"
theory. It also closes the "summary env does not reach gNB" theory and the
"period 10000 was too high" theory.

The live TX write stream is active and clean from the Soapy caller perspective:
no partial returns, no over-returns, no timeouts, no errors, and request/return
sample totals match. The active cadence is MTU-sized writes (`mtu=1022`,
`req_max=1022`) with many non-final data chunks and explicit zero-length EOB
writes for empty discontinuous gaps.

The next branch should interpret these counters against the known-pass replay
helpers and, if justified, run a bounded forced-cadence comparison such as
`OCUDU_SOAPY_TX_FORCE_CHUNK_SAMPLES` rather than repeating a blind live RF run.
