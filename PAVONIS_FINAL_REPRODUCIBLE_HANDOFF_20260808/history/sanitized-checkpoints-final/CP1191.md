# Checkpoint 1191 - Live TX Counters Versus Known-Pass Replay Cadence

Date: [date-redacted] Europe/Zurich

Scope: local/no-RF analysis of CP1190 live gNB Soapy TX summary counters
against known-pass replay helper behavior. No SSH, no bladeRF capture, no UE,
no Android, no PBCH/NRSA run.

## Result

PASS as an analysis checkpoint.

CP1190 proved that live gNB uses `radio_soapy_tx_stream` and that caller-side
Soapy writes are clean. CP1191 compares that live cadence with known-pass
replay helpers and finds that a forced chunk-size run is not the right next
test: live already uses the LiteX MTU (`1022` samples), and the best timed and
CS16-to-SC12 known-pass helpers also use `1022` sample writes.

The sharper remaining live-only difference is EOB behavior. The known-pass
helpers do not send zero-length empty-gap EOB writes. Current live gNB does:
CP1190 observed `1118` zero-length empty EOB writes by logical call `2600`.
The next useful software experiment is therefore an opt-in knob to suppress
empty-gap zero-length EOB writes while keeping the CP1175 last-EOB/chunk patch
active.

## Known-Pass Replay Comparisons

### CP1152 Timed Nonzero Replay

CP1152 replayed the CP1145 current pre-DMA vector as timed nonzero islands and
passed PBCH:

```text
chunk_len=1022
loops=80
segment_count=243
nonzero_samples=409033 / 2000000
total_writes=39200
total_sent=32722640
total_short_writes=0
total_errors=0
PBCH CRC OK windows=34/167
```

CP1152's helper writes each segment with `SOAPY_SDR_HAS_TIME` on the first
write and no `SOAPY_SDR_END_BURST` path. It uses the same chunk size as live
but does not send empty-gap zero-length EOBs.

### CP1161/CP1162 CF32 Metadata Replays

CP1161 and CP1162 replayed the same pre-DMA CS16-derived samples as CF32 with
captured metadata and passed PBCH. CP1162 metadata:

```text
rows=4028 per 2000000 samples
flags={"0": 3765, "4": 263}
period_ns=673611110
total_rows=96672 over 24 loops
total_writes=96672
total_sent=48000000
total_short_writes=0
total_errors=0
```

Flag `4` is `SOAPY_SDR_HAS_TIME`. No captured metadata rows use
`SOAPY_SDR_END_BURST`.

### CP1166 Patched-Module CS16-To-SC12 Replay

CP1166 proved the patched LiteX Soapy module can make raw CS16 replay pass
PBCH when `M2SDR_SOAPY_TX_CS16_TO_SC12=1` is actually active:

```text
chunk_len=1022
loops=90
loop_sent=2000000
loop_writes=1957
total_writes=176130
total_sent=180000000
total_short_writes=0
total_errors=0
```

The CP1166 helper writes continuous CS16 with flags `0`; it has neither timed
metadata nor zero-length EOB writes.

### CP1147/CP1150 Continuous CF32 Replays

The CP1034 partial-write-aware helper used in CP1147/CP1150 requested
`1536`-sample buffers but LiteX returned many partial writes. Those passes are
therefore not evidence for forcing live away from `1022`; they show the helper
loops until the full buffer is accepted:

```text
chunks=416800
short_writes=208320
total_samples=320000000
errors=0
```

## Interpretation

The live chunk size is not the leading mismatch. CP1190 live already uses the
MTU `1022` sample maximum, and CP1152/CP1166 known-pass helpers also use
`1022`. Forcing `OCUDU_SOAPY_TX_FORCE_CHUNK_SAMPLES=1022` would be a no-op
relative to CP1190.

The remaining concrete difference is EOB/empty-gap behavior:

```text
Known-pass CP1152 timed nonzero: HAS_TIME on segment starts, no EOB writes.
Known-pass CP1161/1162 CF32 metadata: HAS_TIME rows, no EOB rows.
Known-pass CP1166 CS16-to-SC12: continuous flags=0, no EOB rows.
CP1190 live gNB: discontinuous=true, 1118 empty zero-length EOB writes by logical 2600.
```

CP1167 was a pre-CP1175 run with no empty-EOB patch but still had the old
repeated-data-EOB problem. CP1177 had the CP1175 last-EOB/chunk fix but kept
empty-gap zero-length EOB writes. There has not yet been a run with the
CP1175 last-EOB/chunk behavior and empty-gap zero-length EOB writes suppressed.
