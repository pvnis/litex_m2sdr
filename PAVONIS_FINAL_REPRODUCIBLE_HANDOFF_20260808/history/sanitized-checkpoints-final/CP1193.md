## Result

PASS as a local software checkpoint.

Implemented an opt-in OCUDU Soapy TX knob:

```text
OCUDU_SOAPY_TX_SUPPRESS_EMPTY_EOB
```

When unset or set to `0`, default behavior remains unchanged: empty
discontinuous EOB logical calls still issue a zero-length
`SOAPY_SDR_END_BURST` write.

When set to a non-`0` value, empty discontinuous EOB logical calls are counted
but the zero-length Soapy `writeStream(..., 0, SOAPY_SDR_END_BURST, ...)` call
is skipped. The existing summary output now reports both:

```text
empty_eob_writes={}
suppressed_empty_eob={}
suppress_empty_eob={}
```

This preserves the CP1175 data-write behavior: MTU-sized data chunks by
default, optional forced chunking, `HAS_TIME` only on the first data chunk, and
`END_BURST` only on the final data chunk.

live-only mismatch. CP1193 makes that hypothesis testable without changing
default behavior. The next checkpoint should deploy this two-file patch to
