# Checkpoint 1200 - LiteX TX Release Post-Dedup Header Counters

Date: [date-redacted] Europe/Zurich

Scope: add post-dedup `_dmaReleaseWrite(...)` counters to distinguish CP1199
pre-release worker metadata from actual DMA header flags handed to the LiteX
timed-TX path. This checkpoint includes local source patching, [host-redacted]
deploy/build/module-smoke, and a short [host-redacted]-only live gNB no-RF probe. No
bladeRF capture, UE, PRACH, NRSA, or Android test was run.

## Result

PASS for the post-dedup header boundary.

CP1200 proves the duplicated CP1199 worker `HAS_TIME` packets are mostly
suppressed before the DMA header is written. The final post-cleanup release
summary was:

```text
LiteX TX release summary: reason=stop seq=1 packets=37535 samples=38360770 pre_has_time=5030 post_has_time=2518 dedup_suppressed=2512 post_no_time=35017 post_eob=2 post_has_time_pos_ns=2518 post_has_time_zero_ns=0 post_has_time_neg_ns=0 post_time_min_ns=[subscriber-redacted] post_time_max_ns=[subscriber-redacted] post_slip_count=2518 post_late_count=2 post_slip_min_ns=-97709635 post_slip_max_ns=92188 reader_enabled=1 samplerate=11520000
```

The paired OCUDU stop summary reported:

```text
has_time_writes=2518
has_time_pos_ns=2518
has_time_zero_ns=0
has_time_neg_ns=0
samples_req=38361600
samples_ret=38361600
partial_ret=0
over_ret=0
timeouts=0
errors=0
```

Interpretation:

- Post-dedup `post_has_time=2518` matches OCUDU `has_time_writes=2518`.
- Pre-dedup worker `HAS_TIME` metadata was duplicated: `pre_has_time=5030`.
- The dedup gate suppressed `2512` duplicate timed packets before DMA header
  submission.
- Actual post-dedup timed headers were all positive timestamped.
- Two actual post-dedup timed headers were committed late in this no-RF run:
  `post_late_count=2`, with worst positive slip `92188 ns`.

This closes the CP1199 ambiguity. The single CP1199 late event was not only a
pre-dedup accounting artifact class; CP1200 observed real post-dedup late
headers, though only two in this short run.

## Verdict And Next Step

Do not repeat CP1200 just to resolve pre-dedup versus post-dedup counts. That
boundary is now clear: actual timed DMA headers match OCUDU's timed writes, and
duplicate worker `HAS_TIME` metadata is suppressed before header submission.

The next useful checkpoint should add a bounded direct-stderr trace for actual
post-dedup late headers, including packet sequence, samples, timestamp,
hardware time, and slip. That will tell whether the two late headers are
ordinary live-run events, near cleanup/stop, or tied to specific short/final
chunks. If late events are ordinary, test whether they line up with the live
PBCH failure windows before changing timing offsets.
