# Checkpoint 1202 - LiteX TX Release Late Trace

Date: [date-redacted] Europe/Zurich

## Goal

CP1200 proved that actual post-dedup timed DMA headers match OCUDU timed writes
and found a small number of actual late post-dedup headers. CP1202 adds a
bounded direct-stderr trace at that exact `_dmaReleaseWrite` boundary to
determine whether those late headers are normal TX data or cleanup/final chunks.

## Key Result

The single actual post-dedup late header was:

```text
LiteX TX release late: trace_idx=0 packet_seq=31371 numElems=1022 mtu=1022 short_chunk=0 post_eob=0 pre_has_time=1 post_has_time=1 dedup_suppressed=0 timeNs=[subscriber-redacted] nowNs=[subscriber-redacted] slipNs=154514 release_late_count=1 release_post_has_time=2105 reader_enabled=1 samplerate=11520000
```

Interpretation:

- It was a full MTU packet: `numElems=1022`, `mtu=1022`, `short_chunk=0`.
- It was not an end-of-burst or cleanup marker: `post_eob=0`.
- It was an actual post-dedup timed header: `post_has_time=1`,
  `dedup_suppressed=0`.
- It occurred during ordinary live TX, around `release_post_has_time=2105`,
  not as the final chunk.
- It was late by `154514 ns`.

## Conclusion

CP1202 proves that the post-dedup late-header condition can occur during normal
full-MTU live TX data, not only at cleanup, not only on short/final chunks, and
not as a duplicate timestamp that `_dmaReleaseWrite` suppresses.

The next useful checkpoint should stay no-RF: rerun the same live gNB probe with
a conservative positive `M2SDR_SOAPY_TX_TIME_OFFSET_NS` larger than the observed
late slip, for example `1000000 ns`, and verify whether post-dedup late headers
drop to zero without caller-side Soapy errors. Only if that no-RF mitigation
behaves cleanly should a full-geometry RF proof be retried.
