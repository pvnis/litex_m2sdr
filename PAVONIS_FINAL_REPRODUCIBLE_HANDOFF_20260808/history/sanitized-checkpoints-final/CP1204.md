# Checkpoint 1204 - +1 ms TX Offset Full-Geometry RF: Post-Late Zero, PBCH Still Fails

Date: [date-redacted] Europe/Zurich

Scope: full-geometry live gNB RF proof after CP1203 showed
`M2SDR_SOAPY_TX_TIME_OFFSET_NS=1000000` clears actual post-dedup late DMA
headers in a no-RF live gNB run. No UE, PRACH, NRSA, Android, or attach test
was run.

## Result

FAIL for live Stage 5/PBCH recovery, PASS for the timed-header mitigation
inside the full RF run.

The +1 ms offset stayed active during a full-geometry live RF capture and the
actual post-dedup LiteX release boundary reported `post_late_count=0` with no
bounded late-trace lines. Caller-side Soapy counters were clean. Despite that,
the bladeRF capture still failed correct off-center PBCH: the one-second
off-center PBCH test was CRC KO, the 20 ms window sweep had zero PBCH CRC OK
windows, and centered detector side-analysis saw TX/PSS without proving PCI 1.

This closes "simple post-dedup late timed DMA headers are the live RF blocker"
as not sufficient for this full-geometry branch.

## Verdict And Next Step

CP1204 proves that clearing actual post-dedup late DMA headers is not enough to
recover live full-geometry downlink. The +1 ms offset is useful evidence and
may improve RF correlation, but the live RF path remains PBCH-undecodable.

Do not rerun this exact RF proof unless a new variable changes the live egress
or RF path. The next useful branch should move beyond simple timed-TX lateness:
compare what changed to improve correlation at `+5.5 kHz`, or build a
minimal live-cadence replay that can vary timestamp lead, cadence, and format
without the full gNB stack. If the branch stalls, use LiteX-only TX/RX as the
bladeRF-isolation baseline before another live RF retry. Do not move to
Android/PRACH until independent live downlink PBCH/NRSA is stable.
