## Interpretation

CP1208 is the first clean standalone failure matching the newly isolated
live-cadence suspicion:

- CP1207 exact/prequeued CS16 metadata with patched module: PBCH OK,
  reference score `0.1219685951`.
- CP1208 paced CS16 metadata with the same patched module, same payload, same
  geometry, same TX attenuation, and no late/short/error counters: PBCH KO,
  `0/65` and `0/167` PBCH OK windows, reference score `0.0819968589`.
- CP1162 paced CF32 metadata with 50 ms lookahead passed, so the failure is not
  generic wall-clock pacing by itself.

The current boundary is now CS16 patched-conversion timed metadata under
live-like pacing or shallow queue depth. The next useful isolation is not
another exact/prequeued replay; it is a paced-lead sweep for CS16 metadata
under the patched module.

## Next Step

Run CP1209 with the same CP1208 helper and geometry but a larger
`PACE_AHEAD_S`, for example `0.25` or `0.50`, while keeping `TIMED_LEAD_S=0.75`.
If larger pacing lookahead recovers PBCH, the issue is queue-depth/lookahead
sensitivity in the CS16 patched path. If it still fails, compare CF32 paced
and CS16 paced driver counters more directly, because the failure is then tied
to CS16 conversion or metadata handling under paced submission rather than
simple lateness.
