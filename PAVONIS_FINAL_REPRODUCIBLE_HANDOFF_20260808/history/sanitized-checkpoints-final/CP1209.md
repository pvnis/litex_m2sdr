## Interpretation

CP1209 proves the CP1208 standalone failure is lookahead/queue-depth sensitive.

Comparison:

- CP1207 exact/prequeued CS16 metadata with patched module: PBCH OK,
  50 ms sweep `33/167`, reference score `0.1219685951`.
- CP1208 paced CS16 metadata with 50 ms lookahead: PBCH KO, 50 ms sweep
  `0/167`, reference score `0.0819968589`.
- CP1209 paced CS16 metadata with 250 ms lookahead: PBCH OK, 50 ms sweep
  `4/167`, reference score `0.2486964235`.

This closes "paced CS16 metadata is intrinsically broken" as too broad. The
failure boundary is shallow paced submission in the patched CS16 timed-metadata
path. The 20 ms sweep did not see the successful window because the first
decodable windows started around 27 ms in this capture; the one-shot and 50 ms
sweep both prove recovery.

## Next Step

Bracket the lookahead threshold before returning to live gNB:

- Run the same patched-module paced-CS16 helper with a mid value such as
  `PACE_AHEAD_S=0.10` or `0.15`.
- If the mid value passes, reduce further to find the minimum useful queue
  depth.
- If the mid value fails, use the CP1208/CP1209 contrast to focus live work on
  queue-depth/lookahead rather than on sample content, patched conversion, RF
  path, or simple late-header counters.
