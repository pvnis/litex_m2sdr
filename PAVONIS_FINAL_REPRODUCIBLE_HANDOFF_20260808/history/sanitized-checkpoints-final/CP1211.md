## Interpretation

CP1211 is a clean paced-CS16 pass at 100 ms lookahead:

- one-shot PBCH CRC OK,
- 20 ms and 50 ms sweeps both find multiple PBCH OK windows,
- reference correlation is stronger than CP1209's 250 ms pass,
- TX/module counters are clean.

This changes the branch interpretation. The current data are not monotonic by
single-run lookahead value:

- CP1208, 50 ms: fail, `0/167` PBCH OK, reference `0.0819968589`.
- CP1211, 100 ms: pass, `13/167` PBCH OK, reference `0.3144885418`.
- CP1210, 150 ms: marginal, `6/167` PBCH OK, one-shot KO, reference
  `0.0927197786`.
- CP1209, 250 ms: pass, `4/167` PBCH OK, one-shot OK, reference
  `0.2486964235`.

So shallow 50 ms lookahead is still closed as insufficient, but a single
lookahead scalar is not enough to explain all per-run quality. The branch now
points to queue-depth/lookahead plus timing phase or run-to-run coherence
variation in the patched CS16 paced path.

## Next Step

Do not jump back to live gNB from a single 100 ms pass. The next useful rung is
either:

- repeat 100 ms to confirm CP1211 reproducibility, or
- run 75 ms to bracket the lower pass/fail edge between 50 and 100 ms.

Given CP1210's non-monotonic marginal result, a repeat control is defensible
before treating 100 ms as a stable threshold.
