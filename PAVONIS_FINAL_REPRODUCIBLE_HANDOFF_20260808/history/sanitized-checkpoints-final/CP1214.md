## Interpretation

The earlier binary ladder labels were too coarse:

- CP1208 at 50 ms lookahead is not a total RF/PBCH failure. It has 21 PBCH OK
  windows over 250 ms, but none in the first 50 ms. Its decodable PBCH windows
  are later and weaker than the strongest 100/150 ms examples.
- CP1211 remains the strongest 100 ms run by count, but CP1212 is also
  decodable over 250 ms and has the strongest single CSI/PBCH window in this
  normalized set.
- CP1210 at 150 ms is not merely marginal over 250 ms; it has 41 PBCH OK
  windows, including strong windows near 90 ms and 220 ms.
- CP1209 at 250 ms remains decodable, but it does not dominate the normalized
  count. Its pass is real, but not a monotonic improvement over shorter
  lookahead values.

The patched-module paced-CS16 path is therefore not governed by a simple
lookahead cutoff in the tested 50-250 ms range. All tested lookahead captures
contain decodable PBCH somewhere in the first 250 ms. The remaining behavior is
window placement, run-to-run phase/coherence, and how much of the capture must
be searched to find stable PBCH.

## Current frontier update

CP1214 closes the "50 ms lookahead produces no decodable PBCH" theory. CP1208
was a short-window miss, not a complete no-PBCH capture. This means a new 75 ms
RF run would not answer the original threshold question cleanly unless paired
with a 250 ms analysis window and preferably repeated.

Next useful step: either run a 75 ms paced-CS16 patched-module replay with the
same 250 ms analysis from the start, or first build a small capture-placement
diagnostic that aligns PBCH/CSI windows against replay metadata time so the
window drift has a physical explanation before more RF.
