## Initial Smoke Failure

The first no-TX 65536-sample smoke found a real chunking bug:

```text
CHUNK index=0 request=32768 actual=32768 timestamp=13 flags=0x80000000 status=0x00030000
CHUNK_ERROR index=1 rc=-14 err=Requested timestamp is in the past request=32768
CHUNKS_OK=1
CHUNKS_ERROR=1
REQUESTED_SAMPLES=65536
WRITTEN_SAMPLES=32768
CAPTURE_OK=0
RUN_RC=1
```

Cause: after the first `BLADERF_META_FLAG_RX_NOW` call, the helper zeroed the
metadata struct for the second call and left `meta.timestamp=0`. libbladeRF
interpreted that as a requested timestamp in the past.

Fix: for chunks after the first one, set:

```text
meta.timestamp = last_ts + last_count
```

This requests the next contiguous receive block.

## Interpretation

CP1219 closes the timestamped capture harness smoke:

- full-capture-scale libbladeRF metadata RX must be chunked;
- subsequent chunks must request `last_timestamp + last_count`;
- the patched helper returns contiguous timestamps over multiple chunks;
- the CP1219 CP920-style harness is ready for a real RF replay trial.

This is still a no-TX smoke. It proves the capture machinery is ready, not that
the paced-CS16 RF comparison has been run.
