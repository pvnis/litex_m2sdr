## Goal

Replay CP1223's exact live same-window pre-DMA payload and metadata through the
known-good patched paced helper, then capture with the timestamped bladeRF RF
harness. The purpose was to isolate whether CP1223's live pre-DMA material and
metadata are intrinsically unreplayable, or whether the CP1223 live RF failure
sits later in the live gNB runtime / egress path.

This checkpoint used RF and SSH, but did not rebuild, use UE/Android, or run
PRACH.

## Interpretation

CP1225 proves that CP1223's exact live same-window pre-DMA CS16 payload and
metadata can produce decodable RF PBCH over the real LiteX TX to bladeRF RX
path when emitted by the corrected patched-module 75 ms paced helper.

This closes several repeat branches:

- CP1223 live pre-DMA payload content is not intrinsically invalid.
- CP1223 live pre-DMA metadata shape and exact row placement are not
  intrinsically unreplayable.
- CP1223's live same-window digital PBCH pass is not merely an offline decode
  artifact; the same pre-DMA material can drive a real RF PBCH pass.
- Repeating CP1220/CP1225-style paced replay just to show PBCH exists is not
  useful.

The checkpoint does not prove the live gNB runtime will work. CP1225 uses the
helper's 75 ms pacing and queueing, not the live gNB's real runtime cadence,
threading, post-DMA gap placement, or hardware-time relationship.

## Status

CP1225 is an RF pass and a boundary-tightening checkpoint. The failure is now
below or after valid live pre-DMA material entering the real live path:
live runtime cadence, actual DMA/gap scheduling, egress timing/format behavior,
or another live-only RF interaction.

The next useful branch is not another CP1225 repeat. It should preserve or
explain CP1223's live actual-DMA schedule/gaps more tightly, for example with a
minimal live-cadence replay or a stronger LiteX-to-bladeRF timing/egress
anchor.
