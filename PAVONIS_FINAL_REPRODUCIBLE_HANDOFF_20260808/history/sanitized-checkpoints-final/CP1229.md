# CHECKPOINT 1229: CP1228 full-span actual-DMA CF32 metadata replay RF pass

Date: [date-redacted] Europe/Zurich

## Goal

Convert the CP1228 `[date-redacted]`-row full-span actual-DMA dump into a replay-ready
CF32 metadata payload, then replay it through LiteX TX and capture it with the
timestamped bladeRF harness.

This directly tests the CP1228 open boundary: CP1228 proved the larger
actual-DMA dump reconstructs and decodes digitally, but paired live RF still
failed. CP1229 asks whether that full-span actual-DMA material itself can
produce RF PBCH when emitted by the controlled helper.

This checkpoint used RF and SSH for the replay run. It did not rebuild, use
UE/Android, or run PRACH.

## Interpretation

CP1229 proves that the CP1228 full-span actual-DMA ch0 material and its
observed `[date-redacted]`-row metadata/gap pattern are RF-replayable. The controlled
helper sends the same full-span reconstructed material over the LiteX TX to
bladeRF RX path and gets PBCH OK, a nontrivial aligned sweep pass, clean TX
counters, continuous bladeRF timestamps, and high reference correlation.

This closes the remaining content-oriented branch from CP1228. The CP1228 live
RF failure is not explained by:

- missing actual-DMA tail,
- invalid full-span actual-DMA samples,
- invalid full-span actual-DMA gap/timing pattern,
- inability of that full-span material to traverse LiteX TX to bladeRF RX, or
- bladeRF capture discontinuity.

The remaining live-only boundary is runtime egress behavior: the live gNB path
can generate DMA dump material that reconstructs and replays as valid RF PBCH,
but its paired live RF capture does not match that material. The next useful
branch should instrument or compare below the current dump boundary, especially
hardware-time scheduling, DMA submission/serialization, or live-vs-helper
device state around the exact transmit window.

## Status

CP1229 is an RF pass and advances the downlink isolation ladder. Do not repeat
the CP1228 full-span actual-DMA replay just to prove PBCH exists; repeat only
with a new variable, such as a live-vs-helper lower-driver trace or a hardware
state comparison that can explain why live egress differs from helper replay.
