## Conclusion

CP1230 partially closes and partially sharpens the CP1229 conclusion.

Closed: the CP1229 helper reaches the lower LiteX DMA dump boundary with the
same full-span row geometry, flags, timed headers, and gap schedule as the
CP1228 failing live run. A gross helper-vs-live DMA scheduling mismatch is not
the explanation.

Sharpened: CP1229 was not a bit-exact RF replay of the CP1228 ch0 DMA payload.
It replayed the same schedule and the same ch0 content after the LiteX CF32 TX
conversion path attenuated every nonzero component by one int16 count. Since
that slightly lower-amplitude helper payload still produced RF PBCH in CP1229,
the live failure is not explained by a need for larger sample magnitudes. But
the exact bit-level live DMA payload has still not been RF-replayed by the
helper path.

## Next Rung

The next useful lower-boundary checkpoint should avoid the native CF32
conversion path if bit-exactness matters. Good options:

1. Build a raw/serialized DMA-frame replay or injection helper and first prove
   its TX DMA dump is bit-exact against CP1228 before spending a bladeRF
   capture.
2. Alternatively, build a precompensated CF32 payload that yields the CP1228
   exact ch0 bytes after the driver's `[date-redacted]` truncation, then run a no-RF DMA
   dump proof before an RF replay.

Do not repeat CP1229 as evidence for bit-exact actual-DMA replay; CP1230 proves
it is schedule-exact but ch0 differs by this deterministic one-LSB conversion.
