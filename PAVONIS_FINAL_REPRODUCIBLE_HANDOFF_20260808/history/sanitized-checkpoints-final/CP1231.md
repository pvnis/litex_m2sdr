# CHECKPOINT 1231 - Precompensated CF32 bit-exact DMA-dump proof

Date: [date-redacted] Europe/Zurich

## Scope

CP1231 followed CP1230's finding that the native LiteX CF32 TX path converts
`CF32 -> DMA` as scale `[date-redacted]` with C-style truncation toward zero, pulling
every nonzero CP1228 ch0 component one int16 count toward zero.

This checkpoint built a precompensated CF32 payload, then reran the CP1230
[host-redacted]-only DMA-dump harness. No bladeRF capture, UE, Android, NRSA, PRACH, or
RF PBCH analysis was run.

Target proof:

```text
precompensated CF32 helper output == CP1228 live actual-DMA payload bytes
```

Absolute timed-header origins were still expected to differ because the helper
schedules against a fresh hardware-time base.

## Conclusion

CP1231 closes the CP1230 bit-exactness caveat at the no-RF lower-driver dump
boundary. The LiteX helper can be made to submit a CP1228-exact full-span DMA
payload and the exact CP1228 normalized DMA schedule through the existing CF32
Soapy path, as long as the CF32 vector is precompensated for the driver's
scale-`[date-redacted]` truncation.

This does not yet prove RF PBCH for the bit-exact payload, because no bladeRF
capture was taken in CP1231. It does prove the next RF rung can test the exact
CP1228 live actual-DMA payload without needing raw DMA-frame injection first.
