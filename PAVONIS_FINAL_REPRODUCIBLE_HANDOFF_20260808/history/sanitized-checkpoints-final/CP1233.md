## Live During vs Helper During

The infrastructure-level state matched in the places that would have pointed
to a gross routing or mode mismatch:

| State file | Diff result |
| --- | --- |
| `crossbar_reg.log` | exact |
| `litex_key_regs.log` | exact |
| `ad9361_port_dump.log` | exact |
| `ad9361_ensm_dump.log` | exact |

The state differed in:

| State file | Diff bytes | Meaningful diff lines |
| --- | ---: | ---: |
| `m2sdr_info.log` | `901` | `6` |
| `ad9361_dump.log` | `6762` | `152` |
| `ad9361_key_regs.log` | `776` | `4` |

The `m2sdr_info` differences were normal run-time differences: board time and
small temperature changes. Live had FPGA temperature `66.8 C` and AD9361
temperature `39.5 C`; helper had FPGA temperature `66.4 C` and AD9361
temperature `40.4 C`.

The decisive key-register diff was AD9361 TX attenuation:

```diff
-0x073 AD9361 reg 0x073: 0x0050
+0x073 AD9361 reg 0x073: 0x0014
 0x074 AD9361 reg 0x074: 0x0000
-0x075 AD9361 reg 0x075: 0x0050
+0x075 AD9361 reg 0x075: 0x0014
 0x076 AD9361 reg 0x076: 0x0000
```

Local source names these registers as:

- `REG_TX1_ATTEN_0` at `0x073`
- `REG_TX1_ATTEN_1` at `0x074`
- `REG_TX2_ATTEN_0` at `0x075`
- `REG_TX2_ATTEN_1` at `0x076`

The local AD9361 driver scales TX attenuation at `0.25 dB / LSB`. With the
high bytes at zero, this means:

- live gNB: `0x50 = 80 * 0.25 dB = 20 dB` TX attenuation
- helper replay: `0x14 = 20 * 0.25 dB = 5 dB` TX attenuation

This matches the known helper configuration used by the CP1232-class replay
(`TX_ATT_DB=5`) and the live gNB backoff/attenuation class
(`backoff20` / about `20 dB` attenuation).

The full AD9361 dump also showed additional differences, including early
registers such as `0x00c`, `0x00e`, `0x01e`, `0x01f`, digital attenuation
related registers `0x079`/`0x07a` and `0x07c`/`0x07d`, and small calibration
or correction differences around `0x08f`, `0x092`, `0x0a0`, `0x0a3`, and
`0x0a7`. CP1233 does not prove which of those are causal. The clearest
deliberate live/helper mismatch is TX attenuation.

## Interpretation

CP1233 proves live and helper state are not identical below the DMA dump
boundary. It also proves the mismatch is not a gross crossbar route, LiteX key
register, AD9361 port configuration, or AD9361 ENSM state difference.

The strongest new candidate is amplitude/state around TX attenuation:

- CP1232 helper replay was bit-exact to CP1228 live at the payload and
  normalized DMA schedule boundary, and it produced decodable RF PBCH at
  helper attenuation `5 dB`.
- CP1233 shows the live gNB state uses about `20 dB` TX attenuation while the
  helper state uses about `5 dB`.

This does not prove that the 15 dB attenuation delta explains the live PBCH
failure, because CP1233 did not take a paired bladeRF capture. It does make the
next rung concrete and cheap to interpret.

## Conclusion

Status: diagnostic pass.

The live-vs-helper lower-device state compare found a real state mismatch
after CP1232 had already closed payload, schedule, capture-continuity, and
bit-exact replay explanations. Crossbar, LiteX key registers, AD9361 port
configuration, and AD9361 ENSM matched. AD9361 TX attenuation did not match:
live was about `20 dB`, helper was about `5 dB`.

Next checkpoint should replay the CP1232 bit-exact full-span helper payload
with live-like TX attenuation, `TX_ATT_DB=20`, using the same timestamped
bladeRF capture and 250 ms off-center PBCH sweep. If that fails in the same
class as live, attenuation/amplitude/state becomes the leading cause. If it
still passes, the next branch should look beyond simple attenuation at the
remaining AD9361 differences, hardware-time/device lifetime, or serialized
live-only RF behavior.
