# Checkpoint 1238 - Live TX_BACKOFF10 `nr_cell_search_rf` at +3000 Hz sees only expected PCI 1

Date: [date-redacted]

## Purpose

CP1237 showed that `+[date-redacted] Hz` produced wrong-PCI ambiguity at the recovered
live `TX_BACKOFF=10` point. CP1238 repeated the same lower-level scanner rung
with only the scanner RF frequency offset changed to `+3000 Hz`, matching the
prior CP1119 best lower-level live setting.

## Setup

- Wrapper: `cp1238_run_live_nr_cell_search_rf_txbackoff10_foffp3000.sh`
- Underlying harness: `cp1237_run_live_nr_cell_search_rf_txbackoff10_foffp2000.sh`
- Stamp: `[date-redacted]TCP1238_LIVE_NRCELLSEARCHRF_TXBACKOFF10_RXG40_FOFFP3000`
- gNB TX backoff: `10`
- gNB env: patched LiteX Soapy module, `M2SDR_SOAPY_TX_CS16_TO_SC12=1`,
  `M2SDR_SOAPY_TX_TIME_OFFSET_NS=1000000`,
  `OCUDU_SOAPY_TX_SUPPRESS_EMPTY_EOB=1`
- Scanner: `nr_cell_search_rf`
- Scanner target SSB: `1839650000 Hz`
- Scanner sample rate: `5760000 sps`
- bladeRF RX gain: `40 dB`
- `rf.freq_offset`: `+3000 Hz`
- Scanner threshold: `-30 dB`

## Interpretation

CP1238 is a lower-level live NR cell-search pass. Combined with CP1236, the
recovered `TX_BACKOFF=10` live downlink now has:

- PBCH windows over bladeRF RF capture: pass at CP1236.
- Lower-level `nr_cell_search_rf` expected PCI: pass at CP1238.
- Best lower-level offset among CP1237/CP1238: `+3000 Hz`, not `+[date-redacted] Hz`.

The next rung is full `nr_sa_cell_search_test` at the same recovered live TX
point, RX gain 40, SSB-centered 5.76 Msps geometry, and `rf.freq_offset=+3000`.
Keep the trial budget short and hypothesis-driven because CP1121 already showed
long NRSA loops can overflow later without helping acquisition.
