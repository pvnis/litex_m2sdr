# CHECKPOINT 1249: UE Sync NR Post-Camping Trace Build

Date: [date-redacted]

## Goal

Prepare the next live NRSA rung after CP1248. CP1248 showed that
`TX_BACKOFF=5`, bladeRF RX gain `32`, and `rf.freq_offset=+3000 Hz` can reach
`CAMPING` while nearly eliminating RF overflow/gap symptoms, but still falls
out of sync about 200 ms later. CP1249 adds bounded visibility inside
`ue_sync_nr` so the next live run can explain the post-camping loss.

## Patch

Changed:

```text
srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c
```

New env-gated diagnostics:

```text
PAVONIS_SRSUE_UE_SYNC_NR_TRACE
PAVONIS_SRSUE_UE_SYNC_NR_TRACE_LIMIT
PAVONIS_SRSUE_UE_SYNC_NR_TRACE_PERIOD
```

When enabled, the trace prints bounded `PAVONIS_UE_SYNC_NR_TRACE` lines for:

- sync configuration entering FIND;
- FIND attempts, with sparse non-hit logging and mandatory PBCH-hit logging;
- `update_ssb()` CFO/delay/sample-offset updates and MIB/SFN state;
- every TRACK SSB opportunity, including PBCH CRC, miss counter before/after,
  drop-to-FIND decision, SNR/CFO/RSRP/EPRE/delay, and current tracker state;
- final zerocopy state transitions such as TRACK to FIND.

The default behavior is unchanged when the env var is unset.
