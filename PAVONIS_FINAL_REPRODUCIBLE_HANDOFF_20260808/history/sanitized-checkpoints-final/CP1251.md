# CHECKPOINT 1251: `ue_sync_nr` Absolute Delay Gate Build/Deploy

Date: [date-redacted] Europe/Zurich

## Goal

Add a minimal, opt-in diagnostic/guard around the CP1250
`ue_sync_nr_update_ssb()` delay gate. CP1250 showed that the legacy signed test
`delay_us < 2.4f` admits large negative delays into TRACK. CP1251 adds an
environment-gated absolute-delay mode for the next RF rung, while preserving
legacy behavior unless the new env var is enabled.

## Local Change

Changed file:

```text
srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c
```

New env controls:

```text
PAVONIS_SRSUE_UE_SYNC_NR_DELAY_ABS_GATE=1
PAVONIS_SRSUE_UE_SYNC_NR_DELAY_ABS_GATE_US=2.4
```

With the gate disabled, CP1250-compatible legacy behavior remains:

```text
measurements->delay_us < 2.4f
```

With the gate enabled, FIND-to-TRACK uses:

```text
fabsf(measurements->delay_us) < delay_abs_gate_us
```
