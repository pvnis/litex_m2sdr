## Interpretation

CP1259 does not support the narrow theory that the normal TRACK decoder is
missing a PBCH that a blind same-current-1ms-buffer search can decode. At all
20 TRACK opportunities:

```text
track_pbch_crc=0
same-1ms blind search_crc=0
```

So the failure is not explained by only TRACK-specific placement/context
inside a decodable 1 ms buffer.

The next software/RF boundary is sharper: why does FIND see PBCH-CRC-true hits
before and after camping, while the buffers presented at scheduled TRACK
opportunities are not blindly decodable in the current 1 ms window?

One important caveat remains. The sidecheck used `srsran_ssb_search()` on only
the same current 1 ms buffer. FIND uses a rolling SSB search path that can span
buffer history. Therefore CP1259 does not rule out a boundary-straddling or
rolling-tail issue where the SSB is not fully inside the current 1 ms buffer at
TRACK time. A good next rung is a sidecheck that mirrors FIND's rolling-buffer
logic, or an explicit 1 ms plus tail side capture, while preserving `sf_buffer`
state.

## Checkpoint Status

Result: **LIVE RF CAMPING THEN TRACK FAIL, SIDECHECK DISCRIMINATOR PASS**.

Reusable conclusion: at the CP1257/CP1259 live point, with `30 us` delay gating
and bad-delay feedback rejection, UE can still reach CAMPING. The post-camping
failure is 20 consecutive TRACK PBCH misses followed by TRACK-to-FIND, and the
new same-1ms sidecheck also fails on all 20 opportunities. This closes the
"TRACK decoder alone is wrong while the same 1 ms buffer is decodable" theory
as sufficient. Continue with rolling-buffer/boundary timing, sample-offset, CFO
feedback, or RF continuity diagnostics around TRACK opportunities.
