# Checkpoint 1260 - ue_sync_nr TRACK rolling-tail sidecheck build/deploy and live attempts

Date: [date-redacted] Europe/Zurich

## Goal

Test the next boundary after CP1259. CP1259 showed that normal TRACK PBCH
decode and a blind search on the same current 1 ms buffer both failed on every
TRACK opportunity. The next theory is that FIND succeeds because it searches a
rolling `previous_tail + current_1ms` buffer while TRACK only decodes inside
the current 1 ms buffer.

CP1260 therefore added a bounded opt-in rolling-tail TRACK sidecheck that
mirrors FIND's rolling-buffer geometry.

Edited:

- `srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c`

## Conclusion

CP1260 passed the software/instrumentation rung:

- rolling-tail sidecheck code builds locally
- the patched source deployed to `[host-redacted]`
- remote NRSA rebuilt successfully
- the remote binary contains the rolling-tail sidecheck strings
- the wrapper enables the expected env knobs

CP1260 did not test the rolling-tail TRACK hypothesis because neither live
attempt reached `CAMPING` or `TRACK`. Both attempts found expected PCI1, then
failed SFN synchronization. No `track_opportunity`, `track_sidecheck`, or
`track_rolling_sidecheck` events were emitted.

This is not evidence against the rolling-buffer/boundary theory. It is evidence
that the CP1259/CP1257 RF point is still variable enough that a run can fail at
SFN before reaching the post-camping TRACK discriminator.

Active frontier:

- obtain a live TRACK window with rolling sidecheck enabled
- keep the same RF point for at least one more rerun if time permits
- if repeated no-TRACK/SFN-fail continues, use a controlled gate/search-budget
  adjustment to force a TRACK window while preserving feedback-reject tracing
