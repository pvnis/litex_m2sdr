Date: [date-redacted] Europe/Zurich

## Goal

Test the CP1264 rolling-only boundary hit by adding an opt-in fallback that can
consume a rolling-tail blind-search hit when scheduled TRACK PBCH fails and the
same-current-1ms fallback is not available.

New env knobs:

```text
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_ROLLING_FALLBACK=1
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_ROLLING_FALLBACK_LIMIT=20
```

Default behavior is unchanged unless the env knob is enabled. Same-buffer
fallback remains first priority; rolling fallback is only considered second.

## Conclusion

CP1265 passed the software rung: the opt-in rolling fallback builds locally,
deploys to `[host-redacted]`, rebuilds remotely, and is active in the live wrapper.

The first live attempt did not test rolling fallback behavior because the UE
SFN-failed before CAMPING/TRACK. This mirrors CP1263, where the first
same-buffer fallback attempt also SFN-failed before TRACK and needed a same
point rerun. A same-point rerun is justified before changing the gate or adding
more code, because CP1264 reached TRACK at this RF point with the same `60 us`
gate.
