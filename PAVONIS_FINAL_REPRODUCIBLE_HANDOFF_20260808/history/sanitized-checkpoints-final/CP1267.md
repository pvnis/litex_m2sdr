# Checkpoint 1267: TRACK feedback-only fallback build/deploy and first live attempt

Date: [date-redacted] Europe/Zurich

## Goal

Test the CP1266 conclusion that blind fallback should apply only the blind-hit
CFO/delay feedback without letting blind PBCH MIB data reset the TRACK
timeline (`q->sfn`, `q->sf_idx`, or `ssb_idx`).

## Code Change

Added a default-off env-gated mode in
`srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c`:

```text
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_FALLBACK_FEEDBACK_ONLY=1
```

The compatibility alias
`PAVONIS_SRSUE_UE_SYNC_NR_TRACK_BLIND_FALLBACK_FEEDBACK_ONLY=1` is also
accepted. With the flag disabled, same-buffer and rolling fallback still call
`ue_sync_nr_update_ssb()` as in CP1266. With the flag enabled, a same-buffer or
rolling blind fallback hit resets `pbch_miss_count` and applies only
`srsran_csi_trs_measurements_t` feedback through `ue_sync_nr_apply_feedback()`;
it does not apply the fallback PBCH MIB to `q->sfn`, `q->sf_idx`, or
`ssb_idx`.

New trace fields/events include:

```text
track_fallback_feedback_only_enabled
fallback_feedback_only
feedback_only_fallbacks
track_fallback_feedback_only
state/sfn/sf_idx/ssb_idx before and after
fallback_mib_sfn logged but not applied
```

## Conclusion

CP1267 proves the feedback-only fallback mode builds, deploys, and is active in
the wrapper/binary, but the live behavior remains untested because this first
attempt SFN-failed before TRACK. There were zero TRACK opportunities and zero
fallback events.

This is the same pattern seen in CP1263 and CP1265, where the first live run
after adding a fallback SFN-failed before TRACK and the next same-point rerun
was needed to exercise the new behavior. The next checkpoint should rerun the
same CP1267 binary and RF point before changing the gate or code.
