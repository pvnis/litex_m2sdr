# Checkpoint 1273: SFN gate widened to 90 us still SFN-fails before TRACK

Date: [date-redacted] Europe/Zurich

## Goal

Test whether the CP1272 near miss at `+77.292381 us` was mainly caused by the
`60 us` absolute-delay SFN gate. This checkpoint changed only the live wrapper
control point by widening `PAVONIS_SRSUE_UE_SYNC_NR_DELAY_ABS_GATE_US` from
`60` to `90`.

No source or binary changed after CP1270. The CP1270 runner still labels some
outer sequence fields as `abs60`, but the uploaded CP1273 wrapper and NRSA log
confirm the active UE sync gate was `90 us`.


The earlier cell-search trace also saw five below-gate expected PCI1
PBCH-CRC-true candidates before the accepted trial, with best pre-acceptance
SNR `-14.878 dB`. The accepted trial itself was healthy at `+4.658 dB`.

## Conclusion

CP1273 weakens a simple "the `60 us` gate is too tight" explanation for the
current SFN failures. CP1272 had a `+77.292381 us` near miss that would have
passed a `90 us` gate, but CP1273 with the `90 us` gate active produced no SFN
`update_ssb` hits at all and still failed before CAMPING/TRACK.

Offset correction remains untested because no TRACK or fallback event occurred.
The first failed stage remains live SFN acquisition variability after a
healthy initial PCI1/PBCH acceptance. The next useful checkpoint should compare
SFN acquisition visibility directly, for example by rerunning a lower-level
scanner or a known-pass NRSA replay at the same software state before adding
more TRACK fallback code.
