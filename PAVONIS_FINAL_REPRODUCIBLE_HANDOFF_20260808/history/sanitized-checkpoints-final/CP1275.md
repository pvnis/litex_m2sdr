# Checkpoint 1275: Known-Pass Replay With Current Binary, No Abs-Gate Or Reject-Feedback

Date: [date-redacted] Europe/Zurich

## Goal

Isolate the CP1274 regression. CP1274 showed that the current CP1273
abs90/reject-feedback wrapper regressed the CP1129 known-pass LiteX TX to
bladeRF RX replay: initial PCI1/PBCH passed, but SFN failed because the
`90 us` absolute-delay gate rejected every PBCH-CRC-true SFN `update_ssb`.

CP1275 keeps the same recovered CP1129 replay vector, same LiteX TX path, same
bladeRF RX path, and same current NRSA real binary, but disables the absolute
delay gate and bad-delay feedback rejection in the wrapper.

## Interpretation

CP1275 isolates CP1274: the same current real binary and same LiteX TX to
bladeRF RX known-pass path can still synchronize SFN and enter `CAMPING` when
the absolute-delay gate and pre-feedback rejection are disabled.

Therefore CP1274's known-pass failure is a software policy regression in the
current wrapper gate/reject settings, not a broken current NRSA binary, not a
dead LiteX/bladeRF RF path, and not a failure of the recovered CP1129 replay
vector.

The legacy no-gate path is also not a clean final answer. It restores SFN and
camping by allowing large-delay feedback such as `-381.704 us`, which can move
`q_delay` and `sample_offset` aggressively and leaves post-camping tracking
unstable. The right next branch is a state-aware or phase-aware gate policy:
allow the acquisition path enough freedom to pass the known-good replay, while
still protecting post-camping TRACK feedback from clearly bad delay updates.

## Next Rung

Before more live RF, create and test a known-pass control that changes the
gate policy rather than simply disabling protection globally. The most useful
next experiment is one of:

- disable or relax the absolute delay gate only during FIND/SFN acquisition,
  while preserving stricter protection after CAMPING/TRACK starts;
- keep feedback rejection enabled only for post-camping TRACK updates, not for
  SFN acquisition hits needed to reach `CAMPING`;
- gate on delay relative to the selected/replay geometry instead of absolute
  raw `measurements->delay_us`.

The acceptance test for the next policy should be the CP1129 known-pass replay
first. Only after it restores SFN/CAMPING should the live CP1270-CP1273 RF
point be retried.
