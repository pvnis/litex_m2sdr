# CHECKPOINT 1276: Initial-Acquisition Delay-Gate Bypass Known-Pass Control

Date: [date-redacted] Europe/Zurich

## Goal

Close the CP1274-CP1275 wrapper-policy regression with a narrower default-off
policy than disabling the absolute delay gate entirely.

CP1274 proved that the current CP1273 `abs90 + reject-delay-feedback` wrapper
regressed the CP1129 known-pass replay: valid SFN PBCH hits near `-171 us`
were rejected, so known-pass no longer camped. CP1275 proved the same current
binary and same RF replay path could still camp when the absolute gate and
delay-feedback rejection were disabled, but that restored the unsafe legacy
large-delay behavior. CP1276 tests a middle policy:

- allow one initial non-TRACK acquisition hit to bypass the absolute delay
  gate;
- count the first transition into `TRACK`;
- after that first `TRACK` entry, keep rejecting later bad-delay FIND or
  reacquisition hits before feedback.

Edited:


```text

```

Added trace/state fields:

```text
initial_acq_delay_gate_bypass_enabled
initial_acq_delay_gate_bypass
initial_acq_delay_gate_bypasses
track_entries
```

Policy:

```text
initial_acq_delay_gate_bypass =
  abs_gate_enabled &&
  initial_acq_bypass_enabled &&
  previous_state != TRACK &&
  track_entries == 0 &&
  !abs_gate_pass
```

When the bypass is true, `track_gate_pass` is allowed for that first
acquisition hit. Once a non-TRACK state transitions into `TRACK`,
`track_entries` is incremented. Later non-TRACK bad-delay hits are no longer
initial acquisition and must pass the absolute gate or be rejected before
feedback.

## Conclusion

CP1276 closes the CP1274 known-pass regression with a narrower policy than the
CP1275 no-gate control:

- `abs90 + reject + initial-acq-bypass` passes known-pass SFN/CAMPING, although
  the bypass is not exercised because the first acquisition delay is already
  inside `90 us`;
- forced `abs1 + reject + initial-acq-bypass` passes known-pass SFN/CAMPING and
  directly exercises the bypass on a `-169.930695 us` initial hit;
- after the first `TRACK` entry, later FIND/reacquisition bad-delay hits are
  rejected before feedback with `track_entries=1`.

Post-camping remains unstable in both known-pass runs, so this checkpoint is
not a tracking fix. It is a gate-policy proof that the current binary can now
pass the CP1129 known-pass control without globally disabling delay protection.

Next justified rung: run the live CP1270/CP1273 RF point with the CP1276
`abs90 + reject + initial-acq-bypass` wrapper, keeping `TX_BACKOFF=5`, RX gain
`32`, `rf.freq_offset=+3000`, and `post_select_ttis=1000`. Interpret live
results only with the CP1276 known-pass control in hand.
