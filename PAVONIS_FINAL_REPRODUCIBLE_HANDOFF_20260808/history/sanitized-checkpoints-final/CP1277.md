## Goal

Run the live CP1270/CP1273 RF point with the CP1276 state-aware wrapper:

- `TX_BACKOFF=5`
- bladeRF RX gain `32`
- `rf.freq_offset=+3000 Hz`
- `PAVONIS_SRSUE_CELL_SEARCH_MAX_TRIALS=1000`
- `PAVONIS_SRSUE_POST_SELECT_TTIS=1000`
- absolute delay gate enabled at `90 us`
- bad-delay feedback rejection enabled
- one-shot initial-acquisition delay-gate bypass enabled

## Conclusion

CP1277 validates the CP1276 state-aware initial-acquisition bypass on live RF.
The live run found expected PCI1, synchronized SFN, and entered `CAMPING` by
using exactly one initial-acquisition bypass on a `+111.360207 us` FIND-to-TRACK
hit that would otherwise have failed the `90 us` absolute gate. After that,
the protection re-engaged: later bad-delay FIND hits were rejected before
feedback unless they were inside the gate.

This closes CP1273's live SFN failure for this run as a software-policy
contaminated failure: the blunt `abs90 + reject` wrapper could block the
initial acquisition hit, while the CP1276 one-shot bypass admits it.

The remaining active blocker is post-camping scheduled TRACK. Scheduled TRACK
PBCH stayed `0/72`, while blind same-buffer and rolling sidechecks found
occasional CRC-valid SSBs and both feedback-only offset-correction paths were
exercised. The next rung should stop treating "can we get to CAMPING?" as the
main question and instead isolate scheduled TRACK offset/timeline handling
after a bypass-admitted live acquisition, especially how corrected
`next_rf_offset`/`q_delay` should feed the selected TRACK offset instead of
leaving scheduled TRACK pinned to failing `selected_sf_offset=825`.
