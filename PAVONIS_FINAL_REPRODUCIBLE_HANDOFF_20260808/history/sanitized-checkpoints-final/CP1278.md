## Goal

Continue from CP1277 without changing the RF point:

- `TX_BACKOFF=5`
- bladeRF RX gain `32`
- `rf.freq_offset=+3000 Hz`
- `PAVONIS_SRSUE_CELL_SEARCH_MAX_TRIALS=1000`
- `post_select_ttis=1000`
- absolute delay gate enabled at `90 us`
- bad-delay feedback rejection enabled
- one-shot initial-acquisition delay-gate bypass enabled
- same-buffer/rolling sidechecks and feedback-only offset correction enabled

CP1278 tests two narrow questions:

1. Does increasing the TRACK miss limit prevent the 20-miss
   TRACK-to-FIND drops from hiding later scheduled TRACK recovery?
2. When fallback offset correction sets `next_rf_offset`, is that sample
   offset actually consumed before later scheduled TRACK opportunities?

## Conclusion

CP1278 validates the CP1278 diagnostic rung and changes the active frontier:

- Live initial acquisition still reaches PCI1/SFN/CAMPING with the CP1276
  initial-acquisition bypass.
- Increasing the miss limit to 100 prevents the old 20-miss TRACK-to-FIND
  reset, but scheduled TRACK still has `0/79` PBCH CRC.
- Same-current-1ms blind search still finds occasional CRC-valid SSBs far from
  the scheduled `selected_sf_offset=825`.
- Feedback-only offset correction computes large `next_rf_offset` changes and
  `ue_sync_nr_recv()` consumes them before later scheduled TRACK opportunities.
- Consumed stream-level offset correction does not make scheduled TRACK land
  on the SSB.

Next frontier: stop testing whether `next_rf_offset` is consumed. It is. The
next rung should directly isolate scheduled TRACK's decode anchor: either
instrument/decode `srsran_ssb_track()` at the blind-hit offset as an opt-in
diagnostic, or add an opt-in selected-offset override/follow mode to test
whether TRACK succeeds when its fixed candidate offset is moved from `825` to
the most recent blind-search offset. Keep Android/attach/PRACH out of scope
until independent downlink NRSA post-camping TRACK is stable.
