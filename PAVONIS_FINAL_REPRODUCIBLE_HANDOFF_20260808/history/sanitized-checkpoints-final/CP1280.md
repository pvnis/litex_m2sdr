# Checkpoint 1280 - Live TRACK Offset Follow And Immediate Override

Date: [date-redacted] Europe/Zurich

## Goal

Test the CP1279 frontier hypothesis: scheduled TRACK was failing because it
kept using the stale `selected_sf_offset=825`, while the TRACK decoder could
decode PBCH when called directly at blind-search offsets. CP1280 adds an
opt-in selected-offset follow/override path and reruns the same live RF point.

## RF Point

- gNB: LiteX/M2SDR live TX from `[host-redacted]`
- UE/RX: bladeRF on `[host-redacted]`
- Wrapper policy: CP1279 policy plus initial-acquisition bypass, abs90 gate,
  reject-feedback, feedback-only fallback offset correction, direct offset
  check, and new offset-follow gates
- `TX_BACKOFF=5`
- `NRSA_RX_GAIN_DB=32`
- `NRSA_RF_FREQ_OFFSET_HZ=3000`
- `max_trials=1000`
- `post_select_ttis=1000`
- Duration/timeout: 5000 ms / 180 s

## Source Change

`srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c` now has default-off selected-offset
follow diagnostics:

- `PAVONIS_SRSUE_UE_SYNC_NR_TRACK_OFFSET_FOLLOW`
- `PAVONIS_SRSUE_UE_SYNC_NR_TRACK_OFFSET_FOLLOW_LIMIT`
- `PAVONIS_SRSUE_UE_SYNC_NR_TRACK_OFFSET_FOLLOW_TTL`

Two mechanisms were tested:

- Stored follow: after a direct PBCH-valid blind offset, try the remembered
  offset on later TRACK opportunities.
- Immediate override: if the scheduled TRACK call misses but a same-opportunity
  direct blind-offset TRACK call passes CRC, promote that direct result into the
  normal TRACK result and run `update_ssb()`.

## Key Observations

The important split is that stored follow failed, while same-opportunity
immediate override worked.

Stored follow attempted the last validated offset on later opportunities and
was `0/58` for PBCH CRC. It tried offsets such as `1017`, `3125`, `1074`, and
`332` after direct hits, but none decoded when reused later.

Immediate override produced all four TRACK PBCH hits:

```text

opp 56: direct offset 3125, selected 825, delta +2300, direct snr -5.233, scheduled crc 0, override 1
opp 75: direct offset 1074, selected 825, delta +249, direct snr -22.535, scheduled crc 0, override 1
opp 93: direct offset 332, selected 825, delta -493, direct snr -16.704, scheduled crc 0, override 1
```

Two preexisting rolling feedback-only recoveries also fired:

```text

opp 39: rolling hit search_current_offset=-23, selected 825, delta -848, boundary crossing
```

## Interpretation

CP1280 closes the simple "remember the last good blind offset" theory at this
RF point. A single stored offset is not temporally stable enough: stored follow
was `0/58`.

CP1280 also proves that direct blind-offset TRACK results can be promoted into
normal TRACK hits and `update_ssb()` calls. Scheduled TRACK at the static
selected offset still misses, but the same opportunity can decode when the
decoder is pointed at the currently visible blind-search offset.

The next frontier is not another static selected-offset follow rung. It should
be a per-opportunity adaptive TRACK anchor or timing model: use same-current
and rolling blind/direct evidence as the active TRACK input, or redesign how
the selected offset is derived before each scheduled TRACK call.
