# Checkpoint 1283: direct-offset primary TRACK live run

Date: [date-redacted] Europe/Zurich

## Goal

CP1282 proved that same-opportunity direct blind-offset TRACK promotion still
creates normal TRACK PBCH hits when every fallback action is disabled. CP1283
tests the next rung: make that direct blind-offset decode primary before the
static scheduled `srsran_ssb_track()` call, while keeping direct override,
stored offset follow, and every fallback action disabled.

## Code Change

Edited:

```text
srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c
```

New default-off control:

```text
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_DIRECT_OFFSET_PRIMARY=1
```

When enabled, TRACK runs the existing sidecheck/rolling/direct-offset
diagnostics before the scheduled static-offset TRACK decoder. If a direct
same-current or rolling-current decode returns PBCH CRC true, it is applied as
the TRACK result immediately and the scheduled decoder is skipped for that
opportunity. If no direct decode is valid, the existing scheduled path runs.

## Interpretation

PASS for the CP1283 mechanism. A current blind-offset decode can be the primary
TRACK result before the scheduled static-offset decoder runs. This is no longer
a post-scheduled override or fallback-action reset: direct override, stored
offset follow, blind fallback, rolling fallback, feedback-only fallback, and
offset correction were all disabled.

The remaining failure is stability, not decode capability. Direct-primary hits
were sparse (`5/77` opportunities), and non-primary opportunities still missed
after falling back to the static scheduled TRACK path. Also, `ue_sync_nr_update_ssb`
only feeds the residual direct measurement delay into `next_rf_sample_offset`;
it does not make the large absolute blind-offset delta the next primary timing
anchor. The next useful rung is to turn the observed direct/sidecheck offset
into a timing model or receive/candidate anchor for following opportunities,
rather than only accepting one current-buffer PBCH hit at a time.
