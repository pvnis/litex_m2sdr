# Checkpoint 1284: direct-primary timing correction live run

Date: [date-redacted] Europe/Zurich

## Goal

CP1283 proved that a current blind-offset decode can serve as the primary
TRACK result before the scheduled static-offset decoder runs, but those hits
were sparse. CP1284 tests the next rung: after a direct-primary TRACK hit,
apply the large direct offset delta to `q->next_rf_sample_offset` so the next
receive adjustment uses that blind-offset evidence as forward timing feedback.

## Code Change

Edited:

```text
srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c
```

New default-off controls:

```text
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_DIRECT_OFFSET_PRIMARY_TIMING_CORRECT=1
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_DIRECT_OFFSET_PRIMARY_TIMING_CORRECT_MAX_SAMPLES=6000
```

When a direct-primary TRACK hit is applied and `ue_sync_nr_update_ssb()`
succeeds, the new path computes:

```text
corrected_next_rf_offset = feedback_next_rf_offset + (direct_current_offset - selected_sf_offset)
```

If the corrected offset is within the configured sample limit and within the
subframe size, it updates `q->next_rf_sample_offset` and `q->avg_delay_us`.
The next TRACK receive call then consumes that correction through the normal
`recv_adjust` path. The feature emits
`event=track_direct_offset_primary_timing_correct`.

## Interpretation

PASS for implementation and execution of the CP1284 mechanism. Direct-primary
timing correction deployed cleanly, applied exactly twice, stayed within its
bounds, and both corrections were consumed through normal `recv_adjust`.

FAIL for the hypothesis that naive direct-delta receive realignment is enough
to recover scheduled TRACK. Scheduled TRACK still produced zero PBCH hits, and
overall direct-primary hit rate fell to `2/72` in this run versus CP1283's
`5/77` at the same RF point. RF stress was present, but the important result
is internal: even after the large corrected offsets were consumed, the static
scheduled TRACK anchor at `selected_sf_offset=825` did not recover.

This closes the simple "direct offset delta plus residual feedback into
`next_rf_sample_offset`" rung as sufficient. The next useful rung should test
candidate-anchor or scheduler semantics directly: make the candidate offset or
candidate set active for the scheduled TRACK decode in the same opportunity, or
trace the predicted selected offset after `recv_adjust` against the next blind
offset to determine whether the current anchor has the wrong sign, phase, or
state-machine owner.
