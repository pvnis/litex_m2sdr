# Checkpoint 1289 - Candidate-Anchor Set Fresh-Evidence Scheduler

Date: [date-redacted] Europe/Zurich

## Goal

CP1288 proved that a single stale candidate-anchor offset with TTL is not a
useful forward scheduler: one fresh same-current candidate hit updated TRACK,
but the next 20 carried-offset attempts all missed. CP1289 tests the next
semantics rung: a small default-off candidate-anchor set that stores recent
direct-offset CRC hits, prefers fresh candidates in the current TRACK
opportunity, and ages stale slots by TTL.

The isolation policy stayed strict: direct-primary, direct override, stored
offset follow, single candidate-anchor, stateful candidate-anchor, and all
fallback actions were disabled. Sidechecks and direct offset checks remained
diagnostic input.

## Implementation

`srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c` was extended with:

```text
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_CANDIDATE_ANCHOR_SET
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_CANDIDATE_ANCHOR_SET_CAPACITY
PAVONIS_SRSUE_UE_SYNC_NR_TRACK_CANDIDATE_ANCHOR_SET_TTL
```

Default values are capacity `4`, TTL `20`, maximum compiled slots `8`. The
candidate set stores current-buffer direct-offset CRC hits from same-current
or rolling-current direct checks, prefers slots refreshed in the current
opportunity, and logs update/attempt/expiry counters into the existing
`track_opportunity` trace.

## Conclusion

CP1289 is a positive result for fresh same-current evidence and a negative
result for stale candidate reuse.

Compared with CP1288's single immediate hit plus `0/20` stateful reuse,
CP1289 produced six normal TRACK PBCH hits with direct-primary, direct
override, follow, single-anchor, stateful-anchor, and fallback actions all
disabled. The useful path was not the stale set itself; every successful
candidate-set application came from a slot refreshed in that same TRACK
opportunity.

Static scheduled TRACK at selected offset `825` remains the wrong anchor, and
reusing old offsets for TTL windows mostly adds miss work. However, the
post-CP1289 gate is no longer another scheduler edit. The raw scheduled-TRACK
downlink metric across CP1283, CP1288, and CP1289 remains sub-threshold: a
strict extraction of `event=track_opportunity` lines with usable `meas_snr=`
fields gives `238` opportunities, mean `-21.156 dB`, and only `5/238`
(`2.10%`) at or above `-10 dB`. This is consistent with the broader working
summary of roughly `-20 dB` mean and only a small usable fraction.

Until the live downlink budget is raised, stop editing `ue_sync_nr.c`
sync/anchor scheduler logic. Future work should gate on improving the raw
TRACK-opportunity SNR and the fraction of opportunities at or above `-10 dB`;
otherwise offset-scheduler changes are mostly selecting sub-threshold windows.
Do not rerun CP1289 unchanged as the next main experiment.
