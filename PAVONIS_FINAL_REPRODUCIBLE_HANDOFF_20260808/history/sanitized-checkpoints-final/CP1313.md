# Checkpoint 1313 - TX_BACKOFF10 Independent bladeRF Raw-DL Capture At CP1311 Geometry

Date: [date-redacted] Europe/Zurich

## Goal

CP1311 measured the scheduled srsUE TRACK gate at the historical
known-baseline-class point:

```text
TX_BACKOFF=10
srsUE RX gain=20
NRSA freq_dl=1842500000
target SSB=1839650000
sample rate=11520000
bladeRF RX bandwidth=10000000
rf.freq_offset=0
```

It reached CAMPING/TRACK but stayed below the raw gate:

```text
56 TRACK opportunities
0 PBCH hits
mean meas_snr=-22.051 dB
0/56 opportunities >= -10 dB
1/56 opportunities >= -15 dB
```

CP1313 runs an independent live bladeRF metadata capture at the same
carrier-centered live gNB TX point, without UE attach, Android, PRACH, or any
`ue_sync_nr.c` sync/anchor scheduler edit. The purpose is to distinguish "no
external downlink exists at this point" from "srsUE scheduled TRACK windows are
still sub-threshold."

## Method

No source code was changed. A thin wrapper was added:

```text
cp1313_run_live_bladerf_rawdl_capture_cp1311_exact_txbackoff10_capg20.sh
```

The wrapper reuses the CP1223/CP1298 live timestamped full-geometry bladeRF
capture harness and treats the already-known missing timed-DMA reconstruction
helper as optional only after all primary capture and RF/PBCH analyses pass.

Run settings:


Important caveat: the bladeRF helper was asked for gain `20`, but bladeRF-cli
read back:

```text

```

This matches the CP1298 helper/readback behavior. CP1313 is therefore an
independent bladeRF capture pass at requested gain `20`, but the effective
helper readback is the high-gain `overall=60/full=71` class. It is not a
like-for-like proof that srsUE RX gain `20` and the helper path use the same
gain.

## Interpretation

CP1313 is an independent external-path raw-DL capture pass, not a ladder
advance.

At the exact CP1311 carrier-centered TX point, the gNB TX dump contains
decodable PBCH, the bladeRF capture is continuous/unclipped, one-shot PBCH is
OK at CSI SNR `+2.0 dB`, and the sweep finds `44/847` PBCH CRC OK PCI1
windows. This rules out a broad "there is no live external downlink at the
CP1311 point" explanation.

It does not raise the active srsUE scheduled TRACK gate. CP1311 remains the
active scheduled-TRACK metric for this RF point: mean `-22.051 dB`, `0/56 >=
-10 dB`.

The helper gain readback is the key caveat. Although CP1313 requested capture
gain `20`, bladeRF-cli reported `overall=60/full=71`. Therefore CP1313 should
motivate a like-for-like scheduled-TRACK probe at the same CP1311
carrier-centered point with srsUE RX gain `60`, 11.52 Msps, forced 10 MHz RX
bandwidth, and `rf.freq_offset=0`. If that still stays near `-22 dB`, the gap
is not explained by the capture-helper high-gain class and further work should
focus on srsUE/bladeRF receive-path measurement semantics or current-buffer
diagnostics without editing `ue_sync_nr.c` sync/anchor scheduler logic.
