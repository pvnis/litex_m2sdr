# Checkpoint 1326: offline PBCH analysis of CP1325 default-RX_NOW srsUE dump

Date: [date-redacted] Europe/Zurich

## Purpose

CP1326 is an offline-only checkpoint on the CP1325 raw srsUE bladeRF RX dump.
It uses no RF transmit airtime and makes no `ue_sync_nr.c` sync/anchor edits.

The question was whether CP1325's default-`RX_NOW` raw receive buffer contains
offline-decodable PBCH windows, even though the live scheduled TRACK metric in
CP1325 remained below gate:

```text
track_opportunities=78
pbch_crc1=0
mean_snr=-21.551282
max_snr=-13.318000
ge_minus10=0/78
```

## Method

1. Extracted the CP1325 dump locally under:

   ```text
   cp1326_cp1325_rxnow_dump_offline_pbch_[date-redacted]/
   ```

2. Ran the existing `cp812_ssb_file_test_one_capture.py` wrapper on the first
   `5760000` complex samples, i.e. the first 500 ms at `11.52 Msps`.

3. Ran the existing `cp814_ssb_file_aligned_window_sweep.py` wrapper on the
   first 250 ms of the full dump.

4. Located the first live CP1325 TRACK opportunity near the 250 ms point:
   `cell_select_done` was logged with last RX debug call `241`, and
   `track_opportunity opportunity=1` was logged with last RX debug call `252`
   at timestamp `3179387`. Relative to the first RX timestamp `298223`, that
   is about `0.250 s`.

5. Created a 250 ms TRACK-era slice starting at sample `2880000`:

   ```text
   cp1325_srsue_rxnow_rx_dump_tracktail_250ms.sc16
   ```

   Hash:


6. Ran the same CP814 aligned-window sweep on that TRACK-era slice.

## Interpretation

CP1326 proves the CP1325 srsUE default-`RX_NOW` raw dump contains
offline-decodable PBCH windows, including in the first TRACK-era 250 ms slice.
This weakens the idea that the srsUE raw receive buffer is simply missing the
LiteX downlink or that the independent bladeRF helper is the only path that can
see PBCH.

It does not unlock the ladder. The live scheduled TRACK metric from CP1325 is
still the active gate and still failed: mean `-21.551 dB`, `0/78 >= -10 dB`,
and `0` TRACK PBCH hits. CP1326 instead narrows the discrepancy: useful PBCH
energy exists in the raw receive dump, but the scheduled TRACK opportunities
being scored by srsUE remain sub-threshold.

Every offline window also hit component max `[date-redacted]`, and every sweep window had
at least one near-clip sample. That makes RX overdrive/clipping a plausible
next RF/link-budget hypothesis. A next live raw-gate checkpoint should test a
lower srsUE RX gain at the same `TX_BACKOFF=3`, carrier-centered `11.52 Msps`,
forced `10 MHz`, `foff=0` point, while still avoiding `ue_sync_nr.c`
sync/anchor edits and still judging by scheduled TRACK mean SNR and
`>= -10 dB` fraction.
