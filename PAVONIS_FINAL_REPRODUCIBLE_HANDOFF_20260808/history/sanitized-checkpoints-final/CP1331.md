## Purpose

CP1331 repeats the CP1329 raw scheduled-TRACK RF point with the bounded
`rf_blade_recv_with_time()` RX dump enabled. This is not a scheduler/anchor
change and does not edit `ue_sync_nr.c`. The point is:

```text
TX_BACKOFF=3
srsUE RX gain=32
freq_dl=1839650000
target_ssb=1839650000
srate=5760000
rf.freq_offset=+3000
no forced bladeRF RX bandwidth override
post_select_ttis=1000
max_trials=1000
```

The gate remains the raw live scheduled TRACK metric: mean
`event=track_opportunity meas_snr` and the fraction of opportunities
`>= -10 dB`.

## Interpretation

CP1331 is not a raw scheduled-TRACK gate pass. The gate remains blocked at
mean `-22.562 dB`, `0/73 >= -10 dB`, and zero TRACK PBCH hits.

It does, however, sharpen the failure: at the exact CP1329 SSB-centered raw
point, the srsUE bladeRF receive dump itself contains offline-decodable PBCH,
including a strong tail-250 ms decode with CSI SNR `+7.0 dB`, while remaining
unclipped. The problem is therefore not simply "the srsUE RF dump has no
downlink energy" and not RX overdrive/clipping at this point. The next work
should stay below the ladder gate but pivot from TX/RX power sweeps to
receive-buffer/timing semantics: explain why scheduled TRACK windows report
about `-22 dB` and zero PBCH while the bounded dump from the same receive path
contains decodable PBCH.
