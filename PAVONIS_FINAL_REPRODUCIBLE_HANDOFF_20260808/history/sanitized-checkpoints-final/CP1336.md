## Purpose

Test whether forcing the srsUE bladeRF RX bandwidth to the harness-recommended
SSB-centered `5.6 MHz` setting raises the live scheduled TRACK raw downlink
metric at the best local SSB-centered point from CP1334.

This checkpoint keeps the current gate:

- mean `event=track_opportunity meas_snr`
- fraction of TRACK opportunities with `meas_snr >= -10 dB`

No `ue_sync_nr.c` sync/anchor logic is changed, and no PRACH/Android/NAS
ladder movement is allowed before the raw gate improves.

## Env Propagation Miss

CP1336 does not close the forced-RX-bandwidth hypothesis because the intended
override did not reach the active srsUE RF process.

The sequence log recorded the intended variable:

```text
forced_rx_bw_hz=5600000
```

The plugin binary verify log contains the `PAVONIS_RF_BLADE_RX_BW_HZ` symbol,
so the deployed RF plugin is capable of reading the variable.

However, the active RF readback in the srsUE NRSA log still reports the default
bandwidth and says the override is disabled:

```text
set_rx_srate requested=5760000 actual=5760000 requested_bw=4608000 bw=4608000 rx_bw_override=0 status=0
set_rx_freq requested=1839653500 actual=1839653498 status=0
set_rx_gain requested=32.000 actual=32.000 status=0
start_rx_stream_gain rx_requested=32.000 rx_actual=32.000
```

Treat CP1336 as a valid clean repeat of the CP1334-like no-forced-BW RF point,
but as an invalid test of `PAVONIS_RF_BLADE_RX_BW_HZ=5600000`. A proper forced
RX bandwidth checkpoint needs to export `PAVONIS_RF_BLADE_RX_BW_HZ=5600000`
inside the remote srsUE wrapper immediately before launching the real NRSA
process.

## Verdict

CP1336 is below the raw scheduled-TRACK downlink gate and does not close the
forced-RX-bandwidth theory. The run stayed clean and reached TRACK, but the RF
plugin readback remained `requested_bw=4608000 bw=4608000 rx_bw_override=0`;
therefore the intended `5.6 MHz` RX bandwidth was not actually applied. The
next raw-only checkpoint should rerun this exact SSB-centered point with the
bandwidth variable exported inside the remote srsUE wrapper and should require
active readback `requested_bw=5600000` or `bw=5600000` before interpreting the
TRACK SNR metric.
