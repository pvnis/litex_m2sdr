# Checkpoint CP1340 - CP1332 TRACK Exact-Window Search Probe

Date: [date-redacted] Europe/Zurich

## Purpose

Use the existing CP1332 srsUE `RX_NOW` dump to compare live scheduled TRACK
opportunity timing against offline PBCH-searchable windows. This is an offline
analysis checkpoint only: no RF run, no source edits, and no `ue_sync_nr.c`
sync/anchor changes.

The active live gate remains the raw scheduled TRACK metric: mean
`event=track_opportunity meas_snr` and the fraction of opportunities
`>= -10 dB`. CP1340 does not itself raise that live metric.

## Method

The script reconstructs RF-call raw sample starts from CP1332 dump metadata and
uses the CP1332 trace's established mapping:

```text
TRACK opportunity N -> previous RX call 441 + 10 * (N - 1)
```

It tests opportunities `48..72`, the live TRACK range overlapping the CP1332
tail slice where aligned offline sweeps found PBCH-OK windows. For each
opportunity it runs `ssb_file_test` on five crop modes:

- `call_start_1ms`
- `call_start_2ms`
- `call_start_5ms`
- `static_offset_2ms`, starting at `call_start + selected_sf_offset`
- `static_offset_5ms`, starting at `call_start + selected_sf_offset`

The live static scheduled offset is `selected_sf_offset=825` samples.

## Limitation

CP1340 uses `ssb_file_test`, which searches inside each crop. It proves that
PBCH is offline-searchable near some live TRACK opportunities, but it does not
by itself prove that the live static primitive,
`srsran_ssb_track_at_offset(..., t_offset=825)`, would decode those same
windows.

## Verdict

CP1340 does not unlock the ladder and does not raise the live scheduled TRACK
gate. It does show that the CP1332 TRACK-era dump contains PBCH-searchable
samples near several live TRACK opportunities, often hundreds of microseconds
to several milliseconds away from the live static `825`-sample offset. The
next diagnostic should directly test `srsran_ssb_track_at_offset()` on the
same CP1332 windows before any more RF sweeps.
