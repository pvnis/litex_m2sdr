# Checkpoint 1351 - SSB-Centered 1580 us gNB TX Time-Offset Probe

Date: [date-redacted] Europe/Zurich

## Goal

CP1350 tested the nearest CP1340/CP1341 timing-alignment hypothesis by
reducing `M2SDR_SOAPY_TX_TIME_OFFSET_NS` from `1000000 ns` to `420000 ns`.
That did not raise the live scheduled TRACK gate. CP1351 tests the opposite
sign around the same `580 us` delta by increasing the gNB timed TX release
offset to `1580000 ns`.

The RF point is unchanged from CP1350 and the best local SSB-centered baseline:
`TX_BACKOFF=3`, RX gain `32`, `5.76 Msps`, default RX bandwidth, and
`rf.freq_offset=+3500 Hz`.

This is a raw-gate checkpoint only. It does not edit `ue_sync_nr.c`
sync/anchor logic and does not move to PRACH, Android, or NAS.

## Verdict

CP1351 does not raise the raw scheduled downlink gate. Increasing
`M2SDR_SOAPY_TX_TIME_OFFSET_NS` from `1000000 ns` to `1580000 ns` at the
best local SSB-centered RF point improves the mean relative to CP1350 but
still gives only mean `-21.404 dB`, with `0/83 >= -10 dB`,
`3/83 >= -15 dB`, and zero TRACK PBCH hits.

Because the run also has one worker-side late-count caveat, CP1351 is a
no-unlock timing-direction result rather than a clean timing fix. The active
ladder gate remains unchanged: no more `ue_sync_nr.c` sync/anchor edits and no
PRACH/Android/NAS work until a live scheduled TRACK run raises mean TRACK SNR
and the `>= -10 dB` opportunity fraction.
