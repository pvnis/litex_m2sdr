# Checkpoint 1352 - SSB-Centered 5263 us gNB TX Time-Offset Probe

Date: [date-redacted] Europe/Zurich

## Goal

CP1350 and CP1351 tested the simple `+/-580 us` live gNB timed-TX offset
pair suggested by the first CP1340/CP1341 alternate TRACK offset. Both failed
the live scheduled TRACK gate. CP1352 tests the largest high-SNR CP1341
alternate offset instead: opportunity 69 had a direct offline
`srsran_ssb_track_at_offset()` decode at `+4263.2 us` from the live static
window with direct TRACK SNR `+1.2 dB`.

The live knob tested here is therefore:

```text
default M2SDR_SOAPY_TX_TIME_OFFSET_NS=1000000
plus CP1341 alternate delta=4263200
tested M2SDR_SOAPY_TX_TIME_OFFSET_NS=5263200
```

The RF point is unchanged from the best local SSB-centered baseline:
`TX_BACKOFF=3`, RX gain `32`, `5.76 Msps`, default RX bandwidth, and
`rf.freq_offset=+3500 Hz`.

This is a raw-gate checkpoint only. It does not edit `ue_sync_nr.c`
sync/anchor logic and does not move to PRACH, Android, or NAS.

## Verdict

CP1352 does not raise the raw scheduled downlink gate. The large
`M2SDR_SOAPY_TX_TIME_OFFSET_NS=5263200` probe produced one above-threshold
single row at `-5.935 dB`, but the gate metric remained essentially CP1351
class: mean `-21.412 dB`, only `1/73 >= -10 dB`, only `2/73 >= -15 dB`, and
zero TRACK PBCH hits.

Because the run reached TRACK and the gNB counters were clean, CP1352 closes
the largest/highest-SNR CP1341 alternate offset as a live gNB TX time-offset
raw-gate fix. The active ladder gate remains unchanged: no more `ue_sync_nr.c`
sync/anchor edits and no PRACH/Android/NAS work until a live scheduled TRACK
run raises mean TRACK SNR and the `>= -10 dB` opportunity fraction.
