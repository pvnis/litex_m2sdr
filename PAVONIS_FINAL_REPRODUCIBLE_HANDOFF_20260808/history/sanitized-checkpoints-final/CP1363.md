# CHECKPOINT 1363: No-RF live gNB native-CF32 feasibility audit

Date: [date-redacted] Europe/Zurich

## Goal

Answer the new theory: can the live gNB emit native CF32 instead of going
through the current CI16/CS16 path, and is the conversion/downsample path a
plausible explanation for the low scheduled TRACK SNR?

This checkpoint used local source inspection only. It did not run RF, SSH,
PRACH, Android, NAS, or source edits.

## Findings

The live OCUDU/M2SDR gNB path does not expose a YAML-only CF32 switch:

- `ocudu/include/ocudu/radio/radio_configuration.h:70` defines OTW formats as
  `DEFAULT`, `SC16`, `SC12`, and `SC8`; there is no `CF32` enum value.
- `ocudu/include/ocudu/radio/radio_configuration.h:140` parses only `sc8`,
  `sc12`, `sc16`, and `default`.
- `ocudu/lib/radio/soapy/radio_config_soapy_validator.cpp:133` documents and
  enforces the M2SDR Soapy config as default/SC16 only.
- `ocudu/lib/radio/soapy/radio_soapy_device.h:141` hardcodes
  `device->setupStream(direction, SOAPY_SDR_CS16, ...)` for the OCUDU Soapy
  stream wrapper, so even `otw_format: default` does not currently select the
  M2SDR plugin's advertised CF32 stream format.

The live baseband buffer type is also CI16:

- `ocudu/include/ocudu/gateways/baseband/buffer/baseband_gateway_buffer_reader.h:29`
  returns `span<const ci16_t>`.
- `radio_soapy_tx_stream.cpp` passes those channel spans directly to
  `writeStream()`.

The M2SDR Soapy plugin does support a CF32 stream API, but CF32 is still
converted before reaching the AD9361/DMA sample lane:

- `LiteXM2SDRStreaming.cpp:1697` implements `interleaveCF32()` by scaling float
  I/Q into integer samples.
- `LiteXM2SDRStreaming.cpp:1762` implements the existing CS16 path, including
  the optional `M2SDR_SOAPY_TX_CS16_TO_SC12` conversion at lines 1773-1778.

Historical controls already show that CF32 helper replay through M2SDR is
viable:

- CP1227 replayed captured actual-DMA material through native Soapy CF32 and
  got one-shot PBCH CRC OK plus `66/847` sweep PBCH-OK windows.
- CP1229 replayed the full-span actual-DMA material through native Soapy CF32
  and got one-shot PBCH CRC OK plus `28/847` sweep PBCH-OK windows.
- CP1359 replayed the current CP1343 live-gNB pre-DMA full-geometry vector
  through the LiteX-only file-RX/TX helper and decoded PBCH CRC OK in all
  loopback modes.
- CP1362 independently captured the current live gNB at the CP1361 point and
  still decoded RF PBCH outside srsUE (`CSI SNR=+10.0 dB`, PBCH CRC OK,
  `35/847` sweep PBCH-OK windows).

## Interpretation

The user's suspicion is technically plausible as a live-path experiment, but
not as a simple configuration mistake. The current live gNB path is CI16 into
Soapy CS16, then the M2SDR plugin optionally maps CS16 to the AD9361 12-bit
lane. A true live CF32 path would require an OCUDU experimental code path that:

1. Opens Soapy TX, and probably RX, with `SOAPY_SDR_CF32`.
2. Converts OCUDU `ci16_t` TX chunks to `cf_t` scratch buffers before
   `writeStream()`.
3. Converts CF32 RX buffers back into `ci16_t` if the gNB receive stream is
   used.
4. Preserves all existing timing, chunking, EOB, and summary counters so it can
   be compared against CP1361/CP1362.

This branch is worth considering only as a controlled raw-gate A/B test because
it touches the live RF transport layer and could affect CPU timing or RX
semantics. It is not evidence that the current conversion path destroys the
downlink in general: multiple CF32 helper and independent live-capture
checkpoints already prove M2SDR can emit decodable PBCH, and CP1362 proves the
current live gNB still emits external PBCH at the failing scheduled-TRACK
point.

The sharper current boundary remains: external PBCH and digital TX are present,
but live srsUE scheduled TRACK reports about `-22 dB` mean and zero PBCH hits.
If the CF32 branch is run, the pass/fail metric must remain the same raw gate:
mean `event=track_opportunity meas_snr` and fraction of opportunities
`>= -10 dB`, with zero `ue_sync_nr.c` sync/anchor edits.

## Status

CP1363 is a no-RF feasibility checkpoint. It closes "set YAML to native CF32"
as impossible with the current OCUDU Soapy wrapper. It leaves one possible
future branch open: an explicit experimental OCUDU live-CF32 transport patch
followed by the CP1361 raw scheduled-TRACK gate A/B. Do not treat standalone
CF32 helper replay as pending; CP1227/CP1229 already covered that class.
