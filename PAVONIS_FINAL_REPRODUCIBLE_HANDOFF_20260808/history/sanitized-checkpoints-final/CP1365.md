# Checkpoint CP1365 - CP1364 Offline TRACK-Window Timing Replay

Date: [date-redacted] Europe/Zurich

## Purpose

Replay the CP1364 srsUE `RX_NOW` dump offline at the exact live TRACK-era
windows. This is a no-RF diagnostic checkpoint: no gNB/UE RF run, no PRACH,
no Android/NAS, and no `ue_sync_nr.c` sync/anchor logic edit.

The active ladder gate remains the live scheduled TRACK metric: mean
`event=track_opportunity meas_snr` and the fraction of opportunities
`>= -10 dB`. CP1365 does not raise that live metric by itself.

This checkpoint also sharpens the user's native-CF32/downsample suspicion. If
the current live SC16/RX sample path were simply destroying decodable samples,
the same CP1364 RX dump should not decode when replayed offline through the
same SSB tracking primitive at alternate offsets.

## Interpretation

CP1365 reproduces and strengthens the CP1340/CP1341 conclusion at the exact
CP1364/CP1361 best `+3500 Hz` point:

- The live-equivalent static TRACK primitive at `selected_sf_offset=825`
  fails offline on every CP1364 opportunity (`0/74`), matching the live CP1364
  scheduled result of zero TRACK PBCH hits.
- The same CP1364 srsUE RX stream contains PBCH-decodable samples during the
  TRACK era. The same `srsran_ssb_track_at_offset()` primitive decodes all
  19 search-derived alternate offsets.
- Therefore the immediate failure does not look like broad external RF loss,
  clipping, default `RX_NOW` failure, or generic SC16/RX conversion destroying
  the dump. It continues to point at scheduled receive-buffer/slot-phase/timing
  semantics, or at a true live RF/link-budget change that raises the static
  scheduled metric.

For the native-CF32 theory: CP1363 already shows live OCUDU/M2SDR cannot emit
native CF32 by configuration; it would require an explicit transport A/B patch.
CP1365 makes a generic "conversion/downsample destroys SNR" explanation less
likely for the current blocker, because the CP1364 SC16/RX dump decodes with
the live tracking primitive when the offset is changed. A live-CF32 patch
remains possible as a controlled experiment, but it is not a config-only next
step and should still be judged only by the live scheduled TRACK gate.

## Verdict

CP1365 is not a ladder unlock because it is offline and does not raise mean
live `event=track_opportunity meas_snr` or the `>= -10 dB` fraction. It is a
reusable no-RF diagnostic baseline: CP1364 static scheduled windows fail
offline exactly like the live run, while alternate offsets decode `19/19` with
the same tracking primitive.

Do not move to PRACH/Android/NAS, and do not resume `ue_sync_nr.c` sync/anchor
edits. Continue with raw receive-path/link-budget diagnostics that can raise
the live scheduled TRACK metric or explain why the static scheduled window is
misplaced without editing the gated sync logic.
