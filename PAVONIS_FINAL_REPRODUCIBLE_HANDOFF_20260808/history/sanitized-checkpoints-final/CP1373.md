## Purpose

Test one bounded receive-path variant at the current best SSB-centered live
raw-gate point before moving up the ladder. The user asked whether live gNB
could emit native CF32 and whether the conversion/downsample path might be
breaking SNR. CP1368-CP1369 already tested the TX-side live CF32 branch: the
gNB can open a Soapy CF32 TX stream via `OCUDU_SOAPY_TX_FORMAT=cf32`, but the
live OCUDU baseband still produces `ci16_t` chunks that are converted to CF32
immediately before `writeStream`, and the CP1369 raw gate did not improve.

CP1373 therefore does not repeat live TX CF32. It holds TX on the normal CS16
path and tests a receive sample-rate/filter geometry: `NRSA_SRATE_HZ=7680000`
with default bladeRF bandwidth selection, expected and confirmed as
`6144000 Hz`.

Gate remains the raw scheduled TRACK metric:

- Mean `event=track_opportunity meas_snr`.
- Fraction of TRACK opportunities at or above `-10 dB`.
- TRACK PBCH hits.

No `ue_sync_nr.c` sync/anchor scheduler edits are part of this checkpoint.

## Conclusion

CP1373 is a clean no-unlock. The `7.68 Msps` receive-rate/default-`6.144 MHz`
bandwidth variant at the current SSB-centered `+3500 Hz` point does not raise
the raw scheduled TRACK link budget enough to move up the ladder.

Do not repeat this exact mid-rate/default-bandwidth receive-path point unless
another variable has changed or a regression check is explicitly needed.
Further work should stay gated on the raw downlink metric: mean
TRACK-opportunity SNR and the percentage of opportunities at or above
`-10 dB`, with zero scheduler/anchor edits until that metric improves.
