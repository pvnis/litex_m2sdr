# CHECKPOINT 1386: Live NRSA RX-Contiguous Metadata At CP1373 Geometry

## Scope

CP1386 tested one receive-transport variable at the current CP1373 geometry:
enable the bladeRF RF plugin's helper-style timestamp-contiguous RX metadata
mode with bounded RX debug, while keeping the rest of the live raw-gate setup
unchanged.

No `ue_sync_nr.c` sync/anchor logic was edited. Sidecheck, direct-offset,
candidate-anchor, follow, and fallback actions stayed disabled. This checkpoint
does not touch PRACH, Android, or NAS.

- mean `event=track_opportunity meas_snr`

CAMPING/TRACK.

## RX Debug Findings

The bounded RX debug emitted exactly `520` `PAVONIS_RF_BLADE_RX_DBG` lines.
The log also contains `227` `Requested timestamp is in the past` receive
failures.

The failure starts after a short successful read:

```text
PAVONIS_RF_BLADE_RX_DBG line=516 call=516 ... status=0 ... actual_count=7680 ... rms_rel=0.019032479
PAVONIS_RF_BLADE_RX_DBG line=517 call=517 ... status=0 ... actual_count=7680 ... rms_rel=0.018764154
PAVONIS_RF_BLADE_RX_DBG line=518 call=518 ... status=0 ... meta_status=0x00030001 ... actual_count=1488 ... rms_rel=0.018830871
PAVONIS_RF_BLADE_RX_DBG line=519 call=519 ... status=-14 status_str=Requested timestamp is in the past ... actual_count=7680 sc16_abs_max=0 rms_rel=0.000000000
PAVONIS_RF_BLADE_RX_DBG line=520 call=520 ... status=0 ... requested_timed=0 ... actual_count=7680 ... rms_rel=0.019143882
```

Interpretation: contiguous timestamp requests stay exact while reads return
full buffers, but after a short successful read (`actual_count=1488`) the next
exact timestamp can already be in the past. This reproduces CP1324's
contiguous-metadata failure class at the later CP1373 geometry.

## Conclusion

CP1386 closes timestamp-contiguous RX metadata as a current-geometry fix. It
does not raise the raw scheduled TRACK metric and it fails before producing any
TRACK opportunities. The branch should not be repeated unless the contiguous
metadata implementation changes to handle short successful reads without
walking into past timestamps.

Continue gating all ladder movement on a real improvement in the live raw
scheduled TRACK metric. Default repeated `RX_NOW` remains the safer srsUE
receive mode for subsequent probes.
