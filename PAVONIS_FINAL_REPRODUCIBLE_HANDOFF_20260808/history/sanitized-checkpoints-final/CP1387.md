## CF32 Question

The live gNB can be made to use CF32 at the gNB-to-Soapy API boundary. CP1368
added the env-gated path and CP1369 ran the A/B with
`OCUDU_SOAPY_TX_FORMAT=cf32`. CP1369 runtime evidence showed:

```text
Soapy TX summary enabled: ... tx_format=CF32
OCUDU_SOAPY_TX_FORMAT_CF32 enabled: stream=0 scale=32767 mtu=1022 channels=1
Soapy TX summary: ... partial_ret=0 over_ret=0 timeouts=0 errors=0 ... tx_format=CF32
```

But the scheduled raw gate still failed in CP1369:

```text
96 TRACK opportunities, mean=-21.931521 dB, 0/96 >= -10 dB, 0 TRACK PBCH hits
```

So "make live gNB emit CF32 toward Soapy" is feasible and already tested as a
raw-gate fix. It did not rescue the link. It also cannot make the M2SDR
hardware path truly float-native end to end: the local Soapy validator states
that M2SDR natively uses `SC16` over-the-wire, and the CF32 TX path still
converts the gNB's `ci16_t` chunks into a CF32 buffer before `writeStream`.
That test specifically checks whether the gNB-to-Soapy integer stream format is
the damaging stage; it does not remove every lower-level device conversion.

## Conclusion

CP1387 is a clean no-unlock for RX gain 40 at the CP1373
`7.68 Msps`/default-`6.144 MHz` geometry. It improves initial acquisition enough
to find/select the cell, but the scheduled TRACK gate is worse than CP1373:

```text
CP1373 RX32: mean=-20.978176 dB, 2/74 >= -10 dB, 0 TRACK PBCH hits
CP1378 RX36: mean=-22.103071 dB, 0/70 >= -10 dB, 0 TRACK PBCH hits

CP1387 RX40: mean=-22.607043 dB, 0/70 >= -10 dB, 0 TRACK PBCH hits
```

The immediate CP1373 mid-rate/default-BW RX-gain bracket is now
`30/32/36/40`. RX32 remains the least-bad point, but it is still below the raw
downlink gate. Do not move up the ladder on CP1387; continue with raw RF/link
budget or receive-path diagnostics until mean TRACK SNR and the percentage of
opportunities at or above `-10 dB` improve.
