# Checkpoint 1390: Live gNB In-Process RX Dump At CP1373 Geometry

Date: [date-redacted] Europe/Zurich

## Purpose

CP1390 tested a gNB-owned M2SDR RX dump path so we could inspect the LiteX SDR
receive side without opening a second Soapy `LiteXM2SDR` device. This follows
CP1385, where a separate RX helper process reinitialized/stressed the live
M2SDR/AD9361 state and therefore was not a transparent baseline.

This checkpoint did not edit `srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c` sync or
anchor logic and did not run PRACH, Android, NAS, or a ladder promotion. It is
not a raw scheduled-TRACK gate run.

## CF32 Context

The user's CF32 concern remains technically reasonable, but the controlled
live-gNB CF32 branch is already closed as a raw-gate fix at the tested points:

- CP1369: live gNB `OCUDU_SOAPY_TX_FORMAT=cf32` at `5.76 Msps`, active
  `tx_format=CF32`, clean TX, but mean TRACK SNR `-21.932 dB`, `0/96 >= -10 dB`,
  and zero TRACK PBCH hits.
- CP1388: live gNB `OCUDU_SOAPY_TX_FORMAT=cf32` at the current CP1373
  `7.68 Msps`/default-BW geometry, active `tx_format=CF32`, clean TX, but mean
  TRACK SNR `-22.281 dB`, `0/75 >= -10 dB`, and zero TRACK PBCH hits.

That makes "native CF32" possible at the OCUDU Soapy API boundary, but not
float-native end to end: the M2SDR hardware/plugin path still converts into
integer device lanes. Do not repeat the same live CF32 A/B unless the
implementation or another material variable changes.

## Caveats

The recovered gNB log contains TX summary lines and shows normal startup, but
it does not contain the expected `PAVONIS_SOAPY_RX_FORCE_CENTER_HZ active`,
`Soapy RX receive`, or `PAVONIS_SOAPY_RX_DUMP` log markers. The manifest proves
the RX dump instrumentation ran, but CP1390 does not yet prove that the patched
RX frequency-force hook was actually called or that RX was retuned/read back at
the intended SSB center.

The raw dump duration is also short: about `17.7 ms`. That is enough to show the
mechanism can capture samples, but too short to treat as a final LiteX RX OTA
baseline.

Therefore CP1390 is diagnostic evidence, not a ladder unlock and not a clean
replacement for a correctly instrumented same-device LiteX RX baseline.

## Verdict

CP1390 does not raise the active raw scheduled TRACK gate. It shows:

- gNB digital TX remains decodable pre/post DMA at this point;
- gNB-owned in-process RX dumping can capture and recover samples without
  opening a second Soapy device;
- the recovered short RX stream contains no PBCH evidence in local decode
  sweeps;
- the RX force/readback instrumentation is not yet strong enough to prove the
  receiver was [interface-redacted] to the intended SSB center.

Next checkpoint should harden the in-process RX instrumentation before spending
another RF run: log forced RX env/readback from the RX-dump path itself, make
the marker unavoidable in `gnb.log`, and capture a longer contiguous stream
or append-stream file. Only after RX retune/readback is proven should this path
be used as a LiteX RX baseline.
