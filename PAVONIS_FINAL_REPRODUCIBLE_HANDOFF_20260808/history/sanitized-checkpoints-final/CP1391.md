# Checkpoint 1391: No-RF OCUDU Soapy RX Dump Readback And Append Build

Date: [date-redacted] Europe/Zurich

## Purpose

CP1391 is the no-RF source/build checkpoint following CP1390. CP1390 proved
that the gNB-owned RX dump mechanism can produce samples, but did not prove
that the RX force/readback path was active in `gnb.log`, and the recovered
stream was too short to be a useful LiteX RX baseline. CP1391 hardens that
instrumentation before spending another RF run.

No srsUE, bladeRF, PRACH, Android, NAS, scheduler edit, or `ue_sync_nr.c`
sync/anchor logic change is involved.

## Source Change

Changed file:

- `/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_rx_stream.cpp`

Default behavior is unchanged unless `PAVONIS_SOAPY_RX_DUMP` is set.

New default-off instrumentation:

- constructor-time log marker:
  `PAVONIS_SOAPY_RX_DUMP active: stream=...`
- constructor-time RX readback marker:
  `PAVONIS_SOAPY_RX_DUMP readback: stream=... ch=... sample_rate_Hz=... frequency_Hz=... gain_dB=... bandwidth_Hz=...`
- optional append-stream capture:
  - `PAVONIS_SOAPY_RX_APPEND_CF32_PATH=/tmp/...cf32`
  - `PAVONIS_SOAPY_RX_APPEND_MAX_SAMPLES=<samples>`
  - `PAVONIS_SOAPY_RX_APPEND_PORT=<port>`, default `0`

The append capture writes channel-buffer samples as CF32 into one file with a
max-samples cap. It is intended to replace thousands of 510-sample per-buffer
files for the next in-process RX diagnostic.

## Verdict

CP1391 closes the CP1390 instrumentation gap at the binary/build-smoke level:
the actual [host-redacted] Soapy-enabled gNB now contains unavoidable RX dump activation
and readback log markers plus an append-CF32 capture path.

This is not a raw scheduled-TRACK gate pass and does not move the ladder. The
next RF checkpoint should rerun the gNB-owned RX diagnostic with:

- `PAVONIS_SOAPY_RX_FORCE_CENTER_HZ=1839650000`
- `PAVONIS_SOAPY_RX_DUMP=1`
- `PAVONIS_SOAPY_RX_APPEND_CF32_PATH=/tmp/...cf32`
- `PAVONIS_SOAPY_RX_APPEND_MAX_SAMPLES` large enough for at least 250 ms

The gate remains the raw scheduled TRACK metric; do not resume `ue_sync_nr.c`
sync/anchor edits or PRACH/Android/NAS ladder work until that metric improves.
