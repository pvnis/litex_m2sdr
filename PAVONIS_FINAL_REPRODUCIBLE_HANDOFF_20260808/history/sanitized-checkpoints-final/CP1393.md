# Checkpoint 1393: No-RF OCUDU Soapy RX Readback Sidecar Build

Date: [date-redacted] Europe/Zurich

## Purpose

CP1393 follows CP1392's unresolved marker gap. CP1392 proved the gNB-owned RX
append path can write a full 250 ms CF32 file, but `gnb.log` still contained
zero RX force/readback marker lines. The next useful step is therefore not
another logger-based live run. CP1393 adds a default-off readback sidecar that
is written from the same RX dump sample-writing block that writes raw and
append samples.

No RF, srsUE, PRACH, Android, NAS, ladder promotion, or `ue_sync_nr.c`
sync/anchor logic change is involved.

## Source Change

Changed file:

- `/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_rx_stream.cpp`

New env-gated sidecar:

- `PAVONIS_SOAPY_RX_READBACK_PATH=/tmp/...txt`

When both `PAVONIS_SOAPY_RX_DUMP` and `PAVONIS_SOAPY_RX_READBACK_PATH` are set,
the RX dump block writes the sidecar once, from the same code path that writes
raw per-buffer files and the append CF32 stream. The sidecar records:

- stream id, MTU, configured sample rate, channel counts, buffer size, loop
  count, overflow count, `ret.ts`, wall time, and hardware time;
- env values for forced RX center, RX bandwidth, append path/max/port, raw max,
  and raw period;
- direct Soapy RX readback for each RX channel: sample rate, frequency, gain,
  and bandwidth, plus readback success flags.

Default behavior remains unchanged unless `PAVONIS_SOAPY_RX_DUMP` and
`PAVONIS_SOAPY_RX_READBACK_PATH` are both set.
