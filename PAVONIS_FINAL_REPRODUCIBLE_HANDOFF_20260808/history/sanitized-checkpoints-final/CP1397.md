# CP1397 OCUDU Soapy TX Readback Sidecar Build Smoke

Date: [date-redacted]

## Purpose

CP1396 left one ambiguity: the run exported `OCUDU_SOAPY_TX_FORMAT=cf32`, but
the retained logs did not include the live `OCUDU_SOAPY_TX_FORMAT_CF32 enabled`
or `tx_format=CF32` marker. CP1397 adds a default-off TX sidecar,
`PAVONIS_SOAPY_TX_READBACK_PATH`, written from the actual OCUDU Soapy TX stream
constructor so the next RF checkpoint can prove the stream object's selected TX
format and TX channel readback without relying only on stderr retention.

This is a no-RF build checkpoint. It does not run srsUE, bladeRF, Android,
PRACH, NAS, or `ue_sync_nr.c` sync/anchor edits.

## Implementation

`radio_soapy_tx_stream.cpp` now writes the TX sidecar only when
`PAVONIS_SOAPY_TX_READBACK_PATH` is set. The sidecar records:

```text
PAVONIS_SOAPY_TX_READBACK_PATH=1
stream_id
mtu
srate_hz
nof_channels
discontinuous_tx
write_timeout_us
tx_force_chunk_samples
tx_suppress_empty_eob
tx_cf32_format
tx_format
ci16_to_cf32_scale
hardware_time_ok
hardware_time_ns
env_OCUDU_SOAPY_TX_FORMAT
env_OCUDU_SOAPY_TX_CF32
env_M2SDR_SOAPY_TX_CS16_TO_SC12
env_M2SDR_SOAPY_TX_TIME_OFFSET_NS
env_OCUDU_SOAPY_TX_SUMMARY
env_OCUDU_SOAPY_TX_SUPPRESS_EMPTY_EOB
per-TX-channel sample rate, frequency, gain, and bandwidth readback
```

Normal runtime behavior is unchanged unless that env var is exported.

## Conclusion

CP1397 proves the TX-readback sidecar instrumentation builds locally and on
[host-redacted] and that the deployed [host-redacted] `gnb` binary contains the new marker. It does
not prove live CF32 activation or raise the raw scheduled-TRACK gate because
no RF stream was opened.

The next checkpoint should run the CP1396-style live gNB-owned RX append
diagnostic with both:

```text
PAVONIS_SOAPY_TX_READBACK_PATH=/tmp/pavonis_soapy_tx_readback.txt
PAVONIS_SOAPY_RX_READBACK_PATH=/tmp/pavonis_soapy_rx_readback.txt
```

That will make the CF32 sidecar question authoritative in the same RF run that
measures the weak live gNB-owned append level.
