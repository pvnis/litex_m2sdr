# CP1399 LiteX Replay Of CP1398 Source Split-Frequency Baseline

Date: [date-redacted]

## Purpose

CP1398 proved that the live gNB Soapy TX stream was opened as `CF32`, but the
gNB-owned RX append level stayed weak and decoded no PBCH. CP1399 tests the
next narrower question: is CP1398's actual live pre-DMA source vector itself,
or the current CI16-to-CF32 boundary conversion, responsible for the weak
append level?

This checkpoint replays CP1398's own `pre_dma_full_scale32768.cf32` vector
through the standalone LiteX TX/RX helper that passed in CP1395, using the same
split-frequency geometry. It does not use bladeRF/srsUE, Android, NAS, PRACH,
or `ue_sync_nr.c` edits, and it is not a raw scheduled-TRACK gate run.

## Native-CF32 Note

The current OCUDU live gNB TX interface is not native float end to end. The
baseband gateway still hands `ci16_t` buffers to
`radio_soapy_tx_stream::transmit()`. In the env-gated `CF32` Soapy mode, the
Soapy stream is opened as `SOAPY_SDR_CF32`, but each chunk is converted from
CI16 to CF32 immediately before `writeStream()` using scale `32767`.

Making the live gNB produce native CF32 upstream would require changing the
baseband/lower-PHY buffer contract, not only flipping the Soapy stream format.
CP1399 therefore tests the practical suspicion without a large rewrite: if the
same CP1398 source replays strongly through LiteX-only CF32 TX/RX, the weak
live append is not explained by bad source content or a generic CF32 helper
conversion failure.

## Conclusion

CP1399 closes the "CP1398 source vector is bad" and "standalone LiteX
split-frequency replay cannot handle the CP1398 source" explanations. The
actual CP1398 live pre-DMA vector replays strongly through the standalone
LiteX path on both external RF-style `none` and AD9361 loopback, at roughly
`+26 dB` over the CP1398 gNB-owned live append level.

It also weakens the practical CI16-to-CF32 suspicion for the observed level
gap: the current source material and helper CF32 replay path are good. True
upstream native CF32 remains a larger architecture change, but CP1399 gives no
evidence that such a rewrite is the next high-value move.

The active blocker remains the live gNB runtime TX/RX path or real link
budget, not source-vector validity, not generic split-frequency LiteX RX, not
unchanged live Soapy TX `CF32`, and not `ue_sync_nr.c` scheduler/anchor logic.
The raw scheduled-TRACK gate remains locked until mean TRACK-opportunity SNR
and the fraction of opportunities at or above `-10 dB` improve.
