## Goal

Make the CP1401/CP1402 timed-metadata result diagnostic by:

- logging the exact failing timed TX row and Soapy return;
- continuing RX capture even after the timed TX thread reports an error;
- rerunning the timed-only CP1402 settings.

This tests whether the queued timed metadata samples actually leave the LiteX
radio at useful level before the standalone Python writer times out.

## Interpretation

CP1403 closes the simple "live-like timed/discontinuous metadata alone destroys
the RF level" theory for the accepted first segment of the CP1400 schedule.
Standalone LiteX timed replay of the actual CP1400 source/metadata produces
decodable PBCH at normal standalone levels even though the Python writer later
times out.

The remaining weak live-gNB path is therefore more specific than:

- source-vector validity;
- standalone CF32 split-frequency replay;
- helper-style BIST/crossbar prequiet;
- Soapy TX format being CS16 instead of CF32;
- the mere presence of live-like timed metadata rows.

The next branch should focus on a live-gNB runtime/process-specific difference
that is absent from standalone Python LiteX replay, or instrument the actual
OCUDU C++ Soapy write path further. Do not treat CP1401/CP1402 empty captures
as RF failures.
