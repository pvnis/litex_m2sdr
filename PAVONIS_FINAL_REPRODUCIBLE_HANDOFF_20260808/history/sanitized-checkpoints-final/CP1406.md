## Goal

Test whether CP1405's post-DMA/digital TX regression was caused by the large
`2,000,000`-sample synchronous C++ write dump. CP1406 reruns the same
CP1400-style live dual-sidecar TX-CF32 append path, but caps the
`writeStream()`-boundary dump at only `23040` samples.

No `ue_sync_nr.c` sync/anchor logic was edited. No RF-code change was made for
this checkpoint; only a small wrapper script was added to set a distinct stamp
and `TX_WRITE_DUMP_MAX_SAMPLES=23040`.

## Interpretation

CP1406 closes the CP1405 caveat. The large `16 MB` CP1405 write dump was
perturbative enough to break the post-DMA/digital sidecar analysis, but the
small `184 KiB` dump is not. With the small dump:

- `writeStream()`-boundary CF32 is strong and matches pre-DMA.
- Post-DMA/digital TX is PBCH-decodable again.
- The gNB-owned RX append remains weak and undecodable.

Therefore the current live weakness is not explained by OCUDU's CI16-to-CF32
conversion or C++ chunking handed to Soapy. The next useful rung is below
`writeStream()`: M2SDR plugin scheduling/release behavior, DMA-to-RF/AD9361
state, or real RF/link-budget/path differences. Do not repeat the large
CP1405 `2M`-sample write dump unchanged.
