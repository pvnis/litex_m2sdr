# Checkpoint 1410 - LiteX M2SDR In-Process State Dump Build

Date: [date-redacted] Europe/Zurich

## Goal

Add a default-off, in-process LiteX M2SDR / AD9361 state dump to the Soapy
plugin so future live gNB runs can capture lower-device state without opening a
second `m2sdr_util` process against the active hardware.

This checkpoint is a no-RF instrumentation/build-smoke. It does not run a gNB
TX window, srsUE, bladeRF capture, Android, PRACH, NAS, or `ue_sync_nr.c`
changes.

## Change

Patched:

- `litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp`
- `litex_m2sdr/software/soapysdr/LiteXM2SDRDevice.hpp`

New env gate:

- `M2SDR_SOAPY_STATE_DUMP_PATH`

When set, the plugin appends `PAVONIS_M2SDR_STATE_DUMP` blocks at
`setupStream` and `activateStream`. Each block records:

- cached stream state, format, rates, frequencies, bandwidths, gain/attenuation
- AD9361 public getter readbacks for sample rate, LO, RF bandwidth, TX
  attenuation, RX gain, gain-control mode, and temperature
- selected LiteX CSRs including crossbar, AD9361 PHY/control, header, and
  timed-TX state/counters where present
- selected AD9361 SPI registers from the CP1233 live/helper state branch,
  including TX attenuation regs and the additional digital/correction regs that
  differed in the full dump

## Interpretation

CP1410 creates the missing non-perturbative state probe for the current lower
path. It does not raise the raw scheduled TRACK gate and does not prove whether
the weak live append is caused by AD9361/LiteX state, but it enables the next
RF checkpoint to capture live gNB-owned state without repeating CP1233's
second-process `m2sdr_util` method.

The CP1409 conclusion still stands: live CF32 at the OCUDU write boundary is
active and strong, M2SDR write/release summaries are clean, but the live
gNB-owned RX append remains weak. The next checkpoint should run the CP1400/
CP1409 live dual-sidecar path with `M2SDR_SOAPY_STATE_DUMP_PATH` enabled and
compare the in-process state dump against the standalone LiteX replay class.
