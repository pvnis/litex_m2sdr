# CHECKPOINT 1413: Offline RX-Append Format Path Probe

Date: [date-redacted]  
Stamp: `[date-redacted]CP1413_RXAPPEND_FORMAT_PATH_OFFLINE`

## Goal

Answer the native-CF32/conversion-path suspicion without spending RF time:
inspect the live gNB-owned LiteX RX append path from CP1412 and determine
whether the reported weak append level is RF/link-budget evidence or a software
sample-presentation artifact.

This checkpoint does not run RF, SSH, gNB, srsUE, Android, or any `ue_sync_nr.c`
sync/anchor logic. It analyzes the already captured CP1412 append file.

## Source Context

Live gNB TX already emits `CF32` at the OCUDU Soapy boundary when
`OCUDU_SOAPY_TX_FORMAT=cf32` is set. CP1398, CP1411, and CP1412 proved that via
TX sidecars/state readback. It is not float-native all the way into hardware:
OCUDU lower/baseband buffers are `ci16_t`, and the LiteX M2SDR hardware/DMA path
is integer IQ. The useful boundary question is therefore where integer IQ is
converted, deinterleaved, and scaled.

The current RX append instrumentation in
`ocudu/lib/radio/soapy/radio_soapy_rx_stream.cpp` writes from the OCUDU
`baseband_gateway_buffer_writer` after `acquireReadBuffer()` has been copied
into `ci16_t` buffers, then converts those `ci16_t` values to CF32 by dividing
by `32767`. The LiteX Soapy plugin's normal `readStream()` path instead
deinterleaves and sign-extends hardware samples, and its CF32 conversion scales
12-bit-ish samples by the plugin sample scale near `[date-redacted]`.

plausible recovered lane at both `11.52 Msps` and `5.76 Msps`.

## Interpretation

The CP1412 append's apparent `~25 dB` deficit versus standalone LiteX captures
is not reliable RF evidence by itself. Multiplying by the expected
`32767/[date-redacted]` scale raises the all-sample RMS from `0.0001867` to `0.00299`,
and the even lane reaches `0.004225`, matching the known-good standalone LiteX
RX level class from CP1395/CP1399.

The odd lane is exactly zero, which strongly indicates the gNB-owned direct
`acquireReadBuffer()` append/copy path is seeing a raw interleaved frame and
treating it as a contiguous one-channel `ci16_t` buffer. That bypasses the
LiteX plugin's normal `readStream()` deinterleave/sign-extension path. The
saved CP1412 append still cannot be recovered offline because the direct copy
appears to have already discarded part of each raw DMA frame, producing
irreversible gaps before the file was written.

This does not by itself unlock the bladeRF UE scheduled-TRACK gate, whose raw
TRACK SNR remains the ladder criterion. It does invalidate using the current
gNB-owned LiteX RX append RMS as a link-budget comparison unless the append is
taken from a correctly deinterleaved path.

## Conclusion

The user's conversion/downsample suspicion is plausible and now has concrete
evidence. Live TX CF32 is already enabled at the OCUDU Soapy boundary, but the
current gNB-owned LiteX RX append path is not a trustworthy native CF32 receive
baseline.

Next checkpoint should run the same live gNB-owned RX append with
`OCUDU_SOAPY_RX_USE_READSTREAM=1` and `M2SDR_SOAPY_STATE_DUMP_PATH` disabled.
That uses the LiteX plugin's normal readStream deinterleaving/sign-extension
path without editing `ue_sync_nr.c` or scheduler logic. If readStream produces
a clean append/CSI/PBCH signal, the direct RX buffer path is the culprit; if it
stays negative, continue isolating LiteX RX under a correctly captured boundary
before interpreting link budget.
