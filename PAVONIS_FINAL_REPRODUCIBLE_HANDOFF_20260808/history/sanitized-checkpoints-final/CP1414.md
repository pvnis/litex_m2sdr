# Checkpoint 1414: Live gNB-Owned RX Append With Soapy readStream

Date: [date-redacted] Europe/Zurich

## Goal

Test the CP1413 suspicion that the weak gNB-owned LiteX RX append was a
software presentation/copy-path artifact rather than a true RF link-budget
measurement. The only intended live-path change was enabling
`OCUDU_SOAPY_RX_USE_READSTREAM=1` for the gNB-owned RX capture while keeping
the CP1400 dual-sidecar live TX-CF32/prequiet harness, state dump disabled, and
no `ue_sync_nr.c` sync/anchor edits.

This also answers the "native CF32" suspicion more precisely:

- Live gNB TX already can open Soapy TX as `CF32` through
  `OCUDU_SOAPY_TX_FORMAT=cf32`, and CP1398/CP1400/CP1414 sidecars prove that
  mode is active.
- That is not an end-to-end float-native radio path. OCUDU baseband buffers
  are still `ci16_t`, and the LiteX/AD9361/DMA path is still integer IQ.
- The broken path isolated here is the previous RX append's direct
  `acquireReadBuffer()` copy/scale/presentation path, not the live TX CF32
  conversion path.

## Verdict

CP1414 passes the same-device gNB-owned LiteX RX baseline. Enabling
`OCUDU_SOAPY_RX_USE_READSTREAM=1` makes the live gNB-owned RX append decodable
without perturbing the TX guard.

Do not treat the old direct `acquireReadBuffer()` append RMS or decode failures
as link-budget evidence. For LiteX same-device RX baselines, either use
`readStream()` or fix/test the direct-buffer path to deinterleave/sign-extend
and copy exactly the intended channel before writing or interpreting CF32.

This does not yet unlock the original srsUE/bladeRF ladder. The active ladder
gate remains the raw live scheduled TRACK metric on the UE path:
mean `event=track_opportunity meas_snr` and percentage of opportunities at or
above `-10 dB`. CP1414 isolates a diagnostic path and provides a clean LiteX
baseline for future variable isolation; it does not prove the bladeRF scheduled
TRACK SNR has improved.
