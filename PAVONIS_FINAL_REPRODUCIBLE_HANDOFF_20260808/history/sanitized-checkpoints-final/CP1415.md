# Checkpoint 1415: Live NRSA With Armed gNB-Owned readStream RX Append

Date: [date-redacted] Europe/Zurich

## Goal

Run the CP1414 known-good gNB-owned LiteX RX append method in the same live
gNB window as a srsUE/bladeRF raw scheduled-TRACK probe. The intent was to
isolate whether the current ladder blocker is specific to the bladeRF/srsUE
receive path or whether the gNB-owned LiteX RX path also becomes weak during
the same live run.

This checkpoint also records the current answer to the native-CF32 suspicion:

- Live gNB TX can already emit to the Soapy API as `CF32` through
  `OCUDU_SOAPY_TX_FORMAT=cf32`.
- That is not native float end to end. OCUDU baseband buffers are still
  `ci16_t`, and the LiteX/AD9361/DMA path is still integer IQ.
- The current source does not expose a YAML/config-only `cf32` OTW setting:
  `radio_configuration::over_the_wire_format` has only `DEFAULT`, `SC16`,
  `SC12`, and `SC8`.
- CP1405 and CP1406 already closed the immediate conversion/chunking suspicion:
  the live C++ `ci16_t` to `CF32` buffer handed to Soapy `writeStream()`
  was strong and near-identical to the same-run pre-DMA reference.

## Interpretation

CP1415 is a mechanically successful but diagnostically negative checkpoint.
It does not unlock the ladder:

- srsUE/bladeRF raw scheduled TRACK remains below gate:
  mean `-22.201587 dB`, `0/92 >= -10 dB`, zero PBCH hits.
- The companion gNB-owned LiteX readStream append also regressed and decoded
  nothing, unlike CP1414.
- Because the gNB-owned RX readback gain was `44` instead of CP1414's `67`,
  CP1415 is not a clean proof that the bladeRF/srsUE path is the only failing
  receive path.
- The live TX path remains healthy and already uses Soapy TX `CF32`; changing
  this path again is unlikely to raise the raw gate unless the implementation
  changes materially below the current conversion boundary.

## Next Step

Before another concurrent bladeRF isolation run, reproduce the CP1414 positive
readStream append class with the CP1415 arm-file mechanism but without srsUE, or
explicitly force/verify the gNB-owned LiteX RX gain/readback back to the
CP1414 `66-67 dB` class before arming. Only after that baseline is stable should
the same-window srsUE/bladeRF isolation be repeated.
