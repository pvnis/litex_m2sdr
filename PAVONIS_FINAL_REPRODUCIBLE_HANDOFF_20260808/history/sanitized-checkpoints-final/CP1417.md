# Checkpoint 1417 - No-RF OCUDU Soapy RX Gain-State Build Smoke

Date: [date-redacted]  
Artifact stamp: `[date-redacted]CP1417_RX_GAIN_STATE_BUILD`

## Goal

Prepare the next gNB-owned LiteX RX baseline so it can explicitly diagnose the
CP1415/CP1416 receive-state regression. CP1414 decoded PBCH with readStream and
RX gain `67`, while CP1415/CP1416 failed with readback gain `44`/`42`. This
checkpoint adds default-off instrumentation and a forced RX gain override, then
build-smokes it on the Soapy-enabled [host-redacted] tree.

This checkpoint does not run RF and does not test the raw scheduled TRACK gate.

## Code Changes

- Added `radio_soapy_device::get_gain_mode()` as a safe SoapySDR wrapper.
- Added `PAVONIS_SOAPY_RX_FORCE_GAIN_DB` in OCUDU Soapy RX gain setup. When
  set to a finite nonnegative value, it replaces the configured RX gain and
  logs requested/applied gain.
- Extended OCUDU Soapy channel readback logging with `gain_mode_ok` and
  `gain_mode_auto`.
- Extended the Pavonis RX readback sidecar with:
  - `env_PAVONIS_SOAPY_RX_FORCE_GAIN_DB`
  - per-channel `gain_mode_ok`
  - per-channel `gain_mode_auto`
