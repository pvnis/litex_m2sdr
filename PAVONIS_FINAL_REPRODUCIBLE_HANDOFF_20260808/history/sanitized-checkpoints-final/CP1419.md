## Goal

Close the CP1418 finding that `PAVONIS_SOAPY_RX_FORCE_GAIN_DB=67` reached
runtime but the live RX sidecar still read back `gain_db=44` and
`gain_mode_auto=1`. This checkpoint adds the missing explicit manual gain-mode
call around forced RX gain and build-smokes it on the Soapy-enabled [host-redacted] gNB
target.

This is no-RF only. It does not run srsUE, Android, PRACH, NAS, or a live
append capture.

## Code Change

`ocudu/lib/radio/soapy/radio_soapy_device.h` now wraps Soapy
`setGainMode()`:

```text
radio_soapy_device::set_gain_mode(direction, channel, automatic)
```

`ocudu/lib/radio/soapy/radio_soapy_impl.cpp` now changes only the forced-gain
path:

- parse `PAVONIS_SOAPY_RX_FORCE_GAIN_DB`
- if finite, force `set_gain_mode(SOAPY_SDR_RX, channel, false)` before
  `set_gain()`
- set the forced gain value
- force manual gain mode again after `set_gain()`
- log immediate post-set `getGain()` and `getGainMode()` readback:
  `PAVONIS_SOAPY_RX_FORCE_GAIN_DB post-set readback`

Default behavior is unchanged when `PAVONIS_SOAPY_RX_FORCE_GAIN_DB` is unset
or invalid.

will return to `66-67 dB`; it proves the correct next binary is in place on
[host-redacted] and that the forced-gain path will now explicitly request manual RX gain

srsUE/bladeRF isolation until that no-srsUE control passes or explains why it
cannot.
