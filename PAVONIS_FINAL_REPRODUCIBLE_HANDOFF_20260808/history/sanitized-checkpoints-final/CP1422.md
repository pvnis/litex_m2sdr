## Interpretation

CP1422 is a partial success.

It proves the CP1421 post-`setupStream()` gain reassertion fixed the immediate
RX state regression: final readback is now manual gain mode with `67 dB`, not
automatic gain mode around `41-44 dB`. The append level also rises from CP1420's
`0.0002003` RMS to `0.0007178` RMS.

It does not restore CP1414's decodable gNB-owned LiteX RX baseline. Despite the
corrected manual gain state and clean TX guard, targeted decode remains `0/30`
and aligned sweep remains `0/847`. So the branch has moved past "gain mode is
being reset" to a narrower problem: manual 67 dB is necessary to recover the
state readback, but it is not sufficient to recover PBCH in this live append.

This checkpoint continues to weaken the live-gNB CF32-conversion suspicion:
TX is live `CF32`, pre-DMA and post-DMA PBCH both decode, and Soapy write
counters are clean. The current failure is downstream or orthogonal to the
OCUDU CI16-to-CF32 write boundary.

## Next

Do not rerun CP1422 unchanged. The next checkpoint should compare CP1422's
manual-67-but-undecodable append against the CP1414 positive readStream append
baseline and identify what changed besides gain mode. Good candidates are:
