# Checkpoint 1437 - bladeRF RX State Sanity With No gNB TX

Date: [date-redacted] Europe/Zurich

## Goal

After CP1435 and CP1436 showed that two historical independent bladeRF
pass-class captures now fail while corrected gNB digital TX remains healthy,
CP1437 checks the bladeRF receive-control state without starting another gNB
TX window. The goal is to verify the obvious software state: loopback, RX mux,
RX filter, AGC, [interface-redacted], sample rate, bandwidth, gain, hardware status, and RSSI.

No gNB was started. No srsUE, PRACH, Android, NAS, or `ue_sync_nr.c`
sync/anchor logic was used or edited.

state:

- loopback: `none`
- RX mux: `BASEBAND`

- requested / actual RX frequency: `1839650000` / `1839649998 Hz`
- sample rate: `5760000`

- overall RX gain: `60 dB`
- full RX gain readback: `71 dB`

Hardware readings were normal:

- temperature: `31.6 C`
- power: `4.928 V`, `0.53 A`, `2.62 W`
- power source: USB bus

RSSI with no gNB TX was:

- preamble: `-77 dB`
- symbol: `-85 dB`

The RF routing print matched CP1435/CP1436:

- `RX1: RFIC 0x0 (A_BAL) <= SW 0x0 (OPEN)`
- `TX1: RFIC 0x0 (TXA) => SW 0x0 (OPEN)`

This checkpoint does not assert whether that `OPEN` switch readback is correct
for the installed physical path; it only records that it is not a new
difference introduced by CP1437. The same routing print appears in the TX-on
CP1435 and CP1436 bladeRF state logs.

## Interpretation

CP1437 finds no obvious bladeRF software-state mismatch: loopback is off, RX
mux is baseband, filter is normal, AGC is off, [interface-redacted]/rate/BW/gain read back as
intended, and the device is not hot. It also shows that TX-on captures did not
raise the bladeRF RSSI above no-gNB baseline in a visible way.

This strengthens the broad external receive-path branch opened by CP1435 and
CP1436. The likely blocker is now physical/analog receive path, RF routing, or
an unresolved bladeRF receive-chain state outside the high-level mux/gain/filter
settings. The next useful software-only checkpoint would be a no-gNB raw sample
capture at the same geometry to compare RMS/noise statistics against CP1436, or
a TX-on/off paired capture after any physical path adjustment.
