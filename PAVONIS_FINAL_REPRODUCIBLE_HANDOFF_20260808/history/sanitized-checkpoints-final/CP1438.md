## Goal

Establish a no-transmitter bladeRF raw-sample baseline at the same receive
geometry used by CP1436, then compare it against the failed TX-on CP1436
independent bladeRF capture. This tests whether the live gNB window visibly
raises the bladeRF receive-chain level, independent of srsUE, scheduler logic,
M2SDR self-RX, Android, PRACH, NAS, and `ue_sync_nr.c`.

This checkpoint does not measure the raw scheduled-TRACK gate directly. It is
a receive-path isolation checkpoint for the current gate.

## Interpretation

The no-gNB bladeRF raw-noise baseline is essentially the same level class as
the failed CP1436 TX-on capture: only `-0.093 dB` RMS difference, similar raw
max, identical RSSI class, one-shot PBCH KO, and `0/847` aligned sweep windows.
This means the live TX-on window is not visibly lifting the bladeRF receive
chain above the no-transmitter baseline at the CP1436 geometry.

Combined with CP1433/CP1434 same-window evidence, where M2SDR self-RX and TX
guard could still decode while bladeRF/srsUE or independent bladeRF capture
failed, CP1438 strengthens the broad bladeRF/OTA receive-path branch. The
leading possibilities are now physical RX path/coupling, antenna/cable/switch
state, or a bladeRF receive-chain state that is not exposed by the high-level
readbacks. It is less consistent with a live gNB digital-TX failure, a
CF32/self-RX-specific issue, or a scheduled-TRACK offset-scheduler issue.

The raw scheduled-TRACK gate remains unchanged: no new `ue_sync_nr.c` sync or
anchor edits should be made until the bladeRF path receives a signal above the
current noise-class baseline.

## Next Step

Prefer physical bladeRF RX path inspection/adjustment or a controlled path
swap before further scheduler work. If physical intervention is not available,
the next software-only branch should be a same-window cross-check that keeps
the M2SDR self-RX path stable enough for one concurrent run with srsUE/bladeRF:
if M2SDR self-RX decodes while bladeRF remains near `-22 dB` or no-detect, it
would further isolate the bladeRF/OTA receive path from live TX health.
