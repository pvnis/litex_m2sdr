# Checkpoint 1445: Live-Geometry Tone, BW2.0MHz, Gain48, bladeRF Filter Bypass

Date: [date-redacted]

## Purpose

Continue the CP1442-CP1444 receiver-side tone branch with one more
software-only split. CP1444 showed that bladeRF RX filter `bypass` at
BW3.84/gain48 improved level and SNR, but did not recover 10 ms frequency-bin
stability.

CP1445 keeps CP1444's filter/gain/tone geometry and changes only bladeRF RX
bandwidth from `3.84 MHz` to `2.0 MHz`. The expected bladeRF tone is
`+500 kHz`, so it remains inside the narrowed analog bandwidth but is close
enough to the passband shape to treat this as an edge-aware tone check.

This is not a raw scheduled-TRACK metric checkpoint.

## Interpretation

Narrowing bladeRF RX bandwidth to `2.0 MHz` with filter bypass is a useful
noise/SNR improvement for the tone, but it does not eliminate the alternate-bin
10 ms instability. This makes the bad stability less likely to be only a
wideband noise-floor issue. It looks more like a spectral/receiver-path
artifact, multipath/coupling/control-path issue, or a tone-placement/spur
interaction that remains visible even with high tone SNR.

CP1445 is not sufficient to return to scheduler work or Android/NAS work:
BW2.0 is too narrow to treat as an SSB/PBCH receive recovery, and the stability
warning remains.

Next useful split if staying software-only: move the tone placement while
keeping BW2.0/bypass/gain48, for example capture tone near `+100 kHz` instead
of `+500 kHz`. If the alternate-bin behavior disappears, CP1442-CP1445 is
mostly a tone-placement/spur/filter interaction. If it persists, keep the
leading branch on physical/coupling/RX-path state.
