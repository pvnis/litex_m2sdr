# CP1447: TX CF32 + Self-RX + Independent bladeRF Raw-DL, BW3.84 Bypass Gain48

Date: [date-redacted] Europe/Zurich

## Verdict

CP1447 is a mechanically clean same-window isolation run, but it does not
recover the bladeRF PBCH path. The live gNB/M2SDR TX guard is PBCH-positive,
the same-window M2SDR self-RX append is PBCH-positive, and the independent
bladeRF capture remains PBCH-negative.

This is not a raw scheduled-TRACK metric datapoint and does not unlock the
ladder. It strengthens the external bladeRF/OTA receive-path, coupling/routing,
or bladeRF receive-state/control-path branch. It also weakens the theory that
CP1441 failed only because its independent bladeRF capture used normal filter
and `6.144 MHz` bandwidth.

## Interpretation

CP1447 is the receiver-path split requested after the tone branch: it applies
the CP1444-style `3.84 MHz` + bypass bladeRF receive-side changes to an actual
SSB/PBCH-compatible live gNB window.

The result is negative for bladeRF: narrowing to `3.84 MHz` and using bypass
reduces raw level from CP1441's `0.112006394` to `0.082747123` rel2048 and
still yields `0/847` PBCH windows. The same-window M2SDR self-RX and corrected
TX guard are positive, so the live TX waveform is not the immediate blocker.

This leaves the leading branch unchanged: broad external bladeRF/OTA receive
degradation, physical/coupling/routing state, bladeRF receive-state/noise/
overdrive, or a persistent bladeRF control/spectral artifact. CP1447 also
supports the user's proposed discriminator: if self-RX decodes while bladeRF
sits weak or PBCH-negative, blame the bladeRF/OTA receive path before live TX.
