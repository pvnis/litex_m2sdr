# Checkpoint 1451: LiteX Tone Self-RX And bladeRF Same-Window Discriminator

Date: [date-redacted] Europe/Zurich

## Purpose

Test the user-suggested self-RX discriminator without changing `ue_sync_nr.c`:
run a live-geometry LiteX-M2SDR tone, capture the same window with M2SDR
self-RX, and also capture externally with bladeRF. If M2SDR self-RX is clean
while bladeRF is weak/unstable, the leading fault moves further toward the
external bladeRF/OTA receive path rather than LiteX TX tone generation,
deinterleave, scaling, or live TX.

This is not a raw scheduled TRACK datapoint. The active ladder gate remains
mean `event=track_opportunity meas_snr` and `% >= -10 dB`.

## Interpretation

CP1451 is a useful discriminator: in the same commanded TX window, the M2SDR
self-RX path sees a clean, stable, high-SNR tone at the expected offset, while
the bladeRF external capture sees a present, high-level, unclipped tone that is
spectrally/phase unstable and fails the tone classifier.

This strengthens the CP1425/CP1431/CP1433/CP1440/CP1447 conclusion: the live
LiteX TX path is not the leading blocker. The active suspicion remains the
external bladeRF/OTA receive/coupling/routing/front-end path or an external
spectral/control artifact. Simple software knobs already closed include
gain/BW/filter, RX2, retune reset, internal bladeRF RFIC BIST, and bladeRF
`[interface-redacted]=fpga`.

Do not rerun CP1451 unchanged. A next useful rung should change the physical
external receive path/coupling or add an independent receiver/spectrum
observation in the same window.
