# Checkpoint 1455 - BW2.0 Bypass Gain48 +100 kHz TX-On/TX-Off Differential

Date: [date-redacted] Europe/Zurich

## Purpose

CP1453 closed the `+500 kHz` BW2.0/bypass/gain48 tone point as no-TX-like.
CP1455 tests the remaining CP1446 variant: the expected bladeRF tone is moved
to `+100 kHz` by changing the M2SDR baseband tone from `-2350000 Hz` to
`-2750000 Hz`.

This answers whether CP1446's apparent high-SNR `+100 kHz` result was real
external LiteX-to-bladeRF signal or another no-TX-like bladeRF pseudo-tone
class.

## Interpretation

CP1455 closes the CP1446 `+100 kHz` variant. The bladeRF capture at
BW2.0/bypass/gain48 already contains a no-TX pseudo-tone class near the
expected `+100 kHz` region, and the TX-on leg is not stronger or cleaner than
no-TX. CP1446's apparent high-SNR `+100 kHz` result should therefore not be
treated as received LiteX TX unless a future physical/independent path change
creates a real TX-on/TX-off delta.

Together:

```text
CP1452: BW3.84, bypass, gain48, +500 kHz -> no-TX-like
CP1453: BW2.0,  bypass, gain48, +500 kHz -> no-TX-like
CP1454: BW2.0,  bypass, gain32, +500 kHz -> lower floor, still no TX delta
CP1455: BW2.0,  bypass, gain48, +100 kHz -> no-TX-like
```

The remote-only bladeRF tone branch is now closed for these tested receive
states and tone placements. The leading explanation remains external
coupling/path/front-end state between M2SDR TX and bladeRF RX1/RF3(B), not
M2SDR TX generation.

CP1455 is not a raw scheduled TRACK metric datapoint and does not unlock the
ladder.

## Do Not Repeat

Do not rerun CP1446/CP1455 `+100 kHz`, BW2.0/bypass/gain48 tone captures
unchanged. The no-TX control already matches TX-on while M2SDR self-RX is
clean.

Do not return to raw scheduled TRACK expecting improvement until there is a
physical/independent receive-path change or a materially different bladeRF
external-RX state that first proves a TX-on/TX-off tone delta.
