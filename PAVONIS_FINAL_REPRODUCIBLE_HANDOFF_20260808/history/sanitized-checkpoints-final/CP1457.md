# Checkpoint 1457 - Retune-Reset BW2.0 Bypass Gain48 TX-Off/TX-On Differential

Date: [date-redacted] Europe/Zurich

## Purpose

CP902 showed that a bladeRF [interface-redacted]/[interface-redacted] reset did not recover an older
TX-on deterministic tone capture, but it did not include a same-geometry no-TX
control. CP1453 through CP1455 then showed that the current BW2.0/bypass tone
captures were no-TX-like, but without a retune reset.

CP1457 combines those two branches:

```text
bladeRF center:    1839650000 Hz
sample rate:       7680000 sps
bandwidth:         2000000 Hz
filter:            bypass
gain:              48 dB requested
retune offset:     +10000000 Hz, then back to target
expected tone:     +500000 Hz
M2SDR TX LO:       1842500000 Hz
M2SDR tone:        -2350000 Hz
```

The question is whether explicitly forcing a bladeRF retune-reset before each
capture lowers the no-TX pseudo-tone/floor or creates a real TX-on delta.

## Interpretation

CP1457 closes the remote-only stale [interface-redacted]/control-state variant at the current
BW2.0/bypass/gain48 tone point. A forced bladeRF [interface-redacted]/[interface-redacted] before
capture did not lower the no-TX pseudo-tone/floor and did not create any
measurable TX-on delta, while M2SDR self-RX proved the transmitter was active
and stable in-window.

This extends CP902 and CP1453-CP1455:

```text
CP902:  retune-reset TX-on only, older tone geometry, still degraded
CP1453: BW2.0/bypass/gain48 on/off, no retune-reset, no TX delta
CP1454: BW2.0/bypass/gain32 on/off, lower floor, no TX delta
CP1455: BW2.0/bypass/gain48 +100 kHz on/off, no TX delta
CP1457: BW2.0/bypass/gain48 on/off with retune-reset, no TX delta
```

The leading branch remains external bladeRF/OTA receive/coupling/routing or
front-end state, not live M2SDR TX, not srsUE scheduler logic, not explicit
RX2, not gain48 masking a weak tone, and not a simple stale bladeRF [interface-redacted]
state corrected by retune-reset.

The user's self-RX discriminator idea is already supported by CP1425, CP1433,
CP1440, CP1441, CP1447, and now this tone-specific CP1457 variant: M2SDR
self-RX is positive in the same broad experiment class while bladeRF remains
no-TX-like or sub-threshold.

CP1457 is not a raw scheduled TRACK metric datapoint and does not unlock the
ladder.

## Do Not Repeat

Do not rerun BW2.0/bypass/gain48 retune-reset on/off tone capture unchanged.
It is no-TX-like with only `+0.010 dB` TX-on RMS delta.

Any fresh companion self-RX RF run should keep the corrected CP1432 decode
center split and immediate/no-arm self-RX path. Do not treat stale wrong-center
self-RX decode failures as evidence against the bladeRF receive-path branch.
