# Checkpoint 1459: BW3.84MHz Normal-Filter Gain48 TX-Off/TX-On Differential

## Purpose

CP1443 tested the live-geometry M2SDR tone with bladeRF RX bandwidth
`3.84 MHz`, RX FIR filter `normal`, and gain48, but only with TX active.
CP1452 later proved the sibling `3.84 MHz`/`bypass` bladeRF tone class could be
reproduced with no transmitter active. CP1459 closes the missing SSB-compatible
normal-filter control: run the exact same receive geometry with TX off, then
run TX on with the same-window M2SDR self-RX discriminator.

This checkpoint changes no `ue_sync_nr.c` sync/anchor logic and is not a raw
scheduled TRACK metric datapoint.

## Interpretation

CP1459 reclassifies CP1443's BW3.84/normal/gain48 TX-on bladeRF tone result as
no-TX-like. At an SSB-compatible bandwidth and normal filter, turning on the
M2SDR transmitter changes bladeRF RMS by only `+0.085 dB`, while the M2SDR
self-RX instrument sees a clean `79.99 dB` tone in the same window.

Together with CP1452 through CP1458, this closes the remaining safe current
external-tone receiver-side filter/BW/gain variants that were likely to reveal
a hidden software-only link-budget fix. The leading branch remains external
bladeRF/OTA receive/coupling/routing/front-end state or physical path, not live
M2SDR TX, the M2SDR self-RX instrument, simple bladeRF filter mode, SSB-
compatible BW3.84 normal filtering, retune-reset, explicit RX2, or gain48 floor
masking alone.

CP1459 does not raise the raw scheduled TRACK gate and does not justify new
scheduler/anchor edits. The next meaningful ladder step needs a physical or
independent receive-path change, or explicit approval for a hardware-affecting
bladeRF state branch such as calibration/correction or bias-tee experiments.
