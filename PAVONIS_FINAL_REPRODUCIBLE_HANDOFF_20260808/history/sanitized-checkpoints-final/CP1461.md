# Checkpoint 1461: bladeRF Frontier Read-Only Audit

## Purpose

After CP1452-CP1460 closed the safe external-tone bandwidth/filter/gain
software bracket as no-TX-like, CP1461 records the current bladeRF state and
the remaining CLI safety boundary before any hardware-affecting branch.

This checkpoint is read-only. It does not transmit, receive, retune, stream,
change loopback, change `rx_mux`, change filters, toggle bias tees, or modify
calibration/correction state.

## CLI Safety Boundary

The available CLI still cannot read current bladeRF2 correction state:

```text
print correction rx1
print: Invalid parameter (correction)
Error: Invalid parameter provided

print correction rx2
print: Invalid parameter (correction)
Error: Invalid parameter provided
```

`calibrate lms show` is still not a useful bladeRF2 readback path:

```text
calibrate: Only use this calibration on bladeRF x40 and x115 devices.
```

The CLI exposes flash backup/restore help:

```text
flash_backup <file> cal
flash_restore <file> [<address> <length>]
```

That can protect flash calibration data, but it does not provide a readback or
restore point for volatile runtime DC/IQ correction values applied by
`calibrate dc` or `calibrate iq`.

## Interpretation

CP1461 finds no obvious idle bladeRF digital-state fault after the CP1452-CP1460
external-tone closures. The device is not stuck in loopback, counter mux,
wrong bit mode, abnormal clock source, enabled bias tee, custom filter, stale
process ownership, or high-temperature/power-fault state.

This does not raise the raw scheduled TRACK gate. It does sharpen the remaining
frontier:

- physical RF/coupling/attenuator/antenna path into bladeRF;
- bladeRF normal external-RF receive/front-end behavior that is not visible in
  idle readbacks;
- calibration/correction state, which remains an explicit-approval branch
  because current correction values are not readable through this CLI;
- bias-tee or other hardware-affecting experiments, also explicit-approval
  branches.

Do not rerun CP1425-CP1461 unchanged. The next meaningful ladder step needs a
physical/independent receive-path change, or explicit approval for a bounded,
reversible-as-possible hardware-affecting bladeRF branch with before/after
logs.
