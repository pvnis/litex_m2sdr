CLI boundary evidence:

- `calibrate dc <rx|tx>` calibrates or directly applies DC correction values
  for current frequency/gain settings.
- `calibrate iq <rx|tx> <gain|phase> <value>` sets IQ gain/phase balance.
- `calibrate table dc` and `calibrate table agc` generate correction tables
  and write files.
- `set biastee` enables or disables a bias tee on a channel.
- `set rx_mux`, `set [interface-redacted]`, `set filter`, and related commands are
  state-changing paths.
- `flash_backup` is read-like and was already used in CP1462 for the
  calibration region.
- `flash_restore`, `poke`, and low-level register writes are explicit write
  paths.
- `peek rfic|pll|dac|lms|si` can read bladeRF2 AD9361/clock-related registers,
  but interpreting useful register addresses is a low-level exploratory path,
  and the original Pavonis brief warns against exploratory AD9361/M2SDR
  low-level commands unless reviewed.

## Conclusion

CP1463 confirms that the installed bladeRF CLI does not expose a safe
read-only correction-state view that would unlock the next rung. The remaining
material branches are still:

- a physical/independent receive-path change;
- a materially different external bladeRF receive/front-end state that is not
  a closed repeat;
- explicit approval for bounded runtime DC/IQ calibration or correction writes;
- explicit approval for bias-tee or other hardware-affecting path changes;
- reviewed low-level `peek` register inspection if a specific register plan is
  defined first.

Do not rerun CP1425-CP1463 unchanged. Do not edit `ue_sync_nr.c` sync/anchor
logic while the raw TRACK metric remains below threshold.
