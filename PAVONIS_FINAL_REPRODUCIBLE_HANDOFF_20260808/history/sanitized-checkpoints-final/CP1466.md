## Configured RX State

The harness configured the same receive class used by CP1437/CP1438:

```text
set loopback none
set rx_mux BASEBAND
set filter rx normal
set agc rx off
set frequency rx 1839650000
set samplerate rx 5760000
set bandwidth rx 4608000
set gain rx 60
```

Readback in the same `bladeRF-cli` session, before `peek`:

- loopback: `none`
- RX mux: `BASEBAND`
- RX FIR filters: `normal (default)`
- AGC: disabled
- RX frequency: `1839649998 Hz`
- sample rate: `5760000`
- bandwidth: `4608000`
- RX1 gain: overall `60 dB`, full `71 dB`
- RX1 RSSI: preamble `-77 dB`, symbol `-85 dB`
- temperature/power during configured read: `29.8 C`, `4.928 V`, `0.54 A`,
  `2.66 W`
- RF routing print stayed in the same class as CP1435-CP1438:
  `RX1: RFIC 0x0 (A_BAL) <= SW 0x0 (OPEN)` and
  `TX1: RFIC 0x0 (TXA) => SW 0x0 (OPEN)`

The separate post-state read returned to the default bladeRF idle state
(`2400000000 Hz`, `30.72 Msps`, `18 MHz`, AGC enabled), so the configured
register snapshot is the in-session evidence, not the later post-state.

## Key Register Observations

The full corrected-range dump is in the CP1466 log. Critical configured-state
readbacks:

| Family | Values | Interpretation |
| --- | --- | --- |
| ENSM/state | `0x013=0x01`, `0x014=0x28`, `0x015=0x84`, `0x016=0x00`, `0x017=0x1a` | Low nibble of `0x017` is `0xa`, matching AD9361 FDD state by local names. No invalid ENSM state. |
| RX power-down overrides | `0x050=0x00`, `0x054=0x00`, `0x055=0x00` | No obvious RX LO or RX ADC power-down override bit is set. |
| RX VCO/lock-adjacent | `0x247=0x02` | Local names mark bit `0x02` as RX VCO lock. CP1465 idle had `0x42`; the configured state keeps lock set and clears the CP overrange-low bit. |
| Manual gain registers | `0x109=0x4c`, `0x10a=0x58`, `0x10b=0x00`, `0x10c=0x4c`, `0x10d=0x18`, `0x10e=0x00` | RX1/RX2 manual gain programming is not symmetric at the LPF register, but the later readback registers are symmetric. This is state evidence only; it is not by itself a fault. |
| RX gain readback | `0x2b0=0x4c`, `0x2b1=0x18`, `0x2b2=0x00`, `0x2b5=0x4c`, `0x2b6=0x18`, `0x2b7=0x00` | RX1 and RX2 gain readbacks are symmetric; digital gain readbacks are zero. |
| RX overrange signals | `0x2b8=0x00`, `0x2b9=0x00` | No RX1/RX2 overrange signal bits are latched in the configured readback. |
| BIST/test | `0x3f4=0x00`, `0x3f5=0x00`, `0x3f6=0x00` | No BIST/data-port test mode is latched. |
| RSSI/power families | `0x150-0x15d`, `0x160-0x163`, `0x1a7-0x1ae` captured | Values move from idle-class CP1465 values after RX configuration, as expected; they do not show a clear clamp/all-zero fault. |

## Conclusion

Status: configured-RX diagnostic complete, no ladder unlock.

CP1466 closes the immediate gap left by CP1465: the bladeRF/AD9361 register
state also looks sane after normal RX-only configuration to the CP1437/CP1438
receive geometry. It weakens the theories of configured-state RX LO/ADC
power-down, RX VCO unlock, latched RX overrange, latched BIST/test mode,
invalid ENSM state, or asymmetric RX1/RX2 gain readback as the explanation for
the no-TX-like bladeRF receive path.

It does not prove active streaming is healthy under a live TX window, and it
does not improve the raw scheduled-TRACK metric. The frontier remains external
bladeRF/OTA receive path, physical coupling/routing, or an explicitly approved
bounded hardware-affecting branch such as calibration/correction or bias-tee
testing. Do not rerun CP1425-CP1466 unchanged.
