# CP1469 - bladeRF USB SuperSpeed Host Audit

Date: [date-redacted] Europe/Zurich

## Goal

CP1469 checks a remaining safe variable from the cabled-ladder notes: whether
the bladeRF on `[host-redacted]` is currently attached through a degraded USB
Hi-Speed path rather than SuperSpeed/USB3.

This checkpoint did not start a transmitter, run srsUE/gNB, receive RF
samples, retune, set bladeRF state, configure streams, run calibration, toggle
bias tees, poke registers, restore flash, edit `ue_sync_nr.c`, or move to
Android/NAS/PRACH. It only reads host USB topology, sysfs, and `bladeRF-cli`
identity/version information.

## USB Topology

`lsusb -t` shows the bladeRF under the USB3 root hub, not the 480M USB2 hub:

```text
/:  Bus 004.Port 001: Dev 001, Class=root_hub, Driver=xhci_hcd/4p, 10000M
    |__ Port 002: Dev 002, If 0, Class=Vendor Specific Class, Driver=[none], 5000M
```

`lsusb -d 2cf0:` identifies the device as:

```text
Bus 004 Device 002: ID 2cf0:5250 Nuand LLC bladeRF 2.0 micro
```

The matching sysfs entry confirms the same link speed:


## Conclusion

Status: USB host-speed audit complete, no ladder unlock.

The bladeRF 2.0 micro is currently attached to `[host-redacted]` as a SuperSpeed USB
device: Linux reports `5000M` in both `lsusb -t` and sysfs, and
`bladeRF-cli info` reports `USB speed: SuperSpeed`. The older cabled-ladder
branch that suspected a degraded Hi-Speed/USB2 connection is closed for the
current host state.

This does not raise the raw scheduled-TRACK link budget and does not explain
the bladeRF/OTA receive failure by itself. The active frontier remains an
external receive-path/coupling/front-end issue or an explicitly approved
hardware-affecting branch such as bounded calibration/correction or bias-tee
testing. Do not rerun CP1469 unchanged unless the physical USB connection or
host topology changes.
