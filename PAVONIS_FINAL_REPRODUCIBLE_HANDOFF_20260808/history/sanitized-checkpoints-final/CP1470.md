## Source Findings

Nuand's shared bladeRF2 header defines low-band SPDT as value `0x2` and
comments that path as `RF1 <-> RF3`. The same source maps RX frequencies from
`70 MHz` through `3 GHz` to low-band SPDT plus `AD936X_B_BALANCED`, and maps
RX frequencies from `3 GHz` through `6 GHz` to high-band SPDT plus
`AD936X_A_BALANCED`.

The shared helper `_modify_spdt_bits_by_freq()` writes the selected SPDT value
into the RX1 field for `BLADERF_CHANNEL_RX(0)`, and `rfic_host.c` calls that
helper during channel enable. The public `bladerf_get_rf_switch_config()` API
reads `rx1_spdt_port` from the same RFFE RX1 SPDT field and `rx1_rfic_port`
from the AD9361 RX RF-port input.

## Mapping CP1467

CP1467 active RX geometry was centered at `1839650000 Hz`, which lies inside
the Nuand low-band RX range (`70 MHz` to `3 GHz`). CP1467 measured:

```text
rx1_rfic=1
rx1_spdt=2
```

CP869 rendered the same active route as:

```text
RX1 <= RF3(B)
```

CP1470 maps that to the expected upstream low-band route:

```text
RX1 active low-band path: AD936X_B_BALANCED through SPDT_LOWBAND
SPDT_LOWBAND: RF1 <-> RF3
```

Therefore CP1467's active `rx1_spdt=2 rx1_rfic=1` is not an unexpected or
disabled route. It is the expected bladeRF2 low-band RF3/B route for the
current `1.83965 GHz` receive point.
