# CP1471 - Self-RX Decode-Center Guardrail Audit

Date: [date-redacted] Europe/Zurich

## Goal

CP1471 turns the CP1431/CP1432 stale decoder-center lesson into a reusable
preflight guard before any future same-window M2SDR self-RX experiment. It
checks local runner scripts that analyze gNB-owned RX append files and verifies
whether their RX-append targeted/sweep decode blocks use the RX append center
and SSB center instead of the gNB TX guard center.

This checkpoint did not start a transmitter, receive RF samples, run gNB,
srsUE, bladeRF capture, retune, set bladeRF state, run calibration, toggle
bias tees, poke registers, restore flash, edit `ue_sync_nr.c`, or move to
Android/NAS/PRACH.

## Findings

The full local audit found ten CP14xx runner scripts with RX-append decode
blocks:

```text
SCRIPTS_WITH_RX_APPEND_DECODE=10
OVERALL_RC=1
```

Nine historical runners are intentionally classified as stale because their
RX-append analysis blocks use the TX guard center variables:

```text
VERDICT=STALE_TX_CENTER_DECODE
HAS_RX_DECODE_CENTER=0 HAS_RX_DECODE_SSB=0 HAS_TX_GUARD_CENTER=1 HAS_TX_GUARD_SSB=1
```

Those include CP1415, CP1416, CP1418, CP1420, and CP1425 through CP1429. They
are valid historical artifacts, but should not be reused unchanged for a future
same-window self-RX branch.

The corrected CP1432 runner passes the guard:

```text
SCRIPT=cp1432_run_live_nrsa_immediate_gnb_readstream_rxappend_rxcenterdecode.sh
VERDICT=SAFE_RX_CENTER_DECODE
HAS_RX_DECODE_CENTER=1 HAS_RX_DECODE_SSB=1 HAS_TX_GUARD_CENTER=0 HAS_TX_GUARD_SSB=0
OVERALL_RC=0
```

The historical CP1425 runner fails the guard as expected:

```text
SCRIPT=cp1425_run_live_nrsa_with_immediate_gnb_readstream_rxappend.sh
VERDICT=STALE_TX_CENTER_DECODE
OVERALL_RC=1
```

## Conclusion

Status: guardrail checkpoint complete, no ladder unlock.

CP1471 does not change the raw downlink budget. It closes the "fix or avoid
stale decoder-center path" prerequisite for any future same-window M2SDR
self-RX revisit: run the CP1471 validator first, and only proceed with a runner
that passes `SAFE_RX_CENTER_DECODE` or uses an equivalent RX-center/SSB decode
block. The known-safe local candidate is CP1432's corrected runner.

The material frontier remains unchanged from CP1470: moving up the ladder still
requires a raw scheduled TRACK metric improvement, most likely through a
physical or independent receive-path/coupling/routing change, or explicit
approval for a bounded calibration/correction, bias-tee, or other
hardware-affecting bladeRF front-end branch.
