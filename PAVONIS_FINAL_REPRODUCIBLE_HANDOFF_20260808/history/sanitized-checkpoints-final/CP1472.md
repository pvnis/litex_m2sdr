- `bladerf2_common.c`: https://raw.githubusercontent.com/Nuand/bladeRF/master/fpga_common/src/bladerf2_common.c

Relevant source-backed constraints:

- At `1839650000 Hz`, bladeRF2 RX is in the low-band map. CP1470 already
  resolves this to `SPDT_LOWBAND=0x2`, `RF1 <-> RF3`, and
  `AD936X_B_BALANCED`, matching CP1467's active RF3/B route.
- The bladeRF2 API has a read call for bias-tee state and a separate set call;
  enabling a bias tee is therefore a state-changing/hardware-affecting branch.
- The bladeRF2 API documents low-level RFIC accessors as development/testing
  tools requiring care; RFIC writes are outside the current no-approval scope.
- The libbladeRF API defines bladeRF2 gain modes, including default AGC and
  manual gain, and documents RX gain limits as frequency-dependent. CP1439 and
  CP1466/CP1467 already show the current gain/readback class is not a simple
  gross flatline.

  revisits.

The next RF run should not be an unchanged CP1425-CP1471 repeat. If a physical
or independent receive-path/coupling/routing variable changes, rerun the raw


approval because it will change bladeRF/front-end state. The least ambiguous
approval-boundary branches are bounded runtime calibration/correction,
bias-tee or other front-end path changes, or a materially different external
receive path.
