## Branch Boundaries

Branch A is preferred because it changes the receive/coupling/routing variable
without mutating bladeRF state. After the physical change, rerun the raw
scheduled TRACK gate only; do not edit scheduler logic.

Branch B requires explicit approval because CP1461/CP1463 show the current
runtime correction state is not readable through this CLI. CP1462 protects the
flash calibration region but does not make runtime correction writes fully
reversible.

Branch C requires explicit approval because bias tee is hardware-affecting.
The packet requires user confirmation that the connected path can tolerate the
chosen bias-tee state, and requires readback before and after any toggle.

Branch D is reserved for a genuinely different external RX/front-end path, not
a renamed repeat of CP1425-CP1472.

Rejected next steps remain:

```text
rerun CP1425-CP1472 unchanged
edit ue_sync_nr.c sync/anchor logic
run Android/NAS/PRACH while downlink raw gate is sub-threshold
run calibration/correction/bias-tee commands without explicit approval
use self-RX without CP1471 guard passing
```
