# CP1474 - Next-Branch Guard

Date: [date-redacted] Europe/Zurich

## Goal

CP1474 turns the CP1473 approval packet into a small local guard that makes the
next branch choice machine-checkable. The guard refuses by default, refuses
hardware-affecting branches without explicit approval tokens, and reports
readiness for branch A only when a physical-path change is explicitly declared.

This checkpoint is no-RF and no-state-change. It did not start a transmitter,
receive RF samples, run gNB, srsUE, or bladeRF capture, retune, set bladeRF
state, calibrate, toggle bias tees, poke registers, restore flash, edit
`ue_sync_nr.c`, or move to Android/NAS/PRACH.

## Results

Default invocation refuses and waits for a decision:

```text
VERDICT=WAITING_FOR_USER_DECISION
VALID_BRANCHES=A_PHYSICAL_PATH_CHANGED,B_APPROVED_CAL_CORR,C_APPROVED_BIASTEE,D_EXTERNAL_RX_PATH
```

Branch A reports readiness only when the physical-path-change flag is present:

```text
VERDICT=READY_BRANCH_A_RAW_TRACK_RERUN_AFTER_PHYSICAL_CHANGE
NEXT_GATE=mean_track_snr_and_percent_opportunities_ge_minus_10_db
FORBID=ue_sync_nr_anchor_edits_android_nas_prach
```

Branch B refuses without explicit approval:

```text
VERDICT=REFUSE_BRANCH_B_MISSING_EXPLICIT_APPROVAL_TOKEN
REQUIRED=PAVONIS_APPROVAL_TOKEN=I_APPROVE_CP1474_BRANCH_B
```

The same pattern is encoded for branch C with
`PAVONIS_APPROVAL_TOKEN=I_APPROVE_CP1474_BRANCH_C`, plus explicit bias-tee
channel and state. Branch D requires a non-empty materially different external
RX/front-end description.
