# CHECKPOINT 1485 - CP1484 offline SSB-offset and window-CFO analysis

Date: [date-redacted] Europe/Zurich

## Goal

Analyze the CP1484 back-to-back continuous-helper and live-gNB bladeRF captures
without touching RF hardware. The immediate question was whether the CP1484
full-capture failures are explained by a simple declared SSB offset or static
CFO correction, or whether they look more like frame/window-local coherence
loss.

This checkpoint is software-only. It does not edit `ue_sync_nr.c`, does not
change radio state, and does not start a hardware branch.

## Method

1. Ran CP837 full-capture SSB-offset sweeps over both captures at
   `11.52 Msps`, center `1842500000 Hz`, first `11520000` samples.
2. Swept declared offsets:
   `-30000,-25000,-20000,-17500,-15000,-12500,-10000,-9000,-7500,-5000,-2500,0,2500,5000,7500,10000,12500,15000,17500,20000,25000,30000 Hz`.
3. Ran CP815 CFO-corrected PBCH checks on the top 12 CP814 aligned-window
   candidates for each capture.
4. Aggregated CP815 results by source window and correction value.

## Interpretation

The CP837 full-capture sweeps do not recover either CP1484 capture by changing
the declared SSB offset. This weakens the theory that the CP1484 one-shot
failure is just a wrong declared SSB frequency/offset.

The CP815 top-window sweeps still find local PBCH-decodable windows in both
captures. Crucially, those windows decode at `0 Hz` correction already, while
many failed windows stay PBCH-negative across the whole correction set. That
weakens the theory that a simple static CFO correction is the missing fix.

The evidence fits a frame/window-local validity problem: the signal contains
valid SSB/PBCH islands, but full-capture acquisition and many otherwise
CSI-visible windows do not maintain enough local phase/timing/coherence to
decode PBCH. Live remains worse than helper in CP1484, but the helper control
also shows intermittent coherence degradation relative to CP1482/CP1483.

## Verdict

CP1485 does not justify a hardware branch or a sync-anchor scheduler edit. It
pushes the software frontier toward timing/cadence/coherence analysis across
captured frames:

- not weak RF power: CP1482/CP1483 and CP1484 raw helper amplitude already
  showed usable path/power when coherence is good;
- not a simple declared SSB offset: both CP837 sweeps have `0` expected PCI1
  recoveries;
- not a simple static CFO correction: good CP815 windows decode at `0 Hz`, and
  bad windows are mostly correction-insensitive;
- still a live runtime/cadence problem, with current intermittent helper
  degradation as a control that must be understood before moving up the ladder.

Recommended next checkpoint: offline frame-phase/cadence analysis on CP1484
and the adjacent CP1482/CP1483 good controls. Compare PBCH-OK window positions,
same-window refcorr peak offsets/frequency, and SSB island periodicity before
running more RF.
