# CHECKPOINT 1489 - CP1482 vs CP1484 SSB-region correlation

Date: [date-redacted] Europe/Zurich

## Goal

Make the CP1488 result more PBCH/SSB-specific. CP1488 showed that broad local
waveform correlation can remain high in CP1484 CSI-only/PBCH-negative windows.
CP1489 asks whether the split is concentrated in SSB symbols and PBCH-bearing
regions rather than being a whole-window effect.

This checkpoint is local-only. It does not run RF, edit `ue_sync_nr.c`, change
hardware state, or move to NRSA/PRACH/Android/NAS.

## Interpretation

CP1489 supports a PBCH/SSB-specific degradation rather than a generic power or
whole-window-correlation failure. CP1484 CSI-only medians are lower than CP1482
across all SSB regions, and the PBCH-bearing regions are weaker than PSS/SSS.
That matches the observed CSI-rich/PBCH-poor behavior.

However, CP1484 is not uniformly missing the PBCH waveform. Selected CSI-only
windows have high PBCH-region correlation to the expected CP1481 reference and
reasonable region EVM by this comparative metric, yet `ssb_file_test` still
reports PBCH KO. That points at a narrower decoder-facing issue: exact timing
used by PBCH search, CFO handed to PBCH demodulation, PBCH DMRS/channel
estimate behavior, or a local inconsistency between the CSI-search anchor and
the PBCH-search path.

CP1489 also makes the CP1484 PBCH-OK rows suspicious as a separate island:
they are weak against the phase-calibrated CP1481 reference across all SSB
regions, unlike CP1482 PBCH-OK rows. Treat them as local decode islands, not
as proof that the degraded helper run has the same coherent reference-aligned
PBCH structure as CP1482.

## Verdict

Do not rerun CP1478-CP1489 unchanged. The next no-RF checkpoint should target a
small set of CP1484 CSI-only rows with high PBCH-region correlation and run
`ssb_file_test` with explicit diagnostic timing/CFO controls, if available, to
test whether the decoder can be made to recover PBCH when forced to the
CSI/region-correlation anchor.

If forced timing/CFO does not recover those rows, the remaining boundary moves
from broad coherence to PBCH DMRS/channel-estimation or PBCH payload-specific
behavior. Still do not move to NRSA/PRACH/Android/NAS and do not start a
hardware branch.
