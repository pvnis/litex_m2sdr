# CHECKPOINT 1490 - CP1484 forced track-at-offset PBCH diagnostic

Date: [date-redacted] Europe/Zurich

## Goal

Test the CP1489 frontier directly: for a CP1484 CSI-only/PBCH-negative window
that still has high PBCH-region correlation, can PBCH be recovered if the
decoder is forced to the CSI/region-correlation timing and CFO instead of using
the normal blind PBCH search path?

This checkpoint is local-only. It does not run RF, edit `ue_sync_nr.c`, change
hardware state, or move to NRSA/PRACH/Android/NAS.

## Method

`srsran_ssb_csi_search()`, not the PBCH `srsran_ssb_search()` path. To avoid
patching srsRAN source or `ue_sync_nr.c`, CP1490 added a local diagnostic
binary in the artifact directory that calls the public
`srsran_ssb_track_at_offset()` API:

All listed PBCH OK cases require `n_hf=0`. The same high-SNR forced cases with
`n_hf=1` return different payload bytes and CRC KO.

The original blind path for the exact same 1 ms window remains:

```text
measure - search pci=1 ... snr=-27.8 cfo=-4644.7 delay=+40.8
search - t_offset=0 pci=0 payload=[00 00 00] ... crc=KO
```

## Interpretation

CP1490 is a material isolation result. The CP1484 degraded helper capture does
contain PBCH-decodable content in at least one CSI-only/PBCH-negative window.
The normal blind PBCH search path fails that window, but
`srsran_ssb_track_at_offset()` recovers PBCH when forced to the CSI-derived
timing and a compatible CFO/half-frame choice.

This shifts the immediate boundary away from RF path, payload, raw power, broad
coherence, and generic PBCH-region absence. The failing surface is now the
decoder-facing bridge from CSI/PSS timing/CFO to blind PBCH search/selection:
timing handoff, coarse CFO handoff, PBCH DMRS selection/thresholding, or
half-frame/SSB candidate handling in the blind search path.

The link is still not ladder-ready: this is an offline forced decode of one
window, not a raw scheduled TRACK pass. But it proves the CP1484 helper
CSI-only/PBCH-negative class is not inherently below PBCH decodability.

## Verdict

Do not rerun CP1478-CP1490 unchanged. The next no-RF checkpoint should expand
this forced-track diagnostic across a small set of CP1484 CSI-only windows and
compare forced PBCH success against the blind `ssb_file_test` failure mode,
then inspect the blind PBCH search/selection handoff. Keep `ue_sync_nr.c`
sync/anchor logic frozen and do not move to NRSA/PRACH/Android/NAS until the
raw/live RF/coherence gate is resolved.
