# Checkpoint 1494 - CP1492 blind PBCH DMRS threshold gate

## Question

CP1493 proved that the CP1492 live CSI-only window
`win1p0ms_start0p016500s` contains PBCH-decodable content:
forced `srsran_ssb_track_at_offset()` recovered PCI1, payload
`[0e 20 06]`, `sfn_lsb=5`, and CRC OK. This checkpoint checks whether the
blind `srsran_ssb_search()` failure is caused by timing/CFO/half-frame
selection, or by the blind PBCH DMRS pre-decode threshold.

No RF was run. No `ue_sync_nr.c` sync/anchor logic was edited.

## Source audit

Relevant source behavior:

- `srsRAN_4G/lib/src/phy/sync/ssb.c`
  - `SSB_PBCH_DMRS_DEFAULT_CORR_THR` is `0.5`.
  - `srsran_ssb_init()` replaces non-normal threshold values, including `0.0`,
    with that default.
  - `srsran_ssb_search()` selects a PBCH DMRS candidate and returns no result
    before PBCH decode if `pbch_meas.corr < q->args.pbch_dmrs_thr`.
  - `srsran_ssb_track_at_offset()` bypasses `ssb_select_pbch()` and the blind
    DMRS threshold; it decodes directly with caller-provided
    `t_offset`/`coarse_cfo_hz`/`ssb_idx`/`n_hf`.

NRSA threshold plumbing exists but is not currently usable from the top-level
SA path:

- `srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c` passes
  `args->pbch_dmrs_thr` into `srsran_ssb_init()`.
- `srsRAN_4G/srsue/src/phy/nr/slot_sync.cc` passes
  `slot_sync::args_t::pbch_dmrs_thr` into `ue_sync_nr`.
- `srsRAN_4G/srsue/hdr/phy/nr/sync_sa.h` has
  `sync_sa::args_t::pbch_dmrs_thr`, but `get_slot_sync()` does not forward it.
- `srsRAN_4G/srsue/src/phy/phy_nr_sa.cc` initializes `sync_args` with only
  sample rate and thread priority, so no runtime config path was found for this
  threshold.

## Interpretation

The CP1492 `016500` blind-KO window is not failing because blind search cannot
find the PSS/SSS timing, because PBCH content is absent, or because only forced
track can decode it. The same public `srsran_ssb_search()` path decodes it
once the blind PBCH DMRS pre-decode threshold is reduced from `0.5` to `0.25`.

This narrows the immediate software boundary to the blind PBCH DMRS threshold
gate in `ssb.c`, and to NRSA plumbing that currently leaves the SA slot-sync
path on the library default threshold. The repeated `n_hf=0` result remains
consistent with CP1490-CP1493, but CP1494 shows the first actionable gate is
the threshold, not half-frame selection.
