## Interpretation

CP1499 reinforces the no-hardware direction. The helper path is not absent:
it has clean metadata, stronger raw amplitude than live, `333/847` CSI PCI1,
and `22/847` PBCH windows. But it remains far below the CP1482 good-control
class (`317/847` PBCH) and has weak broad refcorr (`0.0929`). This is another
helper-degraded/cadence-state sample, not a proof of weak RF path/power.

The live gNB leg is worse at the RF decoder while the host-visible TX is still
valid. Digital TX passes before and after DMA (`6/14` PBCH OK cases,
pre/post-DMA OK), gNB write/release/worker counters are clean, and the bladeRF
capture metadata is continuous. Yet the RF capture is PBCH-dead over the
aligned sweep (`0/847`) with only sparse CSI (`36/847`) and very weak
correlation to both the old CP1145 reference and the same-window pre-DMA
payload (`~0.032`).

That points back at live real-time TX cadence/coherence or a decoder-facing
window/coherence effect below the host-visible dump, not a static link-budget
or hardware-path failure. It also shows the continuous helper control can
remain degraded in the current state, so a single helper pass/fail should not
be over-interpreted without window-local analysis.
