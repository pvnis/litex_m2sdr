## Method

CP1506 mines exact `(relative_timing, cfo)` pairs from CP1505 that satisfy:

```text
PBCH CRC OK on:
  live_159_forced_only
  helper_190_forced_only
  helper_056_threshold_control

PBCH CRC KO on:
  live_069_unrecovered
```

It ranks universal candidates by minimum positive-case SNR, then performs a
fresh validation run on all four saved vectors using the top candidate only.

## Interpretation

CP1506 compresses the CP1505 feasibility result from `2535` candidates per case
to one universal saved-vector candidate. This strengthens the public-search
handoff theory: the failed public path is close to a decodable timing/CFO
hypothesis, and a small deterministic fallback can recover the forced-only
positive classes without producing a false positive on the known live negative.

The primary candidate is not purely a threshold workaround. `live_159` decodes
with PBCH DMRS corr `0.208680272`, below the `0.25` threshold, while
`helper_190` and `helper_056` are above `0.25`. A runtime prototype would still
need an explicit fallback decode policy, not just the existing public DMRS
threshold lowering.
