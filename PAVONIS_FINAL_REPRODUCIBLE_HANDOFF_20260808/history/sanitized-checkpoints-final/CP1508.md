## Interpretation

CP1508 reinforces the no-hardware branch. The continuous helper is again
signal-bearing with healthy raw amplitude and clean metadata, but it is still
not the CP1482 good-control class: only `15/847` PBCH windows despite
`304/847` CSI windows. The helper therefore remains coherence/window-degraded
in the current state, not absent.

The live leg is worse at the RF decoder while host-visible TX is still valid.
The pre/post-DMA digital guard decodes (`6/14`, pre/post-DMA OK), Soapy write
errors/timeouts remain zero, bladeRF capture metadata is continuous, and the
same-window live pre-DMA vector exists. Yet the live RF capture is PBCH-dead
over the aligned sweep (`0/847`) with only `28/847` expected-PCI CSI windows
and weak RF-to-same-window-pre-DMA correlation (`0.0897`). This supports the
user's current theory: the blocker is frame-scale live cadence/coherence or
decoder-facing window quality, not a static weak path/power fault.

The one live `late_count=1` in sampled worker summaries is worth carrying
forward as a cadence clue, but it is not by itself a complete explanation:
release-late trace and timed-commit-slip counts remain zero, Soapy errors are
zero, and digital TX is still PBCH-valid.
