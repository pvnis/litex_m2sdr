## Interpretation

CP1509 splits CP1508 cleanly:

- Current helper CSI/PBCH-KO windows are decoder-facing and fallback-rescuable.
  They pass public search at the already-live `0.25` threshold and pass the
  CP1506-style `dt=-17,cfo=1250,hf=0` forced policy.
- Current live windows are not fixed by the CP1506 policy. Two live top-CSI
  windows have only weak forced islands and no public threshold rescue even at
  near-zero threshold. The third live window can be public-threshold rescued,
  but only at `0.10` and lower, below the current live acquisition threshold.

This argues against implementing a broad runtime fallback as the next ladder
move. The fallback is useful for helper/current threshold-gated classes, but
the fresh live CP1508 windows remain frame/coherence/cadence-limited. The next
work should inspect live gNB cadence/timestamp behavior around the CP1508
capture and the observed worker `late_count=1`, rather than adding another
decode fanout to `ssb.c`.
