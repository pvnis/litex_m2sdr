## Interpretation

CP1510 demotes the sampled CP1508 worker `late_count=1` from a direct
explanation for the CP1508 bad RF windows to a later-run health note. It is not
contemporaneous with the RF windows analyzed in CP1509.

The stronger CP1508/CP1509 conclusion remains:

- live digital TX is valid and Soapy/release counters are clean;
- the CP1508 live RF windows are decoder-facing/coherence-limited;
- helper windows of the same run are fallback/threshold-rescuable, but live
  windows are not rescued by CP1506's small policy;
- broad runtime fallback implementation is still not the next ladder move.
