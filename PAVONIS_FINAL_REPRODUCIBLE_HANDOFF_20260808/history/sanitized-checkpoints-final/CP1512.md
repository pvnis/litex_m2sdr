Capture interval mapping was evaluated under both wall-clock anchors because NUC gNB logs do not timestamp individual writes:

- If first TX metadata row is anchored at `TX_START_REQUEST_UTC`, bladeRF capture overlaps `257` logical data groups, `3084` rows, and `257.000 ms` of TX data in the 1 s capture.
- If first TX metadata row is anchored at `TX_READY_UTC`, bladeRF capture overlaps `257` logical data groups, `3073` rows, and `256.089 ms` of TX data in the 1 s capture.
- In both mappings, capture-window data-group deltas remain the same class (`1/2/7/8 ms`) and max group gap is `8 ms`.

The write metadata therefore does not show a short write, ret/flag corruption, missing HAS_TIME-at-burst-start, or empty-EOB problem at the OCUDU-to-Soapy boundary during the capture.

## Conclusion

CP1512 moves the cadence boundary below OCUDU's Soapy `writeStream()` calls. The live RF failure persists with valid digital TX and clean write-return/flag/HAS_TIME metadata. The next useful rung is below this boundary: M2SDR plugin worker/release/timed-DMA timing and buffer-consumption instrumentation around the capture interval, or an exact capture-window post-write/DMA reconstruction. Do not rerun CP1511/CP1512 unchanged.
