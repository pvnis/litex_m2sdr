## Goal

CP1512 proved the live gNB writeStream boundary is mechanically clean during
the bladeRF capture interval. The remaining boundary is below OCUDU's Soapy
`writeStream()` calls, in the LiteX M2SDR plugin worker/release/timed-DMA
timing or buffer-consumption path. CP1513 adds a bounded, default-off TX worker
packet trace so the next live RF run can map individual plugin release events
against the bladeRF capture wall-clock interval.

No RF transmitter was started in this checkpoint.

## Source Change

Files changed:

- `litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp`
- `litex_m2sdr/software/soapysdr/LiteXM2SDRDevice.hpp`

New env-gated trace:

- `M2SDR_SOAPY_TX_WORKER_TRACE_PATH`: enables a TSV trace file.
- `M2SDR_SOAPY_TX_WORKER_TRACE_LIMIT`: row cap, default `65536`, clamped to `1000000`.
- `M2SDR_SOAPY_TX_WORKER_TRACE_FLUSH_PERIOD`: flush cadence, default `256`.

Trace schema marker:

```text
# PAVONIS_M2SDR_TX_WORKER_TRACE v1
```

Rows include wall-clock ns, sequence, submit stage, DMA handle/ring slot,
sample count, flags before/after duplicate-HAS_TIME suppression, source time,
adjusted release time, hardware-time snapshot, slip, late decision,
reader/user/hw/sw/cleared counters before and after release, zero-copy state,
and sample rate.

## Interpretation

CP1513 does not change the raw scheduled-TRACK gate and does not prove the RF
link. It makes the next live helper/gNB comparison actionable at the current
frontier: with `M2SDR_SOAPY_TX_WORKER_TRACE_PATH` enabled, the gNB log/package
can be paired with a bounded TSV of per-packet LiteX plugin worker/release
events and wall-clock timestamps. That should show whether the failed bladeRF
capture interval overlaps late commits, HAS_TIME suppression anomalies,
reader/counter jumps, ring reuse, or otherwise clean worker behavior.
