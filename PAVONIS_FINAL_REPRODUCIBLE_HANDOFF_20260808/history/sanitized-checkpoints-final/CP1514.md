
## Verdict

CP1514 is a diagnostic pass, not a ladder unlock.

It does not expose an M2SDR worker late/drop/return/sequence fault during the
capture interval. The live worker rows are early, not late, and the OCUDU
`writeStream()` metadata remains clean.

It does expose a live-only boundary condition below OCUDU: one OCUDU HAS_TIME
write can become two plugin HAS_TIME-pre DMA packets when it crosses the
plugin TX remainder boundary. The current dedup logic prevents the second DMA
header from carrying HAS_TIME, but the first HAS_TIME can still be attached to
the currently-open remainder buffer. That is the best next software target for
frame-scale cadence/coherence loss.

Do not rerun CP1514 unchanged. Next checkpoint should be a no-RF
build-smoked, default-off guard or trace around HAS_TIME/remainder alignment:
when a fresh HAS_TIME write arrives and the current TX remainder buffer already
contains earlier untimed samples, release/zero-pad that old remainder without
stealing the timestamp, then start the HAS_TIME burst on a fresh DMA buffer.
Only after that build-smokes should an RF A/B be spent.
