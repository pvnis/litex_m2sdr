## Goal

Build-smoke a default-off LiteX M2SDR Soapy TX guard for the CP1514 live-only
HAS_TIME/remainder boundary before spending another RF run. This checkpoint is
no-RF: no hardware branch approval, no `ue_sync_nr.c` sync/anchor edits, and no
PRACH/Android/NAS work.

## Change

Local source:

```text
litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp
litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRDevice.hpp
```

The new guard is controlled by:

```text
M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER
```

Default behavior is unchanged. When the env is enabled and a fresh
`SOAPY_SDR_HAS_TIME` write with positive `timeNs` arrives while an existing TX
remainder buffer contains earlier untimed samples, `writeStream()` releases the
partial untimed remainder first and then lets the HAS_TIME write start on a
fresh DMA buffer. The first 16 activations log:

```text
M2SDR TX HAS_TIME remainder align: releasing partial untimed buffer ...
```

This targets the CP1514 observation that one clean OCUDU HAS_TIME write could
become two plugin HAS_TIME-pre packets at the remainder boundary.
