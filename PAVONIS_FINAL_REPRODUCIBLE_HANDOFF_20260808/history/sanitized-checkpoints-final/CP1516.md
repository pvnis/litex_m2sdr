## Goal

Run the continuous helper and live gNB back-to-back on the same hardware after
CP1515, enabling `M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1` for the live gNB
leg. This tests whether the CP1514 live-only plugin-side duplicate-HAS_TIME
boundary was the cause of the intermittent frame-scale coherence loss.

No hardware branch was approved or used. No `ue_sync_nr.c` sync/anchor logic was
edited. No PRACH/Android/NAS work was attempted.

## Verdict

CP1516 is a software-boundary pass and an RF-gate fail.

The CP1515 guard did exactly what it was meant to do: plugin HAS_TIME-pre no
longer doubles OCUDU HAS_TIME rows, duplicate positive HAS_TIME-pre rows drop
to zero, and `dedup_suppressed` drops from CP1514's `5013` total / `194`
capture-overlap rows to `0` / `0`. It also did this without new late rows,
sequence gaps, OCUDU return mismatches, negative returns, flag mutations, or
HAS_TIME offset errors.

The remaining live RF problem is therefore not fully explained by the fixed
remainder/HAS_TIME duplication. The live RF remains sparse and floor-level
despite valid host TX and clean lower-boundary timestamps. Do not rerun CP1516
unchanged as the next step. Keep the guard available for future live baselines,
but move the active debugging target to the remaining cadence/coherence source
below clean OCUDU writes and clean plugin HAS_TIME release.
