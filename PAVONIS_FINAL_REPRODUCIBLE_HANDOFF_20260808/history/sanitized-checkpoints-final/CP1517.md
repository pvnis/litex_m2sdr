## Method

`cp1517_cp1516_window_trace_cadence_map.py` maps CP1516 RF sweep windows onto
the worker trace by capture wall-clock time. It groups 1 ms windows into
PBCH-OK, CSI-only, and no-CSI classes, then compares nearby HAS_TIME rows,
previous/next HAS_TIME distance, local source gaps, local wall gaps, late rows,
dedup rows, and trace-row density.

This is only a host-submit-time proxy: worker `wall_ns` describes submit/release
timing, not proven RF sample egress timing.

## Verdict

CP1517 does not explain the CP1516 live sparse/floor-class RF result with a
simple remaining host-side HAS_TIME cadence, duplicate-HAS_TIME, or local source
gap theory. CP1516 already fixed the exact HAS_TIME/remainder duplication, and
CP1517 shows the residual good/bad RF windows do not align cleanly with the
remaining host-submit timing features.

The next useful branch should move below host submit timing: capture-window
DMA/header/effective-egress reconstruction, or lower LitePCIe reader /
TimedTXArbiter instrumentation. Do not rerun CP1517 unchanged.
