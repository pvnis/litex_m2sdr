# Checkpoint 1521 - Worker/Reader Cadence Audit

Date: [date-redacted] Europe/Zurich

## Goal

Use existing CP1519 and CP1520 live gNB worker traces to check whether the
remaining sparse live RF could be explained by host/plugin DMA-ring behavior:
missing worker rows, sequence gaps, duplicate HAS_TIME, worker late decisions,
or a sustained LitePCIe reader queue stall.

This checkpoint is artifact-only. No RF, SSH, or hardware-affecting commands
were run.

## Method

Added and ran:

```text
cp1521_worker_reader_cadence_audit.py
```

The script parses:

- CP1519 live worker trace:
  `txdump/litex_tx_worker_trace.tsv`
- CP1519 bladeRF capture timing log:
  `cp1223_[date-redacted]T2056ZCP1519_LIVE_GNB_TXBACKOFF10_DMA_WINDOW_AFTER_GUARD_sens_collect_capture_summary.log`
- CP1520 live worker trace:
  `txdump/litex_tx_worker_trace.tsv`
- CP1520 bladeRF capture timing log:
  `cp1223_[date-redacted]T2112ZCP1520_LIVE_GNB_TXBACKOFF10_LOWOVERHEAD_AFTER_HELPER_sens_collect_capture_summary.log`

It maps trace rows to the actual bladeRF capture window using chunk 0 start and
chunk 351 end epoch timestamps, then summarizes sequence continuity, HAS_TIME,
dedup, late rows, source cadence, host submit cadence, and
`user_after - hw_after` queue-depth proxies.

## Verdict

CP1521 does not find a host/plugin DMA-ring explanation for live RF sparsity.
Across CP1519 and CP1520, the bladeRF capture windows have no trace sequence
gaps, no duplicate-HAS_TIME regression, no dedup rows, no worker late rows, no
counter negative deltas, and no sustained zero-copy queue stall.

This closes the current saved worker/reader trace as the next explanation. The
remaining boundary stays below clean OCUDU writes, clean plugin HAS_TIME
release, clean capture-window post-DMA contents, and clean host/plugin
DMA-ring accounting.

Next useful work should observe effective live egress below the DMA ring. The
lowest-risk next checkpoint is a bounded live-gNB diagnostic that samples the
existing read-only TimedTX counters (`m2sdr_rf --timed-tx-counters`) during the
live capture window. If that is not discriminating, the next software step is a
default-off egress counter/trace surface around TimedTX output or the
FPGA/AD9361 handoff. Do not rerun CP1520 unchanged, do not start a hardware
branch, and do not edit `ue_sync_nr.c` sync/anchor logic.
