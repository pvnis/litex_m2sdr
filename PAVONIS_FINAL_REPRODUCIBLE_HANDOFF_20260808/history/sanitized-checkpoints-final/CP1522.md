# Checkpoint 1522: TimedTX Counter Probe Blocked by [host-redacted] Reachability

Date: [date-redacted] Europe/Zurich

## Goal

Run the next no-hardware live-gNB diagnostic after CP1521: sample existing
LiteX TimedTX counters with `m2sdr_rf --timed-tx-counters` during the same
bladeRF receive window used for the CP1520 live geometry. This is intended to
test whether the live sparse RF windows correlate with TimedTX late,
underrun, drop, descriptor, state, or sample-counter behavior below the clean
OCUDU/plugin/DMA-ring boundary.

## Method

Created three local helpers:

- `cp1522_remote_nuc4_start_live_timedtxcounter_window.sh`
  - [host-redacted] start variant based on the guarded live CP1516 start path.
  - Keeps `M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1`.
  - Reduces diagnostic load by defaulting worker trace and OCUDU write dump
    off.
  - Starts a short sampler after gNB ready:
    `m2sdr_rf --timed-tx-counters`, `240` samples, `0.075 s` period.
  - Does not reset counters and does not run module/gateware operations.
- `cp1522_run_live_gnb_timedtx_counter_probe.sh`
  - live-only wrapper at CP1520 geometry:
    center `1842500000`, SSB `1839650000`, `11.52 Msps`, `10 MHz`, bladeRF
    gain `36`, normal filter, one second capture.
  - After the first failed attempt, patched it to hard-abort before [host-redacted] TX if
    [host-redacted] SSH preflight fails.
- `cp1522_analyze_timed_tx_counter_probe.py`
  - parses the counter log and, when present, maps samples to the bladeRF
    capture epoch interval.

## Verdict

offline/unreachable from both the local laptop and [host-redacted]. The first attempt is
not valid evidence about bladeRF RF quality. It does prove the existing
TimedTX counter sampler can run during live gNB without read failures, and
that [host-redacted] live host-visible TX remained PBCH-decodable in that failed attempt.

First failed stage for this checkpoint: receiver-host reachability before
Stage 5 independent downlink capture.
