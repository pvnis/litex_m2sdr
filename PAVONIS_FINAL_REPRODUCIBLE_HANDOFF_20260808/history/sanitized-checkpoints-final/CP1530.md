# Checkpoint 1530 - self-RX window to worker queue map

Date: [date-redacted]

## Goal

Use saved CP1528 and CP1529 artifacts only, with no RF/SSH/radio work, to test
whether the live self-RX good/bad 1 ms windows line up with the worker trace
queue-proxy excursions, worker late rows, dedup rows, or sequence gaps.

## Method

I added `cp1530_map_selfrx_windows_worker_queue.py`. It reads:

- CP1528 and CP1529 live self-RX aligned-sweep CSVs.
- The matching live `litex_tx_worker_trace.tsv` files.
- The matching RX readback sidecars.

Because the self-RX append start is inferred rather than timestamped per
sample, the script maps windows under two explicit anchors:

- `rx_readback_hw`: file `t=0` at the RX sidecar `hardware_time_ns`.
- `first_worker_source`: file `t=0` at the first worker `source_time_ns`.

It writes one mapped CSV per run plus a summary:
`cp1530_selfrx_worker_queue_map_[date-redacted]/SUMMARY.md`.

## Interpretation

The queue-proxy burst is not a clean discriminator. Under both plausible
anchors and in both CP1528/CP1529, PBCH-good and dead 1 ms windows both occur
near high queue-proxy intervals. The median queue proxy for PBCH and dead rows
is also low and similar.

Worker late/dedup/sequence errors are also not the current explanation:
CP1529 has `0` late rows, `0` dedup, and `0` sequence gaps, yet live aligned
self-RX remains sparser than helper (`153/847` versus `239/847`). CP1528 has
only `2` late rows, and CP1530 does not show those as a clean PBCH/dead split.

The queue-proxy excursions remain worth monitoring as a symptom, but CP1530
closes "simple worker queue spike/late/dedup/seq-gap explains the live self-RX
sparsity" for the saved CP1528/CP1529 windows.
