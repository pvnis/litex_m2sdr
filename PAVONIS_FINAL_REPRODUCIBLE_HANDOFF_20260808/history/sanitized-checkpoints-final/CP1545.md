## Health Caveats

The gNB side looked clean in the collected summary: OCUDU/Soapy write summaries
had zero partial/over returns, timeouts, and errors; LiteX worker/release
summaries had `late_count=0`, `underflow_count=0`, and `acquire_errors=0` in
the sampled rows.

The srsUE/bladeRF side was not clean enough to treat CP1545 as a pristine raw
gate baseline:

- `153` `[RF] Overflow` log lines
- `98` overflow lines before the first TRACK event/opportunity
- `55` overflow lines from first TRACK onward
- `28` `rf_blade_imp.c:1549: TX failed: Invalid operation or parameter` lines

Therefore CP1545 should be used as candidate/static-window evidence, not as a
clean comparison against CP1540's raw SNR baseline.

## Conclusion

CP1545 confirms the raw scheduled TRACK window remains below the gate and
produces zero scheduled PBCH hits. With every scheduler action path disabled,
the trace-only side/rolling/direct probes still found CRC-positive alternate
candidate windows. That strengthens the CP1543 conclusion: decoder-visible
external IQ/candidate windows can exist while the live scheduled static TRACK
window remains KO.

Because the run had TRACK-era RF overflows and UE-side TX failures, the next
software-only checkpoint should keep the same passive candidate-state direction
but add a stricter UE RF-health gate or bounded IQ/candidate capture around a
high-SNR CRC-KO row. Do not rerun CP1545 unchanged.
