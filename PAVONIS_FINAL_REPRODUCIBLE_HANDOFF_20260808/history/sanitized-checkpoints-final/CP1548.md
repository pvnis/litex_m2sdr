## Source Audit

The TX failure is not the tolerated late-transmit path. In
`srsRAN_4G/lib/src/phy/rf/rf_blade_imp.c`, `rf_blade_send_timed()` calls:

- `bladerf_sync_tx(...)` at line `1301`.
- If the return is `BLADERF_ERR_TIME_PAST`, lines `1541-1547` report a late
  TX event but do not return the hard error.
- If any other nonzero status is returned, lines `1548-1550` log
  `TX failed: ...` and return the libbladeRF error.

Therefore CP1545/CP1546 line `1549` means `bladerf_sync_tx()` returned a hard
non-`TIME_PAST` error. The string `Invalid operation or parameter` is the
libbladeRF status string for that nonzero return, not a PBCH/SSB decoder result
and not a gNB TX-side counter.

The surrounding srsRAN radio code explains the trigger class. In
`srsRAN_4G/lib/src/radio/radio.cc`, when the RF layer detects a receive/timing
gap that is too large to fill with zeros, it logs:

- `Detected RF gap ... Sending end-of-burst.`
- then calls `tx_end_nolock()`, which sends a zero-sample EOB with
  `srsran_rf_send_timed2(..., end_of_burst=true)`.

The CP1545/CP1546 logs show exactly that pattern: TRACK-era RF gap/overflow
messages interleaved with the `rf_blade_imp.c:1549` hard TX failures.

## Interpretation

The active failure for the next candidate-probe rung is a UE/bladeRF
receive-loop timing/gap plus TX/EOB control-path issue, not a gNB TX payload
decode failure and not a current proof that live TX is dead on M2SDR self-RX.

The cleanest next software-only path is to create or use a default-off
receive-only/skip-EOB guard for the passive candidate probe so TRACK-era RF
health can be evaluated without the radio layer sending zero-sample EOB writes
after receive gaps. That should avoid `ue_sync_nr.c` sync/anchor edits and
preserve the CP1546 policy that all candidate actions remain disabled.

Do not rerun CP1545, CP1546, or CP1547 unchanged. The next RF retry should be
the lightest passive candidate probe that can still expose alternate offsets,
with an explicit clean gate of zero TRACK-era RF overflows and zero
`rf_blade_imp.c:1549` TX failures.
