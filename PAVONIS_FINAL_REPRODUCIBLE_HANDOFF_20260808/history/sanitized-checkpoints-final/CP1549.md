# Checkpoint 1549: default-off RF-gap TX-end skip guard

Date: [date-redacted] Europe/Zurich

## Purpose

Implement the next no-RF software step from CP1548: a default-off guard that
can suppress the srsRAN radio layer's automatic zero-sample EOB when it detects
a large RF receive/timing gap. This is intended for a future passive
candidate-probe rerun where we need a clean TRACK-era UE RF-health gate.

This checkpoint does not run RF, SSH, bladeRF, srsUE, gNB, NRSA/PRACH/Android/
NAS, or edit `ue_sync_nr.c`.

Post-check only, outside the experiment: `[host-redacted]` answered ICMP after the
checkpoint (`1/1`, `0%` loss, RTT about `143 ms`). It was not used in CP1549.

## Change

File changed:

- `srsRAN_4G/lib/src/radio/radio.cc`

Default behavior is unchanged. When `PAVONIS_RADIO_SKIP_RF_GAP_TX_END` is unset
or set to `0`, `radio.cc` keeps the existing behavior:

- detect large RF gap
- log `Detected RF gap ... Sending end-of-burst.`
- call `tx_end_nolock()`
- send the zero-sample EOB through the RF backend

When `PAVONIS_RADIO_SKIP_RF_GAP_TX_END=1`, only that automatic RF-gap EOB is
suppressed. The log changes to:

```text
Detected RF gap of %.1f us. Skipping end-of-burst due to PAVONIS_RADIO_SKIP_RF_GAP_TX_END.
```

The guard does not touch NR sync/anchor code and does not suppress normal TX
calls by default. It is deliberately narrow because CP1548 tied the CP1545/
CP1546 hard `rf_blade_imp.c:1549` failures to the RF-gap `tx_end_nolock()` EOB
path.

## Interpretation

CP1549 creates the minimal software control needed for the next candidate-probe
retry, but it does not prove RF improvement. It has not been deployed to
`[host-redacted]` and no RF run used it.

The next step is to sync/build this guarded source on `[host-redacted]` when using
that receiver again, then rerun the lightest CP1546-class passive candidate
probe with:

- all candidate action paths still disabled
- `PAVONIS_RADIO_SKIP_RF_GAP_TX_END=1`
- explicit RF-health gate requiring zero TRACK-era RF overflows and zero
  `rf_blade_imp.c:1549` TX-failed lines

If the guard removes TX-failed/EOB hard errors but raw scheduled TRACK remains
below threshold, use the candidate hits as cleaner static-window evidence. If
the guard does not remove the failures, the invalid-parameter source is below
or beyond the automatic RF-gap EOB path and needs a more direct bladeRF TX
metadata/debug trace.
