# Checkpoint 1557: no-candidate skip-EOB-off TRACK control

Date: [date-redacted] Europe/Zurich

## Purpose

Separate CP1555's no-candidate acquisition/SFN failure from the
skip-EOB/no-candidate combination.

CP1555 ran with passive TRACK candidate probes disabled and
`PAVONIS_RADIO_SKIP_RF_GAP_TX_END=1`, but failed before TRACK. CP1557 keeps the
same guarded binary, CP1540 geometry, raw trace, disabled passive candidates,
and all action paths disabled, but changes the wrapper default to
`PAVONIS_RADIO_SKIP_RF_GAP_TX_END=0`.

No `ue_sync_nr.c` sync/anchor logic was edited. No ladder move was attempted.

## Source/Runtime Audit

Before RF, the source was checked to avoid misattributing CP1555's SFN failure:

- `track_sidecheck`, rolling sidecheck, and direct-offset check are gated inside
  `ue_sync_nr_run_track()` and their functions return early when their flags
  are disabled.
- The FSM dispatch calls `ue_sync_nr_run_find()` in FIND and
  `ue_sync_nr_run_track()` only in TRACK.
- `nr_sa_cell_search_test.cc` exposes `post_select_ttis` but no obvious CLI
  knob to raise the internal SFN-sync trial count beyond the observed `100`.

Therefore the CP1555 disabled passive-candidate flags are not expected to
execute before TRACK.

## Interpretation

CP1557 proves the no-passive-candidate configuration can acquire, complete SFN
sync, and reach TRACK on the guarded binary when skip-EOB is off. CP1555's
pre-TRACK SFN failure is therefore not a stable no-candidate-only blocker.

The result still does not raise the raw scheduled-TRACK gate: mean SNR remains
around `-21.4 dB`, with `0/66 >= -10 dB`, `0/66 >= -15 dB`, and zero scheduled
PBCH hits. Because no RF-gap EOB/send or skip branch fired, CP1557 also does
not measure the old EOB/TX-failed branch.

This run creates a useful clean no-candidate/raw baseline with no TRACK-era RF
overflows and no TX-failed lines. It should not be rerun unchanged. The next
changed RF step should rerun the no-candidate baseline with skip-EOB enabled
again, because CP1557 shows acquisition is possible and CP1555's exact
skip-EOB-on failure was likely a run scatter/SFN instance. If that next
skip-EOB-on repeat reaches TRACK, compare raw metric and RF health against
CP1557.
