# Checkpoint 1560: [host-redacted]-only self-RX helper preflight plus live/helper A/B

Date: [date-redacted] Europe/Zurich

## Purpose

Run the requested [host-redacted]-only self-RX loopback discriminator while keeping
`[host-redacted]`, bladeRF, and srsUE out of the experiment:

1. First run a continuous-helper M2SDR self-RX preflight using the CP1395
   default reference vector.
2. Then run live gNB through the CP1532 RX-append-metadata M2SDR self-RX path.
3. Replay the same fresh live pre-DMA CF32 vector through the continuous helper.

This is a changed variant of CP1547/CP1556 because it adds a same-checkpoint
helper preflight before the live A/B. The discriminator is unchanged: if live
is sparse or dead even on M2SDR self-loopback while helper is strong, the fault
points at live TX cadence/egress rather than the external receiver.

## Interpretation

The requested discriminator did not trigger. CP1560 again shows that live gNB
is PBCH-positive on the M2SDR's own RX, with clean RX metadata and healthy
host-visible TX. The helper remains about `22 dB` higher level and denser, so
live runtime/cadence/egress quality remains relevant, but CP1560 does not
support "live is sparse even in self-loopback" as a current explanation.

No raw scheduled-TRACK metric was run in CP1560, so the ladder gate is
unchanged. The active split remains: M2SDR self-RX can see decodable live TX,
while the external scheduled-TRACK/raw path remains sub-threshold in the latest
raw checkpoints. Do not rerun CP1547/CP1556/CP1560 unchanged.

Post-check only, outside the experiment: `[host-redacted]` was reachable after the
checkpoint (`ping 2/2`, `0%` loss, average RTT `87.640 ms`) and helper SSH
returned `[host-redacted]`, uptime `4:24`. It was not used in CP1560.
