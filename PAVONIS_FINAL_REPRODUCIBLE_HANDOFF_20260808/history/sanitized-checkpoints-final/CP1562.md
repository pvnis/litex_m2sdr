# Checkpoint 1562 - Live gNB TX Force-Attenuation 5 dB Raw TRACK Gate

Date: [date-redacted] Europe/Zurich

## Goal

Stop sweeping RX-side variables and test the largest remaining TX-side
amplitude mismatch: live gNB had historically read back near `20 dB` TX
attenuation, while helper replay uses `TX_ATT_DB=5`. Force the live gNB toward
the helper attenuation class and re-measure the raw scheduled TRACK gate.

This stays under the active gate:

- no `ue_sync_nr.c` sync/anchor edits
- no passive candidate actions
- no fallback/anchor/follow/override actions
- judged by raw scheduled `event=track_opportunity meas_snr` and scheduled
  PBCH CRC hits

## Implementation

The first YAML-only attempt set `tx_gain: 5` and failed before RF:

```text
TX gain 5.0 dB is out of range [-89, 0] dB.
OCUDU ERROR: Invalid radio configuration.
```

That made the sign/API mismatch explicit. OCUDU's Soapy validator accepts
non-positive TX gain values, while the LiteX-M2SDR Soapy TX API represents TX
attenuation as a positive named gain, `ATT`.

I added a default-off OCUDU Soapy bridge:

- `PAVONIS_SOAPY_TX_FORCE_ATT_DB`
- `radio_soapy_device::set_gain(direction, channel, name, value)`
- `set_tx_gain_unprotected()` calls `device->setGain(SOAPY_SDR_TX, ch, "ATT",
  forced_att_dB)` when the env is set

Local build smoke passed. The patched files were deployed to [host-redacted] after
backing up the remote sources:

- `radio_soapy_device.h.cp1562_pre_tx_force_att_[date-redacted]`
- `radio_soapy_impl.cpp.cp1562_pre_tx_force_att_[date-redacted]`

## Caveat

The corrected run proves the patched [host-redacted] binary was present, the force
environment reached the gNB process, the runner wrote `TX_ATT_DB=5`, and the
RF run reached TRACK cleanly. It does not contain a direct in-log AD9361
TX-attenuation register readback or `PAVONIS_SOAPY_TX_READBACK_PATH` sidecar.

If this branch is revisited, do not rerun CP1562 unchanged. Use the existing
TX readback sidecar or a bounded active register read to capture the TX
attenuation proof directly, then pair it with the raw TRACK metric.

## Conclusion

CP1562 does not support the `20 dB` versus `5 dB` TX-attenuation mismatch as an
obvious raw scheduled-TRACK unlock under the corrected patched/env-forced live
run. The raw gate remains failed:

- mean TRACK SNR is still about `-21.4 dB`
- `0/75` opportunities reach `-10 dB`
- scheduled PBCH remains `0`
- TRACK-era RF health and gNB TX counters are clean

Do not rerun CP1557, CP1558, CP1561, or CP1562 unchanged.
