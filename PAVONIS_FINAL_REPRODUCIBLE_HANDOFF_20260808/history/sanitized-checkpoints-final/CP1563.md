# Checkpoint 1563 - TX_ATT5 Post-Setup Readback Raw TRACK

Date: [date-redacted] Europe/Zurich

## Goal

Close CP1562's remaining caveat: verify whether the live gNB actually runs
with helper-class TX attenuation (`5 dB`) while measuring the same raw
scheduled-TRACK gate.

The user also asked to confirm whether CP1562 raised RSRP by about `15 dB`.
That comparison is included here before moving to the next coherence/cadence
branch.

No `ue_sync_nr.c` sync/anchor logic was edited. No RX-side variable sweep was
performed.

## Changes

Added a CP1563 [host-redacted] runner:

```text
cp1563_run_gnb_b3_txatt5_marked_tx_readback_detached.sh
```

It sets `PAVONIS_SOAPY_TX_READBACK_PATH` inside the live gNB process and
records the sidecar path in `TX_READY.env`.

Added a CP1563 wrapper:

```text
cp1563_run_live_nrsa_txatt5_readback_traceonly_nocandidates_cp1540_geometry.sh
```

It reuses the CP1562 raw-TRACK geometry and fetches/parses the TX readback
sidecar. A path parser bug found during CP1563A was fixed by stripping CR from
the parsed remote path.

While CP1563A was running, the sidecar exposed a control bug: the original
CP1562 TX attenuation set happened before Soapy `setupStream()`, and stream
setup restored the TX attenuation to `20 dB`. I patched
`ocudu/lib/radio/soapy/radio_soapy_impl.cpp` to:

- log `PAVONIS_SOAPY_TX_FORCE_ATT_DB` post-set readback,
- reassert forced TX named gain `"ATT"` after `setupStream()`,
- log the post-setup TX reassert marker.

## CP1563A Result

Stamp:

```text
[date-redacted]CP1563_TXATT5_READBACK_TRACEONLY_NOCANDIDATES_CP1540_GEOMETRY
```

The harness and NRSA command returned cleanly, but this was not a valid
TX_ATT5 raw-TRACK result:

- TX readback sidecar printed into the [host-redacted] start log.
- Readback showed `gain_db=20.000000000`, not `5`.
- srsUE/bladeRF found PCI1 in cell search but failed SFN before TRACK.
- TRACK opportunities: `0`.

CP1563A therefore proves the CP1562 attenuation override did not stick through
live stream setup. It also explains why CP1562 could not be treated as proof of
`5 dB` live TX attenuation.

## CP1562 RSRP Check

CP1562 did not show a `~15 dB` scheduled-TRACK RSRP rise versus CP1557.

| Run | TX evidence | TRACK opportunities | TRACK mean RSRP | TRACK mean SNR | PBCH hits |
| --- | --- | ---: | ---: | ---: | ---: |
| CP1557 | no forced TX_ATT | `66` | `-27.798379 dB` | `-21.412879 dB` | `0` |
| CP1562 | env requested `TX_ATT=5`, no readback | `75` | `-27.548880 dB` | `-21.444933 dB` | `0` |
| CP1563A | sidecar proved still `20 dB` | `0` | n/a | n/a | `0` |
| CP1563B | sidecar proved `5 dB` | `68` | `-25.854897 dB` | `-22.033853 dB` | `0` |

CP1562's scheduled-TRACK mean RSRP was only about `+0.25 dB` above CP1557.
CP1563B, with confirmed `5 dB` TX attenuation, was about `+1.94 dB` above
CP1557 on scheduled-TRACK mean RSRP. Neither is a `15 dB` observed receive
level rise.

The selected cell-search hit is not a reliable proof of the full TX drive
delta by itself: CP1557 selected at `RSRP=-5.423 dB`, CP1562 at
`RSRP=-9.208 dB`, and CP1563B at `RSRP=-5.445 dB`.

## Conclusion

CP1563B is the valid attenuation-forced result. It proves the live gNB can be
made to report TX attenuation `5 dB` after stream setup, but the raw scheduled
TRACK gate still fails:

```text
mean SNR=-22.03385294117647 dB
0/68 >= -10 dB
0 scheduled PBCH hits
```

This closes the TX-attenuation/power branch as a simple raw-gate fix. CP1562
did not actually prove `5 dB`; CP1563A caught that, and CP1563B corrected it.
Even corrected, the raw gate did not improve.

Next work should stop amplitude/RX/EOB variable testing and move to the user's
coherence/cadence branch: force the live gNB TX path to emit as one continuous
helper-like stream instead of segmented timed bursts, then compare raw TRACK
SNR and readback/health against CP1563B.

Do not rerun CP1562, CP1563A, or CP1563B unchanged.
