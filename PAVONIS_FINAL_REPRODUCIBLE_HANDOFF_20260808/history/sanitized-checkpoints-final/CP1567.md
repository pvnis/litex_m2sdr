# CP1567 Shared PRACH Timing Instrumentation Build/Deploy Report

Date: [date-redacted] Europe/Zurich

## Goal

Add shared wall-clock and monotonic timestamps to the continuous-TX PRACH path before the next RF run, so CP1568 can align:

- gNB PRACH detector trace rows.
- srsUE PRACH configuration/generation/transmission logs.
- srsUE MAC random-access timing logs.
- Existing bladeRF PRACH TX debug metadata.

This checkpoint is source/build/deploy only. It ran no RF transmission and made no hardware-affecting change.

## Source Changes

`ocudu/lib/phy/upper/channel_processors/prach/prach_detector_generic_impl.cpp`

- Added `clock_gettime()` helper.
- Extended `PAVONIS_PRACHDET_TRACE` rows with:
  - `wall_ns=...`
  - `mono_ns=...`

`srsRAN_4G/srsue/src/phy/prach.cc`

- Added timestamped `PAVONIS_SRSUE_PRACH_CFG` rows for:
  - `set_cell`
  - `generate_buffer`
  - `transmitted`
- Initial local build found the wrong struct field name (`prach_cfg.carrier.nof_prb`); corrected it to this fork's `prach_cfg.carrier_nof_prb`.

`srsRAN_4G/srsue/src/phy/nr/sf_worker.cc`

- Extended the existing `SRSUE_PRACH_TX_DBG` line from:
  - `PRACH-TX max_abs=...`
- To:
  - `PRACH-TX wall_ns=... mono_ns=... max_abs=...`

`srsRAN_4G/srsue/src/stack/mac_nr/proc_ra_nr.cc`

- Added env-gated `PAVONIS_SRSUE_RA_TIMING` console rows with:
  - `wall_ns`
  - `mono_ns`
  - `prach_occasion`
  - `preamble_index`
  - `ra_rnti`
  - `tti`
  - `s_id/t_id/f_id/ul_carrier_id`

No `ue_sync_nr.c` sync/anchor logic was edited.

## Result

CP1567 passes as a no-RF instrumentation checkpoint. The next RF checkpoint should keep the CP1564 force-continuous live gNB TX baseline and enable:

```text
PAVONIS_PRACHDET_TRACE=1
PAVONIS_SRSUE_PRACH_CFG_DBG=1
SRSUE_PRACH_TX_DBG=1
PAVONIS_RF_BLADE_TX_DBG=1
```

The goal is to align gNB detector rows and UE PRACH/RA TX rows by `wall_ns`/`mono_ns`, then determine whether the actual preamble-0 bursts arrive in the detector windows and why they remain below acceptance threshold.
