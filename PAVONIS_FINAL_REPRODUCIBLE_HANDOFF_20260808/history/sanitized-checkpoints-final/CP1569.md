## Interpretation

CP1569 closes CP1568's capture caveat. The gNB is looking at the right occasions and now we have predemod raw files for those occasions. The UE/bladeRF side emits strong PRACH buffers, but the gNB predemod input does not show a corresponding raw-energy bump and the p0 detector metric remains sub-threshold.

The current hard blocker is therefore upstream of detector threshold/RAR/MAC:

```text
bladeRF PRACH TX is strong and timed, but the live gNB/M2SDR uplink predemod input is not visibly receiving it.
```

Do not run a threshold-only PRACH detector override as the next step; false positives already cross threshold away from the real UE attempts, while the true p0 predemod windows look floor-class. Next work should isolate uplink visibility into the gNB RX/predemod path using a controlled bladeRF-to-M2SDR uplink signal or an equivalent same-window gNB RX input check, without changing hardware unless explicitly approved.
