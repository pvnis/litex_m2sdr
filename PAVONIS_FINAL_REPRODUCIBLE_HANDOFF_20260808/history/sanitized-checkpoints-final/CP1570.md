# CP1570 Force-Continuous gNB RX-Append Uplink Tone Report

Date: [date-redacted] Europe/Zurich

## Goal

After CP1569 showed strong/timed bladeRF PRACH transmissions but floor-class live gNB predemod rows, CP1570 tested whether the live gNB-owned M2SDR RX path could see a controlled bladeRF TX1 uplink tone. This kept the CP1564 force-continuous downlink baseline active and added a gNB-owned RX append at the uplink center.

Power context from the previous branch: the requested CP1562/CP1563 RSRP audit did not show a `~15 dB` scheduled-TRACK rise from TX attenuation alone (`-27.798379`, `-27.548880`, `-25.854897 dB` for CP1557/CP1562/CP1563B). CP1564's continuous-write change, not power alone, created the positive downlink baseline (`mean TRACK RSRP=-12.8096 dB`, `31/70` scheduled PBCH hits).

## Interpretation

CP1570 is a useful failure: the live gNB force-continuous downlink baseline was active, RX append readback matched the uplink center, the append filled for 3 s with zero reported overflows, and the controlled +100 kHz uplink tone was not detected.

The result is consistent with CP1569's observation that the live gNB/M2SDR uplink predemod input did not visibly receive strong/timed bladeRF PRACH bursts. However, because the bladeRF TX helper still ended with `bladeRF_tx_exit=124`, CP1570 should not be the final discriminator between:

```text
current bladeRF TX -> M2SDR physical uplink path is not delivering a visible signal
```

and:

```text
the live gNB-owned RX append/control path is not seeing a signal that raw standalone M2SDR RX can see
```

Next changed control should be a current standalone CP798-style raw LiteX/M2SDR RX tone check with the same bladeRF TX1 uplink tone class, preferably with a shorter/cleaner bladeRF TX command. If that standalone raw RX control passes strongly, CP1570 points back at the live gNB-owned RX path/control state. If it also fails, the current physical uplink visibility or bladeRF TX path has degraded and the PRACH ladder should not continue until that is resolved.

Do not rerun CP1570 unchanged.
