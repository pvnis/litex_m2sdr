## Interpretation

CP1571 is a current gross uplink physical-path pass:

```text
bladeRF TX1 -> LiteX/M2SDR standalone raw RX is alive on current hardware.
```

This directly addresses CP1570's caveat. CP1570 did not see the tone in a live gNB-owned RX append, but CP1571 sees the same class of tone strongly in standalone raw RX with a clean bladeRF exit. Therefore the leading suspect shifts away from "current physical bladeRF TX to M2SDR RX path is dead" and toward one of the live-gNB/M2SDR full-duplex RX/control conditions:

```text
live gNB-owned RX append/control state
live gNB TX-active/full-duplex state affecting uplink RX visibility
or a mismatch between the standalone raw RX helper and the gNB RX/predemod input path
```

CP1571 is not a perfect strict-bin pass because the exact-bin gate is brittle for this current capture, and the raw capture stopped early with `readStream error: -4`. Those caveats do not erase the key result: the current physical uplink tone is plainly visible in standalone LiteX/M2SDR RX.

Do not rerun CP1571 unchanged. Next work should isolate why the live gNB-owned RX path misses a tone that standalone raw LiteX/M2SDR RX sees, preferably by testing a TX-active/full-duplex standalone M2SDR condition or another changed live-gNB RX-control probe. Do not go to threshold-only PRACH or higher ladder until uplink visibility inside the live gNB path is explained.
