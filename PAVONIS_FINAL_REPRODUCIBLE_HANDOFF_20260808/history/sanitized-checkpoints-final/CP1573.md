# CP1573 Standalone M2SDR Zero-TX Full-Duplex Preflight Failure Report

Date: [date-redacted] Europe/Zurich

## Goal

CP1572 showed a useful but not clean failure when standalone M2SDR RX was run
full-duplex with a nonzero downlink-frequency M2SDR TX tone while bladeRF TX1
sent a `+100 kHz` uplink tone. CP1573 was intended to run the adjacent zero-TX
full-duplex control:

```text
M2SDR RX center: 1747500000 Hz
M2SDR TX center: 1842500000 Hz
sample rate: 11520000 Hz
RX/TX bandwidth: 10000000 Hz
RX gain: 50 dB
TX mode: zero
bladeRF TX1 tone: +100000 Hz, gain 45, AMPL_Q11=512
```

## Result

The run did not reach RF and is not a zero-TX full-duplex datapoint.

```text
stamp=[date-redacted]CP1573_STANDALONE_M2SDR_FULLDUPLEX_ZEROTX_BLADERF_UL_TONE
overall_rc=1
launch_zero_tx_fullduplex rc=1
analyze_rc=2
raw_missing=1
```

The CP498 launch log stopped immediately after local settings:

```text
remote_nuc4_status=/tmp/..._nuc4_status.env
remote_sens_status=/tmp/..._sens_status.env
remote_nuc4_tar=/tmp/..._nuc4_...tar.gz
remote_sens_tar=/tmp/..._sensnuc7_...tar.gz
```

No [host-redacted] or [host-redacted] remote preflight/start step ran, and collection only
retrieved optional/stale paths. The saved local `nuc4_recorder_summary.env`
inside the CP1573 collection is stale from CP1572 and must not be interpreted
as CP1573 RF evidence.

## Cause

The inherited CP498 zero-TX launcher still performs:

```bash
test -s "$LOCAL_WAVEFORM"
```

with its default legacy CP361 waveform:

```text
cp363_cp361_offline_targeted_ul_symbol_analysis/converted_cf32/pavonis_rf_blade_tx_dbg_000001.cf32
```

That old waveform had been pruned, and the custom CP1573 [host-redacted] tone helper
does not use it. The missing inherited placeholder caused a local `set -e`
abort before SSH/SCP/RF work.

## Follow-Up

The wrapper was patched for the retry so `LOCAL_WAVEFORM` is supplied with an
existing nonempty placeholder while the custom [host-redacted] tone helper remains the
actual transmitter. The retry is CP1574 and should be treated as the valid
zero-TX full-duplex control.

Post-checks still passed after the invalid launch:

```text
[host-redacted] helper SSH rc=0
[host-redacted] ICMP 2/2 received, 0% loss, avg 50.680 ms
```
