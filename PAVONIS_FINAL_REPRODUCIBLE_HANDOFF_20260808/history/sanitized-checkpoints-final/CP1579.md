# CHECKPOINT 1579 - LiteX TX zero-after-arm summary build smoke

Date: [date-redacted] Europe/Zurich

## Purpose

CP1578 tried to use `M2SDR_SOAPY_TX_ZERO_AFTER_ARM=1` as a discriminator for
the native-continuous live gNB uplink-tone branch, but it was invalid because
there was no proof the hook armed or zeroed any TX writes. CP1579 is the
software-only/no-RF fix for that observability gap.

This checkpoint also preserves the CP1562 RSRP audit answer: the requested
`ATT=5` attenuation override did not produce the large downlink lift by itself.
Mean TRACK `meas_rsrp` was:

- CP1557: `-27.798379 dB`
- CP1562: `-27.548880 dB` (`+0.25 dB` versus CP1557)
- CP1563B: `-25.854897 dB` (`+1.94 dB` versus CP1557)
- CP1564: `-12.809643 dB`
- CP1575: `-12.127043 dB`

The large rise is therefore tied to continuous/untimed TX presentation
(CP1564/CP1575), not the attenuation override alone.

## Result

CP1579 is a no-RF instrumentation/build checkpoint and passes. It does not
prove runtime activation of zero-after-arm. It makes the next RF discriminator
interpretable.

Next RF run, if this branch is continued, should be a CP1578-style rerun with
the new sidecar enabled and `M2SDR_SOAPY_TX_ZERO_AFTER_ARM_SUMMARY_PERIOD=1`.
The run must require all of these before interpreting uplink tone results:

- `active_checks > 0`
- `probe_armed_returns > 0`
- `zeroed_interleave_calls > 0`
- `zeroed_interleave_elems > 0`

If any of those are zero, the RF result is invalid in the same way as CP1578.
Do not rerun CP1578 unchanged, and do not resume amplitude/RX/EOB sweeps.
