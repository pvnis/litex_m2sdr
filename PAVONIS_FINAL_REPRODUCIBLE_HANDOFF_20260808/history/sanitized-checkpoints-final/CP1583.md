# Checkpoint 1583 - Native-Continuous TX Skip-Stream-I/O RX-Append Tone

Date: [date-redacted]

## Goal

Run the CP1582 discriminator on RF: keep the live gNB control/RX-append path
and CP1575 native-continuous downlink configuration, but bypass the M2SDR TX
stream activation/write/deactivation path entirely with
`PAVONIS_SOAPY_TX_SKIP_STREAM_IO=1`.

This tests whether the live TX stream-I/O path itself is what suppresses the
bladeRF-to-M2SDR uplink tone in the gNB-owned RX append after CP1580/CP1581
proved that zeroing live TX payload buffers does not restore the tone.

## Conclusion

CP1583 is a valid negative discriminator for TX stream-I/O as the immediate
uplink-tone blocker. With native-continuous gNB control/RX append active and
TX stream activation/write/deactivation bypassed, the gNB-owned RX append still
does not cleanly recover the bladeRF `+100 kHz` uplink tone.

This weakens "TX stream activation/write/deactivation alone suppresses uplink
visibility." Together with CP1580/CP1581, it shifts the remaining software
suspicion toward the live gNB RX/control path, the gNB RX/predemod path versus
standalone RX, or another live gNB control-plane interaction that is not merely
TX sample content or TX stream writes.

Do not rerun CP1583 unchanged. If this wrapper is reused, fix the validation
gate to accept sidecar `tx_skip_stream_io=1` plus Soapy summaries proving
`skip_stream_io=true` and all actual TX write/flush counters at zero, rather
than requiring the missing info-level `not activating`/`not deactivating`
strings.
