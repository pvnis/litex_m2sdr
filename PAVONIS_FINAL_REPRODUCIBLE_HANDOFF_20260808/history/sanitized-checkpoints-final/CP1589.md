# Checkpoint 1589 - Offline RX Tone Spectrum Compare

Date: [date-redacted]

## Goal

Compare saved known-positive standalone M2SDR RX tone captures against the
live gNB-owned RX append captures, without running RF, to separate three
possibilities:

- RX sample-format/scaling presentation artifact.
- Current physical bladeRF TX to M2SDR RX path failure.
- Live gNB RX/control, frequency/content, or predemod path mismatch.

This follows CP1588, where RX-CF32 lifted the live append level but did not
recover the bladeRF `+100 kHz` uplink tone.

## Method

Added local analyzer:

`cp1589_offline_rx_tone_spectrum_compare.py`

It reads saved CF32 files only and performs 100 ms / 50 ms-step FFT windows at
`11.52 Msps`, using a centered `262144`-point FFT. It compares:

- CP1571 standalone LiteX/M2SDR RX, bladeRF TX tone, current physical-path
  positive.
- CP1574 standalone zero-TX full-duplex RX, bladeRF TX tone, positive.
- CP1585 live gNB RX append with TX setup+I/O skipped, CS16 append path.
- CP1588 live gNB RX append with TX setup+I/O skipped, RX-CF32 path.

Outputs:

- JSON: `cp1589_offline_rx_tone_spectrum_compare_[date-redacted].json`
- Env: `cp1589_offline_rx_tone_spectrum_compare_[date-redacted].env`

## Result

The known-positive captures still show the expected uplink tone strongly:

- CP1571 best near `+100 kHz`: `63.144834 dB` over median, peak
  `97602.5390625 Hz`.
- CP1574 best near `+100 kHz`: `62.754119 dB` over median, peak
  `97690.4296875 Hz`.
- `CP1589_KNOWN_POSITIVE_EXPECTED_TONE_VISIBLE=1`.

The live gNB append captures do not show comparable expected-tone content:

- CP1585 best near `+100 kHz`: `12.271191 dB` over median.
- CP1588 best near `+100 kHz`: `12.415967 dB` over median.
- CP1588 is still about `50.7 dB` below CP1571 and `50.3 dB` below CP1574 on
  best near-expected-tone prominence.
- `CP1589_LIVE_EXPECTED_TONE_VISIBLE_AFTER_RXCF32=0`.

RX-CF32 changed level, not the missing tone content:

- CP1588 RMS rose by `25.185383 dB` versus CP1585.
- CP1588 best near-expected-tone prominence rose by only `0.144775 dB`
  versus CP1585.
- CP1585 dominant best-window peak: `1437539.0625 Hz`.
- CP1588 dominant best-window peak: `1437495.1171875 Hz`.
- CP1585 median dominant-window frequency was near `+2.493720 MHz`, with
  `46` windows near that spur class.
- CP1588 median dominant-window frequency was near `+2.492314 MHz`, with
  `41` windows near that spur class.
- `CP1589_RXCF32_CHANGED_LEVEL_NOT_CONTENT=1`.
- `CP1589_LIVE_DOMINANT_PEAK_IS_OFF_TARGET=1`.

## Conclusion

CP1589 supports the CP1588 conclusion more sharply: RX-CF32 fixed the live
append presentation level but did not move the expected `+100 kHz` tone
content in any meaningful way. The current saved standalone captures still
prove the physical bladeRF TX to M2SDR RX tone path is visible outside the
live gNB RX path.

The next changed work should not be amplitude, RX-gain, EOB, or RX sample
format. The remaining software branch is live gNB RX/control,
frequency/content routing, or predemod input mismatch versus the standalone
raw RX path. A useful next step is a software-only source audit of the OCUDU
RX append path versus standalone capture path for frequency translation,
channel/port mapping, and any baseband mixing/resampling before adding another
RF run.
