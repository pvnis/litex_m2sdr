# Checkpoint 1591 - Raw CF32 Preconversion Append Build

Date: [date-redacted]

## Goal

Implement and no-RF build-smoke the CP1590 next rung: a default-off raw Soapy
RX-CF32 `readStream()` append tap before OCUDU converts the scratch buffer back
to `ci16_t`. This creates the instrument needed to compare raw-preconversion
CF32 against the existing post-conversion `PAVONIS_SOAPY_RX_APPEND_CF32_PATH`
append in the same future live no-TX-stream tone window.

No RF was run in this checkpoint.

## Implementation

Changed `ocudu/lib/radio/soapy/radio_soapy_rx_stream.cpp` only.

Added default-off raw tap controls:

- `PAVONIS_SOAPY_RX_APPEND_RAW_CF32_PATH`
- `PAVONIS_SOAPY_RX_APPEND_RAW_CF32_MAX_SAMPLES`
- `PAVONIS_SOAPY_RX_APPEND_RAW_CF32_PORT`

If the raw max/port envs are unset, they fall back to the existing
`PAVONIS_SOAPY_RX_APPEND_MAX_SAMPLES` and `PAVONIS_SOAPY_RX_APPEND_PORT`.
The tap only writes when `rx_cf32_stream` is active, the raw append path is set,
the max sample count is nonzero, and the requested port is inside the active
readStream channel set. It writes directly from `rx_cf32_read_buffers` after a
successful Soapy `readStream()` return and before `cf32_to_ci16_component()`.

Added readback/log proof fields:

- constructor log fields for raw path, raw max samples, and raw port.
- `env_PAVONIS_SOAPY_RX_APPEND_RAW_CF32_PATH`
- `env_PAVONIS_SOAPY_RX_APPEND_RAW_CF32_MAX_SAMPLES`
- `env_PAVONIS_SOAPY_RX_APPEND_RAW_CF32_PORT`
- `raw_cf32_append_enabled`
- `raw_cf32_append_available`
- `raw_cf32_append_seen_samples`

Also fixed the stale debug comment: the legacy append records the
post-receive `ci16_t` buffer, while the new env records the raw RX-CF32
readStream tap.
