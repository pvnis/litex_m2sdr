# Checkpoint 1593 - Raw CF32 Append Arm-Gate Build

Date: [date-redacted]

## Goal

Fix the CP1592 measurement-design failure before any RF repeat. CP1592 proved
that the raw-preconversion RX-CF32 append and the legacy post-conversion append
were not capturing the same window because the raw tap started before the
delayed RX append arm file while the legacy append was arm-gated.

No RF was run in CP1593.

## Implementation

Changed `ocudu/lib/radio/soapy/radio_soapy_rx_stream.cpp` only.

The raw-preconversion append path now shares the RX append arm state:

- reads `PAVONIS_SOAPY_RX_DUMP_ARM_FILE` once, like the legacy append did.
- uses `PAVONIS_SOAPY_RX_ARM_POLL_PERIOD`, defaulting to `1024`.
- snapshots the arm state once per `receive()` call before reading samples.
- gates `PAVONIS_SOAPY_RX_APPEND_RAW_CF32_PATH` writes on that same per-call
  arm state.
- uses the same arm state for the legacy post-conversion dump block.

This intentionally makes both append paths start from the same receive-call arm
decision. If the arm file appears mid-read, both paths wait until the next
receive call rather than letting the legacy append start after the raw append
already skipped or captured a different window.

Added runtime proof fields:

- constructor log fields:
  `append_arm_file`, `append_arm_poll_period`
- RX readback fields:
  `env_PAVONIS_SOAPY_RX_DUMP_ARM_FILE`
  `env_PAVONIS_SOAPY_RX_ARM_POLL_PERIOD`
  `raw_cf32_append_arm_gated`
  `raw_cf32_append_armed`

The manifest writer was updated to use the shared arm-file variable after the
old local `pavonis_arm_file` variable was removed.
