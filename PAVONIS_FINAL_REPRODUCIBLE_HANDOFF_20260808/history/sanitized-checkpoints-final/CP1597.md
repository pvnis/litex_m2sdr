## Conclusion

CP1597 is a valid completed diagnostic run, but it is not the requested
standalone-pass/live-fail RX state A/B. The custom RX-only standalone recorder
failed almost immediately and left the standalone snapshot in a sleeping/
invalid AD9361 state. Do not use the CP1597 state diff to explain the live
gNB RX blocker, and do not rerun the CP1597 standalone recorder unchanged.

The new reusable observation is the opposite-side anomaly: the live no-TX-
stream/RX-CF32/raw-vs-post path saw the bladeRF `+100 kHz` tone in the final
100 ms window with clean raw/post instrumentation. That result should be
reproduced before treating it as a new baseline. The next changed checkpoint
should either repeat the CP1597 live half as a focused live-only reproduction
or pair a genuinely known-positive standalone path, such as CP1571/CP329 raw
LiteX RX or a CP1574-exact zero-TX full-duplex path, with the same CP1233-style
state readback.
