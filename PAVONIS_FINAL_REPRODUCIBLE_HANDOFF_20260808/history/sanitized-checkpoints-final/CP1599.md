## Results

CP1599 changes the interpretation of CP1598 live1. live1 was not actually
tone-absent: it has six windows where the global peak is near the commanded
tone. The strict CP1598 live1 `tone_path_pass=0` came from selecting the
window with the highest exact-bin value, which was masked by a stronger
off-target spur.

live1:

- exact expected-bin windows: `2 >= 10 dB`, `1 >= 15 dB`, `1 >= 20 dB`
- near-tone peak windows: `7 >= 20 dB`, `6 >= 30 dB`
- global peak near tone: `6/59` windows
- masked exact-bin windows: `1`
- most common global peaks: `~2.49 MHz` in `22` windows, `~100 kHz` in `6`
  windows
- tone-dominant windows: starts `2.65`, `2.70`, `2.75`, `2.80`, `2.85`,
  and `2.90 s`, all peaking at `97998.046875 Hz`
- strongest near-tone window: `2.85 s`, near-tone peak `60.781 dB` over
  median

The masked live1 window that drove CP1598's strict failure:

- start `1.95 s`
- global peak `5309692.3828125 Hz`
- global peak `35.289585 dB` over median
- near-tone peak `93471.6796875 Hz`, `25.518686 dB` over median
- exact expected-bin `23.268317 dB` over median
- exact-bin minus global peak `-12.021268 dB`

live2:

- exact expected-bin windows: `4 >= 10 dB`, `2 >= 15 dB`, `1 >= 20 dB`
- near-tone peak windows: `12 >= 20 dB`, `12 >= 30 dB`
- global peak near tone: `12/59` windows
- masked exact-bin windows: `0`
- most common global peak: `~100 kHz` in `12` windows
- tone-dominant windows: starts `2.35` through `2.90 s` in 50 ms steps,
  peaking at `97954.1015625` or `97998.046875 Hz`
- strongest near-tone window: `2.60 s`, near-tone peak `61.781 dB` over
  median

## Conclusion

CP1599 confirms the live gNB no-TX-stream/RX-CF32 path can see the bladeRF
`+100 kHz` uplink tone in both CP1598 live phases. CP1598 live1 was a strict
gate/analyzer-selection failure, not a true no-tone capture: a strong late
near-tone component was present, but CP1598 selected an earlier exact-bin
window where a `5.31 MHz` spur dominated.

The branch now reads: live gNB RX tone visibility exists, but it is
window-local and competing off-target content plus exact-bin selection can
misclassify it. live2 has denser tone-dominant coverage than live1 (`12` vs
`6` global-near-tone windows) and a higher auto-gain readback (`71` vs
`66 dB`), but both phases are tone-visible. Do not turn this into an RX-gain
or amplitude sweep.

Next software-only work should either update the live tone analyzer/gates to
track near-tone peak frequency and off-target masking explicitly, or use the
CP1599 metrics to design one materially changed diagnostic. Do not rerun
CP1598 unchanged.
