Date: [date-redacted] Europe/Zurich

## Goal

Explain the CP1601 result without running more RF: CP1583 is tone-visible
under the corrected near-tone gate, while CP1585 remains tone-negative. The
question is whether the split is really "TX stream I/O skipped" versus
"TX setup/config skipped", and which software calls differ.

No RF was transmitted, no SSH was used, no hardware state changed, and no
source behavior was modified in this checkpoint.

  - rate `11.52 Msps`
  - frequency `1000000 Hz`

The RX gain does not explain the split: CP1583 sees the tone at lower RX gain
(`34 dB`), while CP1585 fails at higher RX gain (`69 dB`).

The TX side does explain a large state difference. CP1583 configured the TX
channel to the normal live downlink state (`1842500000 Hz`, `5 dB`), then
skipped stream I/O. CP1585 skipped TX setup/config and read back a default-ish
TX state (`1000000 Hz`, `20 dB`).

## Source Audit

The CP1585 flag `PAVONIS_SOAPY_TX_SKIP_STREAM_SETUP=1` is broader than the
name might suggest:

- `radio_soapy_impl.cpp:281-303` detects the flag and announces that TX
  channel configuration and `setupStream()` will be skipped.
- `radio_soapy_impl.cpp:315-358` normally performs TX channel config:
  `set_sample_rate(TX)`, `set_tx_port_freq()`, `set_tx_gain_unprotected()`,
  `set_bandwidth(TX)`, and channel readback. With the skip flag active, it
  continues before those calls.
- `radio_soapy_impl.cpp:421-441` normally calls TX `setup_stream()`. With the
  skip flag active, the TX stream pointer remains null.
- `radio_soapy_impl.cpp:112-157` and `222-243` make later TX gain/frequency
  requests no-ops when the skip flag is active.
- `radio_soapy_tx_stream.cpp:181-238` shows CP1583's stream-I/O skip is a
  different layer: `PAVONIS_SOAPY_TX_SKIP_STREAM_IO=1` still allows a real TX
  stream/config path but later skips activation/write/deactivation.

## Conclusion

CP1602 closes the CP1601 follow-up audit: CP1585 is not just "CP1583 plus a
deeper TX stream skip." It removes the TX channel configuration side effects
that CP1583 still had. The next discriminator should keep TX channel
configuration/readback at CP1583 values, but skip TX `setupStream()` and all
TX stream I/O. That separates "TX LO/gain/BW configuration helps live RX tone
visibility" from "the TX stream object/setupStream itself helps."

Do not rerun CP1583, CP1585, CP1601, or CP1602 unchanged. Next changed work
should be a default-off no-RF build discriminator for "skip TX setupStream
only after TX config", followed by one RF run with the CP1600 near-tone gate.
