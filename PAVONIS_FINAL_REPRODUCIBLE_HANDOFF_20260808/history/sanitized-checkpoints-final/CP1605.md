# Checkpoint 1605 - setupStream-only live RX append controlled PRACH

Date: [date-redacted] Europe/Zurich

## Goal

Move one rung above CP1604's uplink tone pass by transmitting the known CP19
srsRAN PRACH waveform from [host-redacted]/bladeRF TX1 while [host-redacted] runs the same live
gNB setupStream-only/no-TX-stream RX-CF32 append state. This checks whether a
PRACH-class waveform, not just a single tone, is visible inside the live
gNB-owned RX append path without requiring UE downlink acquisition.

## Scope

- Controlled repeated CP19 PRACH waveform over bladeRF TX1.
- Live gNB on [host-redacted] with CP1604 state:
  `PAVONIS_SOAPY_TX_SKIP_SETUPSTREAM_ONLY=1`,
  `PAVONIS_SOAPY_TX_SKIP_STREAM_IO=1`,
  `PAVONIS_SOAPY_TX_SKIP_STREAM_SETUP=0`.
- No UE attach and no srsUE PRACH; this is not a Msg1/RAR ladder run.
- No hardware-affecting branch, calibration, bias, or physical-path change.
- No `ue_sync_nr.c` edits.

## Caveats

The [host-redacted] summary markdown was produced by the reused CP1604 remote orchestrator
and still says "SetupStream-Only Live Tone" in its title/table labels. The
actual analyzer JSON and this report are PRACH-specific; the reused title is a
label artifact only.

CP1605 proves RX-append visibility, not live PRACH detector acceptance. The
controlled PRACH waveform is repeated and high-duty, as in CP29, and the run
does not include a UE downlink/attach dependency.

## Conclusion

CP1605 is a positive controlled-PRACH visibility checkpoint. The live
gNB-owned M2SDR RX-CF32 append sees the known CP19 PRACH waveform under the
same setupStream-only/no-TX-stream state that passed the CP1604 tone rung.
This moves the controlled-uplink ladder from "single tone visible" to
"PRACH-class waveform visible" in the live gNB RX append path.

Next work should not rerun CP1605 unchanged. The useful next rung is to route
the same controlled CP19 PRACH window into live gNB PRACH trace/predemod
instrumentation under this state, to distinguish RX-append visibility from
detector/predemod scheduling and threshold behavior. A UE-based PRACH retry
under TX-stream-I/O skip would be invalid unless downlink acquisition is
provided by another path, because srsUE needs downlink to generate live PRACH.
