## Conclusion

CP1606 is a clean positive checkpoint.

Under the CP1604 setupStream-only/no-TX-stream state, the live gNB path sees
the controlled CP19 PRACH in all three places:

1. gNB-owned RX-CF32 append.
2. PRACH predemod dump windows.
3. PRACH detector trace, including accepted preamble-0 rows.

This closes the theory that the detector/predemod path is intrinsically unable
to see CP19-class PRACH under the CP1604 state. The remaining gap is now the
difference between this controlled no-TX-stream state and the normal live
downlink/UE runs such as CP1576, where real UE PRACH attempts aligned to the
right occasions but predemod rows stayed floor-class and p0 ratios remained
sub-threshold.

## Next

The next useful rung is a controlled CP19 PRACH trace/predemod run with normal
live gNB TX stream I/O enabled, keeping the CP1575 native-continuous downlink
baseline and the CP1606 analyzer. If controlled CP19 fails there, the blocker
is the active TX stream/full-duplex live state. If controlled CP19 still
passes, the remaining suspect moves toward real UE PRACH waveform/timing/path
differences rather than gNB predemod/detector visibility itself.
