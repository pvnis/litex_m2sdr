## Goal

CP1620 proved that CP1618's raw append contains strong exact matches to the
real UE TX debug dumps, and that CP1619 used an invalid first-ret_ts file-offset
mapping. CP1621 reruns the event-window comparison using the per-row append
metadata mapping:

```text
corrected_offset = nearest_row.append_file_offset_samples
                 + (manifest_window_start_ts - nearest_row.ret_ts)
```

It then scores raw append, post append, and predemod files with both exact UE
SC16 dumps and the CP19 template.

## Interpretation

CP1621 resolves the CP1619/CP1620 ambiguity.

With per-row metadata mapping, the real UE waveform is present strongly in the
raw append near every CP1618 event, but about `+12 ms` to `+19 ms` after the
corrected event offset. The CP19 template and exact UE SC16 dumps agree on this
placement and score near `0.92..0.93`.

The matching CP1618 predemod files remain floor-class under both exact UE and
CP19 scoring. That means the failure is no longer raw RF visibility at the
gNB-owned M2SDR append tap. The gap is between the append-visible corrected
raw window and the predemod/detector extraction window.

This points directly back to the CP651-CP733 demod-offset family, but now with
a live real-UE, metadata-corrected measurement instead of open-loop phase
sweeps.

## Conclusion

CP1621 is a no-RF positive raw-append / negative predemod isolation result.

The next rung should adjust or replay predemod extraction around the corrected
`+12..+19 ms` raw-hit offset and reuse the prior demod-offset findings. Do not
run more open-loop phase sweeps or RF amplitude/RX-side tests for this branch.
