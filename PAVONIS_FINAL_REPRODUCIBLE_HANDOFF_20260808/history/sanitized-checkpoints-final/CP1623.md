## Findings

The PRACH worker begins collection at the first symbol of the requested slot
that reaches the worker:

- `prach_processor_worker.cpp:24-37` marks a request late if the incoming
  context has already advanced past the requested slot or is in the requested
  slot with `symbol > 0`.
- `prach_processor_worker.cpp:44-52` waits until `context.slot ==
  prach_context.slot`, then sets `collection_start_timestamp =
  context.timestamp` and records `collection_start_symbol = context.symbol`.
- `prach_processor_worker.cpp:109-115` writes the predemod manifest
  `window_start_ts` directly from `collection_start_timestamp`.
- `prach_processor_worker.cpp:147-256` dumps the predemod buffer before any
  demod input crop is applied.
- `prach_processor_worker.cpp:258-270` applies
  `PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES` only by subspanning the already
  collected `cf_buf`.

The uplink processor supplies that timestamp directly from the symbol stream:

- `uplink_processor_impl.cpp:126-160` aligns incoming RX samples to OFDM symbol
  boundaries and sets `current_symbol_timestamp = timestamp`.
- `uplink_processor_impl.cpp:386-389` passes `current_symbol_timestamp` as
  PRACH `symbol_context.timestamp`.
- `prach_processor_baseband.h` documents this as the first sample of the
  current OFDM symbol, adjusted to the lower-PHY SFN0 reference.

The demodulator consumes an offset inside the already collected window:

- `ofdm_prach_demodulator_impl.cpp:68-78` computes the time-domain occasion
  from `config.start_symbol` and slot position.
- `ofdm_prach_demodulator_impl.cpp:114-119` selects
  `input.subspan(sample_offset, nof_samples)`.
- For the CP1618 manifest rows, `start_symbol=0`, `nof_td_occasions=1`, and
  `window_length=11520`, so the demodulator has no hidden 12 ms late-origin
  path inside the nominal window.

The FAPI translator only copies the PRACH request metadata:

- `fapi_adaptor/phy/p7/pdu_translators/prach.cpp:19-35` sets slot, format,
  `nof_td_occasions`, `start_symbol`, `rb_offset`, PRB grid, root, ZCZ, and
  ports. It does not carry an absolute RX timestamp or late collection offset.

## Interpretation

CP1623 identifies the necessary patch surface.

The CP651-CP733 demod crop knob is downstream of the predemod dump and cannot
repair CP1618. A future diagnostic must act before or at
`collection_start_timestamp`, not inside `demod_cf_buf`.

A safe next implementation should be default-off and should prove the mapping
explicitly. It should log at least:

- original PRACH request SFN/slot/start symbol;
- first observed symbol context for that request;
- requested collection delay in samples/ms/slots;
- actual collection start SFN/slot/symbol/timestamp;
- actual predemod `window_start_ts` and `window_end_ts`;
- whether the worker crossed later slots under the diagnostic.

The diagnostic cannot be a simple static `PAVONIS_PRACH_DEMOD_INPUT_OFFSET`
value. It needs either a guarded PRACH collection-window delay/remap before the
predemod dump, or an offline detector replay that feeds append-derived shifted
windows through the detector path before spending RF.
