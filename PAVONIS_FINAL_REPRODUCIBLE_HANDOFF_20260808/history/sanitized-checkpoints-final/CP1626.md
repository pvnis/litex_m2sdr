## Remote Attempt

The first CP1626 remote corrected-window compare intentionally reused the
CP1621 analyzer against the CP1625 remote run directory. It failed:

```text
OVERALL_RC=1
run_remote_compare rc=1
get_remote_json rc=1
get_remote_stdout rc=0
post_sensnuc7_ssh rc=0
```

The fetched stdout shows why:

```text
RuntimeError: window 1168451942:1168463462 beyond 276480000
```

That is not a waveform-analysis result. It means the CP1621 corrected-offset
projection placed the first CP1625 real UE event far beyond the saved
`276480000`-sample raw append.

## Conclusion

CP1626 closes CP1625 raw-append event visibility as invalid: CP1625's append
ended roughly `78.3..79.3 s` before the real UE PRACH windows. Therefore:

- CP1625 is valid for live delayed-collection/predemod/detector behavior.
- CP1625 is not valid for same-window raw-append-vs-predemod comparison.
- The next changed RF run should either extend the raw append long enough to
  cover the real UE Msg1 latency, or arm a smaller raw capture nearer to the
  actual UE PRACH time.
