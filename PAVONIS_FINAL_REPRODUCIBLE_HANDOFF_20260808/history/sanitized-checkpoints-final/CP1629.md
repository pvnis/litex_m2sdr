## Goal

Rerun a current CP1625-style real srsUE PRACH attempt after CP1627 and CP1628
both stopped emitting Msg1. This was a control to see whether the original
CP1625 timing/arming pattern could still reproduce real UE PRACH events before
spending more RF time on the delay knob.

Per the follow-up direction, this is the last RF delay/append checkpoint before
pivoting to the no-RF decisive test: replay the seven CP1618 append windows at
the CP1621 raw-hit offsets through the actual gNB PRACH detector offline.

## Interpretation

CP1629 does not validate or invalidate the CP1624 delayed collection mapping.
It is a current-time PRACH-emission control showing that CP1625-style arming no
longer reliably reproduces the CP1625 real UE behavior: the UE now reaches a
PBCH-positive cell search, then fails SFN/cell select and never receives the
later CP1625-class RACH config or emits Msg1.

Together with CP1627 and CP1628, this says the live RF delay knob is not the
right next spend while the UE intermittently fails before PRACH. The next rung
should be no-RF and use already captured CP1618 data: feed the seven CP1618
raw append windows at the CP1621 raw-hit offsets through the actual gNB PRACH
detector offline. CP1618's event spread (`+11.8..+18.9 ms`) remains important:
a single static 1 ms shifted window can be wrong even if the window-mapping
hypothesis is correct.
