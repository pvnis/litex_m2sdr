## Conclusion

CP1635 closes two sufficient-cause theories:

```text
companion RX CF32/readStream append alone -> not sufficient
static collection delay 141666 alone       -> not sufficient
```

The no-Msg1 regressions split into at least two acquisition stages:

```text
post-cell-select no RACH config/Msg1: CP1627, CP1628
SFN/cell-select failure before Msg1:  CP1629, CP1633
```

CP1633's sequence mode remains a live variable because it is the only
sequence-active RF run, but CP1635 does not prove it caused the failure. The
next changed RF checkpoint, if RF is needed, should be a minimal acquisition-
only A/B using the CP1633 harness lineage: first disable sequence mode and
avoid or separately toggle companion RX append/readStream, then reintroduce one
variable at a time before interpreting PRACH timing.

Do not run more sequence/static-delay timing attempts while the UE is failing
before stable RACH config/Msg1 emission.
