# CP1638 saved self-RX TX-latency readiness audit

Date: [date-redacted] Europe/Zurich

## Goal

Before running new RF, check whether saved [host-redacted]-only self-RX artifacts already
contain enough common timestamp lineage to estimate the continuous-TX pipeline
latency from lower-PHY timestamp to received RF.

## Inputs

Relevant saved branches:

- CP1528: live gNB self-RX with longer TX egress reference, worker trace, and
  OCUDU write metadata.
- CP1532: live gNB self-RX with RX append metadata, worker trace, and clean
  metadata-to-window mapping.

## Findings

CP1528 is useful for TX-side commit timing, but not absolute RF latency:

- worker trace HAS_TIME rows: `5003`
- first TX source/release/slip: `[subscriber-redacted] ns` /
  `[subscriber-redacted] ns` / `-95861545 ns`
- last TX source/release/slip: `[subscriber-redacted] ns` /
  `[subscriber-redacted] ns` / `-1479774 ns`
- late rows: `2`
- no same-run RX append metadata file was present under the saved CP1528 run
  tree.

CP1532 is the closer saved shape because it has both TX worker trace and RX
append metadata in one run:

- worker trace HAS_TIME rows: `4959`
- first TX source/release/slip: `[subscriber-redacted] ns` /
  `[subscriber-redacted] ns` / `-97836892 ns`
- last TX source/release/slip: `[subscriber-redacted] ns` /
  `[subscriber-redacted] ns` / `-1696701 ns`
- late rows: `0`
- RX append metadata rows: `5648`, offsets `0..2880000`, no gaps, no overlaps,
  no overflows, no no-time chunks, no time regressions
- first RX append start/end time estimate: `[subscriber-redacted] ns` /
  `[subscriber-redacted] ns`
- last RX append start/end time estimate: `[subscriber-redacted] ns` /
  `[subscriber-redacted] ns`
- first PBCH-positive 1 ms self-RX window: `start_s=0.0965`, SNR `27.6 dB`
- CP1532 1 ms sweep: `499` windows, `63` PBCH-positive windows, `39` PCI1
  measure windows

The CP1532 first RX append sample is about `5.013020 ms` before the first TX
HAS_TIME source timestamp and about `6.013020 ms` before the first adjusted TX
release timestamp. The first PBCH-positive RX window starts about `96.5 ms`
after RX append start, or about `90.487 ms` after the first adjusted release.

That value must not be interpreted as TX pipeline latency. It includes the live
gNB frame/SSB placement and whatever part of the repeating downlink waveform
the RX append happened to cover. The saved artifacts do not mark a designed TX
edge, pulse, or known symbol whose lower-PHY timestamp can be paired directly
with an RX sample index.

## Decision

Saved CP1528/CP1532 artifacts are sufficient to define the next diagnostic
shape, but not to estimate actual lower-PHY-to-RF latency directly.

The next measurement should be one self-contained same-run diagnostic with:

- OCUDU write metadata enabled;
- `M2SDR_SOAPY_TX_WORKER_TRACE_PATH` enabled;
- RX append metadata enabled;
- a designed RF-visible marker tied to a known TX source timestamp, such as a
  short tone/pulse/edge or a logged SSB/OFDM-symbol source timestamp that the
  analyzer can identify in RX samples;
- a report gate that does not classify a real-UE PRACH RF attempt as a
  datapoint unless the UE emits real Msg1.

## Status

Checkpoint status: no-RF artifact audit pass.

Do not use CP1532's `~90.5 ms` first-PBCH offset as a pipeline-latency value.
It is a readiness clue for designing CP1639, not a measured RF emission delay.
