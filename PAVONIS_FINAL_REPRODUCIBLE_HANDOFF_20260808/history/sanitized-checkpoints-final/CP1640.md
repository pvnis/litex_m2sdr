# Checkpoint 1640 - CP1532 PBCH MIB/SFN Timestamp Map

Date: [date-redacted] Europe/Zurich

## Goal

Before spending new RF, test the user's proposed CP1532 shortcut: decode full
PBCH MIB SFN from the 63 PBCH-positive one-millisecond self-RX windows, then
use SFN as an unambiguous marker to pair each received SSB with a scheduled TX
source timestamp.

## Method

This checkpoint is artifact-only. No RF was transmitted and no OCUDU/LiteX/
srsRAN source files were changed.

Added and ran:

```text
pavonis_stage6_agent_artifacts_[date-redacted]T0918Z/prearmed_raw512_fast_[date-redacted]T0045Z/cp1640_cp1532_pbch_sfn_tx_timestamp_map.py
```

The analyzer:

- parses CP1532's existing one-millisecond RX PBCH-positive sweep logs and
  extracts full `PBCH-MIB: sfn=...`, `ssb_idx`, and half-frame values;
- maps each RX decoded SSB sample through CP1532 RX append metadata;
- runs a bounded one-millisecond, 0.5 ms step pre-DMA TX sweep over the first
  300 ms with `ssb_file_test`;
- maps TX decoded SSB samples through the pre-DMA TX metadata; and
- attempts RX/TX pairing only when full MIB SFN, SSB index, half-frame, and a
  scheduled-to-RX delay inside `-5..25 ms` all match.

## Results

RX side:

- CP1532 one-millisecond RX PBCH-positive rows: `63`.
- Exact RX SSB sample hits after overlap de-duplication: `42`.
- Unique full RX MIB SFNs: `16`.
- Duplicate full RX MIB SFNs at distinct RX sample times:
  `261:6`, `262:3`, `263:5`, `264:4`, `265:4`, `266:2`,
  `267:2`, `268:3`, `280:3`, `282:2`, `757:3`.

TX side:

- Pre-DMA TX sweep rows: `599`.
- TX PBCH-positive rows: `233`.
- Exact TX SSB sample hits after overlap de-duplication: `117`.
- TX unique full MIB SFNs: `117`.
- TX duplicate full MIB SFNs: none in the bounded sweep.

Pairing:

- RX events tested: `42`.
- Unique plausible same-SFN TX pairings: `17`.
- Ambiguous same-SFN pairings: `0`.
- No plausible same-SFN TX timestamp: `25`.
- Unique-pair scheduled-to-RX delay median/min/max:
  `0.021962 ms` / `-1.040711 ms` / `23.66849 ms`.

The pairings are not stable enough to be a timing constant. The first seven RX
hits pair tightly at about `0.021962 ms`, but later repeated RX SFNs either
have no plausible matching TX timestamp or produce widely separated apparent
delays around `-1 ms` and `21..24 ms`.

## Verdict

`RX_MIB_SFN_NOT_UNIQUE_IN_CP1532_SAVED_1MS_POSITIVES`

The CP1532 MIB/SFN shortcut fails its core premise. Full MIB SFN is not an
unambiguous marker in the saved CP1532 RX-positive one-millisecond windows,
because the same decoded full SFN recurs at multiple distinct RX sample times.
Therefore CP1640 must not be used as a run-stable TX-pipeline latency
measurement or as a CP1624 delay value.
