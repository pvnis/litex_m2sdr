## Verdict

`BOUNDED_MARKER_LATENCY_REPRODUCED_BROAD_DELAYED_COPY_REPRODUCED`

CP1643 confirms CP1642's main result. With a live-rate C++ RX path, the
near-scheduled TX-to-self-RX marker latency is repeatable across two runs at
approximately `-14 us` to `-33 us`, median `-28.818 us`, with a `19.271 us`
within-run range. The C++ path has clean per-read RX metadata and no RX gaps in
both runs.

The delayed marker-2 copy at `+22.631945 ms` also repeats, so future marker
analysis must treat broad late peaks as duplicate/echo candidates instead of
blindly using the highest score inside a `±25 ms` window.

Do not apply the `+22.631945 ms` broad hit as a PRACH collection delay. The
bounded near-scheduled result suggests the helper timed-TX self-RX hardware
latency is effectively tens of microseconds, not the `11..20 ms` spread seen
in saved UE/PRACH windows. Before using a delay knob, the next rung should
either remove/guard the tail delayed-copy artifact with a marker layout change
or explicitly connect the bounded marker result to the live gNB lower-PHY
timestamp source being used by PRACH collection.
