# Checkpoint 1644 - CP1642/CP1643 Marker Duplicate Audit

Date: [date-redacted] Europe/Zurich

## Goal

Before spending more RF, audit the CP1642/CP1643 captures offline to identify
the repeated `+22.631945 ms` broad-search marker hit. The question was whether
the delayed peak is a general echo affecting all markers, or a marker-2/tail
artifact that can be removed by a changed marker layout or guarded analyzer.

No RF was transmitted and no [host-redacted]/[host-redacted] command was run for this checkpoint.

## Method

Added and ran:

```text
cp1644_marker_duplicate_audit.py
```

The script scans the full CP1642 and CP1643 RX captures for each marker,
across the same CFO grid used by the marker analyzers:

```text
-[date-redacted], -1000, 0, +1000, +[date-redacted] Hz
```

It reports the top separated normalized-correlation peaks per marker, maps
each peak through RX metadata, and records whether each peak is near the
scheduled marker or in the `+10..+30 ms` late region.

Output directory:

```text
cp1644_marker_duplicate_audit_[date-redacted]/
```


Top-rank behavior:

- marker0 is dominated by the near-scheduled peak in both runs;
- marker1 is dominated by the near-scheduled peak in both runs;
- marker2 is dominated by the delayed `+22.631945 ms` peak in both runs;
- marker0/marker1 have late peaks, but they are weak noise-class peaks around
  `0.058..0.062`, far below their near peaks;
- marker2's delayed peak is not noise-class: it is `2.2x` to `2.7x` stronger
  than its near-scheduled peak.

## Verdict

`STRONG_DELAYED_COPY_IS_MARKER2_TAIL_SPECIFIC`

The delayed-copy problem is not a broad latency measurement and not a general
echo that dominates every marker. It is reproducibly tied to the final marker
in the CP1642/CP1643 waveform/layout. The weak late peaks for marker0/marker1
are normal full-capture false peaks and do not threaten bounded analysis.

This strengthens the CP1642/CP1643 bounded-latency interpretation: the
repeatable near-scheduled latency cluster remains `-14..-33 us`. It also
defines the next RF rung: use a changed marker layout that keeps markers away
from the TX waveform tail and/or adds an explicit duplicate guard. Do not use
the marker2 `+22.631945 ms` delayed copy as a CP1624 delay.
