# Checkpoint 1646 - Timestamp Domain Bridge Audit

Date: [date-redacted] Europe/Zurich

## Goal

Close the no-RF question left by CP1645: whether the clean helper timed-marker
latency can be applied directly to the live gNB PRACH collection delay knob.

This checkpoint ran no RF and no remote radio commands. It audited the CP1645
artifacts and the local OCUDU/LiteX source paths that convert lower-PHY sample
timestamps to Soapy/M2SDR hardware timestamps.

## Evidence

CP1645 is internally timestamp-coherent:

- The C++ helper sends direct timed Soapy writes with
  `time_ns = base_new + sample_offset`.
- The LiteX worker trace records the first submitted `source_time_ns` as
  `[subscriber-redacted]`, exactly matching CP1645's first helper `tx_write_meta`
  `time_ns`.
- CP1645's worker `release_time_ns` is the same value when no
  `M2SDR_SOAPY_TX_TIME_OFFSET_NS` is applied.
- The marker analyzer computes marker latency from the same Soapy/M2SDR
  hardware-time namespace: `rx_time_ns - tx_source_time_ns`.
- The resulting marker latencies are stable and small:
  `-0.014062`, `-0.028819`, and `-0.033332 ms`.

The live OCUDU timestamp plumbing uses the same units:

- `radio_session_soapy_impl::read_current_time()` reads Soapy hardware time and
  converts it to `baseband_gateway_timestamp` samples.
- `radio_soapy_tx_stream::transmit()` converts `tx_md.ts` back to Soapy
  nanoseconds with `samples_to_ns(tx_md.ts, srate_hz)`.
- The PRACH worker's CP1624 delay knob adds samples to
  `context.timestamp`, and `context.timestamp` is also a
  `baseband_gateway_timestamp`.
- The RX stream converts Soapy RX `time_ns` metadata back to
  `baseband_gateway_timestamp` samples.

So the source-level audit does not show a separate clock/unit mismatch between
downlink TX, uplink RX, and PRACH collection timestamps.

## Important Caveat

CP1645 does not fully emulate the production live TX mode. CP1645 sends every
helper packet with `SOAPY_SDR_HAS_TIME`, so every submitted M2SDR DMA header is
a timed descriptor.

The CP1575 production-direction live baseline uses native continuous TX
(`tx_mode: continuous`, effective `discontinuous_tx=0`). In OCUDU continuous
mode, the TX FSM sets `SOAPY_SDR_HAS_TIME` on the first non-empty buffer that
starts the stream, then later buffers are continuation payload. OCUDU still
passes a computed `chunk_time_ns` to `writeStream()`, and the worker trace may
record that as `source_time_ns`, but the LiteX DMA header writes a nonzero
timestamp only when `SOAPY_SDR_HAS_TIME` is present; untimed continuation
headers carry timestamp `0`.

Therefore CP1645 proves the M2SDR timed-descriptor TX-to-self-RX path is not
delayed by `11..20 ms`, but it does not by itself prove the live continuous
stream's frame/SSB cadence and PRACH collection timeline are aligned.

## CP1532 SFN Shortcut Status

The requested pre-RF CP1532 MIB/SFN shortcut was already completed as CP1640.
It did not provide a usable pairing marker: the `63` PBCH-positive 1 ms
self-RX windows collapsed to only `16` unique full MIB SFNs, with repeated
SFNs at distinct RX times, and plausible same-SFN TX/RX pair delays spread
from `-1.040711` to `23.66849 ms`.

Do not use CP1532/CP1640 as a live TX latency value.

## Verdict

`TIMESTAMP_DOMAINS_ALIGN_BUT_HELPER_NOT_LIVE_FRAME_PROOF`

CP1645 is a valid clean baseline for the M2SDR timed-descriptor path. It argues
against a stable millisecond-scale lower-PHY-to-RF delay in that path. It is
not enough to set CP1624's PRACH collection delay to a per-run value, because
the active live baseline is continuous-mode TX after an initial timed anchor.

## Next Rung

If staying on the [host-redacted]-only latency branch, the next changed experiment should
place an RF-visible marker inside the actual live gNB lower-PHY/Soapy TX path,
not in a standalone all-timed helper. The marker must be tied to a known live
lower-PHY `baseband_gateway_timestamp`, use the CP1575 native-continuous mode,
and be captured by same-run M2SDR self-RX metadata. That would directly test
whether live continuous-frame emission is shifted relative to the PRACH
collection timestamp domain.

Until then, do not apply CP1624's delay knob from CP1645's tens-of-microseconds
helper value, and do not use the old CP1642/CP1643 `+22.631945 ms` duplicate
marker hit.
