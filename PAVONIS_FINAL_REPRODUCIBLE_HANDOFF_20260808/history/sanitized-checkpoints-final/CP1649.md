# Checkpoint 1649 - Live Native-Continuous Early TX Marker Self-RX

Date: [date-redacted] Europe/Zurich

## Goal

Run the first [host-redacted]-only live gNB/self-RX marker measurement from the CP1647
and CP1648 live TX marker instrumentation. The purpose was to insert a
deterministic RF-visible marker inside the actual live gNB lower-PHY/Soapy TX
path under the CP1575 native-continuous baseline, capture it with same-run
M2SDR RX metadata, and compare the selected TX timestamp to the marker's RX
time.

This run measured only one early marker, at `+23040000` samples
(`+2.0 s`) after the first live non-empty TX chunk. Per the current frontier,
that makes this checkpoint useful but not sufficient to clear the suspected
late-run mechanism where untimed continuation chunks after the single
`HAS_TIME` anchor could drift or jump tens of seconds into the stream.

## Result

The analyzer found the early marker with a strong zero-CFO match:

```text
PASS_MARKER_FOUND=1
BEST_SCORE=0.5229749083518982
BEST_CFO_HZ=0.0
BEST_SAMPLE=7333584
EXPECTED_RX_SAMPLE=7325610
LATENCY_SAMPLES=7974
LATENCY_MS=0.6921875
SELECTED_START_TS=4599664612140
```

This is evidence that the CP1647/CP1648 live marker hook is functional in the
actual native-continuous live TX path and that the same-run M2SDR RX metadata
can map a selected live TX marker timestamp to an RF-visible marker.

## Caveat

This checkpoint does not answer the late-run timing question. It placed only
one marker at about `+2 s` after the first live TX data chunk, while real Msg1
historically occurs roughly `60-120 s` into the run. The suspected failure mode
is specifically tied to long-lived untimed continuation chunks after the single
`HAS_TIME` anchor, so an early marker reading near zero or sub-millisecond
latency can falsely clear the live path.

The next changed experiment must measure at least two well-separated markers
inside the same live native-continuous gNB stream: one shortly after stream
start and one around `60-120 s`. Do not use CP1649's early `+0.6921875 ms`
result as a CP1624 delay value or as proof that late native-continuous TX
timing is stable.

## Verdict

`EARLY_LIVE_NATIVE_CONTINUOUS_MARKER_FOUND_BUT_LATE_LATENCY_UNTESTED`

CP1649 closes the immediate feasibility risk for live-path marker insertion
and same-device RX analysis, but leaves the active timing hypothesis open.
