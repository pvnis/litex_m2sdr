# Checkpoint 1650 - Live TX Marker Sequence Build Smoke

Date: [date-redacted] Europe/Zurich

## Goal

Add a default-off same-stream multi-marker mode for the CP1647/CP1648 live
gNB TX marker hook. CP1649 proved the early marker path works, but it measured
only `+2 s` after first live TX data. The next RF run needs one early marker
and one late marker around `60-120 s` in the same native-continuous live
stream.

This checkpoint is no-RF.

## Implementation

Patched:

```text
ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp
ocudu/lib/radio/soapy/radio_soapy_tx_stream.h
```

New default-off environment surface:

```text
PAVONIS_SOAPY_TX_MARKER_DELAY_SEQUENCE_SAMPLES=<comma-separated sample delays>
```

Alias also accepted:

```text
PAVONIS_SOAPY_TX_MARKER_DELAYS_SAMPLES=<comma-separated sample delays>
```

The existing single-marker mode remains available:

```text
PAVONIS_SOAPY_TX_MARKER_DELAY_SAMPLES=<single delay>
```

In sequence mode, each marker uses the first live non-empty TX chunk as the
dynamic origin when `PAVONIS_SOAPY_TX_MARKER_START_TS=0`. The marker at index
`i` starts at:

```text
first_live_chunk_start_ts + delay_sequence_samples[i]
```

The marker seed is `PAVONIS_SOAPY_TX_MARKER_SEED + i`, so the early and late
markers have distinct deterministic PN templates.

## New Proof Fields

TX readback now includes:

```text
tx_marker_sequence_mode
tx_marker_count
env_PAVONIS_SOAPY_TX_MARKER_DELAY_SEQUENCE_SAMPLES
env_PAVONIS_SOAPY_TX_MARKER_DELAYS_SAMPLES
```

The marker metadata TSV now records:

```text
sequence_mode
marker_count
delay_sequence_samples
delays_samples
selected_marker_<i>_start_ts
selected_marker_<i>_delay_samples
selected_marker_<i>_seed
selected_marker_<i>_first_chunk_start_ts
selected_marker_<i>_first_chunk_time_ns
selected_marker_<i>_first_chunk_logical_offset
```

The per-overlap rows now include marker index and marker seed:

```text
row marker_index marker_seed channel chunk_start_ts chunk_time_ns logical_offset overlay_start_ts overlay_end_ts marker_offset samples
```

For backward compatibility, marker `0` still writes the CP1648/CP1649 legacy
selection keys such as `selected_start_ts`.
