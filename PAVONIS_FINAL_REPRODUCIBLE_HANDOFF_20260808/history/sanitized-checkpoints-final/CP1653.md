# Checkpoint 1653 - Default-Off TX Reanchor Interval Build

Date: [date-redacted] Europe/Zurich

## Goal

After CP1652 found a valid late-run marker drift (`+1.37 ms` early versus
`+7.76 ms` at `+60 s`), add a software-only candidate fix for the live
native-continuous path before spending another RF run.

This checkpoint is no-RF.

## Source Audit

The OCUDU Soapy TX path computes a per-chunk `chunk_time_ns` from the baseband
timestamp, but under live native-continuous operation only the opening chunk
normally carries `SOAPY_SDR_HAS_TIME`; later chunks are sent as continuation
payload.

The LiteX M2SDR Soapy driver then writes a 16-byte TX DMA header for every
released DMA buffer:

```text
HAS_TIME set   -> timestamp header = ns_to_samples(timeNs)
HAS_TIME clear -> timestamp header = 0
```

The LiteX driver also has a duplicate-timestamp guard, but it only suppresses
`HAS_TIME` when the incoming `timeNs` exactly equals the previous timed
descriptor. Unique periodic timestamps should therefore survive into the DMA
headers.

## Implementation

Patched:

```text
ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp
ocudu/lib/radio/soapy/radio_soapy_tx_stream.h
```

New default-off environment variable:

```text
PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES=<positive sample interval>
```

Behavior when set:

```text
first non-empty data chunk selects the reanchor origin
next reanchor timestamp = origin + interval
each chunk with chunk_start_ts >= next reanchor timestamp gets SOAPY_SDR_HAS_TIME
that write uses the existing chunk_time_ns path
next reanchor timestamp advances by interval until it is ahead of the chunk
```

Default behavior is unchanged when the variable is unset or zero.

New proof fields:

```text
tx_reanchor_enabled
tx_reanchor_interval_samples
env_PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES
reanchor_writes
```

The summary line now reports `reanchor_writes` next to `has_time_writes`, so
future RF gates can prove the mode actually activated.

## Verdict

`TX_REANCHOR_INTERVAL_BUILD_SMOKE_PASS`

The [host-redacted] Soapy-enabled `gnb` now has a default-off periodic reanchor mode. This
does not prove the RF/timing issue is fixed; it only creates the software
lever needed for the next RF checkpoint.

The next changed RF run should rerun the CP1652 two-marker measurement with:

```text
PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES=1152000
M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1
```

`1152000` samples is `100 ms` at `11.52 Msps`; if CP1652's drift rate is the
right model, this should bound residual between-anchor drift to roughly the
low-tens-of-microseconds class while adding only about ten reanchors per
second. The RF gate should require nonzero `reanchor_writes`, many
`has_time_writes`, full RX append bytes, and both markers found.
