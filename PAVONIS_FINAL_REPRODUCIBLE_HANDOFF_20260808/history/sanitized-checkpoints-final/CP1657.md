# CHECKPOINT 1657 - Live Native-Continuous All-Timed Two-Marker RF Rerun

Date: [date-redacted]

## Goal

Run the user-requested two-epoch live-path latency measurement after CP1656's
all-timed live-chunk build. This tests whether the CP1652/CP1654 late-marker
drift is caused by native-continuous untimed continuation chunks after the
single initial `HAS_TIME` anchor.

## Method

Started the normal native-continuous live gNB path on [host-redacted] with same-device
M2SDR self-RX append and deterministic live TX markers.

Key env/gates:

```text
PAVONIS_SOAPY_TX_ALL_TIMED_CHUNKS=1
PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES=0
PAVONIS_SOAPY_TX_MARKER_DELAY_SEQUENCE_SAMPLES=23040000,691200000
PAVONIS_SOAPY_TX_MARKER_LEN=16384

RX_APPEND_MAX_SAMPLES=748800000
PAVONIS_SOAPY_RX_SUMMARY_MAX=1600000
```

This is the same early/late measurement geometry as CP1652/CP1654: one marker
at `+2 s` and one at `+60 s` in the same live stream.

## Verdict

`ALL_TIMED_CHUNKS_STABILIZE_LIVE_TX_TIMING`

This is the first changed live native-continuous TX-cadence variant in the
CP1652 branch that stabilizes the same-stream early/late TX-marker latency.
It strongly supports the theory that the old multi-ms late drift came from the
timed-first-anchor plus untimed-continuation cadence, not from a static RF path
delay, weak power, or a marker/analyzer artifact.

Do not use CP1652/CP1654 marker latency as a CP1624 delay. CP1657 provides the
current stable live-path timing class under all-timed chunks, with apparent
latency around `+0.94..+0.97 ms` over `+2 s` to `+60 s`.
