# Checkpoint 1661: Lead30ms Two-Marker Self-RX, Early Marker Placement Fail

Date: [date-redacted] Europe/Zurich

## Goal

Measure the CP1660-style live all-timed TX path at two well-separated points
in the same stream, not just near startup. This directly follows the
single-anchor/untimed-continuation drift concern: an early-only marker can
falsely clear the path.

CP1661 reuses the CP1657 two-marker self-RX harness but changes the TX
scheduling headroom to CP1660's value:

```text
PAVONIS_SOAPY_TX_ALL_TIMED_CHUNKS=1
PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES=0
M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1
M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000
marker delays=23040000,691200000 samples
marker epochs=about +2 s and +60 s at 11.52 Msps
```

## Marker Result

The late marker was valid and found:

```text
MARKER_1_PASS=1
MARKER_1_DELAY_SAMPLES=691200000
MARKER_1_SCORE=0.5296477675437927
MARKER_1_CFO_HZ=0.0
MARKER_1_LATENCY_SAMPLES=344920
MARKER_1_LATENCY_MS=29.94097222222222
```

This is consistent with the explicit 30 ms TX scheduling offset. The late
point does not show a large CP1652-style drift/jump by itself.

The early marker is invalid because the overlay was partial:

```text
MARKER_0_PASS=0
MARKER_0_DELAY_SAMPLES=23040000
MARKER_0_SCORE=0.03293659910559654
MARKER_0_LATENCY_MS=-44.90043402777778
```

Marker metadata shows why the analyzer failed:

```text
marker 0 rows=2 samples=1894 min_marker_offset=0 max_marker_offset=11370
marker 1 rows=17 samples=16384 min_marker_offset=0 max_marker_offset=15458
```

`marker_len` is `16384`, so marker 0 only covered `1894/16384` samples and is
not a valid correlation marker. Marker 1 covered the full marker.

## Verdict

CP1661 is not a valid two-point latency measurement because the early marker
was not fully overlaid. It is still useful:

```text
TX/all-timed/30ms health: PASS
late +60 s marker: PASS, latency about +29.94 ms
early +2 s marker: INVALID, partial marker overlay
two-point timing stability verdict: NOT MEASURED
```

Do not use CP1661 as a latency-stability proof or as a CP1624 delay. The next
changed rerun should keep two same-stream markers but move the early marker
out of the startup sparse overlay region, for example from `+2 s` to `+5 s`,
while keeping the late marker around `+60 s`.
