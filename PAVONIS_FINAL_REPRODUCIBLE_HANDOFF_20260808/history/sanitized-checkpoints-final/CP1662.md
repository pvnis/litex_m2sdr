# Checkpoint 1662: Lead30ms +5s/+60s Two-Marker Self-RX, Late Marker Placement Fail

Date: [date-redacted] Europe/Zurich

## Goal

Rerun CP1661's two-point CP1660-style marker measurement, but move the early
marker from `+2 s` to `+5 s` so it avoids the startup sparse overlay region.
The late marker remains around `+60 s`, preserving the user's requirement to
measure both a shortly-after-start point and a late `60-120 s` point in the
same stream.

```text
PAVONIS_SOAPY_TX_ALL_TIMED_CHUNKS=1
PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES=0
M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1
M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000
marker delays=57600000,691200000 samples
marker epochs=about +5 s and +60 s at 11.52 Msps
marker_len=16384
```

## Marker Result

Moving the early marker to `+5 s` fixed the startup placement problem:

```text
MARKER_0_PASS=1
MARKER_0_DELAY_SAMPLES=57600000
MARKER_0_SCORE=0.6557425856590271
MARKER_0_CFO_HZ=0.0
MARKER_0_LATENCY_SAMPLES=345861
MARKER_0_LATENCY_MS=30.02265625
```

The late marker failed for the same structural reason CP1661's early marker
failed: only a partial `16384`-sample marker was overlaid.

```text
MARKER_1_PASS=0
MARKER_1_DELAY_SAMPLES=691200000
MARKER_1_SCORE=0.03132990002632141
MARKER_1_CFO_HZ=0.0
MARKER_1_LATENCY_MS=57.48324652777778
```

Marker metadata makes the failure mode explicit:

```text
marker 0 rows=17 samples=16384 min_marker_offset=0 max_marker_offset=15458
marker 1 rows=2 samples=1894 min_marker_offset=0 max_marker_offset=11370
```

`marker_len` is `16384`, so marker 0 was valid and marker 1 was not.

## Verdict

CP1662 is not a valid two-point timing-stability measurement. It does prove
that the corrected early point at `+5 s` is measurable and lands at about
`+30.02 ms`, consistent with the explicit 30 ms TX offset. It also shows that
the current `16384`-sample marker can straddle sparse live TX chunks at either
early or late epochs depending on run phase.

Next changed marker work should keep the two separated epochs but shorten the
marker so it fits inside one live data burst, for example `MARKER_LEN=512`,
rather than continuing to chase phase luck with a `16384`-sample marker.
