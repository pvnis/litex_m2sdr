## Analysis

The original broad `+/-1000000` sample analyzer returned `PASS_ALL_MARKERS=1`,
but with false-looking broad peaks because a 512-sample marker is too short
for an unconstrained `+/-86.8 ms` search:

```text
broad marker 0 latency=-75.71223958333333 ms
broad marker 1 latency=+11.[subscriber-redacted] ms
```

Those broad values should not be used.

CP1663 then reran a saved-capture focused analysis on [host-redacted], restricted to the
plausible `20..40 ms` latency window for the explicit 30 ms TX offset. That
analysis is the checkpoint result:


The early and late markers land in the same latency class to about `9.5 us`.
This answers the immediate drift/jump question: under CP1660's all-timed
`30 ms` headroom, the same-stream marker offset does not grow by milliseconds
between about `+5 s` and `+60 s`.

a late `60-120 s` drift/jump in the CP1660 all-timed 30 ms live path. Do not
use CP1661 or CP1662 as timing results; they are marker-placement diagnostics.

it cautiously for any future CP1624-style delay setting. Its strongest
immediate value is differential: the early and late offsets are stable within
microseconds in the same stream.
