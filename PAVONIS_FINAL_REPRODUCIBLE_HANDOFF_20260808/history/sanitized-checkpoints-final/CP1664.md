Date: [date-redacted] Europe/Zurich

## Goal

Perform a no-RF artifact audit after CP1660. CP1660 restored the delayed
all-timed TX class and UE DL/SFN acquisition, but no real Msg1 was emitted.
The question for CP1664 is whether that no-Msg1 result is explained by a UE
configuration change, a gNB PRACH detector/window issue, or a post-SFN DL
tracking/RACH-config receipt failure.

The comparison baseline is CP1632, the last known real-UE guard0/no-append
run where the UE received usable RACH config and emitted Msg1.

## Interpretation

CP1664 narrows CP1660's failure to post-SFN DL continuity and RACH-config
receipt/application under the all-timed `30 ms` delayed real-UE harness.

The two-marker CP1663 result remains valid and important: the CP1660-style
all-timed `30 ms` TX path does not show millisecond-scale late-run offset
growth between `+5 s` and `+60 s`. But that does not by itself prove the UE can
stay synchronized and decode SIB/RACH config after SFN. CP1660 shows it often
cannot: its repeated PHY out-of-sync skips begin immediately after cell select.

Leading changed variable versus CP1632:

```text
CP1632: native continuous, M2SDR_SOAPY_TX_TIME_OFFSET_NS=1000000
CP1660: all timed chunks, M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000
```

The all-timed mode is required by CP1658 for the raw DL TRACK gate, while
CP1659 showed that the delayed real-UE harness regresses into TX-late without
extra headroom. The next rung should not abandon all-timed mode; it should
bracket the minimum TX time offset that keeps the 60 s delayed pre-UE late gate
clean while reducing the post-SFN out-of-sync/RACH-config failure risk.

## Next Rung

Run a real-UE all-timed guard0 smoke with the same pre-UE late gate as CP1660
but a smaller TX time offset, starting at:

```text
M2SDR_SOAPY_TX_TIME_OFFSET_NS=10000000
```

Gate logic:

```text
If the pre-UE late gate fails: skip UE, report as insufficient headroom.
If the late gate passes: start UE and compare:
  - first post-SFN out-of-sync timing/count
  - whether real RACH config appears (config_idx=1, root_seq_idx=1, freq_offset=7, num_ra_preambles=64)
  - Msg1/PRACH-TX/RA-timing counts
```

This is a changed RF rung. Do not rerun CP1660 unchanged, and do not interpret
a no-Msg1 run unless the UE first receives a real RACH config or the failure is
classified as a post-SFN DL tracking/config-receipt failure.
