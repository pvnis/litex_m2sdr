## SIB1 Trace

The trace classified the failure before SIB1 decode/RACH apply:

```text
si_pdcch=800
si_pdsch_grant=0
bcch_dlsch_decoded=0
processing_sib1=0
phy_set_config_ok=0
worker_pool_prach_after_offset=1
```

The `si_pdcch` trace starts immediately after SFN sync:

```text
slot=5141 sif=1 n_dl=0 candidates=6 max_epre=6.002 max_corr=0.090929
```

and reaches the trace limit at:

```text
slot=5940 sif=0 n_dl=0 candidates=6 max_epre=0.500 max_corr=0.038421
```

Every traced SI-RNTI PDCCH search reported `n_dl=0`; no SI PDSCH grant was
ever produced in the first 800 post-SFN slots. Therefore the missing RACH
config is not a later RRC/RACH-config application failure in this run. The
failure is before `decode_pdu_bcch_dlsch()` and before `handle_sib1()`.

The detail log still shows substantial post-SFN sync loss:

- `out-of-sync` rows: `790`
- first row: `[date-redacted]`

That begins after the 800-slot SIB trace window, so it does not explain the
absence of SI grants in the traced interval.

## Verdict

CP1669 is a valid all-timed failure checkpoint, not a void TX-health retry.
It proves that under the CP1660/CP1658 all-timed `30 ms` presentation, the UE
can acquire PBCH/SFN but cannot decode any SI-RNTI PDCCH into an SI PDSCH grant
during the traced post-SFN window. The no-RACH-config symptom is therefore
upstream of SIB1/RRC/RACH application for this run.
