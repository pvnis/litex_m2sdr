## Verdict

CP1673 is a valid all-timed post-SFN SI/SIB failure checkpoint. It is not a
TX-health void: all-timed readback passed, the delayed pre-UE late gate passed,
final TX counters stayed clean, and UE PBCH/cell-select/SFN were strong.

The CP1672/CP1673 A/B is now sharp:

- CP1672 native-continuous with the same low-impact trace: SI grant, SI PDSCH
  grant, SIB1 decode, RACH config, and seven Msg1 attempts.
- CP1673 all-timed `30 ms` with the same low-impact trace: DL/SFN succeeds,
  but `800` no-grant SI-PDCCH summaries report `n_dl_max=0`; there is no SI
  grant, no SIB1 decode, no RACH config, and no Msg1.

The current blocker is therefore above PBCH/SFN and below PRACH detection:
all-timed live TX presentation breaks the real-UE post-SFN SI-RNTI
PDCCH/PDSCH visibility or its timing/presentation, even though CP1658 proves
the same all-timed mode fully clears the raw scheduled-TRACK PBCH gate.

Do not rerun CP1673 unchanged, and do not spend more PRACH detector/window
runs on all-timed until the all-timed path recovers real SIB1/RACH config.
Next work should be no-RF or low-risk source/log comparison of CP1672 versus
CP1673 SI scheduling/search timing, then a changed TX-presentation variant that
preserves CP1658 raw PBCH/TRACK while recovering CP1672-class SIB1/RACH config.
