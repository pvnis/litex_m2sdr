## TX presentation audit

The TX readback diff between CP1672 and CP1673 is narrow:

- CP1672: `tx_all_timed_chunks=0`,
  `env_M2SDR_SOAPY_TX_TIME_OFFSET_NS=1000000`
- CP1673: `tx_all_timed_chunks=1`,
  `env_M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`,
  `env_PAVONIS_SOAPY_TX_ALL_TIMED_CHUNKS=1`,
  `env_PAVONIS_SOAPY_TX_REANCHOR_INTERVAL_SAMPLES=0`
- The remaining geometry and format stay aligned: `CS16`, `11.52 Msps`,
  `1842500000 Hz`, ATT `5 dB`, continuous gNB config.

Final TX summaries differ sharply:

CP1672 native-continuous:

```text
has_time_writes=1 all_timed_writes=0 partial_ret=1 timeouts=29 errors=0
samples_req=3533077292 samples_ret=3533047264
LiteX has_time/post_has_time=1 late_count/post_late_count=0
```

CP1673 all-timed:

```text
has_time_writes=614490 all_timed_writes=614489 partial_ret=6790 timeouts=132292 errors=0
samples_req=2227192734 samples_ret=2089039356
LiteX has_time/post_has_time=570291 late_count/post_late_count=0
```

The OCUDU wrapper does not directly drop a positive partial return: it advances
`sent_total` by `ret` and loops until the logical data chunk is sent.

The lower LiteX Soapy layer has the more relevant behavior. With
`M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1`, it currently releases a partial
remainder buffer before an incoming timed write only when the existing
remainder is untimed:

```text
incoming HAS_TIME && timeNs > 0 && existing remainder lacks HAS_TIME
```

If the existing partial remainder buffer already has `SOAPY_SDR_HAS_TIME`, a
later timed write can be appended into that same buffer. The code explicitly
keeps the first timestamp:

```text
HAS_TIME must NOT overwrite a timestamp set by an earlier writeStream that
opened this buffer - the buffer fires from the first ts.
```

That is sensible for truly contiguous writes, but all-timed mode is intended
to preserve each live chunk's own timestamp. If a new timed write is not
exactly the continuation time of the partial timed buffer, the current lower
layer can swallow that timed boundary by coalescing the new samples into the
old timestamped buffer.

## Verdict

CP1674 does not prove a final RF fix, but it identifies the next software
rung. CP1673 is not explained by gNB YAML, UE radio config, UE trace env, or
missing the known-good SI slot class. It is consistent with all-timed chunk
boundaries being merged inside LiteX Soapy partial TX buffers while retaining
the first buffer timestamp.

Next work should be a no-RF source patch/build on [host-redacted]: extend
`M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1` so a partial timed TX buffer is
also released before an incoming timed write when the incoming `timeNs` is not
the expected contiguous continuation of `remainder_timeNs + remainderOffset`.
After build/deploy, rerun a raw all-timed gate or a focused real-UE SIB1 gate
only with readback/log proof that the new timed-remainder split path is active.
