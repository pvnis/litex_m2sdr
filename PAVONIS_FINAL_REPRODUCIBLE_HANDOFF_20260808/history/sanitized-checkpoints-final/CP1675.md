# CP1675 - Timed Remainder Split Build

Date: [date-redacted] Europe/Zurich

## Goal

Build-smoke the CP1674 source-level lead on [host-redacted] before spending more RF: when
`M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1` is active, LiteX Soapy should
release an existing partial TX remainder before an incoming timed write if that
incoming timestamp is not the expected contiguous continuation of the partial
buffer's timestamp plus its filled sample count.

This is a no-RF checkpoint.

## Change

Patched:

`litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp`

New behavior in `writeStream()`:

- Existing behavior is preserved for an incoming timed write after an untimed
  partial buffer.
- If the partial buffer is already timed, compute:
  `expected_time_ns = remainder_timeNs + samples_to_ns(samplerate, remainderOffset)`.
- If `incoming_time_ns - expected_time_ns` is outside `[-1, +1] ns`, release the
  current partial buffer before accepting the new timed write.
- Log the first split events as:
  `M2SDR TX HAS_TIME remainder align: releasing partial timed-discontinuous buffer ... expected_time_ns=... delta_ns=...`

## Verdict

CP1675 passes as a no-RF build/deploy checkpoint. The driver-side timed
remainder split is now present in the [host-redacted] LiteX Soapy module.

Do not treat this as RF proof. The next RF checkpoint must prove whether the new
split path is active and whether timing remains stable at two separated points
in the same stream. Per user direction, do not clear the live path from an
early-only marker: arm short markers both shortly after stream start and again
in the `60-120 s` band where real Msg1 historically occurs.
