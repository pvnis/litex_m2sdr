## Interpretation

CP1677 does not create a new failure mode. It reproduces CP1673's all-timed
post-SFN SI-RNTI visibility failure under better diagnostic conditions:

- clean pre-UE and final TX-late gates.
- no release-late rows.
- no camping TTI mismatches in the first 160 rows.
- no CP1675 split-align activity.
- no SI grant despite long SI summary coverage.

The CP1675 timed-remainder split is therefore not supported as the active cause
of the observed real-UE all-timed SIB1 failure. It may still be useful for a
different partial-buffer shape, but it is not being exercised here.

The remaining confound in the CP1672 versus CP1673/CP1677 A/B is that CP1672
uses native-continuous single-anchor TX with `1 ms` TX offset, while CP1673 and
CP1677 use all-timed TX with `30 ms` TX offset. CP1665 showed all-timed `10 ms`
still fails RACH config, and CP1659 showed all-timed `1 ms` is not late-clean
in the delayed real-UE harness. But no current low-impact-trace run has tested
native-continuous with the same `30 ms` TX headroom.

## Verdict

CP1678 is a no-RF audit checkpoint. It closes CP1677 as a repeat of the
all-timed SI visibility failure, not a changed or split-fixed path.

Next changed RF rung:

Run the CP1672 native-continuous positive-control path with
`M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000` and the same low-impact SIB1 trace.

Expected discriminator:

- If native-continuous `30 ms` still reaches SI grant/SIB1/RACH config/Msg1,
  then the blocker is the all-timed TX presentation, not the `30 ms` headroom.
- If native-continuous `30 ms` also loses SI grants, then the `30 ms` headroom
  itself is implicated and the all-timed SI branch should bracket offset or
  compensate SI timing before trying more TX-presentation changes.

This does not replace CP1658 as the raw PBCH/TRACK baseline; it is a focused
real-UE SI-layer discriminator.
