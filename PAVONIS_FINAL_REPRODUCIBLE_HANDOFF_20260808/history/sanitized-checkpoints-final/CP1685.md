## Verdict

CP1685 validates the user's two-point concern for the `2 ms` native
single-anchor path. An early marker at `+5 s` measures only about `+0.976 ms`,
but the late marker at `+60 s` measures `+6.861 ms`; the same stream shifts by
`5.885 ms`. The run is mechanically clean and both markers pass with strong
scores, so this is not an early-only false clearance and not an RX append cap
artifact.

This result explains why CP1684 can show a partial early SI grant while still
not clearing SIB1/RACH config reliably later: native single-anchor timing is
epoch-dependent even at `2 ms`. A static delay derived near startup is not a
valid delay value for the real Msg1/SIB1 decision epoch. Future timing work on
native single-anchor TX must keep at least two same-stream markers, one near
startup and one in the `60-120 s` region, or use a TX presentation whose timing
has already been proven stable at both epochs.
