two-marker method used by CP1685. This tests whether the known-good

## Verdict

CP1686 proves the CP1672-class native `1 ms` path is also epoch-dependent in
the same-marker instrument: `+5 s` latency is `+2.083 ms`, while `+60 s`
latency is `+9.807 ms`, a `7.724 ms` same-stream spread. The run is
mechanically clean, both markers pass strongly, and the RX metadata overflows
are far from both marker windows.

This is an important control: CP1672's real SIB1/RACH-config/Msg1 success does
not mean native single-anchor TX has stable absolute timing over the real-UE
run. Therefore CP1685's `2 ms` drift is not, by itself, enough to explain why
CP1684 only reached an SI grant without BCCH/SIB1 decode. The SIB1 breakpoint
still exists empirically (`1 ms` full pass, `2 ms` grant-only partial,
`5/10/30 ms` no-grant), but the mechanism is not a simple "no drift at 1 ms,
drift at 2 ms" split.

## Next

The next useful discriminator is a same-run coupling of SIB1 behavior and
two-point timing, or a bracket inside `1-2 ms` with the same low-impact SIB1
trace while treating timing as epoch-dependent. Do not use a startup-only
marker or a static run-start delay as a pass criterion for native single-anchor
TX.
