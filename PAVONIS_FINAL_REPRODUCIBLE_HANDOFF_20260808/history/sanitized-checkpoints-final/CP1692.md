## Verdict

CP1692 is mechanically valid and confirms the CP1691 module was installed, but
it does not recover SIB1/RACH/Msg1. It also does not exercise the CP1691
partial-carry path or the older CP1675 timed-discontinuous split path:
both counts are `0`.

Useful conclusions:

- The all-timed `30 ms` real-UE SIB1 failure persists with the CP1691 module.
- The CP1691 partial-buffer carry fix is not the active observed failure path
  for this run.
- The TX path is clean on late/write-error counters, so this is not a repeat of
  CP1659's late-counter failure.
- PRACH detector/window analysis must remain stopped because there is no real
  Msg1.

Do not rerun CP1692 unchanged, and do not spend another RF run on the CP1675/
CP1691 partial-buffer split/carry theory unless a no-RF trace first proves that
the targeted branch will actually be exercised. The next changed work should be
source/log analysis of why all-timed post-SFN SI-RNTI PDCCH visibility remains
absent despite strong PBCH/SFN and clean TX counters, with special attention to
the timed descriptor/write geometry around the SI slot class and the difference
between CP1658 raw TRACK success and CP1672-class real-UE SIB1 recovery.
