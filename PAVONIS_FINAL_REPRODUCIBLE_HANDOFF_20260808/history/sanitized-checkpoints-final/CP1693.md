# CHECKPOINT 1693 - All-timed TX write-timeout 50 ms gate

Date: [date-redacted] Europe/Zurich

## Goal

Continue the all-timed SIB1 branch after CP1692 without returning to the
drifty CP1687 PRACH-window baseline. CP1692 showed that the CP1691 LiteX
partial-carry fix did not exercise, while long real-UE all-timed runs still
lost SI/SIB1. The new no-RF audit found a stronger TX-side suspect:
CP1677/CP1692 all-timed real-UE runs accumulated about `132k` Soapy TX
timeouts and about `138M` missing returned samples, whereas CP1658 raw TRACK
and CP1672 native SIB1-positive controls did not.

The source audit found that OCUDU's default Soapy TX write timeout is `200 us`,
while LiteX PCIe TX buffer acquisition uses `poll(timeoutUs / 1000)`. At
`200 us`, a full TX ring is therefore effectively polled with `0 ms`, causing
immediate `SOAPY_SDR_TIMEOUT` returns. OCUDU records those returns in
`tx_summary.timeouts` and returns from `transmit()`, skipping the rest of that
logical TX buffer.

## Verdict

CP1693 proves two things:

- The large all-timed long-run sample deficit seen in CP1677/CP1692 is tied to
  OCUDU/LiteX TX write-timeout/backpressure handling, because `50 ms` almost
  eliminates timeouts and missing returned samples.
- A `50 ms` blocking write timeout is too blunt for the live real-UE all-timed
  path: it preserves TX-late counters but changes the live presentation enough
  that the UE loses normal PBCH/cell-select acquisition.

Do not rerun CP1693 unchanged. Do not return to CP1687 PRACH-window analysis.
The next changed rung should bracket a smaller explicit write timeout, starting
with the minimum useful LiteX PCIe poll resolution (`1000 us`) and then
possibly `5000 us`, while keeping the same gates:

- readback must prove `write_timeout_us` reached runtime.
- final Soapy `timeouts`, `partial_ret`, and `samples_req - samples_ret` must
  be reported.
- UE must reach PBCH/SFN before SI/SIB1 can be interpreted.
- any run without Msg1 remains void for PRACH detector/window conclusions.
