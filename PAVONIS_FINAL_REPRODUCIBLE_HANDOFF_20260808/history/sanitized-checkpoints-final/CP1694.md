# CHECKPOINT 1694 - All-timed TX write-timeout 1 ms gate

Date: [date-redacted] Europe/Zurich

## Goal

Run the smaller explicit write-timeout bracket requested after CP1693. CP1693
proved the all-timed long-run Soapy timeout/sample-deficit mechanism is
controllable, but `50 ms` was too blunt and regressed UE acquisition before
cell select. CP1694 tests the minimum useful LiteX PCIe poll class:

```text
OCUDU_SOAPY_TX_WRITE_TIMEOUT_US=1000
```

The success criterion from the current frontier is stricter than old SIB1
checks: a run must have both zero returned-sample deficit and normal PBCH/SFN
acquisition before it can be treated as a valid SIB1 datapoint.

## Verdict

CP1694 is useful but fails the new gate:

- `1 ms` explicit TX write timeout restores normal PBCH/SFN acquisition,
  SIB1 decode, real RACH config, and seven Msg1 attempts.
- It still leaves a large all-timed TX returned-sample deficit
  (`129,885,758` samples), with `125,304` timeout returns and `7,678` partial
  returns.

Therefore CP1694 is not a valid SIB1 datapoint by the current success
criterion, and its gNB detector result should not be used as the next ladder
conclusion. Per the updated direction, stop [interface-redacted] constant timeout values.
The next checkpoint should change OCUDU `radio_soapy_tx_stream::transmit()` so
`SOAPY_SDR_TIMEOUT` retries the unwritten remainder with a short poll and a
bounded retry budget instead of abandoning the logical buffer. No-Msg1 runs
remain void for PRACH conclusions.
