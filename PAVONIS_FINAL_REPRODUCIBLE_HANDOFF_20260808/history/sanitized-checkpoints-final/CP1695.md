# Checkpoint CP1695 - OCUDU TX Timeout Retry Build

Date: [date-redacted]

## Goal

Implement the post-CP1694 fix requested for the all-timed SIB1 gate: when
OCUDU `radio_soapy_tx_stream::transmit()` sees `SOAPY_SDR_TIMEOUT` on a data
write, it must retry the same unwritten chunk with a short poll and bounded
retry budget instead of abandoning the logical buffer.

## Source Change

Touched files:

- `ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp`
- `ocudu/lib/radio/soapy/radio_soapy_tx_stream.h`


Behavior added:

- Default-on retry controls:
  - `OCUDU_SOAPY_TX_TIMEOUT_RETRY` (default enabled; `0`/`false`/`no`/`off` disable)
  - `OCUDU_SOAPY_TX_TIMEOUT_RETRY_MAX` (default `64`)
  - `OCUDU_SOAPY_TX_TIMEOUT_RETRY_US` (default/minimum `1000 us`)
- TX readback sidecar fields:
  - `tx_timeout_retry_enabled`
  - `tx_timeout_retry_max_attempts`
  - `tx_timeout_retry_timeout_us`
  - matching env readbacks
- TX summary fields:
  - `data_samples`
  - `timeout_retry_attempts`
  - `timeout_retry_successes`
  - `timeout_retry_exhausted`
  - `timeout_retry_recovered_samples`
  - `timeout_retry_abandoned_samples`
- Data-write path change:
  - first attempt still uses `write_timeout_us`
  - a timeout retries the same chunk, same timestamp, and same requested flags
  - retry attempts use `tx_timeout_retry_timeout_us`
  - only an exhausted retry sequence records abandoned samples and returns

Padding, empty-EOB, and stop-flush writes keep their existing behavior. The
CP1694 failure was sustained data-buffer timeout/backpressure, so the patch is
scoped to data writes.

## Verdict

CP1695 passes as a no-RF build checkpoint. The retry fix is installed in the
[host-redacted] Soapy-enabled OCUDU `gnb` binary and is ready for the next all-timed RF
gate.

This is not a SIB1 or PRACH datapoint. The next valid RF run must prove both:

- zero abandoned/returned TX sample deficit under the new retry path
- normal PBCH/SFN acquisition, then SIB1/RACH/Msg1 if the TX gate passes

No-Msg1 runs remain void for PRACH detector conclusions.
