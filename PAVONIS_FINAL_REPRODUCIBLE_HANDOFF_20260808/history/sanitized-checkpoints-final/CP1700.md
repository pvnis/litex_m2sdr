# CHECKPOINT 1700 - no-RF SI TX geometry and CP1694 PRACH replay

## Goal

Stay no-RF and answer the two requested questions:

1. Compare CP1694 versus CP1698 TX chunk/timing geometry around SI slots,
   because CP1698 shows degraded SI-PDCCH correlation rather than absent
   signal.
2. Replay CP1694's captured PRACH predemod windows through the actual gNB
   detector with swept window offsets to measure any residual Msg1-to-window
   offset available from saved data.

## Method

No RF commands were run.

The analysis script maps UE SI slots to gNB TX summaries by using the gNB PRACH
manifest hardware sample timestamps as a time base, then selects the cumulative
Soapy TX summary whose `has_time_max_ns` covers that mapped slot. For PRACH, a
new C++ harness feeds CP1694's saved same-wall-time 1 ms predemod CF32 files
through OCUDU's PRACH OFDM demodulator and `prach_detector`, sweeping
`-11520..+11520` samples in `128` sample steps.

## SI Geometry Result

CP1694's passing SI row is still the clean reference:

```text
slot=9601 n_dl=1 max_epre=22.977 max_corr=0.797950
```

At the mapped TX summary near that slot, CP1694 had already dropped a large
amount of data in the legacy write path:

```text
samples_req - samples_ret = 29311450 samples ~= 2544.397 ms
timeouts=28266
```

CP1698 behaves differently. The SI signal is present in energy but degraded in
correlation:

```text
SI summary rows: 800
n_dl-positive rows: 0
best max_corr: 0.409127
mean/median max_corr: 0.248491 / 0.249704
rows >= 0.4: 1
rows >= 0.5: 0
max_epre mean/min/max: 22.400 / 22.120 / 23.191
```

The largest testable difference is in-run timeout-carry backlog. CP1698's final
stop summary drains to `stream_deficit=0`, but the SI-era periodic summaries
show queued/pending samples on the order of whole radio frames. The top CP1698
correlation rows map to:

```text
max_corr=0.409127 slot=4321 carry_pending=18.113 ms
max_corr=0.372081 slot=4961 carry_pending=13.540 ms
max_corr=0.370638 slot=9441 carry_pending=17.000 ms
max_corr=0.360795 slot=4481 carry_pending=18.379 ms
```

For the exact CP1694 passing SI slot class (`9601`), CP1698 repeats also carry
multi-ms backlog:

```text
line=248 max_corr=0.225261 max_epre=22.777 carry_pending=18.379 ms
line=299 max_corr=0.199498 max_epre=22.461 carry_pending=8.556 ms
line=350 max_corr=0.297476 max_epre=22.393 carry_pending=15.935 ms
line=453 max_corr=0.233674 max_epre=22.419 carry_pending=9.548 ms
```

This explains why "zero final stream deficit" is not a sufficient SIB1 gate:
the carry path can preserve sample count while dragging live timed TX cadence
by many milliseconds during the SI window. That is a specific, testable
difference between CP1694 and CP1698.

Those weak rows are not detector passes: the absolute peak threshold remains

therefore cannot measure a residual all-timed Msg1-to-window offset. They only
show that the same saved windows are too weak or misplaced for the actual gNB
detector, even after a +/-1 ms offline shift.

## Conclusion

CP1700 produces one actionable no-RF difference and closes one no-RF replay
avenue:

- Actionable SI difference: CP1698 preserves final sample count by carrying
  timed chunks, but has `8-18 ms` of in-run pending backlog during SI windows.
  The next software change should be deadline/cadence-aware, and the gate must
  include in-run `timeout_carry_pending_samples` near SI, not only stop-time
  `stream_deficit=0`.
- Closed PRACH replay avenue: CP1694's saved 1 ms predemod files do not contain
  an accepted detector hit at any swept offset. A future PRACH residual-offset
  measurement would need wider/raw saved material, but no new RF should be run
  until the SI/carry-cadence difference is addressed.
