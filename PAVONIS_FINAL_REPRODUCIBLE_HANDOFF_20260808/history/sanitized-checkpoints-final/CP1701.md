## Goal

Address CP1700's no-RF finding that CP1698 preserved final sample count while

## Source change

Touched files:

- `/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp`
- `/home/[host-redacted]/CLionProjects/ocudu/lib/radio/soapy/radio_soapy_tx_stream.h`

Implemented deadline/cadence-aware timeout carry:

- `OCUDU_SOAPY_TX_TIMEOUT_CARRY_DEADLINE` enables the new policy; it defaults
  on with timeout carry.
- `OCUDU_SOAPY_TX_TIMEOUT_CARRY_MAX_LAG_SAMPLES` caps stale carry lag; when
  unset it defaults to `srate_hz / 1000`, i.e. about `1 ms` (`11520` samples at
  the current `11.52 Msps` Stage 6 geometry).
- `OCUDU_SOAPY_TX_TIMEOUT_CARRY_DEADLINE_GUARD_US` defaults to `[date-redacted] us`.
- `OCUDU_SOAPY_TX_TIMEOUT_CARRY_DEADLINE_MAX_WRITE_TIMEOUT_US` defaults to
  `1000 us`.

Behavioral change:

- Carry drains now choose their write timeout from the remaining hardware-time
  headroom to the current chunk deadline, minus the guard.
- If there is no guarded headroom left, the drain stops instead of blocking
  through the current chunk's deadline.
- Before a current chunk is queued behind older carry, old pending chunks are
  trimmed if their logical sample timestamp is more than the configured max
  lag behind the current chunk.
- Deadline drops are counted as abandoned samples and have dedicated counters,
  so the next RF gate can distinguish "cadence recovered by dropping stale
  backlog" from "zero-drop, low-pending carry".

difference. It does not prove SIB1 or PRACH. The next RF gate should rerun the
CP1698-class all-timed `30 ms`, `1 ms` write-timeout real-UE path against this
binary and require, at minimum:

- CP1701 binary hash `885a4eed8eced14e3ee633a3b972fb0628a70166bb8e145d2b84c9bb25496589`

  not just stop-time `stream_deficit=0`

- normal PBCH/SFN plus SIB1/RACH config before drawing any PRACH detector
  conclusion
