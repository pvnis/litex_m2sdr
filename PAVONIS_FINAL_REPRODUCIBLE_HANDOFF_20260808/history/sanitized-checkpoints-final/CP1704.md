# CHECKPOINT 1704 - all-timed 30 ms / 1 ms lag-observe pre-UE gate

## Goal

Run the CP1698/CP1702 RF shape against the CP1703 lag-observe build:
all-timed native-continuous live gNB TX, `30 ms` TX lead,
`OCUDU_SOAPY_TX_WRITE_TIMEOUT_US=1000`, synchronous timeout retry disabled,
deadline carry enabled, and destructive deadline drop left default-off.

The purpose was to test whether the CP1703 non-destructive policy preserves
stream samples without SI-era backlog, or at least fails the gate before UE/PRACH
work.

## Method

Added wrapper:

```text
cp1704_run_stage6_txatt5_nativecontinuous_alltimed_lead30ms_guard0_txwrite1ms_deadline_lagobserve_sequence.sh
sha256=7f2c74332ed655d65d7a68fc2b89669bc0845bfdbd6ef41394e437bd56811fec
```

The wrapper delegates to the established CP1696 sequence with:

```text
TX_TIME_OFFSET_NS=30000000
TX_WRITE_TIMEOUT_US=1000
TX_TIMEOUT_RETRY=0
TX_TIMEOUT_RETRY_MAX=0
TX_TIMEOUT_RETRY_US=1000
```

No explicit `OCUDU_SOAPY_TX_TIMEOUT_CARRY_DEADLINE_DROP` was exported, so the
CP1703 binary default remained `drop=false`.

## UE / bladeRF Side Note

The UE was not started, so CP1704 contains no SIB1, PRACH, Msg1, or detector
evidence.

[host-redacted] was reachable, but both the run preflight/postcheck and a separate
read-only diagnostic reported no bladeRF device:

```text
probe: No devices are available
lsusb: no Nuand/bladeRF USB device listed
no bladeRF/srsUE/capture processes visible
```

This did not affect CP1704 because the run stopped before UE start, but any
next UE/bladeRF RF checkpoint requires the bladeRF device to be restored or
explained first.

## Conclusion

CP1704 is a TX-gate failure, not a SIB1/PRACH datapoint.

Do not rerun CP1704 unchanged. The CP1703 non-destructive lag counters prove
that the CP1701/CP1702 deadline-carry approach does not preserve stream
continuity at this `30 ms`/`1 ms` point: with dropping disabled, the queue hits
the configured `1,152,000` sample limit, overflows, abandons hundreds of
millions of samples, and trips release-late traces before UE start.

Next work should stay out of UE/PRACH until the TX pre-UE gate can hold:

```text
timeout_carry_deadline_lag_events=0
timeout_carry_deadline_would_drop_samples=0
timeout_carry_deadline_dropped_samples=0
timeout_carry_overflow_samples=0
timeout_carry_abandoned_samples=0
stream_deficit=0
release_late_trace_count=0
```

The current leading software task is not more timeout-constant [interface-redacted]; it is a
different real-time TX/backpressure policy or a fast pre-UE invalidation gate
that stops as soon as these counters become nonzero.
