# CHECKPOINT 1705 - strict pre-UE TX-carry health gate

## Goal

Stay no-RF and turn CP1704's failure mode into a reusable fast pre-UE gate.
The gate must reject a gNB before UE start when OCUDU/M2SDR TX already shows
stream deficit, carry overflow/abandonment, deadline lag/would-drop/drop
counters, or LiteX release-late evidence.

This checkpoint does not try to fix the real-time TX/backpressure policy. It
prevents spending UE/PRACH runs on an already-invalid TX state.

## Method

Added the reusable parser/gate:

```text
cp1705_strict_tx_carry_gate.py
sha256=ff768f55c8bdc8af4450d6d990749bd3d4f9495bcf26899deb04144143b29e82
```

The gate parses `gnb.log` and fails on nonzero:

```text
stream_deficit
timeout_carry_abandoned_samples
timeout_carry_overflow_samples
timeout_carry_deadline_lag_events
timeout_carry_deadline_would_drop_samples
timeout_carry_deadline_dropped_samples
LiteX worker late_count / underflow_count / acquire_errors
LiteX release post_late_count / dedup_suppressed
LiteX release-late trace lines
```

It also supports:

```text
--require-carry-fields
--require-latest-pending-zero
--max-current-pending-samples
```

For pre-CP1697 logs that do not have `stream_deficit`, it derives a legacy
`samples_req - samples_ret` deficit.

Added a no-RF [host-redacted] deploy/smoke wrapper:

```text
cp1705_deploy_strict_tx_carry_gate_nuc4.sh
sha256=71afbc9e4d876e6c6ad235a5d41dd746863c097bb08decc49a73d620be125857
```

The first sandboxed deploy attempt failed at SSH/SCP with `rc=255`, matching
the known sandbox/network behavior. The escalated no-RF retry passed.

## Conclusion

CP1705 is a no-RF gate-hardening checkpoint, not a SIB1/PRACH datapoint.

Future UE/PRACH wrappers should call the strict gate from [host-redacted] before creating
the UE arm file or starting [host-redacted]. A run is invalid if the gate reports any
nonzero stream deficit, carry abandonment/overflow, deadline lag/would-drop/drop,
or LiteX release-late evidence.

This does not solve the CP1704 TX/backpressure problem. It closes the "fast
pre-UE invalidation gate" part of the frontier so the next technical work can
focus on a different real-time TX/backpressure policy without wasting UE runs.
Also, bladeRF visibility on [host-redacted] still must be restored or explained before
any next UE/bladeRF RF checkpoint.
