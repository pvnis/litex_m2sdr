# CHECKPOINT 1706 - OCUDU deadline-aware direct-write timeout build

## Goal

Stay source/no-RF and address the real TX/backpressure issue left after CP1705:
CP1701 made timeout-carry drains deadline-aware, but the first/direct data
`writeStream()` call still used the fixed `OCUDU_SOAPY_TX_WRITE_TIMEOUT_US`
value. At the CP1694/CP1698/CP1704 shape that fixed `1 ms` write timeout can
create the carry backlog before the carry policy ever has a chance to help.

CP1706 adds an env-gated direct-write policy that chooses the first data-write
timeout from the chunk RF deadline and current hardware time, instead of
[interface-redacted] another constant.

## Source Change

```text

sha256=9e6e4df14b84ffa00cacdd4d96aa2a6d9ff6dc34ba07a56463358f1e09dd63fa
```

New env-gated knobs:

```text
OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT=1
OCUDU_SOAPY_TX_DEADLINE_WRITE_GUARD_US
OCUDU_SOAPY_TX_DEADLINE_WRITE_MAX_TIMEOUT_US
```

Default behavior remains unchanged because
`OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT` defaults off.

When enabled, the first direct data write for each chunk:

```text
selected_timeout_us = min(max_timeout_us, (chunk_time_ns - hw_now_ns)/1000 - guard_us)
```

If the guarded lead is already exhausted, or if the direct write times out
under deadline control, the code does not queue that chunk into timeout-carry.
It records the deadline-write counters and returns, so the strict CP1705 gate
can stop the run instead of allowing stale timed data to accumulate.

New summary/readback proof fields include:

```text

deadline_write_max_selected_timeout_us
```

## Conclusion

CP1706 is a no-RF/source build checkpoint, not a SIB1/PRACH datapoint.

It installs a changed real-time TX/backpressure policy for the next gate:
deadline-aware direct data writes should wait longer only while there is safe
RF lead, and should fail fast rather than queuing stale timed chunks once the
deadline path is exhausted.

Next experiment should be a [host-redacted]-only no-UE pre-UE TX gate with:

```text
OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT=1
OCUDU_SOAPY_TX_DEADLINE_WRITE_GUARD_US=[date-redacted]
OCUDU_SOAPY_TX_DEADLINE_WRITE_MAX_TIMEOUT_US=50000
```

and the CP1705 strict gate before any UE arm/start. Do not start a UE/bladeRF
checkpoint until bladeRF visibility on [host-redacted] is restored or explained.
