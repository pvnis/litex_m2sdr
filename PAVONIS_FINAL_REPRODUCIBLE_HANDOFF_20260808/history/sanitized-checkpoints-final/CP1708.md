# CHECKPOINT 1708 - No-RF hardware preflight and deadline gate hardening

## Goal

Respond to the current lab uncertainty without running RF: the cabled path has
changed and nucs are being handled, so future OTA/RF checkpoints must first
prove the software-visible hardware state. Also harden the next CP1706
deadline-write gate so it checks the new `deadline_write_*` counters instead
of relying only on the CP1705 carry fields.

No RF, OTA, TX, UE start, or cleanup command was run for CP1708.


It still fails on the CP1705 carry/late criteria: nonzero stream deficit,
carry abandonment/overflow, deadline lag/would-drop/drop, LiteX worker/release
late/error fields, and release-late trace lines.

## Conclusion

CP1708 is a no-RF safety/tooling checkpoint, not a SIB1/PRACH datapoint.

The next CP1706 deadline-write experiment should remain blocked until the
physical path uncertainty is cleared. When RF is allowed again, first rerun the
read-only hardware preflight, then run the [host-redacted]-only no-UE pre-UE TX gate with:

```text
OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT=1
OCUDU_SOAPY_TX_DEADLINE_WRITE_GUARD_US=[date-redacted]
OCUDU_SOAPY_TX_DEADLINE_WRITE_MAX_TIMEOUT_US=50000
```

and gate before any UE arm/start with:

```text
cp1708_strict_tx_deadline_gate.py \
  --require-carry-fields \
  --require-deadline-write-fields \
  --require-latest-pending-zero \
  --max-any-pending-samples 0
```

The CP1708 preflight confirms the bladeRF is currently USB-visible, but it does
not verify that the stolen/replaced wires reproduce the intended RF path.
