# CP1715 RF deadline-write pre-UE gate fail

Date: [date-redacted] Europe/Zurich

## Purpose

After CP1714 passed the RF hardware-path smoke, CP1715 ran the next ladder
gate: the CP1712-hardened CP1709 no-UE pre-UE TX gate for the CP1706
deadline-write policy.

This checkpoint intentionally starts gNB TX but does not start UE. The gate is
valid only if readback passes and the strict pre-UE carry/deadline check passes
before any UE arm/start.

## Interpretation

CP1715 stops the ladder before UE. The physical path is no longer the immediate
blocker for this rung; CP1714 already passed the path smoke, and CP1715 passed
hardware preflight/start/readback.

The blocker is the CP1706 deadline-write policy shape. With deadline-write
enabled, the data path writes only about `277074` samples, then repeatedly
breaks/abandons timed data instead of sustaining the all-timed stream. The
strict gate correctly rejects this before any UE/SIB/PRACH run can become a
misleading datapoint.

Do not rerun CP1715 unchanged and do not start UE on this TX shape. Next work
should stay no-RF and source/log-audit why the deadline-write branch abandons
nearly the full stream immediately despite clean LiteX worker/release late
counters.
