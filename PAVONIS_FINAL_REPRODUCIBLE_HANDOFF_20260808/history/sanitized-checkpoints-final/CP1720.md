# CHECKPOINT 1720 - OCUDU Deadline-Write Carry-On-Timeout Build

Date: [date-redacted] Europe/Zurich

## Purpose

Close the CP1716 source finding without another RF run: CP1706's
deadline-aware direct write path treated a deadline-controlled
`SOAPY_SDR_TIMEOUT` as final and abandoned the rest of the logical buffer
before timeout-carry could preserve ordering. CP1720 adds a default-off
lead-preserving mode where a deadline-controlled direct write can use a short
poll and, on ordinary timeout, enter the existing ordered timeout-carry queue.

This is a no-RF source/build checkpoint. It is not a SIB1, PRACH, UE, TRACK,
or bladeRF receive datapoint.

## Source Change

Touched files:

- `ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp`
- `ocudu/lib/radio/soapy/radio_soapy_tx_stream.h`

New env/readback knobs:

- `OCUDU_SOAPY_TX_DEADLINE_WRITE_CARRY_ON_TIMEOUT`
- `OCUDU_SOAPY_TX_DEADLINE_WRITE_DIRECT_POLL_US`

New proof/counter fields:

- `tx_deadline_write_carry_on_timeout_enabled`
- `tx_deadline_write_direct_poll_us`
- `deadline_write_carry_timeouts`
- Summary config fields `deadline_write_carry_on_timeout` and
  `deadline_write_direct_poll_us`

Behavior:

- Defaults remain unchanged: CP1706 abandon-on-deadline-timeout behavior stays
  active unless `OCUDU_SOAPY_TX_DEADLINE_WRITE_CARRY_ON_TIMEOUT=1` is set.
- When the new mode is enabled, `select_tx_data_write_timeout()` caps the
  first direct write timeout to `OCUDU_SOAPY_TX_DEADLINE_WRITE_DIRECT_POLL_US`
  if set, otherwise to `write_timeout_us`, and still bounds it by guarded RF
  lead.
- If guarded lead is already exhausted, the existing hard deadline break
  remains.
- If a deadline-controlled direct write returns `SOAPY_SDR_TIMEOUT` while
  timeout-carry is enabled, CP1720 records `deadline_write_carry_timeouts` and
  lets the existing timeout-carry queue preserve the timed chunk instead of
  marking `deadline_write_expired` and abandoning the logical tail.

## Verdict

CP1720 passes as a no-RF OCUDU source/build checkpoint. The next software
ladder rung should run the CP1709/CP1715-style no-UE pre-UE strict TX gate with
the new mode enabled, for example:

- `OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT=1`
- `OCUDU_SOAPY_TX_DEADLINE_WRITE_CARRY_ON_TIMEOUT=1`
- `OCUDU_SOAPY_TX_DEADLINE_WRITE_DIRECT_POLL_US=200` or a similarly short
  value
- existing timeout-carry/deadline observe mode on
- CP1705 strict gate before UE start

Required success criterion before any UE/RF interpretation remains: zero
stream deficit, zero deadline-write abandonment, zero carry abandon/overflow,
zero lag/would-drop/drop, zero pending at the gate, and normal lower LiteX
late/underflow/acquire counters.
