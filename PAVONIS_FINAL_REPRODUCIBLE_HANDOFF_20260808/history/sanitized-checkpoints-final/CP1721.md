# CHECKPOINT 1721 - Deadline-Write Carry-On-Timeout Pre-UE TX Gate

Date: [date-redacted] Europe/Zurich

## Purpose

Run the CP1720 deadline-write carry-on-timeout mode through the [host-redacted]-only
pre-UE strict TX gate before allowing any UE/bladeRF work. The test keeps the
CP1658/CP1698 all-timed native-continuous shape and enables the new mode with
a short direct poll:

- `OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT=1`
- `OCUDU_SOAPY_TX_DEADLINE_WRITE_CARRY_ON_TIMEOUT=1`
- `OCUDU_SOAPY_TX_DEADLINE_WRITE_DIRECT_POLL_US=200`
- `OCUDU_SOAPY_TX_WRITE_TIMEOUT_US=1000`
- `M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`
- timeout-carry/deadline observe mode on
- destructive deadline drop off
- no UE start unless the strict pre-UE TX gate passes

This is a no-UE TX-gate checkpoint. It is not a SIB1, PRACH, Android, raw
scheduled-TRACK, or UE datapoint.

## Verdict

CP1721 fails the strict no-UE pre-UE TX gate and correctly blocks UE start.
Do not rerun CP1721 unchanged and do not start UE/bladeRF on this TX shape.

CP1720 fixed the narrow CP1715 failure where a deadline-controlled direct
write abandoned the logical tail before timeout-carry could run. It did not
fix the deeper all-timed/timed-descriptor pressure: once the timed chunk is
preserved into the ordered carry queue, the queue saturates and overflows
within the pre-UE window, producing a stream deficit and release-late traces.

The next ladder work should stay no-RF/source-level until there is a specific
change that reduces timed-descriptor/backpressure pressure or changes the TX
presentation while preserving CP1658-class timing. [interface-redacted] the CP1721 direct
poll or max-pending constants is not a valid next rung by itself.
