# CHECKPOINT 1735 - CP1733 no-RF PRACH timing join

Date: [date-redacted]

## Purpose

Analyze CP1733's saved real-UE PRACH artifacts without RF before changing any
delay knob or widening the PRACH detector. CP1733 is a valid datapoint because
the UE decoded SIB1/RACH config and emitted seven Msg1/PRACH bursts, while the
gNB PRACH detector still accepted nothing.

## Method

Added `cp1735_analyze_cp1733_prach_timing.py`. The script parses the gNB
`PAVONIS_PRACHDET_TRACE` rows, the predemod manifest, the seven UE
`generate_buffer`/`transmitted`/`RA_TIMING`/`PRACH-TX` events, and the seven
bladeRF TX metadata files. It joins each UE event to the nearest gNB detector
row with the expected `sfn = floor(tti_tx / 10) % 1024` and
`slot = tti_tx % 10`.

Generated artifacts:

- `cp1735_cp1733_prach_timing_analysis.json`
- `cp1735_cp1733_event_trace_join.tsv`

## Results

- Trace and manifest coverage is complete: `1530` detector rows and `1530`
  predemod manifest rows.
- UE events: `7/7` Msg1 attempts with TTIs
  `8494/8654/8814/8974/9134/9294/9454`.
- Every UE event maps to the expected detector row:
  trace indices `43..49`, SFN/slot
  `849/4, 865/4, 881/4, 897/4, 913/4, 929/4, 945/4`.
- Same-SFN/slot wrap is not ambiguous: each event has `24` same-SFN/slot rows
  over the run, but the next-nearest candidate is about `10.21 s` away.
- Wall-clock timing is the decisive new result:
  - UE `PRACH-TX` minus detector trace wall time:
    min/mean/median/max
    `26.575604 / 27.039525 / 27.022979 / 27.668886 ms`.
  - UE `PRACH-TX` minus predemod manifest wall time:
    min/mean/median/max
    `27.446936 / 27.920759 / 27.892129 / 28.540881 ms`.
- Detector metrics at the matched rows remain weak:
  - matched `p0_ratio` min/median/max: `0.230 / 0.310 / 0.498`
  - matched `p0_pass_thr = 0/7`
  - matched `p0_pass_delay = 7/7`
  - matched accepted rows: `0/7`
- The full trace has no accepted rows and no preamble-0 threshold pass:
  `accepted_rows=0`, `p0_pass_thr_rows=0`.
- Matched predemod-window energy does not stand out:
  - matched raw RMS min/median/max:
    `0.000166313 / 0.000169503 / 0.000190823`
  - full-manifest raw RMS median: `0.000186098`
- UE/bladeRF TX debug is internally consistent:
  - `7` bladeRF metadata rows, all `status=0`, `meta_status=0`
  - `cf32_rms=0.560..0.574`, `sc16_peak=[date-redacted]`
  - blade target time is about `-0.026 ms` from the UE `PRACH-TX tx_time`.

## Interpretation

CP1733 did not fail because the gNB never tested the matching SFN/slot
occasions. It did test the expected rows, and those rows are in the saved trace.

The matched rows are still floor-class and preamble-0 sub-threshold, but the
wall-clock join shows a larger issue: the UE's actual bladeRF PRACH write is
about `27 ms` after the gNB detector row and about `28 ms` after the saved
predemod-window manifest row. The saved CP1733 `1 ms` predemod files therefore
cannot contain the actual UE burst if the host wall clocks are comparable; this
is consistent with CP1700/CP1707's earlier warning that 1 ms predemod files
cannot measure residual offsets outside their window.

The leading hypothesis is now a PRACH window/timing-reference mismatch under
the current CP1658-style all-timed downlink headroom, not an in-window detector
threshold or delay-gate miss. The offset scale is close to the configured
`30 ms` TX headroom, with a residual of roughly `2-3 ms`, so the next changed
work should audit how the all-timed TX lead maps gNB scheduled DL time into UE
observed SFN/slot timing before running more RF. A future RF rung may test a
single measured PRACH collection delay or a wider detector window, but only
after this mapping is explicit and only with real Msg1 emission as the gate.

## Checkpoint status

CP1735 is a no-RF artifact-only checkpoint. It advances the frontier from
"CP1733 emitted Msg1 but detector saw nothing" to "CP1733 emitted Msg1 about
27 ms after the matching gNB PRACH detector/predemod windows."
