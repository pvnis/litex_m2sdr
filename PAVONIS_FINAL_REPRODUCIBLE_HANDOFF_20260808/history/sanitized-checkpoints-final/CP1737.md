# CHECKPOINT 1737 - No-RF TX-headroom to PRACH-window mapping audit

Date: [date-redacted]

## Purpose

Audit the source and saved CP1733 runtime evidence behind CP1735's timing
result before spending RF on a PRACH collection-delay run. CP1735 showed the
UE's seven real Msg1 bursts about `27 ms` after the matching gNB detector rows.
The question here is whether that offset is consistent with the configured
all-timed `30 ms` TX headroom, and whether the current PRACH worker applies any
matching uplink collection offset.

## Evidence

Runtime CP1733 readback proves the active TX shape:

- `env_M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`
- `tx_all_timed_chunks=1`
- `tx_reanchor_enabled=0`
- `configured_discontinuous_tx=0`, `discontinuous_tx=0`
- `tx_format=CS16`
- TX attenuation `5 dB`

Source audit:

- OCUDU lower PHY sets TX metadata timestamps as
  `result.metadata.ts = timestamp + tx_time_offset`
  in `ocudu/lib/phy/lower/lower_phy_baseband_processor.cpp:124`.
- OCUDU Soapy TX converts that metadata timestamp directly to Soapy nanoseconds
  via `samples_to_ns(tx_md.ts, srate_hz)` in
  `ocudu/lib/radio/soapy/radio_soapy_tx_stream.cpp:1849`.
- The LiteX Soapy TX worker reads `M2SDR_SOAPY_TX_TIME_OFFSET_NS` in
  `litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp:764`.
- For timed TX packets, the worker applies that offset by setting
  `release_timeNs = pkt->timeNs + tx_time_offset_ns` at
  `LiteXM2SDRStreaming.cpp:4121-4122`.
- The LiteX release summaries in CP1733 reflect that exact `+30 ms` shift:
  early rows show `post_time_min_ns=[subscriber-redacted]` while pre/source time is
  `time_min_ns=[subscriber-redacted]`; stop rows likewise preserve the `30,000,000 ns`
  pre/post delta.
- PRACH collection does not implicitly compensate for this TX release offset.
  With no delay env, `prach_processor_worker.cpp:160-163` starts collection at
  the nominal PRACH slot timestamp. Optional compensation exists only through
  `PAVONIS_PRACH_COLLECTION_DELAY_SAMPLES` or
  `PAVONIS_PRACH_COLLECTION_DELAY_SEQUENCE_SAMPLES`, parsed at
  `prach_processor_worker.cpp:466-490`.
- CP1733's saved predemod manifest has `collection_delay_samples=0` for its
  windows.

CP1735 timing conversion at `11.52 Msps`:

- Mean UE `PRACH-TX` minus detector trace wall:
  `27.039525 ms` = about `311495` samples.
- Median UE `PRACH-TX` minus detector trace wall:
  `27.022979 ms` = about `311305` samples.
- Mean UE `PRACH-TX` minus predemod manifest wall:
  `27.920759 ms` = about `321647` samples.
- Median UE `PRACH-TX` minus predemod manifest wall:
  `27.892129 ms` = about `321317` samples.
- Configured driver TX release offset:
  `30.000000 ms` = `345600` samples.

## Interpretation

The sign is now source-proven: `M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`
delays timed downlink RF release by `+30 ms` at the LiteX driver layer without
moving OCUDU's nominal uplink PRACH collection windows.

That explains the CP1735 class of failure. The UE synchronizes to downlink that
is actually emitted later than OCUDU's nominal timestamp, then emits Msg1 later
than the gNB's nominal PRACH detector window. CP1735's measured `~27-28 ms`
lag is close to, but not exactly equal to, the configured `30 ms`, leaving a
few milliseconds of UE implementation, logging, and processing offset.

For the existing delay knob, the detector-row delta (`~311k samples`) is useful
for trace alignment, but the predemod-manifest delta (`~321k samples`) is the
better first static collection-delay target because the delay knob moves the
collection window start, not the later detector trace log line. A single static
test value around `321600` samples is therefore the most specific next RF
hypothesis. The CP1735 per-event spread is about `316189..328791` samples
against the manifest wall, so a static value may only partly cover all seven
bursts; if it improves raw/p0 visibility but still misses some attempts, the
next change should be a wider/remapped PRACH collection window rather than a
new open-loop sweep.

## Checkpoint status

CP1737 is no-RF and changes the frontier from "timing mismatch observed" to
"timing mismatch source-mapped to the LiteX `+30 ms` timed-TX release offset,
with PRACH collection still nominal." The next RF rung should be a single
measured-delay PRACH collection run, gated on real UE Msg1 emission, not a
blind delay sweep.
