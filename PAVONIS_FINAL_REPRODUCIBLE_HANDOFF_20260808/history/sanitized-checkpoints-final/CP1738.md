# CHECKPOINT 1738 - Delay321600 real-UE PRACH collection attempt, void no-Msg1

Date: [date-redacted]

## Purpose

Run the first RF test of the CP1737 source-mapped PRACH collection-delay
hypothesis. CP1737 showed that the all-timed `30 ms` LiteX TX release offset
delays downlink RF without moving nominal gNB PRACH collection, and selected
`321600` samples as the first static collection-delay target from CP1735's
UE-minus-predemod-manifest timing.

## Method

Used the current CP1733 real-UE SIB1/RACH harness with the CP1658 cadence and
explicit delay env:

- `PAVONIS_PHYSICAL_PATH_CLEARED=1`

- `PRACH_COLLECTION_DELAY_SAMPLES=321600`
- `PRACH_PREDEMOD_SUMMARY_MAX=1700`

## Interpretation

CP1738 proves the new `PRACH_COLLECTION_DELAY_SAMPLES=321600` runner plumbing
and PRACH worker delay path are active, and it does not disturb gNB startup,
TX readback, or pre-UE TX health gates.

It does not test the delay hypothesis. The UE never decoded SIB1/RACH config
and never emitted Msg1, so there was no real UE burst for the shifted gNB
collection window to catch. Per the active gate, this is a void PRACH datapoint.
The three gNB accepted rows must be treated as false/noise accepts because the
UE side has zero `PRACH-TX` and no PRACH TX debug artifacts.

## Checkpoint status

CP1738 is a void RF retry for the measured `321600` sample collection-delay
hypothesis. Keep the CP1737 source-mapped delay target open. A future RF test
of this value is only valid if the UE reaches real RACH config and emits Msg1;
otherwise it remains a no-Msg1/SIB1 acquisition retry, not evidence for or
against the PRACH window mapping.
