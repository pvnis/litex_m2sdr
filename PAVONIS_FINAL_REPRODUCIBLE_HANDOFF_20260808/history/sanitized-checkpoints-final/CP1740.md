## Interpretation

CP1740 confirms CP1738's delay plumbing result and repeats the no-Msg1 failure
class. The run is clean enough mechanically to count as a retry, but it is
still void for the PRACH-delay hypothesis because the UE never decodes SIB1 or
real RACH config and never emits Msg1.

The repeated pattern matters: two consecutive `321600` delay RF attempts
now have active shifted PRACH collection, good PBCH/SFN, and no real Msg1. That
does not prove the `321600` collection delay wrong. It proves the current
all-timed `30 ms` real-UE ladder is intermittently or currently failing below
Msg1 at SIB1 acquisition, so more blind retries of the same RF shape have low
value unless they are explicitly treated as no-Msg1 retries.
