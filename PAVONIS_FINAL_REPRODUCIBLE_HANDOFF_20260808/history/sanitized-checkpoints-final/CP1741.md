## Interpretation

CP1741 does not find a TX-readback, TX-late, or gross TX-counter difference
that explains CP1738/CP1740 versus CP1733. The current evidence says the two
`321600` delay RF attempts are blocked below Msg1 because SI-PDCCH/SIB1 is not
being recovered: CP1733's SI correlation reached `0.714289` and decoded SIB1,
while CP1738/CP1740 top out at `0.345397` and `0.486799` with `n_dl_max=0`
throughout.

This keeps the CP1737 measured PRACH-delay target open, but it changes the
next gate. More identical `321600` RF retries are low-value unless explicitly
treated as void no-Msg1 retries. The next decisive RF step should first
re-establish whether the CP1733 no-delay SIB1/RACH-config path still works on
the current setup. If a no-delay CP1733-style baseline now passes SIB1/Msg1
again, then retry `321600` immediately after or inspect whether the shifted
PRACH collection path perturbs the UE/SIB1 window. If the no-delay baseline
also fails SIB1, the frontier has regressed below PRACH and should be debugged
as SIB1/SI-PDCCH acquisition rather than as PRACH window mapping.

## Checkpoint status

CP1741 is a no-RF audit checkpoint. It closes blind same-shape `321600` retries
