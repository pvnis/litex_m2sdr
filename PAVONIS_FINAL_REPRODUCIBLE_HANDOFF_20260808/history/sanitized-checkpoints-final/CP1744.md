# CHECKPOINT 1744 - No-RF write-timeout and SI-period TX join

Date: [date-redacted]

## Purpose

Stay no-RF and answer the requested pre-RF questions:

- what `write_timeout_us` CP1733, CP1738, CP1740, and CP1742 actually used
- whether a CP1700-style SI-era per-period TX join separates the CP1733 SIB1
  pass from the three no-SIB failures

## Method

No RF commands were run.

Added and ran:

`cp1744_no_rf_write_timeout_si_period_join.py`

The script parses each run's saved TX readback, UE stdout, PRACH predemod
manifest, and gNB `Soapy TX summary:` rows. It maps SI rows to cumulative TX
period summaries using the same PRACH-manifest time-base style as CP1700, then
reports per-period deltas for `timeouts`, `partial_ret`, `write_deficit`, and
`stream_deficit`.

## Write-timeout check

All four runs used `write_timeout_us=200` in both readback and TX summaries:

- CP1733: `200`
- CP1738: `200`
- CP1740: `200`
- CP1742: `200`

All four also match the intended baseline shape:

- `tx_all_timed_chunks=1`
- `tx_reanchor_enabled=0`
- `env_M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`
- retry/carry/deadline-write paths disabled
- `tx_format=CS16`

## SI outcome recap

- CP1733: one SI grant, one BCCH/SIB1 decode, `phy_set_config_ok=1`, seven
  PRACH config/Msg1 rows
- CP1738: `800` SI summaries, best/mean/median `max_corr`
  `0.345397/0.175421/0.160423`, no SIB1, no Msg1
- CP1740: `800` SI summaries, best/mean/median `max_corr`
  `0.486799/0.206523/0.175752`, no SIB1, no Msg1
- CP1742: `800` SI summaries, best/mean/median `max_corr`
  `0.458091/0.205325/0.180830`, no SIB1, no Msg1

## SI-era period join

The CP1733 passing SI grant row maps to a TX period with:

- period delta `timeouts=39`
- period delta `partial_ret=2`
- period delta `write_deficit=3.483 ms`
- period delta `stream_deficit=37.548 ms`

The highest-correlation fail-run SI summaries are same-class:

- CP1738 top rows: `timeouts=38..49`, `partial_ret=2`,
  `write_deficit=3.516..4.444 ms`
- CP1740 top rows: `timeouts=39..49`, `partial_ret=2`,
  `write_deficit=3.483..4.370 ms`
- CP1742 joined top rows: `timeouts=38..45`, `partial_ret=2..3`,
  `write_deficit=3.444..3.927 ms`

The fail-run SI-summary rows covering CP1733's slot class also stay same-class
when they can be mapped:

- CP1738 examples: `timeouts=38`, `partial_ret=2`, `write_deficit=3.468 ms`
- CP1740 examples: `timeouts=39`, `partial_ret=2`, `write_deficit=3.556 ms`
- CP1742 examples: `timeouts=39..49`, `partial_ret=2`,
  `write_deficit=3.556..4.444 ms`

No run shows a CP1700-style timeout-carry backlog near SI. Carry/deadline/retry
paths are disabled, and final carry pending is `0`.

Final stop class is also same-class:

- CP1733: `timeouts=132244`, `partial_ret=6775`, write deficit `11980.153 ms`
- CP1738: `timeouts=132239`, `partial_ret=6785`, write deficit `11988.753 ms`
- CP1740: `timeouts=132213`, `partial_ret=6775`, write deficit `11975.090 ms`
- CP1742: `timeouts=132081`, `partial_ret=6772`, write deficit `11974.694 ms`

## Interpretation

CP1744 does not find a clean no-RF pass/fail splitter in SI-era timeout or
partial-return deltas. The CP1733 pass and CP1738/CP1740/CP1742 failures all
look like the same marginal all-timed `200 us` TX write-timeout class around
SI.

That means `OCUDU_SOAPY_TX_WRITE_TIMEOUT_US=1000` is still a valid single
marginality test, but not a proven fix. The next RF checkpoint should run the
exact CP1733 shape with that value as the only deliberate TX change.
