Run the first RF checkpoint using the CP1749 default-off SIB1 DCI aggregation
override. The intended test was the exact CP1745/CP1733 no-delay real-UE
shape with `TX_WRITE_TIMEOUT_US=1000`, adding only:

```text
GNB_SIB1_DCI_AGGR_LEV=8
```

## Interpretation

CP1750 proves the CP1749 `n8` override is active and mechanically compatible
with gNB start/TX gates. It does not prove or disprove SIB1 aggregation
robustness because the UE failed before SFN sync and never entered the
SI-PDCCH summary/search window.

This is most likely a void acquisition retry rather than a meaningful `n8`
result: changing SIB1 DCI aggregation should not affect SSB/PBCH/SFN. If a
second `n8` run also fails before SFN, run a patched-binary default-`n4`
CP1745-style control to separate ordinary acquisition flakiness from a
post-CP1749 binary/env regression.
