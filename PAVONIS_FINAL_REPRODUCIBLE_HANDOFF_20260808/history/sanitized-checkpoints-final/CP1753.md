# Checkpoint 1753 - No-RF PowerControlOffsetSS Override Build

Date: [date-redacted]

## Goal

Stay no-RF after CP1751/CP1752 and add a targeted SI-PDCCH/SIB1
de-margining lever before spending another RF run. CP1751 showed that raising
SIB1 DCI aggregation to `n8` increased SI correlation but still produced zero
SI grants. CP1752 showed the patched-binary default `n4` control also failed
SIB1 with clean TX late counters. The next lever is power presentation, not
another aggregation-only retry.

## Change

Added default-off gNB env override:

```text
PAVONIS_GNB_POWER_CONTROL_OFFSET_SS_DB
```

Accepted values are `-3`, `0`, `3`, `+3`, `6`, and `+6`. Empty or unset keeps
the existing behavior.

Implementation:

- `ocudu/lib/scheduler/config/csi_helper.cpp`
  - Reads `PAVONIS_GNB_POWER_CONTROL_OFFSET_SS_DB`.
  - Validates against the spec-backed `powerControlOffsetSS` values
    `{-3, 0, 3, 6}`.
  - Logs `PAVONIS_GNB_POWER_CONTROL_OFFSET_SS_DB active value=...` when active.
  - Replaces the hard-coded `res.pwr_ctrl_offset_ss_db = 0` with the override,
    defaulting to `0`.
- `cp1660_run_gnb_b3_txatt5_nativecontinuous_alltimed_lead30ms_stage6_prachtrace_detached.sh`
  - Logs the env in config output, harness output, and `TX_READY.env`.
  - Exports it through the detached gNB runner.
- `cp1733_run_stage6_currentbinary_cp1658cadence_realue_sib1_rachconfig.sh`
  - Adds `GNB_POWER_CONTROL_OFFSET_SS_DB`.
  - Exports it remotely as `PAVONIS_GNB_POWER_CONTROL_OFFSET_SS_DB`.
  - Includes it in settings and manifest output.
  - Adds it to the [host-redacted] binary string preflight grep.

Why this lever is targeted:

- `pwr_ctrl_offset_ss_db` already flows through existing OCUDU code into common
  PDCCH and common PDSCH TX power fields via the NZP CSI-RS resource.
- The existing default remains `0 dB`; unset runs should preserve CP1752 shape.
- The first RF test should use `+6 dB` as a single new scheduler power change.

## Conclusion

itself. It installs a bounded, default-off `powerControlOffsetSS` override on
[host-redacted] and updates the CP1660/CP1733 runners so future artifacts prove whether
the env was present.

a SIB1/RACH/Msg1 supply test. Do not resume the parked `321600` PRACH-window
test unless this or another run restores real SIB1/RACH config and Msg1.
