# Checkpoint 1756 - PRACH Collection Extra Samples Diagnostic Build

Date: [date-redacted]

## Goal

Stay no-RF after CP1755 and prepare a safer diagnostic path before any more
delay-constant retries. CP1755 proved the static `321600` delay was active and
valid but missed real UE Msg1 by millisecond-scale residuals. This checkpoint
adds a default-off way to save a wider predemod window for offline/sample-domain
analysis, without changing the normal default behavior.

## Source Change

OCUDU PRACH worker now supports:

```text
PAVONIS_PRACH_COLLECTION_EXTRA_SAMPLES=<samples>
```

Behavior:

- default `0`, preserving prior behavior
- only applies to the current Stage 6 format-0, start-symbol-0,
  single-TD/single-FD PRACH case
- extends the collected predemod window after the selected collection start
- caps the extension at the existing `prach_constants::MAX_WINDOW_LENGTH`
  worker buffer, which is `5 ms`
- records both `collection_nominal_window_length` and
  `collection_extra_samples` in `pavonis_prach_predemod_manifest.tsv`
- does not by itself make the detector search inside the wider capture; the
  live demodulator still starts from the selected collection origin

The CP1660 detached gNB helper and CP1733 real-UE wrapper now propagate and log
`PRACH_COLLECTION_EXTRA_SAMPLES`, so a future RF run can collect a wider
sample-domain window while keeping the old live detector path visible.

## Conclusion

CP1756 is a no-RF diagnostic-build checkpoint. It does not change the active
Stage 6 RF result and it is not a SIB1/Msg1/PRACH detector datapoint.

The next RF work should keep `GNB_POWER_CONTROL_OFFSET_SS_DB=6` as a fixture
for real-UE Msg1 supply, and should not retry another blind
`PRACH_COLLECTION_DELAY_SAMPLES` constant. Per the current frontier, the next
run should measure PRACH burst placement in sample/hardware time, ideally using
a same-device M2SDR RX append spanning the PRACH epoch and joining burst
positions against predemod-window sample starts. If sample-domain offsets are
stable, use that measured value; if they vary, move to a source-level timing
reference fix rather than [interface-redacted] constants.
