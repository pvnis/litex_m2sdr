## Goal

Prepare the existing CP1733/CP1660 real-UE Stage 6 harness for the next
PRACH timing rung without spending RF. Per the current gate, keep
`GNB_POWER_CONTROL_OFFSET_SS_DB=6` as the real-UE fixture and do not run
another blind `PRACH_COLLECTION_DELAY_SAMPLES` retry. The next RF run needs a
same-device M2SDR RX append spanning the PRACH epoch and a sample-time anchor

## Conclusion

CP1757 is a no-RF harness checkpoint. It does not produce a PRACH detector
datapoint. It makes the next requested rung runnable: one real-UE Msg1 attempt
with `GNB_POWER_CONTROL_OFFSET_SS_DB=6`, same-device M2SDR RX append enabled,
and append metadata in the same M2SDR/gNB sample timestamp domain as the
predemod manifest.

Next RF should enable the append, keep `GNB_POWER_CONTROL_OFFSET_SS_DB=6`, and
avoid another blind delay-constant retry. A no-Msg1 run remains void. If the
append/sample-domain burst offsets are stable, set
`PRACH_COLLECTION_DELAY_SAMPLES` from the measured offset; if they vary, move
to the source-level timing-reference fix.
