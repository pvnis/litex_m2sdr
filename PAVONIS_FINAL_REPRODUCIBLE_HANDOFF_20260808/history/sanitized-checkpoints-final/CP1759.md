# Checkpoint 1759 - RX Append Summary Limit Fix

Date: [date-redacted]

## Goal

Fix the CP1758 harness issue before retrying the real-UE same-device RX append
measurement. CP1758 requested `230400000` append samples but captured only
`102000000` samples because the append writer is gated by
`PAVONIS_SOAPY_RX_SUMMARY_MAX`, which remained at the default `200000` receive
rows.

## Changes

Updated only harness scripts:

- `cp1660_run_gnb_b3_txatt5_nativecontinuous_alltimed_lead30ms_stage6_prachtrace_detached.sh`
  - when `PAVONIS_SOAPY_RX_APPEND_ENABLE=1`, exports
    `PAVONIS_SOAPY_RX_SUMMARY_MAX=${PAVONIS_SOAPY_RX_SUMMARY_MAX:-600000}`
  - logs the active RX summary cap
- `cp1733_run_stage6_currentbinary_cp1658cadence_realue_sib1_rachconfig.sh`
  - adds wrapper variable `PAVONIS_SOAPY_RX_SUMMARY_MAX`, default `600000`
  - logs it in settings
  - exports it to the remote [host-redacted] start command
  - records it in the checkpoint manifest

With the usual `510` sample RX buffers seen in CP1758, `600000` rows allow up
to `306000000` samples, so the requested `230400000` append-sample cap should
now be the active limiter.
