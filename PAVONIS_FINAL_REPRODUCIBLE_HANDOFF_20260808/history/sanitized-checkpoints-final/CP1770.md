Attempt 1 is a weak first-defer outlier: its best correlation is only
`0.356927` and the best CFO is `-8000 Hz`. Do not average it into the delay
constant unless a later run validates the same first-attempt class.

The high-correlation class is attempts 2-7:

- Start-offset range: `347133..357938` samples.
- Span: `10805` samples, or about `0.938 ms` at `11.52 Msps`.
- Midpoint: `352535.5` samples.
- Median: `347719` samples.
- Mean: `350825.666667` samples.

The range is bimodal: attempts 2-5 cluster around `347.1k..348.1k` samples,
while attempts 6-7 cluster around `357.1k..357.9k` samples. This is still too
wide for a narrow 1 ms collection window without extra coverage, but it gives a
specific combined-fix point: use a delay in the `352.5k` sample class and
widen the collection window by about `12k` samples to cover roughly `+/-6k`
around that midpoint.

## Conclusion

CP1770 proves the fixed-defer measurement path is working and captures all
seven real UE PRACH attempts in M2SDR sample time. The gNB still fails because
the PRACH collection window is not aligned to the real RF burst, not because
the UE failed to transmit or because the same-device RX path cannot see the
burst.

Next run the combined fix directly: keep `GNB_POWER_CONTROL_OFFSET_SS_DB=6`,
use the measured high-correlation midpoint class for
`PRACH_COLLECTION_DELAY_SAMPLES` (`~352536`), add approximately `12k` samples
of extra collection coverage for the observed `~0.94 ms` spread, and judge the
run only on whether the gNB detector accepts real p0 Msg1. Keep no-SIB/no-Msg1
runs void.
