# CHECKPOINT 1771 - No-RF PRACH Offset Versus TX Summary Join

Date: [date-redacted]

## Goal

Check, without new RF, whether measured same-device PRACH sample offsets
correlate with in-run all-timed TX timeout/partial-return/deficit deltas. The
purpose is to test the theory that the observed `~0.85-0.94 ms` burst-offset
jitter is a downstream symptom of sample-loss-like TX cadence movement rather
than UE behavior.

## Method

Extended `cp1771_analyze_pracheoffset_txsummary_join.py` to include CP1770 in
addition to CP1764 and CP1767, then reran it locally. The script joins each
analyzer burst row to the nearest periodic `Soapy TX summary` row by converting
`has_time_min/max_ns` to sample timestamps at `11.52 Msps` and comparing to the
predemod window start timestamp.

The script now marks `corr >= 0.9` bursts as the high-correlation subset so
CP1770 attempt 1, the weak first-defer outlier, is retained but does not drive
the main interpretation.

## Result

Joined bursts:

- Total joined: `12`.
- High-correlation joined: `11`.
- All-offset range: `347133..415028`, span `67895` samples. This is dominated
  by CP1770 attempt 1.
- High-correlation offset range: `347133..357938`, span `10805` samples.
- High-correlation median/mean: `349006` / `351118.363636` samples.

## Conclusion

CP1771 does not find a decisive no-RF correlation between per-burst sample
offsets and the available periodic TX timeout/deficit counters. This does not
prove the all-timed stream is free of cadence jumps, because the join is coarse
and cumulative, but it removes the simple "larger per-period TX deficit maps to
larger PRACH offset" explanation from the current evidence.

Proceed with the planned combined RF fix from CP1770: use the measured
high-correlation midpoint class for `PRACH_COLLECTION_DELAY_SAMPLES` and widen
with `PRACH_COLLECTION_EXTRA_SAMPLES`; judge the result only on real p0 Msg1
acceptance, with no-SIB/no-Msg1 runs void.
