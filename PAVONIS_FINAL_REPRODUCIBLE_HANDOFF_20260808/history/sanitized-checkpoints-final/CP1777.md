# CHECKPOINT 1777: No-RF RAR Window Offset Diagnostic Build

Date: [date-redacted]/11 Europe/Zurich

## Purpose

CP1776 proved that CP1775's accepted PRACH detections reached the scheduler, but
expired before RAR scheduling because the delayed-collection result was still
keyed to the nominal PRACH occasion. The four real preamble-0 accepts allocated
TC-RNTIs, then expired with examples like `prach_slot=705.4`, `slot_tx=709.0`,
and RAR window `[705.5..706.5)`.

This checkpoint stays no-RF and adds a default-off diagnostic to separate:

- the original PRACH occasion slot used for RA-RNTI/event identity; from
- the slot used to derive the scheduler RAR response window.

The goal is to make the next single RF run decisive: if an offset window lets the
gNB schedule RAR, CP1776's stale-window diagnosis is confirmed. If RAR schedules
but the UE does not consume it, the next fix should move the whole UL/RACH timing
reference rather than further [interface-redacted] PRACH collection constants.

## Source Change

Edited:

- `ocudu/lib/scheduler/common_scheduling/ra_scheduler.cpp`
- `ocudu/lib/scheduler/common_scheduling/ra_scheduler.h`

- `cp1660_run_gnb_b3_txatt5_nativecontinuous_alltimed_lead30ms_stage6_prachtrace_detached.sh`

New gNB env knob:

```text
PAVONIS_RACH_RAR_WINDOW_OFFSET_SLOTS
```

Properties:

- default unset/empty, equivalent to `0`, preserving normal behavior;
- accepted range `0..1000`;
- invalid values call `report_error(...)` and fall back to `0`;
- when nonzero, logs `PAVONIS_RACH_RAR_WINDOW_OFFSET_SLOTS active value=...`;
- keeps RA-RNTI derivation and scheduler event logging tied to `msg.slot_rx`;
- adds `pending_rar_t::rar_window_ref_slot`;
- computes `rar_window` from `rar_window_ref_slot = msg.slot_rx + offset`;
- expired-RAR warnings include `rar_window_ref_slot` only when the diagnostic is active.

Wrapper plumbing:

- CP1733 top-level runner exposes `GNB_RACH_RAR_WINDOW_OFFSET_SLOTS`.
- CP1733 passes it to [host-redacted] as `PAVONIS_RACH_RAR_WINDOW_OFFSET_SLOTS`.
- CP1660 detached [host-redacted] starter exports it into the generated gNB harness.
- CP1660 writes it into the harness echo, `TX_READY.env`, verdict, and compact summary.
- CP1733 writes it into the local manifest.

## Next RF Diagnostic

Use one CP1775-shape RF run, not more delay/extra [interface-redacted]:

```text
GNB_POWER_CONTROL_OFFSET_SS_DB=6
UE_PRACH_DEFER_MS=1000
PRACH_COLLECTION_DELAY_SAMPLES=352536
PRACH_COLLECTION_EXTRA_SAMPLES=12000
PRACH_PREDEMOD_RAW_MAX=0
GNB_RACH_RAR_WINDOW_OFFSET_SLOTS=30
```

Rationale for `30`: CP1775 real p0 accepts were processed around `36..37`
slots after their nominal PRACH slot. The current RAR window begins one slot
after the PRACH occasion and lasts 10 slots. A `30`-slot reference shift moves a
typical expired window such as `[705.5..706.5)` to `[708.5..709.5)`, which
contains the observed `slot_tx=709.0` without altering the original RA-RNTI
slot used for event identity.

Interpretation:

- If RAR schedules, CP1776's stale-window diagnosis is confirmed.
- If RAR schedules but the UE misses/ignores it, this diagnostic is not the final
  fix; move the whole UL/RACH timing reference by the TX offset in source.
- If detections disappear, classify the run by SIB1/Msg1 supply first; do not
  [interface-redacted] the PRACH window constants from a void run.
