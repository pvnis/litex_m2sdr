## Goal

Stay no-RF after CP1778 and trace the accepted PRACH result path far enough to

## Source trace result

CP1776/CP1778 proved that accepted PRACH reaches MAC/scheduler, but with stale
nominal occasion timing unless the scheduler-only diagnostic offset is enabled.
The traced path is:

- `convert_prach_fapi_to_phy()` stamps `prach_buffer_context.slot` from the
  nominal UL_TTI PRACH slot.
- `prach_processor_worker` can delay sample collection with
  `PAVONIS_PRACH_COLLECTION_DELAY_SAMPLES`, but before this checkpoint it still
  notified upper PHY with the unchanged nominal `prach_context.slot`.
- `upper_phy_rx_symbol_handler_impl::handle_rx_prach_window()` routes by that
  context slot, and `uplink_processor_impl` copies the same slot into PRACH
  detector config and `ul_prach_results.context`.
- `phy_to_fapi_results_event_fastpath_translator::on_new_prach_results()` uses
  `result.context.slot` as the FAPI `RACH.indication` slot.
- MAC then sees that slot as `slot_rx`; CP1777's
  `PAVONIS_RACH_RAR_WINDOW_OFFSET_SLOTS=30` only shifted the RAR response-window
  reference, leaving PRACH attribution split.

Conclusion: keep CP1777 as diagnostic evidence, not as the final ladder fix.
The cleaner next rung is one coherent PRACH timing compensation that delays the
sample window and reports the corresponding shifted PRACH occasion upstream.

## Implementation

Added default-off `PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES` in
`prach_processor_worker` for the current format-0, start-symbol-0, single
TD/FD PRACH case.

When active, it:

- overrides `collection_delay_samples` with the compensation sample count;
- derives `samples_per_slot = sampling_rate_Hz / (1000 * slots_per_subframe)`;
- derives `timing_compensation_report_slot_offset =
  compensation_samples / samples_per_slot`;
- keeps the residual sample offset as
  `timing_compensation_residual_samples`;
- disables the old delay sequence for that request;
- notifies upper PHY with `prach_context.slot + report_slot_offset`.

The predemod manifest now appends:

`timing_compensation_samples`, `timing_compensation_samples_per_slot`,
`timing_compensation_report_slot_offset`,
`timing_compensation_residual_samples`,
`timing_compensation_collection_override`, `reported_sfn`, `reported_slot`.

For the CP1775/CP1778 measured midpoint `352536` samples at `11.52 Msps` and
15 kHz SCS, this computes `11520` samples/slot, `30` report slots, and `6936`
residual samples.

The CP1733 real-UE wrapper now forwards
`GNB_PRACH_TIMING_COMPENSATION_SAMPLES` to the gNB as
`PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES`, records it in settings/manifest,
and includes it in [host-redacted] binary-string preflight evidence.
