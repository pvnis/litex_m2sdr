## UE RAR/Msg3 join

The CP1781 UE summary confirms valid downlink and Msg1 supply:
`cell_select_ok=true`, `sfn_sync_ok=true`, one SIB1 decode, one final RACH
config, seven PRACH defer releases, seven `Random Access Transmission` rows,
and seven `PRACH-TX` rows.

Targeted UE stdout search for RAR/Msg3 evidence found only the seven PRACH
transmissions:

- `tti=8654`, `9774`, `654`, `1774`, `2894`, `4014`, `5134`
- all with `ra-rnti=0x39`
- no `Setting RAR Grant`
- no `PHY:   Set TA RAR`
- no `PROC RA NR: Setting UL grant and prepare Msg3`
- no `Msg3`, `Temporary-C-RNTI`, or contention-resolution marker

srsUE source confirms those strings are the expected path if RAR is decoded:
`proc_ra_nr.cc` unpacks an acknowledged RAR PDU, logs the RAR, sets the
temporary C-RNTI, calls `phy->set_rar_grant(...)`, applies TA, and prepares
Msg3. `worker_pool.cc` logs `Setting RAR Grant: ...` when the RAR UL grant is
installed. `ta_control.h` logs `PHY:   Set TA RAR: ...` when the TA command is
applied.

The gNB side still shows CP1781 advanced beyond stale RAR-window expiry:

- `0x4601`: PRACH accepted at slot `68.9`, RAR scheduled at `68.9`, Msg3 PUSCH
  scheduled at `69.5`, then five CRC KOs with SINR
  `-15.7/-17.9/-25.1/-21.7/-38.6 dB`.
- `0x4602`: PRACH accepted at slot `517.0`, RAR scheduled at `517.0`, Msg3
  PUSCH scheduled at `517.6`, then five CRC KOs with SINR
  `-24.9/-25.2/-13.6/-23.7/-33.1 dB`.
- Both HARQ processes exhaust after four retransmissions.

Conclusion: CP1781 does not prove the UE decoded RAR or transmitted Msg3. The
gNB Msg3 CRC KOs should be treated as scheduled receive attempts after the gNB's
own RAR decisions, not as confirmed UE Msg3 transmissions. The user's
"if yes, gNB is listening about 30 ms early" branch is therefore not confirmed
from CP1781 logs.

## Global timing audit

`time_alignment_calibration` is not a pure global uplink receive-offset knob.
The source describes it as RX-to-TX radio calibration in samples, and
`lower_phy_factory.cpp` converts it into:

```text
tx_time_offset = N_TA_offset - time_alignment_calibration
rx_to_tx_max_delay = 1 ms + tx_time_offset
```

That `tx_time_offset` is then used by the lower PHY downlink side:

- initial DL processing starts at `init_time + rx_to_tx_max_delay`
- downlink processing subtracts `tx_time_offset` when choosing generated frame
  content
- transmitted metadata is stamped as `timestamp + tx_time_offset`
- runtime command `tx_time_offset` controls the same downlink offset

Changing `time_alignment_calibration` would therefore move DL/TX timing and
lower-PHY RX-to-TX pacing. It is not the right "listen later but keep one
coherent UL timeline" knob.

The existing `PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES` is still per-PRACH:
it overrides only PRACH collection delay and offsets only the PRACH report slot
by `floor(compensation/samples_per_slot)`. That solves the PRACH-to-RAR stale
handoff for accepted Msg1, but it cannot automatically move Msg3/PUSCH, PUCCH,
or SRS windows.

A single global UL timestamp offset is feasible, but the best source-level
place is the lower-PHY uplink receive boundary rather than the current
`time_alignment_calibration` path. In `lower_phy_baseband_processor.cpp`,
`receiver.receive(...)` returns `rx_metadata.ts`, the code computes
`adjusted_rx_ts = apply_timestamp_sfn0_ref(rx_metadata.ts)`, and every uplink
channel then enters:

```text
uplink_processor.process(ul_buffer->get_reader(), adjusted_rx_ts)
```

`uplink_processor_impl.cpp` derives subframe, slot, symbol, PRACH context, and
PUxCH context from that timestamp. A default-off signed offset applied before
that call would shift PRACH and PUSCH/PUCCH/SRS together. Applying it inside the
Soapy RX stream would also relabel RX timestamps, but it would perturb
`last_rx_timestamp` and DL throttling because the lower-PHY baseband processor
uses raw received timestamps to pace downlink processing. A lower-PHY UL-only
offset avoids that side effect.

Likely sign for the first implementation: subtract about `352536` samples from
the UL timestamp presented to `uplink_processor.process`. The measured bursts
arrive physically late by that amount relative to nominal collection; labeling
those late samples as the nominal earlier slot is the global equivalent of the
current PRACH-specific delayed collection plus report-slot compensation.
