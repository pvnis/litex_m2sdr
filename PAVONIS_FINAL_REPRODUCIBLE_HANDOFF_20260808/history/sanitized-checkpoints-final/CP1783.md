# CP1783 no-RF lower-PHY global UL timestamp offset build

Date: [date-redacted] Europe/Zurich.

## Goal

Implement the CP1782 source conclusion as a default-off global uplink timing
knob: shift the timestamp presented to all lower-PHY uplink processors, rather
than adding more PRACH-only or scheduler-only compensation.

No RF was run.

## Change

Added `PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES` in
`ocudu/lib/phy/lower/lower_phy_baseband_processor.cpp`.

Behavior:

- default is `0`, so normal behavior is unchanged;
- signed sample offset is parsed once at lower-PHY baseband-processor
  construction;
- nonzero values print one startup line:
  `PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES active value=<n>`;
- the offset is applied to `rx_metadata.ts` before SFN0 normalization and before
  calling `uplink_processor.process(...)`;
- `last_rx_timestamp` remains based on raw `rx_metadata.ts + rx_buffer_samples`,
  so DL/TX throttling and `tx_time_offset` pacing are not intentionally moved;
- `PAVONIS_LOWER_PHY_TS_BRIDGE` output now includes
  `ul_rx_timestamp_offset_samples` and `ul_rx_ts`, so an RF/no-RF run can prove
  the relabeling was active.

This places PRACH and PUxCH on the same shifted uplink slot/symbol timeline,
because `uplink_processor_impl.cpp` derives subframe, slot, symbol, PRACH
context, and PUxCH context from the timestamp passed into
`uplink_processor.process(...)`.

## Expected sign

First RF hypothesis remains:

```text
PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES=-352536
```

at `11.52 Msps`, with the PRACH-specific
`PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES` disabled or reduced to avoid double
compensation. The sign follows CP1782: the physical UE uplink bursts are late by
about `352536` samples relative to nominal gNB collection, so labeling those
late samples as the earlier nominal UL time is the global equivalent of the
successful PRACH-specific delayed collection plus report-slot shift.
