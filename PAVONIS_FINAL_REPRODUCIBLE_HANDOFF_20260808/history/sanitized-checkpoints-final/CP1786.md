# Checkpoint 1786: No-RF SIB1 supply comparison for global-offset voids

Date: [date-redacted] Europe/Zurich.

## Goal

Before spending another RF run after CP1784/CP1785 voided before Msg1, compare
the saved SIB1-era summaries and TX counters against known SIB1-pass controls.
The purpose is to find a specific SIB1-supply splitter without [interface-redacted] PRACH
collection delay, PRACH extra width, or RAR-window logic.

## Findings

The CP1784/CP1785 failures are SIB1-control-decode failures, not missing RF
energy. Both runs reach PBCH/SFN and emit 800 SI-PDCCH summary rows, but all
rows have `n_dl_max=0` and no SI grant/SIB1/RACH/Msg1 follows.

```text
CP1784: si summaries 800, max_corr mean/median/max 0.252241/0.253086/0.462672, rows >=0.4: 13, rows >=0.5: 0, max_epre mean 33.504
CP1785: si summaries 800, max_corr mean/median/max 0.269208/0.272436/0.485816, rows >=0.4: 50, rows >=0.5: 0, max_epre mean 33.214
```

The known SIB1-pass controls reached the grant path instead:

```text
CP1733: SI grant line 136, BCCH/SIB1 decode 1, phy_set_config_ok 1, PRACH-TX 7
CP1754: SI grant line 213, BCCH/SIB1 decode 1, phy_set_config_ok 1, PRACH-TX 7
CP1755: SI grant line 174, BCCH/SIB1 decode 1, phy_set_config_ok 1, PRACH-TX 7
CP1781: SI grant 1, BCCH/SIB1 decode 1, phy_set_config_ok 1, PRACH-TX 7
```

The simple TX-timeout/backpressure theory does not split pass from fail.
CP1754, CP1755, CP1781, CP1784, and CP1785 all use `write_timeout_us=1000`,
all-timed chunks, `M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`, PCOSS `+6`, and
retry/carry/deadline policies disabled. CP1784/CP1785 stop counters are in the
same class as CP1754/CP1755:

```text
CP1754 stop: write_deficit 130216596, stream_deficit 1387938850, partial_ret 7687, timeouts 125674, carry pending 0, deadline timeouts 0
CP1755 stop: write_deficit 131487038, stream_deficit 1388580018, partial_ret 7676, timeouts 125878, carry pending 0, deadline timeouts 0
CP1784 stop: write_deficit 130698220, stream_deficit 1382220834, partial_ret 7679, timeouts 125005, carry pending 0, deadline timeouts 0
CP1785 stop: write_deficit 130824662, stream_deficit 1393065998, partial_ret 7687, timeouts 126410, carry pending 0, deadline timeouts 0
```

CP1781 is the closest positive control for wrapper surface. It used deferred
PRACH, `PRACH_PREDEMOD_RAW_MAX=0`, RX append disabled with the later wrapper
envs present, `write_timeout_us=1000`, PCOSS `+6`, and all-timed DL, and it
still decoded SIB1/RACH and emitted seven Msg1 attempts. Therefore PRACH defer,
raw predemod disabled, disabled RX-append env plumbing, and `write_timeout_us`
do not by themselves explain CP1784/CP1785.

Source placement of `PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES` is as
intended for CP1783: it shifts the timestamp passed to
`uplink_processor.process(...)`, while raw `last_rx_timestamp` still drives
DL/TX throttling. That source read does not prove harmlessness, though: the
only obvious CP1784/CP1785-specific active knob left after CP1781 is the
negative global lower-PHY UL timestamp offset.

## Interpretation

CP1784/CP1785 remain void for the RAR/Msg3 decision, but the repeated SIB1 loss
is no longer well explained by TX timeout, all-timed cadence, PCOSS, PRACH
defer, raw predemod suppression, or disabled RX append setup. The next RF run
should isolate the global-offset knob itself by using the CP1784 wrapper/source
shape with:

```text
PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES=0
PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES=0
PRACH_COLLECTION_DELAY_SAMPLES=0
PRACH_COLLECTION_EXTRA_SAMPLES=0
UE_PRACH_DEFER_MS=1000
PRACH_PREDEMOD_RAW_MAX=0
GNB_POWER_CONTROL_OFFSET_SS_DB=6
PAVONIS_SOAPY_RX_APPEND_ENABLE=0
```

If that zero-offset control restores SIB1/RACH/Msg1, the negative global UL
offset is perturbing pre-RA behavior and should be gated or delayed rather than
enabled from gNB start. If it also voids, the blocker is broader SIB1 supply
variability in the CP1784 wrapper/source environment, not the offset value
alone.
