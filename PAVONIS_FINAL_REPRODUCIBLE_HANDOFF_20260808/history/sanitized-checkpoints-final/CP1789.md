## Source diff

The current CP1783 source differs from the pre-CP1783 backup only in the
intended global-UL-offset plumbing:

```text
lower_phy_baseband_processor.cpp:
- adds <cerrno> and <climits>
- adds pavonis_read_env_i64()
- adds add_signed_timestamp_offset()
- adds ul_rx_timestamp_offset_samples initialized from PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES
- prints the offset only when nonzero
- computes ul_rx_ts = rx_metadata.ts + signed offset, clamped at zero
- passes apply_timestamp_sfn0_ref(ul_rx_ts) into uplink_processor.process(...)
- leaves last_rx_timestamp based on raw rx_metadata.ts + rx_buffer_samples
- extends PAVONIS_LOWER_PHY_TS_BRIDGE columns to include the offset and ul_rx_ts

lower_phy_baseband_processor.h:
- adds int64_t ul_rx_timestamp_offset_samples = 0
```

With `PAVONIS_LOWER_PHY_UL_RX_TIMESTAMP_OFFSET_SAMPLES=0`, this should be near
functionally equivalent for normal operation. CP1787 and CP1788 nevertheless
show the current SIB1 supply remains broken after CP1783 deployment, so the
source/binary state is still a reasonable software-control branch to test.

## Interpretation

CP1789 does not prove that the CP1783 patch causes SIB1 loss. It proves the
current [host-redacted] binary/source state is post-CP1783 and that exact pre-CP1783
backups are available. Because CP1788 moved the blocker outside the global
offset value itself, the next clean control is to restore the pre-CP1783
lower-PHY source on [host-redacted], rebuild `gnb`, and rerun the CP1781 positive-control
shape. If SIB1 returns, the CP1783 lower-PHY build/source state is implicated.
If it still voids, current SIB1 regression is outside that source change and
the next rung should be a raw scheduled-TRACK/SIB1 downlink gate or hardware/RF
receive-state check.
