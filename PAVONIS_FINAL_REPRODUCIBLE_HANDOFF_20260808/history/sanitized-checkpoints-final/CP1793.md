# Checkpoint 1793 - Safe Global UL Offset Build

Date: [date-redacted] Europe/Zurich

## Purpose

Reintroduce the global lower-PHY UL timestamp offset on top of the restored
CP1791-good baseline, but make the default-off path closer to pre-CP1783:

- the header/class layout is restored to the pre-CP1783 hash;
- when the parsed offset is zero, the UL timestamp uses the original
  `apply_timestamp_sfn0_ref(rx_metadata.ts)` computation;
- the old timestamp-bridge TSV format is preserved when the offset is zero;
- the expanded offset bridge columns appear only when the offset is nonzero.

No RF was transmitted.

## Interpretation

CP1793 is a no-RF build/deploy pass. It restores the lower-PHY header to the
pre-CP1783 hash while adding a safer cpp-only global-offset implementation.

This does not yet prove the new binary preserves CP1791 RF behavior. The next
RF checkpoint should run the CP1781/CP1791 positive-control shape with the
global offset unset or zero. If SIB1/RACH/Msg1/RAR still pass, then run the
actual global-offset plan with PRACH-specific compensation disabled. If the
zero-offset control regresses before SIB1/RAR again, the implementation still
perturbs the live path and should be reworked before spending RF on nonzero
offsets.
