## Result

CP1807 did not become an RF datapoint. The generated YAML put
`ra_resp_window: 40` under the wrong block in the first helper version, and
OCUDU failed before the gNB started transmitting.

Observed summary:

- First failed stage: `Stage 5/UE acquisition or cell selection`
- `tx_readback`: absent
- `ue_stdout`: absent
- `UE_STARTED`: false / absent
- PRACH trace: absent (`line_count=0`, `accepted_rows=0`)
- gNB summary counts: no Soapy TX summaries, no PRACH/RAR lines

The gNB log failed at startup with YAML parsing rather than RF behavior:

```text
Error parsing YAML configuration file: yaml-cpp: error at line 42, column 3: end of map not found
```

## Fix Applied After The Run

The gNB helper's YAML insertion logic was corrected so the private `prach:`
block ends when the next non-indented key is reached. A config-only check after
the fix generated the intended shape:

```text
37:  prach:
38:    prach_config_index: 1
40:    ra_resp_window: 40
44:  broadcast_enabled: true
```

