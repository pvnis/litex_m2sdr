# CP1813 - CP1808 vs CP1812 SI-Collapse No-RF Compare

Date: [date-redacted] Europe/Zurich

## Goal

Compare the saved CP1808 pass and CP1812 void artifacts without RF before
spending another run. CP1808 reached SIB1/RACH/Msg1 and one CRC-positive
RA-PDSCH; CP1812 used the same `ra_resp_window=40` trace-on shape after the
CP1811 deeper RAR handoff trace build, but voided before SIB1/RACH/Msg1.

The question is whether CP1812's SI-control collapse has an obvious
config/wrapper/TX-counter splitter, or whether the next action should be a
same-shape trace-on retry to get a valid handoff datapoint.

## Conclusion

CP1813 finds no no-RF config, wrapper, generated-YAML, TX-readback, or TX-stop
counter difference that explains why CP1808 decoded SIB1 and CP1812 collapsed
at SI control. CP1812 is best treated as a void retry caused by current
SI-control variability or by a subtler UE binary/trace side effect not exposed
by these counters.

The next RF action should be one same-shape CP1808/CP1811 trace-on retry, still
with no PRACH/RAR timing changes. If that retry also voids before SIB1/Msg1,
stop retrying the handoff trace blindly and run a trace-off or binary-side
effect control on the CP1811 UE build before spending more RAR-window RF.
