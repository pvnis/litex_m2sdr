## Conclusion

CP1814 repeats CP1812's trace-on no-SIB1/no-Msg1 class under clean mechanics.
It still does not classify the CP1808 CRC-positive RA-PDSCH-to-MAC-RAR failure,
because there is no Msg1, no RA window, and no decoded RA-RNTI TB.

Together with CP1813, this makes another same-shape trace-on retry the wrong
next move. The next checkpoint should run a trace-off or CP1811 UE-binary
side-effect control on the same RF shape, still with no PRACH/RAR timing
changes. If trace-off restores SIB1/Msg1 on the CP1811 binary, the new trace
path is perturbative despite not printing before SIB1; if trace-off also voids,
the current CP1811 UE binary/current RF state needs to be isolated before more
RAR-window work.
