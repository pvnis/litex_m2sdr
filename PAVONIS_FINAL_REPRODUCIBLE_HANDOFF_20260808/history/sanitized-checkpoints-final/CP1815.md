## Conclusion

CP1815 is decisive for the CP1812/CP1814 no-SIB1 pattern: disabling
`PAVONIS_SRSUE_RAR_TRACE` on the same CP1811 UE build restores SIB1/RACH config
and seven Msg1 transmissions. The trace-on path is therefore perturbative
despite producing zero RAR trace lines before SIB1 in CP1812/CP1814.

Do not spend more RF on the RAR handoff trace until the UE trace source path is
audited and made non-perturbative. The next checkpoint should be no-RF/source
level: inspect the CP1811 `mac_nr.cc` and `proc_ra_nr.cc` trace code, find why
`PAVONIS_SRSUE_RAR_TRACE=1` can disturb pre-SIB1/SI acquisition without
printing, and patch it so trace-enabled mode preserves the CP1815 SIB1/Msg1
baseline before rerunning the CP1808 RAR-handoff classifier.
