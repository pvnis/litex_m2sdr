# CP1816 - Low-Impact RAR Handoff Trace Build

Date: [date-redacted] Europe/Zurich

## Goal

Make the CP1811 UE RAR handoff trace less perturbative before another RF
retry. CP1812 and CP1814 both enabled the deeper trace and voided before
SIB1/Msg1 with zero RAR trace lines, while CP1815 disabled only
`PAVONIS_SRSUE_RAR_TRACE` on the same UE build and restored SIB1/RACH/Msg1.
This checkpoint is no-RF.

## Conclusion

CP1816 completes the no-RF trace mitigation and deployment. It does not prove
that trace-on RF is fixed. The next RF run should reuse the CP1808/CP1812 shape
with `PAVONIS_SRSUE_RAR_TRACE=1` and `PAVONIS_SRSUE_RAR_WINDOW_TRACE=0`
or unset, so only the decisive RA-PDSCH/handoff events are active.

Judge the next run first on whether SIB1/RACH/Msg1 supply survives. If it does,
judge the RAR handoff on:

- `ra_pdsch_decode crc=1`;
- `tb_decoded` with RA-RNTI, `ack=1`, payload bytes, and `dispatch_rar=1`;
- `ra_response_entry`;
- unpack result and RAPID match/no-match;
- original UE markers `Setting RAR Grant`, `Set TA RAR`, Msg3 prep;
- gNB Msg3 CRC.

Do not re-enable `PAVONIS_SRSUE_RAR_WINDOW_TRACE` unless the next run reaches
RAR handoff but needs the high-volume RA-window opportunity summaries again.
