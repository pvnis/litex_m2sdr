# CP1817 - Low-Impact RAR Trace RF Retry Voided by Pre-UE TX Late Gate

Date: [date-redacted] Europe/Zurich

## Goal

Retry the CP1808/CP1812 `ra_resp_window=40` real-UE RAR handoff run after the
CP1816 low-impact UE trace rebuild:

- `PAVONIS_SRSUE_RAR_TRACE=1`
- `PAVONIS_SRSUE_RAR_TRACE_LIMIT=1200`
- `PAVONIS_SRSUE_RAR_WINDOW_TRACE=0` locally, and no window-trace forwarding
  to the UE helper
- all-timed/native-continuous gNB TX, PCOSS `+6`
- PRACH timing compensation `352536`, extra `12000`
- lower-PHY global offset `0`
- `prach.ra_resp_window=40`

## Result

CP1817 is void for the SIB1/RAR handoff question. The wrapper aborted before
starting the UE:

```text
overall_rc=1
gate_rc=0
late_gate_rc=34
ue_started=0
```

The initial gNB TX readback gate passed:

```text
configured_discontinuous_tx=0
discontinuous_tx=0
tx_all_timed_chunks=1
tx_force_continuous_stream=0
tx_reanchor_enabled=0
channel0_gain_db=5.000000000
write_timeout_us=1000
```

The pre-UE TX late-health gate then found one LiteX release-late trace and
returned `34`, so the harness skipped UE startup:

```text
RELEASE_LATE_TRACE_LINE_COUNT=1
SOAPY_TX_TIMEOUT_COUNT=0
```

The late trace was:

```text
LiteX TX release late: trace_idx=0 packet_seq=376761 numElems=1022 mtu=1022 short_chunk=0 post_eob=0 pre_has_time=1 post_has_time=1 dedup_suppressed=0 timeNs=[subscriber-redacted] nowNs=[subscriber-redacted] slipNs=372795745226 release_late_count=1 release_post_has_time=116736 reader_enabled=1 samplerate=11520000
```

The summary JSON therefore has no UE artifact:

```text
ue_stdout=null
cell_select_ok=false
sfn_sync_ok=false
sib1_bcch_decoded_count=0
prach_tx_count=0
ra_pdsch_grant_count=0
msg3_prep_count=0
```

This is not a trace-on SIB1 failure and not a RAR handoff datapoint; the UE was
never launched.

## Comparison

The same pre-UE gate passed in the immediately relevant prior runs:

```text
CP1812 late_gate_rc=0, RELEASE_LATE_TRACE_LINE_COUNT=0
CP1815 late_gate_rc=0, RELEASE_LATE_TRACE_LINE_COUNT=0
```

CP1817 is therefore a pre-UE TX-health void, not evidence that the CP1816
low-impact trace did or did not fix the CP1812/CP1814 no-SIB1 trace-on split.

## Conclusion

CP1817 should be treated as a void retry blocked by the pre-UE TX late gate.
It did not exercise the UE, SIB1, Msg1, RA-PDSCH, MAC RAR dispatch, or Msg3.

A same-shape retry is justified before changing trace code or RAR timing,
because the decisive low-impact trace test did not run.
