# CP1818 - Low-Impact RAR Trace-On Retry Still Voids Before SIB1

Date: [date-redacted] Europe/Zurich

## Goal

Repeat the CP1817 low-impact-trace RF validation after CP1817 voided before UE
startup. This run keeps the CP1808/CP1812 `ra_resp_window=40` shape and changes
no timing/RAR knobs:

- `PAVONIS_SRSUE_RAR_TRACE=1`
- `PAVONIS_SRSUE_RAR_TRACE_LIMIT=1200`
- `PAVONIS_SRSUE_RAR_WINDOW_TRACE=0` locally, with no window-trace forwarding
  to the UE helper
- all-timed/native-continuous gNB TX, PCOSS `+6`
- PRACH timing compensation `352536`, extra `12000`
- lower-PHY global offset `0`

## Result

CP1818 is a valid RF run, but it still voids before RAR handoff. Mechanics and
TX gates pass:

```text
overall_rc=0
gate_rc=0
late_gate_rc=0
ue_started=1
litex_release_late_lines=0
soapy_tx_timeout_lines=0
```

The UE starts and reaches cell select/SFN sync:

```text
cell_search trial 4: pci=1 snr=8.757 dB pbch_crc=1
cell_select_ok=true
sfn_sync_ok=true
```

But SIB1/RACH/Msg1 supply does not survive:

```text
sib1_bcch_decoded_count=0
sib1_si_pdcch_count=0
sib1_si_pdsch_grant_count=0
sib1_phy_set_config_ok_count=0
prach_tx_count=0
random_access_transmission_count=0
```

SI summary stats:

```text

n_dl_positive=0
max_corr_max=0.213020
max_corr_mean=0.1559671825
max_corr_median=0.1528815
```

The RAR trace path did not emit any lines before the failure:

```text
PAVONIS_SRSUE_RAR_TRACE count=0
event=ra_pdsch count=0
event=tb_decoded count=0
event=ra_response count=0
PAVONIS_SRSUE_RAR_WINDOW_TRACE count=0
```

The gNB PRACH trace has no real UE supply. It records `1531` timestamped rows,
`2` accepted non-p0 false rows, and zero detected-nonempty rows:

```text
sfn=788 slot=4 best_preamble=62 best_ratio=1.021 p0_ratio=0.227 p0_pass_thr=0
sfn=676 slot=4 best_preamble=24 best_ratio=1.190 p0_ratio=0.655 p0_pass_thr=0
```

Those accepted rows are false because the UE emitted no Msg1.

## Interpretation

CP1818 shows that the CP1816 low-impact trace patch did not, by itself, restore
SIB1/Msg1 under `PAVONIS_SRSUE_RAR_TRACE=1`. The run is still not a RAR handoff
datapoint because it never reaches SIB1/RACH/Msg1, RA-PDSCH, MAC RAR dispatch,
or Msg3.

Because the CP1816 binary changed source in `mac_nr.cc`, `proc_ra_nr.cc`, and
`cc_worker.cc`, the next control should disable only `PAVONIS_SRSUE_RAR_TRACE`
on this new binary. That separates a persistent trace-on environment effect
from current RF/SIB1 scatter or a CP1816 binary regression.
