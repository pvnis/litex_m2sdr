Date: [date-redacted] Europe/Zurich

## Goal

Retry the CP1819 trace-off control after CP1819 voided at the pre-UE TX-late
gate. This run keeps the CP1818/CP1819 shape and disables only the RAR trace
environment on the CP1816 low-impact `srsue` binary:

- `PAVONIS_SRSUE_RAR_TRACE=0`
- `PAVONIS_SRSUE_RAR_TRACE_LIMIT=0`
- `PAVONIS_SRSUE_RAR_WINDOW_TRACE=0`
- all-timed/native-continuous gNB TX, PCOSS `+6`
- `ra_resp_window=40`
- PRACH timing compensation `352536`, extra `12000`
- lower-PHY global offset `0`

## Interpretation

CP1820 answers the immediate CP1818/CP1819 control more than CP1819 did: the UE
does start with `PAVONIS_SRSUE_RAR_TRACE=0` on the CP1816 binary, but trace-off
no longer restores SIB1/Msg1 supply in this run. Therefore the current blocker
is not yet the RAR handoff path and not simply the CP1816 trace-on environment.

Compared with CP1815, which restored SIB1/RACH/Msg1 with trace disabled on the
CP1811 binary, the live split is now either current SI/SIB1 RF scatter or a
CP1816 binary/source-state effect. Do not run more RAR handoff RF until a
no-RF CP1815-vs-CP1820 comparison checks generated config, UE binary/source
hashes, wrapper env, SIB1-era TX counters, and SI summary/correlation behavior.
