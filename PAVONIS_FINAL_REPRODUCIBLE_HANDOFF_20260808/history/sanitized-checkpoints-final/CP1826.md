## Conclusion

CP1826 is a valid exact-global-offset datapoint, not a no-SIB1 void. The exact
CP1783/CP1809 shape now reaches SIB1, RACH config, seven UE Msg1 transmissions,
and one real detector p0 accept with the global lower-PHY offset active.

It still fails the requested RAR/Msg3 gate: the UE never observes RA PDCCH/PDSCH,
RAR grant, TA RAR, or Msg3 preparation. The binary-safe gNB log shows why:
detector results do reach the scheduler, but both pending RAR windows expire
before allocation. The real p0 event is attributed to `prach_slot=577.4` and is
processed at `slot_tx=580.8`, missing the default window `[577.5..578.5)`.
The exact global lower-PHY timestamp offset therefore narrows the old
30 ms-class stale-window problem but does not make this default-window shape
sufficient for UE-side RAR receipt.

Do not [interface-redacted] PRACH delay/extra width from CP1826. The next useful step is no-RF:
compare CP1826's residual `prach_slot -> slot_tx` lateness with CP1776,
CP1792, and CP1808, then decide whether the principled next RF test is a
global-offset plus longer RA response window/config-level window fix, or a
source-level timing/window reference fix. This is not a detector-to-MAC drop.
