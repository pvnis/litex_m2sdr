# CHECKPOINT 1827 - CP1826 Residual RAR Window Timing Audit

Date: [date-redacted] Europe/Zurich

Type: no-RF artifact/source audit.

## Goal

Compare CP1826's exact global lower-PHY UL timestamp-offset result against the
known stale-window and RAR-scheduling baselines before spending another RF run.

The specific question was whether CP1826 rejected the exact CP1783 plan because
of a small residual RAR-window miss, or whether it stayed in the same stale
occasion class as CP1776/CP1775.

## Inputs

- CP1776 no-RF accepted-PRACH-to-RAR trace report.
- CP1781 coherent timing-compensation RF report.
- CP1794 safe zero-global-offset positive-control report and compact-memory
  binary-safe summary.
- CP1808/CP1810 `ra_resp_window=40` RF/no-RF reports.
- CP1826 exact-global retry report and binary-safe gNB log summary.

No new RF was run.

## Slot Delta Method

OCUDU log slots are printed as `SFN.slot`, not decimal milliseconds. Slot delta
is therefore:

```text
delta_slots = (slot_tx_sfn - prach_sfn) * 10 + (slot_tx_index - prach_slot_index)
```

For example, `577.4 -> 580.8` is `34` slots, not `3.4`.

## CP1826 Interpretation

CP1826 was not a detector-to-MAC drop. The binary-safe
`tmp/gnb_m2sdr_band3_ota.log` shows two non-empty `PRACH:` rows and two
`Processed slot events pci=1: prach` scheduler events. Both reached the
scheduler after the default RAR window had expired:

```text
[625.4] PRACH: detected_preambles=[{idx=18 ... detection_metric=1.0}]
[628.8] ra-rnti=0x39: Could not transmit RAR within the window=[625.5..626.5), prach_slot=625.4, slot_tx=628.8
[628.8] Processed slot events pci=1: prach(ra-rnti=0x39 preamble=18 tc-rnti=0x4601)

[577.4] PRACH: detected_preambles=[{idx=0 ... detection_metric=1.3}]
[580.8] ra-rnti=0x39: Could not transmit RAR within the window=[577.5..578.5), prach_slot=577.4, slot_tx=580.8
[580.8] Processed slot events pci=1: prach(ra-rnti=0x39 preamble=0 tc-rnti=0x4602)
```

The real p0 row at `577.4 -> 580.8` is 34 slots late. That puts CP1826 much
closer to CP1776's stale-window class (`36-37` slots late) than to CP1781,
CP1794, or CP1808 (`5-7` slots late and RAR scheduled).

## Consequences

The exact CP1783-style global lower-PHY offset does not reproduce the coherent
PRACH compensation semantics. It can now reach SIB1, Msg1, detector acceptance,
and scheduler handoff, but it still labels or delivers the accepted result late
enough that the default RAR window is stale.

A longer RA response window could cover this 34-slot residual in a diagnostic
run, and CP1808 already proves `ra_resp_window=40` can reach UE RA-PDSCH decode
under the coherent PRACH-compensation path. However, applying that to CP1826
would be a window workaround, not proof that the exact global offset fixed the
UL timebase coherently.

## Decision

Do not rerun the CP1826 exact-global shape unchanged, and do not resume
PRACH delay/extra/RAR-offset [interface-redacted] from CP1826.

The two principled next branches are:

1. Return to the CP1808/CP1810 ladder frontier: coherent PRACH compensation,
   `ra_resp_window=40`, and UE-side decoded RA-RNTI TB handoff tracing. That is
   the only tested path that reaches UE RA-PDSCH decode.
2. Rework the global UL compensation source path so it preserves CP1779's
   sample-domain delayed-collection plus forward report-slot semantics across
   all uplink channels, instead of subtracting `352536` samples from the
   lower-PHY RX timestamp while DL/TX timing remains raw.

If an RF diagnostic is still desired on the exact-global branch, the only
non-blind one is CP1826 shape plus an explicit extended RA response window
(`ra_resp_window=40`) to test whether the UE can see a delayed RAR. That result
must be labeled a window-workaround diagnostic, not a coherent global-timebase
success.
