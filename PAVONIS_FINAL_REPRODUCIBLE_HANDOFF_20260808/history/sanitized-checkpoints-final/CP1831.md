## Goal

After CP1830 moved the blocker above RAR and into Msg3/PUSCH CRC KO, add a
low-impact UE-side trace that proves the path from accepted RAR to actual
Msg3/PUSCH:

- `ra_response_accept -> set_rar_grant`
- resolved pending UL grant and `tti_tx`
- `msg3_prepare` / `msg3_get`
- UL HARQ action and payload availability
- PUSCH grant found, MAC action, and PUSCH encode result

This is no-RF instrumentation only. The trace reuses the CP1829 late-armed,
memory-buffered `PAVONIS_SRSUE_RAR_TRACE` helper, so it stays silent before
`phy_set_config_ok`.

## Conclusion

CP1831 does not run RF and does not change the RF conclusion from CP1830.
It prepares the next valid RF rung so the Msg3/PUSCH failure is observable
from the UE side without reading raw logs:

- If the UE reaches `pusch_encode rc=0` at `tti_tx=4697` / `57` for the same
  temp C-RNTIs that the gNB listens to at `469.7` / `5.7`, the next blocker is
  likely uplink RF/EVM/power/demod, not scheduling.
- If the trace stops earlier, the event boundary will identify whether Msg3 is
  lost at pending grant creation, MAC PDU generation, UL HARQ action, or PUSCH
  encode.

Next RF run should keep the CP1830 shape and enable the same late-armed RAR
trace. Judge it on the new Msg3/PUSCH counters plus gNB PUSCH CRC/SINR for
`0x4601` and `0x4603`.
