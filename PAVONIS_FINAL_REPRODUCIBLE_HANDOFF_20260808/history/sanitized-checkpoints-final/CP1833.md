## Offset Arithmetic

At `11.52 Msps`, one 15 kHz slot is `11520` samples. Therefore:

- `352536 = 30 * 11520 + 6936` samples.
- This is `30.602083` slots, not a decimal `SFN.slot` jump.
- A nominal PUSCH window at `SFN 693 slot 7` would be expected around
  `SFN 696 slot 7` plus `6936` samples, roughly late in that slot.
- The retx nominal window at `696.5` would be expected around `699.5` plus
  the same residual.

This corrects the earlier mental slip that treated `693.7 + 30.6` as a direct
decimal value near `724`. OCUDU `SFN.slot` is two fields, not a decimal slot
counter.

## Conclusion

CP1833 cannot confirm the expected `+352536` sample Msg3 arrival offset from
CP1832 because the only saved gNB UL symbol manifest stops before the accepted
Msg3 epoch. It does confirm the branch semantics, the UE-side Msg3 transmit
metadata, the gNB PUSCH CRC-KO windows, and the correct offset arithmetic.

The next RF checkpoint may still run the requested combined shape as a direct
experiment: global lower-PHY UL RX offset `-352536`, `ra_resp_window=40`,
PRACH-specific compensation/delay/extra off, PCOSS `+6`, and judge on a valid
Msg3 CRC. Interpret no-SIB1/no-Msg1 as void scatter. If the run reaches UE
RAR/Msg3 but gNB Msg3 CRC remains KO, the result argues against this global
offset shape semantically and should trigger the planned PUSCH-specific or
source-level timing fix path rather than more PRACH/RAR [interface-redacted].
