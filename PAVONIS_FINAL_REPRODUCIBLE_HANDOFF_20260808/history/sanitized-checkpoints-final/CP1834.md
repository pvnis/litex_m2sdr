## UE RAR/Msg3 Result

The UE did not decode or accept any RAR and did not transmit Msg3:

- `ra_pdcch_count=0`
- `ra_pdcch_dci_count=0`
- `ra_pdsch_grant_count=0`
- `ra_pdsch_decode_count=0`
- `tb_decoded_count=0`
- `ra_response_accept_count=0`
- `msg3_get_count=0`
- `pusch_encode_count=0`

The only late-armed RAR trace event was the arm event after
`phy_set_config_ok`. With the same window-trace setting, CP1832 still recorded
RA PDSCH decode, RAR acceptance, and Msg3/PUSCH encode, so these zero counters
are a real regression, not just disabled high-volume window logging.

There are no gNB `PUSCH: rnti=0x460...` decode lines in the binary-safe mirror.
The scheduler later discards UL HARQ TBs for `0x4601`, `0x4602`, `0x4603`, and
the false `0x4604` after max retransmissions, but there is no valid UE Msg3
branch to judge on CRC.

## Runtime Health

The wrapper's main summary still reports zero Soapy TX timeout and zero LiteX
release-late lines, but the binary-safe gNB mirror contains:

- `125772` `SoapySDR TX: writeStream timeout` / `Soapy TX timeout` lines
- `2510` `Real-time failure in lower PHY: Downlink data late` lines
- no `LiteX TX release late:` matches

This matches the CP1832 caveat class and remains on the watchlist. In CP1834 it
may directly matter because the run fails at UE RAR visibility, a downlink
control/data receive step.

## Conclusion

CP1834 is a valid RF datapoint, not no-SIB1/no-Msg1 scatter. It proves the
exact-global offset plus `ra_resp_window=40` shape can reach SIB1/RACH/Msg1,
accept real p0 rows, and generate RAR PDUs, but it regresses below CP1832 by
losing UE RA-PDCCH/RAR decode and therefore never reaches Msg3.

This does not satisfy the requested Msg3 CRC criterion. Treat the combined
global lower-PHY offset shape as semantically failed for this branch. The next
step should be the planned fallback on the current branch: keep the CP1830/1832
coherent PRACH-compensation path (`PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES=352536`,
extra `12000`, global lower-PHY offset `0`, `ra_resp_window=40`) and add a
PUSCH-specific or source-level UL collection shift for the measured
`~352536` sample delay, then judge on UE RAR/Msg3 plus gNB Msg3 CRC.
