# CHECKPOINT 1835 - Non-PRACH UL collection shift build

Date: [date-redacted]

## Purpose

Implement the coherent-branch fallback after CP1834 rejected the exact global
lower-PHY UL timestamp offset plus `ra_resp_window=40` shape. The requested
fallback is a generic non-PRACH uplink collection shift for PUSCH, PUCCH, and
SRS while preserving CP1779's PRACH delayed-collection/report-slot semantics.

This checkpoint is no-RF. It covers source changes, local build, [host-redacted] deploy,
remote build, and runner health-accounting fixes.

## Source Changes

Changed files:

- `ocudu/lib/phy/lower/processors/uplink/uplink_processor_impl.cpp`
- `ocudu/lib/phy/lower/processors/uplink/uplink_processor_impl.h`
- `ocudu/lib/phy/lower/processors/resource_request_pool.h`
- `pavonis_stage6_agent_artifacts_[date-redacted]T0918Z/prearmed_raw512_fast_[date-redacted]T0045Z/cp1807_run_stage6_raresp40_realue_rar_msg3.sh`

Implemented default-off `PAVONIS_NON_PRACH_UL_RX_TIMESTAMP_OFFSET_SAMPLES`.
The sign convention matches the rejected global knob: `-352536` makes samples
that arrive 352536 samples later appear to the non-PRACH lower path under the
nominal slot label.

The normal lower uplink path still drives PRACH and half/full-slot timing
notifications from the unshifted timestamp. When the non-PRACH offset is
active, the normal PUxCH demod path is skipped and a second shifted symbolizer
feeds the same PUxCH resource-grid path. That grid is the lower input shared by
upper PUSCH, PUCCH, and SRS processing, so this is the generic non-PRACH shift,
not a Msg3-only shim. RX CFO commands are fanned out to both the normal and
shifted symbolizers.

The lower resource request pool depth was increased from `16` to `128` entries.
The measured delay is about `30.6` slots; the old modulo-16 pool could overwrite
a nominal Msg3 request before the delayed samples were processed.

The CP1807/CP183x runner now records `PAVONIS_NON_PRACH_UL_RX_TIMESTAMP_OFFSET_SAMPLES`,
exports it to [host-redacted] through the remote env prefix, adds a pre-UE binary-safe
health-count step for `/tmp/gnb_m2sdr_band3_ota.log`, and updates summary JSON
to count Soapy TX timeouts and downlink-late lines from both `gnb.log` and the
binary-safe mirror. These counts are reported but not made a hard pre-UE abort,
so the next RF run can still be judged on UE RAR/Msg3 and gNB Msg3 CRC while
treating the timeout/downlink-late storm as a co-suspect.
