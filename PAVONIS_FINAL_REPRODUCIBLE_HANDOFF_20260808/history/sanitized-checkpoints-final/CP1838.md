# CHECKPOINT 1838 - No-RF audit of non-PRACH shift after CP1837

Date: [date-redacted]

## Purpose

Stay no-RF after CP1837. Check whether the CP1835 generic non-PRACH shift is
actually connected to the PUxCH/PUSCH decoder path, and compare CP1832 versus
CP1837 saved logs before adding another offset, PUSCH-specific collection
shift, or backpressure policy.

## Source Audit

Relevant files:

- `ocudu/lib/phy/lower/processors/uplink/uplink_processor_impl.cpp`
- `ocudu/lib/phy/lower/processors/uplink/puxch/puxch_processor_impl.cpp`
- `ocudu/lib/phy/lower/processors/resource_request_pool.h`

Findings:

- `lower_phy_uplink_processor_impl::process()` calls
  `process_non_prach_shifted(samples, timestamp + offset)` whenever
  `PAVONIS_NON_PRACH_UL_RX_TIMESTAMP_OFFSET_SAMPLES != 0`.
- The normal PRACH path still runs from the unshifted timestamp.
- The normal PUxCH demod path is explicitly skipped when the non-PRACH offset
  is active, so there is no normal/shifted double-demod for PUSCH.
- The shifted path symbolizes samples, applies the shifted CFO processor, and
  calls the same `puxch_proc->get_baseband().process_symbol(...)` used by the
  normal path.
- `puxch_processor_impl::process_symbol()` exchanges the request pool on slot
  changes, selects the requested resource grid, demodulates into that grid, and
  emits `on_rx_symbol`. If no request/grid is present, it returns `false` and
  does not produce the PUSCH decode path.
- `resource_request_pool` depth is now `128`, enough to avoid the old modulo-16
  collision for a `~30.6` slot delayed collection.

Because CP1837 produced `PUSCH: rnti=0x460...` decode attempts at the expected
RNTIs and nominal slots, the request/grid handoff reached the PUSCH decoder.
This audit does not support a simple "shifted path not connected" or "slot
attribution missing" theory.

## CP1832 vs CP1837

CP1832 baseline:

- No `PAVONIS_NON_PRACH_UL_RX_TIMESTAMP_OFFSET_SAMPLES`.
- One real UE RAR accept/Msg3 branch: `0x4601`, RAR slot `6931`,
  `tti_tx=6937`, retx encode at `6965`.
- gNB PUSCH decode attempts for `0x4601..0x4603`: `15`.
- CRC OK: `0`; CRC KO: `15`.
- SINR range: `-33.5..-15.9 dB`.
- Hidden binary-safe runtime stress in `/tmp/gnb_m2sdr_band3_ota.log`:
  `125701` Soapy TX timeout lines and `2914` downlink-late warnings.

CP1837 with non-PRACH shift active:

- `PAVONIS_NON_PRACH_UL_RX_TIMESTAMP_OFFSET_SAMPLES=-352536`.
- Two real UE RAR accept/Msg3 branches:
  - `0x4602`, RAR slot `5811`, `tti_tx=5817`, retx encode at `5857`.
  - `0x4603`, RAR slot `6931`, `tti_tx=6937`.
- gNB PUSCH decode attempts for `0x4601..0x4603`: `15`.
- CRC OK: `0`; CRC KO: `15`.
- SINR range: `-33.1..-14.6 dB`.
- Runtime stress: `127705` Soapy TX timeout lines and `3340` downlink-late
  warnings.

The shifted path may have changed details of the scheduler/HARQ cadence and
slightly improved the best observed SINR, but it did not create a new decodable
quality class. CP1837 still matches CP1832's core failure: real UE Msg3 exists
and the gNB listens at nominal slots, but PUSCH CRC never goes OK.

## Result

CP1838 closes the narrow "generic non-PRACH shift was not wired into PUSCH"
theory. It was wired into the PUxCH path strongly enough to produce PUSCH
decode attempts, but the resulting samples remain CRC-KO.

Do not spend the next checkpoint on another unchanged RF retry. The next
checkpoint should remain no-RF and either:

- add very low-volume, default-off instrumentation around shifted PUxCH slot
  pickup/request-grid lifetime and per-PUSCH raw symbol power, or
- audit/fix the all-timed TX timeout/downlink-late storm, which is present in
  both CP1832 and CP1837 and remains a co-suspect for UE timing, retx grant
  visibility, and uplink coherence.
