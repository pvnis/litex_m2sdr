## Result

This run is not the requested second PRACH-detection datapoint. It stopped
before UE start:

- `overall_rc=1`
- `gate_rc=0`
- `late_gate_rc=34`
- `ue_started=0`
- Both NUC helper preflights passed.
- Native/all-timed TX readback passed.
- Post-run [host-redacted] ping and helper SSH passed.

The failing gate was `gate_pre_ue_tx_late_health`. Its small gate log shows the
specific reason:

- `LiteX TX worker summary ... late_count=1`
- `LiteX TX release summary ... post_late_count=1`
- `RELEASE_LATE_TRACE_LINE_COUNT=1`

The wrapper therefore skipped UE launch. There is no UE cell-search/SIB1/RACH,
no Msg1, no PRACH detector trace, no RAR, no Msg3, no PUSCH, and no
`PAVONIS_PUXCH_ORDER_TRACE` event to analyze.

## Health

The binary-safe mirror still shows severe all-timed runtime stress before UE
start:

- `soapy_tx_timeout_lines=25573`
- `downlink_late_lines=675`
- `litex_release_late_lines=1`

The gate log's direct grep reports `SOAPY_TX_TIMEOUT_COUNT=0`, but the latest
Soapy summary line in the same gate log reports `timeouts=25050`; the parsed
summary JSON correctly uses the binary-safe mirror count. Keep this parser/gate
visibility mismatch in mind when comparing health fields.

## Classification

CP1841 is an invalid mechanics attempt, not a PRACH-detection void and not an
ordering or sample-domain Msg3 datapoint. It does not consume the user-requested
"second consecutive PRACH-detection void" rule.

Also, this run does not prove or disprove the streaming UL-symbol-manifest
hypothesis: the UE never started and `ul_symbol_manifest` is null in the summary
JSON, so the 260k-row manifest stream did not produce the requested failure
mode in this checkpoint.
