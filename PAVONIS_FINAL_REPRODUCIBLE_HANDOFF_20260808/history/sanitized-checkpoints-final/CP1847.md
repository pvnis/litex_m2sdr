## SI-Control Evidence

CP1840 used the same trace/manifest settings as CP1845/CP1846 and decoded
SIB1:

```text
CP1840 si_pdcch: n_dl=1 max_corr=0.608405 slot=641
CP1840 then emitted si_pdsch_grant, bcch_dlsch_decoded, phy_set_config_ok,
and seven PRACH-TX transmissions.
```

CP1845 and CP1846 never saw an SI grant:

```text
CP1845: 800 si_pdcch_summary rows, best max_corr=0.431305, n_dl_max=0
CP1846: 801 si_pdcch_summary rows, best max_corr=0.466630, n_dl_max=0
```

CP1837, although it predates the order trace, also shows the same qualitative
gap:

```text
CP1837 si_pdcch: n_dl=1 max_corr=0.535903
CP1837 then decoded SIB1 and later reached RAR/Msg3 supply.
```

## Conclusion

Do not apply the memory-buffered UL-symbol-manifest patch from CP1845/CP1846.
That patch remains gated on a future valid-mechanics run that reaches UE Msg1
and again has zero PRACH detector nonempty/accepted rows.

The repeated CP1845/CP1846 voids are SIB1/SI-control supply failures. CP1840
proves the trace/manifest shape can coexist with SIB1 and Msg1, so the leading
near-term issue is marginal SI-PDCCH/control decode rather than the ordering
trace or manifest stream alone.

The existing supported robustness knob is `PAVONIS_GNB_SIB1_DCI_AGGR_LEV`,
exported by the wrapper as `GNB_SIB1_DCI_AGGR_LEV`. Source accepts
`1/2/4/8/16` or `n1/n2/n4/n8/n16`; default is `n4`.
