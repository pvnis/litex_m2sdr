## Conclusion

CP1857 closes the CP1854/CP1855 concern that the typed-row manifest might still
kill SIB1 supply: it does not. SIB1 and seven UE Msg1 transmissions returned.

It does not answer PUxCH ordering or Msg1-to-Msg3 stability because the run
again fails at gNB PRACH detection with zero nonempty/accepted rows and no RAR
or Msg3. Do not rerun this same RF shape unchanged. The next rung should be
no-RF/source-level analysis of the PRACH collection/detector handoff using the
CP1857 predemod manifest, PRACH trace, and UE PRACH timestamps, with the
runtime TX timeout/downlink-late storm kept as a co-suspect.
