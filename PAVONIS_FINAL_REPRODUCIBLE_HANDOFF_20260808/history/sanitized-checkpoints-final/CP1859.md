# CHECKPOINT 1859 - No-RF UL-symbol metadata-only patch

Date: [date-redacted]

## Purpose

CP1858 narrowed the current blocker to PRACH detector correlation regression on
energized windows. Source/history comparison shows the core PRACH timing
compensation source still matches CP1779 and the safer lower-PHY timestamp
source still matches CP1793, while CP1837 accepted PRACH before the high-volume
UL-symbol manifest was enabled and CP1840/CP1851/CP1857 all failed with that
manifest active.

CP1856 removed per-row allocation and file IO, but the hot path still scanned
every symbol sample for RMS/peak and could still write raw symbols. CP1859 adds
a low-overhead default-off mode to preserve symbol timing metadata while
removing the per-symbol sample scan when requested.

## Source Change

Updated:

```text
ocudu/lib/phy/lower/processors/uplink/uplink_processor_impl.cpp
```

New env:

```text
PAVONIS_UL_SYMBOL_METADATA_ONLY=1
```

When set, `PAVONIS_UL_SYMBOL_DUMP` still records manifest rows with symbol
timestamps, SFN/slot/symbol, port, and raw-path fields, but it skips:

- per-sample RMS accumulation
- per-sample peak search
- raw symbol threshold matching
- raw symbol target matching/writes

The default behavior is unchanged when the env is unset or `0`.

## Conclusion

CP1859 does not prove the RF hypothesis, but it creates a clean discriminator:
run the CP1857 shape once with `PAVONIS_UL_SYMBOL_METADATA_ONLY=1`. Success
criterion is first PRACH detector recovery: accepted real p0/RAR/Msg3 supply,
then PUxCH ordering if Msg3 supply returns. If the detector still maxes out
near the CP1840/CP1857 `~0.34-0.37` p0-ratio class, the manifest sample-scan
load hypothesis is weakened and the next no-RF comparison should move to
PRACH demod/scaling/frequency-bin parameters rather than more instrumentation
policy changes.
