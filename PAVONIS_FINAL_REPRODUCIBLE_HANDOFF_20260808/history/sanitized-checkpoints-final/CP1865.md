# CHECKPOINT 1865 - No-RF PRACH collection segment trace build

Date: [date-redacted]

## Purpose

Continue from CP1864 without RF. CP1864 rejected CFO/gain drift as the
saved-data discriminator, so this checkpoint inspected the PRACH sample
preparation path for other burst-varying coherence inputs and built the next
bounded discriminator.

The goal was not to run another same-shape RF retry. It was to expose whether
the lower-PHY PRACH collector is receiving a continuous sample sequence inside
each strong PRACH window, because CP1863 showed identical high-level collection
geometry and similar raw RMS across pass/fail runs while detector correlation
split by more than an order of magnitude.

## Finding

The existing `PAVONIS_PRACH_PREDEMOD_DUMP` summaries prove the high-level
window boundary fields, but not internal segment continuity. For example,
CP1860/CP1861/CP1862 strong windows agree on the configured collection delay,
extra samples, timing residual, start offset, window length, and raw RMS class.
Those summaries also show `window_end_ts == window_start_ts + window_length - 1`.

What they do not record is each input segment appended into a PRACH window:
context SFN/slot/symbol, segment timestamp, append length, expected timestamp,
and timestamp delta relative to the accumulated sample count. That is the
missing proof needed to distinguish "energized but phase/coherence-broken
window" from "nominal boundary with an internal segment discontinuity or
unexpected timestamp jump."

One source-level suspect remains the CFO/sample-offset handoff:
`baseband_cfo_processor::next_cfo_command()` resets `sample_offset` at slot
symbol 0, while `process()` applies phase based on the current sample offset.
The saved CP1860/1861/1862 artifacts do not prove whether any PRACH collection
window crosses a reset or receives internally non-contiguous symbol chunks.

## Change

Added a default-off, metadata-only PRACH collection segment trace in
`prach_processor_worker`:

```text
PAVONIS_PRACH_COLLECTION_SEGMENT_TRACE=1
PAVONIS_PRACH_COLLECTION_SEGMENT_TRACE_ARM_FILE=/path/to/arm_file
PAVONIS_PRACH_COLLECTION_SEGMENT_TRACE_MAX=4096
```

If enabled and armed, it records one row per PRACH collection segment to a
memory buffer and flushes at process exit to:

```text
/tmp/pavonis_prach_collection_segments.tsv
```

Columns include:

```text
window_id
segment_index
request_sfn/request_slot
reported_sfn/reported_slot
context_sfn/context_slot/context_symbol
context_timestamp
input_samples
appended_samples
samples_before/samples_after
expected_timestamp
timestamp_delta
window_length
collection_delay_samples
collection_delay_target_ts
collection_start_symbol
collection_delay_start_offset_samples
arm_file
```

This follows the CP1860 rule: no per-sample scans, no raw sample writes, no
inline file I/O on the lower-PHY hot path, and a bounded row count.

## Decision

CP1865 does not change the RF conclusion from CP1864: do not implement CFO
compensation or a CFO sweep from the current evidence. The next useful
discriminator is internal PRACH collection continuity.

Before the next RF attempt, deploy/rebuild this patch on [host-redacted]. Then run one
bounded CP1860-shape RF discriminator with:

```text
PAVONIS_UL_SYMBOL_METADATA_ONLY=1
PAVONIS_PRACH_COLLECTION_SEGMENT_TRACE=1
PAVONIS_PRACH_COLLECTION_SEGMENT_TRACE_MAX=4096
```

Use the existing arm-file pattern so rows are captured only for the PRACH epoch.
Judge first on whether accepted and rejected strong bursts differ in
`timestamp_delta`, segment count, symbol/slot crossing, or append continuity.
Only if segment continuity is clean should the branch move on to a bounded raw
strong-window replay/correlation capture.
