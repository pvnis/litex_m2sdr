The captured idle/false PRACH windows had internally contiguous sample
timestamps for every recorded segment. However, because the UE emitted no Msg1,
this says nothing about accepted/rejected real UE PRACH bursts.

The run also exposes an important instrumentation issue: the `4096` row cap is
consumed by idle PRACH windows before any real Msg1 supply. An unchanged retry
with the same cap can miss the actual Msg1 epoch even if a later run reaches
SIB1/RACH.

## Decision

CP1868 proves the CP1867 artifact path, but it is void for PRACH continuity
because there is no Msg1 supply. Do not compare this run's segment rows against
CP1860/1861/1862 p0 outcomes.

Before another RF attempt, avoid the same `4096`-row cap failure. Either raise
`PAVONIS_PRACH_COLLECTION_SEGMENT_TRACE_MAX` enough to cover idle windows until
real Msg1 supply, or narrow/late-arm the segment trace so it does not exhaust on
idle PRACH windows. A no-Msg1 run remains void for PRACH conclusions.
