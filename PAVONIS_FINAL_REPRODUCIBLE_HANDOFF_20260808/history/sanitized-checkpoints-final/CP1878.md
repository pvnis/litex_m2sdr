Date: [date-redacted]

## Goal

Make the CP1877-requested effective `+8 dB` downlink supply-control run
representable without using invalid `PAVONIS_GNB_POWER_CONTROL_OFFSET_SS_DB=8`.

## Source Change

Added default-off `PAVONIS_GNB_POWER_CONTROL_OFFSET_DB` in
`ocudu/lib/scheduler/config/csi_helper.cpp`.

Behavior:

- unset / empty: preserve existing `params.csi_params.pwr_ctrl_offset`
- set: parse integer range `-8..15`
- invalid: `report_error(...)` before startup
- active: print `PAVONIS_GNB_POWER_CONTROL_OFFSET_DB active value=<n>`

The existing SS override remains unchanged and still accepts only
`-3`, `0`, `3`, and `6`, matching the FAPI `power_control_offset_ss` enum.

The Stage 6 wrapper now also:

- accepts local `GNB_POWER_CONTROL_OFFSET_DB`
- logs it in the sequence settings line
- exports it to [host-redacted] as `PAVONIS_GNB_POWER_CONTROL_OFFSET_DB`
- includes it in the [host-redacted] preflight string check
- records it in the manifest

## Interpretation

CP1878 fixes the CP1877 representation failure. It does not itself prove
SIB1 supply or SI-control recovery because no RF run was performed.

The next RF retry should freeze the CP1875 shape and use:

- `GNB_POWER_CONTROL_OFFSET_SS_DB=6`
- `GNB_POWER_CONTROL_OFFSET_DB=2`

This yields effective `+8 dB` in the PDSCH power path via
`power_control_offset_ss (+6)` plus `power_control_offset_profile_nr (+2)`,
without adding an invalid FAPI enum value.

Judge the RF retry on `si_best_corr >= 0.55`, `phy_set_config_ok`, and Msg1
supply. The CP1876 storm-placement concern remains open: recent no-SIB1 runs
show fewer downlink-late lines despite constant `~126k` Soapy timeouts.
