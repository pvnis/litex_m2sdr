## Conclusion

CP1883 found and repaired a concrete current environment blocker: after the
bladeRF re-enumerated, udev assigned it to `root:plugdev 0660` while `[host-redacted]`
was not in `plugdev`, so ordinary bladeRF access failed. That is now fixed and
verified from a fresh SSH session.

This does not fully explain CP1882's no-SIB1 RF result, because CP1882's saved
UE log proves srsUE opened the bladeRF and decoded PBCH/cell-search before
failing SI. It does, however, validate that the lab environment did shift and
that another RF run would have been invalid before the permission repair.

Keep gNB/Soapy rebuilds frozen. The next step should remain environment-first:
either get a human physical check of the RF/cabled/attenuator path, or run a
single no-config-change RF sanity control only after confirming the physical
path is as intended.
