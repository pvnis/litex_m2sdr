# CHECKPOINT 1886 - No-RF M2SDR/bladeRF port audit

Date: [date-redacted] Europe/Zurich

## Intent

Before remote-only RF recovery, audit which RF channels the current CP1882-class
gNB M2SDR and srsUE bladeRF configs actually use. The question was whether an
antenna connected to an otherwise unused port could plausibly couple into the
active software path.

No RF transmission and no rebuild were performed.

## gNB / M2SDR side

The live no-RF probe finds the same LiteX-M2SDR device as CP1884:

```text
LiteX-M2SDR /dev/m2sdr0 40f5067470485c
Channels: 2 Rx, 2 Tx
RX Channel 0 Antennas: A_BALANCED
RX Channel 1 Antennas: A_BALANCED
TX Channel 0 Antennas: A
TX Channel 1 Antennas: A
```

The current gNB template is still the Band 3 LiteX-M2SDR template:

```text
device_args: "driver=LiteXM2SDR"
srate: 11.52
tx_gain: 0
rx_gain: 50
tx_gain_backoff: 30
dl_arfcn: 368500
band: 3
channel_bandwidth_MHz: 10
pci: 1
prach_config_index: 1
```

CP1882 itself patched that template to `rx_gain=40`, `tx_gain_backoff=10`, and
`ra_resp_window=40`, then the TX readback proved only channel `0` in the active
TX stream:

```text
channel 0 rate=11.52 Msps freq=1842500000 gain=5 bw=30720000
nof_channels=1
```

Therefore the CP1882-class gNB software path drives M2SDR TX channel 0 and uses
the corresponding single-channel SDR path. M2SDR channel 1 exists in the Soapy
device, but it is not selected by the CP1882 gNB stream.

## Coupling assessment

An antenna connected to a truly unused software port is not an intended signal
path for CP1882-class runs:

- bladeRF RX2 is not sampled by srsUE; bladeRF TX2 is not used for UE PRACH.
- M2SDR channel 1 exists, but CP1882 streams and readbacks use channel 0 only.
- An antenna on an unused port could only affect results through unintended
  passive coupling, leakage, or local RF scattering, not because the software
  is driving or receiving that port.

The active downlink path remains M2SDR TX channel 0 to bladeRF RX1. The active
uplink path remains bladeRF TX1 to M2SDR RX channel 0. Therefore, if an added
antenna is on RX2/TX2 or M2SDR channel 1, it should not directly recover or
break SI/PBCH/PRACH through the configured SDR channel. If it is connected to
M2SDR TX channel 0, bladeRF RX1, bladeRF TX1, or M2SDR RX channel 0, it is on
the active path and can matter directly.
