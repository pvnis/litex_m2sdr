# CHECKPOINT 1887 - Shift +4 MHz RF discriminator, invalid SSB mismatch

Date: [date-redacted] Europe/Zurich

## Intent

Run the user-requested config-only shifted-carrier discriminator: move the Band
3 carrier by a few MHz while freezing the CP1882 RF shape otherwise. This run
used +4 MHz:

```text
CP1882 DL ARFCN: 368500, DL center 1842500000 Hz
CP1887 DL ARFCN: 369300, DL center 1846500000 Hz
```

No gNB/Soapy/srsUE rebuild was performed. Only generated gNB YAML and copied
srsUE config values were patched by the CP1887 runner copies.

## Invalidating mismatch

The UE config was patched to:

```text
dl_nr_arfcn = 369300
ssb_nr_arfcn = 368730
```

But the gNB computed `dl_ssb_arfcn=368910`, not `368730`. The UE therefore
searched:

```text
center_freq_hz=1846500000
ssb_freq_hz=1843650000
```

while the gNB announced/used the shifted SSB raster at ARFCN `368910`
(`1844550000 Hz`). This `900 kHz` SSB mismatch makes CP1887 invalid as the
frequency-selective path/interference discriminator.

## Conclusion

Do not use CP1887 as evidence that a +4 MHz carrier shift fails or succeeds.
The run only proves the shifted gNB carrier was applied and that the UE SSB
configuration was wrong for the gNB-generated SSB raster.

Next step is one corrected shifted-carrier run with:

```text
GNB dl_arfcn = 369300
UE dl_nr_arfcn = 369300
UE ssb_nr_arfcn = 368910
```

Only that corrected run should decide whether to proceed to the authorized
reboot plus original-frequency no-config-change sanity control.
