## Purpose

Run the user-requested CP1896-style Msg3/PUSCH frontier shape with the external
gNB log watcher removed. The gNB binary has CP1903 in-process arm support, and
this run used `PAVONIS_GNB_INPROCESS_UL_SYMBOL_ARM_EVENT=rar_pdu` so the gNB
would touch the UL-symbol arm file on first RAR PDU encode.

## Interpretation

CP1904 is a valid hardware run but not a Msg3 sample-domain datapoint. It did
not reach RAR, so the in-process `rar_pdu` arm correctly had no event to touch.

This run disproves the narrow theory that the CP1898/CP1900 zero-accept pattern
was caused solely by external gNB log polling. With external watching removed,
SIB1 and seven UE PRACH bursts returned, but gNB PRACH correlation still stayed
in the weak `~0.3` max-p0-ratio class rather than CP1896's accepted
`p0_ratio=15.028` class.
