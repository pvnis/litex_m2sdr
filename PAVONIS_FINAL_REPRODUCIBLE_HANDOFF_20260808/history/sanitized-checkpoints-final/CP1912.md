# CHECKPOINT 1912 - No-RF Strong Predemod Wide-CFO Search

## Objective

Follow CP1911's offline result without RF or live [interface-redacted]: test whether the
fresh rejected strong-predemod windows need a wider per-window CFO / coherent
phase-progression search than the CP1911 `+/-3 kHz` grid, or whether the
unrecovered windows are not simple-CFO failures.

## Method

Copied the corrected CP1911 replay harness into
`cp1912_strong_predemod_wide_cfo_replay.cpp` and kept the live-matched detector
path: `ra_scs=0`, threshold `0.6100000143`, and the same OCUDU PRACH OFDM
demodulator plus detector.

Added two no-RF modes:

- `wide_cfo`: CFO-only from `-25 kHz` to `+25 kHz` in `250 Hz` steps.
- `wide_combo`: the same wide CFO-only grid plus a heavier timing/CFO grid
  using integer shifts `-224..+224` samples, fractional shifts `-0.5/0/+0.5`,
  and CFO `-25 kHz..+25 kHz` in `500 Hz` steps.

Inputs:

- CP1910 accepted-class strong predemod windows.
- CP1909 fresh rejected-class strong predemod windows.
- CP1907 earlier rejected-class strong predemod windows as optional comparator.

## Conclusion

CP1911's `+/-3 kHz` CFO bound was too narrow. A wider per-window CFO /
coherent phase-progression search recovers five of six CP1909 rejected windows
and all six CP1907 rejected windows offline, while preserving p0 identity in
the CP1909 wide-combo run.

This is not evidence for a single static live CFO knob. The best offsets are
large and vary strongly per window (`+2 kHz` to `+24 kHz` in CP1909 wide
combo; CP1907 includes negative and positive wide offsets). CP1909 `idx=5`
still does not recover even with wide timing+CFO and sits at the search edge.

Next rung should remain no-RF: prototype a default-off detector-side bounded
CFO/phase-progression search with strict trace output and an idle/no-PRACH
false-positive control before any RF trial. Do not resume live delay [interface-redacted].
