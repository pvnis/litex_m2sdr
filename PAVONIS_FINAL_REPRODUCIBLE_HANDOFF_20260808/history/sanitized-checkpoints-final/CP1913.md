## Purpose

CP1912 named CFO/coherent phase progression as the only swept variable class
that materially rescued rejected-class strong predemod windows, but the
successful offsets were large and per-window rather than static. CP1913 tests
whether a bounded p0-only detector-side search keeps the CP1909 recovery while
rejecting obvious false-positive controls before any live implementation or RF
run.

## Interpretation

The p0-only restriction is not losing any CP1909 recovered detections observed
in the full-preamble normal replay: accepted CP1909 variants are all preamble 0.

The structural/synthetic controls are clean in this offline dataset. Excluding
preamble 0, changing to the wrong root, preserving amplitude while scrambling
coherent phase, and zeroing samples all produce zero accepted rows even under
the permissive wide timing+CFO grid.

This clears a no-RF safety gate for a default-off bounded search prototype, but
it is not a full live idle/no-PRACH false-positive proof. The strong-window
capture set contains energized PRACH windows, not a fresh captured idle window
from the same bounded raw-CF32 mechanism.

## Frontier

Stay no-RF for the next step. A live detector implementation must operate before
OFDM PRACH demodulation, because CP1912/CP1913 apply the CFO transform to raw
CF32 input, not to the already-demodulated `prach_buffer`.

Next source work should prototype a default-off, trace-heavy, p0-only bounded
CFO/phase-progression search at the lower-PHY raw-CF32 PRACH input, with a
strict cap on candidates and no per-sample hot-path logging. Do not convert the
large CP1912/CP1913 per-window offsets into a static live CFO knob, and do not
resume PRACH delay/window [interface-redacted].
