# CHECKPOINT 1919 - No-RF p0-only CFO-search energy gate

Date: [date-redacted]

## Goal

After CP1918, prevent the live p0-only CFO-search prototype from spending
candidate detector work and trace budget on idle PRACH windows before the UE
has supplied Msg1. This is hot-path/instrumentation hygiene only; it does not
change RF [interface-redacted], PRACH delay, or static CFO policy.

## Changes

`prach_processor_worker.cpp` now supports two default-off floors:

- `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH_RMS_DB_FLOOR`
- `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH_PEAK_DB_FLOOR`

When either floor is set and `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH=1`, the
worker measures the pre-demod CF32 PRACH window energy before constructing the
candidate detector or running the CFO grid. The p0-only CFO search runs only
when the window passes at least one configured RMS/peak floor. With both floors
unset or empty, behavior remains the CP1915/CP1917 default.

`cp1807_run_stage6_raresp40_realue_rar_msg3.sh` now exports, logs, and records
the two floor envs in the final manifest.

New wrapper:

- `cp1919_run_cfo_search_energy_gated_cp1896_shape_rf.sh`

The wrapper keeps the CP1918 RF shape frozen but adds the same floors used by
the bounded strong predemod capture:

- `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH_RMS_DB_FLOOR=-70`
- `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH_PEAK_DB_FLOOR=-55`

## Conclusion

CP1919 makes the next live p0-only CFO-search trial less perturbative by
skipping idle windows before the expensive candidate loop and before trace rows
are consumed. The next step is a no-RF [host-redacted] deploy/build-smoke of this exact
source, then one RF trial using the energy-gated CP1896 shape. A valid RF
datapoint still requires UE Msg1 supply before judging the search.
