## Interpretation

The CP1919/CP1920 energy gate fixed the CP1918 idle trace/work issue: CP1921
packages no CFO-search trace file in a no-Msg1 run. The remaining blocker is
SIB1/SI-control visibility. Since the two SIB1-pass runs and the no-SIB1 run
use comparable host/TX health classes, the next RF run should be a supply
control, not another detector trial.

Specific next discriminator:

- Run the same CP1921/CP1920 binary and RF shape with
  `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH=0`, keeping strong predemod capture and
  all RF/delay settings frozen.
- If SIB1/Msg1 returns, the enabled CFO-search path or its energy check still
  perturbs the live run enough to break SI supply despite the gate.
- If SIB1/Msg1 still fails, the SI-control collapse is independent of the
  CFO-search path and should be handled as a downlink/SIB1 supply problem
  before any more PRACH detector work.

No PRACH delay, RF power, or static-CFO value should be [interface-redacted] from CP1918,
CP1921, or this no-RF join.
