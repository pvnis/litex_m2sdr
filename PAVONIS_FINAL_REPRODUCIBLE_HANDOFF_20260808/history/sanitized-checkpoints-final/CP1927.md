# CHECKPOINT 1927 - no-RF SI-PDSCH compare CP1909/CP1910 versus CP1926

Date: [date-redacted]

Status: PASS. No RF was run.

## Purpose

After CP1926 restored the CP1917 `30f0...` binary but still failed SIB1/Msg1,
compare the SIB1-pass SI-PDSCH path from CP1909/CP1910 with CP1926's repeated
SI grant/no-TB path. The question is whether CP1926 differs structurally in the
SI grant, or whether the same grant geometry is present but the SI transport
block fails to decode.

## SI Control And Grant Geometry

| Run | `si_pdcch` | `si_pdsch_grant` | Direct Corr | Direct EPRE Mean | Grant Signature | BCCH TB |
| --- | ---: | ---: | --- | ---: | --- | --- |
| CP1909 | 1 | 1 | `0.548263` | `33.499` | `S=2 L=12 mapping=0 groups=2 dmrs=type=1,typeA_pos=2,add_pos=2,len=single` | `bytes=80` |
| CP1910 | 1 | 1 | `0.530419` | `33.464` | same | `bytes=80` |
| CP1926 | 41 | 41 | `0.501653..0.601893`, mean `0.534212` | `33.476` | same, repeated 41 times | none |

The first CP1926 direct SI grant slots were:

`2721, 2881, 4001, 4481, 4641, 4801, 5121, 5761`

The grant slot class matches the pass runs: CP1909 decoded at slot `9441`,
CP1910 at slot `7841`, and CP1926 direct grants are all in the same
`slot % 160 == 1` class.

CP1909 decoded immediately:

- `si_pdcch slot=9441 sif=1 n_dl=1 ... max_epre=33.499 max_corr=0.548263`
- `si_pdsch_grant slot=9441 S=2 L=12 mapping=0 nof_dmrs_groups=2`
- `bcch_dlsch_decoded bytes=80`
- `sib1_received ... rach_present=1`

CP1926 repeatedly sees the same control/grant class but never emits
`bcch_dlsch_decoded`, `processing_sib1`, or `sib1_received`.

## Interpretation

CP1926 is not a missing-SI-control problem and not a broad PBCH/channel-quality
collapse. The SI PDCCH is decoded, the SI PDSCH grant geometry is byte-for-byte
the same class as the SIB1-pass controls, and direct SI correlation/EPRE are
pass-class. The remaining observed failure is the SI transport block itself:
the UE receives repeated SI grants but never decodes the 80-byte BCCH DLSCH.

That makes SIB1 PDSCH margin the next live discriminator. The existing gNB
helper already has a config-only knob:

`PAVONIS_GNB_FIXED_SIB1_MCS`

which inserts:

```yaml
  pdsch:
    fixed_sib1_mcs: <value>
```

## Next

Run one RF supply-control with the CP1926 shape and `GNB_FIXED_SIB1_MCS=0`,
leaving SI-PDCCH aggregation and power unchanged. Judge on
`bcch_dlsch_decoded`, `phy_set_config_ok`, and UE Msg1 supply. If SIB1 returns,
keep the fixed low SIB1 MCS as a temporary supply fixture; if it does not,
stay no-RF and inspect the SI-PDSCH/TB decode state or hardware/path condition
before resuming PRACH/CFO work.
