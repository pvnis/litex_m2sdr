## Purpose

After CP1928 failed with `GNB_FIXED_SIB1_MCS=0`, audit whether the
`fixed_sib1_mcs` path is a valid next lever or a branch already closed by
prior checkpoints.

## Source/Config Meaning

The knob is real and reaches the scheduler:

- `du_high_config.h`: default `fixed_sib1_mcs = 5`
- `du_high_config_translators.cpp`: writes `out_cfg.si.sib1_mcs_index`
- `sib1_scheduler.cpp`: uses `expert_cfg.sib1_mcs_index`
- scheduler tests assert the SI DCI MCS field equals `sib1_mcs_index`

CP1928 also proved the generated YAML carried:

```yaml
cell_cfg:
  pdsch:
    fixed_sib1_mcs: 0
```

So CP1928 was a valid test of the existing fixed-MCS config path.

## CP1926 Versus CP1928

The generated gNB configs differ only by the inserted `cell_cfg.pdsch` block in
CP1928. CP1926 had no `pdsch` override.

CP1926:

- PBCH/cell/SFN pass
- `41` direct SI-PDCCH hits
- `41` SI-PDSCH grants
- direct SI correlation `0.501653..0.601893`
- no `bcch_dlsch_decoded`, no SIB1, no Msg1

CP1928:

- PBCH/cell/SFN pass
- zero direct SI-PDCCH hits
- zero SI-PDSCH grants
- `800` SI summary rows only
- summary corr `0.109382..0.236650`
- no SIB1, no Msg1

The low-MCS config did not recover the CP1926 repeated-grant/no-TB class; it
landed in a weaker no-direct-SI-control class.

## Historical Branch Check

CP1748 already tested YAML-only SIB1 demarginalization with:

```yaml
pdsch:
  fixed_sib1_mcs: 0
ssb:
  ssb_block_power_dbm: -4
```

That run passed TX/process gates and reached PBCH/SFN, but still produced:

- `sib1_si_pdcch_summary_count=800`
- `sib1_si_pdcch_count=0`
- `sib1_si_pdsch_grant_count=0`
- `sib1_bcch_decoded_count=0`
- `sib1_phy_set_config_ok_count=0`
- `prach_tx_count=0`

Its SI summary correlation also regressed:

- `max_corr` min/mean/median/max:
  `0.109076 / 0.151214306 / 0.148629 / 0.365240`
- rows `>= 0.4`: `0`
- rows `>= 0.5`: `0`

CP1748 explicitly closed YAML-only demarginalization as a failed SIB1 gate.
CP1928 reproduces the same conclusion in the current restored-binary shape.

## Interpretation

Do not keep spending RF on `fixed_sib1_mcs` or YAML-only SIB1 de-margining.
It is not a supply fixture for the current blocker.

The active blocker remains post-PBCH SIB1 reliability:

- sometimes no direct SI control/grant occurs at all (`CP1921`, `CP1923`,
  `CP1928`);
- sometimes SI control and grants are present but the 80-byte BCCH TB never
  decodes (`CP1926`);
- CP1909/CP1910 still show that the same overall shape can decode SIB1 and
  provide seven Msg1 attempts.

This points away from PRACH/CFO and away from source/binary restoration. The
next useful work is no-RF diagnosis of the SI downlink reliability split:
compare CP1909/CP1910/CP1926/CP1928 on SIB1-era RF/channel metrics, UE
cell-search CFO/timing, SI trace timing, and any available host/USB/RF health
columns; then decide whether the next RF run should be a plain no-config
control, a hardware/path sanity discriminator, or a source-level SI/PDSCH trace.
