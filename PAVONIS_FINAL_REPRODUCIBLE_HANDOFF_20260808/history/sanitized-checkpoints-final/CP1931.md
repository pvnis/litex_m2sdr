# CHECKPOINT 1931 - No-RF srsUE SI-PDSCH decode trace patch

Status: EXECUTED. No RF was run.

## Goal

Follow CP1930's next no-RF rung: audit whether existing CP1909/CP1910/CP1926
logs already expose the SI-PDSCH decode failure point, and if not add a narrow
default-off trace so the next RF run answers it directly.

## Source audit

Existing `PAVONIS_SRSUE_SIB1_TRACE` coverage in
`srsRAN_4G/srsue/src/phy/nr/cc_worker.cc` reports:

- SI-PDCCH search summaries and direct `si_pdcch` hits.
- `si_pdsch_grant` with slot, `S`, `L`, mapping, DMRS groups, and DMRS string.

Existing RRC trace in `srsRAN_4G/srsue/src/stack/rrc_nr/rrc_nr.cc` reports:

- `bcch_dlsch_decoded`
- `processing_sib1`
- `sib1_received`
- `phy_set_config_ok`

The missing link is the actual SI-PDSCH transport-block path. Existing CP1909,
CP1910, and CP1926 logs do not show whether MAC enabled the SI TB, what
MCS/TBS/RV/NDI the UE used, or whether `srsran_ue_dl_nr_decode_pdsch()` returned
CRC OK/KO for SI-RNTI. Therefore CP1926's 41 SI grants cannot yet be classified
as "valid grant but SI-PDSCH CRC KO" versus "CRC OK but BCCH handoff failed".

## Patch

Patched only `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`.

The patch is default-off under the existing `PAVONIS_SRSUE_SIB1_TRACE` gate and
adds metadata-only lines:

- Extends `event=si_pdsch_grant` with `rnti`, `pid`, `nof_prb`, `nof_layers`,
  `mcs`, `tbs_bytes`, `rv`, and `ndi`.
- Adds `event=si_mac_action` after `phy.stack->new_grant_dl(...)`, reporting
  whether MAC enabled the TB and supplied a softbuffer.
- Adds `event=si_pdsch_decode` after `srsran_ue_dl_nr_decode_pdsch(...)`,
  reporting `crc`, `tbs_bytes`, `mcs`, `rv`, `ndi`, `avg_iter`, `evm`, `cfo`,
  `snr`, and `sync_err`.

This is not per-sample instrumentation and should produce one short metadata
line per SI grant/action/decode when SIB1 tracing is enabled.
