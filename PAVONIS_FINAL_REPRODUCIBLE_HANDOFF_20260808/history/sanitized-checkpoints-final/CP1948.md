# CHECKPOINT 1948 - no-RF srsUE SI Candidate Trace Deploy

Date: [date-redacted] Europe/Zurich

## Purpose

Add the next no-RF instrument for the CP1947 frontier: a bounded, metadata-only
srsUE SI-PDCCH candidate trace. This does not dump raw samples. It logs the
per-candidate PDCCH geometry and measured EPRE/RSRP/correlation only when an
SI candidate is near threshold or a DCI is found.

This is intended to explain future no-SIB1 runs where PBCH/SFN works and
independent raw DL is healthy, but live SI-PDCCH stays sub-direct-grant.

## Source Change

File:

```text
srsRAN_4G/srsue/src/phy/nr/cc_worker.cc
```

New default-off envs:

```text
PAVONIS_SRSUE_SI_CANDIDATE_TRACE
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT        default 200
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR     default 0.40
```

When enabled, the trace emits one bounded line per qualifying SI-PDCCH slot:

```text
PAVONIS_SRSUE_SI_CANDIDATE_TRACE event=si_pdcch_candidates ...
```

Each line includes slot/SIF, `n_dl`, SI-RNTI, CORESET0 duration/start RB,
candidate count, max EPRE/corr, and per-candidate `L`, `ncce`, `coreset`,
format, bit count, EPRE, RSRP, corr, and CRC result.

## Interpretation

The next RF run can keep CP1946's shape frozen and enable only:

```text
PAVONIS_SRSUE_SI_CANDIDATE_TRACE=1
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT=400
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR=0.35
```

This should produce bounded per-candidate SI-PDCCH metadata without raw IQ or
sample scanning. It is suitable for comparing a future no-SIB1 run against
CP1933-style SIB1-pass behavior and should not perturb the lower-PHY hot path
like raw dumps did.
