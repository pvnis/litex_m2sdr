# CP1952 - No-RF RAR-Window Trace Audit

Date: [date-redacted]

## Purpose

Correct the CP1949/CP1950 interpretation and decide whether the next RF run can
answer the UE RAR visibility question without adding new hot-path or pre-SIB1
instrumentation.

## Correction

CP1949 and CP1950 prove:

- SIB1/RACH config returned.
- The UE emitted seven Msg1 bursts.
- The gNB accepted one real preamble-0 row in each run.
- The gNB encoded a RAPID-matching RAR on `ra_rnti=0x39`.
- The UE logged no `Setting RAR Grant`, no `Set TA RAR`, and no Msg3.

They do not prove that the UE opened no RAR window or searched no RA-RNTI
PDCCH. `PAVONIS_SRSUE_RAR_WINDOW_TRACE=0` in both runs, and the source gates
`rar_window_start`, `rar_opportunity`, `dl_sched_rnti`, and RA-PDCCH summary
visibility behind that env. The summary fields for those events are therefore
not diagnostic in CP1949/CP1950.

## Source Audit

Relevant source paths:

- `srsRAN_4G/srsue/hdr/stack/mac_nr/pavonis_rar_trace.h`
- `srsRAN_4G/srsue/src/stack/mac_nr/proc_ra_nr.cc`
- `srsRAN_4G/srsue/src/stack/mac_nr/mac_nr.cc`
- `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`
- `srsRAN_4G/srsue/src/stack/rrc_nr/rrc_nr.cc`

Findings:

- `rar_trace_printf()` is memory-buffered and flushes at exit unless immediate
  flushing is explicitly requested.
- `rar_trace_take()` requires `PAVONIS_SRSUE_RAR_TRACE=1`, late-arm state, and
  the bounded `PAVONIS_SRSUE_RAR_TRACE_LIMIT`.
- The late arm is set after `phy_set_config_ok` in `rrc_nr.cc`, so the trace
  should stay silent before SIB1/RACH config.
- `PAVONIS_SRSUE_RAR_WINDOW_TRACE=1` adds the missing RAR-window events but
  remains bounded by the same trace limit and late-arm rule.
- CP1807 forwards `PAVONIS_SRSUE_RAR_TRACE`,
  `PAVONIS_SRSUE_RAR_TRACE_LIMIT`,
  `PAVONIS_SRSUE_RAR_TRACE_LATE_ARM`, and
  `PAVONIS_SRSUE_RAR_WINDOW_TRACE` to the [host-redacted] UE helper.
- The [host-redacted] helper forwards the same envs into `srsue`, `launch.env`, and
  `result.env`.

## Decision

No source patch is needed before the next RF run. The existing trace path is
already the bounded late-armed variant needed for this question.

Next RF should keep the CP1949/CP1950 restored no-search shape, disable the
SI-candidate trace to avoid changing the SIB1 supply path, and enable only:

```text
PAVONIS_SRSUE_RAR_TRACE=1
PAVONIS_SRSUE_RAR_TRACE_LIMIT=800
PAVONIS_SRSUE_RAR_TRACE_LATE_ARM=1
PAVONIS_SRSUE_RAR_WINDOW_TRACE=1
```

Success criteria:

- If SIB1/Msg1 does not occur, the run is void for the RAR question.
- If Msg1 occurs and the gNB sends RAR, use UE-side `rar_window_start`,
  `rar_opportunity`, `dl_sched_rnti`, `ra_pdcch`, `ra_pdcch_dci`,
  `ra_pdsch_*`, and RAR grant/TA/Msg3 markers to split:
  - no UE RA window,
  - RA-RNTI search at wrong TTIs,
  - PDCCH miss,
  - PDSCH miss,
  - MAC RAR handoff failure.
