## Interpretation

The repeated CP1956/CP1957 voids do not by themselves prove that CFO-search
runtime/load kills SIB1:

- CP1940 used the same CP1936 CFO-capable binary with CFO search off and still
  voided before SIB1/Msg1.
- CP1943 used a restored no-search binary and also voided before SIB1/Msg1.
- Later restored no-search runs CP1949, CP1950, and CP1953 recovered SIB1/Msg1
  at similar timeout/late-count class and normal EPRE.
- CP1956/CP1957 have normal EPRE but low SI correlation, matching the high-EPRE
  low-correlation void class seen in CP1937 and CP1943.

So the current split is not "CFO search on versus off" from existing data. It
is current active CP1936 binary state versus current downlink supply/path
quality, with CFO-search runtime still a live co-suspect because CP1956/CP1957
are the only current post-CP1953 runs.

## Next Step

Run one RF supply control on the active CP1955/CP1936 binary with
`PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH=0`, keeping the rest of CP1956/CP1957
unchanged. This is a supply split, not a detector-policy trial:

- If SIB1/Msg1 returns, CFO-search enablement/runtime is the leading cause of
  the current supply collapse and detector RF should stay stopped.
- If SIB1/Msg1 still fails, current downlink supply/path or active binary class
  remains the blocker; the next split is restored no-search binary versus
  physical/path state, not more detector [interface-redacted].
