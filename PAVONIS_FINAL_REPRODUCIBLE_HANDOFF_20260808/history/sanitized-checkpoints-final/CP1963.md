## Delta Summary

The CMake file is identical. The header adds only one member:

```text
std::vector<cf_t> pavonis_demod_input_transform_buffer;
```

The worker changes are three hunks:

```text
1. Add PRACH detector/generic DFT/support includes plus <algorithm>.
2. Add pavonis_env_enabled().
3. Add the CFO-search block immediately before the normal "Demodulate all
   candidates" call.
```

The expensive detector-side work is gated by:

```text
PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH enabled
nof_ports == 1
energy gate passes
```

When the main CFO-search env is off, the CP1936 source still executes only a
small amount of always-on local setup at each demodulation point: selected/best
state initialization, optional RMS/peak floor environment lookups, and energy
floor calculation only if one of the floor envs is present. The candidate
buffer allocation, DFT/detector factory creation, per-candidate phase rotation,
candidate demodulation, and trace writes are all inside the enabled branch.

## Interpretation

CP1963 explains why CP1959 cannot be treated as "CFO search loop load killed
SIB1": CP1959 had `PAVONIS_PRACH_DEMOD_INPUT_CFO_SEARCH=0`, and this audit does
not show the expensive detector/search loop running in that state.

The CP1936 binary/source class is still not safe as a live RF vehicle because
CP1959 failed before SIB1/Msg1 on that binary while CP1961 restored SIB1/Msg1
after returning to the no-search `30f0...` binary. The source delta is narrow,
but the observed supply split remains real. Treat it as a binary/source-class
regression until isolated by a cleaner patch from the restored no-search base.
