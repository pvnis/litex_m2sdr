windows clustered near the `+24 kHz` CFO boundary, while idx4/idx5 had strong
tail peaks but no in-gate threshold pass. This checkpoint widens the no-RF
offline replay grid before any live source patch or RF trial.

Both previously unrecovered CP1961 windows recover offline:

```text

idx5 accepting variants: 1148
```

The best accepted points pass both threshold and delay gate. This means the
CP1962 idx4/idx5 failures were range-limited, not unrecoverable raw windows.

## Interpretation

CP1964 completes the no-RF variable identification for the CP1961 strong-window
set. All six CP1961 windows are recoverable offline by detector-input coherent
timing+CFO correction:

```text
idx0..idx3: CP1962 recovers with shift -112..-224 and cfo about +24 kHz
idx4..idx5: CP1964 recovers with shift -400/-368 and cfo +38.5/+43.5 kHz
```

The next source path should not be a static live CFO or delay knob. It needs a
bounded detector-input transform/search or an upstream correction that can
cover at least this class of per-window timing/CFO variation. Because the
full extreme grid is too expensive for a live hot path, the next no-RF source
step should design a staged or bounded policy from the restored no-search base,
then build-smoke it with strict default-off verification before any RF.
