# CP1965 - No-RF Stage-1 Policy Replay

Date: [date-redacted]

## Purpose

Test whether a live-feasible staged detector-input search can recover the
CP1961 strong-window class without the full CP1964 extreme grid.

## Harness

Copied the CP1964 replay harness and added `stage1_policy`:

```text
baseline plus:
  integer shift -448..-96 samples, step 32
  fractional shift -0.5 and +0.5 samples
  CFO +20000..+50000 Hz, step 1000
  detector path unchanged: ra_scs=0, threshold=0.6100000143
```

This yields `745` candidates per window including the baseline row.

## Results

The compact policy recovers all six CP1961 windows offline:

```text
idx0 accepting variants=205 best_accept p0=4.107 delay=2 shift=-288 frac=+0.5 cfo=+25000
idx1 accepting variants=196 best_accept p0=5.335 delay=2 shift=-192 frac=+0.5 cfo=+27000
idx2 accepting variants=208 best_accept p0=6.509 delay=0 shift=-96  frac=+0.5 cfo=+27000
idx3 accepting variants=173 best_accept p0=4.158 delay=3 shift=-224 frac=+0.5 cfo=+32000
idx4 accepting variants=139 best_accept p0=5.933 delay=1 shift=-256 frac=+0.5 cfo=+40000
idx5 accepting variants=47  best_accept p0=4.172 delay=0 shift=-224 frac=-0.5 cfo=+45000
```

Important selector detail: for idx0..idx3, the largest raw p0 ratio in this
grid is a tail peak at delay `129/130` that fails the delay gate. A live policy
must select the best accepted/in-gate candidate, not the highest raw p0 ratio.

## Interpretation

CP1965 turns CP1964's full offline variable ID into a practical first live
source policy candidate: a bounded positive-CFO, negative-timing stage recovers
the whole CP1961 set with `745` candidates per PRACH window. That is still
expensive enough to keep strictly opt-in and energy-gated, but it is no longer
the CP1964 full-grid class.

Next source work should implement this as a default-off staged policy from the
restored no-search base. It should:

```text
1. run only when the new env is explicitly enabled;
2. keep all heavy allocation/search work inside the enabled branch;
3. energy-gate before the search;
4. select only accepted/in-gate p0 candidates;
5. record enough bounded trace to prove the selected shift/CFO;
6. verify binary string/hash state before any RF.
```
