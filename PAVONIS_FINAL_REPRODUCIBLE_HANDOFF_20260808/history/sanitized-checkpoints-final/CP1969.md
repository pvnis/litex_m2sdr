Source inspection of the CP1966 stage-1 block shows the expensive

Because CP1967/CP1968 have `energy_gate=0` for all traced rows, the full
candidate grid did not run on those traced windows. The enabled path still did

full CP1965 search on real Msg1 supply because the UE never emitted Msg1.

## Conclusion

CP1967/CP1968 do not test the detector fix. They are a paired SIB1-supply
regression under the stage-1-enabled shape.

The no-RF join rejects gross timeout/downlink-late count as the immediate
discriminator: CP1961 passed with the same storm class. It also rejects the
specific theory that the full stage-1 candidate grid killed SIB1 in these runs,
because the energy gate never opened in the traced rows.

The remaining split is:

- stage-1-enabled branch and/or its bounded trace/I/O perturbs supply even
  before Msg1,
- the `c255...` stage-1 binary/source class perturbs supply even when old CFO
  search is absent,
- or the lab downlink supply independently fell into the CP1959-like
  low-correlation class after CP1961.

Next valid action is a supply-only RF control, not detector [interface-redacted]: run the
active `c255...` stage-1 binary with `PAVONIS_PRACH_DEMOD_INPUT_STAGE1_POLICY=0`
and `PAVONIS_PRACH_DEMOD_INPUT_STAGE1_TRACE=0`, keeping the CP1961/CP1967 RF
shape otherwise frozen. If SIB1/Msg1 returns, the enabled stage-1 branch/trace
is the supply perturbation. If it still voids, restore or redeploy the
`30f0...` no-search binary and run the same supply control to split binary/source
class from current lab downlink supply. No live CFO/delay/detector [interface-redacted] should
run until this supply split is closed.
