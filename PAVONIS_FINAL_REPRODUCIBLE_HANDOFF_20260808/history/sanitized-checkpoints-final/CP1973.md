## Documentation and Source Audit

LiteX-M2SDR documents two relevant clock paths:

- SI5351C hardware can use local XO or external `10 MHz` via uFL/FPGA.
- Soapy accepts `clock_source=internal|external|fpga`.
- The Soapy driver defaults to `clock_source="internal"` unless device args
  override it.
- `m2sdr_rf --sync` similarly accepts `internal`, `external`, or `fpga`, with
  default `internal`.
- Gateware exposes SI5351 `clkin_src`: `0` for FPGA `clk10`, `1` for uFL.

## Conclusion

The current M2SDR configuration is internally referenced. The stack has a
documented external-reference path, but the live readback shows internal-XO
mode and SI5351 PLL input sourced from XTAL, with external LOS asserted.

The user's clock-drift theory is plausible and now the leading physical/root
cause hypothesis for the current detection lottery, SI marginality, and likely
Msg3 wall. It is not proven solely by CP1973, because the read-only clock test
only confirms nominal MHz-level counters and does not measure short-term RF
phase noise or thermal ppm drift. But the CP1961 `+25 kHz -> +45 kHz` ramp over
`5.6 s` at nearly constant raw amplitude is strong evidence that further
detector constants or static live CFO/delay knobs are the wrong next move.

Freeze detector/delay/Msg3 RF work until the reference-clock branch is split:
either verify and use a real external `10 MHz` reference path, or explicitly
characterize the internal-XO drift/coherence enough to justify a dynamic
per-run correction.
