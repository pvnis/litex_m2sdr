## Source and Config Path

The current CP1972-style generated gNB YAML used:

`device_args: "driver=LiteXM2SDR"`

with no `clock_source`, so LiteX-M2SDR Soapy defaults to `internal`.

The relevant source path is:

- LiteX-M2SDR Soapy documents `clock_source=internal|external|fpga`.
- `LiteXM2SDRDevice.cpp` defaults to `clock_source="internal"` and consumes a
  `clock_source` key from Soapy device args.
- OCUDU's Soapy radio device constructs the device with
  `SoapySDR::Device::make(args)`.
- OCUDU's `ru_sdr.clock` YAML field is translated into generic radio clock
  config, but the Soapy radio path does not apply it through a post-construction
  `setClockSource()` call in the way the UHD path does.

Therefore the usable live-gNB lever for LiteX-M2SDR clock source is
`ru_sdr.device_args`, not `ru_sdr.clock`.

## Conclusion

CP1974 proves the config path needed for the reference-clock split, but it does
not prove that changing the clock source restores RF coherence. No RF was
started, no live SDR stream was opened, and no SI5351/AD9361 readback after a
clock-source switch was collected.

The next valid step is a controlled clock-source split, not more detector or
delay [interface-redacted]:

- Do not run `clock_source=external` unless a real external `10 MHz` reference is
  physically present and confirmed, because CP1973 showed external LOS in the
  current internal-XO state.
- Before any RF trial, run a read-only or config-limited clock-source readback
  probe that selects the candidate clock source and confirms the expected
  SI5351 status/source state without starting the gNB data-plane.
- Only after the selected clock source is confirmed should one frozen CP1972
  supply-control RF sanity run be spent to judge whether SI correlation,
  SIB1/Msg1 supply, and the CFO ramp recover.

Detector/delay/Msg3 RF remains frozen until that reference-clock branch is
split.
