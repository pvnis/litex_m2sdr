# CHECKPOINT 1978 - No-RF UE SI Tracking-State Instrumentation

Date: [date-redacted]

## Question

CP1977 rejected a static downlink CFO/frequency knob because initial cell-search
CFO stayed tightly clustered while SI-PDCCH correlation varied widely. The
missing measurement was the UE's same-interval post-camping tracking state:
`q_cfo`/delay near the SI-PDCCH summary windows, not just initial cell-search
CFO.

CP1978 asks whether this can be instrumented with low impact before spending
more RF.

## Result

PASS_REMOTE_NO_RF_BUILD. CP1978 adds metadata-only UE-side plumbing that
publishes the latest NR sync tracking outcome into the existing NR PHY shared
state and prints it on the existing
`PAVONIS_SRSUE_SIB1_TRACE event=si_pdcch_summary` aggregate line.

No RF was run.

The next RF run can now join each SI-PDCCH summary window against:

- `sync_seq`
- `sync_tti`
- `sync_sf_idx`
- `sync_sfn`
- `sync_in_sync`
- `sync_cfo_hz`
- `sync_delay_us`

This is the actual `srsran_ue_sync_nr_zerocopy()` outcome path, not the separate
TRS/CSI `phy.get_dl_cfo()` value.

## Source Audit

Relevant source findings:

- Existing SI summary lines are emitted in
  `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc` by
  `pavonis_sib1_trace_pdcch_summary()`.
- `cc_worker` has access to NR PHY `state`, but not directly to the private
  `slot_sync::ue_sync_nr` object.
- `phy.get_dl_cfo()` in `cc_worker.cc` is TRS/CSI-derived and is therefore not
  the desired SSB tracking-loop state.
- `srsran_ue_sync_nr_zerocopy()` already returns `outcome.cfo_hz` and
  `outcome.delay_us` from the SSB sync loop.
- `sync_sa` owns `slot_sync` and calls `slot_synchronizer.run_camping()` before
  dispatching DL workers, while `worker_pool` owns the shared NR PHY `state`.

Chosen path:

- Store the latest `srsran_ue_sync_nr_outcome_t` in `slot_sync`.
- Publish that outcome through `worker_pool` into shared `nr::state` once per
  camping receive.
- Read that state in the existing SI summary emitter and append fields to the
  low-rate summary line.

This avoids enabling older verbose `PAVONIS_UE_SYNC_NR_TRACE` output and avoids
per-sample/lower-PHY hot-path work.

  - Added mutex-protected latest sync-tracking snapshot.
  - Added `set_sync_tracking()` and `get_sync_tracking()`.

  - Added `get_last_outcome()` and `last_outcome`.
- `srsRAN_4G/srsue/src/phy/nr/slot_sync.cc`
  - Saves `last_outcome` after successful `srsran_ue_sync_nr_zerocopy()` in
    SFN-sync and camping paths.
- `srsRAN_4G/srsue/hdr/phy/nr/worker_pool.h`
  - Added `set_sync_tracking()` bridge declaration.
- `srsRAN_4G/srsue/src/phy/nr/worker_pool.cc`
  - Publishes sync outcomes into shared state.
- `srsRAN_4G/srsue/src/phy/sync_sa.cc`
  - Calls `workers.set_sync_tracking()` immediately after each camping receive
    in both align and legacy paths.
- `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`
  - Appends tracking fields to `event=si_pdcch_summary`.
