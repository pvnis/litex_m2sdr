## Source Context

The common SIB1 trace helpers also use uncached env lookups and parsing in
`cc_worker.cc`:

- `pavonis_sib1_trace_enabled()` calls `getenv`.
- `pavonis_sib1_trace_limit()` calls `getenv` and `strtoul`.
- `pavonis_sib1_trace_pdcch_summary_interval()` calls `getenv` and `strtoul`.

That common SIB1 trace path is enabled in all selected runs, including
high/phase-locked and early-pass runs, so it is not a class discriminator in
this dataset. It remains a general hot-path cleanup target if source edits are
approved, but it is not the reason CP1979 differs from CP1972.

## Conclusion

CP1987 prevents over-attribution:

- Candidate trace is a real observer risk from CP1986 and should stay off for
  supply-class RF, but it cannot explain CP1979 because CP1979 had it disabled.
- CP1978 sync-field instrumentation is not sufficient to explain the recurring
  low/scattered class because multiple pre-CP1978 runs are low/scattered.
- The trace/env matrix does not identify a single UE-side instrumentation knob
  that explains all low/scattered runs.
- The active model remains a recurring SI supply/coherence state with three
  observed classes: early-pass, high/phase-locked, and low/scattered.
