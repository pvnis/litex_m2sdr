## UE-Side Meaning of `max_epre_slot`

`pavonis_sib1_trace_pdcch_summary()` stores `max_epre_slot` and
`max_corr_slot` as the absolute `dl_slot_cfg.idx` of the strongest measured
SI-RNTI PDCCH candidate seen inside one 200-sample summary interval.

Important details:

- The summary function returns immediately when `n_dl > 0`, so aggregate
  summary rows exclude direct successful SI DCI decode slots.
- The slot value is not a candidate index and is not reduced modulo 160 in the
  log. CP1990's modulo analysis is post-processing.
- `cc_worker::set_tti()` sets `dl_slot_cfg.idx = tti`.
- In `decode_pdcch_dl()`, SI tracing is only reached when MAC/PHY asks the UE
  to search SI-RNTI in that slot.
- The direct per-slot trace uses `sif = dl_slot_cfg.idx % 20`, but the frozen
  Band 3 config uses `common_scs: 15`, so the absolute slot is authoritative;
  `%20` spans two 10-slot 15 kHz frames in this run.
- `ue_dl_nr_find_dci_ncce()` stores each candidate measurement in
  `ue_dl.pdcch_info[]` before EPRE/correlation threshold rejection, so the
  summary can be dominated by rejected measured candidates rather than decoded
  DCI.

Conclusion: `max_epre_slot` is a UE-side searched-slot measurement provenance
field. It says where the strongest candidate-level PDCCH DMRS EPRE appeared
among searched SI-RNTI slots, not where the gNB definitely scheduled SIB1 and
not which candidate within the slot won.

## gNB SIB1 Occasion Mapping

The frozen generated YAMLs are byte-identical for the relevant parameters and
contain no explicit SI/SIB1 occasion override:

```yaml
cell_cfg:
  dl_arfcn: 368500
  band: 3
  channel_bandwidth_MHz: 10
  common_scs: 15
  pci: 1
```

Runtime/runbook overrides for `PAVONIS_GNB_CORESET0_INDEX`,
`PAVONIS_GNB_SS0_INDEX`, `PAVONIS_GNB_MAX_CORESET0_DURATION`,
`PAVONIS_GNB_FIXED_SIB1_MCS`, and `PAVONIS_GNB_SIB1_DCI_AGGR_LEV` are empty in
the CP1972 sequence/logs, so source defaults apply.

Relevant defaults/source behavior:

- `cell_config_builder_params` defaults `ss0_index = 0`.
- The SI expert config defaults `sib1_mcs_index = 5`,
  `sib1_dci_aggr_lev = n4`, and `sib1_retx_period = ms160`.
- `sib1_scheduler.cpp` has `sib1_newtx_period{160}` ms and computes
  `sib1_rtx_period = max(ssb_period, expert_cfg.sib1_retx_period)`.
- For each active SSB beam it explicitly uses
  `precompute_type0_pdcch_css_n0_plus_1(...)`.
- The scheduler comment says this implementation uses `n0 + 1` to avoid SSB
  collision for this small-bandwidth SIB1 allocation.
- The Type0 helper with FR1 `searchSpaceZero=0` uses table entry `O=0`,
  `M=1`, start symbol `0`; for SCS 15 and SSB index 0 this gives `n0=0`, so
  the gNB SIB1 Type0-PDCCH phase is `n0 + 1 = slot 1`.
- The source also has a separate CSI helper hard-coded to avoid SIB1 at
  `slot_offset % 160 == 1`, matching the scheduler-derived phase.

Conclusion: for the frozen 15 kHz Band 3 config, the expected SIB1 scheduled
phase is `slot % 160 == 1`.

## Interpretation of CP1990 Families

The high/phase-locked class matches the source-derived scheduled SIB1 phase:

```text
max_epre_slot % 160 == 1
```

The low/scattered class does not match a known gNB SIB1 occasion. Its dominant
families are structured but alternate:

```text
max_epre_slot % 10  == 3
max_epre_slot % 20  == 13
max_epre_slot % 160 ~= 103/113/133/143
```

Because `max_epre_slot` records the strongest rejected-or-accepted candidate
measurement among searched SI-RNTI slots, the low family is best interpreted as
a structured alternate UE search/measurement phase with low EPRE, not as proof
that the gNB moved or stopped SIB1. It also is not random summary corruption:
CP1990's entropy and bucket structure show a repeatable alternate phase family.
