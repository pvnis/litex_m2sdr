# CP1997 No-RF SI-PDCCH Correlation-Gate Source Audit

Date: [date-redacted] Europe/Zurich

## Scope

Continue from CP1996 without RF, rebuilds, deploys, source edits, or gateware
changes. CP1996 showed the active separator is scheduled-phase SI-PDCCH
correlation: early-pass direct-decode rows are `0.623..0.668`, while
high/no-SIB1 scheduled rows top out at `0.458..0.464`.

This checkpoint audits the srsUE SI-PDCCH direct/summary trace path and the
PDCCH candidate gate to determine whether the high/no-SIB1 rows are failing
before or after DCI decode and what diagnostics already exist.

## Source Findings

### Trace Path

`srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`:

- Lines `145-220`: `pavonis_sib1_trace_pdcch_summary()` aggregates only
  no-decode SI-RNTI attempts. It returns immediately when `n_dl > 0`, so
  early-pass runs can decode SIB1 before any 200-sample summary appears.
- Lines `391-470`: for SI-RNTI, the worker computes `max_epre` and `max_corr`
  over `ue_dl.pdcch_info[]`, prints a direct `si_pdcch` trace only when
  `n_dl > 0`, optionally prints candidate-level details through
  `PAVONIS_SRSUE_SI_CANDIDATE_TRACE`, and then feeds the aggregate summary.
- Lines `420-460`: existing candidate trace can print per-candidate
  `L`, `ncce`, `coreset`, `format`, `bits`, `epre`, `rsrp`, `corr`, and
  `crc`.

The summary and direct event therefore measure the same candidate list, but
represent mutually exclusive states: direct decode emits when `n_dl > 0`;
summary persists when all candidates fail.

### PDCCH Candidate Gate

`srsRAN_4G/lib/src/phy/ue/ue_dl_nr.c`:

- Lines `25-26`: defaults are `UE_DL_NR_PDCCH_CORR_DEFAULT_THR=0.5f` and
  `UE_DL_NR_PDCCH_EPRE_DEFAULT_THR=-80.0f`.
- Lines `73-81`: if no normal custom threshold is passed, the UE DL object
  uses those defaults.
- Lines `258-290`: each candidate is measured first, then discarded before
  PDCCH decode if EPRE is below threshold or `norm_corr < pdcch_dmrs_corr_thr`.
- Lines `293-316`: only candidates that pass those gates get channel estimates,
  PDCCH decode, and saved CRC result.

`srsRAN_4G/lib/include/srsran/interfaces/ue_nr_interfaces.h` leaves the
PDCCH thresholds unset in the NR PHY args constructor; `0.0` is not a normal
float, so `srsran_ue_dl_nr_init()` selects the `0.5` / `-80 dBfs` defaults.

`srsRAN_4G/lib/include/srsran/phy/ch_estimation/dmrs_pdcch.h` shows the stored
candidate measurement fields are `rsrp`, `rsrp_dBfs`, `epre`, `epre_dBfs`,
`norm_corr`, `cfo_hz`, and `sync_error_us`. The current candidate trace prints
only EPRE/RSRP/corr/CRC, not `cfo_hz`, `sync_error_us`, or the active
thresholds.

## Interpretation

CP1997 explains the CP1996 numeric separator:

- Early-pass rows (`max_corr 0.623..0.668`) are above the default
  `pdcch_dmrs_corr_thr=0.5`, so at least one SI-RNTI candidate passes the
  predecode gate and reaches PDCCH decode.
- High/no-SIB1 rows (`max_corr 0.458..0.464`) are below `0.5`, so every
  SI-RNTI candidate is discarded before PDCCH decode. These are not SI-PDCCH
  CRC failures; they are predecode DMRS-correlation-gate failures.
- EPRE is far above the default `-80 dBfs` threshold in the high/no-SIB1 class,
  so the active gate is correlation, not energy.

This moves the immediate blocker from generic "SI-PDCCH decodability" to a
specific predecode DMRS correlation margin at the scheduled SIB1 phase.

## Diagnostic Options

Existing no-source-change candidate trace can expose the per-candidate
`L/ncce/bits/EPRE/RSRP/corr/CRC` values for high/no-SIB1 rows if enabled with a
threshold near the observed class, for example `PAVONIS_SRSUE_SI_CANDIDATE_TRACE=1`
and `PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR=0.40`.

Caveat: CP1986 already showed the current candidate-trace guard repeatedly
parses env vars on the SI-PDCCH worker path even when no row prints. That makes
it an observer-risk RF diagnostic unless cached/event-triggered first. It is
still safe to reason about from source, but should not be casually enabled in
RF as a "low-impact" trace without accepting that risk.

The source has additional potentially useful fields already measured but not
currently printed by the candidate trace:

- `srsran_dmrs_pdcch_measure_t.cfo_hz`
- `srsran_dmrs_pdcch_measure_t.sync_error_us`
- active thresholds `pdcch_dmrs_corr_thr` and `pdcch_dmrs_epre_thr`

PDCCH EVM exists in the PDCCH decoder result when PDCCH EVM measurement is
enabled, but srsUE does not enable UE PDCCH EVM in the normal NR PHY args path.
Also, EVM is only available after passing the correlation gate and running
decode, so it cannot explain the high/no-SIB1 predecode rejects unless the gate
is relaxed for a diagnostic branch.

## Next

Do not lower the PDCCH corr threshold as a ladder fix without an explicit
diagnostic plan; the current issue may be real coherence/EVM loss, and lowering
the gate could promote false candidates.

Next no-RF step, if source edits are approved later, should be a default-off,
cached/env-once, low-rate SI-PDCCH candidate trace that adds the active
thresholds plus candidate `cfo_hz` and `sync_error_us`, with strict row caps and
no per-sample work. If RF is approved without source edits, the existing
candidate trace can be run once as an observer-risk discriminator, but it
should be treated as perturbative under the CP1986 lesson.
