# CP1998 No-RF Cached SI-PDCCH Candidate Trace Plan

Date: [date-redacted] Europe/Zurich

## Scope

No RF, rebuilds, deploys, source edits, wrapper edits, or gateware changes were
made in this checkpoint.

CP1995 already spent the user-approved pre-CP1978 UE RF A/B and landed in the
high/phase-locked no-SIB1 class, not the low/scattered class, so the conditional
CP1945-style independent bladeRF scheduled-phase IQ capture was correctly not
run. CP1996/CP1997 then narrowed the active blocker to scheduled-phase
SI-PDCCH DMRS correlation: high/no-SIB1 rows have normal EPRE but top out at
`0.458..0.464`, below the srsUE default `pdcch_dmrs_corr_thr=0.5` predecode
gate.

This checkpoint turns CP1997's source audit into a precise implementation and
run plan for the next approval decision.

## Existing Surfaces

`srsRAN_4G/srsue/src/phy/nr/cc_worker.cc` already has the candidate trace hook:

- `pavonis_si_candidate_trace_enabled()`
- `pavonis_si_candidate_trace_limit()`
- `pavonis_si_candidate_trace_min_corr()`
- `pavonis_si_candidate_trace_take()`

The current guard is observer-risk when enabled because it calls `getenv()` and
numeric parsers on the SI-PDCCH worker path for every eligible opportunity. The
existing print row includes candidate `L`, `ncce`, `coreset`, `format`, `bits`,
`EPRE`, `RSRP`, `corr`, and `CRC`, but omits fields already measured by the
DMRS estimator:

- `srsran_dmrs_pdcch_measure_t.cfo_hz`
- `srsran_dmrs_pdcch_measure_t.sync_error_us`

The active thresholds are stored in the UE DL object:

- `ue_dl.pdcch_dmrs_corr_thr`
- `ue_dl.pdcch_dmrs_epre_thr`

The Stage 6 wrapper/helper already forward and log the existing environment
variables:

- `PAVONIS_SRSUE_SI_CANDIDATE_TRACE`
- `PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT`
- `PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR`

Therefore the preferred patch can avoid new runner/helper plumbing by extending
only the enabled trace row and caching the existing settings.

## Recommended Patch If Source Edits Are Approved

Implement a small cached configuration in `cc_worker.cc`, initialized once on
first use:

```text
enabled = env(PAVONIS_SRSUE_SI_CANDIDATE_TRACE)
limit   = env(PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT, default 200)
min_corr = env(PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR, default 0.40)
```

Then make `pavonis_si_candidate_trace_take()` read only cached values. With
`TRACE=0`, the runtime path should be a cached boolean check and return. With
`TRACE=1`, retain the existing strict row cap and min-correlation filter.

Extend the existing candidate trace row when enabled:

- Add row-level `corr_thr=...` and `epre_thr=...`.
- For each candidate, add `cand%u_cfo_hz=...` and
  `cand%u_sync_error_us=...`.

Do not add per-sample work. Do not enable PDCCH EVM in this patch; EVM is only
available after the correlation gate and would require a separate diagnostic
branch if the gate is intentionally relaxed.

## Build And RF Gate If Approved Later

Patch/build checkpoint:

- Local `srsue` build smoke.
- [host-redacted] `srsue` rebuild/deploy only after explicit approval.
- `strings` proof for the new fields and cached helper naming.
- No RF in the patch checkpoint unless separately approved.

First RF use after patch approval:

```text
PAVONIS_SRSUE_SI_CANDIDATE_TRACE=1
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT=200
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR=0.40
```

Keep the frozen CP1972/CP1979/CP1995 supply-control shape otherwise unchanged:
no RX append, no source/gateware changes beyond the approved trace patch, and
candidate trace off again after the diagnostic run unless explicitly kept.

Judge the run first by supply class:

- Early-pass: direct SI decode, SIB1, and Msg1 return.
- High/phase-locked: scheduled EPRE remains high, dominant `slot % 160 == 1`,
  but candidate corr stays below `0.5`.
- Low/scattered: high EPRE disappears and strongest buckets move to the known
  alternate phase families.

For a high/no-SIB1 run, use the trace to determine whether a single candidate
is consistently near the gate, whether candidate `cfo_hz` or `sync_error_us`
separates failed rows from early-pass rows, and whether the active thresholds
match CP1997's expected `0.5` / `-80 dBfs`.

## Alternative If RF Is Approved Without Source Edits

discriminator with the same `LIMIT=200`, `MIN_CORR=0.40` shape. That would cost
no rebuild, but it reintroduces the CP1986 hot-path env-parse risk and should
not be interpreted as a clean supply baseline.
