## Recommended Exact Patch Shape

Keep the patch inside the anonymous namespace in `cc_worker.cc`.

Add a small config object and initialize it once:

```text
struct pavonis_si_candidate_trace_cfg_t {
  bool enabled;
  uint32_t limit;
  float min_corr;
};

const pavonis_si_candidate_trace_cfg_t& pavonis_si_candidate_trace_cfg()
```

The initializer should read the existing env variables exactly once:

```text
PAVONIS_SRSUE_SI_CANDIDATE_TRACE
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT
PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR
```

Then update `pavonis_si_candidate_trace_take()` to use only cached fields:

```text
const auto& cfg = pavonis_si_candidate_trace_cfg();
if (!cfg.enabled) return false;
if (count >= cfg.limit) return false;
if (n_dl <= 0 && max_corr < cfg.min_corr) return false;
```

This preserves the current default-off behavior, the row cap, and the
`n_dl > 0` always-trace rule, while removing repeated env lookup/parsing from
the SI-PDCCH worker path.

Extend the row-level print at `cc_worker.cc:421-435` with:

```text
corr_thr=%.6f epre_thr=%.3f
```

using:

```text
ue_dl.pdcch_dmrs_corr_thr
ue_dl.pdcch_dmrs_epre_thr
```

Extend the per-candidate print at `cc_worker.cc:438-458` with:

```text
cand%u_cfo_hz=%.3f cand%u_sync_error_us=%.6f
```

using:

```text
info->measure.cfo_hz
info->measure.sync_error_us
```

Do not change `ue_dl_nr.c` thresholds, do not relax the PDCCH gate, and do not
enable PDCCH EVM in this branch.
