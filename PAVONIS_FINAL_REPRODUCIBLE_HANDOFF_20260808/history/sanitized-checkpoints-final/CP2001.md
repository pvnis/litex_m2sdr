# CP2001 No-RF PDCCH Sync-Error Precompensation Audit

## Scope

No RF, rebuilds, deploys, source edits, wrapper edits, or gateware changes were
made in this checkpoint.

CP2000 showed that SI-PDCCH `norm_corr` is a coherent DMRS-pilot-quality metric
and found that candidate `cfo_hz` must not be trusted until the CFO store bug is
fixed. CP2001 audits the helper behind `sync_error_us` and the precompensation
step that happens before `norm_corr` is computed.

## Vector Helper Semantics

`srsRAN_4G/lib/src/phy/utils/vector_simd.c`:

- Lines `1776-1818`: `srsran_vec_estimate_frequency_simd()` accumulates
  adjacent-sample conjugate products and returns `-arg(sum)/(2*pi)`, a
  normalized phase slope per sample.
- Lines `1723-1774`: `srsran_vec_apply_cfo_simd()` multiplies by
  `exp(j*2*pi*cfo*n)`.

The vector unit test confirms the sign convention:

- `srsRAN_4G/lib/src/phy/utils/test/vector_test.c` lines `795-804` builds
  `x[i] = exp(-j*2*pi*i*freq_gold)` and expects
  `srsran_vec_estimate_frequency(x)` to return `+freq_gold`.

So in the channel-estimator context, the returned value is a normalized
frequency-domain phase slope. Applying that same value with
`srsran_vec_apply_cfo()` cancels the negative pilot phase ramp.

## PDCCH Measurement Consequence

`srsRAN_4G/lib/src/phy/ch_estimation/dmrs_pdcch.c`:

- Lines `53-55`: `DMRS_PDCCH_SYNC_PRECOMPENSATE_MEAS` is enabled.
- Lines `460-467`: each candidate symbol estimates `tmp_sync_err` over the
  candidate DMRS pilots and immediately applies that correction before
  correlation.
- Lines `475-481`: only after that correction does the estimator form coherent
  `corr[l]`, RSRP, and EPRE.
- Lines `504-505`: `sync_error_us` is derived from the accumulated normalized
  slope using the DMRS pilot spacing of four subcarriers and the numerology SCS.

Neighboring estimators use the same helper as a delay/timing-slope estimator:

- `dmrs_sch.c` lines `815-856` estimates `sync_err`, converts it to
  `delay_us = sync_err / (dmrs_stride * SCS)`, then precompensates pilots.
- `csi_rs.c` lines `659-664` estimates average delay and precompensates before
  RSRP measurement.
- `dmrs_pbch.c` lines `166-178` uses the helper to compute PBCH DMRS delay and
  correct the SSB grid.

## Interpretation For The Next Trace

`sync_error_us` is useful, but it is not an uncorrected failure metric. It tells
us the average frequency-domain timing slope that the estimator saw and already
removed before measuring `norm_corr`.

Therefore:

- If high/no-SIB1 rows show much larger or unstable `sync_error_us` than
  early-pass rows, the SI-PDCCH corr deficit may be driven by timing slope or
  by the estimator fighting a run-to-run timing/ramp state.
- If high/no-SIB1 rows show similar `sync_error_us` to early-pass rows but still
  cap at `norm_corr ~= 0.46`, the residual impairment is not a simple average
  frequency-domain timing slope. It would point more toward non-linear phase or
  amplitude distortion across the candidate pilots, wrong candidate/DMRS
  sequence or CCE mapping in that run, inter-symbol phase drift, phase noise, or
  other coherence/EVM loss that survives the built-in slope precompensation.
- If the CFO store bug is fixed and candidate `cfo_hz` is large in high/no-SIB1
  but not early-pass, that would indicate inter-symbol phase rotation between
  CORESET symbols rather than within-symbol frequency-domain slope.

This sharpens the future RF diagnostic: compare early-pass versus high/no-SIB1
candidate rows on `norm_corr`, `sync_error_us`, and fixed `cfo_hz`; do not treat
`sync_error_us` alone as the cause unless it separates the classes.
