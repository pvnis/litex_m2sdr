# CP2003 No-RF PDCCH Correlation Threshold Config Audit

Date: [date-redacted] Europe/Zurich

## Scope

No RF, rebuilds, deploys, source edits, wrapper edits, or gateware changes were
made in this checkpoint.

CP1996/CP1997 identified the active gate: high/no-SIB1 SI-PDCCH candidates
have normal EPRE but `norm_corr` only reaches `0.458..0.464`, below the default
`0.5` PDCCH DMRS correlation threshold. CP2003 checks whether this threshold is
configurable in the normal srsUE path without a source patch.

## Source Findings

`srsRAN_4G/lib/src/phy/ue/ue_dl_nr.c`:

- Lines `25-26`: compiled defaults are
  `UE_DL_NR_PDCCH_CORR_DEFAULT_THR=0.5f` and
  `UE_DL_NR_PDCCH_EPRE_DEFAULT_THR=-80.0f`.
- Lines `73-81`: `srsran_ue_dl_nr_init()` uses caller-provided thresholds only
  when `isnormal(args->pdcch_dmrs_corr_thr)` or
  `isnormal(args->pdcch_dmrs_epre_thr)` is true; otherwise it applies the
  compiled defaults.

`srsRAN_4G/lib/include/srsran/interfaces/ue_nr_interfaces.h`:

- Lines `214-225`: `phy_args_nr_t` contains `srsran_ue_dl_nr_args_t dl`.
- Lines `235-245`: the constructor initializes antenna count, PRB/layer
  limits, PDSCH EVM/time flags, SIMD, and decoder iterations, but does not set
  `dl.pdcch_dmrs_corr_thr` or `dl.pdcch_dmrs_epre_thr`.

`srsRAN_4G/srsue/src/main.cc`:

- Lines `130-144` expose NR carrier/config options.
- Lines `175-199` expose log options.
- There is no CLI/config option for `pdcch_dmrs_corr_thr` or
  `pdcch_dmrs_epre_thr`.

`srsRAN_4G/srsue/src/ue.cc`:

- Lines `86-94`: the normal srsUE construction path creates
  `phy_args_nr_t phy_args_nr = {}` and fills generic NR PHY/radio/log fields,
  but does not assign PDCCH DMRS thresholds.
- Lines `99-110`: SA mode passes that `phy_args_nr` into `phy_nr_sa::init()`.

`srsRAN_4G/srsue/src/phy/nr/worker_pool.cc` and
`srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`:

- `worker_pool.cc` lines `50-71` copies general NR args and PRB limits, but
  does not set the PDCCH thresholds.
- `cc_worker.cc` lines `233-251` passes `phy.args.dl` directly into
  `srsran_ue_dl_nr_init()`.

## Conclusion

There is no existing normal srsUE config or CLI knob for the SI-PDCCH DMRS corr
gate. The fields exist only in the low-level UE DL args structure, and the
normal SA path leaves them zero/unset, causing `ue_dl_nr.c` to select the
compiled `0.5` / `-80 dBfs` defaults.

Therefore a threshold-relaxation diagnostic would require a source edit or a
new env/config hook. It is not a no-rebuild alternative to the cached trace.

## Frontier

Do not spend RF looking for a config-only PDCCH threshold override; none is
present in the normal srsUE path. The next approved branch remains:

1. Fix the PDCCH DMRS `cfo_hz` store.
2. Cache and extend the existing row-capped SI-PDCCH candidate trace.
3. Run one bounded RF diagnostic on the frozen supply-control shape.

Only after that trace names the failure mode should a separate threshold-relax
experiment be considered. Lowering the `0.5` gate before seeing candidate
identity, `sync_error_us`, and fixed `cfo_hz` risks promoting false SI
candidates without explaining the coherence loss.
