# CP2006 No-RF PDCCH EVM Availability Audit

Date: [date-redacted] Europe/Zurich

## Scope

No RF, rebuilds, deploys, source edits, wrapper edits, or gateware changes were
made in this checkpoint.

CP2005 clarified that `cand_crc=0` is not a real CRC miss when a candidate is
rejected before decode. CP2006 audits whether PDCCH EVM can help explain the
current high/no-SIB1 class or should be included in the first approved
candidate trace patch.

## Source Findings

`srsRAN_4G/lib/include/srsran/phy/phch/pdcch_nr.h`:

- Lines `47-50`: PDCCH init args include `measure_evm`.
- Lines `70-84`: the decoder object has `evm_buffer`, and the result has
  `evm` and `crc`.

`srsRAN_4G/lib/src/phy/phch/pdcch_nr.c`:

- Lines `189-192`: the modem table is byte-configured only when
  `args->measure_evm` is true.
- Lines `245-247`: the EVM buffer is allocated only when `args->measure_evm`
  is true.
- Lines `630-635`: `res->evm` is written only inside
  `srsran_pdcch_nr_decode()`. If no EVM buffer exists, decode writes `NAN`.
- Lines `729-734`: PDCCH info prints EVM only when the EVM buffer exists and a
  decode result is present.

`srsRAN_4G/lib/include/srsran/interfaces/ue_nr_interfaces.h`:

- Lines `235-245`: normal `phy_args_nr_t` enables PDSCH EVM, but does not set
  `dl.pdcch.measure_evm`.

`srsRAN_4G/lib/src/phy/ue/ue_dl_nr.c`:

- Lines `84-89`: `srsran_ue_dl_nr_init()` passes `args->pdcch` into
  `srsran_pdcch_nr_init_rx()`.
- Lines `265-290`: invalid measurement, low EPRE, or low corr return before
  PDCCH decode.
- Lines `293-303`: PDCCH decode runs only after those predecode gates pass.
- Lines `315-316`: the decode result is stored only after decode returns.

## Interpretation

PDCCH EVM is not available for the active high/no-SIB1 failure mode:

- The normal srsUE NR args do not enable PDCCH EVM.
- Even if enabled later, EVM is produced only inside PDCCH decode.
- High/no-SIB1 candidates currently top out at `norm_corr ~= 0.458..0.464`,
  below the active `0.5` gate, so they return before decode and cannot produce
  PDCCH EVM.

Therefore PDCCH EVM cannot explain the current predecode SI-PDCCH correlation
gate failure without a separate diagnostic branch that either enables PDCCH EVM
and also relaxes/bypasses the corr gate, or records deeper equalized-symbol
data. That is not the first safe rung.

## Patch Guidance

The first approved candidate-trace patch should not add PDCCH EVM as a primary
field. It should stay focused on metadata available before decode:

- active EPRE/corr thresholds
- candidate identity
- EPRE/RSRP/corr
- fixed `cfo_hz`
- `sync_error_us`
- unambiguous decode-attempted interpretation

If a future run proves candidates clear EPRE/corr gates but fail CRC, or if the
user approves a threshold-relax branch, PDCCH EVM can become a follow-up
diagnostic. Until then, it is outside the current blocker.

## Frontier

The next approved branch remains the same: fix the PDCCH DMRS `cfo_hz` store,
cache and extend the row-capped SI-PDCCH candidate trace, and run one bounded RF
diagnostic on the frozen supply-control shape.
