## Existing Summary Parser Gap

The same wrapper embeds its summary parser at lines `601+`.

Relevant parser behavior:

- Lines `764-785`: finds `srsue.stdout.log` and reads it into `ue_text`.
- Lines `863-917`: populates the `ue` summary object with cell/SIB1/RACH/RAR
  event counts.
- Lines `867-870`: counts `PAVONIS_SRSUE_SIB1_TRACE`,
  `event=si_pdcch`, and `event=si_pdcch_summary`.
- There is no parser branch for
  `PAVONIS_SRSUE_SI_CANDIDATE_TRACE event=si_pdcch_candidates`.

Therefore the next RF run could generate exactly the diagnostic candidate rows
we need, but the current summary JSON would not compact their contents. Future
analysis would be forced back to raw `srsue.stdout.log`, which violates the
current context-hygiene rule and repeats the raw-log pressure CP2002 tried to
avoid.

## Required Summary Fields For The Approved Trace Branch

When source/wrapper edits are approved, the wrapper summary should be extended
before or with the first candidate-trace RF run. It should parse only the
row-capped candidate trace lines and emit compact derived fields, for example:

- `si_candidate_trace_count`
- `si_candidate_trace_min_corr_floor`
- row-level `max_corr`/`max_epre` min/mean/max
- `corr_thr` and `epre_thr` values seen
- `decode_attempted_count`, `crc_ok_count`, and true decoded `crc_ko_count`
- best-candidate identity histogram by `(L, ncce, format, bits)`
- best-candidate `corr`, `epre`, `rsrp`, fixed `cfo_hz`, and `sync_error_us`
  summaries
- number of rows where best candidate is AL4 versus AL8
- a bounded sample of first/last few parsed best-candidate objects, not raw log
  lines

Parser interpretation must follow CP2005: `crc=0` is only a true decoded CRC
miss when the row proves the candidate cleared active EPRE/corr gates or an
explicit `decode_attempted` field is present.

## Frontier

The approved trace branch should include both sides of the diagnostic:

1. Source: fix PDCCH DMRS `cfo_hz`, cache and extend the row-capped candidate
   trace, and add/derive unambiguous decode-attempted status.
2. Wrapper summary: compact candidate trace rows into summary JSON so the
   checkpoint report can be written from summaries, not raw UE logs.
3. RF: run one bounded frozen-shape diagnostic and judge supply class plus
   candidate identity, `sync_error_us`, and fixed `cfo_hz`.

Until that approval, do not run RF with the existing candidate trace just to
produce raw rows; the parser gap would make the result unnecessarily expensive
to analyze.
