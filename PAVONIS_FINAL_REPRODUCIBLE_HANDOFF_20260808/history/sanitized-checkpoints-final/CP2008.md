## Patch Details

`cc_worker.cc` now uses a process-local static config:

- `PAVONIS_SRSUE_SI_CANDIDATE_TRACE`
- `PAVONIS_SRSUE_SI_CANDIDATE_TRACE_LIMIT`
- `PAVONIS_SRSUE_SI_CANDIDATE_TRACE_MIN_CORR`

Those env vars are read only inside `pavonis_si_candidate_trace_config()`'s
static initializer. The candidate hot path calls
`pavonis_si_candidate_trace_take(config, max_corr, n_dl)`, which contains no
`getenv`. This keeps the disabled path from repeating per-call env parsing.

The trace row now includes active thresholds and row settings:

```text
corr_thr=%.6f epre_thr=%.3f trace_limit=%u trace_min_corr=%.6f
```

Each candidate now includes:

```text
cand%u_cfo_hz=%.3f
cand%u_sync_error_us=%.6f
cand%u_decode_attempted=%u
```

`cand%u_decode_attempted` is derived from the same active EPRE/corr gates used
by the decoder:

```text
epre_dBfs >= ue_dl.pdcch_dmrs_epre_thr &&
norm_corr >= ue_dl.pdcch_dmrs_corr_thr
```

`dmrs_pdcch.c` now stores the accumulated PDCCH DMRS CFO:

```text
measure->cfo_hz = cfo_avg_Hz / (float)(q->coreset.duration - 1);
```

No threshold values were changed. No PDCCH EVM instrumentation was added.
