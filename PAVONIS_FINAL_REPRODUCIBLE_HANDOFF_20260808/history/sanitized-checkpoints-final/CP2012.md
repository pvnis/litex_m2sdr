## Scope

No RF was run. No source, wrapper, gNB, Soapy, M2SDR, bladeRF, gateware, or
remote deploy change was made. The only build action was a local build of the
existing `ue_dl_nr_file_test` target so the CP2011 independent bladeRF IQ file

bladeRF DL IQ capture after CP2010's low/scattered srsUE SI-PDCCH result. CP2012
checks whether CP2011 was only an SSB/PBCH proof, or whether the same IQ file

## Method

Using the decoded MIB, I derived SIB1 opportunities at `SFN % 16 == 0`,
slot `1`, then cut one-slot CF32 windows from the CP2011 SC16 capture at six
predicted opportunities:

```text
SFN 672 sample 1054981
SFN 688 sample 2898181
SFN 704 sample 4741381
SFN 720 sample 6584581
SFN 736 sample 8427781
SFN 752 sample 10270981
```

For each opportunity I swept sample deltas:

```text
-2304, -1728, -1152, -576, 0, +576, +1152, +1728, +2304
```

Each snippet was run through `ue_dl_nr_file_test` in SI/common0 mode with PCI 1,
52 PRB, CORESET0 index 0, and ARFCNs `368500/367930`. The strongest snippet
(`SFN 688`, delta `-1728`) was then used for three no-RF follow-up sweeps:

- slot index sweep from `6881 - 80` through `6881 + 80`
- CFO correction sweep from `-8000` through `+8000 Hz` in `250 Hz` steps
- CORESET0 index sweep from `0` through `15`

## Interpretation

CP2012 strengthens CP2011: the independent bladeRF IQ capture was not only an
SSB/PBCH proof. At the MIB-derived SIB1 opportunities, the IQ file contains
repeatable, high-EPRE, high-correlation CORESET-like energy at the same
`-1728` sample offset across six `160 ms`-spaced SI periods.

However, this offline `ue_dl_nr_file_test` path still does not decode SI DCI or
PDSCH under timing, slot-index, CFO, or CORESET0-index sweeps. Therefore the
correct conclusion is not "SIB1 decoded in the CP2011 IQ"; it is:

```text
Scheduled SI-phase energy is present in the independent IQ path, but the
offline file-test path cannot yet turn that energy into a valid SI DCI/PDSCH.
```

Important caveat: `ue_dl_nr_file_test` uses a broad candidate set. Its strongest
reported rows are often `al=0`/AL1-style candidates, while the live srsUE
SearchSpace0 audit in CP2004 identified common-0 candidates as AL4/AL8. Thus
the high broad-candidate correlation is evidence of SI-phase CORESET-like
energy, not proof that the exact live SearchSpace0 candidate decoded or even
that the best broad candidate is a valid scheduled SI candidate.

## Frontier

Do not rerun CP2010, CP2011, or CP2012 unchanged. The next no-RF branch should
compare the exact live srsUE SI-PDCCH candidate/config path against the offline
file-test assumptions, preferably by reusing the same CP2011 snippets with the
exact common-0/SearchSpace0 candidate generation and decode path that `srsue`
uses. More RF should wait until that no-RF parity question is answered.
