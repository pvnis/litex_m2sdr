## Scope

No RF, remote deploy, gNB, Soapy, M2SDR, bladeRF, wrapper, or gateware change
was made. This checkpoint adds a local-only test mode to
`ue_dl_nr_file_test.cc`, builds the local file-test binary, and replays the
existing CP2012 CF32 snippets with a live-style SearchSpace0 candidate setup.

The local source edit is limited to:

```text
srsRAN_4G/lib/src/phy/ue/test/ue_dl_nr_file_test.cc
```

The new `-X` mode applies, only for SI/common0:

```text
format: DCI 1_0 only
nof_candidates[0]=0
nof_candidates[1]=0
nof_candidates[2]=4  # AL4
nof_candidates[3]=2  # AL8
nof_candidates[4]=0
monitor_common_0_0=false
monitor_0_0_and_1_0=false
```

This matches the live SearchSpace0 candidate counts and format from
CP1992/CP1993/CP2004 while still using the file-test CORESET0 derivation from
the CP2012 snippet setup. It is therefore stronger than CP2014's log projection
but still not a full live `phy_cfg_nr_t` object replay.

## Interpretation

CP2015 answers the CP2014 frontier. When the CP2011/CP2012 snippets are replayed
with the live SearchSpace0 candidate count and `DCI 1_0`-only format, the result
still has:

- no SI DCI;
- no PDSCH;
- no CRC-OK PDCCH rows;
- meaningful correlation only at the known `-1728` sample offset;
- CRC KO on every live-style AL4 `ncce=0` decode attempt.

This closes the "broad file-test candidate mismatch hides a valid SI DCI"
branch for the existing CP2011/CP2012 snippets. The remaining gap is not that
the offline probe was only looking at AL1/AL2; the live-style candidate class
itself is either below-gate or CRC-negative.

## Frontier

Do not rerun CP2010-CP2015 unchanged. The next no-RF rung should inspect the
AL4 `ncce=0` CRC-KO class itself: DCI bit/CRC scrambling assumptions, SI-RNTI
masking, CORESET0/time-reference exactness, and whether the `-1728` sample
offset is still symbol-boundary correct enough for PDCCH payload decode even
when DMRS correlation clears the gate. RF should stay parked until that CRC-KO
semantic branch produces a specific testable difference.
