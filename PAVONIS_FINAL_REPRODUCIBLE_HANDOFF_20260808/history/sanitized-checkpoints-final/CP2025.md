# CHECKPOINT [date-redacted] - No-RF SI PDSCH power-sign translator unit proof

Date: [date-redacted]

## Scope

No RF. No remote deploy. No gNB rebuild. No gateware work.

This checkpoint adds a focused local unit proof for the CP2021
`PAVONIS_GNB_SI_PDSCH_POWER_SIGN_COMPAT` branch. CP2023 proved the env reached
live gNB runtime, but CP2024 showed that run never reached SI DCI/PDSCH decode.
This test proves the translator output itself for SI-RNTI and non-SI RNTIs in
separate env-off/env-on test processes.

Changes:

- Added a small test-side env parser for
  `PAVONIS_GNB_SI_PDSCH_POWER_SIGN_COMPAT`.
- Changed the generic randomized UE-RNTI distribution from `1..65535` to
  `1..65534` so it cannot accidentally exercise the SI-RNTI special case.
- Added `convert_profile_nr_pdsch_for_rnti(rnti_t)` to construct a deterministic
  profile-NR PDSCH PDU at the Pavonis SI geometry class:
  - RNTI supplied by caller
  - BWP `0..52`
  - SCS `15 kHz`
  - normal CP
  - QPSK, MCS `5`, TBS `80`
  - `num_dmrs_cdm_grps_no_data=2`
  - power profile NR `0 + dB6`
- Added `pavonis_si_rnti_power_sign_compatibility`.

The new test expects:

- Env off:
  - SI-RNTI data ratio `+6 dB`
  - SI-RNTI DMRS ratio `+3 dB`
  - non-SI data ratio `+6 dB`
  - non-SI DMRS ratio `+3 dB`
- Env on:
  - SI-RNTI data ratio `-6 dB`
  - SI-RNTI DMRS ratio `-6 dB`
  - non-SI data ratio `+6 dB`
  - non-SI DMRS ratio `+3 dB`

This matches the intended downstream PDSCH processor convention:
`convert_dB_to_amplitude(-ratio)`.

## Interpretation

CP2025 proves the intended translator semantics locally:

- Env-off/default behavior preserves the old SI PDSCH profile-NR ratios:
  data `+6 dB`, DMRS `+3 dB`.
- Env-on changes only SI-RNTI PDSCH profile-NR ratios to `-6/-6 dB`, which the
  PDSCH processor will emit at `+6/+6 dB` amplitude relative to SSS under its
  `-ratio` convention.
- A non-SI RNTI remains unchanged at `+6/+3 dB` even when the env is enabled.

Together with CP2023's live runtime marker, this closes the no-RF question
"does the override branch actually do the intended thing?" The remaining open
question is live-RF/channel presentation under a DCI-OK SI-PDCCH window.
