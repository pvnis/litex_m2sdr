# CP2028 No-RF PBCH-to-Live-SS0 Driver Validation

Date: [date-redacted]

RF use: none.

## Scope

CP2028 removes the remaining manual step between a future CP2026 independent-IQ
capture and CP2027 offline scheduled-SI analysis. CP2027 required hand-entered
PBCH SFN and `t_offset`; CP2028 adds a driver that reads the existing PBCH
one-capture `results.json`, verifies PBCH CRC OK, extracts the MIB timing, and
invokes CP2027 automatically.

No RF, remote deploy, rebuild, gNB, Soapy, M2SDR, or bladeRF action was run.

## New Driver

`cp2028_run_live_ss0_from_pbch_result.py`

Inputs:

- `--pbch-json`: CP812/SSB one-capture `results.json`
- `--out-dir`: output directory
- optional sweep arguments forwarded to CP2027

Behavior:

- requires `pbch_crc_ok=true` unless `--allow-pbch-ko` is explicitly used
- parses `pbch_mib` for `sfn=...` and `coreset0=...`
- reads `search_t_offset`, `fs`, `raw`, `search_pci`, and raw hash
- writes `cp2028_input_manifest.json`
- runs `cp2027_live_ss0_scheduled_si_from_sc16.py`
- writes `cp2028_compact_verdict.json`

This means a future CP2026 capture can go:

```text
CP1223/CP1945 capture runner -> CP812 PBCH results.json -> CP2028 driver -> CP2027 live-SS0 TSV/JSON
```

## Frontier

CP2028 closes the no-RF plumbing gap between CP2026 capture and CP2027 analyzer.
Once RF is explicitly approved, run exactly one CP2026 independent-IQ capture.
If CP812 PBCH analysis is positive, feed its `results.json` into CP2028 and
judge the override on CP2027's DCI-OK rows:

- PDSCH CRC recovery and/or PDCCH/PDSCH-DMRS EPRE parity supports the power-sign
  fix on air.
- DCI CRC OK with the old `~ -9.4 dB` PDSCH-DMRS deficit and PDSCH CRC KO
  rejects or narrows the fix.
- PBCH-missing or no-DCI captures remain void for the SI PDSCH power-sign
  hypothesis.
