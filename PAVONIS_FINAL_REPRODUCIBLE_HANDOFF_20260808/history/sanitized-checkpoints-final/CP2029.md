# CP2029 No-RF Post-CP2026 Verdict Wrapper Validation

Date: [date-redacted]

RF use: none.

## Scope

CP2029 removes one more manual post-RF step. CP2028 can turn a PBCH
`results.json` into the CP2027 live-SS0 verdict, but the user would still need
to locate the CP1223/CP812 PBCH output for the CP2026 stamp. CP2029 adds a
stamp-based wrapper that maps the run stamp to the expected PBCH path and runs
CP2028.

No RF, remote deploy, rebuild, gNB, Soapy, M2SDR, or bladeRF action was run.

## New Wrapper

`cp2029_run_post_cp2026_verdict_from_stamp.sh`

Usage:

```bash
STAMP=<cp2026-stamp> ./cp2029_run_post_cp2026_verdict_from_stamp.sh
# or
./cp2029_run_post_cp2026_verdict_from_stamp.sh <cp2026-stamp>
```

Default PBCH JSON:

```text
$ART/cp1223_rf_pbch_offcenter_${STAMP}/results.json
```

Default output directory:

```text
$ART/cp2029_post_cp2026_live_ss0_verdict_${STAMP}
```

The wrapper records input hashes, calls `cp2028_run_live_ss0_from_pbch_result.py`,
and records the compact verdict, scheduled-SI summary, and TSV hashes. It does
not supply a default stamp; this avoids hard-coded STAMP reuse.

## Frontier

The post-RF path is now:

```text
CP2026 independent-IQ capture
-> existing CP1223/CP812 PBCH output for that STAMP
-> cp2029_run_post_cp2026_verdict_from_stamp.sh <STAMP>
-> CP2028/CP2027 compact verdict
```

Once RF is explicitly approved, run exactly one CP2026 independent-IQ capture.
If PBCH is present, run CP2029 on that stamp and judge only DCI-OK rows:

- PDSCH CRC recovery and/or PDCCH/PDSCH-DMRS EPRE parity supports the power-sign
  fix on air.
- DCI CRC OK with the old `~ -9.4 dB` PDSCH-DMRS deficit and PDSCH CRC KO
  rejects or narrows the fix.
- PBCH-missing or no-DCI captures remain void for the SI PDSCH power-sign
  hypothesis.
