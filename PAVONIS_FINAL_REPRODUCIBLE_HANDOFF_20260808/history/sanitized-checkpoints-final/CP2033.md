# Checkpoint [date-redacted]: No-RF Post-CP2031 Verdict Helper

Date: [date-redacted]

## Purpose

Prepare the post-run analysis path for the approved CP2031 RF diagnostic without
starting RF. The goal is to avoid broad artifact-tree searches and raw-log reads
after the run: pass the exact `srsue.stdout.log` path, or the exact run
directory containing it, and emit compact JSON plus a short text verdict.

## Actions

- Added `cp2033_run_post_cp2031_verdict.sh`.
- The helper is no-RF and does not invoke SSH, gNB, srsUE, radios, gateware, or
  any runner.
- Accepted inputs are intentionally narrow:
  - exact `srsue.stdout.log`
  - exact run directory containing `srsue.stdout.log` directly
- The helper calls the CP2031 parser and writes:
  - `cp2033_candidate_trace_summary.json`
  - `cp2033_candidate_trace_verdict.txt`
  - `cp2033_output_hashes.sha256`
- The text verdict includes the run class, row counts, markers, SI max corr/EPRE,
  best-candidate identity histogram, best `sync_error_us` / `cfo_hz`, and
  decode/CRC-attempt counts.

## Validation

- `bash -n cp2033_run_post_cp2031_verdict.sh`: passed.
- No-argument guard:
  - exits `2`
  - prints usage
  - states that the helper intentionally does not search broad artifact trees
- Exact-log mode on CP2010 control:
  - `candidate_trace_rows=0`
  - `si_pdcch_summary_rows=802`
  - `class_judgment=low/scattered`
  - markers all zero
  - SI max corr `0.255930`, SI max EPRE `24.225`
- Exact-run-directory mode on the same CP2010 run directory produced the same
  compact verdict.
