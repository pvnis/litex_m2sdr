# Checkpoint [date-redacted]: No-RF SI-PDSCH Phase-Ramp Recovery Sweep

Date: [date-redacted]

## Purpose

Run the requested fully offline payoff experiment: take CP2038 DCI-OK
SearchSpace0 windows and apply a per-symbol phase-ramp/CFO correction before
SI-PDSCH decode. The goal is to test whether CP2038's DCI-OK but PDSCH-CRC-KO
state is phase/coherence correctable using data already on disk.

## Instrument

Added an env-gated local analysis hook to
`srsRAN_4G/lib/src/phy/ue/test/ue_dl_nr_file_test.cc`.

The hook is default-off and only activates when
`PAVONIS_FILETEST_PDSCH_PHASE_RAMP_HZ` is set. It runs after PDCCH DCI decode
and DCI-to-PDSCH grant conversion, but before `srsran_ue_dl_nr_decode_pdsch()`.
It rotates the already-FFT'd slot grid by a constant phase per OFDM symbol:

```text
phase(l) = phase0 + 2*pi*ramp_hz*Tsym*(l - ref_symbol)
```

For this sweep the script rotated symbols `[2,14)` with `ref_symbol=2` and
`Tsym=66.6666667 us`, matching the CP2038 SI-PDSCH grant `symb=(2,13)`.

Local build:

```text
cmake --build srsRAN_4G/build-clion --target ue_dl_nr_file_test -j 8
```

The rebuild passed. No RF, gNB rebuild, live UE threshold change, or gateware
change was made.

## Interpretation

This is a positive payoff result. CP2038's SI-PDSCH failure is not a semantic
grant issue, missing scheduled energy, or an EPRE/power-sign deficit once the
CP2038 override is active. The same retained air captures decode SI-PDSCH when
a bounded PDSCH-stage symbol phase ramp is applied offline.

Therefore the PDSCH CRC wall is phase/coherence correctable. Combined with
CP2042 and CP2043, the scalar printed PDCCH CFO field is not the whole
explanation, but CP2044 shows that a symbol-phase/coherence defect is present
in the downlink data path and can determine SI-PDSCH success. This promotes the
upstream LiteX-M2SDR timed-TX/coherent-cadence migration from queued option to
the indicated fix direction. It does not justify a live threshold relaxation or
a new RF run by itself.
