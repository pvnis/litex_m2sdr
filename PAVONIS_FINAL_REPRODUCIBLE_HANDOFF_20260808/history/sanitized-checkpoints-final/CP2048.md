# Checkpoint [date-redacted]: No-RF Bulk-CFO Confound Control

Date: [date-redacted]

## Purpose

Hold the CP2046/CP2047 coherent-continuation branch decision and test the
untested CP2044 confound: the CP2044 recovering PDSCH-stage ramp
(`-3500..-750 Hz`, median around `-2125 Hz`) is in the same class as the
capture-side M2SDR/bladeRF bulk LO offset. If full-snippet time-domain bulk CFO
correction recovers SI-PDSCH without the PDSCH-stage ramp, then CP2044 is not
standalone evidence for a live TX coherent-cadence defect.

No RF, deploy, rebuild, gateware, or product-source change was performed.

## Method

Added artifact helper:

```text
cp2048_bulk_cfo_control.py
```

The helper:

- loads retained CF32 live-SS0 snippets from existing CP2043/CP2044 summaries,
- applies a full-snippet time-domain rotation
  `x[n] *= exp(j*2*pi*bulk_cfo_hz*n/Fs)`,
- sweeps `bulk_cfo_hz = -4000..-1000 Hz` in `250 Hz` steps,
- explicitly unsets `PAVONIS_FILETEST_PDSCH_PHASE_RAMP*` before invoking
  `ue_dl_nr_file_test`,
- runs the unchanged live SearchSpace0 `-X -v` harness:
  `PCI=1`, `52 PRB`, `SI-RNTI`, `CORESET0 idx 0`,
  `dl_arfcn=368500`, `ssb_arfcn=367930`,
- writes compact CSV/JSON results and retains logs for targeted inspection.

Inputs:

- all `9` CP2038 DCI-OK retained CF32 snippets from
  `cp2038_rerun_cfo_visible/live_ss0_analysis/live_ss0_scheduled_si_summary.json`,
- the highest-correlation CP2016 DCI-OK retained CF32 snippet,
- the highest-correlation CP2017 DCI-OK retained CF32 snippet.

## Interpretation

This control resolves the CP2044 confound in the bulk-CFO direction for
SI-PDSCH CRC. Full-snippet time-domain bulk CFO correction, with no PDSCH-stage
ramp, broadly recovers the same failure class that CP2044 recovered with a
PDSCH-stage symbol ramp:

- CP2044: PDSCH CRC OK `96/585`, `8/9` CP2038 windows, no-ramp `0/9`.
- CP2048: PDSCH CRC OK `84/117`, `9/9` CP2038 windows, no PDSCH-stage ramp.

Therefore CP2044's PDSCH recovery is not sufficient evidence for a
LiteX-M2SDR live TX coherent-cadence defect. The captures are compatible with a
mundane inter-device bulk CFO/LO offset being enough to explain the retained
offline SI-PDSCH CRC KO.

The PDCCH correlation ceiling remains real: bulk CFO did not lift PDCCH corr
from the `~0.65` class toward `~0.9`. However, this ceiling did not prevent
PDSCH CRC recovery in CP2048, so it should not be used alone to approve the
local coherent-continuation branch. Treat it as a separate quality/coherence
question, not as the proven cause of the CP2038 PDSCH CRC wall.

## Decision

Branch decision is held:

- Do not proceed to the CP2046 option-2 local coherent-continuation branch based
  solely on CP2044.
- Keep upstream LiteX-M2SDR migration and local coherent-continuation work
  queued, behind a stronger live-path discriminator.
- Next useful no-RF work should explain why live UE runs, which should perform
  CFO tracking, still split into pass/fail supply classes. The immediate
  question is no longer "can PDSCH be recovered by phase rotation?" but "what
  separates live UE CFO/timing tracking from the offline bulk-CFO-corrected
  decode?"

No RF, deploy, gateware, or live threshold/ramp workaround is approved by
CP2048.
