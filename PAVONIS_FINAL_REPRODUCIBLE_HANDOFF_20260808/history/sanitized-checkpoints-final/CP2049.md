# Checkpoint [date-redacted]: No-RF Live UE CFO Tracking Source Audit

Date: [date-redacted]

## Purpose

Follow CP2048 without RF: determine whether the live srsUE path already applies
the same kind of CFO correction that recovered the retained CP2038/CP2016/
CP2017 SI-PDSCH snippets offline.

CP2048 proved that full-snippet time-domain bulk CFO correction, with no
PDSCH-stage phase ramp, recovers SI-PDSCH CRC broadly. The remaining confound is
whether a live UE should have corrected that CFO already. This checkpoint audits
source only; it does not change source, deploy, rebuild, run RF, or touch
gateware.

## Method

Bounded source inspection only:

- `srsRAN_4G/lib/src/phy/ue/ue_sync_nr.c`
- `srsRAN_4G/srsue/src/phy/nr/slot_sync.cc`
- `srsRAN_4G/srsue/hdr/phy/nr/slot_sync.h`
- `srsRAN_4G/srsue/hdr/phy/nr/sync_sa.h`
- `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`
- `srsRAN_4G/srsue/hdr/phy/nr/state.h`
- `srsRAN_4G/lib/src/phy/ue/ue_dl_nr.c`
- `srsRAN_4G/lib/src/phy/ch_estimation/dmrs_pdcch.c`
- `srsRAN_4G/lib/include/srsran/interfaces/ue_nr_interfaces.h`

Also checked the CP2031/CP2035 wrapper artifacts for explicit
`disable_cfo`/`enable_worker_cfo` overrides; none were found in the targeted
runner/manifest files.

## Findings

The live UE has CFO correction, but it is not the same as the CP2048 offline
control and it is not driven by the printed SI candidate CFO rows.

1. Sync-stage CFO is enabled by default.

   `slot_sync` passes `disable_cfo=false` by default into
   `srsran_ue_sync_nr_init()`. `ue_sync_nr_recv()` applies
   `srsran_vec_apply_cfo(buffer, -q->cfo_hz / q->srate_hz, ...)` before the
   find/track FSM processes the received subframe. The zerocopy outcome exports
   `q->cfo_hz` and `q->avg_delay_us`, but the current CP2008/CP2040 candidate
   trace does not include those sync-state values.

2. The worker-level CFO rotator is default-on in source.

   `phy_args_nr_t::enable_worker_cfo` defaults to `true`. `cc_worker::work_dl()`
   checks it via `std::isnormal(phy.args.enable_worker_cfo)` and then rotates
   the worker buffer by `phy.get_dl_cfo()` before `srsran_ue_dl_nr_estimate_fft`.
   That value comes from the PHY state's SSB/TRS measurements, not from the SI
   PDCCH candidate currently being decoded.

3. The SI candidate `cand*_cfo_hz` fields are measurements, not correction.

   `srsran_ue_dl_nr_estimate_fft()` performs OFDM demodulation and PDCCH DMRS
   channel estimation. `srsran_dmrs_pdcch_get_measure()` derives candidate
   `cfo_hz`, `sync_error_us`, EPRE, RSRP, and `norm_corr`. `ue_dl_nr_find_dci`
   then gates on EPRE/correlation and decodes PDCCH using the existing samples
   and channel estimates. There is no feedback from `cand*_cfo_hz` into a
   same-candidate or same-slot bulk CFO correction.

4. The PDSCH stage does not apply a separate CFO correction from the SI DCI
   candidate.

   `srsran_ue_dl_nr_decode_pdsch()` estimates PDSCH DMRS and then calls
   `srsran_pdsch_nr_decode()`. The source path does not insert a PDCCH-derived
   CFO correction between DCI decode and PDSCH decode.

5. Current CP2040-class live traces cannot answer the decisive runtime question.

   They include candidate-level PDCCH DMRS `cfo_hz` and `sync_error_us`, but not
   the sync-loop `q->cfo_hz` applied before FFT or the worker/TRS CFO used by
   `cc_worker::work_dl()`. CP1978 had richer sync-state instrumentation, but
   that tracking-state instrumentation was intentionally kept out of the
   CP2008/CP2040 UE baseline.

## Interpretation

CP2048 does not prove the live UE should already behave like the offline
bulk-CFO-corrected harness. The live correction is split across:

- the sync loop's `q->cfo_hz` correction before find/track/FFT, and
- the worker's SSB/TRS-derived `phy.get_dl_cfo()` correction before DL slot
  demodulation.

The CP2040 candidate CFO rows are downstream measurements and do not prove that
the actual applied correction at the SI slot was right, stable, or present in
the same bulk-CFO class that recovered CP2038 offline.

Therefore the branch decision remains held. CP2048 demotes CP2044's PDSCH-stage
phase-ramp result from "proof of live TX cadence defect" to "offline residual
CFO was recoverable". CP2049 narrows the next no-RF question: reconstruct or
instrument the applied live CFO provenance for SI slots before approving a
coherent-continuation implementation.

## Decision

Do not implement/deploy the CP2046 local coherent-continuation branch or migrate
timed TX based on CP2044 alone.

Next no-RF work should establish the applied CFO state for live SI occasions:

- audit whether existing pass/fail logs contain enough sync outcome / TRS /
  worker-CFO information to reconstruct the applied correction, and
- if not, prepare a default-off, metadata-only trace that records sync
  `q->cfo_hz`, sync delay, worker/TRS CFO, candidate CFO, and SI decode outcome
  together without per-sample hot-path work.

No RF, deploy, gateware, live threshold relaxation, or live phase-ramp workaround
is approved by CP2049.
