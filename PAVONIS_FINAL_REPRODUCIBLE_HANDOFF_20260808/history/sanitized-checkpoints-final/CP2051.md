# CHECKPOINT [date-redacted] - No-RF Applied-CFO Reconstruction Audit

Date: [date-redacted] Europe/Zurich

RF: none. No deploys, no rebuilds, no gateware changes.

## Question

Can the existing pass/fail run artifacts reconstruct the CFO actually applied by
live srsUE at SI occasions, without adding new instrumentation?

The target signals were:

- sync-stage `q->cfo_hz` applied before find/track/FFT
- sync delay at the same point
- worker/TRS `phy.get_dl_cfo()` applied before DL FFT
- existing SI candidate `cand*_cfo_hz` / `cand*_sync_error_us`
- PDCCH/PDSCH outcome for the same SI-RNTI opportunity

## Sources Used

Only compact summaries, checkpoint reports, manifests, and small sidecars were
used for the verdict. Raw UE/gNB logs were not needed for the conclusion.

Relevant prior checkpoints:

- CP2040: bounded SI candidate-sync-error RF diagnostic on the CP2035 wrapper.
- CP2048: full-snippet bulk-CFO confound control.
- CP2049: source audit of live UE CFO application path.
- CP1978/CP1979/CP1981: older tracking-state branch and rollback evidence.
- CP2008: current candidate-trace baseline built on the CP1981/CP1988
  pre-CP1978 UE source.

## Findings

CP2040-class traces record candidate-level PDCCH DMRS measurements:

- `cand*_cfo_hz`
- `cand*_sync_error_us`
- active `corr_thr` / `epre_thr`
- candidate identity and decode-attempt metadata

Those rows are downstream measurements taken after the live sync/worker CFO
correction path. They do not record the correction that was applied to the
samples before SI-PDCCH/SI-PDSCH decode.

CP2049 established that the live applied correction is split across two places:

- `ue_sync_nr_recv()` / `srsran_ue_sync_nr_zerocopy()` applies sync-loop
  `q->cfo_hz` when `disable_cfo=false`.
- `cc_worker::work_dl()` applies worker/TRS `phy.get_dl_cfo()` before DL FFT
  when worker CFO is enabled.

Existing CP2040 summaries do not contain either applied value.

CP1979 contains older `sync_cfo_hz` / `sync_delay_us` rows, but that
instrumentation was explicitly rolled back before CP2008. CP1981 records the
pre-CP1978 restoration and absence of those strings, and CP2008 rebuilt the
current candidate trace on that restored baseline. Therefore CP1979 cannot be
used to infer the applied CFO state of the current CP2008/CP2040 UE binary.

## Verdict

Reconstruction is insufficient from existing summaries/artifacts.

The approved applied-CFO trace patch is warranted. It must be default-off,
env-read-once, metadata-only, row-capped through the existing candidate trace,
and must join the applied sync/worker CFO values with the SI candidate and
PDCCH/PDSCH outcomes in the same SI-RNTI rows.
