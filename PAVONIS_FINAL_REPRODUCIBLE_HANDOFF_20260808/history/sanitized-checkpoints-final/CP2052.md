# CHECKPOINT [date-redacted] - No-RF Applied-CFO Provenance Trace Patch

Date: [date-redacted] Europe/Zurich

RF: none. No threshold changes, no gate relaxation, no gNB/M2SDR/gateware
changes.

## Purpose

Implement the CP2051-required trace so the next bounded RF diagnostic can join,
per SI-RNTI opportunity:

- sync-stage CFO and delay from the live sync loop
- worker/TRS CFO from `phy.get_dl_cfo()`
- SI candidate CFO/sync-error and candidate identity
- PDCCH/PDSCH decode outcome

The hypothesis for the next RF run remains: failing SI classes show applied CFO
diverging from the approximate `-3.7 kHz` truth or wandering within the run,
while pass classes show a stable applied CFO. The capture-side PDCCH correlation
ceiling remains about `0.65` after bulk CFO correction, so the `0.5` live gate
has only about `1-1.5 dB` margin. This does not approve lowering the gate.

## Baseline And Scope

Built on the current CP2008 UE baseline, which was itself built on the
CP1981/CP1988 pre-CP1978 source restoration. This patch does not restore the
old CP1978 tracking-state source/backups. It adds new minimal code under a new
default-off env flag:

`PAVONIS_SRSUE_SI_CFO_PROVENANCE_TRACE`

The existing candidate trace remains separately gated by:

`PAVONIS_SRSUE_SI_CANDIDATE_TRACE`

## Source Changes

Files touched:

- `srsue/hdr/phy/nr/sync_tracking.h`
- `srsue/hdr/phy/nr/state.h`
- `srsue/hdr/phy/nr/slot_sync.h`
- `srsue/src/phy/nr/slot_sync.cc`
- `srsue/hdr/phy/nr/worker_pool.h`
- `srsue/src/phy/sync_sa.cc`
- `srsue/src/phy/nr/cc_worker.cc`

Behavior:

- `slot_sync` can capture the latest sync outcome: sequence, TTI, subframe
  index, SFN, in-sync flag, sync CFO, and sync delay.
- That capture is itself disabled unless
  `PAVONIS_SRSUE_SI_CFO_PROVENANCE_TRACE` was enabled at process start.
- `sync_sa` only publishes the sync metadata into worker state when the same
  env flag is enabled.
- `cc_worker` extends the existing SI rows with `cfo_prov`, sync metadata,
  `worker_cfo_enabled`, and `worker_cfo_hz`.
- The existing SI candidate rows keep candidate `cfo_hz`, `sync_error_us`,
  identity, thresholds, and decode-attempt fields.
- PDCCH, candidate, summary, MAC-action, and PDSCH-decode rows all carry the
  same provenance fields so the join is direct.

Strict default-off proof:

- `slot_sync.cc` caches `PAVONIS_SRSUE_SI_CFO_PROVENANCE_TRACE` in a
  `static const bool` before copying sync metadata.
- `sync_sa.cc` caches the same flag in a `static const bool`.
- `cc_worker.cc` caches the same flag in a `static const bool`.
- The existing candidate-trace config remains cached once in
  `pavonis_si_candidate_trace_config()`.
