## Instrumentation Defect

The applied-CFO provenance part of the diagnostic did not activate in the
remote srsUE process:

```text
cfo_prov=0
sync_seq=0
sync_cfo_hz=0.000
sync_delay_us=0.000000
worker_cfo_enabled=1
worker_cfo_hz=-2410.591
```

The fields were present, proving the CP2052 binary was active, but the flag was
not active inside srsUE. Sequence logs show CP2031/CP1807 thought the flag was
enabled:

```text
settings_srsue_si_cfo_provenance_trace=1
```

However the remote generated `launch.env` and `result.env` contained the
candidate-trace variables and did not contain
`PAVONIS_SRSUE_SI_CFO_PROVENANCE_TRACE`. The remote start shim
`cp193_sens_start_stage6_high_peak_tx_now_ue_remote.sh` filters the env passed
through `sudo -n env`, so CP2053 did not fully propagate the new flag.
