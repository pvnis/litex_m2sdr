## Purpose

CP2054 showed the new applied-CFO provenance fields were compiled into srsUE,
but `cfo_prov=0` in the RF trace row. The local CP2031/CP1807 wrapper had
`settings_srsue_si_cfo_provenance_trace=1`, but remote `launch.env` /
`result.env` did not contain `PAVONIS_SRSUE_SI_CFO_PROVENANCE_TRACE`.

Root cause: `cp193_sens_start_stage6_high_peak_tx_now_ue_remote.sh` generates
the remote `run_srsue_bounded.sh` and filters the `sudo -n env` variable list.
It forwarded candidate trace variables but not the new CFO-provenance variable.
