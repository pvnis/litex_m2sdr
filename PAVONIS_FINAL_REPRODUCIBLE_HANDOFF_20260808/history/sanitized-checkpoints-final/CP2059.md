# CP2059 No-RF RA-PDCCH Candidate Trace Patch

Date: [date-redacted]

## Purpose

CP2058 showed that CP2057's strong first RAR PDCCH candidate cannot be
interpreted with the existing RAR trace: it lacks candidate-level
decode-attempt and CRC fields. CP2059 implements the minimal default-off
RA-PDCCH candidate trace and deploys it to [host-redacted].

No RF was run in this checkpoint.

## Patch Scope

Source:

- `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`

Wrapper propagation:

- `cp1807_run_stage6_raresp40_realue_rar_msg3.sh`
- `cp193_sens_start_stage6_high_peak_tx_now_ue_remote.sh`

## New Env

Default-off:

```text
PAVONIS_SRSUE_RAR_CANDIDATE_TRACE=0
PAVONIS_SRSUE_RAR_CANDIDATE_TRACE_LIMIT=200
PAVONIS_SRSUE_RAR_CANDIDATE_TRACE_MIN_CORR=0.20
```

The config is read once per process through a `static const` config object,
matching the SI candidate trace pattern. It is row-capped and only considered
inside RA-RNTI/RAR PDCCH windows.

## New Row

When enabled, the UE emits:

```text
PAVONIS_SRSUE_RAR_CANDIDATE_TRACE event=ra_pdcch_candidates ...
```

Fields include:

- `slot`, `n_dl`, `rnti`, `candidates`
- `max_epre`, `max_corr`
- active `corr_thr`, `epre_thr`
- `trace_limit`, `trace_min_corr`
- per candidate: aggregation level, NCCE, CORESET, format, DCI bits, EPRE,
  RSRP, normalized correlation, CFO, sync error, `decode_attempted`, and CRC

This mirrors the CP2008 SI candidate trace fields for the RA-RNTI path.

## Wrapper Propagation

`cp1807_run_stage6_raresp40_realue_rar_msg3.sh` now:

- defaults the three new env vars
- logs `settings_srsue_rar_candidate_trace=...`
- forwards all three vars into the [host-redacted] launch command

`cp193_sens_start_stage6_high_peak_tx_now_ue_remote.sh` now carries all three
vars through the generated inner `sudo -n env`, generated `result.env`, outer
`nohup env`, and outer `launch.env` blocks.
