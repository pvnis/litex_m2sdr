## Scope

CP2074 stays no-RF after CP2073's `FAPI-clean + descriptor-churn` verdict. It
patches the LiteX-M2SDR Soapy TX write path so sub-MTU timed corrections into a
partially-filled untimed DMA remainder no longer force a short zero-padded
non-EOB descriptor.

Touched source:

- `litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp`

No RF run, gNB scheduler change, threshold change, RAR change, delay [interface-redacted], or
gateware change was made.

## CP2073 Root Cause Link

CP2073's worker trace showed:

- `1341` short non-EOB descriptors in `65536` startup rows.
- No late rows, no dedup rows, and no duplicate HAS_TIME timestamps.
- Short descriptors clustered around `1.900 ms` and `9.989 ms` modulo `10 ms`.

The source audit tied those rows to the active
`M2SDR_SOAPY_TX_ALIGN_HAS_TIME_REMAINDER=1` path. Before CP2074, whenever a new
`HAS_TIME` write arrived while an untimed partial remainder existed, the driver
released the partial remainder immediately. `_dmaReleaseWrite()` zero-padded
the rest of the MTU, so the hardware stream received a short user-data region
inside a non-EOB continuation.

The CP2073 binary-safe mirror contains six capped examples of that old path,
all `releasing partial untimed buffer` rows, with offsets `278`, `556`, and
`180` samples.

## Patch

The patch adds an `effective_flags` path in `writeStream()`:

- Incoming timed writes still split an existing timed remainder on any sample
  discontinuity, preserving the old exact-timed behavior there.
- For an existing untimed partial remainder, the driver computes the expected
  sample at `remainder_timeNs + remainderOffset` and compares it with the
  incoming `timeNs` in sample units.
- If the difference is within one DMA MTU, the incoming `HAS_TIME` bit is
  suppressed for that write and the buffer continues as untimed payload.
- Larger discontinuities still use the old partial-release split path.
- A capped marker was added:
  `M2SDR TX HAS_TIME remainder align: keeping contiguous untimed buffer`.

Rationale: a sub-MTU timed correction cannot be represented in this ring path
without releasing a short zero-padded non-EOB descriptor. For the reopened
coherent-continuation branch, such corrections must be treated as continuation
unless they are larger than one DMA MTU.
