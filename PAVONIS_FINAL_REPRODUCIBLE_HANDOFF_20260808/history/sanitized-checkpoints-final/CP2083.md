## Source Tap Audit

`ocudu/lib/phy/lower/processors/uplink/prach/prach_processor_worker.cpp` shows
one source buffer path for the relevant zero-format PRACH windows:

- `accumulate_samples()` copies the selected PRACH input port into
  `temp_baseband`.
- The async worker converts `temp_baseband` into `cf_buf`.
- The strong predemod capture records that `cf_buf` before OFDM PRACH
  demodulation.
- `demod_cf_buf` is initialized as `cf_buf`.
- If `PAVONIS_PRACH_DEMOD_INPUT_OFFSET_SAMPLES` is unset or zero, there is no
  offset subspan before stage-1.
- Stage-1 energy/search runs on `demod_cf_buf`.
- The final live detector demodulates the same `demod_cf_buf` and reports
  `pavonis_notify_context`, which is shifted by the timing-compensation report
  slot offset.
- `PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES=352536` also overrides
  `collection_delay_samples=352536` and advances the reported SFN by `30`
  slots, leaving residual `6936` samples.

No source-level evidence was found for a different port, wrong buffer, or
separate detector tap between the strong capture and the live detector input.

## Trace Join

The apparent `-59.7 dB` versus `-86.9 dB` contradiction is a trace-cap/cycle
artifact, not proof that the detector consumed empty samples.

Stage-1 trace:

- `200` rows, no `wall_ns`, all `energy_gate=0`, `candidates=0`,
  `selected=0`.
- Raw RMS median `-86.91 dB`; raw peak median `-77.30 dB`.
- The same SFN/slot labels occur in the stage-1 trace, but SFN/slot repeats.
  Aligning the first stage-1 row to the detector wall-time lattice estimates

## Verdict

CP2082's PRACH failure is not a wrong-buffer/unused-port/tap mismatch. The
strong predemod capture and live detector path share the same `cf_buf` lineage,
and the detector trace has energetic rows at the actual strong-window wall
times. The `-86.9 dB` stage-1 rows were earlier capped trace cycles, not the
saved strong windows.

The actionable finding is policy/provenance, not RF: CP2082 contains real
Msg1-like windows, and offline replay accepts all four when the timing/CFO
search includes the needed axis. The current live stage-1 policy shape did not
cover the accepted combinations for this run.

the next no-RF/RF step should use the CP2083 replay result to define a
default-off, row-capped, live-feasible stage-1 policy/config check that covers
the observed positive-shift/negative-CFO class, then run one health-first ladder
diagnostic. Descriptor-fix "lottery eliminated" remains provisional because
CP2082 is only one early-pass roll.
