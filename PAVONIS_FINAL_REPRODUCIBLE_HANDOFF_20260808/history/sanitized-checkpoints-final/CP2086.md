## Scope

No RF was run. This checkpoint prepares the post-run analyzer needed for the
approved-but-still-RF-gated CP2085 signed-stage1 ladder run. It also fixes the
existing CP1807 summary helper so future `prach_stage1_selected_count` values
come from the `selected` header column rather than a stale numeric index.

## Why This Was Needed

CP2085 is ready to run, but its RF result must answer more than "accepted or
not":

- did the 8192-row stage-1 trace cover all UE Msg1 attempts;
- did the signed timing/CFO grid select candidates;
- did the live detector accept them;
- if accepted, did MAC encode a RAR;
- if a RAR was sent, did the UE skip, CRC-KO, geometry-mismatch, or accept it.

The old summary JSON only counted stage-1 rows and a fragile selected count.
That was not enough for the next ladder verdict.

## Changes

Added:

```text
cp2086_analyze_signed_stage1_ladder.py
```

The analyzer consumes one exact CP1807/CP2031 summary JSON and follows only
paths recorded in that summary. It parses:

- stage-1 trace TSV by header;
- PRACH detector trace key/value rows;
- strong predemod manifest;
- UE SIB1, PRACH, RAR, and Msg3 markers;
- gNB RAR, Msg3, timeout, and downlink-late markers.

It writes JSON plus a compact Markdown verdict and joins each strong predemod
window to:

- stage-1 rows with the same collection and reported coordinates;
- detector rows with the same coordinate;
- the nearest detector row by hardware wall timestamp.

Patched:

```text
cp1807_run_stage6_raresp40_realue_rar_msg3.sh
```

The embedded `count_stage1_selected()` helper now locates the `selected`
column by header and falls back to column `10` only if the header is missing.
This prevents the previous off-by-one interpretation of `candidates` as
`selected`.
