## Scope

No RF was run. This checkpoint fixes a return-code labeling issue in the CP2087
approval-gated wrapper before the next RF spend.

## Issue Found

CP2087 previously recorded the exit code from:

```text
bash cp2085_run_signed_stage1_policy_rf.sh
```

as `RF_RC`.

That was semantically wrong. CP2085 calls CP2035, and CP2035 exits:

- `RF_RC` if the RF runner fails;
- otherwise `POST_RC`.

So CP2087's previous `RF_RC` field could actually be a post-verdict failure
code, not the true RF run code. That would make the future CP2087 result file
ambiguous exactly when the run needs clean health-first interpretation.

## Patch

Patched:

```text
cp2087_run_signed_stage1_policy_rf_with_analysis.sh
```

The wrapper now records:

- `CP2085_RC`: exit code from the CP2085 wrapper;
- `CP2035_MANIFEST`: deterministic CP2035 manifest path;
- `CP2035_RF_RC`: true RF rc parsed from the CP2035 manifest;
- `CP2035_POST_RC`: post-verdict rc parsed from the CP2035 manifest;
- `ANALYSIS_RC`: CP2086 analyzer rc.

The wrapper still returns `CP2085_RC` first if nonzero, then `ANALYSIS_RC` if
analysis fails. The behavior is unchanged, but the result semantics are now
explicit.
