- Exact `shift=-352`, `CFO=+33000 Hz` accepts idx `1`.
- Exact `shift=-352`, `CFO=+49000 Hz` accepts idx `0`, `2`, and `3`.
- With stage-1 loop ordering, fixed `shift=-352`, `CFO=33000..49000 step 16000`
  costs only five candidates total including baseline and tests both fractional
  offsets at both CFOs.

## Interpretation

CP2099 confirms the static-envelope problem: CP2098's `-176/0 Hz` point was
real for the saved CP2098 window but did not transfer one run later. However,
CP2099 also shows the detector input is not empty: all four saved windows are
recoverable offline, and a small two-CFO envelope covers them.

The stage-1 "CFO" parameter continues to behave like a compensation axis for
per-occasion timing/phase presentation, not like a stable physical LO offset.

## Decision

Next RF checkpoint should keep the frozen ladder shape and test:

- `shift=-352`
- `CFO=+33000..+49000 Hz step 16000`
- `max_candidates=5`
- RAR candidate trace on

If this produces live gNB acceptance and RAR, classify RAR/Msg3 as before. If
it still selects zero, stop spending RF on single/static envelopes and move to
a source-level dynamic search/ordering fix or the upstream timing-presentation
root cause.
