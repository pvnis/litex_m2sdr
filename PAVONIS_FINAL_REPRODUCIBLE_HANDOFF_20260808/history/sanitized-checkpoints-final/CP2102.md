# CHECKPOINT 2102 - No-RF UE RAR path trace patch and [host-redacted] deploy

Date: [date-redacted] Europe/Zurich

## Goal

Close the CP2101 instrumentation gap without changing thresholds, scheduler
behavior, RAR payloads, delay constants, gateware, or RF settings. CP2101
proved the UE can see an RA-PDCCH candidate with CRC OK at slot `6291`, but the
normal memory-buffered RAR trace capped at `800` rows before that slot and did
not show whether the decoded DCI became an RA-PDSCH grant, whether MAC enabled
the TB, whether PDSCH CRC failed, or whether a decoded TB failed MAC RAR
handoff.

## Source Patch

Added a new default-off trace:

- Flag: `PAVONIS_SRSUE_RAR_PATH_TRACE`
- Limit: `PAVONIS_SRSUE_RAR_PATH_TRACE_LIMIT`, default `256`
- Output prefix: `PAVONIS_SRSUE_RAR_PATH_TRACE`
- Scope: metadata-only events on the RA-RNTI path, row-capped, direct stderr.

Touched files:

- `srsRAN_4G/srsue/hdr/stack/mac_nr/pavonis_rar_trace.h`
- `srsRAN_4G/srsue/hdr/phy/nr/state.h`
- `srsRAN_4G/srsue/src/phy/nr/cc_worker.cc`
- `srsRAN_4G/srsue/src/stack/mac_nr/mac_nr.cc`

New event coverage:

- `ra_pdcch_dci`: decoded RA-PDCCH DCI identity and string.
- `dl_pending_set`: DCI slot to computed PDSCH receive slot and grant fields.
- `dl_pending_get`: pending PDSCH grant consumed by `decode_pdsch_dl()`.
- `ra_pdsch_grant`: worker-side RA PDSCH grant before MAC action.
- `mac_new_grant_dl`: MAC/HARQ action decision and softbuffer presence.
- `ra_mac_action`: worker view of MAC action.
- `ra_pdsch_decode`: PDSCH CRC result and CFO.
- `mac_tb_decoded`: MAC dispatch decision, payload presence, payload hex, and
  current RA-RNTI match state.

Disabled-path proof:

- `rar_path_trace_enabled()` and `rar_path_trace_limit()` parse env through
  function-local `static const` lambdas, so there is no per-event `getenv()`.
- `rar_path_trace_printf()` calls `rar_path_trace_take()` first and returns
  before formatting or flushing when the flag is disabled.
- Call sites are RA-specific: RA-RNTI DCI/PDSCH/pending-grant/MAC paths only.

## Decision

CP2102 is a no-RF patch/deploy checkpoint. The next RF run should use the
same frozen CP2101/CP2035 shape, with `PAVONIS_SRSUE_RAR_PATH_TRACE=1` and a
small limit such as `256` or `512`, plus the existing SI/RAR/stage-1 traces.
Judge health first, then read the new RAR path trace in order:

1. `ra_pdcch_dci`
2. `dl_pending_set`
3. `dl_pending_get`
4. `ra_pdsch_grant`
5. `mac_new_grant_dl` / `ra_mac_action`
6. `ra_pdsch_decode`
7. `mac_tb_decoded`

This should split the CP2101 frontier into one of: DCI-to-PDSCH grant mapping
failure, pending grant not consumed, MAC/HARQ disabling the TB, PDSCH CRC KO,
decoded payload not matching current RA-RNTI/RAPID, or successful RAR handoff
leading to Msg3.
