# CHECKPOINT 2109 - RAR Scheduler Trace No-RF Patch/Deploy

Date: [date-redacted]

## Purpose

CP2108 showed that `PAVONIS_GNB_RAR_PDU_TRACE` proves the RAR payload but not the
RAR scheduling geometry needed to explain CP2106/CP2107's UE `n_dl=0`
no-candidate RAR windows. CP2109 adds and deploys a default-off scheduler-side
trace before any further RF.

## Source Change

Touched file:

- `ocudu/lib/scheduler/common_scheduling/ra_scheduler.cpp`

Added `PAVONIS_GNB_RAR_SCHED_TRACE`, with optional
`PAVONIS_GNB_RAR_SCHED_TRACE_LIMIT` defaulting to `128` rows. The env is cached
once in a function-local static. Disabled calls only fetch the cached state; no
RAR formatting is done unless the trace is enabled and still under the row cap.

Each enabled `event=rar_alloc` row records:

- RA-RNTI, RAPID, temp C-RNTI, TA.
- Original PRACH slot and RAR response-window reference/start/stop slots.
- Chosen RAR PDCCH slot, RAR PDSCH slot, `k0`, PDSCH time resource index,
  symbols, CRBs, search-space ID, aggregation level, NCCE, and power offset.
- Msg3 slot, delay, PUSCH time-resource index, symbols, CRBs.
- RAR grant resource assignment fields and prior failed-attempt counters.

No scheduler behavior, thresholds, payloads, timing constants, gateware, or RF
config were changed.
