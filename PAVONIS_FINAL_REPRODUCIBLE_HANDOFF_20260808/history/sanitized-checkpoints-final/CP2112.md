# CHECKPOINT 2112 - PRACH Report-Slot Offset Override Deploy

Date: [date-redacted] Europe/Zurich

## Purpose

Implement and deploy the CP2111 decision: keep PRACH timing-compensated delayed
collection, but add a default-off way to override the PRACH slot reported to
FAPI/MAC/scheduler. The next RF run can set the override to `0`, making the gNB
RAR response window use the actual/source PRACH slot instead of the delayed
`+30` reported slot.

## Source Change

Touched source:

```text
ocudu/lib/phy/lower/processors/uplink/prach/prach_processor_worker.cpp
```

New env:

```text
PAVONIS_PRACH_TIMING_COMPENSATION_REPORT_SLOT_OFFSET
```

Behavior:

- Env unset: existing automatic behavior is unchanged. With
  `PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES=352536`, the code still computes
  `timing_compensation_report_slot_offset=30`.
- Env set to `0`: delayed collection still uses `352536` samples, but
  `pavonis_notify_context.slot` remains the source PRACH slot.
- Negative or unparsable values are ignored and the automatic offset is used.

The override is read once through a static cached helper:

```text
pavonis_get_report_slot_offset_override()
```

The only behavioral assignment is:

```text
timing_compensation_report_slot_offset = report_slot_override.value
```

No PRACH envelope, detector threshold, RAR payload, RA-RNTI, DCI geometry,
delay constant, downlink power, or gateware behavior was changed.

## Decision

Run one bounded RF diagnostic on the CP2110 shape with exactly one behavioral
change:

```text
PAVONIS_PRACH_TIMING_COMPENSATION_REPORT_SLOT_OFFSET=0
```

Keep:

- `PAVONIS_PRACH_TIMING_COMPENSATION_SAMPLES=352536`
- CP2110 negative-grid stage1 shape
- `PAVONIS_GNB_RAR_SCHED_TRACE=1`
- RAR candidate/path traces
- power-sign override
- `ra_resp_window=40`

Judgment order:

1. Health first: Soapy timeout/downlink-late counts and stage1 search time.
2. Manifest proof: strong-window and stage1 rows should show source and reported
   slots equal when the override is active.
3. gNB scheduler row: RAR `prach_system_slot` should match the source PRACH
   slot, not source+30.
4. UE outcome: RAR grant/TA/Msg3 markers, or at least RA-PDCCH/PDSCH
   candidate/path rows in the actual UE response window.

If RAR becomes unschedulable because the gNB receives the PRACH indication too
late for the actual UE response window, stop and reduce stage1 search latency.
Do not retune PRACH envelope or RAR payloads in response.
