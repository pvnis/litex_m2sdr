## Source Path

Lower PHY:

- `prach_processor_worker.cpp` collects delayed samples and creates
  `pavonis_notify_context`.
- With CP2113's override, `pavonis_notify_context.slot` remains the source slot.
- The async PRACH task still runs stage-1 first, then always continues to the
  normal all-preamble demod/detect path.
- Notification is emitted only at the end:

```text
notifier->on_rx_prach_window(std::move(buffer), pavonis_notify_context);
```

PHY to FAPI:

- `phy_to_fapi_results_event_fastpath_translator::on_new_prach_results()` drops
  empty result sets and all-negative-TA detections.
- Otherwise it builds a FAPI `RACH.indication` using `result.context.slot`.

FAPI to MAC:

- `fapi_to_mac_indications_fastpath_translator::on_rach_indication()` copies
  `msg.slot` into `mac_rach_indication.slot_rx`.
- It drops only preambles with an empty timing-advance field.

MAC to scheduler:

- `mac_cell_rach_handler_impl::handle_rach_indication()` copies `slot_rx`,
  allocates a TC-RNTI for contention-based preambles, and forwards nonempty
  occasions to `parent.sched.handle_rach_indication()`.
- A preamble can be dropped here if it is treated as CFRA without a C-RNTI, if
  TC-RNTI allocation fails, or if the occasion becomes empty. CP2101/CP2110
  prove preamble `0` can reach RAR on the same configuration, so this is not the
  leading explanation.

Scheduler:

- `ra_scheduler::handle_rach_indication()` only enqueues the RACH indication.
- `ra_scheduler::run_slot()` later pops queued RACHs and calls
  `handle_rach_indication_impl(rach, res_alloc.slot_tx())`.
- `handle_rach_indication_impl()` creates a pending RAR with
  `rar_window_ref_slot = msg.slot_rx + PAVONIS_RACH_RAR_WINDOW_OFFSET_SLOTS`.
- `schedule_pending_rars()` can only allocate while the pending RAR window
  contains the candidate PDCCH slot.

## CP2113 Timing Evidence

CP2113's accepted window is `353:4`. The detector trace has two accepted rows:

```text
stage1 p0-only: wall_ns=1783913264802006173 sfn=353 slot=4 nof_preamble_indices=1  accepted=1 p0_ratio=14.703
normal all-preamble: wall_ns=1783913264807655856 sfn=353 slot=4 nof_preamble_indices=64 accepted=1 p0_ratio=14.703
```

The normal notification-producing detect occurs about `5.65 ms` after the
stage-1 baseline accept. CP2113's stage-1 summary agrees:

```text
selected shift=0 frac=0 cfo_hz=0 metric=14.702595 search_time_us=5186 candidates=9
```

The extra time is not needed for this accepted row because the baseline
candidate already detected preamble `0`; the remaining grid candidates all
ran before the final all-preamble detect and notification path.

## Interpretation

The no-RF audit supports a latency explanation strongly enough for a targeted
source change:

- CP2113 no longer has the `+30` report-slot displacement.
- The accepted p0 row is present, positive, and baseline.
- No gNB RAR allocation is produced.
- The accepted baseline result waits roughly `5-6 ms` before the normal
  notification path can emit the PRACH window result.

At a source-slot RAR window, that delay can make an otherwise valid RACH
indication arrive too late for schedulability. Current logs do not conclusively
separate "late/stale before scheduler" from "not delivered to scheduler", but
the smallest discriminating fix is the same: avoid the unnecessary stage-1 grid
after a detected p0 baseline or first accepted candidate.

## Decision

Implement a default-off stage-1 early-exit policy:

```text
PAVONIS_PRACH_DEMOD_INPUT_STAGE1_STOP_ON_ACCEPT
```

Expected behavior:

- Env unset: current stage-1 behavior unchanged.
- Env set: if the baseline p0-only detect accepts, skip the timing/CFO grid.
- Env set: if a grid candidate accepts, stop further grid candidates.
- The final normal all-preamble detect/notify path still runs, preserving
  downstream semantics and existing detector thresholds.
- Existing stage-1 trace `candidates` and `search_time_us` are sufficient to
  prove the latency change.

Next checkpoint should be a no-RF patch/build/deploy proof, then one RF run
with both:

```text
PAVONIS_PRACH_TIMING_COMPENSATION_REPORT_SLOT_OFFSET=0
PAVONIS_PRACH_DEMOD_INPUT_STAGE1_STOP_ON_ACCEPT=1
```

Do not change PRACH thresholds, PRACH envelope, RAR payloads, delay constants,
or gateware.
