## Purpose

Implement and deploy the CP2114 decision: keep PRACH stage-1 default-off, but
add an opt-in early-exit policy that skips the remaining stage-1 grid after a
baseline p0 accept or first accepted grid candidate.

New env:

```text
PAVONIS_PRACH_DEMOD_INPUT_STAGE1_STOP_ON_ACCEPT
```

Unset or `0` preserves current behavior.

## Source Change

Touched source:

```text
ocudu/lib/phy/lower/processors/uplink/prach/prach_processor_worker.cpp
```

Change summary:

- Add `stop_on_accept` to `pavonis_prach_stage1_policy_config`.
- Read it with cached stage-1 config using
  `pavonis_env_enabled("PAVONIS_PRACH_DEMOD_INPUT_STAGE1_STOP_ON_ACCEPT")`.
- Add loop guards to the stage-1 shift/frac/CFO grid:

```text
(!pavonis_stage1_cfg.stop_on_accept || !pavonis_stage1_selected)
```

The baseline p0-only detect still runs first. If it accepts and the new env is
enabled, the grid is skipped. If the baseline does not accept, the grid runs
until the first accepted candidate or `max_candidates`, depending on the env.
The final normal all-preamble detect and `on_rx_prach_window()` notification
still run, preserving downstream semantics.

No PRACH detector threshold, PRACH envelope, RAR payload, RAR scheduler, delay
constant, downlink power, or gateware behavior was changed.
