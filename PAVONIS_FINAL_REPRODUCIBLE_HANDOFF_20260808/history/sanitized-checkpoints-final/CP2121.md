Date: [date-redacted] Europe/Zurich

## Purpose

Compare the existing RAR-bearing runs without RF:

```text
CP2101, CP2106, CP2107, CP2110, CP2120
```

Goal: explain why CP2101 had one RA-PDCCH CRC-OK RAR candidate while repeated
later RAR transmissions are UE no-candidate at the expected slot.

No RF, source change, rebuild, deploy, threshold change, RAR payload change, or
scheduler change was performed.

## Interpretation

The RAR failures are not explained by:

- RA-RNTI mismatch: all joined rows use `0x39`.
- Basic RAR payload mismatch: CP2101/CP2110/CP2120 all use normal RAPID `0`,
  temporary C-RNTI grants, `freq_resource_assignment=112`,
  `time_resource_assignment=0`, `mcs=0`.
- RAR response-window coverage: CP2120's UE trace covers the exact scheduled
  RAR slot.
- Missing scheduler row in CP2120: scheduler trace proves the exact PDCCH/PDSCH
  slot.
- Trace cap: CP2120's RAR trace includes the scheduled slot.

The leading discriminator is slot phase / scheduled RAR occasion presentation:

- Good CP2101 RAR candidate: `mod160=51`, high EPRE and high corr.
- Bad CP2120 scheduled RAR candidate: `mod160=54`, high EPRE and low corr.
- CP2101 contains three additional `mod160=54` high-EPRE/low-corr rows, matching
  CP2120's failed signature.
- CP2110's scheduled `mod160=57` row is also no-candidate, though in that run
  the scheduled slot is floor EPRE rather than high EPRE.

This points away from RAR payload semantics and toward when the RAR PDCCH is
placed on the live downlink timeline. The next useful question is whether the
gNB scheduler can place RAR three slots earlier in the same UE response window
so the next CP2120-shape run tests `mod160=51` instead of `mod160=54`, without
changing payload or thresholds.

## Decision

Next stay no-RF and audit `ra_scheduler.cpp` for RAR slot selection:

1. Determine why CP2120 chose PDCCH/PDSCH slot `6614`.
2. Check whether an existing config/env can choose an earlier slot inside the
   same response window.
3. If no existing knob exists, consider a minimal default-off RAR-slot advance
   knob for one bounded RF diagnostic, with payload, RA-RNTI, AL/NCCE, and
   thresholds unchanged.

Do not run another unchanged CP2120 RF attempt before this source audit.
