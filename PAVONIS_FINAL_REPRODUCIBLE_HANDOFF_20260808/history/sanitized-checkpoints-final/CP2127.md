## Candidate-Order Simulation

The current CP2124/CP2126 live envelope:

- shift `-192..-96`, step `96`
- CFO `37..42 kHz`, step `5 kHz`
- max candidates `12`

selects `0/6` CP2126 saved windows in replay, matching the live CP2126 result.

A full offline `20..50 kHz` / `1 kHz` grid would recover `3/6`, but is too
large to drop directly into the live path. A compact env-only grid:

- shift `-448..-288`, step `32`
- CFO `20..50 kHz`, step `5 kHz`
- max candidates `64`
- stop-on-accept still enabled

would have selected `2/6` CP2126 windows in candidate order:

- idx `0`: candidate `8`, `shift=-448`, `frac=-0.5`, `CFO=50000`, p0 `2.639`
- idx `5`: candidate `2`, `shift=-448`, `frac=-0.5`, `CFO=20000`, p0 `1.583`

The candidate work is about `266` checked variants over CP2126's six windows,
versus `144` for the CP2126 live run, so this is a bounded health-first RF
diagnostic rather than a wide sweep.

## Verdict

CP2126's windows were not empty and not a wrong-buffer artifact. The live
no-selection was an envelope miss for at least some windows, while other windows
need a different low/negative-CFO lobe. The next RF run should use the compact
`-448..-288` / `20..50 kHz step 5 kHz` envelope inside the direct CP1807
runner, preserving the CP2124 ladder shape and the in-process `after_gnb_rar`
UL-symbol capture. Judge health first; if RAR and Msg3 occur, use the captured
UL-symbol artifacts for the Msg3/PUSCH CRC frontier.
