# CHECKPOINT 2129 - Stage-1 Selected-Shift TA Compensation, No-RF Deploy

Date: [date-redacted]
Mode: no RF, source audit + local build + [host-redacted] deploy

## Question

CP2124 reached UE-decoded RAR and UE Msg3 transmission, but gNB Msg3 PUSCH
stayed CRC KO with low SINR. The user hypothesis was that the PRACH stage-1
transform might shift samples for detector recovery but leave the reported
PRACH delay/TA in the shifted sample frame.

## Source Verdict

The bias exists. The lower PRACH path replaces `demod_cf_buf` with the
stage-1 shifted/CFO-corrected samples before the normal PRACH detector runs.
The detector then computes `preamble.time_advance` from those shifted samples,
and MAC/RAR consumes that TA unchanged.

For a selected negative shift such as `-96` or `-192` samples, the detector TA
is biased high by approximately `-shift` samples. The physical-air TA should be
`detected_ta + selected_shift + selected_frac`, clamped at zero.

## Patch

Implemented default-off compensation behind:

`PAVONIS_PRACH_STAGE1_TA_COMPENSATE_SELECTED_SHIFT`

The first implementation added fields to `prach_buffer_context`, but local
build caught that this grows the PRACH task lambda beyond the no-allocation
executor capacity. The final patch preserves the context ABI and uses a
default-off fixed-size slot table:

- Lower PRACH records `(slot, selected_shift + selected_frac)` only when the
  knob is enabled and a stage-1 transform is selected.
- Upper PRACH consumes the entry after `prach->detect(...)`, adjusts every
  reported preamble TA by that sample delta, and clamps negative TA to zero.
- Disabled path returns before the slot-table lock and does not change
  `prach_buffer_context` size.

Also fixed CP1807 helper propagation so the already-approved compact-envelope
run really forwards `PAVONIS_PRACH_DEMOD_INPUT_STAGE1_STOP_ON_ACCEPT` and the
new TA-compensation flag to [host-redacted], and adds the new flag to run logs/result env.
