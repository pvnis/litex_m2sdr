# CHECKPOINT 2136 - Android Phone Readiness on [host-redacted]

Date: [date-redacted] Europe/Zurich

Purpose: determine whether the Android phone connected to [host-redacted] can be used
as a remotely controlled UE for later OTA attach testing.

No RF was run and no phone settings were changed.

## Installed ADB State

So the host cannot use the phone via normal `/usr/bin/adb` until ADB is

## Temporary ADB Bundle Test

To avoid a system install, a temporary bundle was built from this workstation's
ADB plus Android-specific shared libraries:

```text
/tmp/cp2136_adb_bundle.tar.gz
sha256: 3a8114a80b6e78b77cff49f26ff123f42c5ab07d6b4c6131794e49048cd71df9
```

The first run incorrectly put newer workstation system libraries ahead of the
remote libc and failed on `GLIBC_ABI_DT_X86_64_PLT`. Retrying with only the
Android library directory in `LD_LIBRARY_PATH` worked:

```text
Android Debug Bridge version 1.0.41
Version 34.0.5-debian
Running on Linux 6.8.0-101-lowlatency (x86_64)
```

With that temporary ADB, the phone is detected but not authorized:

```text
List of devices attached
[known-phone-serial-redacted]               unauthorized usb:3-3 transport_id:1
```

Using [host-redacted]'s default ADB key location still reports:

```text
[known-phone-serial-redacted]    unauthorized
```

## Verdict

The phone is physically connected and the [host-redacted] host can run ADB from a
temporary non-system bundle, but the phone is not currently usable as a remote
UE because ADB authorization has not been accepted on the device.

To make it usable later:

1. Provision ADB on [host-redacted], either by a proper package/repo fix or a curated
   portable platform-tools bundle.
2. Accept the ADB authorization prompt on the phone for [host-redacted]'s key, or
   provision a key already trusted by the phone.
3. Re-run an authorized ADB readiness check that can query build/baseband,
   radio/SIM state, and basic shell/logcat access without exposing identifiers.

Until then, OTA attach work should continue with the bladeRF/srsUE path; the
Android phone is a physically present but authorization-blocked future option.
