## Goal

Close the artifact-integrity gap before using CP2134's event-triggered RAR
FAPI and M2SDR TX-worker traces. No RF, source rebuild, binary deploy, radio
configuration change, or ladder [interface-redacted] was performed.

## Finding

The CP2134 runtime mechanism is already correctly ordered and bounded:

- RAR PDU assembly touches `M2SDR_SOAPY_TX_WORKER_TRACE_ARM_FILE` once, before
  the RAR reaches the FAPI/lower-PHY TX path.
- The Soapy worker checks that file before emitting rows and caps output with
  `M2SDR_SOAPY_TX_WORKER_TRACE_LIMIT` (default `65536`).
- At the observed descriptor rate, `65536` rows cover about six seconds after
  the RAR event, enough to include the scheduled RAR descriptor sequence.

The wrapper plumbing had one gap: the detached gNB launcher did not remove the
configured RAR FAPI trace before a run, and the [host-redacted] packager did not collect
the default `/tmp/pavonis_gnb_rar_fapi_trace.tsv` path. This could leave stale
rows on [host-redacted] or omit the decisive trace from the returned artifacts.

The CP2158 tar also contains a stale worker trace despite that run not enabling
the worker trace. Its `65536` data rows span `5.942222 s`; its local mtime is
`[date-redacted] +0200`, before CP2158's `[date-redacted]` run. CP2158
did not interpret this file, so its RAR-candidate verdict is unaffected.
