# CHECKPOINT 2162 - Full-Ring Poll Source Audit (No RF)

Date: [date-redacted] Europe/Zurich

## Goal

Trace CP2161's approximately 20 ms wall-time worker stalls and 11 immediate TX
timeouts to the exact source branch before changing any runtime policy. No RF,
build, deploy, radio configuration, or source edit was performed.

## Data-to-Source Join

The CP2161 worker rows straddling floor RAR slot `3251` show:

```text
before: user_count=692208 hw_count=691952 pending=256
after:  user_count=692209 hw_count=692088 pending=121
wall gap:   20.583633 ms
source gap:  0.088715 ms
```

The decoded RAR slot `6611` crosses the same full-ring regime:

```text
before: user_count=717280 hw_count=717024 pending=256
after:  user_count=717281 hw_count=717160 pending=121
wall gap:   20.096470 ms
source gap:  0.088715 ms
```

The ring is therefore exactly full at `256` entries before each stall. The
source timeline advances by one normal `1022`-sample descriptor while wall
service pauses, proving this is backpressure in descriptor delivery, not an
intentional radio-time gap.

## Exact Source Path

The local LiteX Soapy worker architecture has two finite queues:

- `LiteXM2SDRStreamWorker.hpp`: `kWorkerPktCount = 16`;
- the zero-copy LitePCIe TX DMA ring observed in CP2161: `256` descriptors.

`acquireWriteBuffer()` first pops one of the 16 staging packets and waits only
the caller timeout (`1000 us` in the frozen ladder). The TX worker consumes
that queue, then calls `_dmaAcquireWrite(..., timeoutUs=200000)`.

In zero-copy `_dmaAcquireWrite()`:

1. `buffers_pending = user_count - hw_count` reaches the full ring count;
2. it calls `poll(POLLOUT, timeoutUs / 1000)`;
3. the kernel's `litepcie_poll()` exposes `POLLOUT` only when
   `reader_sw_count - reader_hw_count < DMA_BUFFER_COUNT / 2`.

Thus a full 256-entry ring does not wake after one descriptor is free. It waits
until at least 129 descriptors have drained. At `11.52 Msps` and `1022`
samples per descriptor:

```text
one descriptor:       0.088715278 ms
129 descriptors:     11.444270833 ms
16 staging packets:   1.419444444 ms
```

The predicted `11.44 ms` half-ring wake delay matches CP2161's floor-RAR first
timed rows at `+12.080/+12.094 ms`. The 16-packet staging pool covers only
about `1.42 ms`; once depleted, OCUDU's 1 ms `writeStream()` call times out.
With retry/carry disabled in the frozen shape, `radio_soapy_tx_stream.cpp`
logs the timeout and returns, abandoning the remaining logical data buffer.

The decoded RAR did not avoid the full-ring pause. Its scheduler event landed
near the end of the same drain cycle, so the worker resumed at `+1.074 ms`
instead of `+12 ms`; only one write timed out and its timed source remained in
the intended approximately `29 ms` presentation class.

## Historical Policy Check

Do not answer this finding by re-enabling old OCUDU retry/carry modes:

- CP1696 synchronous retry blocked the caller, retained a deficit, and
  regressed acquisition.
- CP1698 reached zero stop-time deficit by carrying timed chunks, but its
  `8..18 ms` SI-era backlog degraded SI correlation and lost SIB1.
- deadline/carry variants CP1701-CP1727 either dropped stale data, overflowed,
  accumulated lag, or produced release-late traces.

Those branches treated the symptom after the 16-packet pool was exhausted.
CP2162 identifies the earlier cause: a half-ring `POLLOUT` wake threshold is
being used where the real-time worker needs one-slot availability.

## Verdict and Next Gate

The indicated local fix is not another queue/carry policy. Add a default-off
zero-copy full-ring wait mode in `_dmaAcquireWrite()` that refreshes
`hw_count` with `litepcie_dma_reader()` on a short bounded interval and resumes
as soon as one descriptor slot is free, bypassing the kernel half-ring
`POLLOUT` batching only when explicitly enabled. Preserve the existing poll
branch as the default.

Required gates before ladder RF:

1. local and [host-redacted] no-RF build/string/disabled-path proof;
2. bounded gNB-only all-timed TX run with the mode enabled;
3. zero or near-zero OCUDU timeouts/deficit, normal downlink-late class;
4. CP2047 zero short non-EOB, late, dedup, and duplicate timestamp rows;
5. worker inter-row wall gaps collapse from approximately 20 ms toward the
   one-descriptor service scale without introducing late timed rows.

Only a gate passing all five may unlock another ladder run. No scheduler,
payload, threshold, delay, gain, attenuation, slot-attribution, or gateware
change is justified.
