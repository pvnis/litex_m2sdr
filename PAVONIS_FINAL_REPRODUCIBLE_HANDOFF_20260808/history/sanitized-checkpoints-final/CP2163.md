# CHECKPOINT 2163 - Full-Ring Short Refresh (No RF)

Date: [date-redacted] Europe/Zurich

## Goal

Implement the CP2162-indicated fix at the source of the approximately 11 ms
full-ring wake delay, while preserving the deployed default behavior and all
standing ladder freezes. This checkpoint performs no RF.

## Patch

File:

`litex_m2sdr/litex_m2sdr/software/soapysdr/LiteXM2SDRStreaming.cpp`

New default-off environment control:

`M2SDR_SOAPY_TX_FULL_RING_REFRESH_US`

- Default `0` preserves the existing `poll(POLLOUT)` half-ring wake path.
- A positive value is clamped to `10000 us`.
- Only when the zero-copy TX ring is full, the enabled path sleeps for the
  configured bounded interval, refreshes the hardware reader count through
  `litepcie_dma_reader()`, and resumes as soon as one descriptor is free.
- Existing timeout and invalid-count recovery remain in force.
- A once-per-process marker reports the active interval:
  `M2SDR TX full-ring short refresh active: interval_us=...`.

The source hash is:

`aebcb81c7744ea0c0cb7051b19e3d8d1547d8f1a27e2ae2c7e5383918236c84b`

## Disabled-Path Proof

branch is false and `_dmaAcquireWrite()` reaches the original
`poll(&_tx_stream.fds, 1, timeoutUs / 1000)` implementation unchanged. No
short sleeps or extra reader-count ioctls are added to the default path.
