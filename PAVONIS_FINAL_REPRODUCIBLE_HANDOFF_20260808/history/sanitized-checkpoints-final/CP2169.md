## Late-context result

The trace reaches its 64-row cap over 10.082 seconds. Every row is
`delayed_pre_anchor`; every row has `target_valid=0`. The request is therefore
discarded before the 352536-sample delayed collection target is established.

Request slots are always slot 4. Current RX context progresses from the same
slot to three slots ahead:

- slot delta 0: 9 rows
- slot delta 1: 12 rows
- slot delta 2: 15 rows
- slot delta 3: 28 rows

The RX context timestamp modulo the 11520-sample slot reproduces the exact
symbol-start offsets (`0, 828, 1650, ... 10698`), so lateness can be measured
as `slot_delta * 11520 + context_timestamp % 11520` without wall-clock or NTP
joins. It starts at 9054 samples (0.786 ms), ranges from 1650 to 45258 samples
(0.143 to 3.929 ms), and ends at 37032 samples (3.215 ms). Eight-row mean
lateness grows from 0.679 ms to the 3.53-3.57 ms class.

This corrects CP2167's provisional interpretation. The 127-129 ms
last-collection-to-first-late wall interval did not represent a single 31-32
ms sample displacement. The actual fault starts inside the requested slot and
then accumulates to several milliseconds.

## TX deficit join

The binary-safe mirror has the same residual timeout staircase, grouped as
`4,5,4,3,2,1` warning rows. The first late event follows the fourth group by
115.5 ms, and the final two groups occur while trace lateness continues to
grow.

The authoritative stop summary records:

- `timeouts=41`
- `partial_ret=12`
- `write_deficit=48608` samples (4.219 ms)
- `data_samples_req=727153952`
- `data_samples_ret=727105344`

The maximum measured RX-context lead is 45258 samples, only 3350 samples
(0.291 ms) below the final abandoned TX-sample count. This magnitude match,
the shared growth interval, and the absence of any target calculation on the
late path make residual TX sample abandonment the direct explanation for the
global TX/scheduler versus RX timeline split.

## Verdict

PASS and decisive. Do not change PRACH collection delay, stage1, report slot,
or scheduler attribution. The CP2163 refresh removes the half-ring storm but
does not yet guarantee zero returned-sample deficit. PRACH request lateness is
a downstream symptom of that remaining deficit.

CP1696-CP1727 still close ordered carry and deadline queue policies because
they accumulated stale multi-millisecond backlog under the old 125k-timeout
regime. The materially changed CP2169 regime has only 41 internal timeouts and
4.219 ms total deficit. The next bounded gNB-only gate should therefore reuse
the already-built synchronous same-chunk timeout retry, not carry: refresh 50
us, retry enabled, at most two 1 ms attempts, no UE. Acceptance requires zero
write/data deficit, zero retry exhaustion/abandonment, no downlink or release
late events, and zero late-context rows. Only then return to a ladder run.
