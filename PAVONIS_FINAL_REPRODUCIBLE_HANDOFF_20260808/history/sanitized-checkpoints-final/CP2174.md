# CP2174: bounded TX worker-pool override, no RF

Date: [date-redacted] Europe/Zurich

## Question

CP2172 and CP2173 remove persistent PRACH request lateness at 20 ms and
17 ms lead, but both lose 22-23 TX descriptors before logical write 100. The
LiteX Soapy producer has only 16 worker packets (about 1.4 ms at 11.52 Msps)
while the worker and timed hardware ring are still priming. Add a bounded,
default-preserving TX-only staging override so the startup burst can be tested
without changing steady-state cadence or RX allocation.

## Patch

`LiteXM2SDRStreaming.cpp` now reads
`M2SDR_SOAPY_TX_WORKER_PKT_COUNT` once. Unset or values below the existing
default retain `kWorkerPktCount=16`; explicit values are capped at 512. Only
the TX stream uses the selected count. RX remains fixed at the original
16-packet pool.

The worker pool, free FIFO, ready FIFO, and packet initialization loop all use
the same selected count. An active TX override emits:

`M2SDR TX worker packet pool override active: packets=... default=... capacity_bytes=...`

The frozen runner and detached launcher propagate and record the value, with
the default fixed at 16. Both scripts pass `bash -n`, and the remote formatter
remains balanced at 106 `%q` fields and 106 arguments.

## Verdict and next

PASS, no RF. Run one bounded gNB-only acceptance gate at the known-clean
20 ms lead with a 64-packet TX pool, retry/carry/deadline off, full-ring refresh
50 us, and the CP2168 late-context trace enabled. Require the active marker,
zero write/data deficit, zero timeouts and partial returns, zero late-context
rows, and normal PRACH-window progression before using this shape with a UE.
