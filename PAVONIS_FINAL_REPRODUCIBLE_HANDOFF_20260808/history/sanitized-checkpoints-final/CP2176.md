# CP2176: TX worker-pool activation telemetry, no RF

Date: [date-redacted] Europe/Zurich

## Audit

The CP2175 no-RF source audit finds no remaining hidden fixed-16 TX queue:

- `PacketsFIFO(n)` has exactly `n` usable entries (`n+1` ring storage).
- TX packet vector, work FIFO, free FIFO, and initialization loop all use the
  selected `pkt_count`.
- `acquireWriteBuffer()` waits on that TX free FIFO and
  `releaseWriteBuffer()` feeds the matching work FIFO.
- The only other `kWorkerPktCount` use is the intentionally unchanged RX pool.
- The generated gNB runner exports the selected value and fixes
  `SOAPY_SDR_PLUGIN_PATH` to the rebuilt [host-redacted] module directory.

The CP2175 INFO marker was not preserved in either packaged log route, as also
happened to the CP2164 full-ring INFO marker. Runtime pool selection therefore
needed a logger-independent proof before interpreting another deficit run.

## Telemetry-only patch

The existing active-override marker now writes once to `stderr` at TX worker
creation and flushes immediately. The already-enabled, row-bounded worker
summary gains `pkt_pool`, `work_fifo_max`, and `free_fifo_max` fields. This adds
no queue policy, no sample work, and no new hot-path event; the summary runs at
its existing cadence. With the env unset, pool behavior remains 16 packets.
