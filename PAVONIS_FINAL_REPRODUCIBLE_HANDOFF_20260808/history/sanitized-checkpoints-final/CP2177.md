## Result

telemetry. The runtime mechanism is now proven:

- one startup marker: `packets=64 default=16 capacity_bytes=8176`
- worker start: `pkt_pool=64 work_fifo_max=64 free_fifo_max=64`
- rebuilt CP2176 module path remains selected by the frozen runner

Mechanics remain healthy: 394 normal empty PRACH windows continue, no late-
context file is created, and downlink/release-late counts are zero.

The strict internal stop summary still fails:

- `write_deficit=data_write_deficit=20920` samples (`1.815972 ms`)
- `timeouts=20`
- `partial_ret=1`
- retry/carry/deadline counters all zero

These values are present by logical write 100 and remain fixed through stop.
The compact wrapper summary reports zero timeout *log lines*, but that is not a
valid health gate: the binary-safe warnings disappeared while the authoritative
OCUDU summary counters remained nonzero. Future wrapper gates must parse the
stop-summary counters directly.

## Verdict and next

FAIL, but decisive. Close the TX worker-pool theory; do not increase the pool.
Stay no-RF and audit the current OCUDU `transmit()` partial/timeout ordering and
the already-built bounded same-chunk retry at the corrected 20 ms lead. The
next gate must also fix the wrapper health check to consume internal stop
counters. No PRACH, scheduler, threshold, gain, delay, or gateware changes.
