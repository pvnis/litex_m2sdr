# CP2178: authoritative TX summary health gate, no RF

Date: [date-redacted] Europe/Zurich

## Problem

CP2177 proves that warning-line counts can report zero while OCUDU's internal
stop summary records 20 timeouts, one partial return, and 20920 lost samples.
The shared ladder wrapper could therefore start a UE and return overall success
after a mechanically unhealthy TX run.

## Runner fix

The frozen shared runner now has two structured counter gates:

- Before UE start, it parses only the latest periodic `Soapy TX summary` and
  requires exact zeros for `write_deficit`, `data_write_deficit`, `partial_ret`,
  and `timeouts`. Failure feeds the existing `LATE_GATE_RC`, prevents UE start,
  and marks the run failed.
- During compact artifact summarization, the last `reason=stop` row is parsed
  into `.gnb.soapy_tx_stop_summary`. A local `jq` gate requires the same four
  zero values and marks `OVERALL_RC=1` otherwise.

The sequence manifest records both the pre-UE and final stop gate return codes.
Warning-line counters remain useful diagnostics but are no longer accepted as
proof of zero sample loss. Parsing is bounded to one latest summary row and one
stop row; no raw-log dump or high-volume match is added.

## Verdict and next

PASS, no RF. Test the already-built same-chunk retry once under the corrected
shape: 20 ms lead, proven pool64, refresh 50 us, retry max two at 1 ms,
carry/deadline off, no UE. The new gate makes zero internal deficit mandatory.
This is a re-evaluation of existing retry semantics after removing CP2171's
30 ms over-capacity confound, not a new backpressure policy.
