# CP2180: deadline-write RF-offset correction, no RF

Date: [date-redacted] Europe/Zurich

## Root-cause audit

OCUDU computes each chunk deadline from the lower-PHY sample timestamp and
compares it directly with Soapy hardware time. The LiteX worker later adds
`M2SDR_SOAPY_TX_TIME_OFFSET_NS` before releasing that same chunk to RF.
Deadline-write mode therefore judged every chunk early by the configured TX
offset: 30 ms in CP1715 and 20 ms in the current shape. This mechanically
explains CP1715's near-stream-wide `deadline_write_breaks` and abandonment
despite clean LiteX late counters.

## Patch

`radio_soapy_tx_stream` now caches the existing
`M2SDR_SOAPY_TX_TIME_OFFSET_NS` once as
`tx_deadline_write_time_offset_ns`. Only the already default-off
`OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT` selector uses it, adding the offset to
the lower-PHY deadline before computing guarded hardware-time lead. Addition is
saturated at signed 64-bit limits.

The startup and periodic/stop summaries expose
`deadline_write_time_offset_ns`. No new environment control, queue, retry,
carry behavior, timing constant, PRACH path, or default-on behavior is added.
With deadline-write disabled, `select_tx_data_write_timeout()` returns the
unchanged fixed timeout before consulting the corrected deadline.

## Verdict and next

PASS, no RF. Add a default-off frozen-runner surface for deadline-write enable,
guard, and max timeout while keeping retry/carry/deadline-carry off. Then run
one bounded no-UE gate at 20 ms lead, pool64, refresh 50 us, guard 2 ms, and max
50 ms. Require telemetry offset `[date-redacted]`, zero internal deficit/timeouts/
partials/abandonment/breaks, no late-context rows, and normal PRACH progression.
