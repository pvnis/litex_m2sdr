# CP2189: RAR-event late arm for PUxCH ordering, no RF

Date: [date-redacted] Europe/Zurich

## Purpose

CP2188 reached UE-decoded RAR and Msg3 preparation with the coherent 20 ms-era
UL retiming pair, but all five gNB PUSCH attempts remained CRC KO. Cross-host
timestamps suggested that upper-PUSCH decode may run before the shifted
lower-PHY grid is complete, but did not prove ordering in one clock domain.

## Patch

The existing default-off `PAVONIS_PUXCH_ORDER_TRACE` gains one cached,
default-off control:

`PAVONIS_PUXCH_ORDER_TRACE_LATE_ARM`

When enabled, trace events are rejected before their row counter, formatting,
or write path until `puxch_order_trace_arm()` fires. The existing in-process
RAR PDU event calls that arm after its event selector passes and before any UL
symbol arm-file requirement, so a trace-only run does not need raw capture.
The arm emits one marker; subsequent rows retain the existing bounded metadata
format. With the trace disabled, `take()` returns through the existing cached
enable check and the RAR arm path is not reached unless the separately
default-off in-process event control is enabled.

The established CP1807 runner now forwards and records the new flag. No sample
scan, threshold, timing, scheduler, RAR payload, or default-on behavior changes.

## Verdict

PASS, no RF. Run one otherwise frozen CP2188 shape with PUxCH trace enabled,
limit 512, late arm enabled, and the in-process arm event set to `rar_pdu`.
Judge health first. On a valid RAR/Msg3 run, require the Msg3 allocation end
symbol's `puxch_grid_symbol_written` timestamp to precede
`upper_pusch_task_start`. If it does not, fix the decode trigger; if it does,
ordering is closed and the next branch is Msg3 sample/CFO/coherence.
