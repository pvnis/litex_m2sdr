# CP2203: target capture reaches real Msg3 but taps the unshifted buffer

Date: [date-redacted] Europe/Zurich

Stamp: `[date-redacted]CP2203_SCHEDULED_MSG3_TARGET_CAPTURE`

## Mechanics And Health

The RF run executes and packages both hosts, but returns `overall_rc=1` because
the [host-redacted] stop SSH attempt times out. Packaging therefore races the still-live
gNB: the original tar has no Soapy stop summary or atexit UL-symbol manifest and
reports changing gNB logs. Independent binary-safe counters before packaging
are zero for Soapy timeout, downlink-late, and release-late events, but the
strict authoritative stop-summary health gate remains void.

The stale gNB receives SIGINT during cleanup and exits. A corrected `ps -C gnb`
postcheck proves no gNB remains. Graceful exit recovers the complete 85-line
manifest (header plus 84 symbol rows); the finalized gNB log still has no Soapy
stop summary.

## Ladder Result

SIB1 and seven UE Msg1 attempts pass. Stage 1 selects six, the gNB allocates and
encodes six RARs, and the UE accepts one: RAPID 0, temp C-RNTI `0x4602`, TA
`124`, RAR slot `3244`, Msg3 slot `3250`. The UE prepares and encodes one Msg3.
CP2086 classifies `msg3_reached_gnb_crc_not_ok`.

The initial gNB Msg3 result at system slot `3250` is CRC KO with EPRE
`-42.177 dB`, RSRP `-56.937 dB`, SINR `-19.321 dB`, residual timing
`-0.071 us`, CFO `-277.5 Hz`, and total EVM `7.612`.

The exact UE host Msg3 is coherent: expected subcarriers `[-216,-180)`,
inside/outside power `49.11 dB`, nearest-QPSK EVM `0.238`, and uniform symbol
power.

## Target-Capture Result

The scheduler/lower target table works mechanically: six publishes, six
completions, zero expirations, and exactly `6 x 14 = 84` raw CF32 files. Target
1 is exactly labeled `sfn=325 slot=0`, the scheduled Msg3 slot, and contains
11,520 samples.

However, target 1 is floor-class rather than Msg3: raw RMS is approximately
`0.000226`, its strongest 36-bin window is FFT-shift index `366` rather than
expected index `168`, expected-band power is `-1.32 dB` versus outside median,
and static-channel correlation to the exact host waveform is only `0.315`.
All six target slots have the same floor signature; the real target is not
distinguished.

## Source-Level Correction

This does not prove that the active PUxCH detector input is empty. With the
frozen non-PRACH offset `-237336`, `process()` sends PUxCH through the separate
`process_non_prach_shifted()` state machine and suppresses PUxCH processing on
the normal path. CP2203's raw instrumentation was placed only in normal
`process_collecting()`. It therefore captured the unshifted PRACH-path buffer,
not the shifted buffer delivered to PUxCH.

The source displacement is exactly `237336` samples (`20.602 ms`). Event timing
agrees: normal target 1 begins about one TX-lead interval before the UE can emit
Msg3. A relative PRACH-to-Msg3 wall-time join differs by `25.305 ms`; the PRACH
stage-1 search itself costs `2.484 ms`, leaving the same approximately 20-23 ms
class. Do not [interface-redacted] the offset from these wall clocks.

## Decision

Stay no-RF. Move scheduled-Msg3 raw capture to
`process_non_prach_shifted_collecting()` when the non-PRACH offset is active,
disable target consumption on the normal path in that mode, and flush each
completed target incrementally so a stop-SSH failure cannot hide the manifest.
Then run one bounded RF attempt and correlate the actual shifted PUxCH input
against the exact UE host Msg3 and upper-PUSCH EVM. Keep all timing, RF, stage1,
scheduler, payload, and gateware controls frozen.
