# CP2204: shifted-PUxCH Msg3 target capture, no RF

Date: [date-redacted] Europe/Zurich

## Correction

CP2203 proved the first scheduled-target implementation captured normal
`process_collecting()` samples while the active `-237336` non-PRACH path feeds
PUxCH from `process_non_prach_shifted_collecting()`. CP2204 corrects that
ownership without changing the offset or any radio behavior.

When the non-PRACH offset is nonzero, the normal path no longer matches or
consumes Msg3 targets. The shifted path matches the same fixed target table
against `non_prach_shift_current_slot`, writes each exact post-CFO/pre-PUxCH
symbol to `pavonis_puxch_target_*.cf32`, records the shifted sample timestamp,
and then passes that same buffer to `puxch_proc`. With zero offset, the original
normal-path diagnostic remains available.

The capture remains metadata/event-only outside exact target symbols. There is
no raw scan, file write, or target-table walk on the disabled path beyond the
cached false branch.

## Manifest Durability

The buffered manifest now supports incremental flush. Each completed target
flushes its fourteen rows immediately, appending later targets to the same TSV.
The normal atexit final flush remains. A stop-SSH failure can therefore no
longer hide completed target timestamps as it did in CP2203.
