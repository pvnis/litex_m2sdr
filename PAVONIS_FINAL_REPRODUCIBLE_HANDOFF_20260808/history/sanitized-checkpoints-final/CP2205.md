## Sample-Domain Join

The corrected post-CFO/pre-PUxCH target 0 contains the UE signal on the exact
expected 36 subcarriers (FFT-shift start 168, subcarriers `[-216,-180)`) with
`35.33 dB` inside/outside power. It is not aligned to symbol zero:

- target symbols 0-3 are floor, RMS about `0.000230`;
- symbol 4 is the transition, RMS `0.001051`;
- symbols 5-13 are signal-class, RMS `0.001607..0.001645`.

Direct sample correlation against nine independent host OFDM symbols places
the same waveform at a median lag of `3782` samples, range `3781..3783`, or
`328.3 us`. Per-symbol normalized correlation is `0.739..0.825`. This is a
deterministic placement error, not lost RF energy or host waveform corruption.

The no-UE target 1 remains floor for all symbols (`0.000227..0.000235` RMS),
has only `0.27 dB` expected-band inside/outside power, and its strongest FFT
window is index 367 rather than 168. That negative control rules out a static
instrumentation artifact.

## Verdict

PASS and decisive. CP2204 captures the exact buffer consumed by PUxCH. The
current non-PRACH collection starts `3782` samples too early for the real Msg3,
so the upper decoder sees floor for the first four symbols and a truncated
waveform afterward. This explains the CRC KO and extreme EVM despite an
in-range estimator TA/CFO result.

The source sign is explicit: lower PHY calls the shifted path with
`timestamp + offset`; a more-negative offset attributes later physical samples
to the same nominal slot. Therefore the single measured correction is
`-237336 - 3782 = -241118` samples. Before the next RF run, add the new target
filename to cleanup/fetch/summary handling. Then run one otherwise identical
bounded ladder attempt at non-PRACH offset `-241118`, keeping PRACH timing,
stage1/TA compensation, TX, RF, scheduler, payload, and thresholds frozen.
Judge first on initial Msg3 CRC and use the same shifted target to measure any
residual rather than [interface-redacted] open-loop.
