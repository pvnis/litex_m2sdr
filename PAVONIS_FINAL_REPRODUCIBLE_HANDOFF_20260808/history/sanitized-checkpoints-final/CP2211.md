# CP2211: accepted-stage1 dynamic non-PRACH offset, no RF

Date: [date-redacted] Europe/Zurich

## Purpose

CP2205 and CP2210 prove that one fixed non-PRACH receive offset cannot align
both accepted PRACH families. CP2211 implements the smallest source-level
discriminator: accepted negative stage-1 shifts select `-241118`, while
accepted positive shifts select `-237798`.

## Implementation

The new `pavonis_dynamic_non_prach_ul_offset.h` state is default-off behind
`PAVONIS_NON_PRACH_UL_RX_OFFSET_FROM_STAGE1`. Its configuration is read once.
One packed 64-bit atomic holds a signed offset and non-zero generation, so the
lower PHY consumes a consistent update with one acquire load.

The PRACH worker publishes only after stage-1 has selected an accepted
preamble-0 candidate. Zero-shift selections publish nothing. The event records
slot, shift, fractional shift, CFO, metric, selected offset, and generation,
with a default 64-row cap.

The lower PHY keeps the fixed `-241118` startup offset until a publish arrives.
On a new generation it switches the active offset. If the value changed, it
discards the partial shifted symbol and enters alignment once before consuming
the current input under the new timestamp. PRACH collection, nominal slot
attribution, CFO fanout, TA compensation, and normal-path behavior are
unchanged. With the feature disabled, the hot path takes only the cached false
branch and performs no atomic load.

## Verdict

PASS, no RF. Run one bounded CP2212 validation with the CP2210 shape otherwise
frozen. Require launch/result propagation, a publish and lower-PHY consume for
the accepted family, clean health, and an exact target capture. The primary
success criterion is initial Msg3 CRC OK; otherwise measure the signed target
residual and upper-PUSCH EVM/SINR without changing any other control.
