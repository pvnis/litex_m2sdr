# CP2214: coherent UE bladeRF TX guard bias (no RF)

Date: [date-redacted]

## Purpose

Implement the CP2213 source-level fix without changing scheduler, PRACH, RAR,
TA, RF, or gNB collection semantics: preserve the srsUE-requested timing
interval between PRACH and later high-peak bursts instead of recomputing each
burst from the current bladeRF TX hardware time.

## Source baseline and scope

The patch is built on the current deployed Pavonis srsUE baseline in
`srsRAN_4G/lib/src/phy/rf/rf_blade_imp.c`, including the existing CP193-era
bladeRF TX debug/guard, high-peak burst, restart, state, and bounded dump
instrumentation. No rolled-back tracking branch or threshold change was
introduced.

New default-off flag:

`PAVONIS_RF_BLADE_TX_DBG_COHERENT_GUARD_BIAS`

When disabled, the existing guard branch remains byte-for-byte in the fallback:
late forced-SOB timestamps become `pre_tx_timestamp + tx_guard_samples` on each
call. The new flag is read once in `rf_blade_open()` and stored in the handler;
there is no new per-call `getenv()`.

When enabled:

1. The high-peak call that restarts the TX stream keeps legacy guard handling.
2. The first post-restart forced high-peak call derives one nonnegative bias
   from the existing guard boundary.
3. Every later forced high-peak call adds that same cached bias to its original
   scheduler-requested timestamp.
4. The existing common `-16000` time adjustment remains unchanged after the
   guard stage, preserving relative PRACH-to-Msg3 timing.

The restart deferral is required by saved evidence: the first high-peak call in
CP2205/CP2210/CP2212 had a stale requested lead of `-67009/-60204/-108030`
samples after stream restart. Caching those corrections would delay all later
bursts by roughly 9-13 ms. The first post-restart calls instead occupy the
stable positive-lead class.

New bounded metadata fields report mode, initialization, restart deferral,
cached bias, requested/adjusted timestamp, and any shortfall against the
current 40000-sample guard boundary. One initialization marker is emitted.

Wrapper plumbing was added to:

- `cp1807_run_stage6_raresp40_realue_rar_msg3.sh`
- `cp193_sens_start_stage6_high_peak_tx_now_ue_remote.sh`

The outer runner defaults the flag to zero, exports it to [host-redacted], and records
it in `result.env`; both explicit CP193 runner/environment blocks preserve it.

## Saved-data replay gate

`cp2214_replay_coherent_guard.py` replays every saved high-peak metadata file
from CP2205, CP2210, and CP2212 using the implemented policy.

| Run | Cached bias | Worst guard shortfall | Minimum final TX lead | Requested interval | Replayed interval |
|---|---:|---:|---:|---:|---:|
| CP2205 | 26331 | 224 | 23776 | 403179 | 403179 |
| CP2210 | 24529 | 0 | 24000 | 414056 | 414056 |
| CP2212 | 19088 | 577 | 23423 | 403192 | 403192 |

Gate: PASS. Every PRACH-to-Msg3 scheduler interval is preserved exactly. The
worst post-restart shortfall is only 577 samples and still leaves 23423 samples
of final TX lead after the common `-16000` adjustment.

The static disabled/propagation gate also passes:

- source env occurrence one and read once in open;
- legacy disabled guard block present;
- restart call explicitly deferred;
- wrapper default/export/result paths present;
- both CP193 runner and generated-environment paths present;
- both shell files pass `bash -n`.

## Verdict and next run

CP2214 passes its no-RF implementation gate. The patch fixes the independently
recomputed UE burst interval identified in CP2213 and remains default-off
outside the prepared diagnostic.

`cp2215_run_coherent_ue_tx_guard.sh` layers exactly one enabled flag over the
CP2212 frozen RF shape. Judge the next run in this order:

1. normal host/TX/downlink health and propagation proof;
2. restart call deferred, exactly one post-restart initialization, cached bias
   stable, and no material `coherent_guard_bias_late_samples`;
3. accepted PRACH and RAR production;
4. if Msg3 is sent, emitted PRACH-to-Msg3 timestamp interval equals the original
   scheduler-requested interval (including TA);
5. exact target correlation and gNB Msg3 CRC.

The sign-only gNB mapping remains intentionally unchanged for that run. A CRC
KO can still be informative: coherent UE timing is proven by interval and
sample-domain residual, while the separate run-specific PRACH coarse mapping
remains the next collection-side fix.
