# CP2227 - RAR Timing-Advance Provenance No-RF

Date: [date-redacted]

## Purpose

Explain CP2226's exact `-6 samples * TA command` Msg3 residual before changing
source or spending another RF run.

## UE Provenance

The local and [host-redacted] sources are byte-identical:

```text
ta_control.h  9201a3a6e38d73d318288991a15bb2295dd19b6dd9d2179472bd962a321780ac
sync_sa.cc    b62cc10b3346b0c74020b2f942ac09a4aa2f7db1a52eb2a5997d1589488e5df0
```

The deployed srsUE is `12774c790e3d...`, was built after both sources, contains
the cell-numerology and TA log strings, and is not a stale pre-scaling binary.

The decisive runtime row is:

```text
event=cell_select_numerology slots_per_subframe=1 slot_len=11520
```

This frozen Band 3 shape uses 15 kHz SCS (`mu=0`), not 30 kHz. The UE therefore
correctly applies `TA * 16 Ts`. At 11.52 Msps, one RAR TA command is
`520.833 ns`, exactly six samples. CP2226's slope is valid UE behavior, not a
missing numerology divide.

## gNB Path

The detector returns a physical `phy_time_unit`; the scheduler encodes
`time_advance.to_Ta(ul_scs)` into the RAR. The existing default-off stage-1 TA
compensation adjusts that physical detector result by the selected transform
before MAC notification.

The exact six CP2226 strong windows were transformed with their live-selected
candidates and replayed through the unchanged CP1965 detector harness. Applying
the same selected-shift compensation and `to_Ta(15 kHz)` conversion predicts:

| Window | Shift / frac / CFO | Detector delay | Predicted TA | Air RAR TA |
|---:|:---|---:|---:|---:|
| 0 | `0 / 0 / 0` | 80 | 120 | 120 |
| 1 | `0 / 0 / 0` | 81 | 122 | 122 |
| 2 | `0 / 0 / 0` | 5 | 8 | 8 |
| 3 | `64 / -0.5 / 5k` | 56 | 179 | 179 |
| 4 | `64 / -0.5 / 10k` | 2 | 98 | 98 |
| 5 | `-192 / -0.5 / 20k` | 99 | 0 (clamped) | 0 |

The transmitted commands come from the six RAR payload prefixes
`03c0/03d0/0040/0598/0310/0000`. Prediction matches all six exactly. The
lower-PHY selected-candidate result therefore has enough information to derive
the exact RAR-equivalent TA before publishing the accepted-edge offset.

## Root Cause

The accepted-edge publisher aligns generic non-PRACH collection to the
pre-TA PRACH arrival. The UE then advances Msg3 by the RAR command, while the
gNB keeps the pre-TA target. That omission predicts CP2226 directly:

```text
TA 122 -> 732 samples early; measured 734
TA 179 -> 1074 samples early; measured 1073
```

## Decision

Implement one default-off edge-mode option that:

1. retains the selected candidate's physical TA and detector resolution;
2. applies the same selected-shift compensation and zero clamp as the upper
   detector path;
3. quantizes through `to_Ta(pusch_scs)`, exactly as the scheduler does;
4. converts that command back with `phy_time_unit::from_timing_advance()` at
   the live RU sample rate; and
5. subtracts those samples from the edge-derived generic non-PRACH offset.

This changes neither the RAR payload nor scheduler behavior. It makes PUSCH,
PUCCH, and SRS collection follow the exact TA the UE will apply. The disabled
path and existing edge behavior must remain byte-for-byte equivalent when the
new flag is off.

No RF was transmitted in CP2227.
