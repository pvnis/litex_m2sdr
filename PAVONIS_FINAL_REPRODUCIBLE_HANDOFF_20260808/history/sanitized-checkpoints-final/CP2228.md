# Checkpoint 2228: TA-aware accepted-edge offset patch (no RF)

Date: [date-redacted]

## Question

Can the accepted-PRACH energy-edge publisher include the exact quantized RAR
timing-advance term identified by CP2226/CP2227, without changing RAR payload,
scheduler semantics, PRACH timing, or the disabled path?

## Implementation

Added the default-off environment flag:

```text
PAVONIS_NON_PRACH_UL_RX_OFFSET_EDGE_INCLUDE_RAR_TA
```

When the flag is enabled, the lower PRACH worker now:

1. Retains the selected stage-1 candidate's physical delay and detector time
   resolution.
2. Applies the same selected-shift adjustment and clamp used by the upper PRACH
   result path.
3. Quantizes that value to the RAR TA command with the active PUSCH SCS.
4. Converts the quantized command back to the exact 11.52-Msps duration.
5. Subtracts that duration from the accepted-edge-derived generic non-PRACH
   collection offset before publishing it to the shared PUxCH timing state.

The adjustment helper was factored into
`pavonis_prach_stage1_ta_compensation.h` so the lower publisher and upper RAR
path use one implementation. The publish trace now records
`rar_ta_command` and `rar_ta_samples`. PUSCH, PUCCH, and SRS continue to consume
the same generic non-PRACH offset; slot attribution is unchanged.
