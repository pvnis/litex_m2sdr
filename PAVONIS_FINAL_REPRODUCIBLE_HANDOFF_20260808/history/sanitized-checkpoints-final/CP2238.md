# Checkpoint 2238: RAR-bearing order trace exposes arm-condition bug

Date: [date-redacted]
Stamp: `[date-redacted]CP2238_PUXCH_ORDER_TRACE_RETRY2_RF`

The exact retry is healthy and reaches the required epoch: SIB1 passes, six
strong PRACHs select, six RARs are encoded, the UE accepts two and sends Msg3,
and the gNB records `0/30` PUSCH CRC OK/KO. Launch propagation remains correct:
trace1, limit500, late-arm1.

Nevertheless, there are zero arm or order events. Source audit identifies the
mechanical cause in `rar_pdu_assembler.cpp`: `puxch_order_trace_arm(event)` is
called only after `pavonis_gnb_inprocess_ul_symbol_arm_event_enabled(event)`
passes. This run intentionally has `PAVONIS_GNB_INPROCESS_UL_SYMBOL_ARM=0`, so
the function returns before arming the independent order trace.

Verdict: valid ladder datapoint, ordering void due source-level arm coupling.
Do not enable the unrelated UL-symbol arm as a workaround. Move only the
default-off order-trace arm call ahead of that gate, then build/deploy with
disabled-path proofs and retry once.
