## Existing OCUDU control

OCUDU already exposes top-level YAML:

```yaml
expert_phy:
  pusch_dec_max_iterations: <positive integer>
```

The current source default is `6` in `du_low_config.h`; the CLI/YAML schema
maps `pusch_dec_max_iterations` directly to that factory value. No decoder
source change or binary rebuild is needed.

## Minimal runner change

The [host-redacted] config generator now accepts optional
`PAVONIS_GNB_PUSCH_DEC_MAX_ITERATIONS`. If unset, it inserts nothing and the
compiled default remains `6`. If set, it validates a positive integer and
inserts only the top-level `expert_phy.pusch_dec_max_iterations` value.

Both legacy terminal runners preserve the optional value, but source audit
found that the active CP2250 chain terminates in `cp1807`, not `cp1733`.
`cp1807` therefore exports the value in its remote environment prefix and
records it in settings/manifest output. This closes a potential filtered-env
void before RF.

The new thin alias `cp2251_run_msg3_pusch_10iter_diagnostic.sh` sets only:

```text
GNB_PUSCH_DEC_MAX_ITERATIONS=10
```

and then executes the unchanged CP2249 shape.
