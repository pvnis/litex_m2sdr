## Source finding

`sync_sa.cc` derives every slot's UL timestamp from the latest
`last_rx_time`, adds the normal FDD advance, and then subtracts TA. Therefore
sample corrections made by DL tracking between PRACH and Msg3 are inherited
directly by the UE's requested UL hardware time. CP2256 measured those
PRACH-to-Msg3 residuals at `-64..+75` samples.

The fix does not edit `ue_sync_nr.c`. It adds a default-off sample-domain clock
in `sync_sa` behind:

```text
PAVONIS_SRSUE_UL_TX_LATTICE=1
PAVONIS_SRSUE_UL_TX_LATTICE_MAX_SLEW_SAMPLES=1
```

Enabled mode advances the prior output by the exact logical slot length and
allows the new RX-derived timestamp to slew it by at most one sample per slot.
The lattice is applied before the existing TA subtraction, so RAR/MAC TA
semantics are unchanged. It resets on cell/numerology reset or a noncontiguous
TTI jump. Runtime work is timestamp arithmetic and counters only; there is no
sample scan, allocation, file write, or per-slot formatting. A single summary
prints on orderly reset/stop.

Disabled mode returns before timestamp conversion. Both environment values are
read once during `init`; the apply function contains no `getenv`. The header
default is `ul_tx_lattice_enabled=false`.

trustworthy TA-zero CP2256 rows. It also restores the neutral edge calibration
`-237332`; CP2256 proved the active `-237265` value injects about `+67` samples.

- neutral mapping error across saved rows: `-5..+6` samples
- PRACH-to-Msg3 interval: `35..39` slots
- projected target-lag envelope: `-44..+44` samples
- short/long normal CP: `54/60` samples
- all projected rows inside the short CP: yes

The CP2257 alias therefore combines lattice `1`, slew `1`, and neutral
calibration `-237332`. It explicitly unsets the ten-iteration override so the
gNB returns to compiled default `6`. It otherwise inherits the CP2249 cap-30
candidate list, RAR worker trace, PUSCH runtime trace, and bounded target
capture.
