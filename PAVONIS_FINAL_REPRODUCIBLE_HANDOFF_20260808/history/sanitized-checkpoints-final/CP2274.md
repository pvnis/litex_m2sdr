## Explicit 30 ms provenance

The only compact readback env difference between CP2271 and CP2273,
`M2SDR_SOAPY_TX_TIME_OFFSET_NS=30000000`, is not the timeout splitter:

- current OCUDU source reads it into `tx_deadline_write_time_offset_ns`;
- that value is used only by `select_tx_data_write_timeout()` after
  `tx_deadline_write_timeout_enabled` passes;
- both compared runs have `OCUDU_SOAPY_TX_DEADLINE_WRITE_TIMEOUT=0`;
- the current ladder ancestry exports the same 30 ms value, and CP2082 proves
  that shape can be descriptor-clean and downlink-positive.

The key is therefore retained for the ladder shape and is not changed.

## Combined no-RF gate

`cp2274_run_combined_selfrx_worker_bladerf_capture.sh` composes existing,
unchanged instruments:

1. CP2270/CP2268/CP2075 starts the gNB-only all-timed worker gate with immediate
   DL-centered M2SDR self-RX.
2. After the start helper reports ready, the proven CP1219 bladeRF capture runs
   on RX1 at `1842506000/11.52M/9.216M`, gain request40, normal FIR, for
   2.88M samples.
3. The CP2075 runner stops/packages and applies CP2047 as before.

This produces one run-start class with worker descriptors, startup self-RX,
and external bladeRF raw IQ. The controller polls only the bounded local
sequence log; it does not poll a growing gNB mirror or run any UE/detector.

No RF or remote command ran in CP2274.
