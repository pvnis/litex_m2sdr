Date: [date-redacted]

## Change

CP2280 implements the CP2279 saved-IQ result without editing
`ue_sync_nr.c`. A default-off srsUE feature is controlled by:

```text
PAVONIS_SRSUE_SFN_ACQ_HANDOFF=1
PAVONIS_SRSUE_SFN_ACQ_TARGET_OFFSET_SAMPLES=[date-redacted]
```

Both values are read once in `sync_sa::init()`. After the existing cell search
has decoded PBCH and the separate slot synchronizer has been configured, the
enabled path:

1. seeds SFN FIND with the successful cell-search CFO;
2. computes one discard as `(search_t_offset + 11520 - [date-redacted]) % 11520`;
3. gives that discard to the existing one-shot `next_rf_sample_offset` receive
   path, placing the repeated SSB at sample [date-redacted] of subsequent 1 ms buffers.

The observed CP2265/2266/2278 offsets `387/4817/9245` map to discards
`9859/2769/7197` and all result in offset [date-redacted]. The SFN trial limit remains
100. No RF, threshold, timing constant, cell-search acceptance, or tracking
logic changes.

Disabled mode does not call the new setter and emits no handoff line. The
setter itself performs only two scalar assignments; there is no sample scan,
allocation, file write, per-call environment read, or `ue_sync_nr.c` change.
