## UE propagation defect

`PAVONIS_SRSUE_SR_PUCCH_TRACE=1` appears in the controller sequence settings,
and the deployed UE binary contains all trace strings, but the packaged UE log
has zero trace rows. The generated `run_srsue_bounded.sh` passes an explicit
allowlist through `sudo -n env`; it includes prior SI/RAR/SFN/lattice flags but
not the new SR/PUCCH flag or limit. `launch.env`/`result.env` omit them as well.

This is the same propagation-failure class previously codified at CP2054. It
is not evidence that no UE SR opportunity or PUCCH encoding occurred: the UE
again reached `sr-TransMax`, which requires successful SR opportunities in
`proc_sr_nr`.
