# CP2320: Corrected gain propagation exposes a dynamic Msg3 timing failure

Date: [date-redacted] (Europe/Zurich)

## Verdict

RF execution PASS; Stage 8 power hypothesis unjudged; Msg3 timing diagnosis
PASS. The requested bladeRF TX gain propagated and read back at `66 dB`, but
the run reached only one real Msg3. That Msg3 retained normal EPRE and an exact
host-to-gNB waveform correlation of `0.884`, yet arrived `-126` samples from
the captured PUSCH window after a UE timestamp residual of only `+6` samples.
The unexplained `-132` sample displacement exceeds the short cyclic prefix and
explains the CRC failure.

- UE requested PRACH-to-Msg3 residual `+6` samples;
- lag minus requested residual `-132` samples;
- published PRACH-edge offset `-231552`, from edge `-5780` and calibration

The first CP2319 CRC-OK Msg3 is a clean control: correlation `0.869`, lag
`-26`, and edge contrast about `22 dB`. CP2320's relevant edge used only
`4.0 dB` of 80th-to-20th-percentile contrast.

## Edge Root Cause

The widened PRACH window contains only about 19% active waveform in this
displacement class. Therefore the current 80th percentile can still be noise.
Recomputing the saved window with the 90th percentile moves active stop from
`4624` to `4496`, edge from `-5780` to `-5908`, and the derived non-PRACH
offset by `+128` samples. Applied to the measured `-126` lag, it predicts a
`+2` sample residual.

Across all saved controls, the 90th-percentile edge leaves all six CP2319
good-class windows unchanged. It changes four of six CP2320 partial-occupancy
windows; the exact Msg3-producing window changes by the required `-128` edge
samples. This names a specific estimator defect rather than a new static
offset.
