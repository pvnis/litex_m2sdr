## Patch

The existing default-off `PAVONIS_UL_SYMBOL_MSG3_TARGET_CAPTURE` diagnostic now
also publishes fallback-scheduler C-RNTI PUSCH allocations into its existing
target table. No new runtime flag or propagation path is introduced. The
existing shared `PAVONIS_UL_SYMBOL_MSG3_TARGET_MAX` cap remains eight targets,
so a supplied run records Msg3 plus at most seven post-Msg4 PUSCH allocations.
Only those exact target symbols reach the already-proven shifted-symbol writer.

The [host-redacted] helper retains up to 16 pre-TX SC16 dumps instead of eight only
when both `PAVONIS_PUSCH_CSI_TRACE=1` and target capture are enabled. With
either flag off, the historical eight-dump behavior is unchanged. CP2328 shows
the first data PUSCH arrives immediately after dump eight, so this bounded
extension is necessary for an exact waveform join.

The prepared wrapper preserves the frozen CP2328 ladder and enables target
capture/max8, raw-max128, and the existing PUSCH CSI trace. It changes no RF
gain, gate, timing constant, grant, scheduler decision, or decoder behavior.
