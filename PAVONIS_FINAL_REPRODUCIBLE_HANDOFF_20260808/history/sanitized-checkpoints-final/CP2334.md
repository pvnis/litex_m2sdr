## Decisive trace

The UE emitted two live mismatches:

```text
tti=9281 queued_ta_sec=0 current_ta_sec=0.000013021 delta_samples=150 tx_enable=1
tti=9282 queued_ta_sec=0 current_ta_sec=0.000013021 delta_samples=150 tx_enable=1
```

Both transmitting workers were queued before the RAR TA update and reached
`worker_end()` after it. Current code uses the queued timestamp unchanged, so
these transmissions omit the newly commanded 150-sample advance.

This resolves CP2331's timestamp evidence exactly. CP2334's accepted RAR trace
reports command `0`; the 150 samples are the mandatory Band 3
`N_TA_offset=25600`, converted by `ta_control` to 400 LTE time units or
`13.0208 us`. CP2331's RAR command 52 contributes another approximately 156
samples at SCS30, for about `150+156=306` total, matching its observed
`+301..+343` Msg3-to-data timestamp step. Msg3 uses the stale pre-TA timestamp
while later connected-mode workers are queued after TA is current. CP2333's
zero mismatch is therefore a no-transition class, not a global rejection;
CP2334 supersedes that provisional interpretation.

## Correct fix shape

At `worker_end()`, start from the queued timestamp and subtract exactly
`current_ta - queued_ta`. This is idempotent: it does nothing when the queued
timestamp already includes current TA and applies only the missing handoff
delta. Implement it behind a new default-off, environment-cached flag and emit
a bounded metadata row when applied. Do not subtract full current TA again,
restore the old commented line verbatim, or change gNB collection timing in the
same patch.

The first RF test of that fix must judge Msg3 health before connected-mode
uplink. Advancing Msg3 by the commanded TA may expose that the frozen gNB
non-PRACH collection calibration was centered on stale Msg3; if so, measure the
new residual and recalibrate only after the UE semantic fix is proven.
