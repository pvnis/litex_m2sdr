# CP2347 - Security PUSCH target capture late arm deployed (no RF)

Date: [date-redacted] Europe/Zurich

## Question

Can the existing bounded PUSCH target capture skip Msg3 and early connected
uplink allocations, then start only after the first decoded UplinkNAS so its
eight-target budget covers the SecurityModeComplete TBS60 attempts that first
failed in CP2346?

## Patch

The current CP2329 target table gains one cached, default-off switch:

`PAVONIS_UL_SYMBOL_MSG3_TARGET_LATE_ARM`

When target capture and late arm are both enabled, target publication remains
silent until `rrc_ue_impl::handle_ul_info_transfer()` calls the new one-shot
arm function. This event is the decoded Authentication Response UplinkNAS in
the CP2346 procedure, before the core sends Security Mode Command. The arm
emits one metadata marker and does no sample work. With late arm disabled, the
existing target capture publishes exactly as before.

The established CP1807 runner propagates the flag to [host-redacted] and records it in
the settings log and result environment. The CP2347 wrapper enables only this
flag over the frozen CP2345/CP2344 shape. It changes no RF, PRACH, TA, grant,
scheduler, timing, threshold, gain, MCS, qcore, or decoder setting.

## Verdict and next

PASS no-RF. One frozen CP2348 RF run is unlocked while both hosts remain
reachable. Require launch/result proof that target capture/max/late-arm are
`1/8/1`, then require the arm marker after the first UplinkNAS and target index
zero after that marker. If SecurityModeComplete PUSCHs are captured, replay
their exact shifted grids against the same-run successful Authentication
Response before changing any live timing, phase, power, or decoder setting.
