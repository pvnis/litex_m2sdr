## Shape and health

This is the frozen CP2348 `1/8/1` capture shape on the CP2349 gNB. No RF,
qcore, TA, PRACH, MCS, grant, timing, threshold, or decoder setting changes.

Both host and pre-UE gates pass. Soapy timeouts and downlink-late rows are
zero; the stop summary has one historical 480-sample logical partial return,
zero stream deficit, and zero errors. SIB1 and qcore NAS-security activation
pass, so the run remains a good/early-pass downlink class.

## Arm and publisher result

The first UE context has three pre-arm TBS60 PUSCH attempts at system slots
5957/5987/6017. The first two are CRC KO at `-23.12/-31.83 dB`; the third is
CRC OK at `+5.27 dB`. Its UplinkNAS handoff emits exactly one arm marker.

CP2349 then works as intended: all eight post-arm targets are normal C-RNTI
`0x4604`, not temp-C-RNTI Msg3. Every target completes with all 14 symbols:

`6074, 6103, 6110, 6130, 6132, 6161, 6165, 6171`

The package contains 112 target CF32 files and 112 manifest rows, with one arm,
eight publications, eight completions, and one limit marker.

## Remaining capture miss

The eight scheduled connected grants consume the table before the first
post-arm upper-PHY PUSCH result rows at system slots 6420 and 6489. Those rows
are CRC KO (`TBS51`, `-18.83 dB`; `TBS201`, `-45.62 dB`) during the qcore
NAS-security interval. The saved targets therefore prove the common publisher
but still do not provide an unambiguous exact PDU/result pair for the failing
security response. Offline replay remains parked.

Increasing the cap would add avoidable lower-PHY raw work. Source audit provides
a more precise event: after the Authentication Response enters
`handle_ul_info_transfer()`, the next active-state
`handle_dl_nas_transport_message()` carries the Security Mode Command. A new
default-off mode can prime on that UL event and arm on that following DL event,
without changing CP2347's default semantics.

## Verdict and next

PASS publisher, capture still inconclusive. Add the default-off DL-after-UL arm
mode with one prime marker and one arm marker, propagate it through the frozen
runner, and complete the normal no-RF deployment gate. Then run one frozen
retry. Do not increase the cap or [interface-redacted] timing, phase, power, MCS, or decoder
behavior before that event-precise capture.
