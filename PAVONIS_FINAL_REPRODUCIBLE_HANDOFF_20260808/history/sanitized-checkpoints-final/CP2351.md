# CP2351 - Security-command epoch arm deployed (no RF)

Date: [date-redacted] Europe/Zurich

## Question

Can the cap-eight connected-PUSCH capture arm at the Security Mode Command
instead of at the preceding Authentication Response, avoiding CP2350's eight
intermediate grants without increasing lower-PHY raw work?

## Patch

One cached, default-off mode is added:

`PAVONIS_UL_SYMBOL_MSG3_TARGET_ARM_ON_DL_AFTER_UL`

With capture, late arm, and this mode enabled:

1. `handle_ul_info_transfer()` records a one-shot metadata-only
   `target_primed` event and does not arm.
2. The following active-state `handle_dl_nas_transport_message()` calls the
   existing one-shot arm before queuing its DL NAS PDU. In the proven qcore
   sequence this is the Security Mode Command after the Authentication Response.
3. Normal connected-PUSCH publication remains the CP2349 path and starts at
   target index zero only after that DL event.

With the new mode disabled, CP2347's arm-on-UplinkNAS behavior is unchanged.
No target cap, sample work, RF, grant, scheduler, HARQ, TA, timing, MCS, qcore,
power, threshold, or decoder behavior changes.
