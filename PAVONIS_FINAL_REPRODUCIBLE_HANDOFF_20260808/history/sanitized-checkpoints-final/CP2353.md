## Question

Which gNB InitialContextSetup branch returns the unsuccessful outcome observed
by qcore in CP2352?

## Patch

`initial_context_setup_routine.cpp` adds one cached, default-off flag:

`PAVONIS_GNB_INITIAL_CONTEXT_TRACE`

When enabled, it emits at most 16 metadata-only rows to the binary-safe gNB
mirror. The rows distinguish start, success, and every existing early-failure
branch:

- security-context initialization
- empty RRC Security Mode Command context
- F1AP UE-context setup
- missing RRC SecurityModeComplete
- invalid stored UE capability
- UE-capability transfer

The trace does not alter a condition, cause, timeout, message, transaction,
scheduler decision, sample, or protocol state. With the flag unset, the
environment is read once and the trace returns before its atomic counter or
output path.

The CP1807 runner now defaults the flag to zero, propagates it through the
quoted [host-redacted] child environment, records it in settings/manifest output, and a
new CP2353 wrapper enables it while preserving the complete CP2351 frozen
shape.
