# CP2357 - Default-off in-window RAR phase-47 selector deployed

Date: [date-redacted] Europe/Zurich

## Question

Can the CP2356 scheduled-slot-phase discriminator be implemented without
changing the default scheduler, RAR payload, power, response window, or UE
decode gate?

## Implementation

`ra_scheduler.cpp` now reads the cached environment variable
`PAVONIS_GNB_RAR_TARGET_SLOT_MOD160`. Unset or empty returns `-1` and leaves
the existing scheduler path unchanged. Values outside `0..159` are rejected
and also leave the selector disabled.

When enabled, `is_slot_candidate_for_rar()` first proves that a pending RAR's
existing response window contains the current PDCCH slot. It then postpones a
non-matching slot through the existing `log_postponed_rar()` path with reason
`PAVONIS target slot mod160`. It does not alter the RAR PDU, power fields,
search-space geometry, response-window bounds, failure counters, or later
candidate checks.

The CP1807 runner propagates the value through the quoted remote child,
records it in settings and the result manifest, and defaults it empty. New
wrapper `cp2357_run_rar_target_mod47.sh` selects `47` and chains through the
CP2353 InitialContextSetup diagnostic shape. Syntax and propagation evaluation
pass with `47`.

## Verdict and next

response window, and inert by default. Run one fresh frozen RF diagnostic with
target `47`. Judge health first, require postponed-slot telemetry and actual
RAR allocations at `mod160=47`, then compare UE RAR correlation/decode supply
against CP2354/CP2355. If the ladder reaches InitialContextSetup, use the
already-deployed CP2353 terminal-reason trace; do not change the UE `0.5` gate,
power, payload, TA, MCS, or PRACH shape.
