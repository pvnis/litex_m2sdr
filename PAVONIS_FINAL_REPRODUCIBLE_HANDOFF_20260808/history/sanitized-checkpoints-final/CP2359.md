# CP2359 - Existing metadata cannot split good and blind RAR presentation

Date: [date-redacted] Europe/Zurich

## Question

Can retained CP2352 and CP2358 artifacts identify the lower-TX difference
between UE-decoded and UE-blind high-energy RAR occasions without new RF?

## Cross-run result

CP2352 contains five UE-decoded RAR PDCCH rows: one at phase `49` and four at
phase `47`, with EPRE `32.996..33.522` and correlation `0.589981..0.694209`.
CP2358 contains six phase-47 rows with equivalent EPRE `32.404..33.733` but
correlation only `0.045477..0.387689`.

The gNB-side RAR records match on every semantic field visible in retained
artifacts: RA-RNTI `0x39`, AL4/CCE0, 37-bit DCI payload `0300000000`, common
search-space geometry, PDSCH allocation/TBS, power profile, `+6` SS offset,
and power-sign state. Both worker traces are 65,536 rows over about 5.814 s and
CP2047-clean: all writes are full MTU, with zero short non-EOB, late, dedup, or
duplicate HAS_TIME-source rows.

Before ladder progress, the timed-anchor patterns are also equivalent: both
runs show one 12-anchor interval followed by one 23-anchor interval. CP2352's
later 405/3529-anchor burst begins only after the UE advances through RAR and
connected traffic; it is a consequence of progress, not a pre-RAR splitter.

Thus FAPI, power, amplitude, descriptor flags, and observable write health do
not distinguish the two classes. The retained artifacts contain no exact RAR
baseband samples below lower-PHY modulation. Existing
`PAVONIS_SOAPY_TX_WRITE_DUMP_*` begins at stream startup and performs a file
append on every write; it is unsuitable here because it would fill before UE
start and reintroduce a known high-volume observer.

## Bounded capture design

Add a default-off capture immediately after lower-PHY downlink baseband
generation and before `transmitter.transmit()`:

- cache all environment configuration once;
- remain inert until an arm file exists, polling at a bounded interval;
- after the existing pre-UE arm, capture only system slots whose
  `slot % 160 == 47`;
- write the existing CI16 port buffer directly, with no per-sample scan or
  conversion in the runtime path;
- cap at 64 one-millisecond slots, about 3 MiB at 11.52 Msps/one port;
- emit a small manifest containing system slot, modulo, sample timestamp,
  sample count, port, and file path.

The pre-UE-to-first-RAR delay consumes roughly 15-25 phase-47 slots; a 64-slot
budget spans 10.24 s and covers the observed six-RAR epoch. Offline, join the
manifest to FAPI slots and run only exact RAR buffers through
`ue_dl_nr_file_test` configured for RA-RNTI `0x39`, common CORESET0, AL4/CCE0,
and symbols `2..13`.

## Verdict and next

PASS no-RF audit; existing metadata is exhausted. Implement the bounded
default-off lower-PHY capture with disabled-path, cap, arm, build/deploy, and
runner-propagation proofs before one diagnostic RF run. A host-side RAR DCI
decode with a simultaneous UE-low row puts the defect below lower PHY; a
host-side low/KO exact slot puts it in modulation/baseband generation. Keep
phase targeting diagnostic-only and do not change the UE gate, RAR payload,
power, TA, MCS, or PRACH shape.
