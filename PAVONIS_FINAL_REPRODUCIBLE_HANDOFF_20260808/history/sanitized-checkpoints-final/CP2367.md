# CP2367 - Delayed non-PRACH UL exceeds both upper-PHY retention depths

Date: [date-redacted] Europe/Zurich

## Question

Does OCUDU already retain enough upper-PHY slot state for the measured
`21..26 ms` delayed non-PRACH receive path, or is CP2366 reusing the slot
processor/repository before shifted samples arrive?

## Source audit

`du_low_config_translator.cpp` hard-codes the uplink pipeline depth to
`nof_slots_per_frame`. At 15 kHz SCS this is 10 slots/10 ms, and the same value
sets `upper_phy_cell.nof_ul_rg`; the upper-PHY factory creates exactly that
many uplink processors.

Separately, `uplink_processor_pool_impl.h` uses a compile-time circular
assignment table of only 16 slots. FAPI repository setup stores the selected
processor in this table by system slot; the later receive-symbol callback
looks up the processor through the same table.

The normal `expert_phy.max_proc_delay` knob does not change this UL pipeline:
it affects the DL pipeline, PRACH buffers, and request headroom, while UL
remains fixed at one frame. There is therefore no existing config knob that
can cover CP2366's delayed path.

## Join to CP2366

- Active dynamic non-PRACH offset after the successful RAR:
  `-243778` samples = `21.161 ms`.
- Observed slot3309 scheduler-to-PHY-result latency: `25.648 ms`.
- Current UL processor pool lifetime: `10 ms`.
- Current assignment-table collision period: `16 ms`.

Both retention depths are shorter than the measured result latency. The
failure signature follows mechanically: new PUSCH grants are configured, the
processor assignment/repository is reused before their shifted symbols are
handled, upper slots are discarded with zero processed symbols, and later
HARQ retransmissions cannot reserve the missing original buffer. The rare
CRC-OK TBS528 result arrives after the scheduler/MAC transaction is stale.

This also unifies CP2361's discarded PUCCH ACK with CP2366's connected-PUSCH
storm: both are consequences of delayed symbols outliving the upper-PHY slot
state. CP2366's slot2007 positive control shows the channel processors are
sound when timing happens to land inside the lifetime.

## Minimal fix design

Add a default-off Pavonis UL-pipeline-depth override at DU-low translation.
Unset preserves the exact upstream 10-slot path. With the override active,
use 40 slots, which covers the measured 26-slot latency with 14 slots of
headroom and aligns to four frames.

The slot-to-processor assignment table must cover the same delayed interval.
Keep the existing 16-entry table as the default path and use a separate
64-entry table only while the override is active. This avoids sample copying,
per-sample work, scheduler semantics changes, and threshold/timing retuning.
