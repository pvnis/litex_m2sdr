## Root cause

The first synthetic gate reproduced CP2379's watcher delay without RF. The
address-add row reached the filter, but the shell pipeline waited for the
still-running `ip monitor` producer until its 20-second timeout. In CP2379 the
next teardown event caused the producer to notice the closed pipe, which is why
the helper advanced only after `[interface-redacted]` had disappeared.

## Fix

`cp2380_prearmed_netlink_userplane_probe.sh` replaces that pipeline with a
direct Python standard-library RTNETLINK listener inside `[interface-redacted]`. It subscribes
to IPv4 address events and exits only on `RTM_NEWADDR` for `[ip-redacted]`.
Deletion events cannot satisfy the trigger. The helper records the structured
event and verifies that `[interface-redacted]` still owns the address before reading
counters or sending packets.

The path remains event-driven and idle before the address event; it does not
poll RF logs or repeatedly fork namespace commands.
