## Descriptor gate

The existing CP2047 parser sees 65,536 full 1022-sample descriptor rows in
each run. CP2379/CP2381/CP2382 all have zero short non-EOB rows, zero late
rows, zero dedup suppression, and no duplicate HAS_TIME source or release
timestamps. Slip stays in the same approximately 20.7 ms class. The CP2074B
descriptor fix is working in both pass and fail runs.

## Verdict

The repeated Msg4 failures are not missing energy, scheduler/FAPI geometry,
Soapy descriptor churn, namespace setup, or the packet watcher. They are the
known scheduled-slot coherence lottery below the clean descriptor layer. The
second CP2382 retransmission also shows that a recovered PDCCH can still waste
the opportunity on an MCS7 PDSCH coherence failure.

## Next

Use one conservative robustness control before more RF: expose the scheduler's
existing `scheduler_ue_expert_config::max_msg4_mcs` as a default-off Pavonis
override and set it to MCS2 only in the packet-proof wrapper. This preserves
post-RRC `max_ue_mcs=9`, all PDCCH thresholds, payloads, timing, RF, and
credentials. It does not claim to fix the coherence root cause; it makes a
rare DCI-success slot more likely to carry Msg4 successfully by trading more
PRBs for a lower code rate. Build/deploy and disabled-path proofs are required
no-RF before another packet run.
