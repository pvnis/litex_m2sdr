# CP2384 - Msg4-only MCS2 control is ready

Date: [date-redacted] Europe/Zurich  
RF: none

## Question

CP2383 isolated the current post-Msg3 failure to scheduled-slot coherence:
Msg4 EPRE remains normal, but PDCCH correlation and PDSCH EVM vary enough to
flip whole attempts. This checkpoint prepares a conservative robustness
control that lowers only the scheduler's existing Msg4 cap from its upstream
default of MCS9 to MCS2. The connected-UE `max_ue_mcs=9` cap, RF geometry,
timing, stage1, TA, thresholds, credentials, and packet probe remain unchanged.

## Implementation

`du_high_config_translators.cpp` now reads
`PAVONIS_GNB_MAX_MSG4_MCS` once while generating the DU-high configuration.
Unset or empty preserves the existing scheduler default exactly; integers
`0..9` override `out_cfg.ue.max_msg4_mcs`; invalid input terminates with a
specific configuration error. The enabled path emits one startup marker:

```text
PAVONIS_GNB_MAX_MSG4_MCS active value=2
```

The value is propagated and recorded through the active CP1807 runner chain.
New wrapper `cp2384_run_msg4_mcs2_packet_proof.sh` sets only
`GNB_MAX_MSG4_MCS=2` and delegates to the frozen CP2362 ladder shape.
