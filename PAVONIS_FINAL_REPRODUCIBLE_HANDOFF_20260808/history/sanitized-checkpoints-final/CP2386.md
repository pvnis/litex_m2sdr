## MCS2 result

The gNB has `dl_bo=297` bytes for ConRes plus SRB0/RRCSetup. Under the static
MCS2 cap it cannot fit that payload in CORESET0's available PRBs, so it
deliberately schedules only the contention-resolution CE:

```text
slot 839.8 newTx: MCS0, 3 PRB, TBS9, dl_bo=297
slot 842.7 retx:  MCS0, 3 PRB, TBS9
```

The UE decodes the retransmission with C-RNTI correlation `0.759840`, PDSCH
CRC OK, SNR `+14.370 dB`, EVM `0.249`, and returns PUCCH ACK1 at slot843.1.
It reports `Random Access Complete`.

This is a real robustness win for ConRes, but not a full Msg4/RRCSetup pass.
No SRB0 PDSCH follows because the same static cap still cannot carry the
297-byte RRCSetup. A later 528-byte UL grant is not RRCSetupComplete: the
binary-safe MAC log decodes it as `SBSR: bs=0, PAD: len=525`. The PHY CRC is
OK at EPRE `-50.133 dB`, SINR `+5.064 dB`, but qcore correctly sees no
InitialUE. The packet probe times out without an address event; `[interface-redacted]` cleanup
passes.

## No-RF semantic proof

OCUDU's existing
`test_srb0_buffer_size_exceeding_max_msg4_mcs_index` codifies this exact
behavior: if SRB0 exceeds `max_msg4_mcs`, the scheduler may send ConRes alone
and must not schedule the oversized SRB0. Both FDD/TDD parameterizations pass
locally. The scheduler searches MCS from zero upward; CP2383's selected MCS7
is therefore already the minimum that fits this 297-byte payload in the
current geometry. Trying static MCS3..6 would repeat the same semantic wall.

## Verdict and next

The static Msg4-wide MCS2 policy is rejected for the attach path. It proved
that a low-MCS ConRes-only transmission is highly decodable, but it cannot
carry or subsequently schedule RRCSetup while the cap remains active.

Next stay no-RF and implement a distinct default-off ConRes-only cap: apply
MCS2 only while the ConRes CE is pending, while leaving the existing
`max_msg4_mcs=9` default for the remaining SRB0. Add a scheduler unit test that
requires low-MCS TBS9 ConRes, ACK completion, and a later SRB0 allocation at
the normal minimum MCS7. Remove MCS2 from the packet wrapper's static
`max_msg4_mcs` path. Only after local/native disabled/enabled proofs should one
RF run test the split policy.
