# CP2387 - ConRes-only MCS2 scheduler control, no RF

Date: [date-redacted] Europe/Zurich

## Question

Can the robust CP2386 contention-resolution grant remain at low MCS without
also capping the 297-byte SRB0/RRCSetup grant that requires MCS7?

## Implementation

Added default-off `PAVONIS_GNB_MAX_CONRES_MCS=0..9` on the current CP2384 gNB
baseline. The value is read once while translating DU-high configuration and
stored as optional scheduler expert configuration. When ConRes is pending and
the option is set, fallback scheduling selects a standalone ConRes TBS using
that ceiling. Once ConRes is complete, SRB0 still uses the unchanged upstream
`max_msg4_mcs=9` ceiling. Unset preserves the previous scheduler path.

The existing static `PAVONIS_GNB_MAX_MSG4_MCS` diagnostic remains default-off
for provenance, but the new packet-proof wrapper explicitly unsets it and sets
only `GNB_MAX_CONRES_MCS=2`. No RF, timing, PRACH, TA, power, threshold,
payload, credential, or post-RRC MCS setting changed.
