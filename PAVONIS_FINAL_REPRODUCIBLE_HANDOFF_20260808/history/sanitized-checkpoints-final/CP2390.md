# CP2390: fallback DL AL8 startup failure

Date: [date-redacted]  
RF execution: gNB startup attempted; UE never started  
Verdict: configuration-invalid, ladder-void

## Shape

Fresh `[interface-redacted]` and add-only RTNETLINK probe, frozen CP2388 ladder, ConRes MCS2,
fallback downlink AL8, and SearchSpace1 candidates `[0,0,1,1,0]`. No other
intentional setting changed.

## Result

The gNB start helper timed out after 180 seconds (`rc=124`), the native-
continuous readback gate had no data, and the wrapper correctly skipped UE
startup. There is no cell-search, PRACH, RAR, Msg3, RRC, or packet datapoint.
The packet probe was still waiting when the ladder ended and `[interface-redacted]` cleanup
passed.

The packaged config proves the requested common candidate vector was present,
but the runner also synthesized its legacy dedicated-PDCCH compatibility block:

```yaml
pdcch:
  dedicated:
    ss2_type: common
    dci_format_0_1_and_1_1: false
  common:
    ss1_n_candidates: [0, 0, 1, 1, 0]
```

The gNB rejected that combination before radio startup:
`Invalid configuration DU cell detected: 256QAM MCS table cannot be used for
PDSCH with fallback DCI format in SearchSpace#2`.

## Interpretation

This does not judge AL8 and is not a connectivity, RF, or scheduler failure.
The runner coupled any `pdcch.common` override to an unrelated legacy
`pdcch.dedicated` override. The correction is runner-only: when SearchSpace1
candidates are the sole PDCCH change, emit only `pdcch.common`; preserve the
legacy dedicated block for branches that explicitly request its compatibility
settings. Validate the exact corrected shape with `ru_dummy` before RF.
