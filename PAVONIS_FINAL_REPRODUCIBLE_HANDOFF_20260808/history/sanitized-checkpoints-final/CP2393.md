## RF Port Audit

CP2392's generated config uses `driver=LiteXM2SDR`, one channel, NR band 3,
ARFCN 368500, 10 MHz, PCI1, PLMN [network-id-redacted]. CP1886 proved this selects M2SDR
TX0/RX0. The added antenna was reserved on the otherwise unused M2SDR pair, so
the certified channel-0/cabled srsUE shape will not directly drive it.

The current LiteX plugin can parse `channels=1` and route one-channel DMA to
TX2/RX2. However, OCUDU constructs its channel vectors and per-port
sample-rate/frequency/gain configuration as channel index 0. Using only the
device argument would therefore create split control: DMA on physical channel
1 while OCUDU gain/readback remains on channel 0. That is not a valid phone
baseline, especially for uplink RX gain.

## Interpretation

No phone-side, SIM, APN, NR-mode, core-file, or band-support blocker is visible.
The next no-RF task is a default-off logical-to-physical Soapy channel offset
that applies consistently to setupStream, channel configuration, readback, and
post-setup gain reassertion. Build it as a separate phone binary/artifact and
leave the CP2392 gNB and runner unchanged.
