# CP2403: phone is automatic/NR-enabled but has no NR signal

Date: [date-redacted] Europe/Zurich
RF executed: no
Phone settings changed: no

## Result

Read-only ADB evidence rules out a disabled or manually pinned modem as the
immediate CP2402 cause:

- allowed network types include NR;
- preferred-network settings are present for the device and active sub;
- airplane mode is off and mobile data is on;
- the loaded SIM HPLMN matches private `00101`;
- network selection is `false(automatic)`, not manual;
- voice/data remain OUT_OF_SERVICE and current operator does not match `00101`.

Android's generic `SignalStrength` object always contains NR/LTE/WCDMA object
types, so object presence alone is not evidence. The targeted values show NR
and LTE are invalid-sentinel/level-0. The only real signal is unrelated WCDMA:
`ss=-79 dBm`, `rscp=-90 dBm`, level 3, and WCDMA is primary. There is no NR
cell-info or physical-channel configuration.

The first audit command is parser-void because an unescaped awk `$1` trips
`set -u`. The corrected compact audit and one targeted 956-byte signal line are
append-only and read-only.

## Interpretation

The phone configuration is compatible with automatic private-PLMN discovery,
but neither CP2402 nor the post-run audit exposes NR energy/cell state. This
still does not prove whether channel1 RF was absent at the handset or present
but not reported while unregistered.
