# CP2408: Direct-CF32 replay method is invalid for PBCH

Date: [date-redacted] Europe/Zurich
RF transmitted: yes, bounded matched control

## Result

CP2408 repeats CP2407 byte-for-byte except `TX_CHANNEL=0`, using the certified
cabled M2SDR TX0 to bladeRF RX1 leg. The offline-PBCH-positive input, sample
rate, bandwidth, RF/SSB centers, attenuation, amplitude, loop count, capture
geometry, and decoder are unchanged. All mechanics and cleanup pass.

The cabled RX1 amplitude is strong: `-25.39 dBFS`, max component 901, versus
CP2407 TX1/RX1 `-45.10 dBFS`. It is nevertheless one-shot PBCH KO and the
complete aligned sweep is `0/847` PBCH and `0/847` CSI PCI1. RX2 is
`-29.28 dBFS`, max 527, and its one-shot is also KO.

## Root cause and interpretation

This negative control invalidates CP2407 as a channel1 link-margin result.
The current direct-CF32 `test_play.py` file loop is not partial-return safe:
it calls `writeStream()` once for each block and only checks negative returns.
A positive short return causes the unwritten block remainder to be abandoned.
That explains why the same path passes a continuous tone while corrupting the
sample continuity needed by PBCH.

The CP1166 helper is the correct discriminator. It uses `write_all()` to retry
every positive short return until the requested chunk is complete, emits
short/error counters, uses the patched CS16-to-SC12 path, and already accepts a
channel argument. Next run matched CP1166 A/B on TX0 and TX1 with the CP1481
payload tar and dual RX1/RX2 captures. Do not infer anything about channel1 NR
margin from CP2407, and keep the phone parked.
