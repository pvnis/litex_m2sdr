# CP2411: TX-backoff bracket is configuration-void

Date: [date-redacted] Europe/Zurich
RF transmitted: yes, one bounded gNB-only channel1 run

## Result

CP2411 requested the CP2410-planned single-variable bracket with
`TX_BACKOFF=7`, RF attenuation 5 dB, physical M2SDR channel1, bladeRF RX2 gain
56, and the phone held passive. Channel mapping, retained readback, capture,
ADB monitoring, host postchecks, and cleanup all completed.

The decisive sequence record reports `tx_backoff=10`, not 7. Therefore this
checkpoint is configuration-void for the intended power axis and must not be
used to conclude anything about a 3 dB baseband increase.

The independent RX2 capture is consistent with the unchanged CP2410 class:
`-18.136 dBFS`, max component 896, no clipping, one-shot PBCH KO/no CSI, and
`0/847` PBCH/CSI PCI1 windows. The phone produced 19 rows with no private PLMN,
service, NR, or cellular IP. These observations are retained as mechanics and
repeatability evidence only.

The runner's final `overall_rc=1` is expected for this stop-before-UE gNB-only
shape: the channel/health gates passed (`gate_rc=0`, `late_gate_rc=0`,
`ue_started=0`), while unavailable full-ladder raw/authoritative-stop artifacts
failed their inapplicable packaging gates.

## Root cause and fix

The wrapper chain was traced from CP2389 to CP1807. The first destructive
assignment is in `cp2188_run_coherent_20ms_ul_retime_ladder.sh`, which exported
`TX_BACKOFF=10` unconditionally. CP1807 already uses a default-preserving
`${TX_BACKOFF:-10}` assignment.

CP2188 now exports `TX_BACKOFF="${TX_BACKOFF:-10}"`. This preserves the frozen
10 dB default while allowing a caller's explicit bounded bracket to propagate.
The next checkpoint is no-RF propagation proof, followed by a fresh RF retry
only after both the sequence record and generated gNB config prove 7 dB.
