# CP2412: TX-backoff propagation passes no-RF

Date: [date-redacted] Europe/Zurich

## Result

The CP2411 one-line fix is dynamically proven through the complete production
wrapper chain from CP2389 through CP2188. The chain uses the real 22 wrapper
files and replaces only the final CP1807 endpoint with a local print-only stub,
so it cannot start qcore, gNB, SDR streams, or RF.

- Explicit `TX_BACKOFF=7` arrives at the endpoint as 7.
- Unset `TX_BACKOFF` arrives as the frozen default 10.
- The inherited RF attenuation remains 5 and physical-channel offset remains 1.

The live [host-redacted] config generator was audited read-only. It also defaults with
`${TX_BACKOFF:-10}`, passes the value as the Python config-transform argument,
substitutes it directly into `tx_gain_backoff`, includes it in the generated
filename, and prints the resulting config field. CP1807 serializes the same
value into the remote command as `TX_BACKOFF='$TX_BACKOFF'`.

This closes the propagation defect without changing the historical frozen
shape. A fresh CP2411-shape RF retry at 7 dB is unlocked. Before interpreting
the capture, require both the authoritative sequence line to say
`tx_backoff=7` and the generated gNB YAML to say `tx_gain_backoff: 7`.
