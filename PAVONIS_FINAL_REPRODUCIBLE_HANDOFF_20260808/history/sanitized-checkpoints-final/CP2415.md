# CP2415: Existing SSB power controls do not raise PBCH/SSS

Date: [date-redacted] Europe/Zurich
RF transmitted: no

## Result

The remaining power controls were traced end to end through the live generator,
OCUDU scheduler/FAPI path, and SSB PHY processor.

- `PAVONIS_GNB_SSB_BLOCK_POWER_DBM` can insert
  `ssb_block_power_dbm` into YAML, but that value is used for cell/RRC
  configuration and is not carried into SSB PHY amplitude.
- PBCH, PBCH DMRS, and SSS are each hard-coded to amplitude `1.0F` in
  `ssb_processor_impl.cpp`.
- The only SSB PHY ratio is `beta_pss`; it can nominally select PSS +3 dB, but
  the current `ssb_assembler.cpp` hard-codes `pss_to_sss_epre=dB_0` instead of
  using the parsed cell setting. Even if fixed, it would raise only PSS, not
  PBCH/DMRS/SSS needed for cell acquisition.
- The frozen `PAVONIS_GNB_POWER_CONTROL_OFFSET_SS_DB=6` fixture flows into
  PDCCH/PDSCH power configuration relative to SSS. It does not scale SSS or
  any other SSB component. The SI PDSCH sign-compat fixture is likewise a
  PDSCH-only translation.

## Interpretation

There is no existing config-only control that can raise the complete SSB on
channel1. Do not spend RF on `ssb_block_power_dbm` or PSS-only +3 as link-budget
experiments; neither supplies PBCH/SSS power.

The next software discriminator, if continuing remotely, is a minimal
default-off amplitude multiplier applied coherently to all four generated SSB
components (PBCH, PBCH DMRS, PSS, SSS), cached once and enabled only in a
separate phone diagnostic binary. Start with +6 dB while restoring global
backoff10, leaving roughly 4 dB nominal global headroom and preserving the
CP2392 golden and CP2401 phone binaries. No scheduler, payload, timing, SI, or
channel-mapping behavior should change. Gate no-RF on disabled-path identity,
enabled strings/config, separate binary hashes, and golden restore before one
bounded independent RX2 run.

If that controlled SSB boost cannot produce PBCH without clipping, stop
software power work: a physical channel1 link-budget improvement or calibrated
cabled phone path is required.
