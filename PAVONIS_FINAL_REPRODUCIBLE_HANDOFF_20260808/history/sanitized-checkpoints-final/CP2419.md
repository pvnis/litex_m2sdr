# CP2419: M2SDR TX attenuation 0 dB is a real live axis

Date: [date-redacted] Europe/Zurich
RF transmitted: no

## Result

CP2414's label-only conclusion is superseded. It correctly found that the
generated gNB YAML always uses `tx_gain: 0`, but it missed the separate live
OCUDU/Soapy override exported by CP1807:
`PAVONIS_SOAPY_TX_FORCE_ATT_DB=$TX_ATT`.

The complete live path is now established no-RF:

- OCUDU calls the LiteX named TX gain `ATT` when the override is active and
  reasserts it after `setupStream()`.
- The LiteX Soapy plugin advertises `ATT` range `0..89 dB`.
- `libm2sdr` accepts the same `0..89 dB` range and programs the AD9361 TX
  attenuation directly; `0 dB` is not clamped to the current `5 dB` fixture.
- The [host-redacted] checkout independently contains the same `0..89 dB` range and
  direct AD9361 programming path.
- The real 22-wrapper production chain, with only CP1807 replaced by the
  existing print-only endpoint, delivers explicit `TX_ATT=0` unchanged and
  retains `5` when the caller leaves it unset.

CP2188 now uses `export TX_ATT="${TX_ATT:-5}"`. This preserves the historical
5 dB default and allows an explicit diagnostic value without changing any
other run.

## Decision

One bounded channel1 gNB/RX2 run at `TX_ATT=0`, standard CP2401 phone binary,
global backoff 10, and bladeRF gain 56 is unlocked. It is not valid unless the
authoritative sequence records `tx_att=0`, the remote environment records
`PAVONIS_SOAPY_TX_FORCE_ATT_DB=0`, and the gNB readback proves physical TX
channel1 attenuation `0 dB` after stream setup. Judge TX health, clipping,
PBCH/CSI, and passive phone NR visibility. A failed readback is configuration-
void; a clean `0/847` result closes the remaining 5 dB remote hardware-power
bracket.
