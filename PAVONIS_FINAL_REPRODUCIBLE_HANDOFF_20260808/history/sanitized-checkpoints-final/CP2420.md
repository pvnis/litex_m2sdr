# CP2420: ATT0 reaches hardware but the inherited readback gate is stale

Date: [date-redacted] Europe/Zurich
RF transmitted: yes, bounded startup only; no bladeRF capture

## Result

The requested channel1 run starts with authoritative
`tx_att=0 tx_backoff=10`. Host-state gates and gNB startup pass. The archived
Soapy sidecar proves the live hardware setting took effect:

- logical TX row 0 (mapped to physical M2SDR channel1 by the phone binary),
- `gain_ok=1`,
- `gain_db=0.000000000`,
- `11.52 Msps`, CS16, all-timed cadence,
- zero Soapy timeout and zero downlink-late rows before the stop.

The run is configuration-void for RX2 and phone conclusions. CP1807's inherited
native-continuous readback gate still hard-coded the historical acceptable
range `4.9..5.1 dB`; it returned 22 on the correct 0 dB row, stopped the gNB,
and therefore CP2404 never armed or fetched either bladeRF capture. The passive
phone monitor also correctly remained off.

## Decision

Make the gate compare readback against the run's declared `TX_ATT` with the
same +/-0.1 dB tolerance. Prove archived ATT0 passes, archived ATT5 passes, and
ATT0 presented as ATT5 fails before retrying RF unchanged with a fresh stamp.
