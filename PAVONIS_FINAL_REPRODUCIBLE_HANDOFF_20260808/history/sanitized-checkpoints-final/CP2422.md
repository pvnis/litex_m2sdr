# CP2422: ATT0 passes radio gate but phone controller still assumes txatt5

Date: [date-redacted] Europe/Zurich
RF transmitted: yes, bounded gNB-only window; no bladeRF capture

## Result

CP2422 retries CP2420 unchanged after the CP2421 verifier fix. The sequence and
live sidecar again prove `TX_ATT=0` and `gain_db=0.0`; the corrected CP1807
radio readback gate passes rc 0. Physical-channel1 direct telemetry and TX
health are present, and cleanup/postchecks pass.

The run remains configuration-void for RX2 and phone conclusions. CP2395's
downstream propagation proof searches a hard-coded run-directory suffix
`txatt5`. The real append-only directory is correctly suffixed `txatt0`, so
the proof exits rc 2 before opening the readback, the passive phone monitor
stays off, and CP2404 never arms or fetches a bladeRF capture.

## Decision

Make CP2395 default `TX_ATT` to 5 but use an explicit caller value in the run
directory, gNB process-environment proof, and sidecar gain target. Test the
corrected predicates against the archived CP2422 ATT0 directory/readback and
retain the existing channel1 positive/negative markers before another retry.
