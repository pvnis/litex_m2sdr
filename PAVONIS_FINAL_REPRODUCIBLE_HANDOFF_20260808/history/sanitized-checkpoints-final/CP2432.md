default CP848 direct-CF32 starter while the input was the CP1223 tar archive.
The remote player exited `CF32_REPLAY_TX_RC=134` with an invalid buffer-size
error. Its `-37.14 dBFS` PBCH-negative capture is configuration-void because no
valid NR waveform was transmitted. The wrapper's aggregate return code did not

At the same receive gain as CP2409B, the lane fix raises measured RMS by
`6.84 dB` and restores PBCH with no clipping. This is the new TX2/RX2 OTA

## Verdict

The LiteX Soapy 1R1T frame-lane correction is repeatably effective at normal
observer gain. Keep the CP1166 starter explicit in future replay invocations;
do not infer TX health from the CP903 aggregate status without a terminal
`event=done` and zero error/short-write counters.

Next audit which Soapy module the frozen live gNB loads, back up that exact
module/source, deploy or rebuild the CP2429 lane fix into that path, and prove
the runtime hash before resuming the standard CP2401 phone shape.
