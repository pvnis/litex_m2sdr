# CP2439: Live versus exact timing-policy audit

Date: [date-redacted] Europe/Zurich  
RF transmitted: no

## Source and artifact join

CP2438 and CP2435 use the same lane-fixed source-tree Soapy module, physical
TX2/RX2 path, and CS16 conversion. They do not exercise the same timing policy:

| Property | CP2438 exact replay (PBCH pass) | CP2435 live gNB (PBCH fail) |
| --- | ---: | ---: |
| discontinuous TX | n/a, recorded rows | false |
| caller rows/writes | 4,028 per payload | 2,219,280 data writes |
| caller timed rows | 263 per payload (6.53%) | all 2,219,280 requested timed |
| align HAS_TIME remainder | unset/off | explicitly on |
| observed worker prefix | many retained timed anchors | 1 timed / 7,999 continuation |
| timeout/late errors | 0 | 0 |

The exact replay input totals 2,000,000 samples. Its rows are highly fragmented
(4,017/4,028 below MTU; median 482 samples), so its successful decode also
exonerates generic partial-buffer spanning. What it does not exercise is the
live pair of all-timed caller writes plus remainder-alignment suppression.

## Mechanical explanation

OCUDU all-timed mode applies HAS_TIME to every non-empty data chunk. The LiteX
driver's default-off alignment branch compares each incoming timestamp to an
existing partial DMA buffer; when within one MTU, it clears the new HAS_TIME
and fills that buffer as an untimed continuation. The frozen live launcher
explicitly enables this branch. The CP1207 replay launcher does not.

This is the first specific semantic difference left after CP2438. It is more
precise than generic cadence or timed-TX suspicion and requires no source,
power, gain, lane, phone, or gateware change to test.
