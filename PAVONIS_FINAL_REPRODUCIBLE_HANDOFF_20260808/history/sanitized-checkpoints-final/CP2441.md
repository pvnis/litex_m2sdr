# CP2441: Explicit all-timed override propagation

Date: [date-redacted] Europe/Zurich  
RF transmitted: no

## Scope

CP2440 proved that the CP1807 controller hardcoded all-timed mode to `1` at
the remote launch and in its readback gates. This patch adds one diagnostic
override without changing the frozen default:

`PAVONIS_SOAPY_TX_ALL_TIMED_CHUNKS_OVERRIDE`

- Empty/unset preserves historical value `1`.
- `0` or `1` explicitly selects the remote starter's effective all-timed
  value.
- Any other value is rejected before startup.

## Files

- CP1807 remote gNB starter: override precedence and validation;
  SHA `d3acb259...`.
- CP1807 controller: validated override forwarded through `ENV_PREFIX`, plus a
  dedicated readback gate for the override case; SHA `fb92422f...`.
- CP2395 phone controller: expected-value validation and a second runtime proof
  against both `/proc/$pid/environ` and `pavonis_soapy_tx_readback.txt`; SHA
  `f5b45466...`.

The source gNB binary, Soapy module, driver, gateware, RF configuration, power,
gain, lane selection, phone settings, and default runner behavior are
unchanged.

## No-RF proofs

- All three changed scripts pass `bash -n`.
- A nine-case base/override matrix over unset, `0`, and `1` passes; override
  wins when present and the fully-unset case resolves to `1`.
- Static propagation proof shows controller -> remote prefix -> starter
  precedence, and the CP2395 proof requires effective value agreement in both
  process environment and Soapy readback before monitoring/capture is accepted.
