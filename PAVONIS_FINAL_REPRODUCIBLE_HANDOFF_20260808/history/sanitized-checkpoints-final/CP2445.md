# CP2445: Intended 1 ms live control is configuration-void

Date: [date-redacted] Europe/Zurich  
RF transmitted: yes

## Intended control

Run the current phone-channel TX2/RX2 live gNB with all-timed mode disabled and
`TX_TIME_OFFSET_NS=1000000`. This was the single restoration control selected
by CP2443 from the CP1575/CP1666 pass-era 1 ms cadence.

## Runtime verdict

The all-timed proof passed, but the new time-offset proof correctly failed:

- requested outer value: `1000000 ns`;
- live Soapy readback: `env_M2SDR_SOAPY_TX_TIME_OFFSET_NS=[date-redacted]`;
- stop summary: `deadline_write_time_offset_ns=[date-redacted]`;
- `PHONE_GNB_TX_TIME_OFFSET_PROOF=PASS` absent, so phone monitoring was gated
  off and the run is configuration-void for the 1 ms hypothesis.

The RF side measured RX1 `-42.40 dBFS` and RX2 `-32.71 dBFS`, with `0/847`
PBCH and `0/847` CSI windows on both. These values describe the actual 20 ms
run and must not be interpreted as a 1 ms result. TX health remained clean:
one timed anchor, all following data writes untimed, zero timeout/error/
downlink-late lines, one 480-sample partial return recovered by final flush,
and zero final stream deficit.

## Root cause

The inherited wrapper chain reaches
`cp2188_run_coherent_20ms_ul_retime_ladder.sh`, which unconditionally exported
`TX_TIME_OFFSET_NS=[date-redacted]`. This overrode the caller's 1 ms request while
the outer phone controller still expected 1 ms. The proof therefore caught a
real propagation mismatch rather than producing a false RF verdict.

## Fix and next

Make CP2188's historical 20 ms value default-preserving:
`TX_TIME_OFFSET_NS=${TX_TIME_OFFSET_NS:-[date-redacted]}`. This keeps every existing
baseline unchanged when no override is supplied and allows the explicitly
approved 1 ms control to propagate. Rerun with a fresh stamp and require both
the all-timed0 and offset1ms process/readback proofs before interpretation.
