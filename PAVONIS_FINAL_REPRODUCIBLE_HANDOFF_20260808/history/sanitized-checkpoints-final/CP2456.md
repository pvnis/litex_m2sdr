# CP2456: Live partial-buffer carry corrupts framed DMA samples

Date: [date-redacted] Europe/Zurich  
RF transmitted: yes, bounded private-lab gNB-only run

## Shape and health

CP2456 repeated CP2454 on TX2/RX2 with the same 20 ms one-anchor cadence,
deadline-write policy, power fixture, accepted-write dump, 64 lower-PHY slots,
independent RX2 capture and phone monitor. The only additions were the bounded
CP2455 plugin-input and post-framing DMA dumps.

All runtime proofs pass. TX health is valid: zero Soapy timeout/error,
downlink-late and final stream-deficit counts. The bounded artifacts are exact:

- accepted-write CF32: `241920` samples
- plugin-input SC16: `241920` samples in `478` metadata rows
- post-framing DMA: `256` full `8192`-byte zero-copy buffers
- each DMA buffer: `1022` samples, two IQ lanes, no zero padding
- lower-PHY SSB files: `64`

RX2 remains externally blind at `-29.23 dBFS`, component max `984`, no
clipping, and `0/847` PBCH/CSI PCI1 windows. The phone has no private PLMN or
service; three generic NR-state rows do not establish cell acquisition.

## Boundary decodes

The accepted-write CF32 and plugin-input SC16 streams both decode the same
PCI1/MIB at `t_offset=116700`, SFN534, SCS15, CORESET0 index0 and SS0 index0.
The plugin input is therefore clean before interleaving/framing.

The DMA stream's active one-channel payload is lane0; lane1 is all zero. This
is expected for the current single-channel DMA layout: stream metadata selects
AD9361 TX2 while the sole logical stream is packed into frame lane0. The
reconstructed lane0 aligned sweep finds `4/71` PBCH-OK PCI1 windows, but the
best CSI SNR is only `+1.7 dB`. The first clean-boundary SSB is destroyed; a
later SFN535 SSB barely decodes near 20 ms.

## Sample-level proof

Converting the plugin-input SC16 stream with the deployed `/16` SC16-to-SC12
rule and comparing it against DMA lane0 gives:

- comparable samples: `241920`
- exact IQ matches: `236412` (`97.7232%`)
- mismatches: `5508` samples in `16` contiguous runs
- expected-component RMS / difference RMS: `70.60 / 58.04`

The corruption is sparse but lands on scheduled content. The SSB beginning at
sample `116700` intersects four zero/overwrite runs through sample `120160`.
Other mismatch runs begin at exact DMA-buffer boundaries, for example
`26572 = 26 * 1022` and `29638 = 29 * 1022`.

## Source mechanism

In the fresh-buffer branch of `writeStream()`, a caller write may first finish
the previous partial DMA buffer. The remaining source begins at
`samp_avail`, but the newly acquired destination buffer must begin at frame
offset zero. The current call passes `samp_avail` to `interleave()`, whose
implementations apply the same offset to both source and destination. It thus
leaves/overwrites a hole in the fresh DMA buffer. The surrounding assignment
of `remainderOffset = n` independently confirms that the intended destination
start is zero.

This explains why exact/full-buffer helper replays pass while the live gNB's
fragmented writes lose coherence despite clean lower-PHY and accepted-write
samples. It also explains the run-scale lottery: only scheduled signals that
intersect a carry corruption fail.

## Next

Patch only the fresh-buffer interleave call so the source advances by
`samp_avail` while the fresh destination starts at zero. Preserve the deployed
channel-offset and contiguous-untimed fixes. Build and run no-RF unit/fixture
proofs before deployment, then repeat this same bounded DMA discriminator as
the acceptance gate.
