# CP2466: Worker-trace RF attempt is instrumentation-void

Date: [date-redacted] Europe/Zurich
RF transmitted: yes, but no external diagnostic capture started

## Result

The frozen gNB starts and all phone-binary/channel/timing policy proofs pass,
but the shared late-arm gate returns rc1 before touching its file. Consequently
the RX1/RX2 capture and fetch never run (`CAPTURE_RC=99`), and no worker trace,
DMA dump, or [host-redacted] package is available for interpretation. The phone monitor
records 46 no-cell rows, but this is not a new RF datapoint because the intended
diagnostic epoch was never armed.

The small process-proof log identifies the missing field: the gNB environment
contains the requested DMA-probe arm and poll period, then fails before printing
the requested worker-trace arm. No capture-side TX was spent after that failure.

## Root cause

The wrapper chain reaches
`cp2246_run_rar_worker_pusch_runtime_dual_trace.sh`, which unconditionally
overwrites `M2SDR_SOAPY_TX_WORKER_TRACE_ARM_FILE_OVERRIDE` with its historical
RAR-event arm. CP2466's explicit shared arm therefore cannot reach CP2188 or the
gNB process. This is wrapper provenance, not an RF, driver, ring, or hardware
result.

## Verdict

Void for worker occupancy, RX2, phone, and ladder conclusions. Preserve the
fresh-stamp artifacts as append-only. Make CP2246's historical arm a default
instead of an unconditional replacement, prove explicit and default behavior
no-RF, then retry once unchanged.
