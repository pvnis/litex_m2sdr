# CP2474: Looped reader laps zero-anchor live TX and airs stale buffers

## Startup and sustained behavior

Removing HAS_TIME removes CP2473's 121 ms startup pin. Hardware count first
advances by handle24 at 2.126 ms and is already 248 at handle256/21.852 ms.
The reader is therefore active immediately enough to test producer supply.

It repeatedly laps the live producer. The trace has 65,536 submitted rows but
handles span 0..66,739: 122 jumps skip 1,204 handles. The first jump is
10->24 at 2.126 ms and jumps continue through 5.746 s. Producer lead is only
1..86 buffers, mean21.282; 63,467 rows are at 32 buffers or less.

## Source-level meaning

`DETECT_EVERY_UNDERFLOW` refreshes hardware count on every acquire. When
`user_count - hw_count` is negative, `_dmaAcquireWrite()` clears all TX header
flags and jumps `user_count` to `hw_count`; each trace handle gap is direct
evidence of that resynchronization.

The adjacent source comment says looped stale rereads become untimed “no-ops.”
That is false for the deployed gateware: `has_time=0` transitions directly to
STREAM and emits the stale payload. The caller still receives zero-error write
returns, but RF gets duplicated old buffers followed by a jumped host sequence.
That destroys OFDM/frame cadence without appearing in timeout/late/deficit
health counters.

## Verdict

CP2473 and CP2474 explain both live policies. The one-anchor path obtains a
queue by holding the first descriptor; the zero-anchor path immediately exposes
looped-ring stale replay. Passing helpers keep the ring supplied. The active
fault is now the mismatch between a continuously looping hardware reader and a
real-time producer, not waveform content, link power, SDR ports, or caller
write success.

Before writing a new zero-copy policy, test the current copy-mode implementation
with its existing priming path and a 16-buffer prime. A PBCH recovery would
validate priming/non-loop-stale semantics and may provide a temporary working
phone path. If copy mode fails health or RF, add a default-off zero-copy prime
gate with default1 preserving the deployed baseline.
