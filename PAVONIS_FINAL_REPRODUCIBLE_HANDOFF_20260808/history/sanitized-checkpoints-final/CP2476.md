# CP2476: Existing copy mode is RF-dead on the current live path

Date: [date-redacted] Europe/Zurich
RF transmitted: yes, bounded private-lab TX2/RX2 control

## Valid configuration

The gNB process environment directly proves physical channel offset1,
`M2SDR_LITEPCIE_ZERO_COPY=0`, and
`M2SDR_SOAPY_TX_COPY_PRIME_BUFFERS=16`. The run also retains ATT5,
all-timed0, force-continuous1, 20 ms configured offset, and deadline-write1.
The worker trace remains behind an untouched arm file. Controller, capture,
phone monitor, fetch, analysis, stop, package, and cleanup all pass.

Binary-safe health reports zero Soapy timeout, downlink-late, and release-late
lines. The copy-mode reader-enabled INFO marker is absent from both packaged
log routes, but direct process proof plus the driver's setup-time environment
read establishes the selected mode.

## RF result

RX2 falls from the zero-copy live class near `-32.4 dBFS` to `-37.00 dBFS`,
max118, unclipped, with `0/847` PBCH and `0/847` PCI1 CSI. This is the passive
capture-floor class rather than a differently corrupted NR waveform. All 46
phone rows remain without private PLMN, service, NR, or cellular IP.

## Verdict

The current copy-mode implementation is not a working temporary TX path on
this module/kernel combination. Its built-in prime cannot validate the
zero-copy stale-loop theory because the copy route itself does not put an
observable signal on TX2. Keep the deployed default at zero-copy1.

Next implement a minimal default-off zero-copy reader-prime setting, default1
for exact compatibility and bounded to the actual ring size. Prime128 is the
first diagnostic: enough startup headroom to absorb live scheduling jitter
without filling/wrapping the 256-slot ring before reader enable. Build and
deploy no-RF with disabled-path and strings/hash proofs before another RF run.
