# CP2481: Self-RX discriminator void at the outer wrapper

## Intended test

Run the CP2480 phone/channel1 shape with prime128, a 256-row startup trace,
and an immediate 250 ms M2SDR RX2 capture centered on the SSB, alongside the
established external bladeRF capture.

## Valid execution

The bounded RF run started the correct phone gNB, physical channel1 mapping,
zero-copy1/prime128/force-continuous1/all-timed0 path. Controller, capture, and
phone-binary propagation gates passed. Prime128 activated at handle/sequence
127 and the unique reader-enable marker is present. TX health has zero Soapy
timeouts and zero downlink-late lines.

## Shape override

The intended self-RX append did not reach the gNB. The inherited CP2188 shape
hard-sets `PAVONIS_SOAPY_RX_APPEND_ENABLE=0` and
`M2SDR_SOAPY_TX_WORKER_TRACE_LIMIT=65536`, overriding CP2480's explicit values.
No self-RX data or metadata file exists. The resulting 65,536-row trace again
caused 79 handle jumps and 876 skipped handles, matching the CP2478 observer
class.

The force-center/BW pass-through did work: the generated runner contains both
values and physical RX2 reads back exactly `1839650000 Hz`, `11.52 Msps`, and
`7.68 MHz`. That part of CP2480 is accepted and does not need another patch.

This checkpoint is therefore void for the same-device branch. The external
capture is independently negative (`-32.79 dBFS`, max `651`, `0/847` PBCH,
`0/847` PCI1 CSI), and the phone has no cell in 46 rows, but neither should be
used to judge an untraced TX path because the large trace was accidentally
restored.

## Decision

Change only CP2188's hard append-disable and trace-limit assignments to
default-preserving forms. Prove both unset defaults and explicit values no-RF,
then repeat the same-device discriminator. Do not change prime size, gains,
scheduler settings, or the deployed plugin.
