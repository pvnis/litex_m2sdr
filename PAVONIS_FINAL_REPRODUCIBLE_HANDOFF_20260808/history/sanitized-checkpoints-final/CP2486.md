# CP2486: Late self-RX void because detached starter rewrote the arm

## Execution

The controller, phone gNB, external capture, and CP2404 arm-touch gates pass.
CP2404 creates the intended shared file:

`/tmp/pavonis_cp2485_[date-redacted]CP2486_PHONE_CH1_PRIME128_LATE_SELFRX_RF_capture.arm`

The external RX2 result remains `-32.69 dBFS`, max `649`, and `0/847` PBCH/
PCI1 CSI. No self-RX data or metadata file exists, so this is not a same-window
comparison.

## Root cause

CP1807's controller correctly exported the custom `RX_APPEND_ARM`, but the
detached starter recomputed it from an absent
`PAVONIS_SOAPY_RX_APPEND_ARM_FILE` and fell back to the main PRACH arm. The
generated gNB runner therefore watched a different file than CP2404 touched.

## Fix and no-RF proof

The detached starter now selects the explicit PAVONIS arm first, an incoming
`RX_APPEND_ARM` second, and the historical main arm last. Its three isolated
expansion proofs produce `/tmp/explicit.arm`, `/tmp/incoming.arm`, and
`/tmp/main.arm` respectively; `bash -n` passes. No RF control, binary, plugin,
gain, prime, or trace limit changed.

Detached starter SHA256:
`9ad8d695ce79fcab5cf7fa224c0bee22291284463ca90a003c741262c6fbc957`.
