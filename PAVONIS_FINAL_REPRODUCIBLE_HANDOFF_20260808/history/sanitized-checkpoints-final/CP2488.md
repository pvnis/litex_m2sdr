# CP2488: Simultaneous RX2/self-RX capture gated no-RF

## Purpose

CP2487's external helper captured RX1 before RX2, so the negative RX2 samples
were not proven to overlap the positive M2SDR append. CP2488 replaces that
sequence with one synchronous `BLADERF_RX_X2` stream and extracts channel 1
(RX2) from libbladeRF's documented `I0,Q0,I1,Q1` interleave.

The capture process opens and configures the bladeRF before creating a ready
file. It then remains open and sleeps to an absolute `CLOCK_REALTIME` epoch.
[host-redacted] touches the M2SDR self-RX arm at the same epoch. Both actual starts are
recorded, so overlap is a measured gate rather than an assumption.

## No-RF proof

- [host-redacted] has `gcc` and libbladeRF `2.6.0-git-0bf98844` headers/library.
- Strict build passes with `-std=c11 -O2 -Wall -Wextra -Werror`.
- `ldd` resolves `libbladeRF.so.2` from `/usr/local/lib`.
- Usage-only execution exits `2` without opening the device.
- Binary strings contain ready, scheduled-start, actual-start, RX2 readback,
  and capture-OK fields.
- The controller passes `bash -n`; its closed RF gate exits `2` before network,
  device, gNB, or artifact activity.
- Fresh output, ready-file, arm-file, and stamp guards remain mandatory.

The first build attempt failed before binary output because `bladeRF2.h` was
included before `libbladeRF.h`. Reversing those two includes is the only source
correction; the repeated strict build passes.

## Run shape

The prepared CP2489 diagnostic preserves channel1, zero-copy1/prime128,
force-continuous1, all-timed0, 20 ms lead, deadline-write1, the 256-row startup
trace, and late 250 ms M2SDR RX2 append. The external capture stays at
`1842506000 Hz`, `11.52 Msps`, `9.216 MHz`, gain36, normal/DEC1 filter, and
2.88M samples. It is intentionally detection-void under CP1894.
