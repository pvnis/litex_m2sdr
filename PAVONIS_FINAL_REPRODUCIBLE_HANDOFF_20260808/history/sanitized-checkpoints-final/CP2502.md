# CP2502: Phone hardware supports n3 SA but active carrier policy is NSA-only

The exact device is OnePlus CPH2409EEA / Nord CE 2 Lite 5G, OxygenOS
`CPH2409_14.0.0.2200(EX01)`. OnePlus's own global and European specifications
list band n3 under 5G SA, so CP2501 does not justify moving the phone branch to
n78 on hardware-capability grounds.

The read-only carrier-config audit finds a concrete policy conflict. Android's
platform default is `carrier_nr_availabilities_int_array = [1, 2]`, while the
active immutable OnePlus default carrier bundle for MCC/MNC [network-id-redacted] supplies
`[1]`. AOSP defines value 1 as NSA and value 2 as SA. There is no carrier app,
persistent override, or runtime override, and production `adbd` cannot run as
root. Shell carrier-config writes and direct launch of the privileged OnePlus
engineering activity are permission-denied. No permission bypass was used.

Android's supported shell API can still change the user RAT mask. A bounded
no-gNB control switches slot0 from the exact full mask to NR-only, reads back
`NR`, and restores the original full mask exactly. After correction for the
TD-SCDMA bit, both `preferred_network_mode6` and the OnePlus mirror return to
33. This gives a reversible discriminator: run the proven Pavonis n3 broadcast
while the user mask is NR-only, then restore in a trap. With no LTE anchor, any
cell considered in that interval is necessarily an SA search candidate.
