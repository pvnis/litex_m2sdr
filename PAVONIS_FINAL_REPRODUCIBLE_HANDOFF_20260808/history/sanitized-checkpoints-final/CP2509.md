# CP2509: Standard manual-operator path traced and safely gated no-RF

The supported OnePlus network-operator path is now mechanically understood
without changing phone state or transmitting RF. The installed TeleService APK
is `/system_ext/priv-app/TeleService/TeleService.apk`, 31,197,408 bytes, SHA-256
`21611418...`.

Its manifest exports alias `com.android.phone.simsettings.NetworkSetting` to
the internal `com.android.phone.OplusNetworkSetting` activity. Launching
`com.android.phone/.simsettings.NetworkSetting --ei subscription 0` succeeds
and focuses that exact activity. Source provenance confirms the UI uses normal
telephony APIs:

- disabling automatic selection starts the modem network scan;
- selecting a result calls `selectNetworkManually(..., persist=true)`;
- restoration calls `setNetworkSelectionModeAutomatic()`;
- preference keys are `oplus_button_auto_select_key` and
  `list_networks_key`.

The new no-RF probe refuses to continue unless ADB is authorized, the keyguard
is not showing, and the starting network-selection mode is automatic. It only
then opens the exported activity and captures its UI tree. The current locked
gate returns rc20 with `BLOCKED_KEYGUARD=1` before any phone-setting change.
Post-check proves `isManualNetworkSelection=false(automatic)` and the complete
original RAT set including NR, LTE/LTE_CA, TD-SCDMA, GSM/WCDMA and CDMA/EVDO.

The next step requires the operator to unlock the phone and leave it unlocked.
Then rerun this probe with a fresh stamp, map the live switch/confirmation/list
nodes, and build the trap-restored manual-selection RF wrapper around the exact
CP2506 frozen NR-only shape. No RF or modem policy change is approved by this
checkpoint itself.
