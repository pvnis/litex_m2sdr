# CP2512: Passwordless phone can be kept unlocked remotely

The OnePlus production image rejects persistent ADB-shell changes to both
`stay_on_while_plugged_in` and `screen_off_timeout`: the shell lacks
`WRITE_SECURE_SETTINGS` and `WRITE_SETTINGS`. The failed writes leave the
original values unchanged at `0` and `300000 ms`.

This is not an office blocker. The phone has only the non-secure swipe
keyguard. Over the already-authorized USB ADB connection, `KEYCODE_WAKEUP`
followed by `wm dismiss-keyguard` changes the live state from
`showing=true`/`mInputRestricted=true` to
`showing=false`/`mInputRestricted=false`; power readback is `Awake`.

`cp2512_adb_bounded_keepawake.sh` codifies the remote fixture. It runs on
[host-redacted] for at most two hours, wakes and dismisses only the non-secure
keyguard at a bounded interval, changes no phone setting or credential, and
exits automatically. Use it only around an active phone experiment. The next
operator-list discriminator can proceed remotely with no phone taps during
the scan.

## Gate

- ADB state: `device`, authorized CPH2409EEA over USB.
- USB power: `true`.
- Original persistent values after denied writes: unchanged.
- Direct remote wake/dismiss: pass.
- Helper syntax and bounded live execution: pass.
