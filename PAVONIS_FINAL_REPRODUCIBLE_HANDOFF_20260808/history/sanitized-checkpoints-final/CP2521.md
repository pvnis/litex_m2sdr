# CP2521: Package fallback is reversible but config stays cached

The no-RF CP2520 transaction passes exactly. Standard `pm disable-user`
changes `com.android.carrierconfig` from original/default state `0` to
disabled-user state `3`, and the trap restores `pm default-state` to `0`.
Automatic selection and the full RAT mask remain unchanged before, during and
after.

Disabling alone does not change CarrierConfigLoader's effective snapshot over
ten seconds: unique NR values remain Android default `[1,2]` plus active
OnePlus `[1]`. This is cached-state evidence, not a failed fallback verdict.
The help audit exposes no shell SIM-power or carrier reload command. A clean
remaining discriminator is boot-time loading with CarrierConfig disabled,
followed by default-state restoration and a second boot to prove exact recovery.

No RF, root, APK mutation, carrier-config override, or reboot occurred in this
checkpoint.
