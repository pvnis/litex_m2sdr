# CP2523: OxygenOS re-enables CarrierConfig at boot; recovery clean

The two-boot no-RF discriminator reaches its intended first boot, but
OxygenOS changes CarrierConfig from disabled-user state `3` back to original
state `0` during boot. Effective NR values remain `[1,2]|[1]` and
`FALLBACK_DEFAULT_ONLY=0`. The script stops at the expected disabled-state
assertion and its trap performs the recovery boot.

The explicit postcheck is clean: ADB `device`, boot complete, package state
`0`, active default-plus-OnePlus values `[1,2]|[1]`, automatic selection, and
the exact full RAT mask. No RF ran and no persistent package/config change
remains.

This closes `disable-user` as a boot-time fallback. One last reversible
package-manager discriminator remains: `pm uninstall -k --user 0` leaves the
system APK intact and can be restored with `cmd package install-existing`.
Gate it with the same two-boot recovery discipline; if OxygenOS also restores
that package or active `[1]` persists, remote policy fallback is exhausted.
