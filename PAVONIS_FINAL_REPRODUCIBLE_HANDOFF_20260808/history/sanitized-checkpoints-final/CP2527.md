# CP2527: Static overlay ignores user package-disable state

The final bounded no-RF control targets the exact culprit overlay package.
Standard `pm disable-user` changes
`com.android.carrierconfig.overlay` from package state `0` to `3`, but
OverlayManager remains `[x]` enabled because the overlay is static and
`mIsMutable=false`. Exact `default-state` restoration returns package state
to `0`; OverlayManager remains enabled throughout.

No reboot, RF, CarrierConfig reload, network-selection change, RAT change, or
persistent package change occurs. This closes remote stock-firmware control of
the `[1]` overlay. Do not repeat base-package disable/uninstall, overlay package
disable, shell cc, manual operator scan, or nearby-test-PLMN branches.

The phone can still be kept remotely awake and its non-secure keyguard remotely
dismissed. An office visit is not needed for unlocking; it is needed only to
connect a different SA-capable handset or to undertake a separately approved
bootloader/firmware intervention on this OnePlus.
