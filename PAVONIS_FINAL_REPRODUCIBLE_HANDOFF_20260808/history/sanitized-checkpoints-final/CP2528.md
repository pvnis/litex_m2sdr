# CP2528: Existing 5G Switch path reopens phone policy control

The operator's recollection is correct. The phone already has `5G Switch`
(`com.sladjan.sava.petg`, version `4.0.1`) installed. Its `Go` -> `Auto`
sequence opens the platform's hidden
`com.android.phone.settings.RadioInfo` activity. The service menu exposes the
live `Set preferred network type` spinner, including `NR only`.

The phone also has working Magisk `29.0` root. No Magisk modem-policy module is
installed, and the short Termux history contains no prior 5G command. The app
itself does not require root; it is a launcher for the privileged platform
RadioInfo activity. Root does not make `cmd phone cc` available, so CP2527
still closes the stock CarrierConfig/overlay branch, but not this modem
preference branch.

A reversible no-RF control selected `NR only` through the app. The live
allowed-network set changed from the broad baseline to exactly `NR`, and
`preferred_network_mode6` changed from `33` to `23` while the separate Oplus
user preference remained `33`. Selecting `NR/LTE/GSM/WCDMA` back changed the
subscription mode to `26`, proving this UI mutates the preferred-mode state and
is not merely displaying the earlier CarrierConfig result. The exact CP2503
baseline was then restored with the full RAT mask and both
`preferred_network_mode6=33` and
`oplus_user_preferred_network_mode6=33`; all restoration assertions pass.

No RF ran and no setting remains changed. CP2527's conclusion is narrowed to
unprivileged stock-policy controls. The next discriminator is a frozen phone
OTA run with `NR only` selected through this existing app, with exact trap
restoration afterward. This differs from CP2506 because CP2506 changed only
the user allowed-network mask and left the subscription preferred mode at the
full `33` baseline.
