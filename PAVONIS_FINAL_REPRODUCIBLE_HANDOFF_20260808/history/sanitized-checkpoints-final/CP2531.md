# CP2531: Live-cell 5G Switch discriminator gated

The CP2530 cleanup defect is replaced, not patched around. A bounded remote
helper opens the installed app or platform RadioInfo, dumps the current
dropdown, locates the requested row by exact text and parsed bounds, taps its
actual center, and verifies the resulting live RAT/mode state. Its local and
deployed SHA-256 is
`08462904d74a5822e224a76383891e2128853dc468c2ee4caeabace239a2eabd`.
An app-driven `NR only` mode-23 selection followed by direct full mode-33
restoration passes live no-RF.

The new late-apply wrapper starts from exact full RAT/both mode33, launches the
unchanged frozen CP2500 controller, and waits for
`PHONE_GNB_PROPAGATION=PASS`. Only then does it invoke the installed app and
select `NR only`. The observation window and radio capture remain the existing
CP2500 path. Cleanup uses the text-locating helper and verifies exact full RAT
plus both mode keys at 33 on EXIT, INT, TERM, and HUP.

`bash -n` passes. The default RF gate returns `2` before artifact creation,
and fresh-stamp guards are active. Wrapper SHA-256 is
`f12b07f7f081de5521f466eb5201e15ae6654e5744c6288023e6a4afa57919ea`.
`shellcheck` remains unavailable on the local controller.

Run once with a fresh stamp and `PAVONIS_CP2531_RF_APPROVED=1`. This tests the
remaining faithful interpretation of the remembered workflow: change the
phone to 5G-only while the private cell is already live and visible, rather
than before the long gNB preflight/startup interval.
