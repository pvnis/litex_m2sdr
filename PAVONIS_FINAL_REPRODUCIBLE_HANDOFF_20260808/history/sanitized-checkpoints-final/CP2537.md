# CP2537: Userdebug read control is readiness-tooling void

The no-RF helper starts from and records exact `user`/full-RAT/both-mode33,
sets the runtime build type to `userdebug`, and restarts
`com.android.phone`. It exits before the CarrierConfig read because its service
readiness probe uses `cmd phone help`, which returns `255` on this OxygenOS
build even while telephony is healthy.

The process restart did occur (phone PID changes from the prior 3502 to 20890).
The EXIT recovery returns `ro.build.type=user`, restarts the phone process, and
post-readback proves full RAT, subscription mode33, and Oplus mode33. No
CarrierConfig value was read or written, no RF ran, and no state remains
changed. CP2537 is tooling-void for the userdebug-access hypothesis.

Use the functional, non-mutating
`cmd phone get-allowed-network-types-for-users -s 0` readiness probe instead;
it returns `0` while `cmd phone help` returns `255` in the same healthy state.
