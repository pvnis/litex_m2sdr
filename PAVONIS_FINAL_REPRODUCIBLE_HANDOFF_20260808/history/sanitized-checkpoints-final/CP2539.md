# CP2539: Phone kill-status return makes second read tooling-void

The corrected functional readiness probe is deployed, but the no-RF retry
still exits immediately after temporary `userdebug`. The phone PID changes
from the restored CP2537 process 20890 to 21644, proving the requested
`com.android.phone` termination and restart happened. OxygenOS nevertheless
returns nonzero from the enclosing `adb shell su -c kill` command as the radio
process exits, and the helper treated that status as restart failure before
observing the new PID.

EXIT recovery again restores `ro.build.type=user`, full RAT, subscription
mode33, and Oplus mode33. No CarrierConfig read/write and no RF occur. CP2539
is tooling-void for the access hypothesis.

The restart proof must be the bounded old-PID -> new-PID transition plus a
functional telephony read. Ignore the unreliable kill command status itself.
