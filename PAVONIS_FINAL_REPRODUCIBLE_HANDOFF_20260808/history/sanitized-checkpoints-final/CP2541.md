# CP2541: Phone-process restart cannot change inherited user build state

The no-RF control now clears both prior tooling confounds. It starts from exact
production/full-RAT/both-mode33, sets runtime `ro.build.type=userdebug`, and
proves a real `com.android.phone` PID transition `22318 -> 22364` plus
functional telephony readiness.

`cmd phone cc get-value` still returns permission denied from the newly
started phone process. The recovery path returns `ro.build.type=user`; final
readback proves full RAT, subscription mode33, and Oplus mode33, and the
CarrierConfig command remains denied. No value is written and no RF runs.

This rejects phone-process restart as sufficient. Android's zygote had already
initialized the framework `Build.TYPE=user`; a new app process inherits that
static framework state even after the runtime property changes. The result is
consistent with `TelephonyUtils.IS_USER` remaining true in the new phone
process.

Do not iterate phone-process restart again. The least invasive remaining
runtime discriminator is a bounded zygote/framework restart while the property
temporarily reads `userdebug`, followed by the read-only cc command, then
`user` restoration and a second zygote restart. Gate that path no-RF before
execution; no value write yet.
