# CP2544: SIM selection state is clean; no historical phone profile is recoverable

This no-RF audit closes the two read-only follow-ups from CP2543. The active
SIM database row is slot 0/subscription 6, MCC/MNC [network-id-redacted], HPLMN `00101`,
empty EHPLMN, carrier ID 1911, and the full user RAT mask (`916479`). The
standard phone preferences contain empty numeric/name/short manual-selection
keys for every retained subscription, so the modem is not pinned to another
PLMN. Neither the bounded CP2535 radio artifact nor the current 5,947-line
radio buffer contains an FPLMN marker for `00101`; the current buffer contains
no FPLMN marker at all. The telephony database has no FPLMN/forbidden column.

Production state remains exactly restored: build type `user`, airplane mode
off, full allowed RATs including NR, and both preferred-mode keys at 33. The
small OxygenOS state files add no conflicting selection: the Smart5G switch is
`-1`, the new-SIM dialog count is zero, and the PLMN CarrierConfig file only
contains its package version. No phone setting, SIM file, carrier bundle, or
modem state was written.

The two hosts each retain 2,000 shell-history lines. Narrow, deduplicated
searches for CPH2409, RadioInfo/5G Switch, preferred-network mode, the Pavonis
ARFCNs, and phone-gNB profile names return no earlier working phone command.
The grouped campaign memory also contains no phone attach before CP2393. There
is therefore no repository or host-history configuration to restore; the
operator's remembered prior success is useful evidence, but not a reproducible
baseline yet.

Archived CP2535 phone measurements also rule out the obvious broadcast
selection threshold. Fifteen valid NR samples span `-108..-79 dBm` with mean
`-83.4 dBm`; the final service snapshot is `SS-RSRP=-102 dBm`,
`SS-RSRQ=-14 dB`, `SS-SINR=0`. In SIB1, encoded `q-RxLevMin=-70` is the bottom
of the NR ASN.1 range and represents `-140 dBm` for the cell-selection
criterion; `q-QualMin=-20 dB`. Thus the measured Pavonis cell clears both
thresholds. CP2508's selectable-cell conclusion remains valid, but its report's
plain `-70 dBm` wording should not be compared directly to Android RSRP.

The next useful discriminator is an explicit manual request for PLMN [network-id-redacted]
while the already-proven app-driven NR-only mode and frozen phone gNB are live.
That bypasses OnePlus's operator-list candidate filtering and will distinguish
automatic selection policy from a lower modem/SIB1 compatibility refusal. It
must restore automatic selection and the full RAT/mode-33 state on every exit.
