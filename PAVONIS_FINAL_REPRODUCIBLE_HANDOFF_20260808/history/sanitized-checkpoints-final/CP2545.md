# CP2545: Direct manual-PLMN control is gated no-RF

A minimal root-only Android `app_process` helper now exposes exactly three
subscription-scoped operations through the phone's live `ITelephony` Binder:
read selection mode, request automatic mode, and request a validated 5/6-digit
manual PLMN. The manual operation uses the Binder interface signature actually
present on the phone, supporting either its string or `OperatorInfo` form. It
does not alter RAT masks, CarrierConfig, SIM files, radio power, or any gNB
state.

Two early executions are tooling-void and make no telephony call. The first
stops because standalone `app_process` lacks a prepared Looper; the second
reaches `TelephonyManager` but finds its process-local service registerer
uninitialized. The final build avoids both synthetic framework-process paths
and resolves the real `phone` Binder directly.

The final no-RF gate passes on [host-redacted] and CPH2409:

- device jar hash matches local `317ae19d...`, owner/mode `root:shell 600`;
- initial helper read is selection mode `1` (automatic);
- an automatic request is a successful no-op, `before=1 after=1`;
- final helper read remains mode `1`;
- build remains `user`, full allowed RATs still include NR, and both preferred
  mode keys remain `33`.

The actual manual request was deliberately not exercised without the private
cell. Next, wrap `manual 6 00101 false` around the frozen CP2535 substrate:
start the known phone gNB, wait for exact propagation, apply the proven app
`NR only` mode, issue the Binder request, and monitor access. Cleanup must first
request automatic mode and then restore CP2533's full RAT/mode-33 state on every
normal or signal exit. This is the first experiment that bypasses OnePlus's
filtered operator list rather than repeating scan/app timing.
