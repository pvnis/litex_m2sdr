# CP2547: First manual-PLMN run is tooling-void on unknown RAN semantics

The frozen phone substrate, propagation, app NR-only selection, underlying RF
run, and final restoration all pass. The direct Binder call reaches the real
phone interface:

```text
setNetworkSelectionModeManual(int, OperatorInfo, boolean)
manual sub_id=6 plmn=[network-id-redacted] persist=false before=1 accepted=false after=2
```

The radio buffer independently proves the corresponding modem request:

```text
SET_NETWORK_SELECTION_MANUAL operatorNumeric = 00101, ran = 0
```

The helper treated the returned `false` as fatal even though the network-
selection mode changed from automatic 1 to manual 2. It therefore invoked its
internal recovery immediately, returning mode 2->1 and full RAT before the
remainder of the RF observation window. The outer wrapper later repeats and
passes the exact restoration. CP2547 is consequently void for the manual-
selection hypothesis: the requested state was not held long enough to judge
Msg1 supply.

The underlying run remains mechanically healthy and does not create access:
1,156 empty PRACH rows, zero non-empty rows, zero RAR, zero TX timeouts or
downlink-late lines; the phone has 46 rows, 28 NR rows, no private service/IP,
and no RRC/NAS markers. These are expected after the immediate restore and are
not a new RF negative.

The source-level discriminator is specific. Android's `OperatorInfo` supports
an explicit initial RAN, and NGRAN is value 6. The stock OnePlus operator flow
also requests persistent manual selection, relying on an explicit automatic
restore later. Gate a revised helper that constructs `OperatorInfo(..., 6)`,
uses `persist=true`, and records both the live constructor and RIL `ran=6`.
Because cleanup is already exact, persistence does not survive the checkpoint.
Do not classify a second returned `false` as controller failure if mode 2 is
established; hold that state for the bounded window and judge the modem/RF
result, while reporting the boolean separately.

Final phone state is automatic mode 1, production user, full RAT, and both
preferred mode keys 33.
