The corrected bounded run is valid. Propagation passes, RadioInfo selects exact
NR-only mode 23, the live `OperatorInfo` contains PLMN [network-id-redacted] and NGRAN RAN 6,
and network-selection mode changes 1->2. Manual mode remains held through the
RF observation window even though the Binder return is false. Final cleanup
restores automatic 2->1, full RAT including NR, and both preferred mode keys 33.

Retained system/radio logs resolve the false return. The modem receives:

```text
SET_NETWORK_SELECTION_MANUAL operatorNumeric = 00101, ran = 6
```

After 60 seconds it completes with RIL error 38 and
`CommandException: INTERNAL_ERR`; there is no operation-not-allowed,
invalid-argument, unsupported-request, or radio-unavailable error. This is a
real modem selection timeout, not another Binder/helper failure.

The cell is strong during the attempt: 18 valid NR monitor rows span
`-93..-72 dBm`, mean `-73.17 dBm`. Nevertheless the phone has no private PLMN,
service, or cellular IP, while the clean gNB records 1,166 empty PRACH rows,
zero non-empty PRACH, zero RAR, zero TX timeout/error/deficit, and zero
downlink-late events. The failure remains before Msg1.

This closes app timing, radio-cycle timing, automatic operator filtering, and
explicit manual `00101/NGRAN6` as standalone fixes. It does not prove a gNB RF
defect: the exact cell/MIB/SIB1 is decoded and selection level/quality pass.
Before changing broadcast configuration, complete the one selection-policy
check CP2544 did not actually read: the USIM's own EF_FPLMN (`6F7B`). Android
preferences, databases, and logs are not authoritative for a forbidden list
stored on the card. Read it through the privileged telephony/UICC interface;
do not clear or write it yet. In parallel, inventory the phone's vendor SA/
Smart5G state read-only, because the run proves the generic NR-only mask is not
the whole modem policy.

Final phone and both hosts are restored/idle; the srsUE golden baseline and gNB
binaries remain unchanged.
