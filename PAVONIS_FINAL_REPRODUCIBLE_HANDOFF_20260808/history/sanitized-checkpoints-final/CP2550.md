# CP2550 - Read-only USIM forbidden-PLMN audit

## Question

Does the active lab USIM itself forbid Pavonis PLMN [network-id-redacted], explaining why
the phone sees strong NR but never emits Msg1?

## Method

- Stayed no-RF; [host-redacted] and the gNB were not started.
- Built a new append-only root `app_process` helper. Its first action enumerated
  only filtered methods on the live `ITelephony` Binder, capped at 40 rows.
- The live Android 14 Binder exposes
  `getForbiddenPlmns(int,int,String,String)` and
  `iccExchangeSimIO(int,int,int,int,int,int,String)`.
- Used only `getForbiddenPlmns(subId=6, appType=2 /* USIM */, null, null)`.
  Android's `PhoneInterfaceManager` implements this as a read of the selected
  USIM application's forbidden-PLMN records. The helper contains no setter or
  SIM update action.
- Recorded manual/automatic selection mode, user RAT mask, and preferred mode
  before and after the read.

## Result

`EF_FPLMN` resolves to 13 entries:

`00105, 00104, 22801, 22803, 20810, 20815, 20801, 20816, 00108, 99999, 00106, 00102, 00110`

`00101` is absent. The USIM does not forbid the Pavonis PLMN.

State was unchanged across the read:

- network selection mode: automatic (`1`)
- allowed user RATs: full set including NR
- preferred network mode: `33`

## Verdict

Pass as a read-only diagnostic; the FPLMN hypothesis is closed negative. Do
not clear or rewrite `EF_FPLMN`. Continue with the vendor SA/Smart5G policy
inventory and the operator-recalled gNB/5G-only compatibility state. App timing,
radio cycling, automatic/manual PLMN selection, CarrierConfig RAT source, SIB1
selection thresholds, and now USIM FPLMN are all closed as standalone fixes.
