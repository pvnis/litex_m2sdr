# CP2551 - Vendor SA policy audit and reversible NR-band-3 gate

## Question

Does the remembered phone-side "5G only" behavior hide an additional
OnePlus SA/Smart5G control, and can the modem be constrained away from the
public n1 SA cell that won the failed CP2549 selection attempt?

## Method

- Stayed no-RF; [host-redacted] and the gNB were not started.
- Decompiled only the relevant installed `5G Switch` and OnePlus engineering
  components. The app's Android-version buttons all launch the same hidden
  `com.android.phone.settings.RadioInfo` activity; they do not apply a band or
  SA/NSA mode themselves.
- Read active-subscription OnePlus Smart5G properties. For sub6, both the
  master and per-subscription Smart5G switches are already `0`.
- Built a get-only `RadioManager` probe for `getFiveGSaNsaMode` and
  `getPreferNrMode`. Both sub6 and slot0 calls reach the vendor service but the
  firmware service throws on a null response array and delivers no reply. No
  setter exists in this probe and phone state is unchanged.
- Audited Android's standard `ITelephony` system-selection API. The getter is
  unusable on this modem (`PhoneInterfaceManager: ... Empty response`), but the
  setter has a completion callback and an empty-list clear operation.
- Built an exact-purpose helper with only `read`, `set-n3`, and `clear`.
  `set-n3` constructs one `RadioAccessSpecifier` for NGRAN (`6`), NR band 3,
  and no channel restriction. The helper has no arbitrary-band interface.
- Ran a trap-guarded set/clear round trip and required a positive callback for
  both operations. Automatic selection, full user RAT set including NR, and
  both preferred-mode values were recorded before and after.

## Result

- The remembered app path is fully explained by `RadioInfo` NR-only; there is
  no additional app-owned compatibility setting.
- Active Smart5G is already off and is not filtering Pavonis.
- The vendor SA/NR preference getter is broken on this firmware and cannot be
  used as a reliable state gate. Independently, CP2549 proved live NR-SA by
  camping the public Salt n1 cell, so SA capability is not in doubt.
- The standard n3 selection request passed:
  `callback=true accepted=true`.
- Clearing the restriction also passed:
  `callback=true accepted=true`.
- Final state exactly matches initial state:
  automatic mode `1`, full RAT set including NR, `preferred_network_mode6=33`,
  and `oplus_user_preferred_network_mode6=33`.
- The modem does not implement useful readback for this API, so future use
  must remain bounded and must always issue `clear` on every exit.

## Verdict

Pass as a no-RF control gate. The next discriminator is one frozen phone RF
run with the app-driven NR-only state plus the acknowledged NGRAN-band-3 scan
constraint active. This directly tests whether CP2549 failed because the modem
preferred a strong public n1 SA cell over Pavonis n3. The run must restore an
empty system-selection list, automatic selection, full RATs, and preferred
mode 33 on every exit. Do not repeat CarrierConfig, FPLMN, manual-PLMN, app
timing, or Smart5G work first.
