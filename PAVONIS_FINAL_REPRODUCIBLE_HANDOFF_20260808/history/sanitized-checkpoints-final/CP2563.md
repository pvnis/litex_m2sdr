# CP2563: USIM service 124 closed; voice-policy A/B gated

## Evidence

The official srsRAN/OCUDU COTS-UE guidance records that some OnePlus +
Sysmocom test-SIM combinations require USIM service 124 disabled, NR-only,
and VoLTE/VoNR disabled:

`https://docs.srsran.com/projects/project/en/latest/knowledge_base/source/cots_ues/source/index.html`

The phone's own `com.android.phone` dump reports:

`mUsimServiceTable=UsimServiceTable[88]`

Service 124 is outside the loaded 88-bit service table and therefore cannot be
enabled. A separate read-only `iccExchangeSimIO` helper was also built, but
this firmware returned SIM status `6f00` for EF_UST GET RESPONSE/READ BINARY;
that axis is inconclusive and does not supersede the in-process service table.
The helper contains no update command and did not write the USIM.

The platform `ITelephony` Binder reports the active sub6 baseline as:

- VoNR: true
- advanced calling: true

A no-RF round trip set both false, read both false, restored both true, and
read both true. `setVoNrEnabled` returned 0 in both directions. Full RAT and
both preferred-mode keys remained at their golden values after restoration.

## Verdict

USIM service 124 is closed negative. VoNR/advanced calling is the next clean,
upstream-supported discriminator. Run one frozen phone n3 attempt with both
false, restoring the exact true/true baseline on every exit. Do not combine it
with roaming PLMN, data-roaming, RF, detector, or SIB1 changes.
