# CP2565: phone gNB clock-ppm branch passes no-RF gate

## Provenance

OCUDU exposes `ru_sdr.clock_ppm` and translates both radio centers as:

`(nominal_center_hz + freq_offset_hz) * (1 + clock_ppm * 1e-6)`

The current phone gNB binary contains both `--clock_ppm` and
`Clock calibration in PPM.`. The frozen CP2392 srsUE golden measured initial
cell-search CFO `-3747.710 Hz` at the `1842.5 MHz` downlink center. The NR
PBCH estimator's sign convention makes that consistent with the received
carrier being high, so the first centering value is negative:

- candidate: `-2.034035278 ppm`;
- downlink center change: `-3747.710 Hz`;
- uplink center change: `-3554.477 Hz` at `1747.5 MHz`.

The last point is an explicit caveat: OCUDU's built-in calibration is coherent
across TX and RX, not a TX-only shim. A phone Msg1 result must therefore be
judged together with the existing bounded stage-1 search rather than assuming
the old UL displacement class remains unchanged.

## Default-off runner port

The existing CP1660/CP1733 helper chain now accepts
`PAVONIS_GNB_CLOCK_PPM`. The variable is empty by default. CP1660 validates a
nonempty value as numeric and within `+/-100 ppm`, inserts only
`ru_sdr.clock_ppm`, and records it in the generated config/run metadata.
CP1733 passes the value to [host-redacted] explicitly. No OCUDU, Soapy, gateware, or UE
binary was rebuilt.

## No-RF proof

Two config-only generations ran on [host-redacted]:

- disabled config SHA-256:
  `706d653750b6cebd43ea2c974f91469c5e2e8e5aae37bb776c688aaa2f664be5`;
- `-2.034035278` config SHA-256:
  `9a97231b88d74d5e9f9af352c4d81e0c2883546e2d44053efe888965f749a1ba`.

Their complete file diff is exactly:

```yaml
  clock_ppm: -2.03403528
```

Both configurations parse successfully through the deployed phone gNB binary
with `--dryrun`; no radio was opened and no RF was transmitted. Local shell
syntax checks pass for both edited helpers. Unset behavior generates no
`clock_ppm` key, proving the frozen baseline is unchanged.

## Decision

Run a fresh 250 ms independent bladeRF RX1 downlink capture at zero ppm first
to measure current CFO with the CP2497 instrument. Then repeat the same capture
with the calculated negative calibration. Only if the measured residual moves
toward zero should the calibrated value be used in one frozen phone n3 run.
Keep voice policy true/true and all broadcast, power, timing, detector, and
core settings frozen.
