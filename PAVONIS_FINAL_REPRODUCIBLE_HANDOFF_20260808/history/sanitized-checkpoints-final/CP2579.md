# CP2579: CPH2409 compatibility audit and manual 90170 gate

Date: [date-redacted] Europe/Zurich

## Objective

After CP2578 closed roaming plus voice policy as an automatic-selection fix,
compare the current phone/cell shape with known working OnePlus SA practice and
gate the one documented software action not yet tested in the roaming context:
explicit manual selection of serving PLMN [network-id-redacted] on NGRAN.

## Compatibility audit

The attached phone is `CPH2409EEA`, build
`CPH2409_14.0.0.2200(EX01)`, region mark `EUEX`. Official OnePlus global/EU
specification variants include SA n3, and the current Pavonis cell is n3,
10 MHz, 15 kHz SCS. srsRAN's tested OnePlus Nord table covers n3 at 5, 10,
and 20 MHz. Band and bandwidth are therefore supported rather than the present
splitter.

Sources:

- https://www.oneplus.com/au/nord-ce-2-lite-5g/specs
- https://docs.srsran.com/projects/project/en/latest/knowledge_base/source/cots_ues/source/index.html
- https://docs.srsran.com/projects/project/en/latest/tutorials/source/cotsUE/source/index.html

The known OnePlus procedure also instructs the operator to select the visible
`90170 5G` carrier explicitly. Pavonis previously tested manual
`00101/NGRAN6` in CP2549, but never manual `90170` while roaming, voice-off,
NR-only, and n3 were active. That is a distinct, still-open test.

The same upstream evidence uses or recommends an external reference clock for
COTS UEs. Pavonis CP1973 proved the M2SDR currently uses its internal XO and
has no confirmed physical 10 MHz input; CP1976 closed the uncalibrated FPGA
clock-source mode, not a real external reference. Keep clock quality as the
remaining hardware co-suspect if explicit selection fails.

## Controller gate

`cp2579_run_manual_90170_roaming_voiceoff_phone_rf.sh` wraps the exact CP2577
shape. It waits for all three active proofs: data roaming on, voice false/false,
and `PHONE_N3_APPLY=PASS`. It then invokes the existing hash-pinned root Binder
helper with `sub6 / 90170 / persist=true / NGRAN6`, requires selection mode 2,
holds it through the bounded observation, and restores automatic mode 1 last.

No-RF proofs:

- live `OperatorInfo` construction is
  `SENS/SENS/90170/UNKNOWN/6/1/null/null`;
- initial selection mode remains 1 and roaming remains 0;
- shell syntax passes;
- approval-closed invocation exits 2 and creates zero artifacts;
- deployed manual helper hash remains
  `fbcfa2bc96d71786d5daa5df97f8d777e2868b8d6f71567e4ffb1ce23fb1822c`.

`60c80646a0eca6bb7ec6a7100abb2195c9fb1ecd252f6c0c761810143fd45cca`.

## Verdict

One bounded CP2580 manual-90170 run is justified. It is not a repeat of
CP2549: serving/broadcast/core PLMN is now `90170`, roaming and voice-off are
active, and the manually requested PLMN matches the on-air carrier. Judge the
exact RIL request/mode2 hold and restoration first, then Msg1/registration.
If no Msg1 appears, close manual policy and elevate missing external reference
clock quality as the leading known-working-profile gap.
