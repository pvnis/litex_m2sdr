# CP2583: M2SDR PWM is not a usable VCXO trim

Date: [date-redacted] Europe/Zurich

## Objective

Determine no-RF whether the live M2SDR's SI5351 PWM can coherently trim the
physical reference/sample clock before requesting an external 10 MHz source.

## Host and state gate

- Both [host-redacted] and [host-redacted] are reachable through the established
  `ssh_pexpect_run.py` helper. Direct public-key SSH reaches both hosts but the
  previously offered key is rejected; use the helper, as already required by
  `AGENTS.md`.
- [host-redacted] had zero gNB, qcore, or Soapy processes and `/dev/m2sdr0` was present.
- The exact initial PWM state was enable `1`, width `1024`, period `[date-redacted]`.
- Board readback reported the software-selected `SI5351B / internal XO` mode,
  ready/locked PLLs, and FPGA DNA `[hex-value-redacted]`.

## Measurement

Every state-changing probe used an exit trap that restored enable `1`, width
`1024`, and period `[date-redacted]`; all final readbacks passed.

The stock `m2sdr_util vcxo-test` classified the device as
`SI5351C (no VCXO)` because its host-timed three-point estimate did not clear
the hard-coded 1 kHz threshold. A GDB read of the same hidden values on a
repeat produced `38,399,991.69`, `38,399,026.24`, and `38,400,159.36 Hz` at
0/50/100 percent. That non-monotonic U-shape would spuriously clear the
threshold, proving the host-timed detector is scheduler-noise sensitive and
cannot calibrate a sub-ppm trim.

The decisive control used the gateware's atomic `LATCH_ALL` CSR (`0xf03c`) to
snapshot the independent PCIe and AD9361-reference counters simultaneously.
Seven 8-second points covered 50/100/75/50/25/0/50 percent PWM. Their
AD9361/PCIe ratios ranged only from `0.307915208197` to `0.307915218286`, a
total slow drift of about `0.033 ppm`. The values did not follow PWM duty
cycle: 100, 75, 25, and 0 percent remained on the same time-drift trajectory
as the repeated 50-percent anchors. Any PWM-specific effect is below roughly
`0.003 ppm` in this measurement and has no monotonic transfer function.

Earlier separate-latch ratio attempts are invalid because the two counters
were latched in different utility processes; none of their apparent ppm
values is used here.

## Verdict

The live board's PWM path is not a usable physical reference trim. The
`Configured Mode` label reflects a software control bit, not detected hardware,
and the stock VCXO classifier is too noisy to resolve this board. Preserve the
restored 50-percent state and do not add a Soapy PWM knob or [interface-redacted] it from the
stock utility.

CP2568's `ru_sdr.clock_ppm=-0.548059701` remains only a coherent requested
RF-center correction, not a sample-clock correction. A real external 10 MHz
reference remains the only available hardware-reference branch, but current
phone signal strength and roughly sub-ppm carrier error do not justify making
that unavailable hardware a hard blocker. Return to the phone Msg1 frontier:
analyze the CP2582 stage-1 timing/search envelope and obtain observable phone
UL energy before more handset-policy or clock changes.
