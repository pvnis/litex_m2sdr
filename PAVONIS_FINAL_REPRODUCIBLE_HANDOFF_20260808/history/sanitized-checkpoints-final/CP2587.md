# CP2587: manual selection reaches the modem and returns INTERNAL_ERR

Date: [date-redacted] Europe/Zurich

## Objective

Resolve CP2586's false-returning manual `90170/NGRAN` request without RF or
configuration changes. In particular, test whether the custom `OperatorInfo`
shape, Android framework handling, Oplus auto-selection policy, or a visible
test-network setting rejects the request before it reaches the modem.

## Framework and vendor path

The custom helper is not constructing a semantically different request from
Android's own API. `TelephonyManager.setNetworkSelectionModeManual(String,
boolean,int)` constructs the same four-argument `OperatorInfo` with empty alpha
names, numeric PLMN, and RAN. `Phone.selectNetworkManually()` discards the
operator state and passes only `operatorNumeric` and `ran` to the Oplus network
selection feature. On this Qualcomm device, Oplus calls
`mCi.setNetworkSelectionModeManual(numeric, ran, message)` directly.

The completion path is also unambiguous. `PhoneInterfaceManager` request 41
calls `Phone.selectNetworkManually()` and event 42 returns true only when the
modem completion has no exception. The CP2586 radio ring contains:

```text
[6112]< SET_NETWORK_SELECTION_MANUAL error 38 [PHONE0]
[6112]< SET_NETWORK_SELECTION_MANUAL error: ... CommandException: INTERNAL_ERR
       ... what=16 ... target=com.android.internal.telephony.GsmCdmaPhone
```

RIL error 38 maps to generic `CommandException.Error.INTERNAL_ERR`. Therefore
the Binder `false` is a completed Qualcomm modem failure, not a malformed
object, framework timeout, or parser artifact. Manual mode still changes from
1 to 2 because the requested selection is persisted independently of whether
the modem can camp on it.

## Policy readback

Read-only phone state is:

- `vendor.gsm.gcf.testmode` and the checked persist/vendor variants are unset.
- `development_settings_enabled=1`.
- secure `network_selection_rule6` and the Oplus auto-select setting are null.
- the Oplus carrier network-selection rule is absent from the active carrier
  config, so its source default is zero.
- active carrier config advertises NR availability, including `[1,2]` in the
  main subscription block.

Oplus source consults GCF test mode or developer mode only when deciding
whether to force an out-of-service manual selection back to automatic. Since
developer mode is already enabled and CP2586 holds mode 2 until explicit
restore, this branch does not explain the absence of Msg1. There is no source
or readback evidence that setting the GCF property would make the modem accept
the cell, so it is not an approved blind RF knob.

## Verdict

Close the constructed-`OperatorInfo`, framework handoff, and visible Oplus
auto-restore/test-mode theories. CP2586's manual request reaches the Qualcomm
radio, remains in manual mode, sees Pavonis repeatedly, but the modem cannot
select the cell and returns generic `INTERNAL_ERR` before any observable
uplink. This is consistent with a modem-side suitability/compatibility
decision above the already validated RF receive path.

The next discriminator is a bounded Android available-network scan while the
frozen Pavonis gNB is on air. Print the modem-returned `OperatorInfo` rows and
classify `90170` as available, forbidden, current, or absent before issuing any
manual selection. This uses the modem's own classification and avoids another
blind attach retry. If `90170` is returned, a follow-up may feed that exact row
back to the normal manual API; if it is absent or forbidden, inspect the
decoded SIB1 suitability fields against the result before changing RF.

The CP2586 2.0736 GB raw is background-class and this audit closes its only
pending use. Its recorded SHA-256 was rechecked on [host-redacted] and the exact
`2,073,600,000`-byte file was then deleted; cleanup passes without touching the
small summaries or analyzer outputs.
