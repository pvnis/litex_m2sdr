# CP2588: phone available-network scan is gated no-RF

Date: [date-redacted] Europe/Zurich

## Objective

Prepare the CP2587 discriminator without changing the proven manual-selection
helper or any frozen gNB setting: ask the phone modem for its own available
network list while Pavonis is on air and preserve each returned
`OperatorInfo` numeric, state, and RAN.

## Helper

A separate `PavonisNetworkScan` app-process jar reflects only the live
`ITelephony.getCellNetworkScanResults(int,String,String)` API. It prints the
scan status, elapsed time, operator count, and each operator's numeric PLMN,
alpha names, state, RAN, and raw representation. It contains no set/manual,
RAT, SIM, CarrierConfig, or radio-power operation.

The local class is compiled through the installed `jdk.compiler` module and
DEXed with the existing `/tmp/r8-9.1.31.jar`; no package or host change was
needed. The jar is deployed separately as
`/data/local/tmp/pavonis_network_scan.jar`, owner/mode `root:shell 644`, and
does not replace `/data/local/tmp/pavonis_manual_plmn.jar`.

## No-RF proofs

- Local and device jar hashes match.
- The live Binder method resolves under both shell and root app-process
  contexts with the expected three-argument signature.
- No actual network scan is invoked during this checkpoint.
- Phone selection mode remains automatic (`1`) before and after the proof.
- Full allowed RATs still include NR; both preferred mode keys remain `33`.
- The RF wrapper passes `bash -n`, is default-closed with rc2 and zero run
  artifacts, pins the CP2577 runner hash, scan jar hash, and fresh stamp.
- ShellCheck is not installed on the controller or [host-redacted]; that optional proof
  could not be run. The script is syntax-clean and its closed path executed.

The RF wrapper starts the exact CP2577 90170/roaming/voice-off/n3 chain and
changes only its diagnostic hold/monitor durations from 180/150 to 300/270
seconds. Once all three phone-policy gates are live, it runs one bounded
200-second scan as `com.android.shell`, requires status success and automatic
selection before/after, and requires the frozen base runner to remain alive
through scan completion.

## Next run and interpretation

Run CP2589 once with a fresh stamp. The result is valid whether `90170` is:

- `AVAILABLE` or `CURRENT`: feed that exact returned row into the normal
  manual API in a later bounded test, because modem visibility/suitability is
  established.
- `FORBIDDEN`: inspect modem/SIB1 suitability and SIM policy; do not [interface-redacted] RF.
- absent from a successful scan: compare decoded SIB1 suitability fields and
  scan RAN coverage; do not repeat manual selection.

The scan is a classification experiment, not an attach attempt, and the
existing phone state restoration remains owned by CP2577.
