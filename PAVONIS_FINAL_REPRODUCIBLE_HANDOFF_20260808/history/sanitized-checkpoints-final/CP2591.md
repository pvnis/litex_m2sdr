# CP2591: legacy available-network API returns modem SYSTEM_ERR

Date: [date-redacted] Europe/Zurich

CP2591 validly exercises the corrected root caller on the frozen
90170/roaming/voice-off/n3 RF shape. The location-policy problem is gone, but
the deprecated synchronous scan path completes in 21 ms with status 4 and no
operators:

```text
PAVONIS_NETWORK_SCAN_DONE elapsed_ms=21
PAVONIS_NETWORK_SCAN status=4 operator_count=0
```

The contemporaneous main-buffer framework log names the cause:

```text
getCellNetworkScanResults: Exception: ... CommandException: SYSTEM_ERR
```

`PhoneInterfaceManager` maps every command exception other than
`RADIO_NOT_AVAILABLE` and `GENERIC_FAILURE` to status 4. This is therefore a
real modem rejection of legacy `Phone.getAvailableNetworks()`, not an empty
successful result and not evidence that Pavonis is absent. The wrapper refuses
to classify it because status1 is required.

Phone and host postchecks pass: automatic mode1, roaming0, voice true/true,
full NR RATs, both mode keys33, zero gNB survivors, and zero qcore survivors.
Close the legacy scan API for this phone. Use the production Oplus asynchronous
network-scan UI/API path next.
