# CP2593: Oplus operator-scan controller passes runtime no-gNB gate

Date: [date-redacted] Europe/Zurich

CP2593 closes three controller-only issues without starting the private gNB.

1. Direct shell launch was denied because `OplusNetworkSetting` is not
   exported. Launch now uses the phone's existing root authorization; the
   activity, scan implementation, and arguments remain unchanged.
2. The activity remained in its task after the earlier manual control, so a
   new intent could be delivered to a stale completed instance without a fresh
   scan. The controller now brings any instance forward and finishes it before
   scan start and again during cleanup.
3. Oplus debug-tag output is not present in the available log buffers on this
   user build. The production UI nevertheless completes and renders state.
   Completion now requires `Available networks`, no `Searching`, and at least
   one operator title beyond the two headers. Numeric identity remains joined
   from the already authoritative phone service-state rows in the RF run.

The final fresh no-gNB runtime control passes in approximately 109 seconds and
renders:

- `Salt 4G(Forbidden)`
- `Sunrise 4G`
- `Swisscom 4G(Forbidden)`
- `Salt 3G(Forbidden)`

It emits `OPLUS_OPERATOR_SCAN_COMPLETE=1`,
`OPLUS_OPERATOR_SCAN_REMOTE=PASS`, and
`OPLUS_OPERATOR_SCAN_SELECTION_RESTORE=PASS`; automatic selection remains
mode1 and the activity is finished back to the launcher. This validates the
same deployed controller that CP2594 will invoke.

row identifies the already authoritative `90170`, and an optional
`(Forbidden)` suffix gives the modem/UI classification. Absence after a valid
