# CP2597: CORESET0 index-6 phone discriminator passes no-RF gate

## Question

CP2596 proved that the production modem scan discovers private `90170` as an
available n3 network, but production selection returns Qualcomm error 38
(`INTERNAL_ERR`) before the phone emits Msg1. This checkpoint isolates the
largest remaining common-cell difference from the documented working OnePlus
Nord n3 profile: CORESET0 index 6 with SearchSpace0 index 0 at DL ARFCN
368500. PCI 1, TAC 1, 10 MHz, 15 kHz SCS, PLMN [network-id-redacted], RF levels, phone policy,
qcore, and every ladder/detector setting remain frozen.

## Generator audit and correction

The active CP1807 generator already accepted `PAVONIS_GNB_CORESET0_INDEX` and
`PAVONIS_GNB_SS0_INDEX`, but the first generated YAML revealed an unintended
coupling: any explicit CORESET0 value also emitted the old srsUE demarginalized
dedicated-search-space settings (`ss2_type: common` and DCI 0_0/1_0). OCUDU's
schema defaults are instead UE-dedicated and DCI 0_1/1_1, so that block was not
semantically neutral.

The helper now emits that dedicated block only when
`PAVONIS_GNB_SRSUE_PDCCH_COMPAT=1`. Explicit common CORESET0/SS0 settings emit
only `cell_cfg.pdcch.common`. The disabled path remains byte-identical.

## Decision

Run one bounded CP2598 RF discriminator with the CP2596 production scan/select
shape and only CORESET0 index 6 / SS0 index 0 changed. Judge health first, then
the phone-reported SSB ARFCN, scan classification, selection callback, and
first Msg1. If Msg1 appears, continue the existing attach/data ladder without
changing this geometry. If selection still returns `INTERNAL_ERR` with zero
Msg1, close CORESET0/SSB placement as a standalone cause before considering a
separate PCI/TAC profile discriminator.
