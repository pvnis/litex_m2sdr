# CP2598: CORESET0 discriminator is propagation-void

## Execution

CP2598 ran the bounded CP2596 production scan/select shape under the new outer
controller with requested CORESET0 index 6 and SS0 index 0. The RF, phone,
qcore, packaging, and restoration paths completed normally. The outer
controller exited 1 only because its final propagation proof correctly failed.

## Propagation verdict

The intended values did not reach the active CP1807 stage:

- sequence: `gnb_coreset0_index=` and `gnb_ss0_index=`;
- generated YAML SHA-256:
  `71020642a4921e541d05ac89f47db7c181c617a2213cf2e6b98420097f08798d`;
- that hash is exactly the CP2596 baseline YAML hash;
- the generated `pdcch.common` contains only the frozen SS1 candidate list and
  has no `coreset0_index` or `ss0_index`.

The cause is a name mismatch at the active stage boundary. The outer wrapper
set `PAVONIS_GNB_CORESET0_INDEX` / `PAVONIS_GNB_SS0_INDEX`, while
`cp1807_run_stage6_raresp40_realue_rar_msg3.sh` reads
`GNB_CORESET0_INDEX` / `GNB_SS0_INDEX` and only then exports the PAVONIS names
to [host-redacted]. Ordinary shell inheritance was intact; the wrong variables were read.

## Non-discriminator observations

Because the cell was byte-identical to CP2596, the phone result is a repeat,
not a geometry datapoint. The production scan found exactly `901 70 5G`; the
tap moved selection mode 1 to 2; Qualcomm request 2159 returned error 38 /
`INTERNAL_ERR` after about 60 seconds; and Oplus rendered the network-
unavailable dialog. The gNB recorded 1,906 stage-1 rows, zero selections,
1,901 empty and zero nonempty PRACH rows, zero RAR, zero RRC/NAS/IP, zero
Soapy TX timeouts, and zero downlink-late events.

Cleanup is fully normal: qcore 2 to 0 processes, roaming restored off, voice
policy restored on, automatic selection mode 1, full/both mode 33, and no
remaining gNB/srsUE process.

## Decision

CP2598 is void for the CORESET0/SSB hypothesis. Do not count its repeated
`INTERNAL_ERR` as an index-6 failure. Correct the outer controller to set the
stage-facing `GNB_CORESET0_INDEX=6` and `GNB_SS0_INDEX=0`, then run a no-RF
full-shape generation/dry-run proof. That gate must show the frozen SS1 list,
max UE MCS, RA window, power and phone settings plus exactly the two intended
common-PDCCH values before one fresh RF retry.
