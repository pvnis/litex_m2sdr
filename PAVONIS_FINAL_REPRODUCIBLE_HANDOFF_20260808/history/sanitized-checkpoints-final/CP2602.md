# CP2602: PCI500/TAC7 run is CU-CP validation-void

## Classification

CP2602 is void for the phone profile hypothesis. The intended stage values all
propagated (`index6`, `SS0=0`, `PCI500`, `TAC7`) and the generated cell YAML
had PCI500/TAC7, but the gNB rejected configuration before opening the SDR,
before phone NR-only apply, and before production scan/selection.

## Failure

The TAC override updated only `cell_cfg.tac`:

```yaml
cu_cp:
  amf:
    supported_tracking_areas:
    - tac: 1
cell_cfg:
  tac: 7
  pci: 500
```

OCUDU correctly rejected this cross-field mismatch:

```text
Could not find cell PLMN '90170' and cell TAC '7' in the CU-CP supported tracking areas list
OCUDU ERROR: Invalid configuration detected.
```

The start helper then timed out waiting for a new gNB marker (`rc=124`), and
the phone controller stopped with propagation rc24. Packaged partial-profile
YAML hash is
`7df9428571d3584f0b1d0ab1df36542ffbd4989855b452a664381f9a77e49f41`.

The prior `--dryrun` gate did not catch this because this OCUDU binary returns
immediately after CLI parsing in dry-run mode, before `validate_plmn_and_tacs`.
Future identity gates must combine parser dry-run with an explicit structured
cell/TAI PLMN+TAC invariant check.

## Cleanup

Host realtime gates pass. qcore cleanup is 2 to 0 processes, roaming restores
off, and the phone remained in its normal full/automatic baseline because
NR-only apply never ran. No scan or manual selection occurred, so there is no
phone result to interpret.

## Decision

Update TAC atomically in both `cell_cfg.tac` and
`cu_cp.amf.supported_tracking_areas[0].tac`. Keep PCI500 and every CP2601
fixture unchanged. No-RF prove disabled byte identity, a three-scalar profile
diff (two TAC locations plus PCI), parser success, and the explicit PLMN/TAC
cross-field invariant before one fresh RF retry.
