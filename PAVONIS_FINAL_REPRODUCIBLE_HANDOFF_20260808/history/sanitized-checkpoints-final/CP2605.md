# CP2605: OnePlus common-RACH semantic audit names a concrete mismatch

No RF was used. This checkpoint compares the exact Pavonis broadcast decoded
by the CP2392 golden srsUE against the local srsRAN 4G COTS OnePlus n3 profile
and the RRC code that supplies that profile's omitted common-RACH defaults.

## Proven profile provenance

The official srsRAN COTS application note's OnePlus Nord profile specifies
Band 3, PCI 500, TAC 7, DL ARFCN 368500, CORESET0 index 6, and root sequence
index 1. The local `srsRAN_4G` tree at commit
`[hex-value-redacted]` contains the matching
PCI/ARFCN/Band/52-PRB SA geometry. Its profile does not configure the remaining
RACH fields, so they come from `srsgnb/src/stack/rrc/cell_asn1_config.cc` and
`rrc_nr_config_utils.cc`.

Source hashes:

- `cell_asn1_config.cc`: `853b99146fa0090a0bb4f258aee35a92190f6c5370e90d71df0196a634da0ab3`
- `rrc_nr_config_utils.cc`: `687a0d25e7994274579954af5b3c83026bf208208af932eb23c3e80c85297cf0`

## Verdict

The common-RACH profile is not equivalent to the known working OnePlus n3
profile. The first concrete, minimally coupled discriminator is
`prach_frequency_start: 1`: Pavonis currently broadcasts 8 while the COTS
profile broadcasts 1. This changes only the frequency-domain location of
Msg1; it does not change the occasion lattice, response window, power policy,
identity, PDCCH geometry, or core configuration.

Next add a default-off validated passthrough for
`cell_cfg.prach.prach_frequency_start`, prove the CP2604 disabled YAML remains
byte-identical and the enabled structural diff is exactly `8 -> 1`, then run
one frozen production scan/select attempt. Do not simultaneously change PRACH
index, preamble count, response window, thresholds, identity, or RF settings.
