# CP2629: bladeRF gNB phone controller passes the no-RF gate

Status: PASS. No RF ran.

## Controller shape

Four fresh-stamp, default-closed scripts now implement the CP2628 control:

- `cp2629_qcore_remote.sh` starts qcore on [host-redacted] Ethernet at
  `[ip-redacted]:38412`, uses the existing mode-600 private subscriber file,
  records one scoped PID/log, and provides compact status/stop operations;
- `cp2629_srsenb_remote.sh` starts the exact CP2628 `srsenb` and isolated
  bladeRF plugin, requires the cached X2 marker, NG connection, and gNB-start
  marker before succeeding, enables bounded NR-MAC/NGAP pcaps, and provides
  compact RACH/connected status plus stop;
- `cp2629_phone_remote.sh` verifies the established phone-helper hashes and
  baseline state, starts the single CP2625 monitor, applies roaming-on,
  voice-off, and the proven app-backed NR-only+n3 shape, and starts an on-host
  data watcher. The watcher waits for a cellular interface and immediately
  pings private gateway `[ip-redacted]`, before the existing operator selector
  restores state. Its restore action terminates observers and returns automatic
  selection, the full RAT mask, roaming-off, and voice policy true/true;
- `cp2629_run_bladerf_gnb_phone_rf.sh` performs both host preflights, deploys
  hash-pinned helpers, starts qcore then srsENB, requires X2 and NG proof before
  phone action, runs the existing Oplus scan/select helper, gathers compact
  phone/gNB/qcore status, restores and stops everything, and packages both
  host run directories under a fresh stamp.

## No-RF proof

All four scripts pass `bash -n`. Invoking the outer wrapper without
`PAVONIS_CP2630_RF_APPROVED=1` exits `2` before creating run artifacts or
contacting hardware. Deployed helper hashes and syntax pass on both hosts.
The qcore helper was then corrected to use privileged PID liveness checks for
the root-owned qcore process. A fresh no-RF gate exercised `start`, `status`,
and `stop` in three separate SSH sessions; all three passed and no qcore
process remained. This closes the controller-session sudo-cache ambiguity
before CP2630.

The exact runtime preflight commands also pass independently:

- [host-redacted] has performance governors, Ethernet `[ip-redacted]/24`, a mode-600
  private subscriber file, and no qcore/OCUDU gNB process;
- [host-redacted] has performance governors, no srsENB/srsUE process, bladeRF serial
  `5c750e8e...` on USB SuperSpeed `5000`, authorized USB state, authorized
  phone `[known-phone-serial-redacted]`, and lossless reachability to [host-redacted];
- phone baseline is automatic selection mode `1`, full RAT mode `33`, roaming
  `0`, and VoNR/advanced-calling `true/true`;
- the deployed monitor, n3 helper, roaming helper, Oplus selector, RadioInfo
  app helper, and voice-policy JAR all match the hashes proven in the preceding
  phone branch.

## Decision

Run one bounded CP2630 control with a fresh stamp. Mechanics are judged first:
qcore listener, X2 selector, NG setup, gNB start, phone helper propagation, and
cleanup. Then judge cell scan/identity and camping, first RACH/Msg1, qcore
registration, user-plane activation, phone cellular address, and the private
gateway ping in that order. The run is independent of OCUDU/M2SDR and does not
modify the CP2392 golden binaries or configs.
