# CP2632: exact-DL no-TX/tone bracket exonerates the RF path

Date: [date-redacted] Europe/Zurich

## Purpose

Bracket CP2631 at the exact same M2SDR RX2 geometry to distinguish an empty
srsENB transmit path from a frequency-specific bladeRF TX2 / antenna / M2SDR
RX2 failure.

## CP2632A: no-TX baseline

With qcore, gNB, srsUE, and bladeRF TX idle, M2SDR RX2 captured 0.5 seconds at
`1842.5 MHz`, `11.52 Msps`, `10 MHz`, gain `50`:

- `5,752,800` CF32 samples;
- RMS `0.00739579`;
- maximum 20 ms RMS `0.00757401`;
- capture SHA-256 `a9872ac0...`;
- package SHA-256 `cedd7e91...`.

The helper's kernel flag again contains only the benign M2SDR
`Using non-ARM DMA buffer handling` message.

Direct PSD comparison against CP2631 gNB-on gives:

- total RMS delta: `-0.029716 dB`;
- expected SSB core delta: `-0.022666 dB`;
- full SSB-band delta: `+0.087933 dB`;
- only the narrow DC region changes materially (`+5.094 dB`).

Therefore CP2631 is no-TX-like at the actual SSB frequencies.

## CP2632B: exact-frequency CW

The established CP1571/CP798 reciprocal harness then ran at the same
`1842.5 MHz` center with only the proven second pair selected:

- bladeRF TX2, gain `45`, Q11 amplitude `512`, command tone `+100 kHz`;
- M2SDR RX2, gain `50`, `11.52 Msps`, `10 MHz`;
- all run/capture/final/cleanup gates passed.

Measured result:

- peak `97,998.05 Hz`;
- command error `2,001.95 Hz`, matching the established inter-device LO
  offset class;
- peak over spectral median `59.77 dB`;
- near-tone, exact-bin, gross-path, and composite tone gates all pass.

## Verdict

The exact downlink-frequency physical path is healthy and high-margin.
CP2631's missing SSB is born in the isolated srsENB/bladeRF software TX path,
not bladeRF TX2, M2SDR RX2, the antennas, or the 1842.5 MHz propagation path.
CP2630 is therefore not a valid phone-interoperability verdict.

Next stay no-RF and audit the isolated bladeRF plugin's live TX call path. Add
default-off bounded metadata counters for `bladerf_sync_tx` call count,
returned status, sample count, and input-buffer RMS/peak/nonzero count. A
nonzero high-rate input with successful calls but no air signal implicates
stream/channel configuration; zero/near-zero input implicates srsENB's
baseband handoff.
