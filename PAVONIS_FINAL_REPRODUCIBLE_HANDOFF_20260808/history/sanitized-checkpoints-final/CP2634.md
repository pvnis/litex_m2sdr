# CP2634: bladeRF RX actual_count=[date-redacted] confirms the timebase root cause

Date: [date-redacted] Europe/Zurich

## Purpose

Confirm CP2633's receive-derived timeline hypothesis directly before changing
count or timestamp semantics. Use only the existing bounded RX metadata trace
and TX pre-timestamp trace; no phone action or behavior-changing RF option.

## Run

Fresh stamp `CP2634_RXTXDBG_[date-redacted]` ran qcore and isolated
srsENB/X2 for a short window. RX and TX traces were each capped at 64 rows.
TX `PRE_TX` timestamp readback was enabled; all force/skip/shift/restart
options remained off. Start, stop, and cleanup passed.

Packages:

- [host-redacted]: `c8329ea6...`;
- [host-redacted]: `a5e99faa...`.

## Direct result

All 64 bladeRF RX calls show the same contradiction:

- requested `nsamples=11520`;
- API return status `0`;
- metadata `actual_count=[date-redacted]`;
- metadata status `0x00030001`, including the documented overrun bit;
- receive timestamp advances exactly `[date-redacted]` on all 63 transitions.

The first three RX timestamps are `169974, 172018, 174062`.

TX reproduces the downstream effect:

- call 1: 11,520 samples, requested timestamp `216033`;
- pre-TX device timestamp `255194`;
- exact initial lateness `-39161` samples / about `-3.40 ms`;
- calls 2-64: 2,044 samples after `radio.cc` overlap trimming;
- all TX API and TX metadata statuses remain zero.

## Contract audit

The installed libbladeRF is `2.6.0-git-0bf98844`. Its installed
`libbladeRF.h` states that `actual_count` is the number of contiguous
samples populated, differs from the request on a discontinuity/overrun, and
that reading beyond it is invalid because the rest of the buffer is undefined.

The current plugin violates that contract: it calculates `actual_count`, but
converts all requested 11,520 samples and returns 11,520 to the radio layer.
It also exposes the first segment timestamp, causing the next gNB RX/TX time to
advance by only 2,044 samples. CP2633's perpetual 9,476-sample TX overlap trim
follows directly.

## Decision

Implement a default-off isolated-plugin receive accumulator. When enabled, it
must loop `bladerf_sync_rx` until the full requested count is populated,
append only each segment's `actual_count`, retain the first segment
timestamp, reject zero-progress/error cases, and expose segment/count/timestamp
continuity in bounded metadata. Disabled behavior and golden srsUE artifacts
must remain unchanged. Build/deploy proof comes before RF.
