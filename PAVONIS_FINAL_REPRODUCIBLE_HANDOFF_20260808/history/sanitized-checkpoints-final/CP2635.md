# CP2635: isolated bladeRF RX short accumulator gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Created a new checkpoint-owned overlay,
`cp2635_rf_blade_imp_x2_rx_accumulate.c`, from the archived CP2628 X2
source. The existing source and plugin artifacts were not edited.

The new policy is default-off and cached at device open:

- `PAVONIS_RF_BLADE_RX_ACCUMULATE_SHORT`;
- `PAVONIS_RF_BLADE_RX_ACCUMULATE_MAX_SEGMENTS`, default `64`.

When enabled, one logical RX request loops over `bladerf_sync_rx` segments,
appending only each documented-valid `actual_count`. It retains the first
segment timestamp, requires every later timestamp to equal
`first_timestamp + filled_count`, rejects zero progress, API errors,
discontinuity, or segment-cap exhaustion, and exposes bounded segment/fill/gap
metadata through the existing RX debug row. The disabled branch preserves the
single original `bladerf_sync_rx` call and adds no per-call environment read.

## No-RF runtime proof

The existing open/close-only channel probe performs no stream enable:

- policy disabled: X2 marker, `active=0 max_segments=64`, open/close pass;
- policy enabled: X2 marker, `active=1 max_segments=64`, open/close pass;
- enabled with max segments `0`: rejected before device open.

The deployed CP2635 helper pins the new plugin hash, sets the isolated library
path and policy `1`, and requires the `active=1` marker plus X2, NG, and
gNB-start markers. It leaves the CP2629 helper and golden srsUE binary
unchanged.
