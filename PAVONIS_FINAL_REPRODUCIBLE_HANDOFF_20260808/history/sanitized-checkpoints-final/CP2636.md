# CP2636: strict accumulator exposes recurring 650-sample gaps

Date: [date-redacted] Europe/Zurich

## Purpose

Run the CP2635 fixed-path acceptance with no phone: bounded RX/TX metadata and
simultaneous independent M2SDR RX2 capture. Require full contiguous RX fills,
full TX subframes, and PCI500 PBCH.

## Mechanics

Fresh stamp `CP2636_FIXED_[date-redacted]` passes qcore, isolated CP2635
plugin/helper selection, X2/NG/gNB start, 0.5-second M2SDR RX2 capture,
service stop, packaging, and cleanup.

- [host-redacted] `4c16da81...`;
- [host-redacted] `8fa4fed6...`;
- CF32 capture `44e1cb01...`.

## Timeline result

The strict accumulator is active on all 64 traced RX calls, but reveals an
alternating pattern:

- 32 calls fill `11520` in 6 segments with zero segment gap;
- 32 calls collect `744` samples, then the next segment begins `+650`
  samples after the expected timestamp;
- those 32 discontinuous calls correctly return error rather than append
  samples across the gap;
- every underlying metadata record still includes overrun.

RX start-timestamp deltas consequently alternate `10870` and `3438`.
The downstream TX trace has:

- 64 full `11520` calls;
- 62 trimmed `2788` calls;
- one `30720` and one `3840` gap-handling call;
- first timed SOB still `40723` samples late.

Thus the strict fix prevents undefined-buffer conversion but cannot restore a
continuous logical radio timeline while positive hardware timestamp gaps are
treated as fatal.

## Air result

The independent capture remains floor-class (RMS `0.00735777`).
The validated 48-case PBCH sweep yields `0/48` PCI500 CRC OK. One window
weakly reports CSI PCI500 at `-17.1 dB`, insufficient for a cell verdict.

## Decision

CP2636 fails the acceptance gate and does not unlock a phone run. The next
isolated overlay should represent positive timestamp gaps honestly: insert
zero samples for the missing hardware-time interval, append the valid segment
after the gap, and continue until the logical 11,520-sample request is full.
Negative overlap must be trimmed from the segment; zero progress, API error,
and cap exhaustion remain fatal. Keep per-request inserted/dropped counters in
bounded metadata, build/deploy no-RF, then repeat the same acceptance.
