# CP2637: timestamp-aware bladeRF RX gap-fill gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Created the append-only overlay `cp2637_rf_blade_imp_x2_rx_gapfill.c` from
the CP2635 strict accumulator. The shared srsRAN source and established build
artifacts were restored after the isolated build.

The existing cached, default-off policy remains controlled by:

- `PAVONIS_RF_BLADE_RX_ACCUMULATE_SHORT`;
- `PAVONIS_RF_BLADE_RX_ACCUMULATE_MAX_SEGMENTS`, default `64`.

When enabled, one logical RX request still consumes only the documented-valid
`actual_count` from each `bladerf_sync_rx` call and retains the first segment
timestamp. Positive segment timestamp gaps are represented by explicit zero
samples before the valid segment. Negative gaps drop the overlapping prefix.
If the logical request becomes full, excess valid samples are discarded rather
than exposed beyond the request. API errors, zero progress, and segment-cap
exhaustion remain fatal.

The bounded RX debug row now records `inserted_zeros`, `dropped_overlap`,
segment count, and minimum/maximum segment gap. The disabled branch retains
the original single-call behavior and performs no per-call environment read.

## Decision

RX/TX metadata plus simultaneous M2SDR RX2 capture. Require completed 11,520-

geometry and decoder-visible PCI500 PBCH before returning to the phone.
