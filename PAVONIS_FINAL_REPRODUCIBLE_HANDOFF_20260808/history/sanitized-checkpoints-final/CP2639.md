# CP2639: bladeRF single-channel stream layout gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Created append-only overlay `cp2639_rf_blade_imp_x2_single_layout.c` from the
CP2628 physical-channel source. It adds one cached, default-off policy:

`PAVONIS_RF_BLADE_SINGLE_CHANNEL_LAYOUT`

Channel-control calls now use explicit
`BLADERF_CHANNEL_RX/TX(physical_channel)`. With the policy disabled, stream
layouts retain the CP2628 behavior. With it enabled, all three
`bladerf_sync_config()` sites use `BLADERF_RX_X1`/`BLADERF_TX_X1`, while gain,
[interface-redacted], rate, bandwidth, enable, and restart calls remain on physical RX2/TX2.
The environment is read once at device open, not per RX/TX call.

This follows Nuand bladeRF commit `0bf98844`: its CLI selects X1 layout for one
active channel and separately enables channel index 1. No RX accumulation,
zero insertion, timing shift, threshold, or sample transform is present.

## No-RF Runtime Proof

The existing open/close-only probe contains no stream activation:

- disabled: physical `rx=2 tx=3`, `active=0 rx_layout=2 tx_layout=3`, pass;
- enabled: physical `rx=2 tx=3`, `active=1 rx_layout=0 tx_layout=1`, pass.

The loader resolves the CP2639 isolated plugin and both hosts are idle after
the proof. Static source proof finds exactly one policy environment read.

## Decision

The no-RF gate passes. Repeat the CP2638 bounded acceptance with CP2639 and no
accumulator. Require 64/64 full 11,520-sample RX calls with timestamps stepping
11,520, full 11,520-sample TX continuation geometry, a non-late initial SOB,
and decoder-visible PCI500 PBCH before returning to the phone.
