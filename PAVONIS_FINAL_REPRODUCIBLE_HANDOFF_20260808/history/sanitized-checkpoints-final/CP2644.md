# CP2644: default-off pre-NGAP UE cleanup gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Added one default-off branch to `ngap::user_release_request()`. When
`PAVONIS_RRC_REMOVE_PRE_NGAP_ON_RELEASE_MISS` is enabled and NGAP has no
context for the requested RNTI, NGAP calls the existing RRC release path
instead of returning after a warning. `rrc_nr::release_user()` sends the
existing release and defers `rem_user()` by 60 ms; that removes MAC, PHY, RLC,
PDCP, and scheduler state through the established lifecycle.

The environment value is cached on first use. With the flag unset or `0`, the
original warning-and-return path is byte-for-byte intact. No RF, sample,
scheduler, PUCCH-capacity, RRC payload, or timing setting changed.

## Build And Restore

[host-redacted] built the patch against the existing CP2628 srsENB tree and copied
the result to `/home/[host-redacted]/pavonis_cp2644_srsenb/srsenb`. The build script
then restored the established source and rebuilt/restored the established
binary. Final remote hashes are again exactly `2af2c64c...` and
`1705db0f...`; CP2644 is isolated from the old helper.

The first build invocation exited 141 because a `strings | grep -q` proof ran
under `pipefail`. The build itself had completed and the trap restored the
baseline. Replacing that proof with direct binary-safe `grep -aFq` produced a
clean second build; this was a proof-script failure, not a compiler failure.

## No-RF Gate

The isolated binary contains both the environment name and cleanup marker.
Two normal config-parser launches, one with the cleanup flag disabled and one
enabled, used the intentionally invalid physical channel. Both exited 255
before `Opening bladeRF` and before any RX stream start. Helper syntax and all
config/plugin/binary hash pins pass.

## Phone Diagnostics

ADB remains authorized. The phone has ten third-party packages, including the
root manager and `com.sladjan.sava.petg`, but no package name directly exposes
a modem diagnostic logger. Android's radio log currently spans only the last
30 minutes, so CP2643's RRC epoch has rolled out; future phone attempts should
clear and package the bounded radio buffer in the same run.

## Decision

The stale-user cleanup is ready for RF use. Before the next phone run, add one
default-off metadata-only HARQ-ACK event trace for RRCSetup and package the
phone radio buffer. This will distinguish “phone never decoded RRCSetup” from
“RRCSetup ACKed but SetupComplete failed later” without verbose PHY logging.
