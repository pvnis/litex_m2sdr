# CP2645: bounded RRCSetup HARQ-ACK provenance gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Added `PAVONIS_NR_PUCCH_ACK_TRACE`, default off and cached on first use, at the
MAC PUCCH result boundary. It emits a warning-level metadata row only when a
decoded PUCCH opportunity carries at least one configured HARQ-ACK bit. Each
row contains slot, RNTI, ACK count, UCI validity, first ACK value, SR, CSI
count, and decoder SNR. A process-lifetime atomic cap limits output to 64 rows.

The trace does no sample scan, allocation, or file IO and performs no work for
ordinary PUCCH events beyond the ACK-count check and cached flag check. This
complies with the CP1860 metadata-only/event-triggered instrumentation rule.

CP2645 combines that trace with CP2644's default-off stale pre-NGAP UE cleanup.
No scheduler capacity, RRC payload, PHY threshold, MCS, RF, or timing behavior
changed.

Binary strings prove both environment names and both event markers. Enabled
and disabled invalid-channel launches each exit 255 before bladeRF open or
stream start. Static source inspection finds one `getenv` site for the PUCCH
trace. The run helper verifies both enabled flags directly from
`/proc/$pid/environ` after startup and emits `CP2645_TRACE_ENV=PASS`.

One helper verification command used the wrong expected hash typed into the
command and failed closed; the immediate retry used the actual local hash and
passed. No binary or helper bytes changed between those verification attempts.

## Decision

Run one bounded fresh-stamp MCS4 phone attempt with cleanup and ACK trace
enabled. Clear and package the Android radio log in the same run. Interpret
RRCSetup per temporary RNTI: valid ACK proves the phone decoded and accepted
the DL transport through HARQ; invalid/DTX leaves the failure in DL delivery or
PUCCH reception. Continue to qcore/PDU/private data immediately if
RRCSetupComplete appears.
