# CP2648: SetupComplete is blocked at the dedicated SR PUCCH resource

Date: [date-redacted] Europe/Zurich

## RF Run

Fresh stamp `CP2648_[date-redacted]` repeated CP2646 with only the CP2647
bounded setup-UL trace added. All mechanics, live flag propagation, cleanup,
phone restore, and packaging passed. Final artifacts contain two RACH attempts;
the wrapper status sampled before the second late attempt and therefore listed
one.

Package hashes:

- [host-redacted]: `6b94c2da...`;
- [host-redacted]: `e9019aa2...`.

The phone observed exact PCI 500 in 51/59 monitor rows. Two quality rows were
`-85 dBm` RSRP, `-12 dB` RSRQ, and `+5 dB` SINR. Registration remained out of
service.

## Post-Setup UL Join

Both attempts repeat CP2646's positive downlink result:

- RNTI `0x4601`: Msg3 PUSCH CRC OK at `+19.788 dB`; RRCSetup HARQ ACK is
  valid/positive at `+16.396 dB`;
- RNTI `0x4602`: Msg3 PUSCH CRC OK at `+10.371 dB`; RRCSetup HARQ ACK is
  valid/positive at `+7.800 dB`.

For `0x4601`, the gNB then schedules the first 64 sl40 SR opportunities from
slot 48 through 2568. Every result is invalid. Decoder SNR ranges from
`-13.679` to `-7.731 dB`, mean `-10.942 dB`; no valid positive SR is delivered
to the scheduler. No post-setup PUSCH exists. The only two PUSCH trace rows are
the two 11-byte CRC-OK Msg3 transmissions.

This places the failure at the configured scheduling-request PUCCH, before UL
grant allocation and before RRCSetupComplete PUSCH. It is not a scheduler
handoff or PUSCH CRC failure.

## Resource Split

The hard-coded RRC config uses:

- HARQ format-1 resource at `starting_prb=0`, which succeeds strongly in both
  attempts;
- SR format-1 resource at `starting_prb=51`, which remains floor-class for all
  64 opportunities;
- identical 14-symbol format-1 geometry, cyclic shift 0, and OCC 0.

The upstream srsRAN_4G source still contains this hard-coded split. Upstream
issue `srsran/srsRAN_4G#1107` records the same COTS-UE frontier between
RRCSetup and RRCSetupComplete and the same later PUCCH-capacity warning, but
has no fix or linked development. CP2644 already closes the capacity leak; the
new live data identifies SR resource delivery as the earlier blocker.

## Decision

Gate a default-off compatibility A/B that changes only the dedicated SR
resource's `starting_prb` from 51 to the proven HARQ resource PRB 0. The same
RRC object feeds both the encoded RRCSetup and gNB PHY config, so the phone and
decoder remain coherent. Keep all traces, cleanup, RF, MCS, periodicity,
cyclic shift, and scheduler behavior frozen. Success is a valid positive SR,
followed by PUSCH and RRCSetupComplete; continue immediately through qcore,
PDU, and private data if reached.
