# CP2649: dedicated SR PRB0 compatibility A/B gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Added `PAVONIS_NR_SR_PRB0_COMPAT`, default off and cached on first use, in the
RRCSetup dedicated PUCCH builder. Disabled behavior keeps the upstream
hard-coded scheduling-request resource at `starting_prb=51`. Enabled behavior
changes only that resource to `starting_prb=0` and emits one marker per created
UE. Format 1, cyclic shift 0, 14 symbols, OCC 0, resource ID 2, sl40 offset 8,
HARQ resources, and every other RRC/PHY field remain unchanged.

The encoded RRCSetup and gNB PHY configuration are generated from this same
RRC object, so both ends receive the same resource move.

## No-RF Gate

Enabled and disabled normal config launches both exit 255 at the intentional
invalid physical-channel guard before bladeRF open or stream start. Source has
one cached environment read site. The run helper pins the isolated binary and
proves cleanup, all traces, and SR PRB0 compatibility in `/proc/$pid/environ`.

## Decision

Run one bounded CP2648 phone shape with only SR PRB0 compatibility added.
Success requires a valid positive SR after a positively ACKed RRCSetup, then a
post-setup PUSCH. If RRCSetupComplete reaches the gNB, continue through qcore
registration, PDU session, and private data in the same run.
