# CP2651: live standalone SR resource-0 compatibility gated no-RF

Date: [date-redacted] Europe/Zurich

## Change

Added `PAVONIS_NR_SR_RESOURCE0_COMPAT`, default off and cached once, in the
actual standalone master-cell-group builder in `cell_asn1_config.cc`.
Disabled behavior keeps `SchedulingRequestResourceConfig.resource=2`.
Enabled behavior changes only that reference to resource ID 0.

This does not move frequency: both resource IDs are PRB51. It changes the SR
from resource 2's cyclic shift 8 to the exact resource-0 geometry already
proven by the phone's positive RRCSetup HARQ ACK: format 1, PRB51, cyclic
shift 0, 14 symbols, OCC 0. sl40 offset 8 and every RF/RRC/scheduler field are
unchanged.

## No-RF Path Proof

Enabled and disabled normal config launches both exit 255 before bladeRF open
or stream start. The stronger path gate also passes:

- disabled log contains no live resource-0 marker;
- enabled log contains
  `PAVONIS_NR_SR_RESOURCE0_COMPAT active cc=0 resource_id=0`.

This proves the stimulus reaches the standalone builder before RF. Source has
one cached environment read. The run helper proves the new flag in the live
process environment and requires the same active marker before declaring
startup ready.
