## Verdict

The actual resource-ID A/B is negative. Reusing resource ID 0, PRB 51,
cyclic shift 0, format 1, 14 symbols, and OCC 0 changes the encoded dedicated
SR reference and the gNB PHY together, but it does not produce a valid SR.
Close resource ID 2/cyclic shift 8 as the standalone cause.

The earlier inference that invalid SR rows necessarily prove a PUCCH decoder
failure is now too strong. A positive HARQ ACK proves that the phone received
the RRCSetup transport block, not that its RRC layer accepted the setup and
queued RRCSetupComplete. If the phone rejects or cannot apply the dedicated
configuration, the gNB will still schedule SR occasions and decode only noise,
which matches CP2652.
