# CP2656: SA CSI removal compatibility gated no-RF

Date: [date-redacted] Europe/Zurich

## Provenance

The exact CP2652 over-air `masterCellGroup` advertises a periodic CSI report on
PUCCH resource 17 (`slots80=1`, format 2, PRB 50). Repository history provides
a direct match to the current failure:

- `bab0b488b` disabled `csi-MeasConfig` because the current configuration made
  PUCCH decoding fail;
- `dfe5cca7f` later commented out that safeguard while adapting CSI to a new
  source, without claiming the PUCCH failure was fixed;
- `d5859fb60` only removed the resulting dead comment.

The exact phone behavior is setup HARQ ACK followed by invalid SR and no energy
in proactively scheduled post-setup PUSCH windows. CSI is therefore a concrete
semantic compatibility candidate, not a speculative resource sweep.

## Coherence Audit

The standalone master cell-group object is copied into each UE, transmitted in
RRCSetup, and passed to `update_mac()`. The same object drives
`make_csi_cfg_from_serv_cell()` for the gNB UE PHY/scheduler. The common UE PHY
configuration initializes CSI to disabled. Removing `csi-MeasConfig` therefore
keeps both sides coherent: the phone receives no CSI setup and the gNB installs
no periodic CSI report.

## Patch

`srsgnb/src/stack/rrc/cell_asn1_config.cc` adds cached, default-off
`PAVONIS_NR_DISABLE_SA_CSI_SETUP`. For standalone cells only, the enabled path
clears `csi_meas_cfg_present` after the normal serving-cell builder completes
and emits:

```text
PAVONIS_NR_DISABLE_SA_CSI_SETUP active cc=0
```

The disabled path, RF configuration, SR resource, proactive grant, scheduler,
thresholds, and timing constants are unchanged.
