# CP2658: qcore foreign-GUTI identity fallback gated no-RF

Date: [date-redacted] Europe/Zurich

## Finding

CP2657 reached qcore twice with a real phone `RRCSetupComplete`, but the phone
presented a stale 5G-GUTI whose embedded PLMN and AMF identifiers do not belong
to this private core. qcore already routes an unknown GUTI into its Identity
Request procedure, but `validate_registration()` rejected a PLMN-mismatching
GUTI before that standards-coherent fallback could complete.

The patch does not accept or authenticate the foreign identity. It treats only
a nonmatching temporary GUTI as unknown, so qcore must retrieve the permanent
identity and run the normal AKA and NAS/RRC security procedures.

## Patch

`qcore/src/procedures/ue_associated/nas/registration.rs` adds cached,
default-off `PAVONIS_QCORE_ALLOW_FOREIGN_GUTI_IDENTITY_FALLBACK`. When enabled,
only a registration whose identity type is GUTI may continue past the embedded
PLMN mismatch. Direct SUPI behavior, authentication vectors, NAS security,
RRC security, registration acceptance, and subscriber authorization are
unchanged.

The flag is read once through `OnceLock`. The enabled path emits a bounded
protocol-level marker without logging the identity or subscriber credentials.

## Integration Gate

Two [host-redacted] integration tests pass:

- default off: the foreign-GUTI registration receives the existing reject;
- enabled: the same registration completes Identity Request/Response, AKA,
  NAS security mode, RRC security mode, capability exchange, Registration
  Accept, and configuration update.

The tests use qcore's private fixture credentials and do not print or copy
credential values into this report.

The June moving `+nightly` alias fails qcore's nested eBPF build with an LLVM
LTO parser error. The repository's own build helper documents
`nightly-[date-redacted]`; an isolated Cargo wrapper maps only aya-build's hardcoded
`+nightly` invocation to that already-installed project toolchain. No global
rustup state changes. A scoped `cargo clean -p qcore` removes generated output
before the isolated build.
