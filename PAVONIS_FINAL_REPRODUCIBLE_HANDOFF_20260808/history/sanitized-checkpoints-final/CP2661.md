## Repair

The remove action required the audited pre-write hash and a previously absent
backup path. It created the backup first, removed only `90170`, called the live
setter, and required exact ordered-list readback.

Authoritative result:

- setter result: 13;
- before/after count: 14/13;
- before target occurrences: 1;
- after target occurrences: 0;
- after canonical hash:
  `20825f15d52cb0f59cc8ffc4f83879e50b9c729a552b6084a4497535daf3ddab`;

ordinary `adb pull` could not read the deliberately root-owned mode-600 backup.
No second write was issued. A retrieval-only helper action streamed that same
backup through root and passed.
