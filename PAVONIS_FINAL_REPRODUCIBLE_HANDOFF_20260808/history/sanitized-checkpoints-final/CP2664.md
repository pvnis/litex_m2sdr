# Checkpoint 2664: qcore foreign-SUPI home-PLMN no-RF gate

Date: [date-redacted] Europe/Zurich

## Purpose

CP2663 proved that the real phone reaches qcore with a stale outer GUTI=[subscriber-redacted],
but its NAS Registration Request carries the authorized lab SIM's home PLMN.
The serving private network uses a different PLMN, so CP2658's GUTI-only
fallback correctly did not apply. This checkpoint gates a separate roaming
SUPI policy without bypassing subscriber authorization or security.

## Change

`registration.rs` now caches the default-off environment variable
`PAVONIS_QCORE_ALLOW_FOREIGN_SUPI_HOME_PLMN`. When enabled, it permits only a
PLMN-mismatching `MobileIdentity::Supi` to continue into the existing SUPI
registration path. That path still performs private `SubscriberDb` lookup,
AKA, NAS security, RRC security, capability exchange, Registration Accept and
configuration update. CP2658's separate foreign-GUTI behavior is unchanged.

Test-only framework support allows qcore and the mock UE to use the serving
network name for PLMN [network-id-redacted] while the mock USIM retains its home PLMN. No
subscriber credential values are written to this report or helper output.

## No-RF gate

On [host-redacted], four isolated integration-test binaries passed:

- foreign GUTI, flag off: registration reject;
- foreign GUTI, GUTI flag on: Identity, AKA and full secure registration;
- foreign SUPI, flag off: registration reject;
- foreign SUPI, SUPI flag on: AKA and full secure registration.

The first build attempt found and fixed a test-only borrow/clone compile error.
The next helper attempt proved all four tests passed but stopped on a redundant
INFO-log assertion after the tests. The helper was corrected to use test
results as the protocol assertion and binary strings as the deployment proof.
Neither issue changed qcore runtime semantics.
