# Checkpoint 2672: qcore drops all phone GTP for missing PDU-session extension

Date: [date-redacted] Europe/Zurich
Stamp: `CP2672_[date-redacted]`

## Result Class

Valid frozen real-phone attach/PDU and user-plane diagnostic. The loss is now
localized exactly: standalone srsENB emits plain legacy GTP-U on N3, while
qcore requires the 5G PDU Session Container extension. All uplink packets reach
qcore XDP and all are dropped as `UlDropGtpExtMissing`.

## Four-Stage Discriminator

All independent caps reached 128 rows:

```text
pdcp_input  128
adapter     128
gtpu_lookup 128
sendto      128
```

Every adapter row begins with IPv4 `0x45`. This includes exactly twelve
84-byte IPv4 packets, matching the phone pings. Every GTP lookup finds one
active [interface-redacted]. Every send returns the full wire length with errno zero; the
twelve ping packets are 84-byte payloads and 92-byte base-GTP datagrams. The
outgoing TEID is stable at `0x04f9b602` and matches qcore's activated local
TEID byte representation.

[host-redacted] captures 173 outgoing UDP/2152 packets from `[ip-redacted]` to
`[ip-redacted]`; [host-redacted]'s ordinary tcpdump capture is header-only. The latter is
expected once qcore XDP accepts packets for inspection: XDP runs before the
normal packet-capture path, so it must not be interpreted as an Ethernet loss.
Both hosts' route readback uses their direct Ethernet interfaces and addresses.

## Decisive Qcore Evidence

Qcore's pinned `/sys/fs/bpf/qcore_counters` map survived process shutdown. Its
only nonzero counters are:

```text
UlRxPkts             377
UlDropGtpExtMissing  377
```

Every other uplink parser/drop counter and all payload-byte counters are zero.
This proves all observed srsENB datagrams arrived at [host-redacted], their destination
and TEID lookup passed, and they failed only qcore's N3 PDU Session Container
gate.

The source explains the exact interoperability mismatch:

- srsENB `send_pdu_to_tunnel()` sends an eight-byte base GTP header for this
  NR path, despite the shared GTP library already supporting extension `0x85`;
- qcore `try_uplink_n3()` requires `GTP_EXT_PDU_SESSION_CONTAINER`, validates
  its four-byte length/terminator, then decapsulates the inner IPv4 packet;
- this standalone stack advertises and maps QFI 1 in both NGAP and RRC.

Close PDCP reorder, bearer mapping, TEID setup, socket send, Ethernet transport,
and qcore TEID lookup as causes. CP2669's zero-[host-redacted]-pcap interpretation is
superseded because it did not account for pre-tcpdump XDP interception.
