# Checkpoint 2673: NR GTP-U PDU Session Container gated no-RF

Date: [date-redacted] Europe/Zurich

## Purpose

CP2672 proves that qcore receives every real-phone uplink GTP packet but drops
all of them as `UlDropGtpExtMissing`. This checkpoint supplies the missing 5G
N3 framing on the gNB transmit side without modifying qcore or the frozen
CP2656 baseline.

## Patch

`srsenb/src/stack/upper/gtpu.cc` adds cached, default-off
`PAVONIS_NR_GTPU_PDU_SESSION_CONTAINER`. When enabled on an NR GTP instance,
`send_pdu_to_tunnel()` uses the existing srsRAN GTP serializer to emit:

```text
flags 0x34: GTPv1, PT=1, E=1
next extension: 0x85 PDU Session Container
extension bytes: 01 10 01 00
                 len=4, UL PDU Session Information, QFI=1, end
```

The QFI is not guessed from RF behavior: this standalone implementation
already hardcodes associated/mapped QFI 1 in its NGAP response and RRC DRB.
LTE instances and disabled NR instances retain the original path. The existing
PDCP-PDU-number extension remains the fallback for callers that supply a PDCP
SN. A once-per-process marker proves activation, and CP2671 send telemetry now
records `pdu_session_ext` while preserving the pre-header payload byte count.
