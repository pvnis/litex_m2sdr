# CP2675: Successful srsENB versus OCUDU SIB1 semantic diff

Status: PASS, NO RF. This checkpoint reopens the operator's actual endpoint:
the Android phone must attach and pass data through OCUDU on the LiteX M2SDR.
CP2392 and CP2674 remain separate untouched golden baselines.

## Method

The frozen CP2674 srsENB configuration was pulled read-only and started locally
against the file RF backend with RRC info logging. It generated the successful
control's exact 77-byte SIB1 without transmitting. The exact CP2392 OCUDU gNB
binary (`1add70ea...`) was then run on [host-redacted] against a ZMQ radio backend and the
private qcore, also without opening the M2SDR. Its SIB1 ASN.1 log was captured
after DU setup. Both gNB/qcore processes were stopped and the [host-redacted] postcheck
passed.

Both implementations emit JSON-like ASN.1 text with anonymous CHOICE braces,
so `cp2675_compare_sib1_semantics.py` canonicalizes named scalar fields,
container presence, and primitive arrays. It finds 118 named tokens on each
side, with 111 identical.

## Differences

The only new pre-access discriminator is cell identity:

- failed OCUDU phone profile: gNB ID `332`, NCI `5439488`;
- successful srsENB phone profile: gNB ID `411` (`0x19b`), NCI `105217`.

The other differences are downstream or non-blocking for Msg1: SearchSpace1
AL8 candidate count, `n-TimingAdvanceOffset`, `msg3-DeltaPreamble`, `p-Max`,
other-SI search space, `t311`, TX direct-current location, and an ASN.1-release
PLMN container name. Notably, the successful cell includes the stricter
`p-Max=10`, so suitability power compensation does not explain the OCUDU miss.

## Decision

Run one isolated OCUDU/M2SDR phone RF discriminator with only `gnb_id` changed
from `332` to `411`, reproducing the successful control's NCI while preserving
the CP2626 radio/cell/RACH shape. Judge camping and Msg1 first. Only after Msg1
may the TA, SearchSpace1, or Msg3 differences be tested.
