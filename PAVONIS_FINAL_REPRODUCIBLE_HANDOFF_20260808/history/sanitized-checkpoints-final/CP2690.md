# CP2690: Port map keeps the phone on channel 1 and gates a structured helper control

CP2690 stays no-RF and audits the durable port/path history before acting on
CP2689. Channel 0 is the certified cabled OCUDU/srsUE path. The added phone
antenna pair is physical channel 1. Therefore moving the gNB to channel 0 would
make the cabled bladeRF observer strong but would not be a valid phone-facing
antenna control.

The correct current discriminator is the known structured NR helper on channel
1:

- CP2432B used the partial-write-safe CP1166 starter, physical TX channel 1,
  ATT5, and RX1/RX2 gain36.
- It sent all 180M samples in 176130 writes with zero errors/short writes.
- RX2 was unclipped at -30.34 dBFS/max611 and decoded PCI1 PBCH with CSI +5.2 dB.
- CP2438 independently proved exact timed metadata on the same fixed path with
  one-shot PBCH and CSI +12.9 dB.

The current replay input is present at 3,094,340 bytes with SHA256
`95b6e060...`. The current CP1166 starter is `a1828689...`; the CP903 dual-RX
controller is `25999272...`. Both hosts are idle after CP2689/CP2688 cleanup.

## Decision

Do not run a channel-0 phone attempt and do not repeat ATT0 yet; CP2424 already
showed ATT0 alone did not restore channel-1 NR under the earlier path state.
First rerun the exact CP2432B structured helper on physical channel 1 with both
RX1 and RX2 at gain36, then decode both files with the established PBCH sweep.

- Helper PBCH pass: current RF path can carry structured NR, so CP2689 is a
  live-gNB presentation/output-state split despite self-RX.
- Helper PBCH fail: the current antenna/link path regressed below structured-NR
  margin; stop phone software work and use current tone/helper levels to select
  a physical/path or bounded drive recovery.

No gNB, phone, source, binary, gateware, threshold, or scheduler change is part
of this checkpoint.
