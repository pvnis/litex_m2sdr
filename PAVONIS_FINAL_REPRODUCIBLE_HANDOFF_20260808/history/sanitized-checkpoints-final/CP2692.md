# CP2692: Live all-timed gNB reaches RX2 with energy but no decodable SSB

CP2692 captures one live old9cbf gNB transmission on bladeRF RX1 and RX2 at
the same time, with the same physical channel-1 antenna path used by CP2691.
The capture and both analyzers complete successfully. The phone controller
returns `24` because the phone never acquires a cell, so this is a valid
external-waveform measurement and not a phone-ladder datapoint.

## External decode

RX1 measures `-44.4560 dBFS` relative to [date-redacted] with max component 73. It has
`0/847` expected-PCI PBCH and `0/847` CSI windows.

RX2 measures `-26.1425 dBFS` in the one-shot window with max component 1909.
It also has `0/847` PBCH and `0/847` CSI windows. CP2691's structured helper on
this same receiver was `-22.9944 dBFS`, max1328, `489/847` PBCH and best CSI
`+21.3 dB`. The live run therefore puts substantial energy onto RX2 but does
not present a recognizable NR SSB.

## No-RF presentation audit

The SI scheduler/FAPI trace is clean and matches the CP2497 baseline: CP2692
has 1157 scheduled lattice rows, 1157 PDCCH PDUs, 1157 PDSCH PDUs, zero
off-lattice rows, and the same DCI payload `0a80140000` throughout. Both runs
use the exact old9cbf gNB binary and have zero Soapy timeouts and zero
downlink-late events.

The decisive difference is the TX policy:

- CP2692 used all-timed mode: 2,222,268 all-timed writes and 569,137
  HAS_TIME writes.
- CP2497 used the forced-continuous fixture: zero all-timed writes, zero
  HAS_TIME writes after the single logical anchor, and its bounded 256-row
  worker trace was clean.

CP2692 did not arm a worker trace, so it cannot prove descriptor cleanliness
inside this run. Neither the CP2074B keep marker nor the old release marker
appears; that is expected because the all-timed shape does not exercise the
same contiguous-untimed path as CP2497.

## Verdict

The current failure is not an RX lane, receiver gain, raw channel-1 power,
gNB rebuild, MIB, scheduler, FAPI, or ordinary timeout/late-event defect. It is
specific to live all-timed TX presentation versus the structured helper and
the known-good forced-continuous fixture.

Next run the same dual RX1/RX2 live capture with only the CP2497 TX fixture
restored: all-timed off, forced-continuous on, the same zero-copy priming and
deadline-write settings, and a capped startup worker trace. PBCH recovery will
make this cadence split causal; continued failure will move the suspect below
the worker-descriptor layer.
