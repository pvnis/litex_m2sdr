# CP2699: ColorOS modal blocked RadioInfo; NR-only gate recovered

Date: [date-redacted] Europe/Zurich

## Finding

No RF was used. ADB remained authorized and the phone was unlocked, but the
foreground window was `com.oplus.ota`. A screenshot/UI dump showed a ColorOS
`System update available` modal over the RadioInfo screen. This overlay
mechanically explains CP2698's `expected one preferred-network spinner, got 0`:
the helper was parsing the modal hierarchy, not RadioInfo.

The modal was dismissed with Android Back. The next bounded UI dump proved:

- foreground `com.android.phone/com.android.phone.settings.RadioInfo`;
- exactly one `com.android.phone:id/preferredNetworkType` spinner;
- zero `Remind me later` modal rows.

The unchanged authoritative helper was then run with `nr_only via_app` and
passed end to end:

```text
RADIOINFO_TARGET=NR only
RADIOINFO_ALLOWED=NR
RADIOINFO_MODE6=23
RADIOINFO_OPLUS_MODE6=33
RADIOINFO_SET_MODE=PASS
```

## Decision

CP2698's zero-NR phone result is closed as a UI-stimulus artifact, not an OCUDU
RF failure. Repeat the exact CP2698 RF shape under a fresh stamp while this
proven phone state is available. The existing CP2531/CP2552 helper hashes and
the CP2392/CP2674 goldens remain unchanged.

Summary: `cp2699_summary.json`.
