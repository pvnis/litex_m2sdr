# Checkpoint 2732: OCUDU-on-bladeRF host and ZMQ no-RF gate

Date: [date-redacted] Europe/Zurich

## Question

Can the exact CP2729 OCUDU build run on [host-redacted] and connect to qcore before
using the successful CP2674 bladeRF-to-phone RF path as an OCUDU-versus-M2SDR
discriminator?

## Preserved baselines

- CP2392 OCUDU/M2SDR+srsUE and CP2674 srsENB/bladeRF+phone were not rebuilt,
  overwritten, or retuned.
- The deployed OCUDU executable is an isolated stripped copy of CP2729 commit
  `2d8b3b995e`, hash
  `78d0204e1b52d8659c2fd0181c377413828e1d9b56d984e7e51ee169f0ead826`.
- The successful srsENB radio geometry is bladeRF physical channel 1
  (RX2/TX2), TX gain 45 dB, RX gain 50 dB, DL center 1842.5 MHz, SSB
  1842.05 MHz, and UL center 1747.5 MHz.

## [host-redacted] capability gate

- `SoapySDRUtil --find driver=bladerf` succeeds.
- The Soapy bladeRF module exposes two RX and two TX channels, hardware time,
  CS16/CF32, native CS16 full scale [date-redacted], and 11.52 Msps support.
- Required host packages are `soapysdr-tools 0.8.1-4build1`,
  `soapysdr-module-bladerf 0.4.1-5`, `libzmq5 4.3.5-1build2`, and
  `libmkl-rt [date-redacted].4.304-4`.
- OCUDU uses an isolated `LD_LIBRARY_PATH`. The private `libmkl_rt.so.2`
  points to [host-redacted]'s coherent distro MKL runtime; no global library symlink
  or golden binary was changed. `ldd` has no missing dependency and
  `gnb --version` reports OCUDU 25.10.0 commit `2d8b3b995e`.

## ZMQ result

The second bounded no-RF launch ran for the full eight-second timeout and
returned the expected `REMOTE_RC=124`. All intended broadcast controls were
active:

- MIB intra-frequency reselection allowed
- srsENB SIB1 compatibility
- 20 ms SIB1 retransmission
- SearchSpace0 n0 phase
- `msg3_delta_preamble: -1` in the config

N2 connected to qcore at `[ip-redacted]:38412`; OCUDU reported the AMF
connection established and PLMN [network-id-redacted] supported. The only matched error text
was the pre-existing nonfatal DRM KMS permission warning. qcore then stopped
cleanly (`CP2664_QCORE_STOP=PASS`). No RF was emitted.

## Verdict and frontier

PASS. Host ABI, private runtime packaging, exact OCUDU executable, configuration
parsing, compatibility controls, cross-host N2, and qcore integration are
ready on [host-redacted]. The next checkpoint is a bounded OCUDU/Soapy/bladeRF RF
startup gate on physical channel 1, followed by one phone discriminator if
radio readbacks and runtime health pass. A phone success there exonerates
OCUDU semantics and localizes the unresolved pre-Msg1 failure to the
LiteX/M2SDR presentation; a phone failure keeps the fault above the SDR.

This branch is diagnostic only. Final success remains phone attach and private
bidirectional data through OCUDU on the LiteX M2SDR.
