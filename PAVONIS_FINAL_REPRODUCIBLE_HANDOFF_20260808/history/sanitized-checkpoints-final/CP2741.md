## Same-hardware modem join

Compact Android radio-state comparison confirms the CP2735/CP2740 split:

- CP2735 progresses to `REG_ROAMING`, NR data service, PDU-session setup, and
  bidirectional qcore traffic;
- CP2740 repeatedly reports the exact target NR cell as emergency-only,
  `NOT_REG_SEARCHING`, with `reasonForDenial=NONE`, and never reaches Msg1;
- neither path records a NAS rejection before this split.

The actual compatibility-profile SIB1 audit was rechecked. With the CP2731/
CP2740 profile and omitted Msg3 delta, all decoded values match the successful
srsENB payload. The only remaining structural difference is the release-
specific dissector path name for the PLMN container; its MCC/MNC, TAC, NCI,
and `notReserved` values match. Public Android logs therefore cannot explain
why access is not started.

`diag_mdlog`; QXDM logging is enabled and the vendor diagnostic router runs.
QCSuper 2.1.0.post4 was installed in the isolated [host-redacted] virtual environment
`/home/[host-redacted]/pavonis_qcsuper_cp2741` without system package changes.

The no-RF `qcsuper --adb --info` gate passed against the SM6375 modem:

- firmware `MPSS.HI.4.3.1.c5-00105-MANNAR_GEN_PACK-1.9283.189`;
- Qualcomm Diag version 8;
- QCSuper automatically changed USB from `adb` to `diag,adb`;
- the wrapper restored the original `adb` configuration and confirmed the
  authorized device afterward.

NR RRC code `0xb821`, produced a valid 24-byte empty-PCAP header as expected
with no serving RF cell, and again restored USB to `adb`.
