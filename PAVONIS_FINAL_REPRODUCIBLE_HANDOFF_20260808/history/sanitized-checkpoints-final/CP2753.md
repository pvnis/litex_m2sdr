# Checkpoint 2753: capture64 first-attempt interval passes no-RF gate

Date: [date-redacted] Europe/Zurich

CP2753 creates an isolated capture-only chain for the CP2752 follow-up. It
does not edit or replace the established CP2730, CP2745, or CP2751 files and
does not rebuild or deploy any gNB, Soapy, or gateware binary.

The isolated stage differs from the CP2730 stage in only two places:

- a default-off `PAVONIS_CP2753_CAPTURE_PROFILE` branch;
- one manifest line recording that branch.

With the profile disabled and the inherited CP2188 values supplied, the
assignment smoke returns exactly `capture=1 max=16 rms=-65 peak=-55`. With the
profile enabled it returns `capture=1 max=64 rms=-70 peak=-60`. Detector
policy, stage-1 candidate list, collection delay, TA compensation, RF shape,
and the existing arm file are unchanged.

The 64-window cap is about 12 MiB at 188160 bytes per window and covers about
10.24 seconds at the observed 160 ms opportunity cadence. The unchanged
12-second watcher delay therefore retains the CP2752 first-attempt interval,
including the previously omitted floor-class row.
