# CP2759 - Interrupted temporary swap caused a pre-RF void

Date: [date-redacted]

## Result

CP2759 did not start the gNB or the independent bladeRF RX2 capture. It is void
for phone, RF, PRACH, and uplink conclusions.

The CP2758 wrapper passed the [host-redacted] preflight and deployed its detached
capture helpers, but its exact gNB watcher timed out. The nested frozen runner
had already returned `BASE_RC=1`; no CP2730 run artifacts or gNB process were
created, and the QCSuper PCAP contains only its 24-byte header.

## Root cause

CP2757's externally forced cleanup interrupted the CP2753 temporary source-file
swap before its EXIT trap could restore the canonical files. Readback before
CP2759 repair showed:

- `cp1807_run_stage6_raresp40_realue_rar_msg3.sh` had the isolated CP2753 hash
  `1a2b90fa02fec7b4658329fb646a0e9a86c6d00d4bea04e9e4798e82bf09d1ba`.
- `cp2595_oplus_operator_select_remote.sh` had the isolated CP2676 hash
  `0b1fdaf23bbf64abd498dc27e020050bb6e3a5b802195ab8fc6c448c826a8d7e`.
- The CP2753 outer runner therefore failed its canonical-hash guard before RF
  startup. This guard is silent because it is a bare `[[ ... ]]` under
  `set -e`.

This is an orchestration-state failure, not a new radio failure.

## Repair

Both files were restored byte-for-byte from the known-good pre-CP2754 backups:

- canonical stage restored hash:
  `2c15ff6b899f95f4fda968d83c8e96d5755865ce99537e3786e1ae1f2fcc34f3`
- canonical selector restored hash:
  `223b45238a52d2322c151e53fde9db3542e6712442bfc8b32fb2e8de3bf022cc`

Both restored scripts pass `bash -n`. Targeted host checks found no gNB,
bladeRF capture, or QCSuper process left behind, and ADB still reports the phone
as `device`.

stamp. The discriminator remains: a phone-correlated RX2 uplink burst outside
