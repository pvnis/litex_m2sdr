# CP2797 - Long downlink capture reveals one-time timeline discontinuity

CP2797 ran the CP2796 sample-domain SFN diagnostic on the frozen phone/M2SDR
shape with stamp `[date-redacted]CP2797_M2SDR_PHONE_DL_SFN`. The bladeRF RX2
capture completed all `748800000` requested samples (`2995200000` bytes) at
`11.52 Msps`. Remote reduction retained 128 bounded 25 ms slices at 500 ms
cadence and removed the remote raw capture and slice archive afterward.

Run health was clean. The gNB recorded zero Soapy TX timeouts, downlink-late
events, release-late events, stream deficits, and partial returns. The phone
reported NR in 66/80 rows but never entered the private network or in-service
state. QCSuper recorded 66 MIB, 66 SIB1, one generated UL-CCCH, and no
DL-CCCH. The gNB completed 1907 empty PRACH windows with zero selected
preambles and no RAR. Per CP2754, the generated UL-CCCH record is not proof of
an over-air Msg1.

The downlink itself was strong: 124/128 slices decoded PCI500 PBCH, median SNR
was `21.1 dB`, minimum decoded SNR was `19.7 dB`, and 107 distinct SFNs were
observed. The four consecutive failures were slices 2 through 5, spanning
approximately 1.5 through 3.0 seconds into the reduced capture. Each still
measured PCI500 PSS/SSS at `25.2-26.9 dB`, so this was not an RF-amplitude
fade.

The exact sample/SFN join exposes the event:

- slices 0 and 1 have SFN residual 0 and SSB sample phase near 46.5-47.5k;
- slices 2-5 retain strong PCI500 sync but PBCH CRC fails;
- slice 6 recovers PBCH with SFN residual -1 and SSB phase near 27.3k;
- all remaining 121 decoded slices retain residual -1 through the end.

Across the outage the decoded SFN advances by 300 frames while the capture
advances by about 3008.336 ms. This is a persistent approximately 8.3 ms
sample/SFN step. After recovery there is no further frame-scale drift; SSB
phase changes by only about 687 samples over the remaining roughly 60 seconds.

The original CP2796 analyzer reports `continuity_pass=true` because its first
criterion allows an absolute residual of one frame. That result is retained
unchanged, but it is insufficient for this run: the single residual-state
transition following a strong-signal PBCH outage is the decisive metric.
CP2797 is therefore classified
`m2sdr_downlink_one_time_timeline_discontinuity_pre_msg1`.

A bladeRF capture-side drop was checked before assigning the event to the
transmit path. The capture returned the complete expected byte count with rc0;
its bounded console, bladeRF, and summary logs contain no overflow, overrun,
drop, timeout, warning, or error. The only error-like matches are benign stream
armed and USB inventory lines. This strongly weakens a capture drop, although
the raw bladeRF file has no hardware timestamps and cannot exclude it
mathematically.

Next: repeat the same bounded diagnostic with the existing default-off M2SDR
Soapy TX worker descriptor trace late-armed exactly when capture starts. Keep
the trace capped and metadata-only. Judge observer health first, then localize
any repeated 8 ms step: a coincident descriptor anomaly returns the work to the
Soapy continuation/timed-cadence branch; descriptor-clean air discontinuity
places the suspect below the Soapy descriptor layer. Do not resume PRACH
envelope widening until the downlink timeline is stable enough for the phone
to camp and emit a real Msg1.
