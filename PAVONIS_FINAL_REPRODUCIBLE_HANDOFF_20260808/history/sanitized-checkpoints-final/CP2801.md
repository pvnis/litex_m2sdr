# CP2801 - Looping DMA stale-payload replay identified

CP2801 ran stamp
`[date-redacted]CP2801_M2SDR_PHONE_DL_SFN_WORKER_PROP`. The intended fresh
trace path, nonempty late-arm file, and 65,536-row cap propagated. The wrapper
completed rc0 and fetched exactly 65,536 metadata rows.

RF, phone, and host health remain the same pre-access class. All 128/128
bladeRF slices decode PCI500 PBCH at median `20.7 dB` and minimum `19.4 dB`.
The gNB has zero TX timeout, downlink-late, release-late, and stream-deficit
events. The phone reports NR in 64/80 rows but never camps/private/in-service;
QCSuper records 64 MIB, 64 SIB1, one generated UL-CCCH, and no DL-CCCH. The
gNB completes 1905 empty PRACH windows with no selection or RAR.

The sample/SFN timeline fails again. It changes residual 0 to 2 between slices
0 and 1 (`-18.808160 ms` sample-minus-SFN), then 2 to 1 between slices 15 and
16 (`+6.386979 ms`). The remaining 112 slices stay in residual state 1. Thus
three consecutive long captures reproduce millisecond-class, run-variable
timeline steps while PBCH and host-visible TX health stay strong.

The descriptor rows are superficially clean: fixed 1022-sample zero-copy
submissions, no HAS_TIME-post, late, dedup, or short non-EOB rows. The handle
sequence is not clean. In 75 events it jumps over 872 virtual handles; the
largest jump is 21. At 11.52 Msps that is approximately 77.4 ms of DMA-frame
sample positions consumed without corresponding fresh user submissions. The
skips are concentrated near stream start with a few later events. For
comparison, the CP2075 and CP2077 traces skip only 7 and 3 handles over the
same 65,536-row scale; the CP2799 256-row startup trace already skips 25.

The source/gateware audit makes the mechanism mechanical:

- the kernel programs all 256 TX descriptors once and sets
  `LOOP_PROG_N=1`, so hardware cycles them indefinitely;
- when hardware `hw_count` overtakes userspace, `_dmaAcquireWrite()` resets
  `user_count` to `hw_count`, creating the observed handle jumps;
- flags are cleared after first consumption, but payload bytes are not;
- `TimedTXArbiter` treats an untimed standalone descriptor as immediate
  pass-through, not as a no-op.

Consequently, a hardware-overrun loop retransmits stale IQ. OCUDU later writes
all requested samples successfully, so its return accounting and timeout
counters remain clean, while the RF sample timeline has already repeated old
payload. This explains the otherwise contradictory CP2797-CP2801 evidence.

The gNB SI/FAPI trace rules out a scheduler-SFN jump: all 1365 adjacent SI
occasion deltas are exactly 160 slots. Wall cadence is approximately 160 ms;
the only greater-than-2-ms anomaly is the first startup interval. The defect is
below the scheduler/FAPI boundary.

Caveat: writing 65,536 TSV rows adds overhead and likely increases the 872-skip
count. It does not create the branch: CP2797 and CP2799 reproduce air timeline
steps without the extended trace, and CP2799's tiny startup trace already sees
hardware overtake.

Next: run the trace-off CP2802-gated control with the maximum 256-buffer
zero-copy prime. If it produces zero SFN residual transitions, retain prime256
and immediately resume the phone ladder. If it still steps, the ring cannot
provide sufficient headroom and the fix must prevent looping stale descriptors
at the kernel/DMA ownership boundary.
