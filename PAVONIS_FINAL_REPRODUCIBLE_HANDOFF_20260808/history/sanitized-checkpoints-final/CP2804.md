# CP2804 - Stale-payload zero-fill module and RF gate

CP2804 implements the functional fix identified by CP2801, default-off behind
`M2SDR_SOAPY_TX_ZERO_STALE_PAYLOAD`.

When enabled, the Soapy module sanitizes all TX ring payloads while the reader
is stopped. During operation it zeroes a consumed slot only if that physical
slot has not already been acquired for its next ring generation. If hardware
overtakes userspace, it zeroes the stale ring before advancing `user_count` to
`hw_count`. The existing flags/timestamp cleanup remains. Up to 16 bounded
metadata-only overtake markers report that the recovery branch fired.

Zero fill is the required semantic distinction: the LOOP-mode hardware still
advances DAC sample time, but an unavailable fresh descriptor emits zeros
instead of replaying old SFN-bearing IQ. This may erase individual symbols
during a producer miss, but it cannot shift all future waveform timing by
repeating stale payload.
