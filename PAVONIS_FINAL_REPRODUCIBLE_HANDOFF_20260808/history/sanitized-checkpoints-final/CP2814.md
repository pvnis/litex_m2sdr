# CP2814 - One-shot DMA closes replay but SFN step persists

Stamp: `[date-redacted]CP2814_M2SDR_PHONE_DL_SFN_DMA_PROGRAM`.

CP2814 is mechanism-proven. The kernel marker count rises from one to two, the
postcheck passes while the parameter is `Y`, and cleanup restores it to `N`.
The launch record proves stale zero-fill off, prime128, and worker trace off.

The one-shot path sustains the complete OCUDU/phone/65-second capture workflow
with clean host health: zero Soapy TX timeouts, downlink-late lines, or
write/stream deficits. Downlink is strong at 128/128 PCI500 PBCH and median
21.0 dB SNR, but it is still not sample-time continuous. Residual state is zero
for 11 slices and -1 for 117; the adjacent transition at indices 10 to 11 has
no failed slice between it and measures 5.981337 ms (495.981337 ms capture
elapsed versus 490 ms MIB-SFN elapsed).

The phone remains pre-Msg1: 68/83 monitor rows see NR, none camp or enter
service. QCSuper contains 66 MIB, 66 SIB1, one UL-CCCH, and no DL-CCCH. Stage-1
has 1905 rows, 1903 energy-gated, zero candidates/selections, maximum raw RMS
-60.488 dB, and no RAR.

Verdict: static descriptor replay is not the sole source of the timeline step.
One-shot DMA removes the stale-fetch mechanism but an empty-table interval can
still expose the existing untimed-continuation semantics: the AD9361 emits
zeros while invalid, then fresh untimed host buffers resume late and shift the
logical waveform. The active run proves `PAVONIS_SOAPY_TX_ALL_TIMED_CHUNKS=0`
and reanchor interval zero.

Next: combine one-shot DMA with the existing all-timed-chunks mode. This is a
new combination, not a repeat of CP1658/CP1718: those dense timestamps ran over
LOOP descriptors and suffered the exact descriptor-pressure family now
removed. With one-shot ownership, every late frame is timestamped and the
TimedTXArbiter can drop it while the PHY emits zeros, preserving the SFN/sample
timeline. Gate propagation and health before another long continuity run.
