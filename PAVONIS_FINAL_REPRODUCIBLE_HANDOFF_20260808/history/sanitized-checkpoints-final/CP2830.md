# CP2830 - Phone signal state splits OCUDU bladeRF and M2SDR

CP2830 stays no-RF and compares the Android monitor and QCSuper summaries from
the successful CP2744 OCUDU/bladeRF control with coherent CP2828
OCUDU/M2SDR. Both expose PCI500/TAC7/NCI105217 and the same decoded broadcast,
but the phone's lower-layer serving-cell outcome is categorically different.

| Metric | CP2744 bladeRF | CP2828 M2SDR |
| --- | ---: | ---: |
| Monitor rows | 89 | 83 |
| Exact PCI500/NCI105217 rows | 62 | 55 |
| Valid NR RSRP rows | 83 | 0 |
| Mean valid NR RSRP | -95.964 dBm | unavailable |
| Valid NR RSRQ/SINR rows | 71/71 | 0/0 |
| `CellSignalStrengthNr` primary rows | 83 | 0 |
| `ROAMING` rows | 82 | 0 |
| `NOT_REG_SEARCHING` rows | 1 | 67 |
| QCSuper UL-CCCH | 14 | 1 |
| QCSuper DL-CCCH | 1 | 0 |

CP2828's primary signal remains LTE for 79 rows and WCDMA for four rows even
while its NR cell identity is visible. CP2744 promotes NR-SA within 20 seconds,
reports RSRP/RSRQ/SINR, transmits repeated Msg1/UL-CCCH, receives DL-CCCH, and
reaches service. This is not a SIB1 semantic mismatch and CP2829 proves it is
not an M2SDR receiver missing an existing Msg1. The first physical divergence
is that the phone never establishes valid NR measurement/tracking on the
M2SDR waveform.
