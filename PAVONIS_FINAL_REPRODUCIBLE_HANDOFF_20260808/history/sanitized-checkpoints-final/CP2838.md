# CP2838 - SSB+6 observer run loses phone NR measurement

CP2838 runs the CP2837 bounded RF shape: the coherent one-shot/all-timed/
timestamp-backfill M2SDR transmitter, all-SSB `+6 dB`, the three-phase PRACH
collection sequence, the Android phone, and the independent 65-second bladeRF
RX2 uplink observer at gain 32.

The configured shape is valid. Both SSB-amplitude environment names are `6`,
the active runtime marker is present, the one-shot kernel marker advances
`8 -> 9` and restores off, and all 1,700 PRACH rows are phase-active with
timing override zero (`567/566/567` rows in phase classes 0/1/2). The gNB has
zero Soapy TX timeout and downlink-late events. Its only partial return is
fully recovered at the stream level (`stream_deficit=0`).

The phone does not reproduce CP2836's valid NR measurement state. Of 82
monitor rows, 77 identify the exact cell, but none has valid NR RSRP, RSRQ,
SINR, or primary-NR status; 66 rows are `NOT_REG_SEARCHING`. QCSuper records
63 MIB, 63 SIB1, one internal UL-CCCH, and no DL-CCCH. The gNB records 1,904
empty and zero nonempty PRACH detections, with no RAR.

The independent capture is continuous and unclipped (`absmax=656`). Its PRACH-
band median is `-41.637 dBFS`, maximum `-30.765 dBFS`, and it contains 818
groups at least 6 dB above the median. These groups are candidates only; CP2839
performs the required lattice join and detector replay.

Verdict: CP2838 is a valid no-Msg1 run and proves SSB+6 phone measurement is
not yet deterministic across the CP2836 and CP2838 shapes. It does not prove
an M2SDR waveform regression: the independent bladeRF observer and its launch
path are the largest run-shape difference from CP2836 and must be isolated as
a possible observer effect. Do not [interface-redacted] PRACH from this run unless CP2839 finds
a detector-valid over-air preamble.
