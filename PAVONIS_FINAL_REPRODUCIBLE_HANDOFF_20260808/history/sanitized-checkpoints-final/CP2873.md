# CP2873 - srs service timeout races late RegistrationComplete

The post-reboot CP2870 data run does not start OCUDU because the 180-second srs
private-interface gate expires. Identity audit again shows two exact configured
identities.

The qcore pass/fail join changes the interpretation. In CP2869, srs user-plane
activation occurs about 39 seconds after NGAP setup. In CP2873, qcore receives
both RegistrationComplete messages and repeated session-establishment uplinks at
the exact timestamp the wrapper terminates the srs NGAP association. Qcore then
cannot create the session because the transport is already gone.

Thus CP2873 is not missing AuthenticationResponse indefinitely; the phone's
registration completes late and the fixed 180-second service deadline tears
down the only working RAN at the finish line. It is void for OCUDU/data, but it
provides a specific control fix.

Add a default-preserving service-wait parameter and use 300 seconds for the next
phone ladder run. Keep the marker-authoritative SSH handling, RF shape, qcore,
identity audit, and data probes unchanged. Reboot/reload the phone before that
run because current post-handoff modem epochs remain one-shot.
