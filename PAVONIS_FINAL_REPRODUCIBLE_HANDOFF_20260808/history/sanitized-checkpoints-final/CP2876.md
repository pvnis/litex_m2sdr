# CP2876 - 300-second wait exonerated; srs PUSCH MCS 10 is marginal

The fresh-epoch run uses the approved 300-second srs service wait but still
never creates the primer bearer. It produces six exact configured identity
events and no OCUDU/data phase. RegistrationComplete/session messages again
surface only as the srs transport closes.

The CP2869 pass versus CP2876 fail radio join shows equivalent uplink quality
and the actual bottleneck. Both profiles use fixed `nr_pusch_mcs=10`. Their
initial 11-byte PUSCH decodes at +16.638/+18.475 dB. Subsequent 1,153-byte
grants sit near 0 dB and are highly marginal: CP2869 decodes 4 of the traced
large grants; CP2876 decodes 3. PUCCH ACK remains strong and mostly valid.

The longer deadline is therefore exonerated as the general fix. The primer's
fixed MCS 10 large uplink grant is marginal at the measured SNR, explaining why
authentication/security/session uplinks intermittently miss while initial
access works. The scheduler's own 0 dB mapping corresponds to MCS 4.

Create an isolated srsENB primer configuration changing only NR PUSCH MCS
10 to 4. Preserve the current srs helper/config and all OCUDU/M2SDR baselines.
Gate and deploy it no-RF, reboot the phone, then use it only for the primer in
the continuous attach+data run.
