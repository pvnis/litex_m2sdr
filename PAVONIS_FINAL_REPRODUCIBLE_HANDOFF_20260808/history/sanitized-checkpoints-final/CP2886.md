# CP2886 - User plane works; ICMP probe endpoint is invalid, no RF

The pinned qcore eBPF map preserved after CP2885 proves user-plane processing:
267 uplink GTP packets, 58,547 uplink payload bytes, 340 downlink packets, and
228,876 downlink payload bytes. All TEID, length, control, IPv4, and internal
drop counters are zero. The only drop is 33 packets without the required PDU-
session extension. OCUDU independently logs 234 target uplink GTP PDUs and 320
target downlink SDUs; 234 valid plus 33 extension-missing packets exactly
matches qcore's 267 uplink GTP receipts.

The original core probe is invalid. `qcoretun` is deliberately unnumbered, so
forcing `ping -I qcoretun` does not select a usable private source. The actual
private route is `[ip-redacted]/24 dev veth2 src [ip-redacted]`. The phone has curl,
so the next proof should prearm a bounded HTTP responder on `[ip-redacted]` and
have the live target phone request and verify a nonce response through its
private interface. That single request/response proves both directions without
depending on ICMP behavior. No RF ran in this checkpoint.
