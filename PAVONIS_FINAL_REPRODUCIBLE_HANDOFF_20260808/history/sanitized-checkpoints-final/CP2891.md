# CP2891 - Second HTTP run target-access void; pivot to M2SDR

The unchanged fresh-epoch retry repeats CP2889 exactly. The MCS4 primer reaches
service with one RACH/activation, both target and HTTP watchers prearm, but
OCUDU receives zero PRACH/PUSCH and qcore has no second RAN context, activation,
or reject before timeout. The HTTP client never runs. Cleanup passes.

Two consecutive target-access voids make another bare bladeRF retry
unwarranted. CP2885/CP2886 already provide the needed bladeRF control: target
attach, 234 OCUDU uplink GTP PDUs, 320 downlink SDUs, matching qcore eBPF packet
receipts, and nonzero phone RX/TX bytes. Preserve that baseline and transfer
the same continuous MCS4-primer, activation-event, and HTTP proof semantics to
the coherent M2SDR fixture, which is the actual endpoint.
