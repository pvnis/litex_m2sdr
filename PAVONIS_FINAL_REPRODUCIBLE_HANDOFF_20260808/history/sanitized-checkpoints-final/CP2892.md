# CP2892 - Coherent M2SDR continuous target no-RF gate

CP2892 implements the missing target service needed to move the proven CP2885/
CP2886 continuous phone handoff from bladeRF to LiteX M2SDR. No RF process was
started in this checkpoint.

The new gNB-only OTA stage preserves the continuous wrapper's existing qcore
and routing ownership. It reuses CP2730's generated M2SDR YAML and changes only
the N2 endpoint from the stock local qcore to the already-running continuous
qcore at `[ip-redacted]:38412`; it never starts/stops qcore, changes routing,
or owns a UE. Its cleanup is limited to its gNB and restoring
`dma_reader_program_mode=N`.

The new [host-redacted] service helper provides bounded `start|status|stop` ownership and
pins the CP2819 coherent fixture: one-shot DMA program mode, all-timed writes,
contiguous timestamp backfill, 128 zero-copy prime buffers, SSB `+6 dB`, the
CP2845 cell/PRACH/TA settings, the CP2794 gNB binary, and the current CP2074B
Soapy module. Status uses compact counters only.

The isolated CP2893 wrapper preserves the CP2857/CP2887 sequence while changing
only the target RAN. It keeps one qcore and one phone-policy epoch, uses the
CP2877 MCS4 srsENB primer, prearms the target activation and HTTP proof, applies
the proven CP2844 NR-only/manual-N3 control immediately before M2SDR launch,
and restores phone mode on every exit. The existing bladeRF wrapper and all
golden binaries/configs are unchanged.
