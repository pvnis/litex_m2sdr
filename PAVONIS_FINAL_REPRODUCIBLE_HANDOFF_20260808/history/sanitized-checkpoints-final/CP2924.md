# CP2924 - Phone-working srsENB staged for a native M2SDR substitution test

CP2924 stays no-RF and gates the direct hardware substitution requested by
CP2923. The exact isolated CP2656/CP2877 phone-working srsENB binary and MCS4
configuration are copied from [host-redacted] into a new [host-redacted]-only stage; neither the
CP2674 bladeRF golden nor the CP2392 OCUDU/M2SDR+srsUE golden is modified.

The binary hash is unchanged at `288cfcbd...`. The original config is retained
beside the M2SDR copy at hash `67cb9722...`. The copied config changes only:

- gNB bind/advertise address `[ip-redacted] -> [ip-redacted]`;
- TX setting `45 -> 0` (LiteX Soapy exposes this value as attenuation dB);
- RX gain `50 -> 40`;
- RF backend `bladeRF/auto -> soapy/driver=LiteXM2SDR`.

The M2 copy hash is `4d0e67a9...`; `rr.conf`, `sib.conf`, and `rb.conf` retain
their exact phone-working hashes. Address `.52` is absent and does not answer
from [host-redacted]; the helper owns it only as a temporary `/32` secondary address and
removes it on every stop. This supplies a distinct local gNB endpoint while
qcore remains on `.50`.

[host-redacted] already has the Soapy RF plugin (`d7eefbdb...`) and the deployed CP2074B
LiteX module/source plus current kernel module at their pinned hashes. `ldd`
passes, and `srsenb --version` reports version 25.10.0 with
`libsrsran_rf_soapy.so` active. No rebuild was needed.

The new remote helper `cp2924_srsenb_m2sdr_remote.sh` pins every binary,
config, plugin, module, source, and kernel hash; requires qcore and realtime
preflight; owns the temporary address and one-shot DMA program mode; preserves
the phone-working CSI, SR, cleanup, and GTP extension policies; and restores
address/program state on exit. Its SHA-256 is `e7d7cd7a...`.

The default-closed gate passes mechanically: unapproved `start` returns `2`,
creates no run directory, leaves no srsENB process or `.52` address, and leaves
`dma_reader_program_mode=N`.

Next: one bounded gNB-only RF run with qcore and an independent established
bladeRF DL snapshot. First judge whether this live srsENB waveform through
M2SDR restores isolated 20 ms PBCH decodability. Only if that air gate passes
should the phone be introduced for Msg1/attach.
