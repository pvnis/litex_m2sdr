# CP2930: channel-0 cabled observer explains phone no-cell result

Date: [date-redacted]

CP2930 stays no-RF and compares CP2927 against the retained CP2640
phone-working srsENB/bladeRF waveform using the same decoder and bounded
SearchSpace0 slot sweep.

The waveforms are the same quality class:

- CP2640 control: PCI500 PBCH SNR `9.8 dB`, CORESET0 index 6, SS0 index 0;
- CP2927 M2: PCI500 PBCH SNR `9.9 dB`, same MIB geometry;
- both place their only detected SI-grant class on slot 0 with five timing
  rows, `f_alloc=0x150`, MCS5, PRB `[1,8)`, symbols `[2,13)`, TBS80;
- CP2927's median PDSCH SNR is `10.5 dB` versus `4.3 dB` for the working
  control. Both offline captures remain PDSCH CRC-KO under the non-tracking
  file harness, so that CRC is not a live-phone discriminator.

The mechanical split is the port. CP2927/CP2929 logs say `Selected channel 0`.
The durable CP2690 map says physical M2 channel 0 is the certified cabled
bladeRF baseline and physical channel 1 is the phone antenna pair. CP2927
therefore proved exactly the cabled path observed by bladeRF, while CP2929 did
not transmit the target waveform on the phone-facing port.

Verdict: do not retry channel 0. Add an isolated, default-off srsRAN Soapy
logical-to-physical channel map and use `channels=1`, ensuring stream, gain,
frequency, bandwidth, and readback all address physical channel 1. Preserve
the CP2927 channel-0 binary/plugin baseline.
