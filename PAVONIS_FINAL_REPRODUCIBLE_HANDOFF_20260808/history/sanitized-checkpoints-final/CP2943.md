# CP2943: registration-aware service and data gate no-RF

Date: [date-redacted]

An isolated CP2937 lifecycle variant now preserves the CP2939 gain-fixed RF,
qcore, phone preparation, selector, FPLMN, restore, and packaging behavior, but
does not stop the radio after a stale status snapshot.

After the selector returns it checks the live qcore log for an existing
`Registering` event. If absent, it invokes one bounded N3/full-mode restore
without changing the prepared roaming/voice policy, matching CP2942's proven
late-access trigger. It then uses a streaming bounded registration wait,
polls up to 180 seconds for `[ip-redacted]`, and runs the established independent
phone-to-core and core-to-phone four-packet probes before phone restore or gNB
shutdown. Every outcome is packaged; wrapper success requires both probe gates.
