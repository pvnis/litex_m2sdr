Date: [date-redacted] Europe/Zurich

## Verdict

SUPERSEDED by CP2961. The no-RF synthetic and closed-path gates below passed,
but the SSH-spawned watcher did not survive the real remote session: it died
before the first setup ACK, and even a manual `nohup setsid` retry later died.
Do not reuse this external watcher. Use the CP2961-specified in-process event
touch instead.

At this checkpoint, a separate ATT16/RX40 helper used the existing M2SDR metadata-only TX
worker trace without exhausting its row budget at startup. The trace is armed
once by an incremental `tail -n 0 -F | grep -m1` watcher when srsENB emits the
first successful `PAVONIS_NR_SETUP_ACK_UL_GRANT active` marker. This centers the
trace on the reactive RRC/NAS exchange that fails in CP2953/CP2957.

## Trace Shape

- `M2SDR_SOAPY_TX_WORKER_TRACE_LIMIT=65536`;
- flush period `256` rows;
- per-run trace, arm file, and watcher PID live inside the fresh run root;
- arm-file path is propagated and verified through `/proc/<pid>/environ`;
- before the event, neither arm file nor trace file may exist;
- the M2 driver checks the arm file before incrementing the trace sequence;
- watcher uses streaming incremental input, never rescans the growing log;
- stop and failed-start cleanup terminate the watcher process group;
- status reports armed, watcher-alive, and compact trace-row counts.

Live helper startup also requires channel1/control0 RX40 requested/readback
`40.00 dB`. ATT16 and all CP2948 behavior remain otherwise unchanged.
