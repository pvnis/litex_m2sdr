# CP2961: phone reaches NR-SA service and qcore userplane; trace arm is void

Date: [date-redacted] Europe/Zurich
Stamp: `[date-redacted]CP2961_PHONE_SRSENB_M2SDR_CH1_ATT16_RX40_LATE_TRACE_SERVICE_DATA`

## Verdict

This is the first M2SDR phone run to cross the NAS registration frontier. The
phone enters NR-SA data service, qcore activates a private user-plane session
for `[ip-redacted]`, and Android starts its default `internet` data call. The
radio does not sustain delivery of the data-session response: Android receives
`ERROR_UNSPECIFIED`, creates no cellular interface, and no traffic probe runs.

The TX worker descriptor axis is void. The SSH-spawned `tail -F` arm watcher
dies before the first setup ACK. A manual `nohup setsid` retry starts only after
all then-existing ACKs and also disappears later. No arm file or trace TSV is
created. CP2958/CP2959's external-watcher gate is therefore superseded; the
next instrument must touch the existing driver arm file in-process at the
already-proven setup-ACK event.

## Registration And Data Sequence

The first accepted setup reaches qcore at `[date-redacted]`. Qcore registers the
private test subscriber and activates `[ip-redacted]` at `[date-redacted]`. The
phone monitor changes to `data_reg=IN_SERVICE`, `data_rat=NR_SA` at
`[date-redacted]` and remains in-service through `[date-redacted]`.

Android creates a cellular network agent at `[date-redacted]` and asks the modem
to set up the preferred `internet` data profile over NGRAN. At
`[date-redacted]`, the modem returns `ERROR_UNSPECIFIED`, no interface, no
addresses, and no bearer/QoS state. Qcore deactivates its session on the first
connection's inactivity release at `[date-redacted]`. Later retries include one
new registration and two stale security-protected updates without a usable
outer TMSI.

This distinguishes network registration from data-session completion: the
M2SDR stack now proves the former, but not the latter or bidirectional traffic.

## Trace-Arm Failure

The original watcher PID is already absent at the first direct check. Four
setup ACKs occur at `[date-redacted]`, `[date-redacted]`, `[date-redacted]`, and
`[date-redacted]`. The manual watcher is launched at about `[date-redacted]`, after
those events, and later dies with `armed=0`, `rows=0`, and no trace file.

The M2 driver already checks `M2SDR_SOAPY_TX_WORKER_TRACE_ARM_FILE` before
opening/incrementing the bounded trace. No driver change is required. Add a
default-off, env-cached, once-per-run file touch to srsENB's existing valid
setup-ACK branch and pass the same path to both srsENB and the driver.

## Next

Build the event-only in-process arm hook in an isolated srsENB binary; do not
replace the CP2924/CP2674 goldens. Prove the disabled path and closed helper
no-RF, then repeat ATT16/RX40 from a fresh phone epoch. The descriptor trace
must cover the qcore user-plane/data-call interval. A descriptor defect names
the timed-TX presentation fix; a clean descriptor sequence moves the suspect
below Soapy or into reactive downlink scheduling/delivery.
