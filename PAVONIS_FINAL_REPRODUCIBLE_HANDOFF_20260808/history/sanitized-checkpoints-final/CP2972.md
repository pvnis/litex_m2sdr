# CP2972: Identity Request duplication discriminator no-RF

Date: [date-redacted] Europe/Zurich

## Verdict

The saved NR-MAC PCAPs identify the first concrete difference between CP2961's
working stale-GUTI exchange and CP2971's stall. Both use the exact same
15-byte downlink LCID1 payload hash `e0c9efd43d4c`, the qcore-generated Identity
Request path. In CP2961 RNTI `0x461a`, that payload is transmitted twice at
`[date-redacted]` and `[date-redacted]`; the phone emits a new 36-byte UL LCID1 SDU
45 ms after the second copy and continues bidirectional SRB traffic. In CP2971
RNTI `0x4604`, it is transmitted once at `[date-redacted]`; the phone emits a
strong positive HARQ ACK 15 ms later but never emits another UL LCID1 SDU.

The CP2971 follow-up grants are not empty-air: fourteen decode CRC OK. They all
contain exactly the same short-BSR-zero plus padding shape. This places the
stop before UL scheduling or decoding: the reactive downlink does not cause a
new SRB/NAS response.

## Instrument

`cp2971_nr_mac_pcap_summary.py` parses the structured srsRAN `mac-nr` PCAP
header and NR MAC subheaders and prints only direction/RNTI/frame, LCID/length,
and SHA-256 prefixes. It never prints raw RRC/NAS bytes. Python compilation and
both PCAP parses pass.

## Controlled Test

Add a default-off one-shot post-setup downlink-retransmission control. Arm it
after the first valid setup ACK, then convert the next positive HARQ ACK for
that RNTI into one scheduler NACK while retaining the decoded value only in
telemetry. That requests one normal HARQ retransmission of the exact reactive
DL TB and reproduces the CP2961 two-copy shape without changing qcore payload,
RLC/RRC/NAS semantics, RF, thresholds, or timing. Keep the bounded CP2967 UL
grants enabled so any resulting Identity Response has opportunities.
