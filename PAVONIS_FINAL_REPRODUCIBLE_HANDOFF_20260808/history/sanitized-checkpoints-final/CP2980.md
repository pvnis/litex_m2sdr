## Verdict

CP2980 is a valid frontier advance. Close qcore DNN policy and teardown timing
as the immediate blockers. The remaining failure is late connected-mode DL
delivery/response on the M2SDR path. The current branch forces only the first
positive DL ACK after setup to one scheduler NACK; its budget is exhausted
long before PDU-session setup.

Next use the already-built bounded env control with no source change: set
`PAVONIS_NR_SETUP_FOLLOWUP_DL_HARQ_RETX_ACKS=16` so the first 16 decoded
positive ACKs after each setup each receive one normal HARQ repeat. Keep every
other CP2980 control frozen. Judge whether the two late setup blocks now lead
to an UL response, LCID4, Android `[ip-redacted]`, and both data probes. This is a
diagnostic reliability fixture, not yet a native final fix.
