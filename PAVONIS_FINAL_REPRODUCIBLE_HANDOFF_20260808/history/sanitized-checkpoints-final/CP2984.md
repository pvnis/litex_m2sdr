## Verdict

CP2984 is a valid retry-mechanism and earlier NAS-progression datapoint, but it
is void for the CP2980 late-session-downlink question. The run never reaches
qcore userplane allocation, gNB bearer registration, or the late 35/156-byte
LCID1 pair that CP2980 left unanswered. Spending retries from the first setup
ACK onward therefore does not reliably target the frontier and did not produce
service in this roll.

Do not repeat budget 16 unchanged. Keep the proven one-shot baseline and audit
the smallest default-off way to arm a bounded retry only at the PDU-session /
bearer-setup transition. The next RF run should preserve the CP2980 lifecycle
and RF shape, leave early NAS HARQ native, and repeat only the late connected
downlink whose missing UE response currently blocks LCID4 and Android private
IP.
