# Checkpoint 2985: DRB-triggered late DL HARQ retry gated no-RF

Date: [date-redacted] Europe/Zurich

## Source finding

The CP2980 late downlink is emitted by `send_rrc_reconfiguration()` after RRC
adds the new DRB logical channel to MAC through `mac_nr::ue_cfg()`. This is a
direct in-process event before the reconfiguration is queued to SRB1. It is a
more precise arm point than either a log watcher or a retry budget consumed
from the first setup ACK.

## Implementation

The current CP2973 source baseline gains one default-off cached control:

`PAVONIS_NR_PDU_SESSION_DL_HARQ_RETX_ACKS`

When `ue_cfg()` first receives a logical channel at or above the first DRB
LCID for an RNTI, it atomically arms the existing scheduler-NACK/HARQ-repeat
state with this bounded budget and logs one
`PAVONIS_NR_PDU_SESSION_DL_HARQ_RETX armed` marker. The existing setup-ACK
one-shot remains independent and unchanged. The common feedback branch is
active when either cached budget is enabled; unset/zero/invalid values retain
the previous behavior. There is no per-sample work, file polling, or new lower
PHY instrumentation.

The isolated helper selects:

- setup-follow-up DL retry budget: 1;
- DRB/PDU-session late DL retry budget: 2;
- all CP2980 RF, UL-grant, core, phone, and configuration fixtures unchanged.
