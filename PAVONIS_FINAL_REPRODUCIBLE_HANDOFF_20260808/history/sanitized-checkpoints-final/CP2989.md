# Checkpoint 2989: unknown-update identity fallback qcore gate no-RF

Date: [date-redacted] Europe/Zurich

## Implementation

Qcore now has a cached, default-off private-lab compatibility control:

`PAVONIS_QCORE_ALLOW_UNKNOWN_UPDATE_IDENTITY_FALLBACK`

The standards-default path is unchanged: a mobility/periodic registration
update without a recoverable NAS security context is rejected as implicitly
deregistered. With the flag enabled, only that reject is bypassed. The request
then follows qcore's existing unknown-temporary-identity path: reset local NAS
security, request SUPI identity, authenticate the configured private subscriber,
activate NAS security, and continue normal registration.

## Runtime gate

The isolated helper starts qcore without RF, verifies the new binary hash, and
enables all three established private-lab compatibility flags. `/proc` proves
the new flag is present in the qcore process. Compact status reports a separate
`unknown_update_fallback` count. Start, listener, status, redacted stop, and
no-residual-process checks pass.

The first `/proc` proof attempted a privileged redirection as the unprivileged
shell and failed before reading data. Repeating with `sudo cat` passes; this was
an audit-command issue, not a runtime failure.
