## User-data verdict

The PDU session is real, but payload traffic is not proven. The root Android
ICMP probe had a valid route yet received no replies and advanced neither the
private interface RX nor TX counter. The qcore eBPF map independently records
zero UL packets, zero DL packets, and zero payload bytes, with all drop counters
also zero. This localizes the negative before qcore user-plane processing and
agrees with the absence of LCID4 at the gNB.

The core-side ICMP result is instrument-invalid rather than a second data-plane
negative. Its helper exits before printing when `ip route get [ip-redacted]`
selects source `[ip-redacted]`; the helper incorrectly requires source
`[ip-redacted]`. The host also retains stale qcore-owned `/32` routes for
`[ip-redacted]` through `.6` on `veth0`; qcore logged `File exists` while adding
the active `.2` route. The established CP2887 private HTTP request/response is
the correct bidirectional instrument because it explicitly binds the server to
`[ip-redacted]` and the Android client to the live [interface-redacted] interface.
