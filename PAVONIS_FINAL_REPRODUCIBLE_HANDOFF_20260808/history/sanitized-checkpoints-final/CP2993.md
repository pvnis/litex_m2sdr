## Scope

This checkpoint changes no RF, NAS, retry, subscriber, phone-policy, qcore
binary, or srsENB binary setting. It wraps the frozen CP2990 lifecycle with the
already-proven CP2887 private HTTP request/response and adds stopped-qcore route
hygiene plus compact eBPF accounting.

## Components

- `cp2993_qcore_stale_route_cleanup_remote.sh` removes only validated
  `10.255.0.2..254/32 dev veth0` routes and refuses to clean while qcore runs.
- `cp2993_phone_http_on_private_ip_remote.sh` holds one bounded SSH session,
  polls only Android interface metadata, and immediately invokes the preserved
  CP2887 bound curl when `[ip-redacted]` appears.
- `cp2993_qcore_counter_summary.py` reduces the pinned per-CPU eBPF JSON map to
  22 named totals without printing the raw map.
- `cp2993_run_phone_http_data_proof_rf.sh` prearms the CP2887 server and phone
  waiter, runs exact CP2990, preserves the legacy ICMP probes as diagnostics,
  and independently packages both remote roots even if CP2990 returns RC1.

The HTTP gate requires both remote commands to return zero, an exact nonce
request from `[ip-redacted]`, the exact response on Android, and positive private
interface RX/TX deltas. The server snapshots qcore eBPF counters immediately
after the response and before CP2990 tears down the bearer.
