Date: [date-redacted]

Stamp: `[date-redacted]CP2999_CH1_ATT16_AGE_0_60_120_SI_CAPTURE`.

## Purpose and shape

CP2998 found normal RF amplitude but weak PBCH and uniformly undecodable SI in
a one-second capture. CP2999 held the identical CP2985 srsENB/M2SDR physical
channel-1, RX40, ATT16 shape up and captured independent one-second bladeRF RX2
windows at controller delays 0, 60, and 120 seconds. No phone control or RF,
gain, timing, scheduler, retry, qcore, or threshold setting changed.

Both host preflights passed. The gNB and qcore ran cleanly for the entire
sequence: zero RACH/connected/core events and zero Soapy timeouts, time errors,
underflows, or late events. After capture, both services stopped, [host-redacted] returned
to M2 program mode `N`, and both hosts passed quiescence/device postchecks. The
fetched 138,280,960-byte archive SHA-256 is
`8dcab6c83519d861a282668f23da319c60cea3a1acaef874762bffebfe614350`;
the redundant [host-redacted] copy was removed after local hash verification.

## Analyzer repair

The first PBCH analysis preserved all data but stopped while writing mixed
CRC-KO/CRC-OK rows: `cp2916_analyze_m2sdr_dl_snapshots.py` added
`sfn_residual_frames` only to good rows, while `csv.DictWriter` derived its
schema from the first bad row. The parser-only repair initializes that field to
`None` in every row. Source SHA-256 changed from
`0a81e93a48e91c0032d5996fbe053221c8c25c90e39f039abf03a95e368d096b`
to `627b6a14b1d62b22d79fe33bc542b538f36f7650c63197ed834fa92f6dc1a2d1`.
Compilation and the preserved-data rerun pass. No RF runtime source changed.

## Verdict and next rung

Simple late settling is rejected for scheduled SI through roughly 127 seconds.
This run remains in a persistent scheduled-phase TX bad class despite constant
external power and improving PBCH. Another phone retry would be predictably
void for SIB1/access.

The next rung is a bounded bad-class TX descriptor trace spanning a scheduled
SI epoch, judged with the existing CP2047 continuation gate and joined to an
independent capture. CP2997 already found identical startup descriptor geometry
between the CP2992 good roll and CP2995/2996 failures, so the trace must cover
the actual SI capture interval, not just setup. If descriptors remain clean
while SI stays weak, move the suspect below the Soapy descriptor layer and test
a controlled M2 stream/device reset or known-good helper presentation before
another phone run. Preserve CP2993's prearmed HTTP proof for the next qualified
PDU-session roll.
