# CP3002: clean descriptors and strong PBCH coexist with weak scheduled SI

Date: [date-redacted]

Stamp: `[date-redacted]CP3002_SELFCONTAINED_SI_EPOCH_TRACE_CAPTURE`.

## Purpose and execution

CP3000/CP3001 proved that separate tool calls could not synchronize the worker
trace and independent capture. CP3002 used one self-contained local command:
start the frozen CP2985 channel-1/RX40/ATT16 gNB with a bounded 131,072-row TX
worker trace, wait for readiness, then immediately start a delay-zero one-second
bladeRF RX2 capture. The doubled row cap changed only diagnostic duration; all
RF, waveform, qcore, scheduler, retry, and phone controls stayed frozen.

Both host preflights passed. The gNB and qcore had zero RACH/core events and
zero Soapy timeout, time-error, underflow, or late events. Both services stopped
and both hosts passed postchecks; [host-redacted] returned to M2 program mode `N`.

## Verdict and next rung

CP3002 supplies the missing discriminator: a persistent scheduled-SI bad class
exists while the exact overlapping Soapy descriptor presentation is clean and
PBCH is stronger than the known-good reference. Gross RF level, general TX
coherence, descriptor churn, late/dedup/partial flags, and the worker trace as
the cause are closed for this roll. The trace-enabled result also reproduces
CP2998/CP2999's weak SI without a trace, so diagnostic overhead does not explain
the class.

Move below the descriptor metadata boundary. First stay no-RF and inventory
the already-built bounded pre-DMA, post-conversion, actual-DMA, and same-device
self-RX taps. Choose the smallest existing sample tap that can cover scheduled
SI without changing the runtime hot path. The next RF discriminator should
compare host-visible scheduled-SI samples to simultaneous bladeRF air IQ. If
host-visible SI is already bad, the source/srsENB path is responsible; if it is
good while air SI is bad, the fault lies in sample conversion/DMA/gateware/RF
serialization. Do not retry the phone until scheduled SI passes.
