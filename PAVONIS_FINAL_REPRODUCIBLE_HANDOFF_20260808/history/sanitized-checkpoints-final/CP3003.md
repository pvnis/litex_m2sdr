# CP3003: select the bounded actual-DMA tap for scheduled-SI isolation

Date: [date-redacted]

## Purpose

CP3002 proved that the complete bladeRF capture overlapped a CP2047-clean TX
descriptor stream while PBCH remained strong and every scheduled SI occasion
remained weak. CP3003 stays no-RF and inventories the deployed LiteX M2SDR
sample taps so the next run can compare host-visible scheduled-SI samples with
simultaneous air IQ without adding new source instrumentation.

## Tap inventory

The deployed source is the CP2817/CP2074B lineage, source hash prefix
`b5131aab` and module hash prefix `b784c400`. It contains two relevant TX dump
paths.

`M2SDR_SOAPY_TX_DUMP_PATH` is a pre-DMA Soapy-input tap. It performs per-sample
RMS, peak, and mean work, converts CF32 to CS16 for the dump, and opens/writes
data and metadata from each call. CP1405 already showed that a large use of this
tap can degrade the live path. It is rejected as the first discriminator.

`M2SDR_SOAPY_TX_DMA_DUMP_PATH` is the selected tap. It runs after sample
conversion/interleaving, the 16-byte TX DMA header, timestamp, and zero padding
have been finalized. In zero-copy mode it records the exact mmap ring slot made
visible by the subsequent software-count update. It has existing bounded
controls for buffer count and start handle. It does no per-sample statistics,
although it still opens and appends the data and metadata files once per dumped
buffer, so run health remains a validity gate.

Full-rate same-device RX append is rejected: CP1764/CP1894 make it detection-
void and it measures the RF return path rather than the host-to-DMA boundary.
The worker descriptor trace remains useful only as metadata and was already
exonerated by CP3002.

## Handle window

CP3002's bladeRF capture starts at epoch ns `[hex-value-redacted]`. Its final
strong-energy SI occasion, SFN 416, has best snippet start sample `9879676`, or
about `0.857611 s` after capture start. This maps to epoch ns approximately
`[hex-value-redacted]` and worker handle approximately `24062` in the CP3002
trace. The trace readbacks around that point are monotonic: handles 23000,
24000, and 25000 occur at epoch ns `[hex-value-redacted]`,
`[hex-value-redacted]`, and `[hex-value-redacted]`.

The next discriminator therefore uses:

- `M2SDR_SOAPY_TX_DMA_DUMP_START_HANDLE=23000`
- `M2SDR_SOAPY_TX_DMA_DUMP_BUFFERS=[date-redacted]`
- a bounded 131072-row worker trace
- the same self-contained gNB-start plus immediate bladeRF-capture launch used
  by CP3002

The dump covers handles 23000 through 25047, bracketing the predicted SI event
by roughly 90 ms on each side while staying at the CP1228-proven [date-redacted]-buffer
budget. No pre-DMA dump, probe-arm polling, same-device RX append, phone, or
source change is required.

## Acceptance and interpretation

The run is valid only if the bladeRF capture overlaps both the worker trace and
the DMA-dump handle range, the DMA metadata contains exactly [date-redacted] consecutive
records beginning at handle 23000, CP2047 remains clean over the joined epoch,
and TX timeout/late/error counts stay in the CP3002 zero class. Failure of any
gate makes the host-sample comparison observer-void.

If reconstructed actual-DMA samples contain a standards-valid SI DCI/PDSCH at
the matching scheduled occasion while air IQ does not, the defect lies below
the finalized DMA buffer boundary: ring publication, kernel/gateware timed-TX,
or RF serialization. If the actual-DMA samples are already weak or invalid,
the defect lies above that boundary in srsENB sample generation or the
conversion/framing path. The phone remains parked until scheduled SI passes.
