Date: [date-redacted]

## Purpose

CP3006 reaches qcore registration but stalls while waiting for the UE's
authentication response after one setup-era forced DL retransmission. CP3007
prepares a single-knob budget2 control without changing the srsENB binary, RF
configuration, qcore, phone policy, PDU-session retry budget, or HTTP proof.

## Implementation

The existing CP2985 remote helper now reads
`PAVONIS_NR_SETUP_FOLLOWUP_DL_HARQ_RETX_ACKS` once at script start, defaults it
to the previous value `1`, validates integer range `0..16`, passes it into the
gNB process, verifies the exact process environment, and records the value in
the start marker. The CP2990 inner lifecycle validates the same value, forwards
it through the SSH launch, and requires the matching start marker.

No standards-default source or binary behavior changes. The CP2990 outer and
CP2993 HTTP wrapper hashes remain byte-identical. The frozen srsENB binary,
configs, RF plugin, Soapy module/source, PDU-session retry budget2, and 128
follow-up UL grants remain pinned by the existing helper.
