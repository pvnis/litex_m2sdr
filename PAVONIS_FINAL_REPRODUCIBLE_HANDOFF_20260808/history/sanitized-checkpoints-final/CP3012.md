# CP3012: Soapy RX sub-MTU timestamp root cause

Date: [date-redacted]

No RF transmission was used. The only hardware operation was bounded M2SDR RX.

The CP3010/CP3006 event join closes the proposed setup-retry arm change. In
CP3010, a CRC-OK 11-byte Msg3 at `+9.188 dB` is followed by five native RRC
Setup HARQ/PUCCH ACK opportunities, all invalid at `-12.586..-6.314 dB`. In
CP3006, the fifth setup ACK becomes valid at `+22.243 dB`; only then does the
post-setup policy arm, and it forces the next valid downlink ACK at
`+25.797 dB`. The policy is correctly post-setup. Moving its arm to Msg3 would
not affect invalid UCI because the forced-NACK path requires a decoded positive
ACK, and native scheduling already retries RRC Setup on invalid ACKs.

A compact join of 13 named phone runs also rejects static PRACH offset as the
splitter: good and bad runs have heavily overlapping Msg3 offset ranges. The
reusable discriminator is instead the bimodal uplink state. Valid PUCCH/SR rows
jump to roughly `+10..+33 dB`; invalid rows remain around `-17..-6 dB`, often
for a whole RNTI or run.

Source audit finds a matching defect in `LiteXM2SDRStreaming.cpp::readStream()`.
When a call first copies samples from an old remainder and then fills the same
return from a new DMA packet, the function overwrites `timeNs` with the new
packet timestamp even though the returned buffer begins at the old remainder.
The installed module reports RX MTU `510` samples. A new bounded continuity
probe passes MTU-clamped requests, then deterministically exercises the defect
below MTU:

| Request | Discontinuous transitions | Maximum absolute error |
| --- | ---: | ---: |
| 257 | 23/23 | 253 samples |
| 333 | 23/23 | 324 samples |
| 377 | 23/23 | 376 samples |
| 509 | 0/23 | 1 sample rounding |

srsENB asks for 11,520 samples per millisecond, which is not divisible by the
510-sample stream MTU. Its final short read creates a remainder; the next receive
buffer can therefore inherit a startup-phase-dependent timestamp error hundreds
of samples wide. This is larger than PUCCH timing tolerance and matches the
run-start-decided good/floor behavior.

Next patch only timestamp ownership: once a read has emitted remainder samples,
preserve that first sample's `timeNs`/`HAS_TIME` instead of replacing it with
metadata from the appended packet. Build and deploy with the established
CP2817 source/module backup discipline, then require all four continuity probes
to pass before any RF run.
