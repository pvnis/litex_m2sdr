# CP3016: RX timestamp fix restores attach; uplink user packets stop before qcore

Date: [date-redacted]

Stamp: `[date-redacted]CP3016_PHONE_HTTP_SOAPY_RX_TIMESTAMP_FIX_RETRY`.

The exact unchanged no-reboot retry of CP3015 runs on the CP3013 LiteX Soapy
RX timestamp fix. The launch proof records source `644e7858...`, module
`81b8cb2e...`, and setup retry budget2. RF health is clean: zero timeout,
time-error, underflow, late, and stream-error events.

This is the first strong end-to-end access result after the timestamp repair.
The gNB accepts four RACH attempts. PUSCH is CRC OK on 58/64 rows, with a best
SINR of `+12.518 dB`; PUCCH ACK is valid on 50/64 rows and SR on 16/64 rows.
The phone has valid target-cell NR service and its private interface for 84/90
monitor rows, first appearing three seconds after qcore registration. Qcore
completes registration and user-plane activation, and retains the session for
about 321 seconds. This closes the former run-stable floor/good uplink split:
the CP3013 first-sample timestamp fix is effective in the real phone lifecycle.

User data reaches the radio stack but not qcore. The NR MAC capture contains
175 LCID4 packets, all uplink, proving decoded DRB traffic from the phone at
srsENB. The phone HTTP client binds to the private interface and transmits
4722 bytes before timing out; its receive counter does not move. The prearmed
qcore HTTP listener accepts no connection. The gNB also emits the expected
PDU-session GTP-U container marker. Thus the remaining boundary is below
srsENB MAC and before qcore user-plane ingress, not OTA access, Msg3, PUCCH,
or phone interface creation.

The qcore-side eBPF counter snapshot is missing because the CP2993 command uses
`set -e`: the expected HTTP accept timeout exits the shell before `bpftool`
runs. Fix that instrumentation no-RF, then audit the host-local GTP-U route and
qcore attachment points. In this deployment both endpoint addresses live on
[host-redacted], so Linux may route the srsENB-to-qcore datagrams over `lo` while qcore's
user-plane program is attached only to the physical interface. Do not spend
another RF roll until that path is confirmed or rejected from source and host
state.
