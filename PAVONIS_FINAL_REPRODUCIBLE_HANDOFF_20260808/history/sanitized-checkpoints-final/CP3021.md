# CP3021: local M2 handoff reaches the OCUDU cell but emits no Msg1

Date: [date-redacted]

The first CP3020 RF execution used one continuous qcore/phone epoch, qcore N3
on `lo`, the local srsENB/M2 primer, the CP3013 Soapy RX timestamp repair, and
the preserved OCUDU/M2 target. All optional post-target phone actions remained
off. CP3019 remains the unchanged srsENB/M2 bidirectional-HTTP golden.

The primer stage passed. The phone acquired its private test address, the
srsENB/M2 primer counted two RACH procedures with zero stream errors, and qcore
reported one user-plane activation. The primer then stopped cleanly. The target
activation watcher and exact HTTP server were armed before OCUDU started.

OCUDU started with the expected CP3013 Soapy source and module hashes
`644e7858...` and `81b8cb2e...`. Its post-stop 6.7 MB binary-safe snapshot was
reduced with the helper's compact parser: PRACH, RAR, PUSCH, CRC-OK, and RRC
Setup counts are all zero. Soapy TX timeout, downlink-late, underflow, and time
error counts are also all zero. The target watcher timed out after 240 seconds,
so no second qcore activation occurred and the HTTP probe correctly did not run.

The target was nevertheless visible to the phone. In the target-phase monitor
window, 37 rows identified PCI 500. Fourteen were the strong class at about
`-81 dBm / -11 dB RSRQ / +21 dB SINR`; the other 23 were floor or degraded
rows and out of service. The phone retained the primer's private address, but
that stale interface did not correspond to a fresh target registration. This
is a valid OCUDU access-supply datapoint and void for RAR, registration, and
user-data conclusions. The CP3013 RX timestamp fix is live, but remains
unexercised because the phone sent no Msg1.

Cleanup found an independent state-restoration defect: the direct RadioInfo
full-mode path failed three times and left one mode key at the temporary
NR-only value. The existing installed-app entry path then restored the full
mask and both mode readbacks to 33 with RC0. The phone is in the established
idle full-RAT state; [host-redacted] is idle and M2 program mode is N.

Do not repeat CP3021 unchanged. Before another RF roll, make the phone restore
helper fall back from the direct RadioInfo entry to the proven installed-app
entry and gate that no-RF. Then compare the actual over-air access semantics of
the phone-working srsENB/M2 primer and OCUDU/M2 target, concentrating on the
decoded MIB/SIB1 and RACH-related fields rather than power or RX timing. The
existing post-start service, reselection, and airplane branches have already
failed to produce OCUDU Msg1 in CP2903, CP2906, CP2915, and CP2922 and must not
be repeated as bare controls.
