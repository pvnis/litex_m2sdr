# CP3032: System-update modal phone-prepare gate

Date: [date-redacted]

CP3031's zero-spinner failure was not a keyguard, modem, or RF regression. A
system-update prompt was covering the installed RadioInfo launcher. The exact
safe defer action was selected once and a fresh UI dump proved that the prompt
was absent. The temporary screenshot and XML were then removed because the
underlying engineering screen contains device and subscriber identifiers.

The new `cp3032_dismiss_system_update_modal_remote.sh` helper is deliberately
narrow: it wakes the phone, opens only the known RadioInfo launcher, parses the
UI XML structurally, and taps only one clickable node whose text exactly matches
the safe defer action. It never selects either restart action, emits no UI
contents, cleans up its XML, and fails closed on duplicates or invalid bounds.
Its SHA-256 is
`7818a04688ad806ecb0e62f2d896009acf0308126d284e7a6867d5f947b02e28`.

The helper is hash-pinned in both phone entry paths. The CP2629 prepare helper
now runs it before checking or changing phone policy; its deployed SHA-256 is
`4b7e0c0a30568742fde751f6c5b7446a5570c89223251d98b4baf2ba913b8386`.
The CP3030 post-target reboot helper runs it after Android finishes booting and
before restoring voice policy or N3 mode; its deployed SHA-256 is
`cf10332e914133b8eb10588973856b59acf91efc98f5a639400e32a70e80cc17`.
Pre-change copies are preserved locally and on [host-redacted].

All no-RF gates pass: local and remote syntax, local/remote hash equality,
default probe, live absent-prompt behavior, the normal CP2629 prepare/N3-apply/
restore round trip, and the CP2893 approval-off RC2/zero-artifact gate. The
phone finishes automatic with the full RAT mask, roaming off, voice policy
restored, and no stale private address. Both hosts are idle and M2SDR program
mode is N. One intermediate standalone restore used an inactive subscription
context and was rejected; the same gate with the wrapper's active context
passes and no RF was used.

CP3032 closes the orchestration blocker without changing any RF, gNB, core,
stage-1, timing, threshold, or protocol setting. Retry the exact CP3031
post-target full-reboot experiment with a fresh stamp.
