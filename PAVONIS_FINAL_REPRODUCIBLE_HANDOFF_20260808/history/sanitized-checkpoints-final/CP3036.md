## Attempts

### CP3036: pre-RF configuration void

The first start stopped before opening Soapy/M2SDR because the preserved
40-slot RA response window requires the historical validation gate. The log
contains only the configuration rejection. Adding
`PAVONIS_ALLOW_EXTENDED_RA_RESP_WINDOW=1` exactly restores the CP2392 setting;
the corrected config then passes the golden binary's no-RF `--dryrun` gate.

### CP3036A: bounded golden control

The golden gNB passed configuration and N2 readiness and transmitted for the
bounded acquisition run. The preserved srsUE initialized at the expected
11.52 Msps/9.22 MHz/1842505998 Hz and entered attach. Unlike CP3035, it reached
the PCI-1 `set_cell` path, establishing a positive cell/PBCH-MIB acquisition
contrast against the current target.

The run cannot judge SIB1 or attach. Once the cell path activated, bladeRF
reported 85 overrun status events totaling 82,633 overruns, with individual
reports as high as 999. No SIB1 completion, PRACH, or RACH followed. This is a
new receive-health regression in the preserved srsUE control, not evidence
against the golden air waveform.

The golden gNB remained clean: zero Soapy deadline-write timeout,
downlink-late, underflow, time-error, and RACH-indication events. The completed
UE result was retrieved no-RF after the wait helper returned nonzero despite
writing its READY marker. Both final host gates pass, bladeRF remains present,
and M2SDR is in program mode N.

## Verdict

CP3036 is positive through the cell/PBCH-MIB acquisition path and void above
that path. The same bladeRF, srsUE binary, current kernel, and current Soapy
module progress farther with the golden gNB/config than with the current target.
That strengthens the current-target PBCH/SIB1 delivery regression established
by CP3033-CP3035. The severe post-acquisition overrun storm means srsUE is no
longer a trustworthy SIB1/attach calibration instrument until separately
repaired.
