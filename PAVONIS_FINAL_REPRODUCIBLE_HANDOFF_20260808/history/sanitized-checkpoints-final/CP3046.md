## No-RF comparison

CP3045 proved that nominal PRACH windows covering the first two phone access
epochs are floor-class. Before capturing more spectrum, this checkpoint compares
the exact successful CP3019 srsENB/M2SDR phone baseline with the current
OCUDU/M2SDR launch shape.

The advertised PRACH geometry matches:

- Band 3, 52 PRBs, 15 kHz SCS;
- PRACH configuration index 0, one FDM, frequency start 1;
- zero-correlation zone 0, root sequence 1, unrestricted set;
- eight preambles, target power -110 dBm, ramp 4 dB, transmission max n7;
- response window 10 slots;
- successful CP3019 RACH events all occur at absolute slot modulo 160 equal to
  11; CP3045 collects `SFN mod 16 = 1, slot = 1`, the same lattice.

An OCUDU-ASN.1 decode of the current phone-captured SIB1 additionally confirms
UL Point A 348564, Band 3, BWP start 0/length 52 and the fields above. The
80-byte SIB1 input is referenced only by SHA-256
`83a76eddd61ee3bed8a89cb376dc424594616a1a385056f8d623f936eff68054`.

## Decisive difference

The successful CP3019 helper launches srsENB with
`PAVONIS_SRSRAN_SOAPY_PHYSICAL_CHANNEL=1` and requires the runtime marker
`RX setupStream: Selected channel 1`. Its eight RACH records prove that this
physical pair receives the phone.

CP3045's generated `run_harness.sh` instead exports an empty
`PAVONIS_SOAPY_PHYSICAL_CHANNEL_OFFSET`. OCUDU maps an empty/default offset to
physical TX0 and RX0. The offset-1 path already exists and maps both streams to
physical channel 1. The established CP2690 port audit records channel 0 as the
cabled pair and channel 1 as the phone-antenna pair.

This explains the otherwise contradictory evidence. Channel-0 downlink leakage
is strong enough at short range for the phone to decode repeated MIB/SIB1, while
the phone's wireless uplink does not enter cabled RX0, leaving every target-era
PRACH input near -87 dB RMS. CP3019 works because it explicitly uses channel 1
for both directions.
