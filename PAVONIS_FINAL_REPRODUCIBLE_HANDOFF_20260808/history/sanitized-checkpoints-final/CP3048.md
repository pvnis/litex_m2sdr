# CP3048: channel 1 restores UL energy, but the current stage-1 list rejects

Date: [date-redacted] Europe/Zurich

## Run validity

The fresh `[date-redacted]TCP3048_PHONE_CHANNEL1_LADDER` run completed with base RC 0.
The generated harness exports physical channel 1, and the live gNB proves the
mapping mechanically:

- physical offset active at 1 for one logical TX and RX channel;
- TX stream mapped to physical channel 1 at `11.52 Msps` and the expected DL
  frequency;
- RX stream mapped to physical channel 1 at `11.52 Msps`, the expected UL
  frequency, and 40 dB gain.

The target remained on the CP3025 gNB `dbc7cb79...`, phase mode off, early raw
capture disabled, and the frozen protocol/timing/gain shape. GNB transport was
clean: zero Soapy TX timeouts, downlink-late events, underflows, or time errors.
The wrapper stopped OCUDU and qcore, restored the phone, and returned the local
selector to its idle state.

## Phone observation

QCSuper captured 78 well-formed NR-RRC records. The primer phase passed with
MIB, SIB1, UL/DL-CCCH, and bidirectional DCCH. The target phase contained 23
MIB, 23 SIB1, and five UL-CCCH records at target-relative offsets about
`0.000`, `11.137`, `22.197`, `33.256`, and `44.316` seconds. It contained no
target DL-CCCH or DCCH. The phone therefore continued to decode the target
broadcast and initiate the access procedure, but no gNB response reached it.

## Uplink result

The final append-only stage-1 trace segment is segment 25:

- 963 PRACH opportunities;
- 953 energy gates;
- 7624 detector evaluations, exactly eight for each energetic window;
- zero selected preambles;
- maximum raw RMS `-54.136 dB` and peak `-48.149 dB`;
- maximum search time `6940 us`.

The ordinary gNB PHY log independently contains 961 PRACH rows, all with empty
detected-preamble lists; its maximum reported RSSI is `-47.2 dB`. It contains
zero RAR, PUSCH, or RRC-setup events. Around the five QCSuper access epochs,
the nearest five-opportunity neighborhoods reach RMS maxima of `-63.183`,
`-67.303`, `-67.276`, `-63.217`, and `-66.764 dB`, respectively, but the
current eight-entry search still selects nothing.

This is a large and causal change from CP3043 on physical channel 0, which had
only 84 energy gates in 959 opportunities. CP3046's dropped-channel diagnosis
is confirmed: channel 1 is the phone-facing receive path. It does not by itself
complete Msg1, because the restored samples do not fit the current bounded
stage-1 candidate list.

## Verdict and next rung

CP3048 is a valid access-supply datapoint and a failure at live Msg1. The
physical-channel branch is closed as fixed; do not return to channel 0 or [interface-redacted]
RF gain from the old floor-class runs. The next bounded run should combine the
already-gated channel-1 mapping with CP3044's first-128 predemod capture. It is
detector-void by construction and should be used only to retain the first two
phone access epochs, then replay those exact channel-1 windows through a broad
offline timing/fractional-phase/CFO search. Live stage-1 entries should change
only after that replay names a recovering transform.

Consolidation remains blocked.
