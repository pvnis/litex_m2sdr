# CP3053 - Channel-1 post-target reboot and data no-RF gate

CP3053 gates the first full phone reboot under the corrected phone-facing
physical channel 1. This is not a repeat of CP3033: that run occurred before
CP3046 discovered that the OCUDU target had silently fallen back to cabled
channel 0.

## Composition

The new wrapper `cp3053_run_channel1_posttarget_reboot_data.sh` has SHA-256
`70c3731f31cacf3cf5e7d2a2d342c9da294a903a532e186d333325fcabd48c8c`.
It pins the unchanged CP2893 handoff wrapper at
`547d9d5abe0c5348b834a20b46b80af8b8ae36014993deda138f5af88d259c8d`
and the proven reboot-under-target helper at
`cf10332e914133b8eb10588973856b59acf91efc98f5a639400e32a70e80cc17`.

The RF/protocol shape is the frozen CP3048 target: physical channel 1,
collection phase off, early capture off, CP3025 gNB `dbc7cb79...`, Soapy source
`644e7858...`, and module `81b8cb2e...`. After the local M2 primer stops and
OCUDU starts, the existing CP3030 helper performs a full phone reboot, restores
voice policy, reapplies the private N3 selection, and verifies no stale private
address. The target activation watcher and private HTTP echo are prearmed. A
successful run therefore continues through both established data directions
rather than stopping at Msg1.

## Verdict

CP3054 is RF-gated. Msg1 is the first validity boundary. If it flows, the same
run must continue through RAR, Msg3, qcore activation, private interface, and
bidirectional HTTP. No collection timing, detector threshold, RF gain,
attenuation, SIB1, scheduler, or Soapy behavior changes in this checkpoint.
