# CP3056 - ATT16 label did not change live attenuation

CP3056 executes the isolated CP3055 path with stamp
`[date-redacted]CP3056_CHANNEL1_ATT16_REBOOT_DATA`. Primer, target startup,
phone reboot, cleanup, and both final host gates pass. The phone still emits no
Msg1. The intended attenuation discriminator is void, however: the helper's
`TX_ATT=16` changed only generated names and telemetry, not the live radio
configuration.

## Execution result

The target startup marker proves the intended frozen shape and claims channel
1 / ATT16 / phase off / early capture zero. The phone fully reboots after the
target starts, reapplies the N3 and voice policy, and has no stale private
address. The target activation watcher times out.

After reboot and policy restoration, the phone monitor has 40 rows. Twenty-six
identify the target cell. Thirteen valid samples are all `-62 dBm` RSRP,
`-11 dB` RSRQ, and `+29 dB` SINR. There are zero in-service or private-interface
rows and 38 `NOT_REG_SEARCHING` rows. This is effectively the same strong-cell,
no-access state as CP3054.

The gNB snapshot has zero PRACH, RAR, PUSCH, uplink CRC-OK, and RRC setup
events. Transport health is clean: zero Soapy TX timeouts, downlink-late events,
underflows, and time errors. Cleanup leaves [host-redacted] idle in DMA program mode `N`
and [host-redacted] idle with the phone authorized over ADB.

## Attenuation provenance failure

The CP3054 and CP3056 generated gNB YAML files are byte-identical despite their
`txatt0` and `txatt16` filenames. Both contain `tx_gain: 0`, and CP3056's live
Soapy readback also reports logical TX gain `0.0 dB`. The phone therefore
remaining at the same `-62 dBm` level is expected; CP3056 did not test 16 dB
attenuation.

The source audit gives the mechanical cause. In the frozen CP2730 starter,
`TX_ATT` is used for output/config filenames and summary fields, while config
generation explicitly rewrites `tx_gain` to zero. The starter never exports
`PAVONIS_SOAPY_TX_FORCE_ATT_DB`. The current CP3025 gNB binary does contain
that default-off hook, established earlier for named LiteX `ATT` gain and
post-`setupStream()` reassertion.

CP3055's no-RF probe was therefore insufficient: it proved the helper constant,
not its propagation into the generated config or runtime. Future RF gain gates
must require the live post-setup readback, not a filename or launch marker.

## Verdict and next step

CP3056 is a valid second post-reboot ATT0/no-Msg1 observation and is void for
ATT16. It neither rejects nor confirms the overdrive theory. Create another
isolated helper/handoff pair that passes
`PAVONIS_SOAPY_TX_FORCE_ATT_DB=16` to the unchanged gNB, and gate it no-RF on
the binary string plus exact env propagation. The RF run is valid only if the
startup sidecar reports post-setup TX gain `16.0 dB`; otherwise stop before
phone interpretation. Preserve CP2892/CP2893 and CP3055 artifacts unchanged.
