# CP3057 - FORCE_ATT16 live-readback no-RF gate

CP3057 corrects the propagation failure found in CP3056 while preserving every
earlier helper and handoff. The new isolated helper exports the already-proven
OCUDU `PAVONIS_SOAPY_TX_FORCE_ATT_DB=16` bridge, verifies that exact variable
in the live gNB process environment, and refuses its start-pass marker unless
the post-setup Soapy sidecar reports named TX gain `16.0 dB`.

The helper has a new append-only run root. It retains `TX_ATT=16` for naming,
adds the real force-attenuation environment, checks `/proc/$GNB_PID/environ`,
and validates the sidecar's `gain_ok` plus `gain_db` within `16 +/- 0.01 dB`.
Only after those checks does it emit
`CP3057_OCUDU_M2SDR_FORCE_ATT16_START=PASS` with an explicit
`tx_attenuation_readback_db=16` field. The handoff requires that field before
the phone reboot can begin.

## Verdict

CP3058 is RF-gated. If live attenuation does not read back `16.0 dB`, the
helper must fail before phone interpretation and the run is configuration-
void. If it does, compare the post-reboot phone level and Msg1 against CP3054/
CP3056; if access returns, continue automatically through RAR, Msg3,
registration, private interface, and bidirectional HTTP. No other RF,
protocol, timing, detector, scheduler, binary, or Soapy variable changes.
