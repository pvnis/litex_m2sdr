# CP3058 - FORCE_ATT dropped at detached-runner gate

CP3058 executes the CP3057 path with stamp
`[date-redacted]CP3058_CHANNEL1_FORCE_ATT16_REBOOT_DATA`. The local M2 primer
passes, and OCUDU reaches gNB readiness briefly. The new runtime gate then
rejects startup before the phone reboot because post-setup TX attenuation is
still `0.0 dB`, not `16.0 dB`. This is a clean configuration-void checkpoint,
not a phone or Msg1 datapoint.

## Gate result

- Both host preflights, primer qcore registration, and primer service pass.
- The target creates `TX_READY.env` and a complete Soapy TX readback.
- The readback row has rate/frequency/gain/bandwidth status all valid, but
  `gain_db=0.000000000`.
- The target gNB log contains zero force-attenuation hook lines.
- The helper withholds its start-pass marker, so the handoff never reaches the
  post-target phone reboot or any phone interpretation.
- Cleanup stops qcore/gNB/primer state, restores the phone, leaves [host-redacted] in DMA
  program mode `N`, and leaves [host-redacted] idle with authorized ADB.
- The brief target interval has zero Soapy TX timeouts and zero downlink-late
  events.

The guard behavior is correct: CP3058 cannot be mistaken for an ATT16 run.

## Environment-boundary cause

The CP2730 starter does not launch the stage directly. It generates a detached
runner script with an explicit list of exported variables. That allowlist
contains the continuous/all-timed/timing and other Pavonis controls but omits
`PAVONIS_SOAPY_TX_FORCE_ATT_DB`. Therefore setting the variable in the parent
helper does not place it in the eventual gNB process environment. The CP2892
stage itself launches gNB with `setsid` and would preserve an environment set
inside that stage.

The smallest isolated correction is consequently a new copy of the 129-line
CP2892 gNB-only stage with one default-specific export:
`PAVONIS_SOAPY_TX_FORCE_ATT_DB=16`. Point a new helper at that stage and retain
the CP3057 process-env plus post-setup readback gates. Do not modify the shared
CP2730 starter, CP2892 stage, CP2892/CP2893 baseline, or any previous CP305x
artifact.

## Verdict

CP3058 is configuration-void and spends no phone attempt. Gate the isolated
stage no-RF, including syntax, stage hash, exact one-line functional diff,
generated-sequence proof, closed-gate behavior, and both hosts. The following
RF run remains valid only after its start marker proves live attenuation
readback `16 dB`.
