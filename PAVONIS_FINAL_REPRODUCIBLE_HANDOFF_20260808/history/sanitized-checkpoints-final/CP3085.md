# Checkpoint 3085: USIM DF5GS absent; retained state is device-side

Date: [date-redacted]

## Question

CP3083/CP3084 repeatedly enter the private core's unknown-update fallback but
never reactivate the private user plane, even after a phone reboot. This
checkpoint asks, without RF or any SIM write, whether the retained 5GS identity
and location state is stored in the USIM `EF5GS3GPPLOCI` file.

## Read-only audit

Small root `app_process` readers were built as isolated DEX jars. They emit only
APDU status, byte count, hashes and semantic flags; no subscriber identity, USIM
application identifier or file payload is printed.

1. Android `iccExchangeSimIO` returned `6F00` for the full standard path and
   all bounded path-convention variants.
2. Reflection proved the phone exposes the current request-object logical
   channel and APDU APIs. A logical-channel open using the internally obtained
   active USIM application identifier returned status `3` with no channel.
3. The decisive basic-channel control selected the active USIM application
   successfully (`9000`, 60 response bytes), proving the application/routing
   inputs are valid. Selecting `DF5GS` (`5FC0`) then returned `6A82` with both
   FCP and legacy response modes.
4. The helper reselected the original USIM application in `finally`; restore
   returned `9000` and passed. No UPDATE BINARY or other write APDU exists in
   any audit helper.

ETSI TS 31.102 states that `DF5GS` must be present at the ADF USIM level when
5GS mobility-management service 122 is available, and that
`EF5GS3GPPLOCI` (`4F01`) is present under that DF. The clean `6A82` therefore
means this USIM has no writable 5GS location file for the stale context.

Primary reference:
`https://www.etsi.org/deliver/etsi_ts/131100_131199/131102/17.05.00_60/ts_131102v170500p.pdf`

Key source hashes:

- direct SIM-I/O reader: `c3ec5792...`
- bounded path reader: `c791b0e8...`
- logical-channel reader: `b0dedd3c...`
- basic-channel control: `6689af08...`

Final host checks pass: both RF stacks are idle, ADB remains authorized, the
M2SDR device is present, and DMA reader program mode is `N`.

## Verdict

USIM-STORAGE THEORY CLOSED. The stale 5GS update/session context is retained in
the phone/modem software state, not `EF5GS3GPPLOCI`. Do not attempt a SIM-file
clear. Next, audit the established fresh-phone helper against available
device-side subscription/SIM-power reset mechanisms, then gate one reversible
state reset with pre/post readback before retrying the frozen CP3082 target.
