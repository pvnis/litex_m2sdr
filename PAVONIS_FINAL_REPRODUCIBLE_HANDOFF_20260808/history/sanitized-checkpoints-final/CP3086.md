# Checkpoint 3086: reversible SIM-power cycle passes no-RF gate

Date: [date-redacted]

## Scope

CP3085 proves the retained 5GS update/session state is device/modem-side. This
checkpoint gates one reversible SIM power cycle without RF or a state change.

The Android shell convenience command exists but is intentionally disabled on
the phone's rooted user build. A read-only binder method audit instead proves
that the live telephony service exposes:

- `getSimStateForSlotIndex(int)`;
- `setSimPowerStateForSlot(int, int)`;
- the callback variant and modem-level recovery methods, which remain unused.

## Gate

`PavonisSimPowerCycle` and its remote wrapper implement two modes:

- `audit` is the default path and cannot carry the approval flag;
- `cycle` requires both `PAVONIS_CP3086_SIM_POWER_CYCLE_APPROVED=1` and a
  literal in-process approval token.

The active slot is derived internally from the current subscription database
row; neither value is printed. The cycle path issues power-down, requires an
observed transition away from READY/LOADED within 60 seconds, and always issues
power-up from `finally`. It then requires READY/LOADED within 120 seconds and
independently verifies the subscription database remains enabled.

The first audit-only build exposed an unavailable hidden static slot mapper and
made no state call. The corrected build removes that dependency. It reports
initial state `10` (`LOADED`) and `changed=0`. A closed-path probe invokes cycle
without approval, requires nonzero exit, proves no run root was created, and
reruns audit successfully.

## Verdict

NO-RF GATE PASS. Execute one approved cycle under a fresh stamp. Require both
transition markers, final subscription-enabled/ADB readback, then restore and
verify the established phone network policy before spending the next primer RF
run. Do not invoke modem reboot/reset methods.
