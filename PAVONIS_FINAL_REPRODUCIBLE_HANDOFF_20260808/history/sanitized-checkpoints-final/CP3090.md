## Decoder and ordering verdict

The trace produces 75 PUSCH result rows, all CRC KO. At each of the first three
real target slots:

- all 14 shifted-path grid symbols are written;
- one upper-PUSCH task starts only after symbol 13 is written;
- allocation-end write precedes task start by `80.230`, `65.836`, and
  `11.865 us`;
- exactly one full-slot, 11-byte, RV0 PUSCH result returns CRC KO.

The corresponding scheduled-RB lifts are `7.81`, `11.70`, and `15.36 dB`.
Upper-PHY SINR is `-16.17`, `-31.79`, and `-32.06 dB`; EVM is `11.94`,
`89.62`, and `91.40`. The target tap and PUxCH handoff therefore agree. The
signal is already absent or misplaced in the shifted input; it is not lost by
early decode or post-tap truncation.

## Dynamic-offset coverage gap

The three real RAR/Msg3 allocations arise from PRACH report slots 651, 971,
and 1291 and schedule Msg3 at 687, 1007, and 1327. No dynamic non-PRACH offset
is published before them, so they use the stale startup offset `-241118`.
The first dynamic publish occurs only at PRACH report slot 1451.

CP3088's first accepted edge instead published `-237174` before its real
targets. The difference is exactly `3944` samples, about 4.8 OFDM symbols.
CP3088 then captured scheduled energy through symbols 0--5; CP3090 captures
only the final approximately one-symbol tail. This cross-run displacement is
the predicted consequence of the offset difference.

Source audit explains the coverage gap. The edge-derived dynamic publisher is
called only inside `if (pavonis_stage1_selected)`, before the normal upper-PHY
PRACH detector runs. A normal/baseline detector acceptance can therefore reach
RAR scheduling without publishing the edge offset needed by its Msg3. CP3090's
first three RARs exercise exactly that uncovered path.

## Verdict and next action

VALID DISCRIMINATOR. PUxCH ordering and target-tap correctness are closed. The
next fix must make the accepted-event edge offset coherent for every
RAR-producing PRACH result, including normal/baseline acceptance, while
preserving the current immediate stage-1-selected path and default-off
behavior. A safe design is to stage bounded per-occasion edge metadata in the
lower path, commit it only after the upper detector returns a non-empty result,
and consume/clear it when the existing stage-1 path already publishes.

Do not [interface-redacted] the static startup offset. After that no-RF gate, rerun the frozen
shape and require one publish before every real RAR/Msg3 allocation. The
separate six-symbol-versus-full-slot waveform question remains open and is the
next semantic rung once Msg3 placement is coherent.
