# Checkpoint 3091: accepted-PRACH edge bridge passes the no-RF gate

Date: [date-redacted]

## Scope

CP3090 proved that a normal upper-PHY PRACH acceptance can schedule RAR/Msg3
before the stage-1-only edge publisher updates the non-PRACH receive offset.
This checkpoint implements only that missing accepted-event bridge. It does
not change PRACH thresholds, detector search policy, static offsets, TA,
grants, scheduler behavior, Soapy, or gateware, and it transmits no RF.

The new path is default-off behind
`PAVONIS_NON_PRACH_UL_RX_OFFSET_COMMIT_ON_UPPER_ACCEPT`. When enabled, the
lower worker measures and stages bounded edge metadata only after the existing
stage-1 energy gate passes. The upper processor consumes that metadata after
the real PRACH detector returns. A non-empty result publishes the dynamic
offset using the strongest accepted preamble's adjusted TA; an empty result
only clears the staged entry. The existing immediate stage-1-selected path
keeps its semantics and discards its staged entry after publication, preventing
a duplicate upper publication.

## No-RF proof

consumption:

- disabled: staging, acceptance, publication, and snapshot validity are all
  zero;
- enabled: a wrong slot cannot consume the entry;
- the matching slot publishes generation 1 at offset `-233332` in the
  synthetic control;
- a second consume of the same slot is invalid.
