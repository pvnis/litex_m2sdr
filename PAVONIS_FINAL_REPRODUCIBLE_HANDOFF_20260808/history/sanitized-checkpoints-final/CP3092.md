## Ring alias finding

The first three accepted upper publications use exactly the edge staged for
that occasion. Starting with the fourth, the published edge differs from the
last logged staged edge for the same nominal `system_slot`; publication is
delayed behind 19--38 still-visible staged events, after which the stage trace
cap hides further producer activity. Examples include staged/published
`-2766/+4594`, `+4518/-1226`, and `-882/-3682` samples.

This is a software association failure. CP3091 stores one entry in a 64-element
ring indexed by wrapped `system_slot % 64`; the key itself is the wrapped NR
system slot. The upper PRACH detector is asynchronous and can complete after a
later producer cycle has reused that key. Exact metadata identity is therefore
not guaranteed even though the nominal slot matches. [interface-redacted] the edge
calibration cannot fix metadata from the wrong capture.

The fetched `/tmp` stage-1 TSV also contains 40 appended header segments from
multiple runs and is not used as a current-run aggregate. The current gNB
mirror and exact target package are authoritative for this verdict.

## Verdict and next action

VALID DISCRIMINATOR. The accepted-event bridge closes normal-detector coverage,
but its global ring transport is rejected. Replace it no-RF with edge metadata
carried in the exact `prach_buffer_context` delivered with each PRACH buffer.
The upper detector must consume that context-local copy after detection;
immediate stage-1 publication clears only its own context copy. Remove the
ring/mutex side channel entirely, keep the feature default-off, and repeat the
same build/deploy/disabled-path gates before RF.

Do not change calibration, static offsets, TA, thresholds, grants, power, RAR
window, or full-append state. The next RF success criterion is exact
staged-to-published edge equality for every target plus residual timing within
the CP, followed by gNB Msg3 CRC OK.
