# Checkpoint 3093: context-carried PRACH edge passes the no-RF gate

Date: [date-redacted]

## Scope and design

CP3092 rejected the global ring because wrapped-slot lookup could return edge
metadata from a later producer cycle after asynchronous upper-PHY delay.
CP3093 removes that array and mutex entirely. When the existing stage-1 energy
gate passes and the default-off upper-accept flag is enabled, the lower worker
stores the measured edge and sample rate in the exact
`prach_buffer_context` sent with that PRACH buffer. The upper detector reads
only that copied context after detection. Immediate stage-1 publication clears
only the copy associated with that same buffer.

No RF parameter or protocol behavior changes. Calibration, static offsets, TA
quantization, PRACH thresholds/search, grants, RAR window, power, Soapy, and
gateware are untouched. The feature remains controlled by
`PAVONIS_NON_PRACH_UL_RX_OFFSET_COMMIT_ON_UPPER_ACCEPT`, default off.

## Callback-capacity gate

The first direct context implementation correctly failed the full build: its
56-byte diagnostic metadata made `process_prach` exceed the 64-byte
allocation-forbidden callback capacity. The fix did not relax that invariant
or permit heap allocation. Only two functional values cross the boundary:
signed edge samples and sample rate, exactly 8 bytes. Producer diagnostics stay
at the producer.

A focused two-translation-unit test proves:

- default context metadata is invalid (`sampling_rate_Hz=0`);
- copying the context preserves edge `-2766` and `11.52 Msps` after the source
  is mutated;
- metadata size is 8 bytes;
- `prach_buffer_context` size is 48 bytes;
- the real callback capture shape is exactly 64 bytes;
- the commit flag is false when unset and true only when explicitly enabled.

The complete local `gnb` build then passes under OCUDU's `-Werror`.
