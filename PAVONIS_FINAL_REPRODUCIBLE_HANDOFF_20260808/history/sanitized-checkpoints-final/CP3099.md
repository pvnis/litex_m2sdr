## Msg3 result

Phone diagnostics contain 17 RACH-attempt rows in six groups. Fifteen rows
have message mask 7 and one has mask 15; both classes include the Msg3 bit.
The phone-side procedure therefore did not disappear.

Nevertheless, all eight scheduled target captures are floor:

```text
scheduled lift: 0.80 .. 1.29 dB
raw RMS:       -68.49 .. -75.48 dBFS
active symbols: 0 / 14 for every target
PUSCH:          0 / 75 CRC OK
```

This is qualitatively different from CP3096, where seven targets carried
14.06..23.54 dB lift and 3..11 active symbols. The canonical branch did not
produce a full Msg3 slot; it moved the physical burst outside the scheduled
logical slot.

## Alias correction

CP3097 selected edge `4800` from the correct phase class but did not preserve
the absolute slot branch. The same lattice has another boundary-14
representative:

```text
-6722 = -138 - 8*823
offset = -237332 - (-6722) = -230610
offset mod 11520 = 11310
```

Edges `4800` and `-6722` differ by `11522 = 14*823`, which is one
`11520`-sample slot plus the two-sample accumulated lattice rounding error.
For every non-floor CP3096 target, moving from its observed snapped edge toward
`-6722` adds only the missing 3..11 symbols and does not cross the slot wrap.
Moving toward `4800` crosses that wrap. The CP3099 all-floor result is the
live discriminator between those aliases.

## Verdict

VALID REJECTION. The canonical-control mechanism works, but edge `4800` is the
wrong absolute representative. CP3099 closes it and revises the candidate to
congruent in-slot edge `-6722`, offset `-230610`. No source rebuild is needed;
the CP3098 validation already permits any congruent canonical value.
