# CP3105: Msg3-to-Msg4 path trace passes no-RF gate

Date: [date-redacted]  
RF transmitted: no

## Source audit

The CRC-OK PUSCH path has no unconditional stale-result filter. PHY always
emits CRC and nonempty RX-data indications; FAPI copies nonempty transport
blocks into MAC; MAC parses unknown-RNTI PUSCH as Msg3 and dispatches
CCCH-size LCIDs; DU then creates the UE, forwards the initial UL RRC message,
and generates RRC Setup. The nominal Msg3 slot is retained for contention
resolution and can cause an explicit scheduler expiry, but no source evidence
showed that this happened in CP3104B.

## Instrument

A new default-off `PAVONIS_MSG3_PATH_TRACE` records metadata at:

```text
PHY CRC OK -> FAPI RX-data -> MAC enqueue/unpack -> CCCH dispatch
DU queue/create procedure -> Initial UL RRC -> RRC Setup parse/pack
F1/SRB0 downlink -> contention resolution -> fallback PDSCH allocation/expiry
```

Rows contain stage, monotonic timestamp, slot, payload length, FNV-64 payload
tag, LCID, HARQ ID, and outcome. They contain no payload bytes, subscriber
identity, or persistent UE identity. Environment controls are read once,
events are only emitted for CRC-OK/nonempty or later control-path work, and
`PAVONIS_MSG3_PATH_TRACE_LIMIT` caps the trace at `1024` rows in the diagnostic
wrapper.

Header SHA-256:

```text
feb45a2f93ee1eb3af96540f35b554d6e6b4b76d708de4de55619ca4ce9ec442
```
