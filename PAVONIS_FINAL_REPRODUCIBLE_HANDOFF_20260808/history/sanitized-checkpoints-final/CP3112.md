## Msg3 To Msg4 Result

The gNB produced 256 PUSCH results, including 26 CRC-OK 11-byte Msg3-class
results. Every one of those 26 procedures traversed PHY, FAPI, MAC CCCH, DU UE
creation, RRC Setup, F1, and SRB0. All 26 scheduler-local rebase operations
derived `+20` slots from `-230610` samples. Nevertheless:

- `fallback_conres:pending`: 26;
- `fallback_pdsch:new_tx_allocated`: 0;
- `fallback_pdsch:conres_expired`: 26.

The adjusted origin still expired exactly 65 slots later. Expiry occurred
58.424 to 59.432 ms after the PHY result. The first complete procedure used
nominal slot 2287, adjusted slot 2307, and expiry slot 2372; the last used
6287, 6307, and 6372. The scheduler-repository placement therefore moves the
timer as designed but does not make Msg4 schedulable. The CP3106-CP3112 timer
rebase branch is closed.

## Root Cause

The actual generated run config has SearchSpace1 candidates
`[0, 0, 1, 0, 0]`: one aggregation-level-4 candidate and zero
aggregation-level-8 candidates. The same gNB process reports
`PAVONIS_GNB_FALLBACK_DL_DCI_AGGR_LEV active value=8 level=n8`.

Source and starter provenance explain the contradiction:

- `ue_fallback_scheduler` requests the configured
  `fallback_dl_dci_aggr_lev` in the RA search space;
- the frozen outer wrapper requests candidates `[0, 0, 1, 1, 0]` and fallback
  aggregation level 8;
- the SIB1-compat branch in `stage6_cp2730_start_nuc4.sh` subsequently and
  unconditionally rewrites SearchSpace1 candidates to `[0, 0, 1, 0, 0]`.

The fallback scheduler is therefore asked to allocate an AL8 Msg4 PDCCH where
the active search space exposes no AL8 candidate. Allocation is impossible;
contention-resolution expiry is the terminal symptom.

## Next Gate

Use an isolated wrapper around the same CP3109 real binary that:

1. leaves the failed scheduler-rebase feature disabled;
2. overrides only `PAVONIS_GNB_FALLBACK_DL_DCI_AGGR_LEV=4`;
3. preserves every established UL and diagnostic setting.

Prove no-RF that the runtime reports `level=n4`, the actual SearchSpace1 remains
AL4-capable, and the rebase marker is absent. Then repeat the combined phone
recovery and one frozen ladder run. The decisive marker is
`fallback_pdsch:new_tx_allocated`, followed by phone RRC progression.
