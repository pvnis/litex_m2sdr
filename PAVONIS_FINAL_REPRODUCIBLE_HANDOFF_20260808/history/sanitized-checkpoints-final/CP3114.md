# Checkpoint 3114: phone OCUDU M2SDR attach and bidirectional data

Date: [date-redacted]

## Run Classification

CP3114A stopped locally before RF because the lower runner required the
authorized ADB endpoint explicitly. CP3114B passed preflight but is a
primer-supply void: the srsENB primer did not form private service, so OCUDU
never started and the AL4 change was not judged.

After another full phone fresh epoch, SIM cycle, and policy audit, unchanged
CP3114C is valid. The primer passed with one RACH and one qcore user-plane
activation. The sequence then stopped srsENB, started OCUDU on the M2SDR, and
observed a new target-era user-plane activation before running data probes.

Valid stamp:
`[date-redacted]CP3114C_FALLBACK_AL4_TARGET`.

## Access Result

The isolated CP3113 wrapper and unchanged real CP3109 gNB were used. Runtime
proof is exact:

- fallback aggregation-level-4 marker: 1;
- fallback aggregation-level-8 marker: 0;
- scheduler contention-slot rebase markers: 0.

The gNB processed 203 traced PUSCH results, 186 with CRC OK. One CRC-OK
11-byte Msg3-class result traversed PHY, FAPI, MAC CCCH, DU UE creation, RRC
Setup, F1, and SRB0. The decisive result changed from CP3112's zero allocation:

- `fallback_pdsch:new_tx_allocated`: 10;
- `fallback_pdsch:conres_expired`: 0.

The AL8-with-zero-candidates mismatch was therefore the Msg4 blocker. Matching
fallback AL4 to the starter-generated AL4 SearchSpace1 restores contention
resolution and allows the phone to progress.

## User Data Milestone

The target-activation watcher was armed only after the successful primer
activation and srsENB shutdown. It passed on a new qcore user-plane activation
under OCUDU; the activation count increased from one in the primer epoch to two
in the target epoch.

Two independent private-data checks then passed while OCUDU was live:

- the phone sent four successful private-network echo probes to the core;
- the phone made an HTTP request through its private interface to the core
  server, and the server received the request and returned the expected
  response; both endpoint gates report pass and phone RX/TX counters increased.

The final data gate is `1`. The older simultaneous core-to-phone echo helper
still reports its known SSH/pipe transport false negative, so that legacy
sub-gate is `0`; it does not invalidate the separate end-to-end HTTP
request/response, which proves user bytes in both directions.

This is the requested milestone: the real Android phone accesses the private
core through OCUDU on the LiteX M2SDR and exchanges bidirectional user data.

## Health And Teardown

The complete valid run has zero Soapy TX timeout, downlink-late, underflow, and
time-error events. Both hosts are idle after teardown, the phone remains
authorized for ADB, and the M2SDR returned to program mode `N`.

## Preserved Baselines

The established CP2392 and CP2674 baselines were not modified. CP3114 uses an
isolated wrapper around the pinned gNB and does not edit the starter or
generated baseline in place.
