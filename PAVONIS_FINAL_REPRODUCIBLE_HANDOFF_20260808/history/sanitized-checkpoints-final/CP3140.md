Date: [date-redacted]

## Verdict

Tier 2 is honestly closed as a partial result.

OCUDU alone brought the phone through RF access, repeated Msg3/RRC setup, and
into qcore registration handling. It did not establish the private PDU session,
so target user-plane activation and bidirectional data did not occur.

This was a valid semantic failure, not a void. The unchanged-retry allowance
does not apply because the run progressed far beyond the clean zero-RACH
scatter class.

## Radio and RRC result

The gNB trace proves that the apparent top-level timeout was not a radio-access
failure:

- 122 PUSCH result rows;
- 111 CRC OK and 11 CRC KO, for 90.98% CRC yield;
- eight CRC-OK 11-byte uplink rows;
- six complete DU/CU RRC setup-request paths;
- six DU UE-create procedures completed;
- six initial UL RRC notifications reached the CU;
- 26 downlink SRB0 forwards and 80 new fallback PDSCH allocations;
- clean AL8 marker;
- zero Soapy TX timeouts and zero downlink-late events.

The original helper's legacy compact counters undercounted these events because
their old text patterns do not match the current metadata traces. The
metadata-only `PAVONIS_PUSCH_CSI_TRACE` and `PAVONIS_MSG3_PATH_TRACE`
aggregations are the authoritative CP3140 radio evidence.

## Core/session blocker

qcore reached registration handling once. It then logged:

- six requests to reactivate sessions absent from the fresh core context;
- five requests for the unsupported IMS DNN;
- zero target user-plane activations.

The phone never obtained the private data address. The activation watcher
therefore timed out, and the echo/HTTP gates correctly did not claim success.

This is consistent with the already documented handset limitation: retained
5GS/session state can outlive a restarted private core even after the normal
reboot/SIM-cycle ritual. The proven srsENB primer creates a compatible session
state before the OCUDU handoff; without it, this phone requested stale session
reactivation and IMS rather than establishing the expected private data
session.

Per the Tier 2 scope, this device-side retained-state behavior is documented,
not chased with new phone-state manipulation or protocol changes.
