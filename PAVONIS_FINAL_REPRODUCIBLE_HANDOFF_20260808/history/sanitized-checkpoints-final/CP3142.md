## qcore NAS recovery

`nas_request()` now implements the 3GPP T3560/T3570 recovery shape:

- encode the request once, preserving NAS COUNT and the protected bytes;
- use a six-second T3560 or T3570 timer according to the procedure;
- retransmit the identical encoded request on the first four expiries;
- abort the NAS procedure on the fifth expiry.

Identity uses T3570. Authentication and Security Mode use T3560.

The focused integration test deliberately discards the first Identity Request,
receives a byte-identical retransmission after T3570, responds to it, and then
completes registration. It passed on an isolated, secret-excluded [host-redacted] source
snapshot:

`1 passed; 0 failed`, runtime `6.15 s`.

The tested source archive SHA-256 was
`8c07b1ba87165bea6185dc96763525ee8c70b9dd202ded1341c76a60d36376c0`.

Two preliminary isolated builds used [host-redacted]'s unpinned current nightly for the
eBPF sub-build and failed with the known LLVM bitcode-reader/toolchain mismatch.
The final test reused CP3141's native wrapper, pinning the eBPF sub-build to
nightly [date-redacted], and passed. These preliminary failures did not execute the
test and are not semantic failures.

## OCUDU RRC and NGAP recovery

RRC now retains the exact generated `RRCReconfiguration`, including its
transaction identifier and dedicated NAS list. A separate response watchdog
waits 100 ms, retransmits that same RRC message once, and then fails the pending
NGAP transaction and releases the UE if no matching completion arrives. A
completion with the wrong transaction identifier is ignored. A matching
completion cancels the watchdog before applying the final configuration.

The 100 ms watchdog is an implementation recovery bound, not a 3GPP-defined
network timer. It leaves substantial margin over the ordinary UE processing
target while remaining short enough to recover the current phone failure.

PDU Session Resource Setup no longer reports success when RRC bearer setup is
merely queued. The NGAP procedure remains pending and emits its Setup Response
only after the matching `RRCReconfigurationComplete` outcome.

Focused validation:

- `rrc_nr_test`: PASS, zero warnings/errors. It observed one watchdog retry,

  matching transaction completion, and proved no later retry occurred.
- `ngap_test`: PASS, zero warnings/errors. A valid PDU-session request invoked

- `srsenb` production target: PASS.
