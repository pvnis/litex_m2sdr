# CP3150 - Phase C native uplink scheduling fix

## Verdict

**Deferred; not prioritized in this follow-up.**

No source change, build, deployment, or RF run was made. Phase A produced no
valid sustained benchmark and Phase B remained locked, so this follow-up has
no new throughput cohort against which a deep PUCCH fix could be judged.

## Evidence and scope

The existing evidence already bounds the shortcoming:

- CP3136's fixture audit, SHA-256
  `eb20660b1b9b06c9362d02df5a854d2c3adca5e555b8e10850482f6d4bca0390`,
  found only 293 of 1280 capped native PUCCH SR rows in the positive class;
- CP3137's uplink analysis, SHA-256
  `003e2e535cb172a3c64951f5bb6a5cfe7c83e39d7709620bf92db168d880b396`,
  placed the dominant bound in the tens-of-kilobytes-per-second radio uplink
  service envelope rather than TCP, MTU, or host transport.

The proper fix remains a no-RF-first PUCCH timing/power/demodulation repair,
followed by native SR/BSR scheduling tests and only then one bounded RF
validation that removes the synthetic-grant fixture. It must not be attempted
as an opportunistic change to the frozen POC.
