# CP3154 - Phone OTA Sustained Benchmark Partial

Date: [date-redacted]

## Verdict

`HONEST PARTIAL`. The dedicated benchmark produced a valid 45-second OTA
downlink result of **7.842 Mbit/s**, but the uplink duration gate exposed a
receiver-side tooling error. Phase B remains locked.

## Attempts

Attempt 1 is a controller void. Fresh epoch, SIM cycle, policy audit, and the
persistent-server arm passed, but the controller exited before the runner
boundary. Attempt 2 is a read-only preflight transport void: lifecycle and
helper proofs passed, then the remote preflight returned no marker. Neither
attempt started the target radio.

Attempt 3 is a valid radio execution. Primer service passed, target activation
completed in `21691 ms`, the final data gate passed, and RF health was clean:
zero Soapy TX timeouts and zero downlink-late events. The one-shot correctness
HTTP endpoint remained disabled.

## Throughput

The phone received `44,110,308` bytes in `44.9996 s`, or `980,237 B/s`
(`7.841896 Mbit/s`). This is `1.246x` the CP3133 one-shot DL median.

The uplink is not valid. The phone stopped its benchmark at approximately
45 seconds, but the core receiver continued draining queued socket data for
`183.0977 s` and eventually counted `15,663,104` bytes. The initially
generated pass verdict divided by that 183-second interval and is superseded
by `sustained_validity_audit.json`. No sustained uplink number is claimed.

The required fix is measurement-only: stop the receiving server at the
requested deadline, record bytes received at that point, and require its
duration to be within the 45-second gate.
