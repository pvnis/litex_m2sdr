# CP3155 - Server-Deadline Benchmark No-RF Gate

Date: [date-redacted]

## Verdict

`PASS`. The uplink benchmark now measures exactly the receiving interval rather
than draining client socket buffers after the requested deadline. No RF was
used.

## Fix

The phone supplies the requested duration in an HTTP header. The core receiver
reads only until that deadline, records bytes and elapsed time immediately,
then closes the request. Uplink throughput is derived only from core receive
bytes. The analyzer requires core uplink duration between 44 and 47 seconds
for a 45-second run.

Downlink remains phone-receive authoritative. Phone-side upload counters and
curl status are retained as transport diagnostics, not used as the uplink
throughput numerator or timer.

## No-RF Evidence

- The deadline integration test forces a partial request and proves the server
  stops at its configured deadline.
- CP3154's 183.1-second upload is rejected with verdict `invalid`.
- A synthetic 45-second core receive control passes.
- Shell/Python syntax and the closed RF gate pass.
- Remote helper hashes, idle state, SDR state, authorized-phone presence, and
  CPU performance state pass.
- The CP3154 RF runner remains unchanged.
