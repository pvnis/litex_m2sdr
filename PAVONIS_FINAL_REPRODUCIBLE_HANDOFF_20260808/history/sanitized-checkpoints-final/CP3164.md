# CHECKPOINT 3164 - Native PUCCH conducted partial

## Verdict

Honest partial. The CP3163 native-candidate branch clears the prior
scheduling-request wall, creates the private data session, and completes both
traffic directions. Uplink has a valid sustained result. Downlink is rejected
because the receiver drains queued data for `6.46 s` after the requested
window, so the two-direction conducted baseline is not complete.

## Radio result

The otherwise-frozen 10 MHz, one-layer, TX-ATT5, max-MCS9 shape selects the
cell at `9.670 dB` SNR. Two Msg1 transmissions produce a RAR and Msg3. The
private interface becomes available and both benchmark endpoints complete.
There are zero Soapy TX timeouts and zero downlink-late events.

PUSCH records `98/128` CRC-OK rows (`76.56%`), median CRC-OK SINR
`21.864 dB`, and median TBS `544 bytes`. This proves the conducted data path
and high-SNR premise. The CP3160 post-RRC scheduling-request blocker no longer
prevents user data in this run.

## Traffic result

| Direction | Authoritative receiver | Bytes | Seconds | Rate | Verdict |

| Downlink | UE | 19,904,008 | 51.460801 | 3.094240 Mbit/s | rejected |
| Uplink | Core | 1,256,864 | 45.000126 | 0.223442 Mbit/s | valid |

The downlink sender stops after `45.079 s`, but the receiver continues until
EOF and counts `51.461 s`. Its loop checks the deadline only after a socket
timeout, so continuously arriving queued bytes bypass the deadline. The
reported `3.094240 Mbit/s` downlink value is retained only as an unaccepted
diagnostic and must not be used as the conducted baseline.

## Decision

Add a receiver-enforced downlink deadline using the same receive-shutdown
pattern that closed the phone benchmark's queued-drain error. Gate it locally
with a sender that intentionally outlives the requested window. Then rerun
this exact RF shape. Do not change PRACH, PUCCH, MCS, bandwidth, power, timing,
scheduler, kernel, FPGA, or gateware while closing the measurement defect.
