# CHECKPOINT 3166 - Stale-process preflight void

## Verdict

Void before RF. No throughput or radio conclusion.

## Failure

The gNB start step times out before stream setup. Its compact log reports that
the private user-plane UDP endpoint is already in use, so the gNB cannot
allocate user-plane resources. No UE process starts, there is no TX readback,
and there are no Soapy summary rows.

Read-only socket/process attribution identifies the owner as the isolated
CP3164 gNB process. The established stop helper did not match it because the
isolated executable basename did not begin with `gnb`. The exact owner was
verified, terminated, and the private user-plane port was confirmed free.

The isolated benchmark controller also has a secondary defect: after the valid
upstream-void summary was packaged, its parser assumed the UE-log path was a
string and raised `TypeError` on null. The execution summary still records the
failed stage, but the parser must be null-safe.

## Decision

Before the single-void retry:

1. Launch the isolated binary through a target whose basename is `gnb`, so the
   established stop helper owns it.
2. Add a fail-fast private-user-plane port-free preflight.
3. Make radio-summary parsing tolerate missing UE/gNB logs and return an
   explicit upstream-void health record.

Gate all three no-RF, then rerun CP3165 unchanged.
