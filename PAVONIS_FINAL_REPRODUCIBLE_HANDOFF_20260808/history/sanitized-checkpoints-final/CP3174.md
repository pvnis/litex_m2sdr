# Checkpoint 3174: stale core process preflight void

## Verdict

CP3174 is void before RF. The frozen phone benchmark correctly refused to
start because one `qcore` process from the controller-interrupted CP3172 run
was still alive on the core role.

This corrects the interpretation recorded at CP3173. The 35-byte preflight
artifact was only the transport prompt preceding a remote `set -e` exit.
Authoritative helper SSH passed immediately, while a labeled replay of the
preflight showed that only the zero-process assertion failed. SDR presence,
DMA mode, remote artifact hashes, and CPU-governor assertions all passed.

The orphan was stopped through its owning lifecycle helper. Both RF roles then
passed explicit zero-process gates. No base service, primer, gNB, endpoint
result, traffic measurement, or RF conclusion belongs to CP3174.
