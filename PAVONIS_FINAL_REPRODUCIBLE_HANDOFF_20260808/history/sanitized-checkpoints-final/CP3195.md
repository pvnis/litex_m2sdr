# Checkpoint 3195: zero-follow-up phone attach and data

Date: [date-redacted]

RF executed: yes, two bounded primer starts; only the second attempt reached
the target OCUDU/data stages.

## Verdict

Pass. The proven 10 MHz phone chain reaches target activation and passes
bidirectional user-data with the primer's legacy 512 synthetic follow-up UL
grant budget disabled.

The valid run proves all three zero-budget conditions independently:

- launcher readback: `followup_ul_grants=0`;
- primer status: zero follow-up arms and zero injection log rows;
- archived primer log: zero active-branch markers and zero injection markers.

The same log contains 16 native valid/positive SRs. All 16 are followed by a
same-RNTI PUSCH within 12 slots, all at a median `+8` slots, and all 16
responses pass CRC. Native-SR median SNR is `12.951 dB`. The unchanged
post-setup-ACK one-shot grant remains present once; this checkpoint retires
only the 512 follow-up branch.

The target OCUDU phase passes activation, bidirectional echo, the 1 MiB HTTP
transfer in both endpoint views, context invariants, and the final data gate.
The OCUDU status records zero Soapy TX timeouts and zero downlink-late rows.

No explicit decoded BSR CE row is emitted by this primer build, so this report
does not claim a separately observed BSR payload. It does prove the behavior
that mattered: native SR drives scheduled, CRC-valid PUSCH without fabricated
requests, and the full target user-data transaction completes.

## Attempts

Attempt 1 is a setup void. The zero-budget primer started correctly, but the
phone-preparation helper exited before target OCUDU launch. It carries no
SR/BSR or target-data verdict.

Before attempt 2, fresh-phone epoch, SIM cycle, policy audit, and overall reset
all passed. The first local classifier called this reset a failure only because
the helper transcript used carriage-return line endings; a bounded
line-normalizing check proved all four markers present. No RF was spent by
that false classification.

Attempt 2 is valid and passes. It uses the exact CP3194 candidate and frozen
CP3121 target shape, with a fresh identifier.

## Decision

Remove the 512 synthetic follow-up grant branch from the required POC flag
inventory. Preserve CSI removal, the bounded post-setup-ACK one-shot grant,
and the reactive-downlink controls as separate known fixtures; this checkpoint
does not evaluate or retire them.

The next comparison is the already-proven 15 MHz reference. It must remain an
isolated check: do not change RF, MCS, gain, power, kernel, FPGA, or gateware.
The question is whether the zero-follow-up conclusion carries into the wider
bandwidth evidence, not whether 15 MHz should be retuned.
