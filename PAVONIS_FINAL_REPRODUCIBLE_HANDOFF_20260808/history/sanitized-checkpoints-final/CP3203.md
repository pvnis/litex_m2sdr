# Checkpoint 3203: min-k2 OTA Msg3 void

## Verdict

VOID for throughput and for the dedicated `min_k2=1` hypothesis. The UE
acquires the 10 MHz cell, decodes SIB1 and six RARs, then all six Msg3
procedures fail at gNB PUSCH CRC. No RRC/user-data session or traffic result
exists.

This is a pre-service Msg3 scatter run. Msg3 uses the unchanged common
`msg3_delay=6`, before the dedicated `cell_cfg.pusch.min_k2` policy can be
judged. One unchanged retry is required by the standing single-void rule.

## Controlled shape

Every CP3176 control remains frozen: 10 MHz, 52 PRB, 11.52 Msps, one layer,
MCS9, FDD, TX attenuation 5 dB, gNB RX gain 40 dB, 45-second traffic windows
and default 512-byte SR fallback. The only candidate change is generated YAML
`min_k2: 1`.

Runtime proves the candidate reached the process:

- activation marker: `1`;
- `k2=1` log rows: `25`;
- transformed config present in the packaged [host-redacted]-role run.

## Decision

Retry the identical `min_k2=1` shape once with a fresh stamp. Do not alter
gain, timing compensation, stage-1, grant size, MCS or traffic tooling. If the
retry reaches sustained data, use it for the response-delay comparison. If it
repeats a pre-service failure, close `k2=1` as operationally unreliable on
this stack without claiming a throughput result.
