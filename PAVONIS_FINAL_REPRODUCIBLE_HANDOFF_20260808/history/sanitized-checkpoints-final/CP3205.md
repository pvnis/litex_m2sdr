# Checkpoint 3205: min-k2=3 ZMQ failure

## Verdict

FAIL at the no-RF gate. Two exact ZMQ attempts reach RRC connection but fail
the PDU session with the same UL CRC distribution. No RF run is justified.

This rejects `min_k2=3` for the current stack and closes `min_k2` as the
response-delay throughput lever. Baseline `min_k2=4` remains the active
runtime whenever the isolated launchers are not selected.

## Candidate proof

The `k2=3` launcher is normalized-identical to the gated `k2=1` launcher
except for the value and checkpoint names. It pins the same proven binary,
preserves the default 512-byte SR fallback and native PUCCH candidate, and
copies the YAML before adding only:

```yaml
  pusch:
    min_k2: 3
```

Local syntax and normalized comparisons pass. The deployed config-only gate
proves exactly two added lines and the expected activation marker.

## ZMQ results

| Metric | Attempt 1 | Attempt 2 |
|---|---:|---:|
| highest milestone | RRC connected | RRC connected |
| first failure | PDU session | PDU session |
| activation markers | 1 | 1 |
| `k2=3` rows | 246 | 246 |
| other `k2` rows | 0 | 0 |
| UL newTx rows | 884 | 885 |
| CRC OK | 3 | 3 |
| CRC KO | 247 | 247 |

The exact 3/247 CRC split across both attempts is deterministic enough to
reject a transient core-state explanation. For comparison, the passing CP3202
`k2=1` ZMQ control had 51 CRC-OK and 77 CRC-KO rows and completed the PDU
session plus ping. The non-monotonic result points to a slot-lattice/timing
interaction in this prototype, not a generic rule that shorter `k2` is better.
That mechanism is outside this throughput-policy phase.

Both attempts clean up to zero gNB, qcore and occupied private user-plane
port counts.

## Decision

Do not run `min_k2=3` over RF and do not retry `min_k2=1`. Retire the
response-delay branch and restore baseline `min_k2=4` by launcher selection.
The next separate cadence variable is the standards-aligned PUCCH scheduling
request period advertised to the UE. Audit its current value from source and
runtime, then lower one supported step through config, ZMQ and bounded OTA.
