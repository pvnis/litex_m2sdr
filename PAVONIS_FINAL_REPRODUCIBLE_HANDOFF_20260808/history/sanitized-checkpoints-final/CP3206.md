# Checkpoint 3206: SR-period 10 ms no-RF gate

## Verdict

PASS. The standards-aligned scheduling-request cadence control is isolated and
passes the 10 MHz ZMQ chain through attach, PDU session and private gateway
ping. One bounded OTA sensitivity run is unlocked.

No RF was opened.

## Source finding

OCUDU's scheduler already evaluates eligible UL new transmissions every slot.
The UE receives fresh-demand opportunities through its dedicated PUCCH
SchedulingRequest resource. The DU-high default is
`cell_cfg.pucch.sr_period_ms=20`, and the translator writes that period into
the UE-dedicated SR configuration.

For 15 kHz SCS, 10 ms is a supported next-lower period. This changes when the
UE can report new demand after its cached BSR has been consumed; it does not
change grant size, PDCCH-to-PUSCH `k2`, HARQ policy, RF geometry or the
retired primer branch.

## Isolated candidate

The proven launcher and binary remain untouched. The side-by-side launcher
pins the same baseline and copies generated YAML before adding only:

```yaml
  pucch:
    sr_period_ms: 10
```

The local syntax gate, remote hash gate and exact-two-line config comparison
pass. Runtime emits one hash-only activation marker. `min_k2` remains its
baseline value 4 and the SR fallback remains 512 bytes.
