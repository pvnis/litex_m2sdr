# Checkpoint 3208: sustained-uplink deadline-race no-RF gate

## Verdict

PASS. The CP3207 client/server deadline race is reproduced by source
inspection and removed in an isolated benchmark-server variant. Local
loopback, analyzer, syntax, compile, and validate-only gates all pass.

No RF or scheduler setting changed.

## Root cause

Both endpoints used the same exact uplink deadline. The server shut down its
receive side at 45 seconds while the client could still be inside its final
bounded `send()`. CP3207 landed in that race: the server durably completed the
receiver-authoritative UL result, while the client received a connection reset
before writing its sender-side crosscheck.

## Isolated fix

The new server retains the requested traffic duration and receiver-authority,
but its safety shutdown waits an additional bounded two seconds for the client
to finish and half-close. Normal completion still occurs immediately on EOF.

The controller accepts `PAVONIS_SUSTAINED_SERVER_PATH`; when unset it continues
to deploy the original CP3159 server. The CP3207 wrapper explicitly selects
the CP3208 server. This is a benchmark-tool change only.

## No-RF proofs

A two-second localhost run passed:

- client/server/analyzer return codes: `0/0/0`;
- core and UE results: `complete=true`;
- final receiver ACK: `received`;
- uplink receiver duration: `1.999964 s`;
- analyzer duration gate and verdict: `PASS`.

Python compilation, wrapper shell syntax, controller validate-only, and the
zero-artifact validate-only check also pass.
