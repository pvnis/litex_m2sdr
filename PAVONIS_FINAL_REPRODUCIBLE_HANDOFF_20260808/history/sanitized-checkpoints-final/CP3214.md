# Checkpoint 3214: ZMQ throughput discriminator

## Verdict

Pass. The unchanged 10 MHz FDD OCUDU/srsUE stack sustains normal
bidirectional traffic when the SDR/RF path is removed. The low M2SDR OTA
uplink is not a fixed scheduler, core, or srsUE throughput ceiling.

The operator's remembered USB-LiteX result is external precedent. It is not a
Pavonis checkpoint, its exact device/configuration is unavailable, and it is
not used as a numeric baseline.

## Evidence

- The first attempt is an honest setup void: qcore exited before NG setup, no
  benchmark traffic ran, and cleanup completed.
- The unchanged retry passes core start, NG setup, ZMQ RF open, random access,
  RRC, private session establishment, assigned test interface, and the bounded
  reachability gate.
- Receiver-authoritative 45-second throughput is `7.508669 Mbit/s` downlink
  and `33.379038 Mbit/s` uplink.
- CP3176 M2SDR OTA is `2.983260/0.167066 Mbit/s`, making this ZMQ control
  `2.517x` faster downlink and `199.795x` faster uplink.
- The bounded ZMQ gNB window contains `49,729/49,729` PUSCH CRC OK rows. Its
  modal modulation is 64QAM, median UL TBS is `4612 B`, median allocation is
  `51 PRB`, and the median positive new-transmission gap is one slot.
- A same-parser reanalysis of CP3176 contains `5,145/9,361` PUSCH CRC OK
  (`54.96%`), median UL TBS `512 B`, and only `5,388` UL new transmissions
  over `238.10 s`.
- CP3176 runtime provenance exposes inherited connected-uplink state:
  run-derived offset `-234086` samples and active `-4000 Hz` correction.
  CP3104 had already recovered live PUSCH CRC with canonical offset `-230610`
  and that correction disabled. This fix was not carried into the throughput
  wrapper.
