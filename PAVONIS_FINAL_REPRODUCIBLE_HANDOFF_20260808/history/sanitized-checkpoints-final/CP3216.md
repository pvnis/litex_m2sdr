# Checkpoint 3216 - Canonical candidate negative; connected-UL TIME_PAST root

## Verdict

**VALID NEGATIVE WITH A NEW CONNECTED-UPLINK ROOT CAUSE.**

Two byte-identical bounded OTA runs applied the phone-branch canonical
non-PRACH receive candidate (`-230610` samples, CFO correction disabled).
Both acquired a healthy cell and reached the first scheduled PUSCH, but both
ended with exactly `0/30` PUSCH CRC OK and never established a user-data
session. The result is repeatable and rules out transferring that receive
candidate directly to the srsUE branch.

The follow-up no-RF join identifies a different blocker in the established
srsUE baseline: the bladeRF PRACH-only timing fixture is selected by waveform
amplitude, so it also classifies connected PUSCH as PRACH. It forces
start/end-of-burst semantics and applies the negative PRACH transmit offset
after the coherent lead guard. That reduces final transmit lead and produces
`TIME_PAST` writes on real PUSCH opportunities.

The recollection that a USB LiteX SDR once achieved normal bidirectional
throughput is external context, not a Pavonis measurement, and is not used as
a numeric baseline here.

## Evidence

### Canonical candidate

| Run | Cell SNR | PUSCH CRC | TBS | Session |
|---|---:|---:|---:|---|
| A | 13.878 dB | 0/30 | 11 B | no |
| B | 14.173 dB | 0/30 | 11 B | no |

Both runs propagated the intended canonical lattice and converged on the
`-230610`-sample non-PRACH receive class with no active non-PRACH CFO
correction. Both gNB transmit health counters remained clean. The bounded UE
timeout and controller nonzero result are expected consequences of failing to
establish a session, not infrastructure voids.

### The old OTA baseline is two-state, not uniformly weak

The CP3176 bounded PUSCH trace contains `66/128` CRC-OK rows and `62/128`
CRC-KO rows. The two classes have nearly identical median timing estimates
(`0.448 us` versus `0.435 us`), but the KO class falls about `24.4 dB` in
median EPRE (`-77.67 dB` versus `-53.30 dB`) and its median SINR collapses
from `14.52 dB` to `-20.09 dB`.

All `128/128` bounded gNB PUSCH result slots match a PUSCH encode slot in the
UE log. The floor class is therefore not a missing grant or a grant that the UE
failed to encode; it is lost between the encoded UE waveform and the gNB
detector input.

### bladeRF write failure joins the floor class

Historical CP2318 already established an exact join: all exact floor PUSCH
rows mapped to bladeRF status `-14` (`TIME_PAST`), while all exact strong rows
mapped to status `0`. The CP3176 transmit-debug summary now quantifies the
timing envelope over `263` high-energy writes:

- status `-14`: `68`;
- status `0`: `195`;
- `TIME_PAST` remains common below `26000` final lead samples;
- `1/23` writes fail in the `26000..27999` bin;
- `0/14` writes fail in the `28000..29999` bin.

Every failing high-energy row passed through both the coherent guard and the
PRACH time-offset path. Source audit confirms the negative PRACH offset is
applied after the guard. This explains why raising receiver-side timing
constants did not repair the connected uplink and why the ZMQ discriminator
can sustain high uplink throughput while the OTA branch cannot.

## Decision

Do not keep the phone-derived canonical receive candidate for srsUE. Restore
the last working dynamic receive-offset/CFO shape.

The next bounded mechanism test should add enough coherent UE transmit lead to
keep high-energy writes above the measured clean class while moving the gNB
PRACH timing compensation by the same sample delta. This preserves the
relative Msg1 collection geometry and changes only bladeRF transmit lead. If
`TIME_PAST` and floor PUSCH rows disappear, replace the amplitude-based PRACH
classification with an explicit PRACH control path; the larger guard remains
a diagnostic accommodation, not the final fix.
