# Checkpoint 3220 - TIME_PAST removed; PRACH classifier still corrupts PUSCH

## Verdict

**VALID NEGATIVE FOR THE PURE TRANSMIT-LEAD THEORY.**

The corrected equal-delta control propagated end to end:

- UE bladeRF guard: `56000` samples;
- requested gNB PRACH compensation: `253336` samples;
- runtime PRACH collection/timing compensation: `253336` samples.

Random access recovered, but Msg3 did not:

- six nonempty gNB PRACH detections;
- six gNB RAR allocations;
- six UE RAR accepts;
- eighteen UE PUSCH encodes;
- `0/30` gNB PUSCH CRC OK.

The extra lead eliminated bladeRF `TIME_PAST`, so late submission was a real
loss mode but is not the complete connected-uplink defect.

## Evidence

### bladeRF transmit path

The bounded UE trace contains `25` high-energy writes. All `25/25` return
status `0`; none return `TIME_PAST`. Final lead is
`34474..45753` samples with median `40613`.

All 25 rows also show both `tx_guard_applied=1` and
`prach_time_offset_applied=1`. Seven are Msg1; the remaining eighteen align
with UE PUSCH encodes. The amplitude classifier therefore still sends every
connected PUSCH through the PRACH-only path.

### gNB detector input

All 30 Msg3 decode rows are CRC KO at 11-byte TBS. Their median:

- EPRE: `-67.965 dB`;
- SINR: `-21.134 dB`;
- EVM: `11.449`;
- timing estimate: `-0.660 us`.

This is a floor-class receive window, not a marginal decoder result. gNB
transmit health remains clean at zero timeout and zero downlink-late events.

The dynamic non-PRACH offset also changed from CP3176's single `-234086`
publication to a CP3220 cluster around `-236.8k`. [interface-redacted] that offset again is
not the preferred next step: the source audit already shows PUSCH is being
modified by a PRACH-only waveform classifier before transmission.

## Root Cause Boundary

`PAVONIS_RF_BLADE_PRACH_BURST_ONLY=1` currently uses waveform peak amplitude
as the PRACH predicate. For every high-energy write, including PUSCH, it:

1. forces bladeRF start-of-burst and end-of-burst flags;
2. applies the coherent transmit guard;
3. applies the `-16000`-sample PRACH timestamp offset;
4. can trigger the first-high-peak TX-stream restart and PRACH frequency
   correction.

The NR subframe worker already knows whether a buffer is PRACH (`prach_ptr !=
nullptr`), so amplitude is unnecessary as the protocol discriminator.

## Decision

Implement a minimal default-off explicit PRACH context:

- the NR subframe worker marks only the synchronous PRACH `worker_end()` call;
- the bladeRF module uses that marker for PRACH-only burst, guard, timestamp,
  restart, and frequency-rotation behavior;
- connected PUSCH follows the ordinary radio path;
- when the new flag is disabled, legacy amplitude behavior remains
  byte-for-byte unchanged.

No receive-offset, scheduler, threshold, power, kernel, FPGA, or gateware
change is justified before this source-level split is built and no-RF gated.
