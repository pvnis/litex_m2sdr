# Checkpoint 3221 - non-PRACH receive co-shift gate

## Verdict

**PASS.** One bounded co-shift run is unlocked.

CP3220 moved every high-energy UE transmission `16000` samples later. It
coherently moved the gNB PRACH collection window, recovering Msg1/RAR, but the
dynamic non-PRACH receive offset did not move by the same amount. CP3220
published roughly `-236.8k` samples versus CP3176's `-234086`.

OCUDU processes the non-PRACH branch using:

```text
shifted_timestamp = hardware_timestamp + dynamic_offset
```

A waveform arriving `16000` samples later must therefore use an offset
`16000` samples more negative. The existing edge formula is:

```text
offset = edge_calibration - edge - scheduler_error + RAR_TA
```

The candidate sets only:

```text
PAVONIS_NON_PRACH_UL_RX_OFFSET_EDGE_SCHEDULER_ERROR_SAMPLES=16000
```

This predicts a CP3220-derived cluster of `-252904..-252760`, compared with
the CP3176 reference shifted by the measured transmit delta: `-250086`.
Run-scale edge/TA variation explains the remaining few thousand samples.

## Why This Precedes The Source Split

CP3176 decoded `5145` PUSCH blocks with the same amplitude-selected burst
semantics whenever timing landed correctly. CP3220 proves `TIME_PAST` is gone
but also changes the PUSCH air timeline by `+16000`. Therefore the immediate
all-floor result does not yet prove that forced SOB/EOB itself corrupts PUSCH.
A matching receive co-shift is the smaller causal test.

If it restores Msg3/PUSCH, the explicit PRACH-context source split remains
valuable cleanup but is no longer the first correctness blocker. If it does
not, proceed with that default-off split without further offset [interface-redacted].
