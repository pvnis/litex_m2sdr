# Checkpoint 3224 - Extra TX lead is a valid negative

## Verdict

**VALID NEGATIVE FOR MORE STATIC LEAD. FORMAL THROUGHPUT PARTIAL.**

Runtime propagation passed:

- UE TX guard: `72000`;
- gNB PRACH compensation: `269336`;
- non-PRACH scheduler error: `32000`.

The cell and gNB remained healthy (`16.067 dB` cell SNR, zero Soapy timeout,
zero downlink-late). The gNB observed `80/128` PUSCH CRC OK (`62.5%`), nearly
identical to CP3222's `81/128`.

The sustained bladeRF result regressed:

| Metric | CP3222 | CP3224 |
|---|---:|---:|
| High-energy writes | `264` | `264` |
| `TIME_PAST` | `38` (`14.39%`) | `66` (`25.00%`) |
| Median final lead | `46605.5` | `55330.5` |
| PUSCH CRC yield | `63.28%` | `62.50%` |

More static lead did not suppress late returns. It increased their count even
while the reported pre-submit lead rose.

## Throughput Classification

The core-side result completed both 45-second receive windows. The UE-side
result persisted downlink but not its uplink section, so the generic analyzer
correctly failed rather than fabricating a formal pass.

The available receiver-authority measurements are:

- downlink: `3.078901 Mbit/s`;
- uplink: `0.041960 Mbit/s`.

The uplink figure is a measured partial, not a formal benchmark. It is still
decisive for the lead hypothesis because lateness rose, PUSCH CRC did not
improve, and receiver-side UL fell from CP3222's `0.134631 Mbit/s`.

## Source Interpretation

The bladeRF coherent guard is initialized once as a fixed timestamp bias.
Later submissions reuse that bias even when host scheduling delay grows. In
CP3224, high-energy rows have median `669.5` and p90 `5027` samples of
coherent-guard lateness. A larger initial bias therefore does not guarantee a
larger margin at `bladerf_sync_tx()`.

Every connected PUSCH remains amplitude-classified as PRACH and receives the
PRACH-only forced burst and timestamp behavior. CP3222 proved that path can
decode when timing lands, but CP3224 proves static lead cannot make it robust
under sustained load.

## Decision

Reject CP3224's timing values and restore the CP3222 baseline:

- guard `56000`;
- PRACH compensation `253336`;
- non-PRACH scheduler error `16000`.

The next change is the previously gated source-level split: pass explicit
PRACH context from the NR worker to the bladeRF send path and apply forced
SOB/EOB, PRACH timestamp offset, first-burst restart, and PRACH frequency
rotation only to true PRACH. It must be default-off and preserve the exact
legacy amplitude path when disabled.
