# Checkpoint 3225 - Explicit PRACH context no-RF gate

## Verdict

**PASS. ONE CP3222-SHAPE OTA CONTROL IS UNLOCKED.**

The source now carries the protocol fact already known by the NR worker into
the synchronous RF send:

1. the single `prach_ptr != nullptr` branch calls `worker_end(..., true)`;
2. ordinary connected UL keeps the default false context;
3. the common PHY sets a thread-local RF context only when the new feature is
   enabled;
4. the bladeRF plugin applies PRACH-only behavior only when that context is
   true.

The feature is default-off behind
`PAVONIS_RF_BLADE_PRACH_EXPLICIT_CONTEXT`. With the flag absent or zero, the
legacy amplitude-classified path remains selected.

## Scoped Behavior

When explicit context is enabled, only true PRACH can receive:

- forced SOB/EOB from `PAVONIS_RF_BLADE_PRACH_BURST_ONLY`;
- the PRACH timestamp offset;
- PRACH frequency rotation;
- first-high-peak TX stream restart;
- the coherent guard that is entered through forced SOB.

Connected PUSCH uses the ordinary timed radio call. The added telemetry is one
metadata-only line per already-selected bounded TX debug row; it performs no
new sample scan.

## No-RF Proofs

- all local and deployed source hashes match;
- source verifier, Python compile, and shell syntax pass;
- controller validate-only keeps CP3222 timing (`56000/253336`, delta
  `16000`);
- closed RF gate exits `2` without a result directory;
- binary strings prove the environment gate and bounded context marker;
- RF core exports both thread-local context functions;
- srsUE `--help` output is byte-identical with the flag off and on;
- the host-linked unit test loads the rebuilt bladeRF plugin, reports it
  active, verifies main-thread and child-thread context isolation, and exits
  zero.

A standalone `ldd -r` on the plugin reports the RF-core getter unresolved.
That is expected when inspecting this `dlopen` plugin without its host. The
actual host-linked loader test resolves the symbol and is the relevant runtime
proof.
