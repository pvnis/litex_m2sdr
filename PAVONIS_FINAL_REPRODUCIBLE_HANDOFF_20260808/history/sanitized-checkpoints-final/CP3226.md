# Checkpoint 3226 - Explicit PRACH context OTA partial

## Verdict

**HONEST PARTIAL. EXPLICIT CONTEXT PROPAGATED; THROUGHPUT IS VOID.**

The CP3225 feature propagated correctly into the live bladeRF plugin. The run
then failed at Msg1 supply because six of seven real PRACH writes returned
`TIME_PAST`. It did not reach RAR, Msg3, connected PUSCH, or either sustained
traffic direction. This checkpoint is therefore evidence for the context
handoff and the existing transmit-timing scatter, not a throughput datapoint.

One unchanged retry is warranted by the campaign's single-void rule.

## Frozen Shape

- UE TX guard: `56000` samples.
- gNB PRACH timing compensation: `253336` samples.
- Coherent non-PRACH shift: `16000` samples.
- Explicit PRACH context: enabled.
- RF, scheduler, stage-1 envelope, and 45-second traffic method: unchanged
  from CP3222.

Cell selection and SIB1 passed at `13.991 dB` reported cell SNR and
`-4033.006 Hz` CFO. The gNB recorded zero Soapy TX timeouts and zero
downlink-late events.

## Context Proof

All `23` bounded context rows joined to their corresponding bladeRF TX debug
row:

| Context class | Rows | Forced SOB/EOB | Guard | PRACH offset | Result |
|---|---:|---:|---:|---:|---|
| non-PRACH selected false | 16 | 0 | 0 | 0 | 16 OK |
| PRACH selected true | 7 | 7 | 7 | 7 | 1 OK, 6 `TIME_PAST` |

The non-PRACH rows were startup writes. Because the run did not attach, live
connected-PUSCH behavior remains unmeasured even though the source and no-RF
gate prove the intended branch.

## Failure Classification

The UE emitted seven Msg1 attempts. The gNB recorded `1929` empty detector
rows, zero nonempty detections, and no RAR allocation.

The seven PRACH writes had final lead `40000..42373` samples, median `41350`.
Only the first write succeeded; the next six returned bladeRF status `-14`.
This is the same marginal timing boundary already visible in the connected
baseline, not a context-selection miss.

For comparison, CP3222's first two high-energy writes both succeeded at
`40000` samples and the second initialized the coherent bias. CP3226's second
write had the same nominal lead but was late. The difference is run-time
scatter at the RF submission boundary.

## Decision

Keep the CP3225 implementation deployed and default-off. Run one unchanged
CP3222-shape retry with explicit context enabled. Require all of the following
before interpreting throughput:

1. real PRACH is selected and accepted;
2. RAR and Msg3 complete;
3. connected PUSCH rows show context false and no PRACH-only transformations;
4. both sustained traffic directions complete.

Do not increase the static lead again: CP3224 already showed that a larger
constant did not robustly remove `TIME_PAST`.
