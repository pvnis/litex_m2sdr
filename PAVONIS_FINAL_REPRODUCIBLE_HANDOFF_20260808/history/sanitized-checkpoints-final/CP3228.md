# Checkpoint 3228 - True-PRACH restart-each no-RF gate

## Verdict

**PASS. ONE BOUNDED CP3229 OTA CONTROL IS UNLOCKED.**

CP3226 and CP3227 each produced the same discriminator: the first real PRACH
write restarted the bladeRF TX module and succeeded, while all six later
PRACH writes did not restart and returned `TIME_PAST`. CP3228 ports that
observed successful mechanism into a minimal default-off control.

## Change

`PAVONIS_RF_BLADE_PRACH_RESTART_EACH=1` makes every true PRACH write use the
existing bladeRF TX disable/restart path. The option:

- is cached once when the bladeRF device opens;
- requires explicit PRACH context and a true PRACH row;
- cannot select ordinary PUSCH;
- preserves the existing first-high-peak restart behavior;
- adds only a bounded metadata field,
  `restart_tx_stream_each_prach`, to the existing TX debug row;
- is absent by default in both wrapper layers.

No gNB, scheduler, timing constant, RF level, or stage-1 policy changed.

## OTA Judgment

CP3229 keeps the exact CP3226/CP3227 RF and timing shape and adds only
restart-each. Interpretation requires:

1. every true PRACH row reports restart-each and avoids `TIME_PAST`;
2. the gNB accepts Msg1 and reaches RAR/Msg3;
3. connected-PUSCH rows are context false, do not restart, and receive no
   PRACH guard/offset/burst transformation;
4. both 45-second sustained directions complete;
5. PUSCH CRC yield and throughput are compared against CP3222.

If PRACH remains late despite per-occasion restart, stop this mechanism. Do
not stack a larger static lead.
