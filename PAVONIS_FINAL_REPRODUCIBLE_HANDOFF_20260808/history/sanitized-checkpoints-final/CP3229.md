# Checkpoint 3229 - PRACH restart-each continuation partial

## Verdict

**PARTIAL. RESTART REMOVES `TIME_PAST`, BUT ORDINARY TX CONTINUATION BREAKS.**

The CP3228 mechanism does exactly what its evidence predicted for PRACH:
both real Msg1 writes restart the bladeRF TX module and return status `OK` at
`40000` samples final lead. Neither returns `TIME_PAST`.

The run still does not reach a gNB Msg1 detection because a separate,
deterministic stream-state bug appears after the second restarted PRACH. The
PRACH write ends its burst; the next ordinary timed write has no SOB.
`bladerf_sync_tx` then blocks for its timeout and returns status `-1`,
`An unexpected error occurred`. This repeats and starves the UE runtime.

This is not a throughput datapoint.

## Frozen Shape

The run keeps CP3222 timing and CP3227 RF settings:

- guard `56000`;
- PRACH compensation `253336`;
- non-PRACH scheduler error `16000`;
- explicit PRACH context enabled;
- restart-each enabled as the only new runtime control.

Cell selection and SIB1 pass at `15.322 dB` and `-4064.068 Hz`. The gNB has
zero Soapy TX timeouts and zero downlink-late events.

## Evidence

The bounded context/TX join contains:

| Class | Rows | RF result | Transform state |
|---|---:|---|---|
| true PRACH | 2 | 2 OK, 0 `TIME_PAST` | restart, guard, offset all active |
| ordinary | 134 | 17 OK, 117 status `-1` | no restart, guard, or offset |

Both PRACH writes complete in about `0.064 ms`. The ordinary-error rows mostly
block for about `[date-redacted] ms`, matching the synchronous TX timeout. Only two Msg1
attempts occur before the run is consumed by those stalls. The gNB records
`1961` empty detector rows, zero nonempty rows, and no RAR.

The restart hypothesis is therefore supported, while restart-each alone is
not a usable fix.

## Decision

Keep both new controls default-off. Before more RF, add a one-shot continuation
repair:

1. after a successful restarted true-PRACH write that forces EOB, mark the TX
   stream as needing continuation SOB;
2. on the next ordinary timed non-PRACH write, synthesize SOB from its existing
   requested timestamp and clear the marker;
3. do not apply PRACH guard, offset, restart, or burst-only semantics to that
   ordinary write;
4. emit bounded metadata proving the one-shot reopen;
5. prove disabled behavior and build/deploy before one bounded rerun.

Do not add static lead or change gNB timing for this repair.
