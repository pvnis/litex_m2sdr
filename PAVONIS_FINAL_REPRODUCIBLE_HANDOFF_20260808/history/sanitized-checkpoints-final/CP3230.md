# Checkpoint 3230 - Post-PRACH continuation SOB no-RF gate

## Verdict

**PASS. ONE BOUNDED CP3231 OTA CONTROL IS UNLOCKED.**

CP3229 proved restart-each removes PRACH `TIME_PAST`, but a restarted PRACH
ends the bladeRF burst and leaves the next ordinary write without SOB. CP3230
adds only that missing stream transition.

## Change

`PAVONIS_RF_BLADE_PRACH_REOPEN_CONTINUATION=1` enables a default-off state
machine:

1. a successful restarted true-PRACH write with forced EOB arms a marker;
2. the next timed ordinary non-PRACH write synthesizes SOB from its existing
   requested timestamp;
3. the marker clears only after that send succeeds;
4. the ordinary write receives no PRACH guard, offset, rotation, restart, or
   burst-only classification.

The option is cached once at bladeRF open. Bounded TX metadata reports whether
continuation was pending, applied, armed, and still pending.

- apply requires an ordinary pending non-PRACH write;
- clear requires successful continuation send;
- the continuation block does not set the general `forced_sob` selector, so
  the guard block remains inaccessible to it;
- local/remote source hashes and plugin strings pass;
- help output is byte-identical with both controls off versus on;
- controller validation keeps `56000/253336`, delta `16000`;
- the closed RF gate exits `2` without artifacts;
- no srsUE or gNB process remains.

Only the plugin changes, matching the intended scope.

## OTA Judgment

CP3231 is CP3229 plus only continuation reopen. Require:

1. true PRACH restart rows remain status `OK`;
2. exactly one successful continuation SOB follows each successful restarted
   PRACH;
3. the CP3229 ordinary status-`1`/two-second stall disappears;
4. Msg1, RAR, Msg3, and connected PUSCH progress;
5. connected context-false rows receive no PRACH transforms;
6. both sustained directions complete before throughput interpretation.

No timing or RF setting changes in this control.
