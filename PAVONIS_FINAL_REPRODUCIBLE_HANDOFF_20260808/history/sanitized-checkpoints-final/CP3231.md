# Checkpoint 3231 - Zero continuation time-past partial

## Verdict

**PARTIAL. PRACH AND STREAM STATE RECOVER; TIMED ZERO REOPEN IS LATE.**

All seven true-PRACH writes restart and return status `OK`. The CP3229
status-`1`/two-second stall is gone. The continuation state machine arms on
all seven PRACH writes and attempts to reopen the ordinary stream.

Every reopen attempt is a zero-energy buffer whose inherited scheduled
timestamp is already in the past. All 69 attempts return `TIME_PAST`, keep the
marker pending, and prevent gNB Msg1 detection. This is not a throughput
datapoint.

The arm/apply/retry state machine is correct. Its timestamp policy is not.

## Decision

Keep all controls default-off. For a pending continuation buffer:

1. when its already-measured peak is zero, synthesize SOB with `TX_NOW`;
2. clear the marker only after successful send;
3. retain the current timed behavior for any nonzero buffer;
4. add bounded telemetry for the TX_NOW choice;
5. no-RF build/deploy/default-path gate before one bounded rerun.

This transmits only an empty continuation buffer immediately and does not move
PRACH, PUSCH, gNB timing, RF levels, or any scheduler setting.
