# Checkpoint 3233 - Zero-continuation TX_NOW failed

## Verdict

**FAIL. PRACH TRANSMITS; THE POST-PRACH ORDINARY STREAM DOES NOT REOPEN.**

Both explicit true-PRACH writes restart and return status `OK`, with no
`TIME_PAST`. The CP3232 zero-energy continuation policy then clears the pending
marker. Nevertheless, all 117 subsequently logged ordinary timed appends
return bladeRF status `-1` (`An unexpected error occurred`).

The gNB receives no Msg1 and sends no RAR. This is not a throughput datapoint.

- Continuation marker: armed twice and later cleared twice.
- Visible continuation transition rows: `0`.
- Post-PRACH ordinary appends: `117/117` status `-1`.
- Those 117 rows are all timed, zero-energy, flags `0`, SOB `0`, with the
  continuation marker already clear.
- Ordinary PRACH-transform leakage: guard `0`, offset `0`, restart `0`.
- gNB detector: `1961` empty, `0` nonempty; no RAR.
- gNB TX timeout/downlink-late: `0/0`.

The successful transition write is absent because the debug-row selection
predicate does not include `prach_continuation_sob_applied` or
`prach_continuation_sob_armed_now`. Marker state proves that it ran and
returned success, but CP3233 cannot prove its exact emitted metadata row.

## Decision

Stay no-RF. Add one bounded metadata-only row for each continuation arm/apply
transition, then audit the exact burst sequence against libbladeRF's scheduled
TX contract. Do not [interface-redacted] timing, gain, PRACH detection, or the scheduler before
that transition is mechanically explained.

The remembered USB LiteX throughput remains external qualitative precedent
only; it is not a Pavonis measurement or a numeric baseline.
