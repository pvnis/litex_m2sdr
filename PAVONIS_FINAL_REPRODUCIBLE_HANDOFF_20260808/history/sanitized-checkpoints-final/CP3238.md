# CP3238 - Isolated libbladeRF TX-timestamp reset, no-RF gate

## Verdict

**PASS.** An isolated libbladeRF candidate was built from the exact installed
source commit with one behavior change:

`sync->meta.curr_timestamp = 0;`

The system library was not replaced. The default srsUE/plugin path still loads
the installed library; the candidate is reachable only through the new,
empty-by-default `PAVONIS_RF_BLADE_LIB_DIR` selector.

This checkpoint authorizes one bounded OTA acceptance of the frozen CP3237
shape. It does not claim that the fix works on hardware yet.

## Why this change

CP3237 proved that the first restarted PRACH burst and guarded ordinary
continuation were accepted, while the second restarted PRACH was rejected as
`TIME_PAST`. The exact installed libbladeRF source resets TX message and burst
state in `sync_init()` but retains `meta.curr_timestamp` across repeated
`bladerf_sync_config()` calls. That stale software timestamp survives while the
worker and hardware burst state are restarted.

Resetting `curr_timestamp` beside the other TX metadata fields restores a
coherent fresh-stream timeline without changing Pavonis RF timing, samples,
power, scheduler, or detector policy.

- ABI: both libraries expose SONAME `libbladeRF.so.2`, the same direct
  dependencies, and the same exported-symbol-set hash.
- Resolution: default plugin loading selects the installed system library;
  opt-in loading selects the isolated candidate.
- Runtime: default and candidate `srsue --help` outputs are byte-identical;

- Safety: zero radio/data processes before and after the runtime gate; the
  installed system-library hash stayed unchanged.
- Wrapper behavior: the selector defaults empty and changes
  `LD_LIBRARY_PATH` only when explicitly set.

An initial optional version probe used the wrong foreign-function signature
and crashed that short-lived probe process. It did not open the SDR, start RF,
or alter the candidate/system libraries. The corrected ABI-accurate probe is
the accepted runtime evidence.
