# CP3241 - Lifecycle experiment void: inner srsUE environment omitted flag

## Verdict

**PROPAGATION VOID / LADDER VOID.**

The outer control, launch record, and result record contain
`PAVONIS_RF_BLADE_PRACH_RECONFIG_BEFORE_DISABLE=1`, but the generated
`sudo env` command that actually starts srsUE omits the variable. Both runtime
restart rows prove `restart_tx_stream_reconfig_before_disable=0`.

CP3241 therefore does not test the CP3240 lifecycle order and cannot reject it.
The run instead reproduces the legacy worker failure.

## Evidence

- Candidate-library outer propagation: PASS.
- Lifecycle outer launch/result propagation: PASS.
- Generated runner contains a default assignment and result reporting, but its
  actual srsUE `sudo env` list omits the flag: FAIL.
- Runtime lifecycle mode: 0 on both true-PRACH restarts.
- Runtime sync/disable/start/write statuses: zero, using the legacy order.
- Both guarded continuations: status zero at +56,000 samples.
- First failed ordinary write: 47 calls after the second continuation, again
  at the sync-ring capacity boundary.
- libbladeRF USB TX-buffer timeouts: 15 logged callbacks.
- Subsequent bounded status -1 rows: 117.
- `TIME_PAST`: zero, so the isolated timestamp reset remains effective.
- Cell/SIB1: PASS at 14.239 dB.
- gNB TX health: zero Soapy timeout and zero downlink-late.
- Two UE Msg1, zero nonempty gNB PRACH rows, no RAR/PUSCH/traffic.

## Decision

Add exactly one missing lifecycle-variable assignment to the generated srsUE
`sudo env` list. The next no-RF verifier must inspect a generated runner, not
only the wrapper source or outer launch/result layers. Then retry the otherwise
unchanged CP3241 shape with a fresh identity. Do not alter plugin logic,
dependency, RF timing, PRACH envelope, or detector policy.

CP3240's source/build gate remains valid, but its wrapper-propagation proof was
insufficient and is superseded by this checkpoint.
