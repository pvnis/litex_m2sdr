## Verdict

**PASS.** A current official Nuand `master` candidate is pinned at
`[hex-value-redacted]` and built in isolated source,

## Rationale

CP3239 and CP3245 reproduce the same failure after the second synchronous TX
worker: the software ring fills because no USB TX buffers complete. The
installed feature-branch commit predates upstream sync initialization, buffer
management, transfer diagnostics, and thread-lifecycle work. Relative to that
commit, current upstream changes 227 lines added and 38 removed across the four
relevant streaming/board files.

This checkpoint does not claim one upstream change fixes Pavonis. It establishes
a controlled dependency A/B that can answer that question without an in-place
migration.

## Decision

Run CP3247 once. Apply the CP3245 transport gate first: both restarts and
continuations must pass, then the second worker must survive the 48-call failure
point with zero USB timeout, `TIME_PAST`, `INVAL`, or status storm. Only then
judge PRACH/RAR/Msg3, connected PUSCH CRC, and sustained traffic.

If the second worker still fails, reject full upstream as the repair and move
to eliminating repeated sync-worker replacement by bounding software TX
queue-ahead below the PRACH hardware lead. Do not migrate the system library
based on this gate alone.
