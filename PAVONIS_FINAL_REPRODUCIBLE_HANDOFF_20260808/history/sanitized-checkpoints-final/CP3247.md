# CP3247 - Upstream improves but does not fix repeated TX workers

## Verdict

**DEPENDENCY PARTIAL / TRANSPORT FAIL / LADDER VOID.**

The pinned current-upstream library materially improves repeated synchronous TX
worker operation but does not make it reliable. Five replacement intervals
complete; after the sixth replacement, USB TX completions stop and the
software ring fills.

Do not migrate the system library based on this result.

## Evidence

- Upstream candidate and reconfigure-only propagation: PASS.
- Six restart rows: sync-config and restarted write status `0`.
- Six continuation rows: status `0`, exact +56,000-sample hardware lead.
- Workers 1 through 5 survive until the next PRACH replacement.
- First failure after worker 6: call 6886, 47 calls after its continuation.
- TX trace: 147 rows; status histogram `0:30`, `-1:115`, `-3:2`.
- USB TX transfer-timeout callbacks: seven.
- `TIME_PAST`: zero.
- Cell/SIB1: healthy at 15.895 dB.
- gNB TX health: zero Soapy timeout and zero downlink-late.
- Six UE Msg1, zero nonempty gNB PRACH results, no RAR or PUSCH.

Compared with CP3245's failure after worker 2, the upstream lifecycle changes
are relevant. The same deterministic ring-capacity signature after worker 6
shows they are not a complete repair.

## Decision

Reject an in-place upstream migration as the next step. Retain the isolated
candidate for later comparison only.

Move to avoiding repeated worker replacement. The source-derived mechanism is
software queue-ahead: with 256 TX buffers rounded to 2,048 samples, libbladeRF
can accept 524,288 samples (45.5 ms) while PRACH is scheduled only about
40,000 samples (3.47 ms) ahead of hardware. The software timeline can therefore
overtake a real PRACH timestamp.

Next no-RF work should add a default-off, TX-only bounded queue profile whose
total software ring is below the measured PRACH hardware lead. Keep RX
buffering unchanged. Gate the profile with a capacity proof, native build, and
disabled-path identity. Its RF control should remove restart-each and use the
normal timed metadata path; if a first-PRACH transition still needs one initial
restart, test that separately rather than restoring repeated replacement.
