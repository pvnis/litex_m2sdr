# CP3248 - Default-off bladeRF bounded TX queue no-RF gate

## Verdict

PASS. The default-off TX-only bounded-queue branch builds natively and passes
the source, propagation, rollback, dependency, and closed-RF gates. CP3249 is
approved as the single frozen-shape RF control.

The historical USB LiteX result is recorded only as user-recalled external
qualitative precedent. Pavonis did not produce that measurement, and no
numeric baseline or attribution is inferred from it.

## Change

`PAVONIS_RF_BLADE_TX_BOUNDED_QUEUE=1` selects 12 TX buffers and 8 transfers.
The current library rounds each configured 1024-sample TX buffer to [date-redacted]
samples, so the modeled software queue capacity is 24,576 samples. That is
6,396 samples below the minimum previously observed 30,972-sample PRACH
hardware lead.

RX remains at 256 buffers and 32 transfers. The disabled TX profile remains
256 buffers and 32 transfers.

For a true timed PRACH arriving while a burst is open, with restart selectors
off, the branch converts the existing forced `START|END` metadata to
`UPDATE_TIMESTAMP|END`. Official libbladeRF source documents this as the
in-burst mechanism that zero-pads to the requested timestamp without replacing
the sync worker. A successful update arms the already-proven guarded
continuation start.

The event trace emits only for PRACH and continuation transitions. It performs
no per-sample instrumentation.

## CP3249 acceptance

Run the frozen CP3245 geometry once with:

- bounded queue on;
- PRACH restart and reconfigure off;
- guarded continuation on;
- system libbladeRF selected;
- guard 56,000 samples and compensation 253,336 samples unchanged.

Transport passes only if the runtime proves 12/8/24,576, every true PRACH uses
`UPDATE_TIMESTAMP|END`, every continuation starts at the existing 56,000
sample lead, there are no restart rows, and there are zero time-past, invalid,
status-minus-one, or USB timeout events. Only after that gate may Msg1, RAR,
Msg3, connected PUSCH, or sustained throughput be interpreted.
