## Verdict

TRANSPORT PASS; SECOND VALID PRACH-SUPPLY FAIL.

The frozen CP3253 shape again transports all seven Msg1 bursts without a
bladeRF metadata, queue, or USB failure. The gNB stage-1 path selects none,
so the single-scatter retry budget is exhausted and a third unchanged RF run
is not justified.

## Evidence

The transport signature reproduces CP3253:

- Runtime queue: 5 buffers, 4 transfers, 10,240 modeled samples.
- PRACH writes: 7/7 status 0.
- First restart/EOB: one row with flags `0x3`.
- Continuous timestamp updates: six rows with flags `0x8`, burst open before
  and after.
- Continuation: one row, status 0, exactly +56,000 samples.
- PRACH hardware lead: 34,680 to 40,000 samples.
- USB timeouts, time-past, invalid, and status-minus-one rows: all zero.

The downlink and gNB TX path are healthy: cell selection succeeds at
15.107 dB with CFO -4011 Hz, and Soapy timeout/downlink-late counters are
zero. The UE sends seven Msg1 attempts. The gNB records 1,924 stage-1 trace
rows, zero selected candidates, zero nonempty detections, zero RARs, and zero
PUSCH rows.

## Decision

Keep the continuous-update transport branch as the working baseline. Do not
take a third unchanged run.

The next work is no-RF first: add a bounded capture mode that retains the
actual below-floor Msg1 opportunities without full-rate append, per-sample
logging, or live log polling. Then run the wide offline detector search on
those exact samples and change only the candidate envelope named by replay.
