## Purpose

Capture the seven actual srsUE Msg1 collection windows below the old strong-
capture floor, then decide offline whether the live detector failure is caused
by an incomplete timing/CFO candidate envelope.

precedent only. It was not produced by this Pavonis campaign and supplies no
numeric baseline.

## Offline Replay

The established CP1965 detector harness was copied into this checkpoint and
extended locally. CP1965 source and binary remain byte-identical. The added
grid spans integer timing `-12000..+11936` samples in 128-sample steps and CFO
`-60..+60 kHz` in 1 kHz steps.

Results:

```text
seven matched windows, stage-1:       5,215 evaluations, 0 accepts
seven matched windows, extreme:     274,365 evaluations, 0 accepts
seven matched windows, full-span:   159,243 evaluations, 0 accepts
matched-window maximum p0 ratio:      0.245
64-window neighborhood, stage-1:     47,680 evaluations, 0 accepts
64-window neighborhood, full-span: 1,455,936 evaluations, 0 accepts
```

The same full-span grid was run against the six known-positive CP1961 windows.
It produced `4,083` accepted variants from `136,494` evaluations and recovered
all six windows. This positive control proves that the timing-grid resolution
can recover detector-visible PRACH.

## Verdict

**Valid zero; candidate-envelope [interface-redacted] is closed for this run.**

No detector-visible bladeRF PRACH exists anywhere in the seven matched
23,520-sample buffers or in any of the 64 captured collection opportunities.
This is not explained by the live stage-1 list, a displacement elsewhere
inside the extra 12,000 samples, or a one-occasion association error.

The next discriminator must locate the actual bladeRF emission in M2SDR
hardware sample time. Use a bounded, explicitly instrumentation-only continuous
M2SDR RX capture. Per CP1894, that run is detection-void by design and must not
be interpreted as a PRACH/RAR ladder datapoint.
