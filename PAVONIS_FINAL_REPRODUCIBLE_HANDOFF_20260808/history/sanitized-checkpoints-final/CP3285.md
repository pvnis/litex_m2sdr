# CP3285 - Parallel TCP Demand Discriminator No-RF Gate

Date: [date-redacted]

## Purpose

CP3284 proves that nonzero BSR demand reaches OCUDU but does not raise
single-flow throughput. CP3285 tests the remaining demand-feed hypothesis
without changing the radio: four concurrent TCP streams run sequential
downlink and uplink phases over the same private user-data session.

## Endpoint Tooling

New isolated server/client tools preserve the established aggregate JSON
fields while adding:

```text
schema:                 2
streams:                4
per-stream result rows: 4 per direction
```

Each direction accepts or opens all four connections, then uses a thread
barrier so their deadlines start together. Aggregate authority remains UE
receiver bytes for downlink and core receiver bytes for uplink. A dedicated
analyzer requires complete endpoints, four stream rows, positive data, and
the established duration tolerance.

## Loopback Gate

A one-second local loopback run passes:

```text
server rc:       0
client rc:       0
analyzer rc:     0
stream gate:     PASS
duration gate:   PASS
server rows:     4 DL / 4 UL
client rows:     4 DL / 4 UL
```

## Controller and Runner

The isolated CP3285 controller changes the CP3283 extended controller only to
deploy the parallel endpoint tools, accept/validate `--streams`, propagate
the count, record it in `rf_shape`, and invoke the parallel analyzer.

The CP3286 runner keeps:

```text
45 seconds per direction
UE timeout 360 seconds
gNB duration 540 seconds
the byte-identical 21-transform candidate list
all CP3273 radio, timing, transport, scheduler, MCS, gain, and attenuation
```

Fresh BSR is explicitly disabled (`refresh=0`, `trace=0`) because CP3284
retired it. The measured variable is four TCP flows versus CP3273's one.

Python compilation, `bash -n`, controller validate-only, and the closed RF
gate all pass. The closed gate exits 2.

## Verdict

**PASS: one CP3286 formal four-stream RF discriminator is unlocked.**

If aggregate UL and scheduler gross rate rise materially, single-flow
TCP/RLC demand feed is the active ceiling. If they do not, application demand
is exonerated and the next source target is scheduler grant continuation,
followed by the high-order modulation failure policy.
