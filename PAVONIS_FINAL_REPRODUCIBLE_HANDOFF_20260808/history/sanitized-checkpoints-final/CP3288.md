# Checkpoint 3288: Static-Order Retry Access Void

## Verdict

**VOID for four-stream throughput; static candidate reordering is closed.**

The order-only retry again had healthy downlink and Msg1 supply but produced no
RAR or endpoint traffic. The transform selected in CP3286 did not accept in
this run. Instead, all six accepted occasions selected a different late-list
transform.

## Evidence

- Cell selection passed at 15.661 dB SNR.
- The UE transmitted seven PRACHs; the gNB selected six candidates.
- All six selected rows used `shift=64`, `frac=-0.5`, `cfo=+5000 Hz`.
- This was candidate 20 including the baseline, with search time
  10,858-11,746 us.
- Every accepted indication reached scheduling after its 40-slot RAR window.
- PDCCH, PDSCH, and PUSCH allocation-failure counters remained zero.
- RAR allocations, UE RAR accepts, Msg3/PUSCH, and endpoint results were zero.
- Soapy TX timeout and downlink-late counts were zero.

CP3286 selected `-224/-0.5/+60000 Hz` on all six occasions; CP3288 selected
`64/-0.5/+5000 Hz` on all six. The useful transform is stable within a run but
changes between runs. Static list ordering therefore cannot make access
reliable.

The next source audit should evaluate a default-off sticky fast path: after the
first accepted stage-1 transform, try that same transform before the normal
baseline/list on later PRACH occasions. The full list remains the fallback, so
standards-default and diagnostic-disabled behavior stay unchanged.
