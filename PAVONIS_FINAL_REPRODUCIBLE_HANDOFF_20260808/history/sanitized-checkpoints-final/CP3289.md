# Checkpoint 3289: Stage-1 Sticky Transform No-RF Gate

## Verdict

**PASS.** One CP3290 bounded formal RF diagnostic is unlocked.

The change is default-off and diagnostic-scoped. It addresses the evidence
from CP3286 and CP3288: the accepted stage-1 transform changes between runs
but remains identical across all six accepted occasions within a run.

## Implementation

`PAVONIS_PRACH_DEMOD_INPUT_STAGE1_STICKY_LAST_ACCEPT=1` enables a worker-local
cache of the last accepted non-baseline transform.

On a later PRACH occasion, the worker:

1. Tries the cached transform first.
2. Stops immediately when the existing stop-on-accept policy accepts it.
3. If it does not accept, runs the existing baseline and full candidate list.
4. Skips the cached transform when its original list/grid position is reached,
   preserving the number of unique candidate evaluations.
5. Replaces the cache only after another accepted transform. A baseline accept
   clears it; no-accept occasions preserve it.

The existing trace gains three metadata columns:
`sticky_valid`, `sticky_tried`, and `sticky_hit`. No new per-sample scan or
file path was added. The transform computation merely moves one existing
candidate to the front when the cache is valid.
