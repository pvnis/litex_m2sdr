# Checkpoint 3292: Timing Fixture Propagation Void

## Verdict

**VOID.** The controller pins and records 115,200 samples, but the live gNB
still receives zero. Throughput and the intended timing correction are
unjudged.

Sticky stage-1 and RAR supply pass again:

- First accept: candidate 2, 836 us.
- Next five accepts: candidate 1, 741-810 us, sticky `1/1/1`.
- gNB RAR allocations and UE RAR accepts: 6/6.

The UE encodes 18 Msg3 PUSCH attempts, but the gNB is 0/30 CRC OK because the
runtime non-PRACH scheduler-error correction remains zero.

## Root Cause

The complete wrapper-chain audit finds one clobber:

`cp2232_run_msg3_edge_calibration.sh` unconditionally exports
`PAVONIS_NON_PRACH_UL_RX_OFFSET_EDGE_SCHEDULER_ERROR_SAMPLES=0`.

That assignment occurs after the isolated controller sets 115,200 and before
the shared stage reads it. The correct no-RF fix is caller-preserving default
behavior:

```bash
export PAVONIS_NON_PRACH_UL_RX_OFFSET_EDGE_SCHEDULER_ERROR_SAMPLES="${PAVONIS_NON_PRACH_UL_RX_OFFSET_EDGE_SCHEDULER_ERROR_SAMPLES:-0}"
```

Unset callers must still receive zero; CP3292-family callers must retain
115,200 through the full chain.
