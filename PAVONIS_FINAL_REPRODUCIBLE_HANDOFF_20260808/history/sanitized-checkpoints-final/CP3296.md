**Reactive downlink allocation PASS. Contention-resolution PDSCH decode PASS.
PUCCH HARQ-ACK FAIL.**

The failure after Msg3 is not an RRC/F1/scheduler drop and is not a missing
reactive downlink block. It is a strong but phase-invalid format-1 HARQ-ACK.

## Ordered Path

The default-off, metadata-only trace emits 45 rows and proves the first
CRC-valid Msg3 traverses:

```text
PHY CRC -> FAPI -> MAC unpack -> CCCH -> DU UE creation
-> Initial UL RRC -> RRC Setup pack -> F1/SRB0
-> fallback contention resolution pending -> fallback PDSCH allocated
```

The fallback PDSCH is allocated 37 slots after Msg3, inside the contention
resolution window. The event occurs `1.957 ms` after the first CRC callback;
there is no stale-result or scheduler-expiry failure.

At the exact fallback slot the UE sees a strong candidate (`EPRE 28.113`,
correlation `0.952155`) and decodes the 9-byte PDSCH CRC OK at `11.122 dB`
SNR and `0.361` EVM. This is the contention-resolution block.

Its `k1=4` format-1 HARQ-ACK then reaches the gNB at normal power but is
invalid:

```text
EPRE:              -32.765770 dB
detection metric:    0.853303
demodulated SINR:  -12.719677 dB
```

The full seven-candidate adaptive phase bank runs and finds no valid class.
Without that ACK, the gNB does not transmit the subsequent RRC Setup PDSCH.

The CP3273 pass is the exact control. Its equivalent ACK has effectively
identical EPRE (`-32.762070 dB`) but metric `262.830841`, SINR
`+12.179433 dB`, and valid status. The gNB then sends the 301-byte RRC Setup
PDSCH and the attach continues. This is a phase/timing demodulation split, not
power or missing UE transmission.

The event-armed worker trace covers the reactive epoch with 65,536 full-MTU
zero-copy rows, zero late/dedup/short/duplicate-timestamp rows, and no timed
anchor in the first 150 ms. Descriptor presentation is structurally clean
through the Msg4/ACK window.
