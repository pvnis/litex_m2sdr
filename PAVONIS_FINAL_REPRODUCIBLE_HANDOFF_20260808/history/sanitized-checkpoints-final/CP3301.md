## Verdict

**PASS.** The CP3300 behavior is explained and the final phase candidate is
corrected from `166:1` to `-14:1`.

This checkpoint supersedes CP3298's candidate interpretation and CP3299's
candidate choice. It does not invalidate CP3300's live result: CP3300 really
did produce a valid format-1 decode, but that decode was NACK.

## Root Cause

The CP3298 replay tool inserted the captured grid into a format-1 mux with
zero HARQ bits, the SR-only geometry used by the 16 historical captures. The
grid itself came from a one-bit HARQ-ACK opportunity. The sweep therefore
found the correct correlation family but evaluated the wrong UCI semantic.

The FAPI adapter maps decoded bit `1` to ACK and bit `0` to NACK. Replaying
the same captured grid with one HARQ bit gives:

| Candidate | Valid | HARQ value | Meaning | Metric | SINR |
| --- | --- | ---: | --- | ---: | ---: |
| `166:1` | yes | `0` | NACK | `113.019` | `+6.285 dB` |
| `-14:1` | yes | `1` | ACK | `113.019` | `+6.285 dB` |

The candidates differ by `180 degrees/symbol`, preserving correlation while
inverting the decoded one-bit payload. This exactly explains CP3300: the new
candidate made the result valid, but the scheduler received NACK and did not
advance.

## Corrected Gate

The seven established fallback candidates remain byte-identical. Only the
final entry changes:

```text
4:-178,8:90,8:-96,6:-104,4:-112,2:-120,0:-128,-14:1
```

The replay tool now has explicit HARQ-aware trial and bank modes. The
corrected mixed-geometry regression gate passes `17/17`:

- all 16 historical SR grids retain valid earlier winners;
- the CP3298 ACK grid reaches index 8;
- index 8 is valid with `harq_value=1`.

No production detector source or binary changed. The CP3302 runner matches
CP3300's frozen RF, timing, PRACH, BSR and scheduler controls, validates with
21 PRACH candidates and scheduler error `115200`, and remains RF-closed by
default with exit code `2`.
