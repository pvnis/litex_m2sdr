# Checkpoint 3310: Preconnected Bidirectional No-RF Gate

Date: [date-redacted]

RF executed: no

## Verdict

**PASS / READY FOR ONE BOUNDED RF RUN.** An isolated benchmark now establishes
all four downlink and four uplink TCP connections before either direction
starts. It then runs the same sequential directions and preserves receiver-side
throughput authority.

## Rationale

CP3309 proved attach and sustained downlink, then timed out while creating the
second connection set. Preconnection removes only that transition. It does not
change RF, scheduling, packet sizes, stream count, direction duration, or the
radio process lifetimes.

## No-RF Validation

Two exploratory loopbacks exposed endpoint-boundary races:

- A receiver acknowledgement may miss the client timeout after the server has
  already recorded a complete authoritative uplink result.
- The server may close exactly at the duration boundary while a sender is
  finishing its last write.

The client now records those conditions without discarding the server-receiver
result. Five consecutive final loopbacks pass with four preconnected sockets
per direction, positive DL/UL at both endpoints, both endpoints complete, and
all four uplink acknowledgements present.

The controller wrapper delegates to the frozen CP3303 main and overrides only
the server/client file paths. The RF runner's candidate list is unchanged from
CP3308 and reverse-normalizes exactly after accounting for checkpoint paths,
fresh identifiers, and the private benchmark port. Validate-only reports
22/30 candidates, four streams, UE guard `56000`, PRACH compensation `352536`,
sticky enabled, and scheduler error `115200`. The default RF gate exits `2`.

## Next Step

Run one bounded CP3310 measurement with a fresh identifier. Judge health and
attach first, then require both 45-second directions complete. If UL completes,
compare it with CP3273 and the ZMQ ceiling. If preconnection succeeds but UL
still fails or remains slow, the remaining issue is sustained uplink
scheduling/PHY behavior rather than TCP handshake supply.
