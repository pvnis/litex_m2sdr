# CHECKPOINT 3326 - PAIRED VIRTUAL SOAPY TIMEBASE NO-RF GATE

## Verdict

**PASS.** A default-off paired virtual Soapy timebase is implemented, built,
deployed and no-RF gated. No RF was transmitted in this checkpoint.

The candidate subtracts the existing 20 ms M2SDR TX lead from OCUDU current
time and RX metadata, adds it back only when activating the physical RX stream,
and leaves TX timestamps virtual for the LiteX worker to convert to physical
time with the same 20 ms lead. The two offsets must match exactly or session
construction fails.

## Rationale

CP3325 proved that the demod-only hardware correction leaves MAC/HARQ about
30.565 ms behind the received PUSCH. At 11.52 Msps, the paired 20 ms offset is
230400 samples. The first diagnostic therefore changes the established PRACH
collection compensation from 352536 to:

```text
352536 - 230400 = 122136 samples
```

All static and dynamic non-PRACH demod shifts are disabled in the candidate.
The 40-slot processor lifetime remains enabled as a guard until live evidence
shows it can be reduced.

## Implementation

The Soapy session reads `PAVONIS_SOAPY_VIRTUAL_TIME_OFFSET_NS` once during
construction. Disabled or zero preserves the existing path. An enabled value
must be in `(0, 1000000000]` and exactly equal
`M2SDR_SOAPY_TX_TIME_OFFSET_NS`.

The conversion is applied at four boundaries:

1. hardware current time: physical to virtual;
2. RX activation: virtual to physical;
3. readStream and acquireReadBuffer metadata: physical to virtual;
4. RX lag telemetry: physical current time to virtual before comparison.

No environment lookup, formatting, file IO or per-sample work was added to the
receive hot path. The cached offset adds one integer conversion per timestamp,
and the disabled path is identity.
