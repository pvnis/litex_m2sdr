# CHECKPOINT 3327 - PAIRED VIRTUAL TIMEBASE MECHANISM FAILURE

## Verdict

**MECHANISM FAIL; no throughput datapoint.** The bounded candidate run stopped
at the pre-UE TX-health gate. The UE was never started, so this is not a
cell-acquisition void and does not consume the standing single-void retry.

The simple paired virtual-clock design is closed without an unchanged retry.

## Propagation

The native candidate and isolated launcher were active:

- virtual Soapy offset: 20 ms;
- LiteX TX release offset: 20 ms;
- virtual offset at 11.52 Msps: 230400 samples;
- PRACH collection compensation: 122136 samples;
- static and dynamic non-PRACH demod shifts: disabled;
- MCS ceiling: 16;
- 40-slot processor lifetime: retained.

The runtime emitted the virtual-timebase activation marker once. Readback
confirmed the 20 ms LiteX release offset, all-timed mode, corrected deadline
write, one RF channel, 11.52 Msps and the frozen attenuation.

## Evidence

The first 100 logical writes already show:

```text
timeouts=50
deadline_write_breaks=50
stream_deficit=576000 samples
```

At the pre-UE gate:

```text
timeouts=63250
deadline_write_breaks=63250
stream_deficit=728640000 samples
```

The LiteX worker emitted only its startup summary and zero periodic rows:
post-start data never reached the worker. Release-late and downlink-late
counters stayed zero because the TX stream abandoned writes before descriptor
publication.

## Explanation

CP3326 made OCUDU current time 20 ms behind physical hardware time. The lower
PHY therefore produced steady-state TX timestamps 20 ms earlier. The existing
deadline selector added the driver's 20 ms release offset before comparing
against physical hardware time, cancelling the virtual shift and leaving
approximately zero submission lead. After the initial startup buffer was
consumed, every all-timed write was at or behind the 2 ms guard.

This is causal, deterministic evidence. It is not the CP3320-style random
pre-access class, so repeating the same shape would waste RF.

The deeper constraint is real-time causality: the current architecture obtains
TX stability by scheduling RF emission ahead of host processing. A global
clock translation cannot remove that physical lead and simultaneously retain
the same descriptor-submission margin. Eliminating HARQ aging therefore
requires reducing the actual TX lead or introducing a separate future-DL
lookahead pipeline, not relabeling the whole radio clock.

## Decision

Keep the feature default-off and preserve its tests as a documented negative.
The CP3322 launcher remains byte-for-byte isolated on the prior proven binary.

Next use bounded gNB-only health gates to find the lowest sustainable actual
TX lead with the corrected deadline and CP2074B descriptor path. Start at
10 ms, then bracket toward the approximately 1.5-5 ms historical working
region only when each preceding gate has zero delivered-stream deficit and
normal worker activity. For each accepted lead, reduce PRACH and non-PRACH
timing by the same sample delta before a full OTA run.
