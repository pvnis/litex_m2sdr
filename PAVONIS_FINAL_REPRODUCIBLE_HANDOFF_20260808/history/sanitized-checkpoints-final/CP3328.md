# CHECKPOINT 3328 - REDUCED TX LEAD GNB-ONLY GATE

## Verdict

**PASS at 10 ms; fail below 10 ms under the current host/runtime shape.**

Four bounded gNB-only transmissions bracketed the actual LiteX TX release lead.
No UE was started, so PRACH, acquisition and traffic variability cannot affect
the result.

## Results

| TX lead | Deadline guard | Stream deficit | Breaks/timeouts | Late rows | Verdict |
| ---: | ---: | ---: | ---: | ---: | --- |
| 10 ms | 2 ms | 0 | 0 / 0 | 0 | PASS |
| 7.5 ms | 2 ms | 21274 samples | 3 / 3 | 0 | FAIL |
| 5 ms | 2 ms | 168336 samples | 21 / 21 | 0 | FAIL |
| 5 ms | 0.5 ms | 153006 samples | 21 / 21 | 0 | FAIL |

The 10 ms run delivered all 742037610 requested samples over 64413 logical
blocks. All retry, carry, abandonment, deadline, error, downlink-late and
release-late counters were zero. All-timed mode and the corrected deadline
offset were active.

## Failure Shape

At 5 ms with the normal 2 ms guard, break counts changed around logical blocks
13000/13100, 36100 and 59100. The loss therefore recurs during steady state;
it is not the historical startup-prime deficit. Reducing the guard to 0.5 ms
left the break count unchanged at 21, proving the 5 ms wall is not merely a
conservative 2 ms gate.

The 7.5 ms point reduced the same class to three breaks but did not eliminate
it. Current host/runtime stalls therefore occasionally consume more than
7.5 ms of physical lead. A lead below 10 ms is not promoted until that stall
source is isolated and the strict zero-delivery-loss gate passes.

## Decision

Promote the lossless 10 ms/2 ms-guard shape to one MCS16 OTA run. Relative to
the CP3322 20 ms baseline, retime both uplink classes by 115200 samples:

```text
PRACH: 352536 - 115200 = 237336
non-PRACH edge calibration: -237332 + 115200 = -122132
```

Keep the empirical 115200-sample scheduler term and all other CP3322 controls
unchanged. The run must prove the new constants and 10 ms readback before
traffic is interpreted.
