# CP3333: periodic deadline forensics

## Verdict

**NO-RF MECHANISM SPLIT.** CP3332 did not hit a Soapy write timeout. All
`12` losses were pre-write deadline breaks in
`radio_soapy_tx_stream::select_tx_data_write_timeout()`: the TX producer
arrived after the guarded hardware deadline and abandoned `85096` samples
before calling `device.write_stream()`.

The initial DMA-wrap theory is not supported by the source widths. The leading
mechanism is instead missing real-time scheduling permission on [host-redacted].

## Evidence

The `23 s` recurrence is real. CP3328's 5 ms gate changes near logical blocks
`13000/13100`, `36100`, and `59100`; CP3332 changes at `98500`, `121500`,
`144500`, `190100`, `235700`, and `419500`. CP3332's `121500` transition
coincides with its PUSCH collapse.

The tempting power-of-two explanation does not survive the source audit:

- the mmap ring is `256` buffers of `8192` bytes;
- the live stream MTU is `1022` complex samples;
- kernel software counters are signed 64-bit;
- LitePCIe exposes a 16-bit loop index and 16-bit loop count;
- timed-TX timestamps and the sample-domain reference are 64-bit.

The loaded `m2sdr.ko` hash matches the module built beside the audited source.
No counter wraps at `2^18` descriptors or `2^28` samples in this path.
The numerical resemblance remains a correlation, not a driver defect.

By contrast, the CP3332 startup log reports failed priority changes for every
critical worker, including `lower_phy_tx#0`, `lower_phy_ul#0`, and
`lower_phy_rx#0`. The operator's fresh SSH session has `RLIMIT_RTPRIO=0`;
the gNB has no file capability. OCUDU requests `SCHED_FIFO`, but
`pthread_setschedparam()` returns insufficient privilege. The kernel itself
reserves a normal `950000/1000000 us` RT budget, so the missing piece is
process permission, not a disabled RT scheduler.

This explains the observed margin behavior coherently: 20 ms hides producer
descheduling, 5-7.5 ms exposes it even without a UE, and 10 ms survives the
light gNB-only shape but fails under full PHY traffic.

## Decision

Do not patch DMA or add per-descriptor telemetry. Add a persistent,
operator-scoped RT limit, verify from a fresh SSH session that an unprivileged
process can enter `SCHED_FIFO`, then repeat the exact CP3328 5 ms bounded
gNB-only gate. The discriminator is strict:

- zero priority warnings and zero deadline/sample loss support the mechanism;
- unchanged periodic loss rejects it and reopens event-triggered producer/DMA
  timing telemetry.

No UE is needed for that gate.
