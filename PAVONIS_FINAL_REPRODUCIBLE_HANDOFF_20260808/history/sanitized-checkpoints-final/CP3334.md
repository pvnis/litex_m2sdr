# CP3334: real-time permission no-RF gate

## Verdict

**PASS.** A fresh [host-redacted] login now has `RLIMIT_RTPRIO=98` and can enter
`SCHED_FIFO` at priority `10` without elevation. The candidate gNB remains
byte-identical at
`a52943b098aa8c8c20a051ed2b70362bbed220e0f304e19dd57ba38c70ff827d`;
no file capability was added.

## Change

The host now has a dedicated Pavonis real-time operator group and a single PAM
limits file:

`/etc/security/limits.d/99-pavonis-realtime.conf`

The file grants that group `rtprio 98`. `pam_limits.so` was already required
by the SSH PAM stack. The project operator was added to the group, and a new
SSH login independently proved both the inherited limit and a successful
`SCHED_FIFO` transition.

This is deliberately narrower than setting capabilities on the gNB. It does
not alter the executable, its hash, shared-library loading, the kernel RT
budget, CPU policy, RF configuration, or any source.

## Gate

The no-RF proof is:

```text
group_active=1
rtprio_limit=98
sched_fifo_entered=1
scheduling policy: SCHED_FIFO
scheduling priority: 10
```

The persistent limits file hash is
`3470b7fef07b680c2e9a0540be0231a6f9bb66bdcff63ea96b40adaf22952877`.

`AGENTS.md` now requires this effective fresh-session probe before any
reduced-lead M2SDR verdict and treats lower-PHY priority warnings as an
invalid host-state gate.
