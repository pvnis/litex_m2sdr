# CP3335: RT-enabled 5 ms gNB-only gate

## Verdict

**MECHANISM REJECTED.** The host scheduling repair worked mechanically:
the gNB emitted zero failed-priority warnings. It did not improve the exact
CP3328 5 ms / 2 ms-guard discriminator.

CP3335 recorded `26` pre-write deadline breaks and `199364` missing samples,
versus CP3328's `21` and `168336`. No UE ran, and generic Soapy timeout,
downlink-late, release-late, and deadline-controlled write-timeout counts were
all zero.

## Evidence

The authoritative stop row is:

```text
logical=64915
deadline_write_breaks=26
deadline_write_timeouts=0
deadline_write_abandoned_samples=199364
stream_deficit=199364
```

Break counts changed at logical `6700/6800` and `29800`; the cluster spacing
is again approximately `23.1 s`. Effective `SCHED_FIFO` therefore does not
remove the periodic producer stall and is not the root-cause fix.

## Next Split

The gNB wrote `651` periodic TX summary rows during this no-UE window. Those
multi-kilobyte rows account for almost all of the `2598549`-byte gNB log.
The wrapper forces `OCUDU_SOAPY_TX_SUMMARY_PERIOD=100`, while the source
default is `10000`.

Source inspection proves that setting the period to `0` disables only
`maybe_log_tx_summary()` periodic rows; `stop()` still calls
`log_tx_summary("stop")` directly. The authoritative final counters can
therefore be retained while eliminating the high-rate diagnostic.

Keep the RT permission active for one-variable isolation. Build an append-only
runner with summary period `0`, no source or binary change, and repeat this
same 5 ms bounded gNB-only shape.
