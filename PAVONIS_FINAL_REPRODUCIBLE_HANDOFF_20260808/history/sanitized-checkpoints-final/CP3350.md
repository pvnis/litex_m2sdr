# CP3350: 6 ms period-zero pre-UE summary void

## Verdict

**VOID for OTA, useful TX gate.** CP3350 proves the CP3348 expectation shim:
the readback gate passes with the intended 6 ms lead and 500 us deadline
guard. The UE is still not started because the frozen full-ladder wrapper
requires a periodic pre-stop TX summary, while the CP3346 launcher deliberately
sets summary period zero.

## Gate sequence

```text
settings deadline guard=500 us
start_gnb_nativecontinuous_stage6 rc=0
gate_nativecontinuous_tx_readback rc=0
gate_pre_ue_tx_late_health rc=0
gate_pre_ue_tx_summary_health rc=1
SKIP_UE gate_pre_ue_tx_late_health_failed
UE_STARTED=0
```

The final skip label is generic: its immediate failing sub-gate is
`gate_pre_ue_tx_summary_health`, not the late-event gate.

## TX health

Across the approximately 60-second pre-UE window, the packaged gNB log has:

```text
deadline_break_trace_rows=0
write_stream_timeouts=0
downlink_late=0
rf_errors=0
```

Device readback proves:

```text
tx_all_timed_chunks=1
tx_deadline_write_timeout_enabled=1
tx_deadline_write_guard_us=500
env_M2SDR_SOAPY_TX_TIME_OFFSET_NS=6000000
```

This supports the CP3345 clean result but does not replace a stop-summary
counter verdict because the wrapper's generated-config cleanup again leaves
the gNB running. Targeted cleanup removes that exact process and frees private
UDP port 2152.

## Decision

Use the source-default sparse summary period of 10,000 logical blocks rather
than period zero for the full-ladder path. This supplies roughly one compact
row per 10 seconds, avoiding CP3335's period-100 logging load while satisfying
the inherited pre-UE gate.

No-RF gate a copied CP3346 launcher that changes only summary period
`0 -> 10000`, then run one bounded gNB-only full-wrapper pre-UE gate with the
UE explicitly disabled. Only after readback, periodic summary, stop health and
cleanup all pass should another attach/traffic attempt run.
