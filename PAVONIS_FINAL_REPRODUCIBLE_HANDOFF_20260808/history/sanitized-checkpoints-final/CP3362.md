# CP3362: 8.5 ms / 500 us Long gNB-Only Gate

## Verdict

**FAIL. Stop sweeping static lead.** The 420-second run reads back 8.5 ms /
500 us but records 25 guard-triggered breaks, 169448 abandoned stream samples,
and 24062 unwritten data samples. All raw leads remain positive, worker and
release late counts are zero, and no actual write timeout occurs.

## TX Evidence

- requested / returned: 4838265984 / 4838241922 samples;
- deadline breaks / actual write timeouts: 25 / 0;
- abandoned / stream deficit / data-write deficit:
  169448 / 169448 / 24062;
- partial / generic timeout / downlink-late / worker-late / release-late /
  errors: all zero.

Every trace row retains exact 11520-sample metadata progression. Raw lead is
163--498 us, mean 427.9 us; all 25 events are guard-only. Seven logical-gap
cluster roots have raw lead 387--477 us. Their recurring deltas include 22529,
23041, 23040, 46080, and 22522 logical milliseconds, exposing the same
approximately 22.528/23.040-second cadence across the long runs.

Increasing static lead has therefore changed event counts without bounding or
eliminating this periodic lead consumption. Another constant-only rung is not
justified.

## No-RF Log Audit

The generated gNB config sets `log.all_level: info`. CP3362's 20.68 MB log has
157358 lines, of which 154575 (98.23%) are per-slot PHY `INFO` rows. A bounded
root window shows dense SSB/NZP-CSI logging immediately before and through the
deadline break.

This does not yet prove logging is the cause, but buffered logger/filesystem
flush pressure is now a specific discriminator that matches a periodic,
run-variable host-side stall better than a fixed RF or timestamp offset.
Soapy INFO must remain enabled because it carries the authoritative TX health
summaries; only the generated gNB YAML verbosity should change.

## Decision

that changes only generated `log.all_level` from `info` to `warning`, while
retaining Soapy INFO summaries, then repeat one 420-second gNB-only
discriminator. OTA remains locked.
