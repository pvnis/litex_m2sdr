# CP3364: gNB Log-Warning Long Gate

## Verdict

**PASS (bounded RF, gNB only).** With the exact CP3362 8.5 ms lead and 500 us
deadline reservation retained, changing only the generated gNB application
log level from `info` to `warning` removes the complete 420-second deadline
failure signature.

All 4,838,353,770 requested samples return. Deadline breaks, abandoned
samples, stream/data deficits, actual write timeouts, partial returns,
worker/release/downlink late events, and errors are all zero.

The wrapper exits 1 only because this gate deliberately never starts the UE;
its authoritative startup, readback, late-health, stop-summary, packaging, and
cleanup gates pass.

## Evidence

CP3362's binary-safe application mirror contains 20,683,627 bytes and 157,358
logical rows, including 154,575 per-slot PHY INFO rows. CP3364 reduces that
mirror to 15,266 bytes and 70 logical rows with zero PHY INFO rows.

The independent Soapy log remains effectively unchanged in size and retains
4,734 worker-period rows, 4,734 release-period rows, 41 Soapy period rows, and
the authoritative stop row. The result therefore does not come from hiding
health telemetry.

At the same timing policy, CP3362 recorded 25 guard-only deadline breaks,
169,448 abandoned stream samples, and 24,062 data-sample deficit. CP3364
records zero for every one of those counters. Host realtime-state gates pass,
and post-run cleanup leaves no gNB process and no private user-plane socket.

This controlled result strongly supports buffered per-slot application logging
as the periodic lead-consumption mechanism. Because it is one clean roll, the
claim that the timing lottery is eliminated remains provisional until the
promoted OTA run and later repeats remain clean.
