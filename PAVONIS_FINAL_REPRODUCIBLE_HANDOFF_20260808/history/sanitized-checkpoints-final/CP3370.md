# CP3370: period-10000 MCS16 OTA benchmark

## Verdict

**PASS, PARTIAL PARITY.** The qualified warning-level, period-10000 TX shape
completes attach and sustained bidirectional data with clean unique TX stream
continuity. Uplink reaches `8.028467 Mbit/s`, more than twice CP3322's
`3.692189 Mbit/s`, but remains only `51.88%` of the CP3324 ZMQ MCS16 result.

This run does not contain sustained scheduler debug rows because the gNB
application log is deliberately held at warning level. No scheduler-to-PUSCH
latency is claimed from the startup-only trace.

The lower downlink result is a weak-roll datapoint, not a new downlink ceiling:
cell SNR and accepted-PUSCH SINR are materially below CP3322. Both endpoint
JSON files nevertheless complete for the full four-stream, 45-second interval
in each direction.

The single 480-sample call-level partial is fully recovered by OCUDU's
`sent_total += ret` retry loop. It is not a unique RF-stream deficit.

Runtime strings and the separate gNB log prove worker and release
`period=10000`; the log contains 475 worker and 475 release summary rows,
zero rows with nonzero late count, and is only 1,267,679 bytes. This is the
second clean long-duration result for the reduced-telemetry policy after
CP3368.

## Comparison

| Run | MCS16 uplink |
| --- | ---: |
| CP3322 M2SDR, 20 ms lead | 3.692189 Mbit/s |
| CP3370 M2SDR, 8.5 ms lead | 8.028467 Mbit/s |
| CP3324 ZMQ | 15.475241 Mbit/s |

The hardware result improves `117.44%` over CP3322. This supports the
hardware-timeline/HARQ-lifetime diagnosis, but does not close it: approximately
half the ZMQ capacity is still missing.

## Decision

Use the newly qualified warning-level and period-10000 telemetry policy to
retest a lower TX lead. Gate the exact candidate for 420 seconds with no UE
before spending another OTA benchmark. Keep coherent PRACH and non-PRACH
timing constants retimed with the lead. Do not change MCS, grant size, RF
power, ring depth, or traffic shape at the same time.
