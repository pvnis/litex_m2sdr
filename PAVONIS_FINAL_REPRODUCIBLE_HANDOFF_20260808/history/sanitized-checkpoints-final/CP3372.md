# Checkpoint 3372: Coherent Timeline v2 Rejected

Date: [date-redacted] UTC

## Verdict

**REJECTED_MECHANISM.** The bounded 420-second gNB-only gate activated the
CP3371 coherent-timeline v2 exactly as designed, but it destroyed TX queue
headroom. The run abandoned 2,556,008,120 unique stream samples through
221,952 deadline-guard breaks. There were zero actual Soapy write timeouts,
zero downlink-late lines, zero partial returns, and zero hard errors.

No UE was started. This is a transmitter continuity verdict, not an RF,
acquisition, PRACH, RAR, PUSCH, or throughput datapoint.

## Runtime Shape

The live candidate binary was
`56ba736484d574b16becfb0235c0263d70f7f7c1e1df9054f35561451cdad897`.
Its runtime marker proved:

- scheduler offset: 10,000,000 ns;
- OCUDU TX metadata offset: +10,000,000 ns;
- M2SDR physical TX lead: +8,500,000 ns;
- RX metadata offset: -18,500,000 ns;
- PRACH compensation: 6,936 samples;
- static non-PRACH shifts: -27,998 / -24,678 samples;
- dynamic edge calibration: -6,932 samples, scheduler term zero;
- worker and release summary periods: 10,000 packets.

The stream processed 4,838,342,250 nominal samples, approximately the intended
420 seconds at 11.52 Msps. Of 2,509,165,354 samples offered to Soapy after
deadline gating, 2,282,334,130 were returned. The guard abandoned
2,556,008,120 stream samples before they could become valid timed writes.

## Comparison

CP3370 ran the same physical 8.5 ms lead and reduced-telemetry policy through a
full OTA data session with 4,838,330,730 stream samples returned and no unique
stream deficit, deadline break, actual write timeout, late write, or error.
CP3372 changed the logical clock mechanism and immediately produced:

| Metric | CP3370 | CP3372 |
|---|---:|---:|
| Stream deficit | 0 | 2,556,008,120 |
| Deadline-guard breaks | 0 | 221,952 |
| Actual deadline write timeouts | 0 | 0 |
| Soapy timeout log lines | 0 | 0 |
| Downlink-late lines | 0 | 0 |

The generic `timeouts=221952` stop-summary field is derived from deadline
breaks in this path. It must not be read as 221,952 Soapy timeout returns.

## Mechanical Finding

The CP3371 arithmetic assumed TX scheduling was anchored only by
`read_current_time()`. The live lower PHY is also driven continuously by RX
metadata. v2 presented received samples at:

`H - (10.0 ms scheduler offset + 8.5 ms physical lead)`

The lower PHY then generated TX work from that retarded RX timeline. OCUDU
added 10 ms to TX metadata and the M2SDR driver added 8.5 ms, yielding a
physical deadline near `H`, not `H + 8.5 ms`. The 500 us guard therefore
rejected a large fraction of buffers before any Soapy timeout could occur.

This generalizes the earlier CP3327 lesson: a global RX-clock translation
cannot preserve physical queue lead in an RX-driven lower-PHY loop. Do not
retry v2, [interface-redacted] its constants, or use another paired RX/TX clock shift.

## Restoration

The active RF-host source and gNB were restored from the complete CP3371
rollback before further work. All eight source/test hashes match the recorded
qualified versions. The live gNB is again:

`1f7fd4702de1993563de0c11bb14c71a5ac6b226b9b4e241229bdcbc0a0f2205`

The restored binary contains zero coherent-v2 markers. The controller copy of
the v2 source remains only for forensic comparison and is not deployed.

## Decision

Keep the qualified radio timeline, dynamic physical-latency compensation, and
8.5 ms queue lead. The remaining fixed 10 ms term must be traced through UL
allocation, symbol processing, result attribution, and scheduler delivery.
Any next patch should change that scheduler/PHY handoff without translating
the radio clock.

The recollection that a USB/non-M2 LiteX SDR previously achieved normal
bidirectional throughput is recorded only as external qualitative context. It
is not a Pavonis checkpoint result and will not be used as proof.
