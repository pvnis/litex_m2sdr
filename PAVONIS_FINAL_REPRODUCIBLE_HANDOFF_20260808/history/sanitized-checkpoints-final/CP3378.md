# CP3378 - Native PRACH residual MCS16 OTA

## Verdict

**VALID PARTIAL: RAR HANDOFF FAILURE.** The 97,764-sample correction restores
live Msg1 supply. Seven stage-1 selections produce accepted PRACH results, the
gNB schedules and encodes ten RARs, and the seven RAR slots that overlap the
UE's RA windows all decode RA-PDCCH with CRC OK. The UE nevertheless records no
RAR PDSCH grant, no RAR acceptance, and no Msg3 preparation.

This closes native PRACH collection as the current blocker. No timing,
threshold, payload, gain, or RF setting should be changed before tracing the
CRC-OK DCI handoff.

## Evidence

- Live propagation: all 64 bounded strong-window rows carry collection and
  timing compensation 97,764.
- Access: cell/SIB1 pass at 7.028 dB and -3998.034 Hz; seven UE PRACH
  transmissions; 2,614 stage-1 rows with seven selections; 17 detector
  accepted rows.
- gNB RAR supply: ten scheduler allocations, ten RAR PDCCH/PDSCH FAPI pairs,
  and ten encoded MAC PDUs.
- UE RA search: 91 candidate rows across seven 13-slot windows.
- Exact slot join: seven of the gNB RAR slots fall in those UE windows; all
  seven use the matching RA-RNTI, report `n_dl=1`, attempt candidate zero, and
  pass its CRC.
- Joined quality is not marginal: correlation 0.958694-0.972014 and EPRE
  25.219-26.341.
- UE downstream counts remain zero for RAR PDSCH grant, MAC RAR acceptance,
  timing advance, Msg3 preparation, and PUSCH encode.

The other three gNB RAR rows occur outside the seven recorded UE RA windows
and are not used to judge UE decode.

## TX Health

The full run is mechanically clean: 4,818,193,770 unique stream samples equal
returned samples, with zero stream deficit, deadline break, actual write

No throughput result exists because access stopped before Msg3.

## No-RF Source Audit

After `srsran_ue_dl_nr_find_dl_dci()` returns the CRC-OK RA DCI,
`cc_worker::decode_pdcch_dl()` calls `state::set_dl_pending_grant()`. That path
converts DCI to PDSCH, computes the ACK resource, stores the pending grant, and
`decode_pdsch_dl()` retrieves it before MAC/PDSCH processing in the same
worker. The deployed source already has default-off, metadata-only markers at:

1. decoded RA DCI;
2. pending grant set;
3. pending grant get;
4. RA PDSCH grant and MAC action;
5. PDSCH decode and MAC TB dispatch.

The next run should enable only `PAVONIS_SRSUE_RAR_PATH_TRACE` with a small
limit. It requires no rebuild and will name the first missing boundary.
