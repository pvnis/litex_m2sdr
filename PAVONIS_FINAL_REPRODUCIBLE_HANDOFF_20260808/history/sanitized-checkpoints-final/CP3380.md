## Verdict

**TRACE AXIS VOID: PROPAGATION FAILURE.** Two attempts were made under the
standing single-void retry rule.

The first attempt (`[date-redacted]`) never started the UE because the
pre-UE TX health gate correctly rejected eight deadline breaks and 74,786
missing stream samples. It is void for all radio and trace questions.

The unchanged retry (`[date-redacted]`) is a valid radio partial but void for

Zero path rows therefore say nothing about the post-DCI boundary.

- Seven UE PRACH transmissions and seven stage-1 selections.
- Thirteen gNB RAR PDUs; seven fall inside the UE's seven RA windows.
- All seven joined slots use the matching RA-RNTI, report `n_dl=1`, attempt
  decode, and pass CRC.
- Joined correlation is 0.949197-0.963427; EPRE is 25.016-25.358.
- UE RAR acceptance and Msg3 remain zero.
- The live manifest carries PRACH 97,764 on all 64 rows.
- Later in the long no-access run, TX records three deadline breaks and
  15,142 missing stream samples. No throughput or clean-health result exists.

This is the second consecutive reproduction of the CP3378 RAR handoff
signature, but it does not answer which post-DCI call fails.

## Propagation Audit

The Python controller preserves the caller environment, and the Stage 6
wrapper exports the path trace into the UE-start helper. The final helper then
reconstructs explicit environment lists and manifests in four places:

1. generated runner `sudo env`;
2. generated runner result manifest;
3. outer `nohup env`;
4. outer launch manifest.

It forwarded RAR trace and RAR candidate-trace controls in all four places,
but not the RAR path-trace controls. CP3381 adds only the same default-off
passthrough pair beside those existing controls.
