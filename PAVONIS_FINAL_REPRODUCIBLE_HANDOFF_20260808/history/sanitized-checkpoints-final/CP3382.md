# CP3382 - RAR reaches UE MAC TB dispatch

## Verdict

**VALID PARTIAL.** The native-timeline radio path remains healthy through
Msg1, gNB RAR scheduling, UE RAR PDCCH, UE RAR PDSCH CRC, and UE MAC TB
dispatch. Seven of seven traced RAR transport blocks report CRC OK, current
RA-RNTI match, and `dispatch_rar=1`. No RAR acceptance or Msg3 follows.

This moves the first missing boundary from PHY/MAC handoff into the deferred
RA procedure. The absence of the older detailed RAR rows is not evidence that
the callback was skipped: that trace buffers until `atexit`, while the bounded
runner ends `srsue` with signals and does not guarantee the flush.

## Evidence

- Cell acquisition and SIB1 pass at `9.829 dB`; CFO is `-4072.892 Hz`.
- UE transmits seven PRACH preambles; stage 1 selects seven of 2,606 rows.
- The gNB schedules and encodes thirteen RARs.
- The immediate UE path trace records seven complete paths:
  `ra_pdcch_dci` -> `dl_pending_set/get` -> `ra_pdsch_grant` ->
  `ra_mac_action` -> `ra_pdsch_decode` -> `mac_tb_decoded`.
- All seven `mac_tb_decoded` rows have CRC OK, payload present, matching
  current RA-RNTI, and RAR dispatch selected.
- There are no Msg3 preparation or PUSCH encode events.
- TX health is clean across `4,818,101,610` requested/returned samples:
  zero deficit, timestamp breaks, timeouts, downlink-late events, partial
  returns, or errors.

The live path-trace cap is `1200` despite the runner requesting `256`. This
propagation mismatch is recorded but does not invalidate the result: only
49 bounded event rows were emitted.

## No-RF Audit

`mac_nr::tb_decoded()` calls `proc_ra.handle_rar_pdu()` for the exact traced
condition. `handle_rar_pdu()` defers `ra_response_reception()` onto the MAC
task queue. The latter's detailed trace uses an in-memory vector registered
with `atexit`; the bounded UE script later sends `TERM` and then `KILL`.
Consequently, zero detailed rows cannot distinguish queue delay, RA-state
rejection, unpack failure, RAPID mismatch, or successful Msg3 setup.

The next checkpoint will add default-off, capped, immediate, metadata-only
path markers at those boundaries. It will not log payload bytes and will not
change radio, timing, threshold, scheduler, or protocol behavior.
