# CP3387 - Measured non-PRACH alignment candidate gated

## Verdict

**PASS, NO RF.** A fresh CP3388 runner is gated with the sole runtime alignment
change measured by CP3386: edge calibration moves from `-104852` to `-97760`
samples. PRACH collection, RAR behavior, RF levels, stage-1 policy, CFO,
scheduler settings, and the MCS16 profile remain frozen.

## Proof

- Both shell files pass `bash -n`.
- Controller validation passes with 23 stage-1 candidates, limit 30,
  PRACH collection 97764, guard delta 16000, independent compensation enabled,
  sticky accepted candidate enabled, and scheduler error zero.
- The default RF gate exits 2 with `CP3388_RF_GATE=CLOSED`.
- A nested-shell override test starts from the legacy bad values and resolves
  to calibration `-97760`, UL symbol dump unset, raw max zero, Msg3 target
  capture zero, strong predemod capture zero, and metadata-only mode one.
- Normalized comparison with CP3386 changes the calibration and removes the
  raw capture only. All ladder-shape values remain byte-identical.

The raw capture is deliberately disabled because CP3386 has already answered
the sample-placement question. Immediate capped RAR-path metadata stays on so
the next run can distinguish a Msg3 CRC result from a pre-PUSCH void.

## Next Step

Run CP3388 once with a fresh stamp. Judge health, then cell/SIB1, PRACH/RAR,
gNB Msg3 CRC, attach, and sustained traffic in that order. A no-RAR roll is a
void retry; a RAR plus CRC KO rejects the measured calibration.
