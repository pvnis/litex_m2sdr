# CP3388 - Measured calibration filtered by the gNB launcher

## Verdict

**VOID FOR CALIBRATION JUDGMENT.** The radio run is otherwise valid and
RAR-bearing, but the intended `-97760` edge calibration did not reach the gNB.
The live configuration remained `-104852`, so the 65 PUSCH CRC failures only
repeat the already-known old-offset behavior and do not test CP3386.

## Evidence

- Cell/SIB1 passes at `10.614 dB`; seven PRACH transmissions yield seven
  stage-1 selections and thirteen gNB RAR allocations.
- Seven CRC-OK RAR transport blocks reach UE MAC dispatch.
- The gNB records 65 eleven-byte PUSCH results, all CRC KO.
- TX health is fully clean: zero timeout lines, downlink-late rows, deadline
  breaks, sample deficits, partial returns, and hard errors.
- The no-capture shape propagated: zero strong predemod files, shifted target
  files, UL symbol manifest rows, and UL raw files.
- The live gNB config row states `edge_calibration=-104852`, and all dynamic
  publish rows are the old `-104430/-104424/-104432` class.

The immediate cause is the hash-pinned CP3377 gNB launcher. It defines
`EDGE_CALIBRATION_SAMPLES=-104852` and exports that value after the
controller-side environment has been processed. CP3387's nested-shell proof
validated the wrapper layer but could not override this final launcher
assignment.

## Next Step

Create an isolated CP3389 launcher from the exact CP3377 source, changing only
the hard-coded calibration to `-97760`. Hash-pin and deploy it, run its
validate-only path, and prove its runtime-export marker before preparing the
next RF runner. No source build or radio/config change is needed.
