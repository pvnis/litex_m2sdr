# CP3390 - Corrected M2SDR timeline reaches attach and sustained data

## Verdict

**VALID ATTACH AND USER-DATA MILESTONE; THROUGHPUT PARTIAL ON STRICT TX
HEALTH.** The measured non-PRACH correction works. The live gNB uses edge
calibration `-97760`, publishes dynamic offset `-97332`, decodes 128/128
traced PUSCH results, attaches, and completes both sustained traffic
directions. The outer runner returns 1 only because the strict final TX stop
summary records 20 deadline breaks and sample deficit; the traffic artifacts
and analysis themselves pass.

## Timing And PHY Payoff

- Live config proves edge calibration `-97760`.
- The first PRACH edge publishes dynamic offset `-97332`, inside CP3386's
  predicted `-97337 .. -97336` class within five samples.
- One PRACH and one stage-1 selection are sufficient for access.
- All 128 capped PUSCH result rows are CRC OK.
- Median CRC-OK PUSCH SINR is `21.607 dB`; median TBS is `528 B`.

This is the direct A/B against CP3388's filtered old value, where 65/65
eleven-byte PUSCH rows were CRC KO. The 7092-sample correction changes the
same stack from no Msg3 decode to a stable data session.

## Sustained Throughput

The passing analysis uses four parallel TCP streams for 45 seconds in each
direction, with receiver-side byte counts:

| Path | CP3390 M2SDR | CP3324 ZMQ MCS16 | ZMQ share |
| --- | ---: | ---: | ---: |
| Downlink | `7.059 Mbit/s` | `7.600 Mbit/s` | `92.89%` |
| Uplink | `12.614 Mbit/s` | `15.475 Mbit/s` | `81.51%` |

Against the earlier clean CP3322 M2SDR result, this is `2.21x` downlink and
`3.42x` uplink. The hardware path is now in the same throughput class as ZMQ,
but a clean-health repeat is required before treating these as the final
authoritative numbers.

## Health Qualification

The final TX summary has zero log-level timeout lines, zero downlink-late
rows, zero partial returns, and zero hard errors, but records:

- 20 deadline breaks;
- 19,696 returned-sample deficit;
- 132,288 stream deficit.

That fails `gate_authoritative_tx_stop_summary`, producing the outer rc 1.
Both traffic result files are ready and fetched, and `sustained_analysis.json`
passes. The correct classification is therefore valid attach/data and
provisional throughput, not a failed radio run and not a clean baseline.
