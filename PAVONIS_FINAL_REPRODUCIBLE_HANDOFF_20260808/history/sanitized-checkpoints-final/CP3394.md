# CP3394 - Corrected-timing MCS28 no-RF gate

## Verdict

**PASS.** A separate, hash-pinned MCS28 branch is ready for one bounded OTA
measurement. It preserves the CP3393 M2SDR timing and benchmark shape and
changes only the explicit PUSCH maximum from MCS16 to MCS28.

The historical default-MCS28 CP3314 result remains a control, not evidence
from a USB LiteX device. CP3314 ran before the CP3386 sample-domain correction
and achieved only `0.431181 Mbit/s` uplink with unreliable 64QAM. CP3390 and
CP3393 now provide a materially different premise: corrected timing,
`127-128/128` PUSCH CRC success, and about `21 dB` accepted PUSCH SINR.

## Evidence

- The new config generator explicitly creates exactly one
  `cell_cfg.pusch.max_ue_mcs: 28` block and changes application logging from
  info to warning.
- The PDSCH maximum remains 9. This checkpoint does not change downlink MCS.
- The corrected launcher retains:
  - TX lead `8.5 ms`;
  - PRACH compensation `97764` samples;
  - non-PRACH static shifts `-125918/-122598`;
  - edge calibration `-97760`;
  - edge scheduler error `0`;
  - deadline guard `500 us`;
  - summary period `10000`.
- Its exported runtime control lines are byte-equal to CP3389.
- The 23-point PRACH candidate list is byte-equal to CP3390.
- Remote dependency/hash validation passes against the qualified gNB binary.
- A fresh config-only invocation proves one MCS28 block, warning logging, and
  no info-level application logging.
- Controller validation passes with 23 candidates, four streams, 45 seconds
  per direction, and independent PRACH compensation.
- The RF gate is default-closed with exit code 2.

No existing launcher or baseline was edited. In particular, the CP3389 MCS16
launcher, CP3314 control, and CP3390/CP3393 artifacts remain unchanged.

## Next

Run CP3395 once with a fresh stamp. Judge in this order:

1. pre-UE and final TX deadline health;
2. live marker plus packaged config proof that MCS28 reached the gNB;
3. attach and private data;
4. PUSCH modulation, CRC ratio, SINR, TBS, and grant cadence;
5. sustained DL/UL against CP3214 ZMQ MCS28 and CP3324 ZMQ MCS16.

A pre-access or pre-UE-health run is void. A valid MCS28 run that lowers
delivered throughput is still decisive and retires MCS28 for this RF path.
