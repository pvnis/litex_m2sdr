# CP3397 - Corrected-timing MCS19 no-RF gate

## Verdict

**PASS.** A separate explicit-MCS19 branch is ready for one bounded OTA
measurement. The corrected MCS16 fallback and rejected MCS28 branch remain
unchanged.

## Rationale

OCUDU's table maps MCS16 to 16QAM with rate numerator 658, MCS19 to 64QAM with
517, and MCS28 to 64QAM with 948. MCS19 therefore has about `1.1786x` MCS16's
nominal spectral efficiency, closely matching the remaining MCS16-to-ZMQ gap,
while its target code rate is only `0.5049`.

This is not a sweep or a threshold relaxation. It is one isolated policy
sensitivity earned by CP3396's finding that MCS28's `0.9258` code rate adds
CRC loss without sustained payload benefit.

## Evidence

- The config generator writes exactly one explicit PUSCH MCS19 block.
- PDSCH remains capped at MCS9.
- Runtime exports are byte-equal to CP3394.
- The runner's common environment and 23-point PRACH list are byte-equal to
  the MCS28 runner.
- TX lead, PRACH compensation, non-PRACH timing, edge calibration, deadline
  guard, summary periods, RF gain/attenuation, traffic duration, and stream
  count are unchanged.
- Local syntax and normalized-control comparisons pass.
- Deployed dependency, launcher, and qualified-gNB hashes pass.
- Fresh remote config-only generation proves one MCS19 block, warning logging,
  and no info logging.
- Controller validate-only returns 0.
- RF remains default-closed with exit code 2.

## Next

private data, then report sustained DL/UL and the bounded modulation/CRC/TBS

improves on corrected MCS16 without a material reliability regression.
