# CP3401 - Pre-UE deadline-regime forensics

## Verdict

**GUARD-ONLY ABANDON POLICY IDENTIFIED.** All 19 recent deadline breaks occur
while the requested timed write is still in the future. OCUDU's 500 us
reservation converts a positive 198-498 us raw lead into a negative guarded
lead and abandons the unwritten logical remainder before calling
`writeStream`.

This is above the LiteX driver and independent of MCS policy.

## Evidence

The join covers clean CP3391/CP3399 and failed CP3392/CP3395/CP3398/CP3400.

Across all 19 break events:

- metadata timestamp delta: exactly `11520` samples;
- logical data size: exactly `11520` samples;
- raw lead: `198..498 us`, median `433 us`;
- configured guard: `500 us`;
- guarded lead: `-302..-2 us`, median `-67 us`;
- entry gap: `91..1967 us`, median `1579 us`;
- five events abandon before sending any sample.

The failures appear in a single cumulative 10-second bucket at run ages near
10, 20, 30, or 60 seconds. Clean runs remain zero-deficit for longer, so this
is a phase/jitter lottery rather than sustained overload.

The class does not split on:

- CPU governor or EPP;
- package temperature;
- PCIe link/power state;
- LiteX worker late, underflow, or acquire errors;
- release dedup, post-late, or driver-level late counts.

All of those driver error counters are zero in both classes. Driver slip
counters are nonzero in clean and failed runs and are not the discriminator.

Source confirms the behavior. OCUDU computes:

```text
guarded_lead_us = raw_lead_us - guard_us
```

When that is nonpositive, it returns `-1` without a device write, marks the
deadline expired, and abandons the remainder. Thus every current break is
policy-induced even though the hardware deadline has not passed.

## Decision

Do not add lead or retune UL offsets. Test the existing policy with the sole
change `500 us -> 100 us` at the same 8.5 ms lead. On the 19 measured events,
that projects a positive `98..398 us` write budget.

First gate it in a 420-second gNB-only run. Acceptance requires zero:

- deadline breaks/timeouts and sample deficits;
- partial returns and hard errors;
- LiteX late/underflow/acquire errors;
- release late/dedup and downlink-late lines.

Only a clean gate unlocks another MCS19 ladder run. A failure below 100 us
would reject the constant and motivate a source-level immediate-write attempt
inside the reservation instead of further guard [interface-redacted].
