# CP3403 - Guard-100 long-gate setup void

## Verdict

**SETUP VOID.** The guard-100 candidate was live and clean during the short
transmit interval, but the planned 420-second mechanism gate did not run.

The failure is a stale wrapper expectation, not a deadline event and not a
radio result.

## Evidence

The live TX readback proves:

- deadline-aware writes enabled;
- deadline guard `100 us`;
- maximum selected timeout `50000 us`;
- TX lead `8500000 ns`;
- all chunks timed;
- one CS16 TX channel at the frozen rate and gain.

The stop summary covers about `2.651 s` and is perfectly balanced:

- requested and returned samples: `30527850`;
- deadline breaks and timeouts: zero;
- write and stream deficits: zero;
- partial returns and hard errors: zero;
- driver-late and downlink-late events: zero.

The wrapper exited before its 420-second stop-before-UE dwell because its
inherited stage-expectation file reasserted the old `500 us` guard. The
qualified launcher then correctly applied `100 us` to the actual gNB process.
The readback gate compared live `100` against stale expected `500` and returned
one. The UE never started.

## Decision

Do not interpret the clean 2.651-second prefix as acceptance. Pin a copied
stage-expectation file whose only delta is `500 -> 100`, validate that the
wrapper marker, remote environment, launcher marker, and live readback all say
`100`, then repeat the exact transmit-only gate with a fresh identifier.
