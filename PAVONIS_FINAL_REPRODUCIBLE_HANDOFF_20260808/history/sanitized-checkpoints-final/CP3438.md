# CP3438 - 15 MHz pre-UE readback-gate voids

## Verdict

**VOID.** Two fresh-stamp attempts stopped at the same native-TX readback
proof before the UE was started. They provide no cell-acquisition, PHY, or
throughput evidence about 15 MHz.

Each stop summary contains one `430`-sample partial return, fully recovered
before stream accounting; neither run lost stream samples.

## Forensics

The second attempt has exactly one matching run directory and a present
`TX_READY.env`. The captured TX readback contains every value required by the
original gate:

- continuous, all-timed CS16 mode;
- `15.36 Msps`;
- `11 ms` TX time offset;
- deadline writes enabled with `100 us` inside-guard policy;
- zero retry/carry modes;
- the requested `5 dB` TX gain.

The original key assertions, gain assertion, and complete gate command all
pass when replayed after publication. The immediate wrapper invocation fails
without producing assertion output in both attempts.

This is a reproducible proof-timing race: the start helper publishes readiness
before the readback proof is reliably consumable by the immediate gate.

## Decision

CP3439 isolates the remedy in a copied runner: wait a bounded two seconds
after successful gNB startup, emit start/done markers, then execute the
unchanged readback assertions. The historical CP3186 runner and the proven
baseline remain untouched.

The next RF attempt is CP3440 after CP3439's no-RF syntax, hash, normalized
diff, validation, and default-closed gates pass.
