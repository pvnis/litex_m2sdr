# CP3442 - 15 MHz pre-UE TX-headroom failure

## Verdict

**VALID PRE-UE TX-HEALTH FAILURE.** The CP3441 proof fix works live: the
native-TX readback gate passes with the correct `100 us` guard. The run then
fails the strict 60-second pre-UE TX-summary gate, which correctly suppresses
UE startup.

This is the first non-tooling result on the current 15 MHz stack.

## TX Health

| Metric | Result |
|---|---:|
| Pre-UE window | `60 s` |
| Soapy summary timeouts | `3` |
| Downlink-late lines | `0` |
| Deadline-write breaks | `3` |
| Abandoned/stream-deficit samples | `33816` |
| Hard errors | `0` |

The 15 MHz profile at the current `11 ms` lead is not acceptable under the
same zero-deficit gate used for the proven 10 MHz baseline.

## Break Trace

The binary-safe event trace contains exactly three events, matching the stop
summary:

| Event | Entry gap | Raw lead | Guarded lead | Abandoned samples |
|---:|---:|---:|---:|---:|
| 0 | `1887 us` | `-30 us` | `-130 us` | `3096` |
| 1 | `1911 us` | `-43 us` | `-143 us` | `15360` |
| 2 | `2229 us` | `-228 us` | `-328 us` | `15360` |

The event sum is exactly `33816` samples. These are short producer-entry
latency bursts that consume the timing cushion; the stream is otherwise
stable for the rest of the minute. This is not evidence that the transport
cannot sustain `15.36 Msps` continuously.

## Decision

Derive one conservative timing-headroom gate:

- increase TX lead from `11 ms` to `13 ms`;
- keep sample rate, RF, MCS, scheduler, deadline guard, and timeout policy
  unchanged;
- first run a 60-second gNB-only strict TX-health gate;
- unlock a UE throughput run only on zero timeout, break, abandoned, and
  stream-deficit counts.

MIMO remains parked until the bandwidth/headroom dependency is resolved.
