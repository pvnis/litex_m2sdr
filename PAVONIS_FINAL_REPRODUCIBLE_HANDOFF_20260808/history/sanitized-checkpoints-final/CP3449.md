# CP3449 - Retiming attempt is a configuration void

## Verdict

Configuration void. The controller records the CP3448 coherent timing values,
but the hardware-facing gNB launcher overwrites them with the CP3443 values.
The RF result does not test the retiming hypothesis.

## Evidence

- Controller intent records PRACH `199472`, non-PRACH `-198611/-194184`, and
  edge calibration `-199467`.
- The packaged hardware PRACH manifest records both collection delay and timing
  compensation as `168752`.
- Source audit finds the exact overwrite: the deployed CP3443 launcher assigns
  and unconditionally exports `168752/-167891/-163464/-168747` after the
  controller environment is established.
- Cell/SFN/SIB1 pass and seven Msg1 attempts again produce no accept/RAR, but
  that observation is the stale CP3445/CP3447 shape and is not new evidence.
- TX delivery is clean: zero deadline break, timeout, stream deficit,
  downlink-late event, or hard error.

## Decision

Do not interpret this as a retiming failure. Replace the hard-coded launcher
with a new hash-pinned copy containing the coherent constants. Before RF,
require local syntax, remote hash, remote validate marker, controller
validate-only, and default-closed proofs. The subsequent run must verify the
packaged runtime manifest before interpreting Msg1.
