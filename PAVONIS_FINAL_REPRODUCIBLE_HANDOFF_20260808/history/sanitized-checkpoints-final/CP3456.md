# CP3456 - Caller-preserving PDSCH MCS chain

## Verdict

PASS, no RF. The inherited PDSCH9 wrapper no longer overwrites an explicit
caller value, while its default remains 9.

## Change

The 22-file baseline chain is copied. Only three chain files differ:

1. `cp2343_run_pdsch_max_ue_mcs9.sh` changes its unconditional export to
   caller-preserving/default9 behavior.
2. The top runner points to the copied chain.
3. The retime layer points to the copied final stage runner.

The proven baseline chain, gNB source, and gNB binary are untouched.

## Proofs

- All copied shell files parse and the controller compiles.
- A default-off probe runs through the complete chain and exits at the final
  stage before host or RF work.
- With no caller, the full chain reports `GNB_MAX_UE_MCS=9`.
- With the CP3457 caller, the full chain reports `GNB_MAX_UE_MCS=7`.
- No downstream chain file assigns the variable again.
- Controller validation passes at MCS7 with 23 stage-1 candidates.
- The RF wrapper remains default-closed with rc2 and no result directory.

## Decision

Run one CP3457 attempt. It is interpretable only if both packaged gNB configs
contain PDSCH7 and the connected UE trace contains no MCS above 7. This
explicitly closes the CP3455 propagation failure before judging PHY or
throughput.
