# CP3460 - Isolated 10 MHz 2x2 MIMO gate, no RF

## Verdict

**PASS.** An additive two-antenna overlay on the proven 10 MHz shape passes
OCUDU dry-run validation locally and on the deployed gNB stack. The existing
single-channel baseline is unchanged.

No RF was transmitted. No source, binary, kernel, module, FPGA, gateware,
subscriber, or phone state was changed.

## Isolated shape

- Bandwidth: 10 MHz.
- Downlink and uplink antenna count: 2.
- PDSCH ceiling: 9.
- PUSCH ceiling: 19.
- TX lead: 11 ms.
- Deadline guard: 100 us, inside-guard policy.
- Soapy physical channel offset: 0, required for logical channels `{0,1}`.
- UE start: disabled for the first execution gate.

The 2x2 change is a separate overlay. It does not edit the CP3424 config or
the CP3422 launcher. The new launcher hash-pins both and appends the overlay.

## Proofs

The local gNB accepts the exact base plus overlay with `--dryrun`. The same
launcher and overlay were deployed with matching SHA-256 values. On the RF
host, the wrapper validates the frozen CP3422 MCS19/lead11 launcher, generates
the expected MCS19 config, appends the 2x2 overlay, and exits cleanly under
`--dryrun`.

The CP3461 execution runner passes controller validation and exits `2` with
`CP3461_RF_GATE=CLOSED` by default.

## Interpretation

This proves the configuration and launcher path, not real-time delivery. The
next run is deliberately gNB-only: it must prove that the M2SDR opens two RX
and two TX channels and can sustain the doubled aggregate sample payload
without deadline breaks, abandoned samples, short non-EOB descriptors, late
headers, or stream deficit. A failure closes the current 2x2 path at producer
capacity and feeds the producer-headroom branch directly. A clean result
unlocks one isolated real-phone rank-2 attempt.
