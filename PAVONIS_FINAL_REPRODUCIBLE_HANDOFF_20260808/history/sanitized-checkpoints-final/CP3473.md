# CP3473 - Same-run MCS9/MCS10 discriminator no-RF gate

## Verdict

**PASS.** The default-off OCUDU selector is inert when disabled and produces a
perfectly balanced, cleanly decoded MCS9/MCS10 sequence over ZMQ when enabled.
No SDR was opened and no RF was transmitted.

This unlocks one bounded M2SDR discriminator. It does not itself explain the
hardware-path downlink ceiling.

## Diagnostic

The minimal scheduler diagnostic is in
`ocudu/lib/scheduler/ue_scheduling/ue_cell_grid_allocator.cpp` at source hash
`6b131584...afeb7`. Its configuration is read once from the environment. When
enabled, it alternates only new PDSCH transmissions between MCS9 and MCS10;
HARQ retransmissions retain the original transmission's MCS. Its metadata trace
is row-capped and the standards-default disabled path does not change MCS.

The source builds locally under `-Werror`. The first deployed copy is an honest
void: it was linked against a different major crypto-runtime ABI and the gNB
never started. That run reached no cell, selector row, or scheduler result. A
native build on the core/gNB host then passed with all available build cores,
linked against the installed ABI, and restored the host source byte-for-byte
after producing the isolated diagnostic binary.

## Disabled Control

The exact 10 MHz ZMQ chain passes 30 seconds in each direction with:

| Metric | Result |
|---|---:|
| Selector startup markers | 0 |
| Selector rows | 0 |
| Receiver DL | 14.914756 Mbit/s |
| Receiver UL | 14.999357 Mbit/s |

This proves the cached disabled branch is behaviorally inert in a full
attach-and-data run.

## Enabled Control

The only runtime change is enabling `MCS_A=9`, `MCS_B=10`, and one-grant
alternation. The bounded selector trace contains exactly `1,024` rows for each
MCS. The existing scheduler parser then measures the full active interval:

| Metric | Result |
|---|---:|
| Active new transmissions | 29,226 |
| MCS9 / MCS10 new transmissions | 14,613 / 14,613 |
| Retransmissions | 0 |
| Median allocation | 52 PRBs, 1,089 bytes |
| Scheduled-slot utilization | 97.42% |
| Scheduled new-data rate | 8.128779 Mbit/s |
| Receiver DL | 7.748855 Mbit/s |
| Receiver UL | 15.957607 Mbit/s |

MCS9 and MCS10 intentionally have the same TBS at this full-band geometry, so
the roughly 8 Mbit/s downlink is expected. Zero retransmissions across equal
populations proves both branches decode cleanly in the no-radio control.

The older ZMQ UE binary does not contain the optional C-RNTI PDSCH trace, so
that axis has zero rows. It is not used for the verdict: the gNB selector trace,
scheduler newTx/RV counts, and receiver-authoritative endpoint result are
jointly sufficient here. The hardware run must separately prove its deployed
UE trace before using UE-side CRC counts.

## Decision

Run one bounded same-run discriminator on the frozen `10 MHz`, one-layer M2SDR
profile. Require exact selector propagation, balanced MCS9/MCS10 supply,
UE-side per-MCS RV0 CRC counts, normal attach/traffic health, and strict TX
health. This within-run comparison removes the channel/run confounds in the old
cross-run archives. Bandwidth, further MIMO, and producer-stall work remain
locked until that verdict.
