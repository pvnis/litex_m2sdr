# Checkpoint 3483: 15 MHz ATT0 pre-RF hash void

## Verdict

**EXECUTION VOID, NO RF: not a bandwidth or access datapoint.** The inherited
15 MHz launcher rejected the currently deployed gNB binary before Soapy opened.

## Evidence

- gNB log: exactly one line, `CP3450_BASE_GNB_HASH_MISMATCH`.
- gNB start step: timeout rc124 waiting for a process that the launcher refused
  to execute.
- Soapy TX readback: absent.
- Authoritative TX stop summary: absent.
- UE process/log: absent; `ue_started=0`.
- PRACH, RAR, PUSCH, and endpoint rows: 0.

The earlier transient UE-role helper precheck failure is not causal: its
postcheck passed, while the gNB's explicit hash rejection deterministically
prevents startup.

## Root cause and next gate

The CP3450-era 15 MHz launcher still pins an older gNB hash. The live host now
correctly carries the newer CP3473 selector-capable binary used by CP3477,
CP3478, and CP3481. Restoring the old binary would discard qualified fixes and
is prohibited.

Next stay no-RF:

1. Read the old launcher's expected hash and the current deployed binary hash.
2. Copy the launcher additively and change only that expected hash.
3. Prove the current binary contains the required 15 MHz and default-off
   instrumentation paths.
4. Repoint a fresh fail-closed runner and validate through the full chain.

Only then retry the endpoint run. This does not consume the CP3482 access-void
retry because no radio process started.
