# Checkpoint 3503: explicit-context propagation void

## Verdict

**VOID FOR THE INTENDED DELTA.** RF executed, but explicit PRACH context did
not reach the live UE process. Do not interpret the zero-accept result as a
failure of explicit context and do not count it as a PUSCH datapoint.

## What happened

The controller pinned and validated
`cp3502_stage6_explicit_prach_context.sh`, but its execution path invoked the
inherited CP3456 chain. The terminal CP2188 script in that chain hardcodes
`cp3456_run_stage6_bandwidth15.sh`; the validated CP3502 Stage 6 runner is
never called. The UE-copy log consequently shows the old CP3186 wrapper.

Both runtime env files contain zero
`PAVONIS_RF_BLADE_PRACH_EXPLICIT_CONTEXT` rows. All seven bounded bladeRF
metadata records retain the old amplitude-selected behavior: forced SOB=1,
forced EOB=1, and the `-21333`-sample PRACH offset applied. This mechanically
proves the experiment did not exercise its sole intended variable.

## Incidental run outcome

- Cell selection and SIB1 pass at 9.984 dB; the UE transmits seven Msg1.
- Fixed collection delay is 245760 samples, but the gNB accepts none and sends
  no RAR. This is non-diagnostic for explicit context.
- TX health has zero timeout, zero downlink-late, zero stream deficit, and one
  430-sample partial that is fully retried. The run is not rejected for gross
  producer loss.

Stage 6 handoff to the CP3502 explicit-context runner. Pin and execute that
chain, prove the live UE-copy basename/hash and launch/result env rows, and
