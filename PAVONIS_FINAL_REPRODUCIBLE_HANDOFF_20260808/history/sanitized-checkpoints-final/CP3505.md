# Checkpoint 3505: explicit context requires continuation reopen

## Verdict

**VALID REJECTION OF EXPLICIT-CONTEXT ALONE.** The intended control propagates
end-to-end, but only the first PRACH write succeeds. The next six return
bladeRF `TIME_PAST` (`-14`), so no Msg1 is accepted and PUSCH separation is not
yet tested.

## Propagation and health

- The UE-copy log names `cp3502_stage6_ue_explicit_context.sh`.
- Both launch and result env record explicit context=1.
- Cell selection/SIB1 pass at 9.944 dB and the UE emits seven Msg1.
- TX health has zero timeout, zero downlink-late, zero stream deficit, and one
  fully retried 430-sample partial.

This is not the CP3503 dead-pin failure and not a gross gNB producer failure.

## PRACH result

All seven true PRACH calls retain forced SOB/EOB and the `-21333`-sample
offset. Call one succeeds; calls two through seven return `-14`. All captured
windows remain floor-class at -69.947 to -64.247 dBFS, with zero accept/RAR.
By contrast, same-day CP3503 with context off had seven successful bladeRF
writes, so the status split follows the live context delta.

## Source mechanism

With burst-only and context off, low-peak calls between PRACH occasions are
skipped. With explicit context on, non-PRACH low-peak calls are no longer
selected by burst-only and therefore resume after the PRACH EOB. The first
PRACH closes the bladeRF burst, but
`PAVONIS_RF_BLADE_PRACH_REOPEN_CONTINUATION` is disabled, so the continuation
does not receive the existing guarded SOB path. Later timed PRACH starts are
then rejected as past.

The next sole-variable test is the existing default-off continuation-reopen
control. Keep explicit context, fixed16ms, burst-only, offset, restart-first,
and every gNB/detector/producer value unchanged. Require all seven PRACH writes
to return success before judging acceptance or PUSCH.
