# Checkpoint 3510: nonzero-only continuation-reopen source gate

## Verdict

**PASS, NO RF: one bounded CP3511 run is unlocked.** A minimal, default-off
bladeRF transport policy now keeps the post-PRACH continuation-reopen arm
pending across zero/low-energy non-PRACH calls and consumes it only when the
first real non-PRACH waveform arrives.

## Why this is the next isolated change

CP3507 proved that reopening immediately on an exact-zero continuation leaves
the bladeRF burst open and makes the next PRACH SOB invalid. CP3509 proved that
bounded queueing fails earlier: resumed zero calls generate transport errors
before a second Msg1 can exercise the timestamp-update branch. Queue depth is
therefore not the variable to [interface-redacted].

The new `PAVONIS_RF_BLADE_PRACH_REOPEN_NONZERO_ONLY` policy changes only the
continuation-reopen decision. With the flag enabled, a pending reopen plus a
sub-threshold non-PRACH call follows the existing low-peak skip path and leaves
the arm set. The first nonzero connected waveform receives the guarded SOB and
clears the arm. True PRACH keeps its existing SOB/EOB and `-21333`-sample
offset. Bounded queueing returns to disabled.

## Disabled-path and hot-path proof

- The environment is read once in `rf_blade_open()` and stored in the handler;

## CP3511 judgment

Judge in this order:

1. Producer and propagation health: context=1, reopen=1, nonzero-only=1,
   bounded-queue=0, plus clean gNB delivery counters.
2. Transport sequence: exact-zero calls must skip with status 0 while the arm
   remains pending; repeated true PRACH writes must retain SOB/EOB/offset and
   return status 0.
3. On RAR, the first connected PUSCH waveform must receive the guarded
   continuation SOB, clear the arm, and avoid PRACH offset/EOB handling.
4. Only then judge Msg1 acceptance, RAR, PUSCH CRC, endpoints, and sustained
   throughput.

If repeated PRACH transport is clean but the detector remains floor-class,
the fixed-16 ms collection point is run-variable and the next branch is
dynamic collection timing. Do not add more bladeRF queue/reopen flags.
