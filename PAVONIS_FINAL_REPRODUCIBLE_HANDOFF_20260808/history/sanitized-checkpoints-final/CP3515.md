**PASS, NO RF: one bounded CP3516 run is unlocked.** The sole runtime delta

## Why the combination is now justified

CP3514 proves nonzero deferral prevents the old zero-call arm clear, permits
two PRACH writes, and opens connected PUSCH correctly. Once PUSCH opens the
continuation burst, five later true PRACH writes fail because they force a new
SOB on an open burst. The existing bounded branch handles exactly that state by
replacing PRACH SOB/EOB with `UPDATE_TIMESTAMP`.

CP3509's bounded-queue failure occurred before a second PRACH because the old
continuation path transmitted an exact-zero reopen and resumed zero writes
failed. That causal path is now removed. Queue geometry itself remains
unchanged at 5 buffers, 4 transfers, and 10240 samples; it is not being [interface-redacted].

## CP3516 judgment

Judge health and propagation first, including queue readback 5/4/10240 and no
zero-call transport storm. Then require:

1. initial PRACH writes status 0 while reopen stays pending;
2. first real PUSCH applies continuation SOB, clears pending, and has no PRACH
   offset/EOB;
3. later true PRACH writes apply `UPDATE_TIMESTAMP` and return status 0;
4. no `TIME_PAST`, invalid-operation, or unexpected zero-write sequence.

Only then judge PRACH/RAR supply, PUSCH CRC, endpoints, and sustained
throughput. If the small bounded queue still fails before timestamp update,
reject the queue coupling and separate update-timestamp semantics from queue
geometry in source. If transport and producer health pass but PUSCH remains
floor-class, move to dynamic non-PRACH receive timing rather than another
transport flag.
