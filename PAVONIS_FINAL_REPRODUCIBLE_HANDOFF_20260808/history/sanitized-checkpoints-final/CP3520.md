# CP3520 - Non-PRACH TX timestamp offset no-RF gate

## Verdict

**PASS, NO RF.** A minimal default-off bladeRF policy now restores the historical `-21333`-sample timing correction to real non-PRACH waveforms without restoring the PRACH burst/restart/EOB behavior that CP3502 correctly isolated.

One bounded CP3521 fixed-16 ms RF run is unlocked.

## Source Policy

`PAVONIS_RF_BLADE_NON_PRACH_TIME_OFFSET_SAMPLES` is read once when the plugin opens and defaults to zero. Its branch executes only when all of these are true:

- TX debug policy is active;
- explicit PRACH context is active;
- the current write is not PRACH;
- the write has samples and a nonzero hardware timestamp;
- the existing bounded real-waveform peak gate passes.

The branch adjusts only `meta.timestamp`. It does not set SOB/EOB, open or close a burst, restart/reconfigure the device, select TX-now, scan samples, format new per-call output, or perform file IO. It reuses the existing bounded metadata record with separate selected/applied/old/new fields.

## CP3521 Shape and Judgment

The sole runtime semantic delta from CP3518 is non-PRACH TX timestamp offset `-21333` samples. Keep fixed `245760`-sample PRACH collection, explicit context, continuation reopen, nonzero-only arm handling, bounded queue, 15 MHz geometry, gNB receive offsets, detector list, power, gain, scheduler, and producer controls frozen.

Judge in this order:

1. producer and transport health;
2. runtime launch/result propagation of the new value;
3. PRACH remains on its existing offset path while PUSCH shows only the new non-PRACH offset, with no PRACH burst/EOB flags;
4. Msg1/RAR supply;
5. gNB PUSCH CRC and SINR versus CP3518 `0/30` and CP3451 `128/128`;
6. endpoints and throughput only if PUSCH CRC recovers.
