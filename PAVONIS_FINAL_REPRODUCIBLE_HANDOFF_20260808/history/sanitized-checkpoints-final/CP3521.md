# CP3521 - Non-PRACH offset propagation void; access baseline valid

## Verdict

**POLICY AXIS VOID; ACCESS BASELINE VALID.** CP3521 did not execute the CP3520 non-PRACH timestamp offset. It is not evidence against the timing hypothesis.

The run independently repeats CP3518's fixed-16 ms access result: clean cell/SIB1, seven Msg1 transmissions, six gNB RARs, six UE-decoded RARs, and six Msg3 preparations under clean transport. Fixed 16 ms now has two consecutive strong access rolls, although broader lottery elimination remains provisional.

## Propagation Failure

- Controller RF-shape telemetry declares `rf_blade_non_prach_time_offset_samples=-21333`.
- Actual UE `launch.env` and `result.env` contain no such field.
- Seven PRACH waveform rows show existing PRACH offset applied.
- Eighteen PUSCH waveform rows show `non_prach_time_offset_applied=0`.
- The Stage6 copy log proves the inherited CP3515 UE wrapper was deployed.

The controller hash-gated CP3520's Stage6 file but executed `RUNNER`, the inherited 22-script chain. Its terminal CP2188 handoff still selects CP3515. This is the same class of dead-boundary defect previously isolated at CP3503/CP3504.

## Valid Baseline Evidence

- Cell search `8.001 dB`, SFN and SIB1 pass.
- Msg1 / stage-1 selected / gNB RAR / UE RAR: `7 / 6 / 6 / 6`.
- UE Msg3 preparations / PUSCH encodes: `6 / 18`.
- Soapy TX timeout, downlink-late, hard error, UE TX failure, final stream deficit: all `0`.
- One 430-sample partial return was fully recovered.
- PUSCH remains `0/30` CRC at `-27.909..-14.077 dB` SINR, but this merely repeats the offset-zero baseline.

## Decision

Copy the accepted CP3515 chain additively and change only its terminal Stage6 handoff to CP3520. Prove the remaining chain files normalize byte-identically, bind the CP3520 controller to that copied runner, and require launch/result evidence before another semantic judgment. No source, binary, RF, PRACH, gNB timing, detector, power, gain, or scheduler change is needed.
