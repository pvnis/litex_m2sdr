# CHECKPOINT 3536 - Root-chain rebind propagation void

## Verdict

**VOID for timestamp-fixture removal.** CP3535 changed the copied terminal and
Stage6 clone correctly, but the copied root runner still set `CHAIN` to the
original CP3525 directory. Runtime therefore bypassed both CP3535 files and
again launched with `-21333`.

## Evidence

- Controller/execution summary declare timestamp offset `0`.
- Live result environment and UE TX metadata report offset `-21333` and
  burst-only `1`.
- The CP3535 root runner line 5 points to the CP3525 chain directory.
- The sequence log shows deployment of the CP3525 UE wrapper, mechanically
  confirming that the CP3535 terminal was never reached.

The proper copied-chain shape is therefore 20 byte-exact files plus two
path-only files: the root must select the copied chain, and the terminal must
select the copied Stage6 clone.

## Radio classification

The radio run reached cell selection and SIB1 at `6.812 dB`; the UE emitted
seven Msg1 attempts, but stage-1 selected none, so there was no RAR or PUSCH.
Health remained clean with zero timeout, downlink-late, error, or final stream
deficit. Because propagation failed first, this is not a zero-offset detector
datapoint and does not consume the semantic retry.
