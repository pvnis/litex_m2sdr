# CHECKPOINT 3540 - gNB owns displacement; UE timestamp fixture retired

## Verdict

**PASS.** Moving the exact `21333`-sample displacement from UE TX into the gNB
receive-time calibration restores Msg3/PUSCH and sustained bidirectional data.
The UE non-PRACH timestamp fixture is retired.

## Causal evidence

CP3538 used UE offset `0`, burst-only `1`, and gNB calibration `-245755`; it
reached six RAR/Msg3 attempts but produced `0/30` PUSCH CRC. CP3540 changes only
the gNB calibration to the source-derived `-267088` and produces `74/128` PUSCH
CRC plus complete user-plane transfers.

Propagation is explicit:

- Result environment: UE offset `0`, burst-only `1`.
- 280 TX metadata rows carry offset value `0`; zero rows apply an offset.
- 264 transmitted rows carry forced independent SOB+EOB metadata.
- Live gNB config calibration is `-267088`.
- The accepted edge event publishes `-261960`, exactly
  `-267088 - (-4600) + 528`.

## Results

- Cell selection: `7.259 dB`, CFO `-3811.3 Hz`.
- Access: two Msg1, one stage-1 selection, one gNB RAR, one UE RAR, one Msg3.
- PUSCH: `74/128` CRC OK (`57.81%`), successful median SINR `14.946 dB`,
  median TBS `309 B`.
- Sustained 45-second data: DL `1.939 Mbit/s`, UL `0.331 Mbit/s`.
- Health: zero TX timeout, downlink-late, error, or final stream deficit; one
  430-sample partial return recovered.

## Interpretation

The physical displacement remains real, but it now has one coherent owner: the
gNB receive timeline. The bladeRF/srsUE path no longer modifies scheduled PUSCH
timestamps. This removes a cross-device timing workaround and makes the next
test meaningful: whether independent PUSCH bursts are still required.

The gNB calibration is still expressed as a static value tied to the current
`245760`-sample PRACH collection delay. A later source cleanup must derive it
from the actual collection delay and the retained `-21328` effective invariant.
