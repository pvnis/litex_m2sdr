# CP3551 - Post-OFDM hardware integration no-RF gate

## Verdict

**PASS_NO_RF_HARDWARE_INTEGRATION_GATE.** The CP3550 post-OFDM collector is
integrated into the exact CP3548 10 MHz, one-layer, ATT5, MCS9/MCS10 hardware
shape. Local syntax, deployed hashes and strings, disabled and armed launcher
validation, controller validation, default-closed behavior, temporary UE helper
lifecycle, and current host-state gates all pass. No SDR stream was opened and
no RF was transmitted.

## Frozen Shape

The next run preserves the CP3548 radio, timing, scheduler, detector, and
traffic settings: 10 MHz, one layer, 11 ms TX lead, ATT5, PDSCH alternating only
new-data MCS9/MCS10, 45 seconds with four streams, gNB-only uplink timing
ownership, and the required independent non-PRACH burst fixture. The only new
runtime behavior is the CP3550 bounded arm/post-OFDM collector.

The gNB wrapper pins binary
`ca359c650cdaf81a3de19beba8aceea14a9fb0b9992251bbb2a06948258d7905`.
When armed, the first selected upper-PHY PDSCH creates the lower collector's
sentinel, 16 upper grids are retained, and 64 complete post-OFDM CI16 slots are
retained. When disabled, all new variables are explicitly unset.

## Gates

- Local `bash -n` passes for the launcher, armed wrapper, and controller wrapper.
- Deployed launcher/wrapper hashes match local files, and the gNB contains both
  the buffered lower collector and upper arm-creation markers.
- Disabled launcher validation reports selector/capture zero; armed wrapper
  validation reports selector/capture one and the pinned base hash.
- The inherited controller validates the 23-candidate list, candidate cap,
  four-stream shape, MCS9 endpoint, UE guard, gNB PRACH timing, and independent
  compensation without opening RF.
- Running the controller wrapper without `PAVONIS_CP3552_RF_APPROVED=1` exits
  exactly 2 with `CP3552_RF_GATE=CLOSED`.
- The temporary UE preparation shim passes activation, active-state proof,
  byte-exact restore, and post-state proof.
- Current gNB-side preflight proves device presence, effective RTPRIO 98,
  successful SCHED_FIFO entry, performance governor/EPP, maximum 55 C, and idle
  roles.
- Current UE-side preflight proves one authorized SuperSpeed bladeRF with USB
  power control `on`, performance governor/EPP, maximum 61 C, and idle roles.

## Honest Voids

One config-only probe used a generic template rather than the frozen generated
hardware profile, so the inherited CP3397 profile checks rejected it before the
runtime-export line. It started no process or RF stream and is not propagation
evidence. The exact disabled/armed launcher validations and controller
validation pass instead.

The first gNB thermal one-liner encountered a sysfs thermal path that was
nominally readable but returned no data. A bounded per-file reader skipped
unavailable zones and produced the valid 55 C maximum. This is a parser void,
not a host-state failure.

## Decision

Exactly one CP3552 hardware run is unlocked. It must fetch the upper-PHY grid,
post-OFDM CI16 waveform, and UE FFT/raw/equalized/channel-estimate captures,
then apply the CP3550 source-defined phase reconstruction. Health is judged
before stage localization.

Bandwidth, MIMO, power, scheduler, detector, timing, and producer-stall changes
remain prohibited until CP3552 reports whether the live post-OFDM boundary is
clean or degraded.
