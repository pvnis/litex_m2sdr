# CP3562 - same-window self-RX/bladeRF no-RF gate

Timestamp: [date-redacted]

## Verdict

PASS. A default-closed controller is ready to replay CP3558's exact payload
while capturing the same bounded interval on M2SDR self-RX and bladeRF RX1.
No RF was transmitted and no production source, binary, driver, plugin,
kernel, FPGA, gateware, scheduler, or radio configuration was changed.

## Design

The controller reuses the established CP1395 standalone LiteX TX/self-RX
helper and CP1219 bladeRF SC16 capture implementation. It transmits the same
CF32 sequence and hardware shape as CP3560/CP3561: `11.52 Msps`, `10 MHz`,
`1842500000 Hz`, attenuation 5, channel 0. M2SDR self-RX uses the proven
split-frequency geometry at `1839650000 Hz`; bladeRF uses the CP3561 geometry
at `1842506000 Hz`, gain 40.

The self-RX interval is four seconds and the external capture is two seconds.
The run refuses interpretation unless wall-time metadata proves at least
500 ms overlap. Both captures are correlated to the exact payload and scored
against the same 16 CP3558 gNB PDSCH grids.

## Gates

- Shell syntax and Python compilation pass.
- Closed RF gate exits `2` before creating a run directory.
- Existing helper/capture inputs are hash-pinned and unchanged.
- The new analyzer uses memory-mapped SC16/CF32 input and performs no live-path
  instrumentation.
- Regression against CP3561 reproduces 16 records, alignment `+26` samples,
  CFO `-3975 Hz`, and median `5.[subscriber-redacted] dB` exactly.

## Decision rule

- Clean M2SDR self-RX with approximately 6 dB bladeRF quality isolates the
  ceiling to the inter-device air/bladeRF receive leg.
- Matching degradation on both receivers places the ceiling at or below
  M2SDR TX/gateware/RF.
- Missing overlap or weak payload correlation makes the run void, not a
  physical-path verdict.

Bandwidth, MIMO, power and producer-stall headroom remain locked.
