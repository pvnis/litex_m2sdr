# CP3572 - Forced build-module CF32 verdict

## Verdict

Valid bounded RF run. Forcing the exact Soapy LiteX-M2SDR build module used by
the good CP3561 replay does **not** recover the CF32/native-MTU path. The
authoritative 64 ms period median is -5.700 dB, statistically the same as
CP3570 at -5.672 dB and 11.425 dB below the CP3561 +5.725 dB CS16 reference.

Plugin provenance was a real reproducibility hazard, but it is not the cause of
the unexplained downlink ceiling. The next earned experiment is a same-helper,
same-module, same-payload, same-chunk CS16 versus CF32 format A/B. Bandwidth,
MIMO, power, and producer-stall headroom remain locked.

## Controlled change

Only Soapy module discovery changed from CP3570. The run used an empty
SOAPY_SDR_ROOT, an isolated plugin path, and build module SHA-256
a15642a20c022d412a78fd27e922c27313e577c5f38c95adf1236c8b8008b0a2.
The exact payload, CF32 format, 1022-sample writes, RF frequency, sample rate,
bandwidth, TX attenuation, and bladeRF receive configuration stayed frozen.
