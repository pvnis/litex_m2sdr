# CP3580: OCUDU TX lifecycle is safe only through the frozen force-att path

Date: [date-redacted]

## Verdict

PASS for the live-ceiling discriminator. The frozen OCUDU ladder already
reasserts `5 dB` attenuation after both Soapy streams are set up, and that state
survives TX activation, RX activation, and a 50 ms settle. The CP3578 helper
root cause therefore does not explain the current live downlink ceiling.

The audit also confirms a real remaining crutch: without
`PAVONIS_SOAPY_TX_FORCE_ATT_DB`, the deployed module resets normal configured
TX attenuation to `20 dB` during `setupStream()` and leaves it there. The
working ladder is protected by the force-att path, not by standards-default
device behavior.

## Frozen-run provenance

The CP3558 controller passes `--tx-att 5` as `TX_ATT=5`. The inherited CP1807
launcher writes that value into the remote environment as
`PAVONIS_SOAPY_TX_FORCE_ATT_DB`. OCUDU's source applies this value during the
initial gain request and again after both TX and RX stream setup.

CP3558's TX sidecar is constructed after both streams are set up and reports
channel-0 gain `5.0 dB`. The force-att logger is INFO-level while the frozen gNB
used warning-level logging, explaining why the explicit marker was absent from
the saved main log. Its absence was not evidence that the environment was off.

## No-write lifecycle probe

A default-closed Python/Soapy probe used the exact build module SHA-256
`a15642a20c022d412a78fd27e922c27313e577c5f38c95adf1236c8b8008b0a2`,
the live 11.52 Msps/frequency/bandwidth geometry, OCUDU stream ordering, and no
`writeStream` call.

| Path and stage | TX attenuation readback |
|---|---:|
| normal config, before setup | `0 dB` |
| normal config, after TX setup | `20 dB` |
| normal full-duplex, after RX setup | `20 dB` |
| normal full-duplex, after TX and RX activation | `20 dB` |
| force-att path, after RX setup but before reassert | `20 dB` |
| force-att path, immediately after reassert | `5 dB` |
| force-att path, after TX activation | `5 dB` |
| force-att path, after RX activation | `5 dB` |
| force-att path, after 50 ms | `5 dB` |

The probe completed in under ten seconds, opened no data writer, emitted no
sample stream, and closed both streams and device sessions.

## Source/build finding

Current driver source contains an intended cached-RF-state reapply after
channel-mode setup, but the exact deployed build module behaves as though that
fix is absent or ineffective. This is a source/build divergence to resolve in
a later crutch-retirement checkpoint. Rebuilding or changing the frozen module
now would conflate that maintenance task with downlink localization.

For the current production shape, active attenuation is mechanically proven
correct. A frozen force-att RF rerun would repeat CP3558 rather than test a new
variable.

## Next frontier

Run one corrected same-window exact-payload M2SDR self-RX versus bladeRF
discriminator with post-setup attenuation reassert. Compare its external leg
against CP3578's `+5.744 dB` period class and live CP3558's `+4.896 dB`
selected-grid class. This replaces CP3565's confounded 20 dB-attenuation
physical split. Bandwidth, MIMO, and producer-stall headroom remain locked.
