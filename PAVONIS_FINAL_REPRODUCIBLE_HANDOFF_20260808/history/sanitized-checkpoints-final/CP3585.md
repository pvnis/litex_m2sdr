# CP3585 - Phone 15 MHz setup recovery

## Verdict

**PASS for setup recovery and the revised no-RF gate; void for bandwidth.**
Two bounded executions stopped before any RF transmission. They expose two
independent cold-lab prerequisites rather than a 15 MHz radio result. The
canonical core routing state is restored, and the local M2SDR primer now uses
a checkpoint-owned helper that pins every runtime artifact while no longer
requiring an unrelated historical source-file hash.

The CP3121/CP3153 baseline, original core helper, original primer helper,
binaries, configs, RF parameters, and CP3584 bandwidth overlay remain
byte-identical.

## Attempt classification

### Attempt 1: missing core routing state

The phone lifecycle, policy gate, traffic-helper deployment, and controller
preflight passed. Core startup then stopped because the pre-created private
[interface-redacted] and veth topology was absent. The process never started and the radio
runner never reached the primer or OCUDU.

Read-only audit confirmed a clean missing state rather than a partial or stale
topology. The repository's canonical `qcore/setup-routing` and
`qcore/setup-ethernet` scripts hash-matched their remote copies. Running that
documented setup once restored the private [interface-redacted], both veth pairs, forwarding,
and the private gateway address without error. This is host prerequisite
restoration, not an RF or protocol change.

### Attempt 2: stale local-primer source assertion

Core startup passed after the routing restoration. The local M2SDR primer then
returned before device setup. Its exact binary, RF plugin, installed Soapy
module, kernel module, configs, program mode, device node, and CPU governor all
matched their pins. The only failed check was a historical hash of the live
Soapy source file.

That source file is not compiled or loaded by the already-built primer. The
installed module still matches the proven phone baseline hash. Therefore the
check was a stale provenance assertion, not runtime integrity. No stream was
opened and no RF was transmitted.

An initial audit of the remote bladeRF-primer branch was irrelevant and was
discarded before deployment or execution; the phone controller explicitly
selects the local M2SDR primer.

## Isolated fix

The checkpoint-owned primer helper differs from CP2985 in three mechanical
ways:

1. It removes only the live Soapy source-file hash assertion.
2. It retains pins for the primer binary, RF plugin, installed Soapy module,
   kernel module, and all four configs.
3. It emits an explicit runtime-artifact-pin marker and labels the source gate
   as non-runtime.

A copied CP3153 benchmark driver adds default-preserving local/remote helper
override variables. With no override, its behavior is identical to CP3153.
The CP3585 filtered runner opts into the checkpoint helper. The execution
controller deploys and hash-verifies it before the radio runner.

## No-RF proofs

- All five checkpoint scripts pass shell syntax checks.
- The driver diff is limited to the two default-preserving helper override
  assignments.
- The helper diff is limited to the source assertion and two truthful markers.
- Remote helper hash verification passes.
- The helper's own approval gate returns 2 and creates no run directory.
- Inner and outer benchmark gates each return 2; the closed outer gate creates
  no attempt directory.
- The CP3121/CP3153 immutable manifest still verifies.
- The restored private routing state remains present after both voids.
