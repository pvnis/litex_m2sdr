## Verdict

VOID FOR MCS9/MCS10. The RF/access/data run is healthy, but the selector enable
did not reach the remote gNB executable boundary. The runtime wrapper reports
`selector_enable=0`; selector startup rows and selector newTx rows are both
zero. No MCS10 conclusion is permitted.

The run itself completes attach and sustained data at 12.617000/0.394692
Mbit/s DL/UL, activates in 44.181 seconds, records 256/256 bounded PUSCH CRC OK,
and has clean exact producer delivery. Those facts classify it as another
valid baseline-class MCS9 roll, not as a failed radio or phone attempt.

## Root cause

The CP3600 local runner set `PAVONIS_CP3600_DL_MCS_AB_ENABLE=1`, but the inherited
historical remote launch chain filters environment variables before invoking
the gNB override wrapper. The wrapper therefore consumed its default 0.

This is the same executable-boundary propagation class closed by CP3476. The
fix is not another RF retry with the same command. Add a distinct hash-pinned
armed wrapper that hard-codes selector enable 1 at the final executable
boundary, prove it no-RF, and then run once.
